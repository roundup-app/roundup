# UI: the first Workstream (U143)

Module: `apps/desktop` (the webview); U146, U166 and U177 also edit the fake `claude` at `crates/rup/tests/e2e/fake_claude.py`; U176 edits `crates/agents/src/name.rs`. Found by walking the first journey in the U26 harness: an open Project with no row says only `select an agent or a terminal` and offers no first action in the centre; a Workstream whose Door is not running shows a bare `start Door`, so a Door that never launched, one that stopped, one that is starting and one that failed to start look the same.

**U143 the first Workstream says where it stands.** Narrows U38 and U9; changes no contract, App seam command or token. Given an open Project, then:

- **Empty.** Only when `rail.tree` has no row, the centre replaces U38's `select an agent or a terminal` with a light `no Workstream yet` and one button, `start a Workstream`. The button runs the same path as the Rail's `+ workstream` (U9): one `rail.createWorkstream {name: "workstream", parent: null}`, then select the returned Workstream once `rail.tree` has its row, then one `rail.startDoor {id}`. It is a native button, so Tab reaches it and Enter or Space activates it. While creation is pending the line reads `creating Workstream…`, the button is disabled, and a second activation of it or of `+ workstream` calls nothing (U9). A failed creation shows its message as an alert, selects nothing, starts no Door, and leaves the button ready to try again. A failed Door launch afterwards retries that same Workstream through U9's `retry Door`; it never creates another. With any row present and none selected, U38's text and no button show. The Rail's `no agents yet` / `⌘N starts one` and `+ agent` are unchanged, so direct Agent access stays; `+ terminal` is gone (U165).
- **Door states.** When the selected row is a Workstream whose Door has no running program, the centre shows one light state line above U9's `start Door` / `retry Door`, in a fixed block that does not resize the pane. The line is one of:
  - `starting Door…` while a `rail.startDoor` call is pending; the button is disabled, so a repeat activation calls nothing (U9);
  - `Door did not start` after a failed start (U9), beside the `✕ <message>` line and `retry Door`;
  - `Door not started` when the Workstream has no Attempt (A20) and no Terminal;
  - `Door stopped` when it has an Attempt and no running program, followed by `, exited <code>` or `, exited by signal` when the ending is known (U7's wording). `stopped` means launched before and not running now, however it ended, so a Workstream whose first launch failed reads `stopped` after a reload.
- **Running.** A Workstream with a running Door shows its Terminal and no state line. The words never mention a Thread or coordination: today the Thread is the Door's Terminal (`GLOSSARY.md`).
- **Direct access.** With a stopped Door selected, `+ agent` and `⌘T` still work inside that Workstream (U9, U165).

**U145 the Thread's input shows only where it has a Door.** Found by the user's report #440: with `no Workstream yet` in the centre, the Thread's input still sat at the window's bottom edge with no margin, an outline on a borderless field, and the line `select a Workstream to talk to its Door` above it. Narrows U105 to U110 and U143; changes no contract, App seam command or Token. Given an open Project, then:

- **No Workstream.** While the selection resolves to no Workstream (no row at all, no row selected, or a selected row with no Workstream among itself and its ancestors), the centre has no Thread: no `[data-thread-input]`, no feed, no failure line and no send action. No code path produces `select a Workstream to talk to its Door`.
- **A Workstream.** While the selected row is a Workstream or lies under one, whatever its Door's state (U143), the Thread shows inside the centre below the pane. Its composer is inset from the centre's bottom, left and right edges by `--space-3` or more, rests on its own surface (`--sunken`, one 1 px `--hairline` border, `--radius-control`), and uses only Tokens. When the input has keyboard focus the composer shows the one focus ring (`docs/design-system.md`, "Click targets") and the input draws no second outline.
- **Send.** A native `send` button sits at the composer's trailing end. Activating it, by pointer, Enter or Space, sends exactly what Enter in the input sends (U105, U109, U110). While the input is empty and no Quote or Attachment waits, and while a `message.send` it made is pending, it is disabled (`aria-disabled`, `--grey`) and calls nothing, so a repeat press sends no duplicate and shows no line. It meets D6 and D7.
- **Focus.** Opening a Project, selecting a row by pointer, creating a Workstream and starting its Door move no focus into the Thread. The input takes focus only from a pointer, Tab or `⌥0`.
- **Errors.** Only what the UI cannot prevent shows on U80's one line: a failed `message.send` with its message, and U109's refusal of a dropped file that is not an image. No other line shows there.
