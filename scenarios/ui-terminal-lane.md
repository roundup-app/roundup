# Terminal directory uses shared controls

Scope (policy): `apps/desktop/src/terminal/`, catalogue entries that directory uses, and only the `.pane*` and `.terminal*` rules in `styles.css`. Do not edit another lane, `ui/`, `keys/`, `tokens.css`, manifests, lockfiles, contracts or the App seam. A missing shared capability is a native prerequisite against UI epic #1647, never a local primitive (policy).

Direction: #1606. Require the merged implementations of #1619 (Terminal output stream), #1629 (`ui/` primitives), #1627 (copy catalogue), #1630 (system UI font), #1608 (registry, implementation #1869) and #1610 (semantic Tokens), not their specification closures. #2217 only parked this Issue and was closed as not planned; it builds nothing this lane needs (policy). This specification adds no domain name or product behaviour. Planned tests are implementation obligations, not claims of tests passing on this specification head.

The Understand and Intervene stages of `.agents/data/journey.md` need a readable Terminal and direct typing into an Agent's Terminal. Preserve them; this migration claims no new storage or real Agent outcome (policy).

**U3705 Terminal controls and copy use shared infrastructure.** Given every control in `terminal/`, including those revealed only in a daemon-gone, watch or empty state, when reached by pointer and keyboard, then each icon-only button is a `ui/IconButton` with a nonempty accessible name and a `ui/Tooltip`, each menu is `ui/Menu`, and no native `title=` remains. Every App-authored visible string, placeholder and accessible name comes from `copy.ts` and reads as a user label (never a `GLOSSARY.md` code term); Terminal output, Agent names and returned errors stay content (`u3705_copy_is_catalogued`, planned in `terminal/`, over every state above). Only entries `terminal/` uses change (policy). Ark owns component arrows, Escape and focus return of the Popover and Menus (policy).

**U3706 Pane keys run through the registry; typing is never intercepted.** Given a Pane with a watched Agent, when `⌘⏎` takes control, then the registry's pane-scoped binding runs it once; Close and Terminal-tab switching follow `ui-terminal-tabs.md` (U469, U534) and are likewise registry bindings, never a listener in `terminal/` (`u3706_pane_keys_follow_the_registry`, planned, using the real registry). Given focus in the xterm.js screen, when `⌘C`, `⌘V`, `⌘=`, `⌘-`, `⌘0` are pressed, then they act as U2241 and U532 say, once, and every other `⌃`, `⌥` or `⌘` chord reaches xterm.js's key handler unprevented and unwritten by roundup (`u3706_typing_reaches_xterm`, planned; the U2241 sweep and U2242 byte tests keep passing). The Pane's capture-phase `keydown` listener in `Pane.tsx` is replaced by registry bindings in the Terminal scope; if the registry cannot run a Terminal-screen binding before xterm.js sees the key, file that as a prerequisite against #1647 and stop (policy). Disposal or Project switching leaves no stale binding (same observer). #3529 retires Send to Agent's Popover/Menu and its `⇧⌘A` binding; U3529a–d govern their removal (policy).

`emulator.ts` tracks the `⌘` state with window `keydown`/`keyup`/`blur` listeners only to show U365's link hover; it dispatches no action and is xterm.js input support, so it is the one allowed match of the observer below. It is deleted if Ark or xterm.js exposes the modifier state (policy).

**U3707 Adoption keeps Terminal behaviour, metrics and budgets.** Given `agents-10` with a watched Agent, a Door Terminal, a Bubble, a daemon-gone Pane and the longest Agent name, when each owned state and its focus and hover states is observed in light, dark and increased contrast for non-capture metric/behavior observations, and dark only for captures and critic Check readings (U3725), at 1512×950, then D2, D5 and D6 pass, no Check passing on the same main baseline regresses, and xterm.js keeps its monospace font and cell metrics, so the columns and rows U13 reports are unchanged (`u3707_rendered_checks`, planned isolated headless browser observer in `terminal/`; the design critic judges U59's D1, D6, D7 and D10 reading, AGENTS.md rule 10). Check definitions: `docs/design-system.md`, heading `The checks`; observer: `window.__checks()` in `.agents/data/harness.md`, heading `Held-out screens`. Publish paired main/head captures and Check JSON under `artifacts/ux/U3707/{base,head}/`, linked in the implementation PR (policy).

Use only existing Tokens. Delete `.pane*` and `.terminal*` rules serving only removed hand-written focus, open-state or press handling; keep layout and visible focus. Delete tests that pin one computed style or exercise deleted mechanics, each cut naming the surviving behavioural proof or the retired clause under rule 10; rewrite the rest against roles and accessible names (policy). Every scenario the directory carries (`terminal.md`, `terminal-stream.md`, `ui-terminal-*.md`, U11–U532 tests above) still passes (policy).

Given the implementation head, when `just perf` runs, then rule 7's limits and 10% regression gates pass (`u3707_budgets`, observer `just perf`, interpretation in `docs/perf.md`). A failure that also fails on `main` (the Linux RSS regression; #1990 closed as not planned) does not block; report matched before/after values. No limit or baseline changes. Daemon measurements do not prove keystroke latency; never launch the native opt-in probe without the user's request (policy).

## Reuse evidence

The lane adds no primitive and consumes `ui/` wrappers over [Ark UI](https://ark-ui.com/docs/components/tooltip) (installed `^5.39.3`, [Solid npm metadata](https://registry.npmjs.org/@ark-ui%2fsolid) dates 5.39.3 to 2026-10-05). [Kobalte](https://kobalte.dev/docs/core/components/tooltip/) ([0.13.14, 2026-09-07](https://github.com/kobaltedev/kobalte/releases/tag/%40kobalte/core%400.13.14)) is maintained but would add a second primitive layer against the work order's Ark boundary. Key dispatch uses the installed registry on [tinykeys](https://github.com/jamiebuilds/tinykeys), not a new library (policy).
