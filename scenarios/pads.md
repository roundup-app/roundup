# Pads

Module: `crates/pads`. Ids: every `P` heading in the file.

**P1 create.** Given an empty Project, when an Agent `a` calls `pad.create {name: "notes", text}`, then the Pad's owner is `a`; creating `notes` again fails with `CONFLICT`, and so does `Notes` (names are unique ignoring case, because the macOS file system is case-insensitive and file-backed Pads would otherwise share one file); `pad.changed {name}` is emitted and a `wrote` Touch on `pad:notes` is logged.

**P2 owner rewrites, others append.** Given Pad `notes` owned by `a`, when `a` calls `pad.write`, then the text is replaced. When another Actor `b` calls `pad.write`, then it fails with `FORBIDDEN` and nothing changes. When `b` calls `pad.append`, then the text is added at the end, `pad.changed` is emitted and a `wrote` Touch by `b` is logged.

**P3 read and list.** Given three Pads, when `pad.list` is called, then all three come back ordered by name; `pad.read {name}` returns one and logs a `read` Touch; an unknown name is `NOT_FOUND`.

**P4 flip ownership.** Given Pad `notes` owned by Agent `a`, when the user calls `pad.setOwner {owner: user}`, then the Pad is the user's (◇) and `a` can no longer rewrite it. `a` may hand it over too. Another Agent `b` calling `pad.setOwner` fails with `FORBIDDEN`.

**P5 file-backed storage.** Given Pads `notes` and `plan`, when `pad.setStorage {files: true}` is called, then `pads/notes.md` and `plan.md` exist in the Project's data folder (N1) with the Pads' text, and later writes and appends update the files. When a file is edited on disk and `pad.setStorage {files: false}` is called, then the edit is imported into the Pad. Files are not added to any ignore list. In file mode the app database stays the source of truth and the files are a mirror: `pad.read` returns the database text, and edits made on disk are imported only when flipping back to app storage. Every file write is atomic (temp file then rename) and happens before the database change is committed, so a failure leaves nothing applied; `setStorage` records the new setting only after every file operation succeeded, so a retry redoes the work. A name the file system refuses is `INVALID_PARAMS`.

**P6 export.** Given a Pad, when `pad.export {name, path}` is called, then one `.md` file with the text is written to `path`, whatever the storage setting; a relative `path` is `INVALID_PARAMS` (the Daemon's working directory is not the caller's), and a path whose directory does not exist is an error, never a silent create.

**P7 persistence.** Given app-stored Pads, when `Pads::open` is called again on the same directory, then every Pad, its owner and text are intact.

**P8 names.** A Pad name containing `/`, `\`, `..`, a leading dot, or an empty string fails with `INVALID_PARAMS` for every method that takes a name.

**P9 delete.** Given Pad `notes` owned by `a`, when `a` or the user calls `pad.delete {name}`, then the Pad is gone (`pad.read` is `NOT_FOUND`), its file is removed when file-backed, `pad.changed {name}` is emitted and a `wrote` Touch on `pad:notes` is logged; any other Actor gets `FORBIDDEN`; the name is validated like every other (P8).

**P10 a rejected call leaves no trace, in either storage mode.** Given Pad `notes` owned by Agent `a` in app storage and again in file storage (P5), when another Actor's `pad.write` fails with `FORBIDDEN`, `pad.create` of `Notes` fails with `CONFLICT` (P1), and `pad.read`, `pad.append` and `pad.delete` of `../x` fail with `INVALID_PARAMS` (P8), then after each call `pad.read {name: "notes"}` returns the same text and owner, the Project's data folder `pads` (N1) holds exactly the files it held (none in app storage, no temp file left in file storage), no `pad.changed` arrived and no Touch was logged. A refused call to a Pad that is not there is `NOT_FOUND` and creates no file. Owns `crates/pads/**`. It keeps P1, P2, P5, P8 and P9 green and narrows none.

**P11 a Pad's Scribe may rewrite that Pad and no other Agent may.** Narrows P2; adds the RPC method `pad.ask {name, text}` (Contract recipe: every caller changes in the same PR; it sends Messages, so it touches M1, M5, M6 and M7 and leaves `proofs/messages` and `docs/messages.md` agreeing, with no law weakened). The right is a binding the Daemon writes, never a parameter a caller passes. Given Pad `notes` owned by the user or by Agent `a`, then:
- **Start.** `pad.ask` by the user with no Scribe for `notes` starts exactly one Agent (the Scribe, `GLOSSARY.md`) whose system prompt names the Pad, binds it to `notes`, and sends `text` to it as a `note` Message from `you` (B1); the result is `{agent, message}`. A second `pad.ask` while a Scribe exists starts none and sends one more Message to it; two concurrent first asks start one Scribe. A caller other than the user gets `FORBIDDEN`, an unknown name `NOT_FOUND`, an empty `text` or a name failing P8 `INVALID_PARAMS`, and each leaves no Agent, Message or Touch (P10).
- **Right.** `pad.write` on `notes` succeeds for its owner (P2) and for its Scribe, and fails `FORBIDDEN` with nothing changed for every other Agent, including `a` when the user owns `notes`, and including a Scribe of another Pad. The Scribe has no other right: it cannot `pad.setOwner`, `pad.delete`, `pad.setStorage` or `pad.ask`, and gains none for any other Pad. The binding is not the owner: `notes` keeps its owner and `a` can still rewrite it (P2, P4).
- **Touch.** Each Scribe write is a `wrote` Touch on `pad:notes` by the Scribe's id, `pad.changed` names that id as `actor`, and `provenance.history {item: "pad:notes"}` lists it, so the last-touch line (U190) names the Scribe's name.
- **End.** The binding and the Scribe's right end with the Pad (P9) and with the Scribe's removal; neither survives a Daemon restart without the Pad (P7). A Scribe whose Kind is `done` or `error` is replaced by the next ask, which Resumes its conversation when it has one (A22) and otherwise starts fresh.
- **Model.** Each Pad has its own Scribe and so its own conversation; an ask on `notes` never reaches `plan`'s Scribe.

Owns `crates/pads/**` and the method's wiring in the Daemon. Tests (`p11_`, Rust): the start and its one Scribe with its system prompt naming the Pad (`p11_start_prompt_names_pad`), `notes` and `plan` each reaching only their own Scribe (`p11_each_pad_its_own_scribe`), the binding gone after a Daemon restart without the Pad (`p11_binding_ends_with_pad_across_restart`), the concurrent first asks, each refusal and its absent trace, the `FORBIDDEN` matrix with a second Agent and a second Pad's Scribe, the Touch and `actor`, the ending on delete and removal, and the replacement after `error`. It keeps P1 to P10 green.

**P12 a Pad has a Home.** Found by the user's report #798: the Shelf cannot show a Workstream's own Pads because a Pad records no Workstream. Mirrors T12, T13 and T14 for Pads; closes `GLOSSARY.md` Pad's "Workstream-scoped storage is still open" for Home only (storage is unchanged). Contract change (Contract recipe of `.agents/builder.md`; the review run's approve covers it; every caller changes in the same PR): `Pad` gains `home: Option<String>`, `Some(<Rail id of a Workstream>)` or `None` for the Project root; `pad.move {name, home}` is a new RPC method; `crates/pads/**`, `crates/rupd`, `crates/contracts/**` with `contracts/generated/`, the `Pad` uses in `crates/rup/tests/e2e.rs` and the webview fixtures that build a `Pad` change with it; `GLOSSARY.md` Pad names Home. Given the Project, then:
- **Create.** `pad.create` gives `home: null`, except that the Daemon sets `home` to the nearest Workstream in the Rail ancestor chain (A16) of an Agent caller; the user, an Extension and an Agent under no Workstream give `null`; a `home` in the params is ignored, and the MCP tool schema (M1) is unchanged. `pad.list`, `pad.read` and `pad.changed`'s refetch carry `home`; `pad.write`, `pad.append`, `pad.setOwner`, `pad.setStorage` and `pad.export` never change it.
- **Move.** `pad.move {name: "notes", home: "r1"}` from the user or an Extension sets the Home, emits `pad.changed {name}` once and logs a `wrote` Touch on `pad:notes`; `home: null` returns it to the Project root; the same Home succeeds with no event and no Touch. An unknown name is `NOT_FOUND`; a `home` that is no Rail node is `NOT_FOUND`; one that is a Rail node but no Workstream is `INVALID_PARAMS`; a name P8 refuses is `INVALID_PARAMS`; an Agent caller is `FORBIDDEN` (M1 gains no `pad_move`). A rejected call leaves no trace (P10). The Daemon checks the Rail before it asks `crates/pads`.
- **Removal and persistence.** `rail.remove` of a Workstream gives each Pad whose Home it was `home: null`, with `pad.changed` per Pad in name order after the Workstream is gone, and deletes no Pad; a failed `rail.remove` changes none. The Home survives `Pads::open` (P7), and a `pads.db` written before this field reads `home: null` for each Pad (a nullable column by migration, as T12 does).
Tests (`p12_`): a Door's `pad.create` returns its Workstream's id and a nested Workstream gives the nearer one; the user, an Extension and an Agent under no Workstream give `null`; a `home` in the params is ignored; `pad.move` to a Workstream, back to `null`, to the same Home, to an unknown id, to an Agent's id, by an Agent, and an unknown name; the field survives `Pads::open`; a hand-written old database reads `null`; `rail.remove` resets it in name order; each rejected call leaves no trace. Observer: `pad.list` on a real `rupd` after a Door's `pad_create` in a Workstream reads that Workstream's id, again after the Daemon restarts on the same Project directory.

**P13 a Pad answers who its Scribe is.** Found by Issue #917: the Pad Drawer's exchange and the Rail's hiding of a working Scribe (U190 **Exchange**, **Rail**) can only come from `pad.ask`'s result, which the webview forgets on a restart. Narrows P11 **End** and U190; adds no RPC method. Contract change (Contract recipe of `.agents/builder.md`; the review run's approve covers it; every caller changes in the same PR): `Pad` gains `scribe: Option<String>`, the Rail id of the Pad's Scribe or `None`; it is read from the binding P11 writes (`Pads::scribe`, `crates/pads/src/lib.rs:37`), never a parameter: `pad.create` and every other Pad method ignore a `scribe` in their params, and the MCP tool schemas (M1) are unchanged. `crates/contracts/**` with `contracts/generated/`, `crates/pads/**`, `crates/rupd/**`, the `Pad` uses in `crates/rup/tests/e2e.rs`, and the webview fixtures that build a `Pad` change with it; `GLOSSARY.md` Scribe names the field. It touches no Message law: M1 to M10 stay as they are and `proofs/messages` and `docs/messages.md` are unchanged. Given Pad `notes`, then:
- **Answer.** `pad.list` and `pad.read` carry `scribe`: `null` until a Scribe is bound, then the id of the Agent `pad.ask` (P11 **Start**) started, and the id of its replacement after P11 **End**'s `error` or `done` replacement. A Scribe whose Kind is `done` or `error` is still the answer, so its exchange stays findable. The answer is `null` for a bound id that is no Rail node (the Scribe was removed), and `null` after `pad.delete`. Test `p13_scribe_field_follows_ask`.
- **Event.** The `pad.ask` that binds or rebinds a Scribe emits `pad.changed {name}` once, with the user as `actor`, so a webview refetches `scribe`; an ask that finds a live Scribe emits none; a rejected ask emits none (P10). `pad.write` by the Scribe keeps P11 **Touch**. Test `p13_bind_emits_one_changed`.
- **Persistence.** The answer survives a Daemon restart on the same Project directory while the Scribe is a Rail node (S5), and is `null` for a Pad whose Scribe is gone (P11 **End**). Test `p13_scribe_survives_restart`, and `p13_scribe_gone_reads_null`.
- **Not a right.** The field is not the owner: `owner` is unchanged, a `scribe` in `pad.create`, `pad.write`, `pad.setOwner` or `pad.move` params changes nothing, and a Scribe set by name in the params gives no right to write (P11 **Right**). Test `p13_scribe_param_is_ignored`.
- **Reader.** U190's implementation (#900) finds the Scribe from `Pad.scribe` and keeps no `pad.ask` result as the Scribe's memory; P13 builds none of the Drawer or the Rail, and #900 is blocked by P13's Issue (#919).
