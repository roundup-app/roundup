# UI: grouped native context menus (U4322a, U4322b)

Acceptance for #4322. Journey: Understand and Intervene, finding an action on the intended object without activating another row or interrupting Terminal input. This specification delivers no implementation.

**U4322a every context menu groups applicable actions.** Given an open Project, when the user opens an object's native context menu by pointer or its existing keyboard entry point, then its applicable actions appear in the following group order. A semicolon separates groups; a comma separates items within a group. Group names describe membership and are not inert menu headings.

| Surface | Ordered groups |
| --- | --- |
| Workstream row | run: Start or Retry, Restart, Start YOLO, Stop, Resume; open/share: Open directory, Open in editor, Send to Agent, Copy link; edit: Rename; add: Add submenu; remove: Remove |
| Agent row | run: Restart, Start YOLO, Stop, Resume; open/share: Open directory, Open in editor, Send to Agent, Copy link; edit: Rename; remove: Remove |
| Queued Workstream row | queue: Start now, Remove from queue, Move up, Move down; open/share: Open directory, Open in editor; add: Add submenu; remove: Remove |
| Project tab | copy: Copy (the existing Project-path copy); edit: Rename; close: Close |
| Terminal tab / Bubble | open/share: Send to Agent, Copy link; edit: Rename; close: Close |
| Pad in the Rail | open/share: Send to Agent, Copy link; delete: Delete |
| Pad in work items | open/share: Send to Agent, Copy link; delete: Delete |
| Todo in the Rail or work items | status: Complete; open/share: Send to Agent, Copy link; edit: Assign, Move, Move up, Move down; delete: Delete |
| Ask's published-output row | open/share: Send to Agent, Copy (the existing published-output copy) |

- **Separators and order.** Exactly one native separator splits adjacent nonempty groups, with none at either end or around an omitted group. Remove, Delete and Close each remain last and alone in their group. Existing Dismiss failure, where present, precedes the table's groups as its own recovery group. Keep the existing queue and reorder boundary rules; a menu does not gain an action its surface cannot perform. Planned mounted-App test: `u4322a_each_surface_projects_ordered_nonempty_groups`, extending `apps/desktop/src/rail/menu/u2694_menu.test.tsx`, opens every caller in the table, including Rail and work-item Pad/Todo variants and queued Workstreams, and asserts action ids, separator positions and submenu structure through `showContextMenu`, not rendered geometry or exact prose.
- **Availability.** An inapplicable action is absent, never greyed out. Omit unavailable submenu children and a submenu with no remaining children. Fixtures cover a running normal Agent, running YOLO Agent, stopped resumable Agent, stopped non-resumable Agent, Workstream without a Door, queued Workstream at each queue boundary, completed Todo, reorder boundaries, unchanged Home/owner and a Project with only the source Agent or an exited peer. Send to Agent offers only eligible other receivers under the existing source and Project rules; when none remain it is absent. Planned mounted-App test: `u4322a_inapplicable_actions_are_absent`, in the same suite, asserts absence and zero action calls from opening/dismissing each menu. Webview pickers outside these native menus retain their existing disabled-state policy.
- **One Add submenu.** A Workstream's creation group contains one Add submenu with Agent, Todo, Pad and Terminal children, in that order, filtered only by their existing eligibility. These use the existing creation flows and the clicked Workstream as Home; they do not start a supervisor. Start/Retry belongs to the run group and retains its existing start eligibility. Agent creation may open its existing form, Todo its capture field and Pad its existing editor; opening the submenu creates nothing. Planned mounted-App test: `u4322a_add_uses_the_clicked_workstream`, in the same suite, opens an unselected Workstream's menu while another is selected, chooses each child independently and completes its existing flow, asserting one creation at the clicked Home, no creation at the selected Home and no supervisor start. Missing wiring is implemented through the existing flows, not a new creation protocol (policy).
- **Copy (rendered policy).** Use short, sentence-case action labels, leading with a verb and retaining established user-label nouns: `Copy link`, `Open directory`, `Open in editor`, `Send to Agent`, `Rename`, `Remove`. Add `…` when choosing opens a dialog requiring further input or confirmation; an in-place rename does not acquire an ellipsis. The Add submenu is the noun-list exception: `Agent`, `Todo`, `Pad`, `Terminal`, with an ellipsis on any child that opens such a dialog. The native submenu arrow is system-owned, not a character appended to the label. No duplicate flat `Add Agent` remains. Start/Retry in a Workstream menu names its supervisor through the existing user-label copy. Authored names remain unchanged. Similar label lengths and scan quality are judged in the Mac observer below, not by padding labels or imposing a character-count test.

**U4322b shortcuts use the native column and preserve dispatch.** Given those menu models and the current keyboard bindings, when the host builds a menu or the user chooses an action, then:

- **Single-step shortcuts.** Every item with an expressible single-step chord carries a native accelerator, including Rename's F2 and Remove's ⌘⌫. Labels contain neither tabs nor appended chord text. An item with no binding gains no invented accelerator. Planned Rust test: `u4322b_items_carry_native_accelerators`, in `crates/desktop/src/menu.rs`, exercises the actual construction path and observes the accelerator supplied to the native API and the resulting plain label; it fails when the accelerator argument is removed, not merely when a test fixture changes.
- **Native structure.** Separators are native separator items and children become native submenus recursively, preserving the model's group order and selectable leaf ids. The context menu and Project menu share the construction path in `crates/desktop/src/menu.rs`; no parallel menu builder is added. Planned Rust test: `u4322b_native_groups_and_submenus_reach_the_menu`, in that file, builds a mixed menu and inspects native item kinds, order, nested membership and ids. Reuse the Project-menu grouping/accelerator work owned by #4278 (policy).
- **Sequences.** Existing two-step bindings, including the focused Terminal's ⌘K W, remain sequences: a separate right-aligned native hint, no accelerator for the sequence, second key or substitute chord, and no tab/chord appended to the label. Use the same native hint facility as the Project menu. Planned Rust test: `u4322b_sequences_remain_hints`, through the shared construction path, observes a separate hint and no registered accelerator. Alignment is rendered policy; retain the current binding from the action registry rather than copying a second shortcut inventory (policy).
- **One chosen action.** Choosing a leaf by pointer or menu keyboard activation runs its existing action exactly once on the menu's object, including a nested leaf. A native accelerator and webview listener do not double-dispatch. Opening, opening a submenu and dismissal run nothing; a separator or submenu container cannot dispatch an action. Popup accelerators do not install persistent menu-bar/global shortcuts after dismissal. Planned mounted-App test: `u4322b_native_choice_dispatches_once`, in `apps/desktop/src/rail/menu/u2694_menu.test.tsx`, covers nested choice, dismissal and the combined native-event/webview route, asserting exact targets and call counts. Planned Rust test: `u4322b_popup_accelerators_stay_in_the_popup`, in `crates/desktop/src/menu.rs`, verifies the popup's accelerator-bearing items are absent from the installed application menu. Keep the existing focused-row menu keys and pane/Terminal key ownership; the native observer below covers actual OS key routing (policy).
