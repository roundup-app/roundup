# Text selection

Work Issue: #2680. Journey stage: Intervene — select and copy Terminal output, then return to the App without a lingering highlight. Terms: Terminal, Bubble, Door, Rail, Shelf, Pad, Todo (`GLOSSARY.md`). This specification changes no contract, RPC method, App seam command, Token or domain term.

**U2680a Terminal drags never create browser selection.** Given output containing several words in each of a Bubble Terminal, an Agent's centre-pane Terminal and a Door's Terminal, when the user drags with the primary mouse button, then:

- A drag across output selects nonempty text through the Terminal emulator, while `window.getSelection()` stays collapsed. A double-click on a word selects that word through the emulator and leaves browser selection collapsed. Test: `u2680a_output_drag_and_double_click_use_only_terminal_selection`, parameterised by the three placements.
- Drags starting in each Terminal's insets, the strip below its last drawn row, and the unused part of its final cell or space after its last column never create browser selection, including when they end over output, the Bubble header, the pane outside the Bubble or the Rail. Drags from output to each of those areas, and reverse drags into output, also leave browser selection collapsed. The Bubble header applies only to the Bubble placement; the other cases apply to all three placements. Test: `u2680a_terminal_boundaries_never_create_browser_selection`, parameterised by placement, start and end area. It asserts browser selection only; a drag through blank space need not select Terminal text.

**U2680b one click clears old selections throughout the App.** Given a nonempty emulator selection and a stray noncollapsed browser selection, when the user makes a primary-button click anywhere in the App, then both are empty after that click. Cover an output row, the Terminal insets and bottom strip, a Bubble header and every resize edge, the pane, Rail, Shelf, window title bar, bottom bar and shortcut hint line, including targets whose handlers prevent default or stop propagation. Apply the Terminal cases to all three placements in U2680a. Test: `u2680b_a_click_clears_browser_and_terminal_selections`, parameterised by target and placement; install a browser Range as setup when chrome cannot be selected through gestures. Assert the emulator's selection is empty even if an outside click minimises its Bubble; restore it and assert it stays empty. Test: `u2680b_minimising_and_restoring_does_not_restore_selection`.

An old selection clears without cancelling the clicked control's action or a new drag, double-click or editable-field selection. A new gesture may establish its own selection after the old one clears. In particular, U515/U516's selection actions still send the selected Excerpt once, and U101's keyboard copy still copies a selected Terminal's text. Test: `u2680b_selection_actions_keep_the_excerpt_and_clear_the_highlight` (click the existing selection action with a known Excerpt; assert the receiving call and empty selection). U2680a's gesture tests and U2680d's editor tests prove new selection remains possible. Existing U101 tests in `apps/desktop/src/terminal/u101_copy_paste.test.tsx` retain the keyboard-copy contract (policy: keep passing).

**U2680c chrome cannot be selected as browser text.** Given the rendered App, when the user drags across or double-clicks chrome text, then browser selection remains collapsed. Cover the window title, Project and Terminal tabs, the Managed chip where present, Rail rows and buttons, Shelf tabs and section heads, the Todo button and nonediting Todo titles, bottom-bar Terminal action and resource readouts, shortcut hints, overview headings and empty-state titles and hints. Include drags from the centre pane across the Shelf and from the blank Bubbles layer past the last Terminal column into the pane. Test: `u2680c_chrome_drag_and_double_click_leave_no_browser_selection`, parameterised by surface and gesture. A double-click that starts renaming is tested before selecting text within the resulting editor; entering rename remains allowed.

**U2680d editable text remains selectable and copyable.** Given a Pad editor, a text input, a Todo title in edit mode or a name in rename mode, when the user drags across text or double-clicks a word, then that editor holds the selected text; copying it yields that text. For an input, observe `selectionStart`/`selectionEnd`; for a document editor observe its selected text. Clicking elsewhere clears the old selection as U2680b says, without changing the edited value. Test: `u2680d_editors_keep_native_selection_and_copy`, parameterised by the four editor kinds and both gestures. Test: `u2680d_leaving_an_editor_clears_selection_without_changing_text`, parameterised by editor kind. These exceptions apply within chrome and floating editors as well as the centre pane.

## Observer and bounds

All named tests are planned behavioral regressions, not claims of existing coverage. Use isolated headless Chromium and WebKit at 1512×950 with the real xterm emulator; do not substitute a selection mock or assert CSS declarations. Use the U26 fake-Daemon harness for App gestures and editable controls, with `tree-40`, `bubbles` and the appropriate empty states (`.agents/data/harness.md`). Exercise the App's WebGL renderer on `just harness-real` with real `rupd` and a live shell for U2680a and U2680b as well as the fake harness's DOM renderer. Record the renderer actually used; a fallback does not prove WebGL. Terminal selection is read through the existing emulator instance; browser selection through `getSelection()`. Gesture coordinates locate the named areas but no test asserts position, layout, colour or exact copy. Each test must fail when its named selection behavior breaks (rule 10).

Implementation scope (policy): `apps/desktop/src/terminal/`, `bubbles/`, and the App shell/global styles plus affected Shelf, header, bar and empty-state surfaces and their behavioral observers. #2680 explicitly authorizes these module boundaries together. Reuse the existing emulator and App event handling; this specification requires no new parser, store, protocol or interaction primitive. Rule 9 research applies before implementation adds machinery. Keep Terminal input, output, keyboard copy/paste, Bubble move/resize/minimise and control activation working; no selection-clearing gesture writes Terminal input except the existing control's intended action (policy: existing scenario tests keep passing).

Rendered policy: introduce no regression to Checks 2, 5 and 6 in `docs/design-system.md`, heading `The checks` (D2 spacing/type, D5 contrast, D6 control states and hit targets). These Checks already hold the visual requirements; this work changes selection behavior and adds no visual design. The implementation's design critic observes dark, the densest `tree-40` seed and visible failure text, using `.agents/data/harness.md`. Linux/Chromium/WebKit evidence makes no native macOS claim; the user reports what they meet on the Mac. No new per-PR Mac observation gate is required.
