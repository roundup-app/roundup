For the scroll: `@pierre/diffs` 1.6.1 `CodeView` first (an item for each file, `scrollTo`, `setSelectedLines`, sticky headers), then its `Virtualizer` with one `VirtualizedFileDiff` for each file as `DiffReader.tsx` uses them; a stacker of our own only when both fail, naming what they lack, for example reading one file's contents only when it nears the view. **U7678a the list groups the change by module.** Given the open Changes view and the fake App's `agent.changedFiles`, then:
- **Modules.** The list holds one row for each module (U7678b) in path order, each with its name, its file count and `+added -removed`, the sums of its files' `counts` (U7610a). A file whose `counts` is `null` adds to the file count and to no sum; a module of such files shows no sums. With several repository groups the list is the open group's (U7674a's switcher stays). Asserted in `u7678a_the_list_groups_files_by_module_with_summed_counts`.
- **Files inside.** A file shows only inside its module, folded at first; unfolding shows each file's name and its own counts (U7674c). No file row stands at the top of the list. Asserted in `u7678a_files_show_only_inside_their_module_folded_at_first`.
- **Up and Down.** A module row that takes focus opens its scroll (U7678c); a file row opens as U7678c's "A file row" says; a noise row (U7678b) opens nothing and the open scroll stays. Asserted in `u7678a_up_and_down_open_the_module_that_takes_focus`, replacing `u7674a_up_and_down_open_the_next_and_previous_file`.
- **Unfinished work.** A file's unfinished note (U7676c) marks its module's row and not the file's row, with the same label for assistive tech; a file under a noise row marks that noise row. Asserted in `u7678a_unfinished_work_marks_its_module_row_or_its_noise_row`, which replaces the file-row half of `u7676c_unfinished_work_survives_a_file_switch_and_marks_its_row`.
- **A module leaves.** When the open module's last file leaves the list, the pane says "<module> no longer differs from <From>" and focus moves to its neighbour module, the next, else the previous, else the view's empty state (U7675a), as U7675c does for a file. Asserted in `u7678a_when_the_open_module_leaves_focus_moves_to_its_neighbour`, replacing `u7675c_when_the_open_file_leaves_focus_moves_to_its_neighbour`.

**U7678b three rules read a file's module, its kind and its row from its path alone.** Given a changed file's `path`, a renamed file's new path and a deleted file's last path, then:
- **Module.** The module is the file's directory with trailing `src`, `lib`, `test`, `tests`, `__tests__` and `spec` segments dropped, again and again until none ends it; a file whose directory drops to nothing belongs to "Top level". So `crates/x/src/b.rs` and `crates/x/tests/a.rs` share `crates/x`, `apps/desktop/src/changes/A.tsx` and its `A.test.tsx` share `apps/desktop/src/changes`, and `README.md` is Top level. A file renamed across directories belongs to its new path's module, and its notice names the old path (U7675b). The name depends on the file's own path only, never on the other files, so a module's name never changes as files come and go. Asserted in `u7678b_a_files_module_comes_from_its_path_alone`.
- **Test or logic.** A file is a test when a directory segment is `test`, `tests`, `__tests__` or `spec`, or its name contains `.test.` or `.spec.`, ends in `_test` or `_spec` before its extension, or begins with `test_`; every other file is logic. One function holds the rule, and #7679's Logic and Tests lenses read it, never a copy. Asserted in `u7678b_a_test_is_told_from_logic_by_its_path`.
- **Noise.** A file is a lockfile when its name is `go.sum` or `bun.lockb` or ends in `.lock`, `-lock.json` or `-lock.yaml`; any other file is generated when a directory segment is `generated`, `__generated__` or `autogenerated`, or its name contains `.generated.` or ends in `.min.js` or `.min.css`. A noise file belongs to no module. Asserted in `u7678b_lockfiles_and_generated_files_are_noise`.
- **Noise rows.** The list ends with one quiet row for each kind the change holds, "Generated · N files" and then "Lockfiles · N files" ("Generated · 1 file" for one), and none for a kind it lacks. A noise row is not a module: it shows no counts, opens no scroll, and J and K skip it. It unfolds to its files; choosing one opens that file's diff alone, which keeps its own scroll and line like a module (U7678d). A noise file never enters a module's scroll or its reads. Asserted in `u7678b_noise_folds_to_quiet_rows_whose_files_open_alone`.

**U7678c a module opens as one scroll of its hunks.** Given a module of several files and the fake App's `agent.compareFile`, then:
- **One scroll, logic first.** Choosing a module opens one scroll of every hunk of its files, the logic files in path order and then the test files in path order, each file's hunks under a header for that file (its path, state and counts). It is never a file-by-file diff, and it holds no file of another module. Asserted in `u7678c_a_module_opens_as_one_scroll_with_logic_before_tests`.
- **Hunk header.** Each hunk carries its function in its own header, under its file's header. The function is the nearest line above the hunk's first old line that starts with a letter, `_` or `$`, cut to 80 characters, which is the line git's default hunk header chooses; a hunk with no such line above it names no function. Decided here: the reader builds its patches from the compared text (`diffDraw.ts`), so the function comes from that text with no Daemon change, and a repository's own `diff` drivers are not read. The library draws a hunk's context only in a separator that cannot reveal lines, so the reader draws the function beside the count of the fold above the hunk (a hunk at the top of its file has no fold above it and names none on screen). Asserted in `u7678c_each_hunk_header_names_its_file_and_function` for the rule and `u7678c_a_fold_names_the_function_of_the_hunk_below_it`, in `u7692_rendered.test.ts`, for the drawing.
- **Reads.** Opening a module reads `agent.compareFile` only for the files the scroll reports in view (the library's own report) and the one after them; scrolling reads each file it newly reports once, and a file never reported is never read. Until read, a file's section holds its header and a place sized from its `counts`. A module of 100 files makes fewer than 100 reads at open, and the renderer chunk stays lazy (U2540d). Asserted in `u7678c_opening_a_module_reads_only_the_files_its_first_screen_shows`, which drives that report for the first files only, as `u2540a_reader.test.tsx` drives Pierre's callbacks, and asserts every call names one of them; it replaces `u7674e_opening_requests_only_the_first_files_comparison` and the "first file" half of `u7610b_opening_the_list_never_calls_compare_file`.
- **File states.** Each file state of U7675b (loading, added, deleted, renamed, binary, mode only, whitespace only, too large, changed on disk, left the list), an image (U7694b) and a failed read with Retry (U80) draws as that file's notice or pictures inside its section; Reload, Show anyway and Retry act on that file alone, the 10,000-line fallback holds for each file (U5646c), and an image's pictures are released when its module closes. Asserted in `u7678c_one_files_notice_leaves_the_other_sections_alone`; the states themselves stay in the `u7675b_*` tests, `u7675c_when_the_open_file_leaves_its_pane_says_so` and the `u7694b_*` tests, edited to drive a module's scroll.
- **Notes.** The gutter +, N, a drag and Shift-click work inside the scroll as U7676 builds them. A note keeps the file, side and line it was made on, a range never spans two files, and the Message names that file (U2540b, U2540c). Asserted in `u7678c_a_note_made_in_a_scroll_keeps_its_file_side_and_line`.
- **Reveals.** V reveals the fold nearest the focused line in that line's own file (U7692b). A file's reveals stay while its module stays the open one, also when the file scrolls out of view and back, and fold again on a module switch, Reload or a changed comparison (U7692a). Asserted in `u7692a_reveals_stay_across_a_note_and_a_refresh_and_fold_again_on_a_file_switch`, edited to a module switch and a scroll away and back.
- **Editor.** Enter or a double click on a hunk opens its file in the editor at that line (U2539d). Asserted in `u7678c_enter_or_a_double_click_on_a_hunk_opens_its_file_in_the_editor`.
- **A file row.** Choosing a file row opens its module's scroll at that file's first hunk; no file above it is read. Decided here, as the Issue's reading. Asserted in `u7678c_a_file_row_opens_its_modules_scroll_at_that_files_first_hunk`.
- **No fold inside a hunk.** `@pierre/diffs` 1.6.1 cannot fold a run of lines inside a hunk, so noise folds at file level (U7678b) and a hunk shows whole; a fold inside a hunk waits for the library (`scenarios/ui-changes-reveal.md` says the same). Policy.

**U7678d the keys move between modules and across a module's files, and each module keeps its place.** Given the open view with no note field, text input or editor holding focus, then:
- **J and K.** J opens the next module and K the previous, in list order, from the list or the diff alike, and both stop at the last and first module. Noise rows are not modules: with a noise file open J does nothing and K opens the last module. Asserted in `u7678d_j_and_k_step_modules_and_skip_noise_rows`, replacing `u7675e_j_and_k_step_files_from_anywhere`.
- **] and [.** `]` moves the focused line to the first line of the next change in the scroll, from a file's last change on to the next file's first (reading that file when unread, U7678c), and `[` to the previous; both scroll it into view and stop at the module's last and first change. In a noise file they stay in that file. Asserted in `u7678d_bracket_keys_step_changes_across_a_modules_files`, replacing `u7675e_bracket_keys_step_changes`.
- **Places.** Each module keeps its scroll offset and focused line across switches, as does an open noise file, in the App's memory for the run only, so nothing stored is migrated; a module never opened starts at its top. A file that changes on disk keeps its module's place and offers Reload (U7675b). Asserted in `u7678d_each_module_keeps_its_scroll_and_line_across_switches`, replacing `u7675d_a_file_keeps_its_scroll_and_line_across_switches`.
- **Opening and reopening.** The view opens on the first module, scrolled to its top, with focus in the list. Closing and reopening restores the open module at its scroll and line while it stays in the list, else the first module opens (U7675f). Asserted in `u7678d_the_view_opens_on_the_first_module_at_its_top`, replacing `u7674a_the_first_file_opens_and_focus_lands_in_the_tree`, and `u7675f_reopening_restores_the_open_file_its_scroll_and_line`, edited to the module.
- **The rest as #7675.** Left and Right fold or unfold a module, Tab goes from the list to the module's focused line, Enter opens the editor, Esc closes the ? list before the view, and the ? list shows J and K as the next and previous module (`u7675e_left_and_right_fold_a_folder`, `u7675e_tab_moves_from_the_list_to_the_diff` and `u7675e_question_mark_lists_the_keys`, edited). Typing in a note field blocks every key (`u7675e_keys_do_not_fire_while_typing_in_a_note_field`, kept). No key action animates: a scroll or focus change is instant. Policy; the design critic judges it (U7678e).

**U7678e the rendered list and scroll at 1512 by 950 and at 388 px.** Given the U26 harness, dark App, on the dense fixture (500 changed files, a 120-character path) and on a 14-module fixture, then these draw: the module list with its sums, a module's scroll with its hunk headers, a file's notice inside the scroll, the noise rows folded and unfolded, a module row marked for unfinished work, and the worst cases (a 120-character module name, a one-letter name, an emoji name, a module of 100 files, 0 files).
