# The user marks a `needs-you` done (U7915a to U7915e)

Module: `apps/desktop/src/rail` and `apps/desktop/src/state`. Ids: U7915a to U7915e. Work order: [#7915](https://github.com/roundup-app/roundup/issues/7915). Journey: Understand → Intervene (`.agents/data/journey.md`).

Source: the owner, 2026-11-24: "there should always be a way for the user to mark needs input like these as checked/done". A plain report that closed with "stays your call" showed the amber dot, and only the Agent's next turn could clear it (A7180c). This amends A7180c, U5502 and U3566a only so far as the owner may clear a `needs-you` mark by choice; opening an Agent still leaves it set. Words: **Mark done** is the action; a **mark** is a `needs-you` Status the owner marked done. It reuses U5151c's dismissal: the same key (Agent id, Attempt, Status revision), the same per-Project storage, no new RPC, no contract change and no new Status kind. The implementation PR adds the code term for the action to `GLOSSARY.md`.

**U7915a click the dot to mark done.** Given a row without a fold arrow showing `needs-you`, then hovering its dot shows the tooltip `Mark done`, and one click clears the mark: the dot shows the grey idle ring. The click only clears the mark: it does not select the row, start a turn, send a Message or type into the Agent, and the Agent's pane and any native prompt in it stay as they were. A dot of any other Kind has no such click. Tests: `u7915a_clicking_the_needs_you_dot_marks_it_done`, `u7915a_the_click_selects_nothing_and_sends_nothing`. Observer: the rendered Rail with a fake seam, counting turn-producing calls, selection and Terminal writes.

**U7915b a row that folds marks done from its menu.** Given a row that folds (a Workstream, a Mode holding Agents) showing `needs-you`, then hover keeps showing the fold arrow and the arrow keeps folding; the dot has no Mark done click. Its right-click menu offers `Mark done`. On a folded row the action also clears the marks of the Agents folded under it, so the rolled-up dot (`rollup.ts`) shows idle; on an open row it clears that row's own. Tests: `u7915b_the_fold_arrow_still_folds_an_amber_row`, `u7915b_mark_done_in_a_folded_rows_menu_clears_its_agents`. Observer: the rendered Rail with a folded Workstream holding two amber Agents and one idle. **No unclearable item (#7970).** An item whose `attempt` or `status_revision` is null (an Agent the Daemon has not stamped) can be marked done and, in `error`, dismissed as any other: its key falls back to the Agent id with its status's `since` in place of each null part, so a new status brings it back (U7915e), and the Project tab's mark and the Rail clear at once. Tests: `u7915b_an_error_agent_with_a_null_status_revision_can_be_dismissed`, `u7915b_a_null_revision_needs_you_marks_done_and_returns_on_a_new_status`.

**U7915c every amber row's menu offers it.** Given any row showing `needs-you`, then its right-click menu offers `Mark done`, beside `Dismiss error` when that row also shows one; a row not showing `needs-you` offers none. It works on every amber dot, including an Agent waiting at a native prompt (a permission request or an `AskUserQuestion` dialog): the prompt stays in the Agent's pane until the user answers it, and the choice sends nothing to it. Tests: `u7915c_the_menu_offers_mark_done_only_while_needs_you`, `u7915c_a_native_prompt_stays_after_mark_done`. Observer: the rendered Rail with a fake seam.

**U7915d a cleared mark leaves every list and stays cleared.** Given a marked-done `needs-you`, then it leaves everything `attentionList` feeds (the menu bar's Waiting rows, the Dock badge, tab counts, Needs you and Jump), through the same dismissed set U5151c uses, and the counts drop at once. The mark binds to Project, Agent, Attempt and Status revision, survives a remount and an App restart for that same Status, and marking one Agent or Project never clears another's. Tests: `u7915d_a_marked_done_needs_you_leaves_the_attention_list`, `u7915d_the_mark_survives_a_restart_and_stays_scoped`. Observer: the production state module over real storage doubles and `attentionList`, two Agents in two Projects, a remount.

**U7915e the Agent's next needs-you brings the dot back.** Given a marked-done Agent, when it reports a new `needs-you` (a new Status revision), then the amber dot and its attention entries return and `Mark done` is offered again. Test: `u7915e_a_new_needs_you_shows_again`. Observer: ordered Status events through the production state module.

Policy: the dismissal storage is U5151c's; if it cannot save, U5151e's recovery line covers it, with `Mark done` named in place of `Dismiss error`. Gates (policy): P3 — the mark removes attention only, never answers or resolves a request, discards a draft or claims work done; P9 — zero turn-producing calls; P12 — row identity unchanged. UI copy is `Mark done`; the dot's tooltip and the menu item use these words alone.
