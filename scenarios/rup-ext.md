# The `rup` command line for a user and an outside Claude Code

Module: `crates/rup` (`ping`, `help`, the `--as` and `--json` options), with `crates/rupd` (the `daemon.ping` reply). Ids: CL1–CL4. `scenarios/cli.md` (I1–I8) owns the command tree, `rup help` and the exit codes; this file adds `ping`'s line and the `--as` option, and where the two meet, I1–I8 hold.

The owner switches to roundup from their own terminal, and drives it from a Claude Code started outside roundup. Neither is an Agent: the Daemon knows an Agent by walking the caller's parent processes to a running Agent, so every other `rup` call acts as the User, and only `rup mcp <agent-id>` can name a caller. `rup` reaches the Daemon at `RUPD_SOCKET`, else `~/.roundup/rupd.sock`. Tests start the built `rup` (`CARGO_BIN_EXE_rup`) against an in-process Daemon on a temp socket, as `crates/rup/tests/ping.rs` does. No `claude` is involved.

**CL1 ping says which Daemon it reached.** Given a Daemon opened on a Project folder and serving a socket, when `rup ping` runs with `RUPD_SOCKET` set to that socket, then it exits 0 and prints one line `rupd <pid> at <socket> for <project folder>` (policy: the words and order), with the Daemon's process id, the socket path `rup` connected to and the Project folder the Daemon was opened on; the Daemon's `daemon.ping` reply gains `pid` and `project` (the absolute folder) beside `pong` and `contract` (`cl1_ping_names_the_daemon_its_socket_and_its_project`). Given `RUPD_SOCKET` unset and no Daemon on `~/.roundup/rupd.sock`, then `rup ping` exits 1 with one stderr line naming that default path, so a shell that does not reach the App's Daemon shows it at once (`cl1_ping_without_a_daemon_names_the_default_socket`). `rup ping --json` prints one JSON object `{actor, socket, result}` (CL2) where `result` is the unchanged `daemon.ping` reply (`cl1_ping_json_holds_the_actor_the_socket_and_the_reply`). The line replaces the old output `{"result": …}`; nothing else in the repository reads it.

**CL2 `--as ext:<name>` acts as an Ext Actor.** Given a Daemon, when `rup --as ext:claude-code mcp` runs (the option comes before the command) and an MCP client calls `todo_create {title: "x"}`, then the Todo's `wrote` Touch has actor `{kind: ext, id: "ext:claude-code", parent: null}` and not the User's `you` (`cl2_an_ext_actor_mcp_call_is_a_touch_under_its_name`). `rup` sends `daemon.identify` with that Actor before its first call, and for `rup mcp` with no agent id it serves the tools of a non-Door caller. `<name>` is 1 to 64 characters of lowercase letters, digits, `-` and `_`; any other name, an empty one, or `--as` with a value that does not start `ext:` exits 2 with a stderr line naming the rule and sends nothing to the Daemon (`cl2_a_bad_actor_name_exits_2_and_sends_nothing`). `--as` before `signal`, `context` or `permission` exits 1 with a stderr line saying those are Agent hooks (they never exit 2, H8, E3, H15), and `rup mcp <agent-id>` with `--as` exits 2: an Agent id and an Ext name cannot both be given (`cl2_as_with_an_agent_command_is_refused`). With `--json`, `rup ping` prints `actor` as `{kind: "ext", id: "ext:<name>", parent: null}`, and as `{kind: "user", id: "you", parent: null}` when `--as` is absent (`cl2_json_prints_who_rup_acted_as`). `--json` before any command other than `ping` exits 2, since `mcp` owns stdout for the protocol. A caller that is below a running Agent stays that Agent whatever `--as` says (the Daemon's rule for `terminal.write` and held actions, H21); no new check.

**CL3 an Ext Actor's reach is the Daemon's, not the caller's.** Given the Daemon's present rules, when an Ext Actor calls `agent.context` or `agent.brief` for an Agent, or `agent.actionHistory`, then each is `FORBIDDEN`, unchanged; every `todo.*`, `pad.*`, `message.*` and `decision.*` tool that M1 offers the Daemon accepts from the User is accepted from the Ext Actor, and its Touch names the Ext Actor; and a call the User needs the `daemon_proof` for (`decision.answer`, H4) is refused to an Ext Actor without it (`cl3_an_ext_actor_is_forbidden_what_the_daemon_forbids_it`, `cl3_an_ext_actor_todo_and_pad_calls_touch_under_its_name`, `cl3_an_ext_actor_decision_answer_needs_the_proof`). The tests record what the Daemon does today; a method the Builder finds that the Daemon refuses the Ext Actor but `rup help` (CL4) would list is a defect in CL4's list, never a change to the Daemon.

**CL4 `rup help` states who may run what.** On top of I2's text, when `rup help`, `rup --help` or `rup` with no command runs, then it prints to stdout and exits 0 (`rup` with no command also exits 0, replacing the old exit 2) a text with one line per command (`ping`, `mcp`, `signal`, `context`, `permission`, `help`) and under each the words `User` and `Ext` saying whether a shell outside every Agent (the User) and `--as ext:<name>` may run it: `ping` and `mcp` both; `signal`, `context` and `permission` neither, because Claude Code runs them as an Agent's hooks and they need an Agent id. It also names `--as`, `--json`, `RUPD_SOCKET` and the default `~/.roundup/rupd.sock`, and says that `rup ping` shows which Daemon answered (`cl4_help_lists_each_command_and_who_may_run_it`). An unknown command still exits 2 with its stderr line and the same text after it (`cl4_an_unknown_command_exits_2_with_the_help`). Policy: the owner's request for "full parity with the MCP" is met by `rup mcp` being the parity surface for both; a command per tool is not built here.
