# Call paths: which calls an Agent added, removed or changed, read from the code (CP1–CP7)

Module: `crates/agents` (one module: the language-server client, the server table, hunk-to-symbol mapping, call sets, the export cache), `crates/contracts`, `crates/rupd` (route and policy). Ids: CP1, CP2, CP3, CP4, CP5, CP6, CP7. Work order: [#7681](https://github.com/roundup-app/roundup/issues/7681), blocked by #7680. Rust is #7682; the Flows lens that draws the result is #7683; the symbol list is #7695; marking moves is #7696.

Owner, 2026-11-18 and 2026-11-19: a tree shows which function calls were added, removed or changed between the old and the new code, read from the code with no model; call paths are built before the readback so Flows is never empty; proper tools resolve each call to its real symbol, never by name matching. Precedence: when a design check reads one of these as a defect, the drawing changes, never the decision.

Contract change (rule 4): `agent.callPaths` is a new Daemon method and the Daemon starts a child process, so "no new Daemon method" does not hold. Every caller changes in the implementation PR: `contracts/generated/` (regenerated, never hand-edited), `crates/rupd/src/route/policy.rs`, `crates/perf/tests/large_project.rs` and `crates/rup` where they list methods, `scenarios/rpc.md`, `docs/worktrees.md`, the fake App (`apps/desktop/src/testing/fakeApp.ts`, `apps/desktop/src/state/connectedProject.ts`) and `GLOSSARY.md` (**Call path**, user label Flow; **Language server**). The implementation PR's `Reuse:` section is required: the engine is each project's own language server, TypeScript 7's `tsc --lsp -stdio` here; for the client it weighs `lsp-types` 0.97.0 (types only, last release 2024-06-04, which #7704 counts as a failure for the same crate, so it stands only if every newer candidate lacks a type the client needs and the PR names it), `ls-types` 0.0.6, `async-lsp` 0.2.4 and `lsp-server` 0.10.0, reading each one's client support and licence; and it records the rejected call-edge tools with one reason each: SCIP (no call role, two full indexes per run), stack-graphs (archived), codegraph 1.6.2 (matches by name), calldiff and plannotator's CallDiff (syntactic), tree-sitter queries and ast-grep (syntax only). It measures the Daemon's native size change (C9b) if it adds a crate.

Decisions this specification takes, each held by a scenario below:
- One request per language, so one language's answer never waits for another's (CP1).
- A project on TypeScript 6 or older answers no server with its cause (`tsserver` speaks its own protocol, not LSP; a second client is not built here). Only projects on TypeScript 7 or later get flows; the tsserver client is a separate Issue if the owner wants it.
- Limits, set from the 2026-11-19 measurement on this repo (TypeScript 7.0.2: 310-414 ms and 543-644 MB peak per tree, a cold first query 163-388 ms, `outgoingCalls` for `App` 147 callees in 37 ms): a request ends at 30 s as failed; a symbol's calls in one direction are counted past 200 (outgoing) and 500 (incoming; `rpc` here has 205 callers in 122 files); a tree follows calls through changed functions to depth 6; a result a cap cut says `capped: true`.
- A **symbol key** is `(path, container names, name, kind)`, never a line. A call is keyed by its caller's key, its callee's key and the call site's text and enclosing symbol.
- Cache: `<Daemon cache directory>/call-paths/<merge-base commit>/`, the last 4 merge bases kept, oldest evicted when a fifth is written; an entry is exported into a sibling temporary directory and renamed whole, so a crash leaves no entry, and a directory without its `complete` marker is deleted and rebuilt.

Observer: Rust tests on Linux in real temporary git repositories with an origin and the real `tsc --lsp` from `node_modules`; the scenario names the real server, so rule 10 allows the process, and a missing server fails a test, never skips it. `just perf` for CP7's budget. Never a native Mac capture. No layout or looks are tested (rule 10).

**CP1 `agent.callPaths` answers per language: done, no server or failed.** Params `{id, to, language?}` with `to` a Compare target (U7672a). Given an Agent whose changed files (`agent.changedFiles`) hold TypeScript, then:
- **Lookup.** Without `language` the reply is `{languages: [{language, files, server}]}`, one row per language the changed files hold, with `files` the changed-file count and `server` either `{found: true, name, version}` or `{found: false, cause}`; the lookup starts no process and the App keeps no extension table. Asserted in `cp1_the_lookup_lists_languages_and_starts_no_process`.
- **Answer.** With `language`, the reply is `{state: "done", symbols, flows, capped}`, `{state: "noServer", cause}` or `{state: "failed", cause}`. Asserted in `cp1_a_language_answers_done_no_server_or_failed`.
- **A server counts only with call hierarchy.** The server found is `tsc` in the project's `node_modules/.bin`, then on PATH, run as `--lsp -stdio`; it counts only when its initialize answer advertises `callHierarchyProvider`. Otherwise `noServer` with the cause `notInstalled`, `predates` (naming the version: "TypeScript <version> predates `tsc --lsp`; 7 or later is needed") or `noCallHierarchy`. A project on TypeScript 6 or older, and a project with no TypeScript, start nothing past a version read. Asserted in `cp1_a_project_without_a_typescript_7_server_answers_no_server_with_its_cause`.
- **Never guessed.** A language with no row in the server table answers `noServer` with `notInstalled` naming the language, never a guess. Rust's row is `scenarios/call-paths-rust.md` (RA1); the test uses a language with no row, such as Go. Asserted in `cp1_a_language_with_no_server_row_is_reported_as_that`.
- **Independent languages.** One request names one language, so a language's reply never waits for another's: see CP5's serial run.

**CP2 each changed hunk maps to its innermost symbol.** Given one commit that edits a function, a method, a type and a top-level statement in one TypeScript file and adds a new function in another, then `symbols` carries one entry per changed symbol, `{key, name, kind, path, old, new, status, callable}`, where `old` and `new` are the symbol's ranges on each side or `null`:
- **Which side.** A removed line maps through the old side's `textDocument/documentSymbol` and an added line through the new side's, to the innermost symbol around it. `status` is `added` (new side only), `removed` (old side only) or `changed` (both). Asserted in `cp2_a_hunk_maps_to_the_innermost_symbol_on_its_side_with_a_status`.
- **Callable.** A symbol the server prepares as callable (`prepareCallHierarchy`) is a changed function with `callable: true`; a function and a method each carry name and kind. Asserted in `cp2_a_changed_function_and_method_carry_name_and_kind`.
- **No call path.** A hunk in a type, a field or top-level code is a changed symbol with `callable: false` and no call path. Asserted in `cp2_a_hunk_in_a_type_or_at_top_level_is_a_symbol_with_no_call_path`.
- **A file with no hunk, or a binary.** Neither adds a symbol. Asserted in `cp2_a_rename_without_edits_and_a_binary_file_add_no_symbol`.

**CP3 each changed function's calls are added, removed, changed or unchanged.** For each changed function, `outgoingCalls` and `incomingCalls` are read on both sides and keyed by the symbol key and the call site, never by line. Given a commit that adds a call, removes one, edits the line of a third and leaves a fourth alone, then:
- **Status.** The calls read `added` (new side only), `removed` (old side only), `changed` (both sides, the call site on a changed line) and `unchanged` (both, not on a changed line). Asserted in `cp3_a_commit_that_adds_removes_and_edits_calls_lists_each_with_its_status`.
- **A moved line is no change.** A call whose line number moved because lines were added above it reads `unchanged`. Asserted in `cp3_a_call_that_only_moved_lines_is_unchanged`.
- **No name matching.** Two functions of one name in different files are never joined: a call to one that becomes a call to the other reads as one removal and one addition. Asserted in `cp3_two_functions_of_one_name_in_different_files_are_never_joined`.
- **Filtered and deduplicated.** A callee in the standard library or under `node_modules` is not listed; `fromRanges` repeats collapse to one call per call site. A move of a function reads as a removal plus an addition. Asserted in `cp3_library_callees_are_filtered_and_repeated_call_sites_collapse`.
- **No guess past the server.** A call the server does not resolve, a string-keyed boundary (an RPC method name, a route, an event) included, is not listed and nothing guesses the next hop. Asserted in `cp3_a_string_keyed_call_ends_the_path`.
- **Capped.** Unchanged calls are counted, not listed, past the caps; a result a cap cut has `capped: true`. Asserted in `cp3_a_function_with_more_calls_than_the_cap_says_capped`.

**CP4 an entry point carries the changed functions it calls, in call order.** `flows` has one flow per changed function with no changed caller (an entry point), `{entry, tree}`, where `tree` nodes hold the symbol key, the call's status and `calls` in the order the call sites appear. Given an entry point whose callee also changed and a changed function called by another, then:
- **The callee is in the tree.** An entry point whose callee also changed carries that callee under it, and the callee is no entry point. Asserted in `cp4_an_entry_point_whose_callee_changed_carries_that_callee`.
- **A cycle ends where it closes.** A recursion or a call cycle stops at the node that repeats, marked `cycle`. Asserted in `cp4_a_cycle_ends_where_it_closes`.
- **Depth.** A tree deeper than 6 stops at 6 and says `capped: true`. Asserted in `cp4_a_tree_stops_at_the_depth_cap_and_says_so`.
- **A changed function with no calls.** A changed function that calls and is called by nothing is an entry point with an empty tree. Asserted in `cp4_a_changed_function_with_no_calls_is_an_entry_point_with_an_empty_tree`.

**CP5 servers run one at a time and are gone when the run ends.** Given the Daemon:
- **The pair.** The old side is the merge base (U7672a's From) exported once; the new side is the working tree for `to: "tree"` and HEAD for `to: "branch"`. Each `node_modules` directory of the working tree is linked at its path in the export; a dependency the Agent changed can misresolve on the old side, and the reply then carries `oldSideResolvedThroughNewDependencies: true`. The two servers start one after the other. Asserted in `cp5_the_old_and_new_servers_run_one_after_the_other_and_the_reply_flags_shared_dependencies`.
- **Serial.** A second request waits for the first; the Daemon runs one trace at a time. Asserted in `cp5_two_requests_run_one_after_the_other`.
- **The limit.** A server that never answers ends at the limit as `failed` with the cause `timeout`, and its process is gone. The test sets the limit to under a second through the Daemon's test configuration and uses a stub that completes `initialize` and then stays silent. Asserted in `cp5_a_server_that_never_answers_ends_at_the_limit_as_failed_and_is_gone`.
- **Cancel.** The caller closing its connection before the reply cancels the trace, kills the server with its process group and leaves the next request free to start. Asserted in `cp5_closing_the_connection_kills_the_server`.
- **Nothing resident.** After every outcome (done, noServer, failed, cancelled) the Daemon has no language-server child. Asserted in `cp5_no_language_server_child_is_alive_after_any_outcome`.

**CP6 the old side is exported once per merge base and bounded.** Given the cache of the Daemon:
- **Reuse.** A second request for the same merge base exports nothing: no `git archive` runs and the entry's files are unchanged. Asserted in `cp6_a_second_request_for_the_same_merge_base_exports_nothing`.
- **Written whole.** An entry appears only complete: an interrupted export leaves no entry, and a directory without its `complete` marker is deleted and rebuilt on the next request. Asserted in `cp6_a_corrupt_entry_is_rebuilt_and_an_interrupted_export_leaves_none`.
- **Bounded.** Writing a fifth merge base evicts the oldest; the cache never holds more than 4 entries. Asserted in `cp6_a_fifth_merge_base_evicts_the_oldest`.

**CP7 a trace is a personal aid that costs nothing resident and writes nothing in the Agent's folder.** Given a trace of every outcome in CP5:
- **Read only.** The repository's index, refs and Worktree are byte-identical before and after, and the trace holds no lock the Agent needs (git's index, a package manager's, cargo's): `git add` and `git commit` in the Agent's Worktree succeed while a trace runs. Asserted in `cp7_the_repository_is_byte_identical_after_a_trace`.
- **Never a gate.** No Landing, Send, Message or Rail state reads a trace; `agent.callPaths` failing changes no other method's reply. Asserted in `cp7_a_failed_trace_changes_no_other_method`.
- **No model.** The trace makes no call to a model and records no token or cost. Policy (P9, P14), held by the module's imports: no `claude_code` item is used.
- **Perf (rule 7).** `just perf` shows idle RSS unchanged (10 idle Agents under 150 MB extra) and cold start unchanged with the feature in; the PR reports the peak memory and time of one trace on this repo. Asserted by `just perf`, checked in the implementation PR's review.
