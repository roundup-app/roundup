# Pending row focus

Acceptance for #4414; specification only. Extends U3787c in `scenarios/ui-mac-expectations.md` and Z3788d in `scenarios/app-libraries.md` without changing selection, activation or query editing. Implementation follows the measured Switcher virtualization work in #4401. No new RPC, App seam command, public name or motion is specified (policy).

**U4414a choosing another focus target cancels deferred navigation.** Given the open virtualized Switcher with a focused content row, a first and last eligible row outside the mounted range, and an End or Home request whose target has not mounted, when the user either ⌘-clicks a different mounted row or moves focus with Tab/Shift-Tab to the query field, then mounting the originally requested row does not move focus from the user's new target. After the late mount, Enter on the chosen content row still activates exactly that identity once; query-field keys retain native editing. Planned test: `u4414a_late_mount_preserves_the_users_focus`, table-driven over Home/End and both focus changes in `apps/desktop/src/switcher/u529_switcher.test.tsx`.

**U4414b user scrolling cancels deferred navigation.** Given the same pending Home/End request, when the user scrolls the Switcher's results with the wheel or scrollbar before its target mounts, then mounting that target does not focus it or scroll back to it; the focus owner immediately after the user scroll remains the focus owner after mounting. Merely scrolling or mounting activates no destination and makes no `terminal.write` call. Planned test: `u4414b_user_scroll_cancels_late_focus`, table-driven over Home/End and wheel/scrollbar in the same Switcher suite. Scroll position is an interaction outcome here; no pixel value or layout is prescribed.

**U4414c uninterrupted navigation still completes once.** Given the same unmounted Home/End target, when its navigation request reveals and mounts that row without a subsequent user focus change or user scroll, then that exact identity receives focus once, including when revealing it generates a programmatic scroll event. Navigation makes no activation or `terminal.write` call. A later explicit Home/End after U4414a/b's cancellation can focus its own target once; cancellation does not disable future navigation. Planned test: `u4414c_only_the_current_navigation_completes`, table-driven over Home/End and uninterrupted/reissued requests in the same Switcher suite.

## Observer and regression policy

The implementation's tests drive the production Switcher, Ark collection and virtualizer through the existing mounted App seam. Use distinct first, middle and last identities in a list longer than the viewport; keep the requested endpoint unmounted until after the intervening action, then observe actual mounting before asserting focus and call counts. A controlled range-mount fixture may delay that mount, but must not replace navigation, selection or focus completion with a test double. Observe focus after the row-registration completion has run, using its scheduling bound rather than an arbitrary sleep. Tests above are planned implementation obligations, not existing proofs (policy).

Preserve Z3788d's selected identity, accessible navigation and measured rendering budgets, U3787c's selection/activation rules, and exact retained query/caret/draft behavior. Use installed Ark/platform event support and the virtualizer's callbacks before adding machinery; rule 9 applies to the implementation. Add no parallel selection machine, global focus owner or timer-based expiry (policy).
