# One terminal host everywhere (step 3 of the Multi-Machine Strategy)

Module: `crates/terminal` and `crates/herdr`. Work order: #6707; spike: PR #6705 (`spikes/herdr-core-client/REPORT.md`); Decision: `docs/adr/0012-herdr-core-machine-layer.md`; Principles: P15 and P16 in `PRINCIPLES.md`. herdr-core is the one terminal host on every machine, this Mac included, reached through a backend beside `crates/terminal/src/remote.rs` (`spikes/rex-client/REPORT.md`, "Smallest rupd change that lets Rex hold the terminals", now for herdr-core). No Rex adapter and no tmux adapter. This file is specification only; each planned test ships with its implementation Issue.

Decided by the owner on 2026-11-07, so these scenarios build them as stated: herdr-core is the one terminal host; roundup's own PTY path goes in the same change; only a rule 7 failure on this Mac keeps it; roundup's read, search and screen stay as they are; an offline machine is a status with no alert; moving a running agent between machines is not built.

## Checks on main

1. `scenarios/terminal.md`, headings `X8 in-process API` and `X13 read a Terminal's output`; `scenarios/terminal-stream.md`, heading `X14 output belongs to one Terminal`: the answers MC10 keeps.
2. `scenarios/terminal-program-status.md`, heading `PS1 a report becomes a record`: the status report MC10 and MC14 pass through.
3. `scenarios/terminal-owner-gap.md`, heading `X6014a output written while no client is attached is kept and replayed in order`: the gap contract MC14 meets by other means.
4. `scenarios/perf-terminal-ready.md` and `docs/perf.md`: `just perf` and its rows `cold_start_ms` and `rss_extra_mb`, the observer of MC11.
5. `scenarios/machines.md`, headings `MC3 a machine shows as a chip or status on an Agent, nowhere else` and `MC4 an unreachable machine layer fails loud`: the chip and the coded error MC15 relies on.
6. `crates/terminal/src/remote.rs` and `spikes/rex-client/REPORT.md`: the seam the new backend sits beside.

**MC10 a Terminal's bytes come from herdr-core unchanged.** Given a Terminal hosted by herdr-core whose program prints 5,000 numbered lines, an OSC 7501 report and a multi-byte UTF-8 character, when roundup attaches, then `read`, `search`, `screen`, catch-up and output subscribers give the answers they give on `main` (X8, X13, X14), the OSC 7501 report becomes the record PS1 names, and the stream is buffered as bytes and decoded once, never per frame, so a frame ending inside a UTF-8 character loses nothing. Tests: `mc10_attach_stream_gives_same_read_search_screen` (against a fake herdr-core replaying the spike's frames, comparing with the log herdr-core holds); `mc10_split_utf8_frame_decodes_once`; `mc10_osc_7501_report_reaches_status`. The exit code on the stream's CLOSE reaches X3: `mc10_exit_code_reaches_terminals`, reading `terminal.get` after a short delay because `terminal.wait` can answer `null` right after exit.

**MC11 rule 7 holds with herdr-core as the local host.** Given herdr-core as the local host on this Mac, when `just perf` runs, then cold start stays under 300 ms, keystroke-to-render under 16 ms p95 and ten idle Agents under 150 MB extra RSS, and no row regresses more than 10% against the recorded baseline (rule 7). Observer: `just perf`, whose result is recorded in the implementation PR. A failure keeps roundup's own PTY path (MC12 then does not apply) and the Issue `ask`s with the failing row. Policy: the herdr processes' RSS counts toward the 150 MB.

**MC12 roundup's own PTY path is gone.** Given MC11 passed on this Mac, when the change lands, then no code opens a PTY for a Terminal, no code reads the old owner socket, and every Terminal, local or remote, starts through the herdr-core backend. Tests: `mc12_no_owner_socket_reads` (a source scan of `crates/` for the old owner socket path and PTY spawn, failing on any hit); `mc12_local_terminal_starts_through_herdr_core` (against a fake herdr-core, asserting `terminal.run` is called with argv, cwd, env and size). Policy: when MC11 failed, this scenario is retired by the Issue's `ask`, never by weakening MC11.

**MC13 a remote Terminal adds under 1 ms to a keystroke.** Given a remote Terminal attached through `ssh <host> herdr-core connect`, when keystrokes are sent and echoed, then the p50 added beyond an `ssh cat` baseline, interleaved, n=200, stays under 1 ms (the spike measured 0.15 ms at p50 and a pairwise 0.56 ms; ssh's own jitter is not counted). Test: `mc13_remote_keystroke_adds_under_1ms` (a real `ssh` to localhost, as the spike's Q9 did; the one test here that needs a process). Policy: typing goes through the fast stream, not `terminal.send` (0.34 s a call) and not `terminal.keys` (it waits out `HC_QUIET_MS`); the choice between lowering the period and sending through the stream is the implementation's, and a paste followed by Enter is two frames.

**MC14 a Terminal survives losing ssh.** Given a remote Terminal whose program prints one numbered line per tick, when the ssh process is killed or paused for several ticks and reattaches, then the program's pid and state `live` are unchanged, the gap is filled from `history:N`, and the repaint is deduped by content, so every number appears once and in order with no doubled line at the seam. Tests: `mc14_reattach_keeps_program` (a real core, ssh killed, then paused); `mc14_gap_filled_from_history_without_duplicate_lines` (a fake core replaying the spike's repaint with one repeat at the seam, asserting each number once). Policy: no byte-offset resume token exists; `N` is at least the outage's lines, so a longer outage than `N` shows as a gap by the count of lines missing, never silently (X6014b's rule).

**MC15 an offline machine is a status on its Agents' rows, with no alert.** Given a machine whose ssh does not answer, whether unreachable or hibernated and not yet woken, when roundup cannot attach, then each of its Agents' rows shows an offline status (MC3's place) and no alert fires; on return the row clears and the Agent's program is as it was. Tests: `mc15_offline_machine_sets_status_on_rows` (asserting the status on every Agent of that machine and none on others); `mc15_offline_machine_raises_no_alert` (asserting no `StateAlert`); `mc15_reconnect_clears_status` (asserting the status clears when hello answers). Policy: an `ssh … herdr-core connect` wakes a hibernated machine (0.77 s in the spike); the guest clock steps forward on wake, so no timeout inside roundup reads machine time.

**MC16 an Agent starts from a clean environment.** Given herdr-core started over an ssh session carrying `CLAUDECODE=1` and `CLAUDE_CODE_SESSION_ID`, and this Mac's own environment, when an Agent starts, then its program sees none of those variables except those the launch names, and `HC_TERMINAL_ID` stays set. Tests: `mc16_agent_env_has_no_session_leak` (a real core and `env` as the program: asserts the output holds the launch's variables and the herdr id, and no inherited name); `mc16_core_starts_from_clean_environment` (asserting the start command is `env -i` with the named variables, not an empty-string value, since an empty string sets the variable rather than removing it). Policy: removal is by `env -u NAME … prog` in argv or by starting the core clean; a spawn with a bad cwd or program returns `spawn_failed` to X10's answer.

**MC17 frames for a channel no one attaches are freed.** Given a connection to herdr-core whose core sends frames on a channel `attach` never claims, when the connection drops, then every frame held is freed (a CLOSE keeps its channel's frames, since an attach racing the exit must still read them, MC10), and while it stays open the frames held across all unclaimed channels stay within 4 MiB, a frame past that dropped (its credit still returned). A channel that `attach` claims after its first paint, as the attach reply promises, still gets those frames in order (MC10). Tests: `mc17_orphans_freed_on_connection_drop` (a fake core sending DATA on channels no attach claims, then CLOSE on one and a dropped pipe, asserting the CLOSE keeps its frames and the drop frees all); `mc17_unclaimed_frames_are_bounded` (a fake core sending more than 4 MiB on unclaimed channels, asserting the held bytes stay within the bound); `mc17_attach_after_first_paint_gets_frames_in_order` (a fake core sending the first paint before `attach` is claimed, asserting the Stream yields it in order). Policy: the held count is read by a `#[cfg(test)]` accessor on `Channels`, never a public function.

## Observer and regression

`loop/rules.sh vocab` exits 0. X8, X14, PS1–PS12 and `scenarios/terminal-owner-gap.md` keep their meaning: MC12 retires only the owner path that serves them, and MC14 meets the gap by `history:N` where X6014a meets it by the owner's Output log. Policy for the size: `RESIZE` from an `observe` viewer is ignored and the last active non-observer sets the size, so roundup keeps authority by re-sending `RESIZE` on attach and resize. Policy for versions: roundup pins protocol generation 1, checks it at hello and fails an unsupported generation loud, per MC4.
