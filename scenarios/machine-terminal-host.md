# One terminal host everywhere (step 3 of the Multi-Machine Strategy)

Module: `crates/terminal` and `crates/herdr`. Work order: #6707; spike: PR #6705 (`spikes/herdr-core-client/REPORT.md`); Decision: `docs/adr/0012-herdr-core-machine-layer.md`; Principles: P15 and P16 in `PRINCIPLES.md`. herdr-core is the one terminal host on every machine, this Mac included, reached through a backend beside `crates/terminal/src/remote.rs` (`spikes/rex-client/REPORT.md`, "Smallest rupd change that lets Rex hold the terminals", now for herdr-core). No Rex adapter and no tmux adapter. This file is specification only; each planned test ships with its implementation Issue.

Decided by the owner on 2026-11-07, so these scenarios build them as stated: herdr-core is the one terminal host; roundup's own PTY path goes in the same change; only a rule 7 failure on this Mac keeps it; roundup's read, search and screen stay as they are; an offline machine is a status with no alert; moving a running agent between machines is not built.

**MC10 a Terminal's bytes come from herdr-core unchanged.** Given a Terminal hosted by herdr-core whose program prints 5,000 numbered lines, an OSC 7501 report and a multi-byte UTF-8 character, when roundup attaches, then `read`, `search`, `screen`, catch-up and output subscribers give the answers they give on `main` (X8, X13, X14), the OSC 7501 report becomes the record PS1 names, and the stream is buffered as bytes and decoded once, never per frame, so a frame ending inside a UTF-8 character loses nothing. Tests: `mc10_attach_stream_gives_same_read_search_screen` (against a fake herdr-core replaying the spike's frames, comparing with the log herdr-core holds); `mc10_split_utf8_frame_decodes_once`; `mc10_osc_7501_report_reaches_status`. The exit code on the stream's CLOSE reaches X3: `mc10_exit_code_reaches_terminals`, reading `terminal.get` after a short delay because `terminal.wait` can answer `null` right after exit.

**MC11 rule 7 holds with herdr-core as the local host.** Given herdr-core as the local host on this Mac, when `just perf` runs, then cold start stays under 300 ms, keystroke-to-render under 16 ms p95 and ten idle Agents under 150 MB extra RSS, and no row regresses more than 10% against the recorded baseline (rule 7). Observer: `just perf`, whose result is recorded in the implementation PR. A failure keeps roundup's own PTY path (MC12 then does not apply) and the Issue `ask`s with the failing row. Policy: the herdr processes' RSS counts toward the 150 MB.

**MC12 roundup's own PTY path is gone.** Given MC11 passed on this Mac, when the change lands, then no code opens a PTY for a Terminal, no code reads the old owner socket, and every Terminal, local or remote, starts through the herdr-core backend. Tests: `mc12_no_owner_socket_reads` (a source scan of `crates/` for the old owner socket path and PTY spawn, failing on any hit); `mc12_local_terminal_starts_through_herdr_core` (against a fake herdr-core, asserting `terminal.run` is called with argv, cwd, env and size). Policy: when MC11 failed, this scenario is retired by the Issue's `ask`, never by weakening MC11.

**MC13 a remote Terminal adds under 1 ms to a keystroke.** Given a remote Terminal attached through `ssh <host> herdr-core connect`, when keystrokes are sent and echoed, then the p50 added beyond an `ssh cat` baseline, interleaved, n=200, stays under 1 ms (the spike measured 0.15 ms at p50 and a pairwise 0.56 ms; ssh's own jitter is not counted). Test: `mc13_remote_keystroke_adds_under_1ms` (a real `ssh` to localhost, as the spike's Q9 did; the one test here that needs a process). Policy: typing goes through the fast stream, not `terminal.send` (0.34 s a call) and not `terminal.keys` (it waits out `HC_QUIET_MS`); the choice between lowering the period and sending through the stream is the implementation's, and a paste followed by Enter is two frames.

**MC14 a Terminal survives losing ssh.** Given a remote Terminal whose program prints one numbered line per tick, when the ssh process is killed or paused for several ticks and reattaches, then the program's pid and state `live` are unchanged, the gap is filled from `history:N`, and the repaint is deduped by content, so every number appears once and in order with no doubled line at the seam. Tests: `mc14_reattach_keeps_program` (a real core, ssh killed, then paused); `mc14_gap_filled_from_history_without_duplicate_lines` (a fake core replaying the spike's repaint with one repeat at the seam, asserting each number once). Policy: no byte-offset resume token exists; `N` is at least the outage's lines, so a longer outage than `N` shows as a gap by the count of lines missing, never silently (X6014b's rule).

**MC15 an offline machine is a status on its Agents' rows, with no alert.** Given a machine whose ssh does not answer, whether unreachable or hibernated and not yet woken, when roundup cannot attach, then each of its Agents' rows shows an offline status (MC3's place) and no alert fires; on return the row clears and the Agent's program is as it was. Tests: `mc15_offline_machine_sets_status_on_rows` (asserting the status on every Agent of that machine and none on others); `mc15_offline_machine_raises_no_alert` (asserting no `StateAlert`); `mc15_reconnect_clears_status` (asserting the status clears when hello answers). Policy: an `ssh … herdr-core connect` wakes a hibernated machine (0.77 s in the spike); the guest clock steps forward on wake, so no timeout inside roundup reads machine time.

**MC16 an Agent starts from a clean environment.** Given herdr-core started over an ssh session carrying `CLAUDECODE=1` and `CLAUDE_CODE_SESSION_ID`, and this Mac's own environment, when an Agent starts, then its program sees none of those variables except those the launch names, and `HC_TERMINAL_ID` stays set. Tests: `mc16_agent_env_has_no_session_leak` (a real core and `env` as the program: asserts the output holds the launch's variables and the herdr id, and no inherited name); `mc16_core_starts_from_clean_environment` (asserting the start command is `env -i` with the named variables, not an empty-string value, since an empty string sets the variable rather than removing it). Policy: removal is by `env -u NAME … prog` in argv or by starting the core clean; a spawn with a bad cwd or program returns `spawn_failed` to X10's answer.

**MC17 frames for a channel no one attaches are freed.** Given a connection to herdr-core whose core sends frames on a channel `attach` never claims, when the connection drops, then the frames held for that channel are freed (a CLOSE frame on it does not free them, MC27), and while it stays open the frames held across all unclaimed channels stay within 4 MiB, a frame past that dropped (its credit still returned). A channel that `attach` claims after its first paint, as the attach reply promises, still gets those frames in order (MC10). Tests: `mc17_orphans_freed_on_connection_drop` (a fake core sending DATA on channels no attach claims, then a dropped pipe, asserting nothing is held); `mc17_unclaimed_frames_are_bounded` (a fake core sending more than 4 MiB on unclaimed channels, asserting the held bytes stay within the bound); `mc17_attach_after_first_paint_gets_frames_in_order` (a fake core sending the first paint before `attach` is claimed, asserting the Stream yields it in order). Policy: the held count is read by a `#[cfg(test)]` accessor on `Channels`, never a public function.

**MC27 a channel closed before its attach reply still closes its Stream.** Given a fake core that sends DATA and then CLOSE on channel N, and only then replies to `terminal.attach` with channel N, when `attach` claims N, then the Stream yields the held DATA in order and then `None` (its Close), exactly as when the reply came first. The CLOSE is held with the frames, in order after them, and counts toward MC17's 4 MiB bound as a frame of no bytes; a channel that is never claimed is freed when the connection drops (MC17). Tests: `mc27_close_before_the_attach_reply_reaches_the_stream` (the fake core's order above, asserting the DATA, then the end of the Stream); `mc27_a_closed_unclaimed_channel_is_freed_on_connection_drop` (CLOSE on an unclaimed channel, a dropped pipe, nothing held). Policy: the case is outside the ordinary path, where the core replies first; it is specified because the loss is silent (P4).

## herdr-core stays invisible (#7008)

Work order: #7008, Key `herdr-invisible`. Specification only; each test ships with the implementation Issues that #7008's dependents file. Decided by the owner on 2026-11-12: roundup runs its own herdr-core session; the core's live list is the only answer to what runs for an Agent; errors reach the App in App words. The user never meets herdr-core: Agents keep running across Daemon restarts, core restarts and core upgrades, and roundup takes back what runs.

Checks on main for this section:

7. `scenarios/machines.md`, heading `MC4 an unreachable machine layer fails loud`: the coded error MC56 maps to App words.
8. `scenarios/app.md`, heading `S5981a exit for an update leaves every Agent running`, and `scenarios/daemon-restart-children.md`, heading `A5335a a restart reattaches every live child`: the restart behaviour MC52 keeps with the core's list in place of owner records.
9. `crates/herdr/tests/mc4.rs`: the test file MC4's tests live in, which keeps passing.

**MC51 roundup runs its own herdr-core session.** Given Herdr.app running its own core, when roundup starts a Terminal, then it connects with `herdr-core connect --session roundup`, a core separate from Herdr.app's, and an Herdr.app restart or upgrade leaves roundup's core and its programs running. Tests: `mc51_connect_names_the_roundup_session` (the connect argv carries `--session roundup`, against the test-support core); `mc51_second_core_keeps_its_own_terminals` (on a real core in a scratch HOME, started with and without `--session roundup`, asserting each core lists only its own terminals; the one test here that needs a process). Policy: Herdr.app no longer shows roundup's Terminals, and the extra core costs about 48 MB with 8 Terminals while Herdr.app also runs, counted toward MC11's 150 MB; Agents running on the old shared core restart once on the switch and resume their conversations through their Run.

**MC52 the core's live list decides what runs for an Agent.** Given every Terminal roundup starts carries labels naming its Project, Agent and Attempt, when the Daemon opens, when it reconnects and when an Agent starts, then roundup reads the live list filtered by those labels and makes it match the Agents, never reading its own records to decide: one live program for an Agent is attached to; none is started; two or more leave the busiest or most recently active one, end each idle extra, and show a busy extra until it is idle; a finished Terminal is removed with `terminal.rm` once roundup has kept what it shows (its screen and exit code); a Terminal labelled with an Agent that no longer exists is ended and removed. Tests: `mc52_one_live_program_is_attached`; `mc52_none_starts_one_labelled_program`; `mc52_two_programs_end_the_idle_extra`; `mc52_a_busy_extra_is_shown_until_idle`; `mc52_finished_terminal_is_removed_after_its_output_is_kept`; `mc52_terminal_of_a_deleted_agent_is_ended_and_removed`; `mc52_agent_start_reads_the_list_first` (two starts of one Agent in a row run one program); `mc52_names_are_unique_across_daemons` (four Daemons and a restart never reuse a name, which #7007 fixed). Policy: roundup's owner records (A12a) are removed, the labels replace them; `mc12_no_owner_socket_reads` keeps its scan.

**MC53 a lost connection reconnects and reads the list again.** Given a connection to herdr-core that closes (the core restarted, was upgraded, or the pipe dropped), when roundup next needs the core or its live feed (`events.subscribe`) ends, then it reconnects, reads the live list again by MC52 and resumes the feed, so a Terminal start or a Retry after the loss succeeds with no program doubled. A core that stays away is MC56's failure. Tests: `mc53_core_restart_reconnects_and_reattaches` (the test-support core restarted with its Terminals kept, asserting the same program attached and the next start succeeds); `mc53_core_restart_that_loses_terminals_starts_them_once` (the core restarted with an empty list, asserting one program per Agent); `mc53_feed_is_event_driven` (the test-support core sends a status event, asserting roundup reacts with no list poll in the call count). Policy: the upgrade of 0.1.18 to 0.1.20 on 2026-11-12 closed the connection and no start recovered; this scenario is that case's proof.

**MC54 a Terminal that roundup did not label is never touched.** Given the core's list holds Terminals with no roundup labels (the user's own Herdr.app shells) beside the Agents' Terminals, when MC52 runs, then none of them is attached, ended, removed or counted as an extra. Test: `mc54_unlabelled_terminals_are_untouched` (the call log of the test-support core holds no call naming one).

**MC55 roundup reads the core only by its checked-in schema.** Given herdr-core's `schema` output for the pinned version, checked in, when CI runs, then every reply the test-support core sends validates against it, so a bump of the pinned version that changes a reply fails CI. Tests: `mc55_every_fake_reply_matches_the_schema` (each method the test-support core answers, including `terminal.run` replying `address`, #7003); `mc55_schema_file_is_the_pinned_version_output` (the file names the pinned version, which `herdr-core schema` prints on a Mac, checked by MC58's real-core observer). Policy: a reply field roundup reads that the schema does not hold fails the first test.

**MC56 a core failure reaches the App in App words with an action that works.** Given herdr-core is missing, refuses the version, closes the connection, does not answer or fails a spawn, when the App shows the failure, then its text and action use user labels and no herdr-core word, error code or hint, and Retry reconnects first (MC53) and then repeats the action. MC4's coded error stays the Daemon's answer; the App maps each code to a label. Tests: `mc56_each_core_failure_has_an_app_label` (a table of every code to a label, asserting none holds a `GLOSSARY.md` _Avoid_ word or the text `herdr`); `mc56_retry_after_connection_closed_succeeds` (the test-support core closes, the first start fails, Retry succeeds with one program). Policy: the text of the label is the design critic's.

**MC57 tests start their own core.** Given any test that needs a herdr-core, when it runs, then it starts a core of its own in a temp HOME and session, and no test reaches the user's core; after it, no core or Terminal of its remains. Test: `mc57_no_test_reaches_the_users_core` (a source scan for a connect that names no session or HOME of the test, failing on any hit, and a run with the user's core socket path made unreadable). Policy: on 2026-11-12 the user's core held three finished `fake-claude` Terminals from test temp dirs.

**MC58 any sequence ends with one program per Agent.** Given the test-support core and a randomized sequence (seeded, the seed printed on failure) of Daemon restart, core restart, core upgrade, a second Daemon, a killed program and a deleted Agent, when the sequence ends and roundup settles, then these hold: exactly one program per live Agent; no roundup-labelled Terminal without an Agent; no finished roundup-labelled Terminal; and no herdr-core word in any App error shown on the way. Tests: `mc58_random_sequences_keep_four_invariants` (at least 200 sequences of 30 steps on CI, each checked after settling); `mc58_real_core_sequence_matches_ps` (the same generator against real herdr-core 0.1.20 in a scratch HOME, comparing the core's list and `ps` with the four invariants). Observer: `mc58_real_core_sequence_matches_ps` runs on this Mac and its result is recorded in the implementation PR; no Linux observer replaces its `ps` comparison.

## A test never reaches the owner's core (#7055)

Work order: #7055, Key `issue-7055`. Owner bug, 2026-11-13: a `test-support` run found no `herdr-core-test` beside its binary, fell back to `herdr-core` on `PATH` under the real `HOME`, and started the `roundup` session's holder with the test's `CLAUDE_CONFIG_DIR`; the App then ran every Terminal under that holder, and `claude --resume` found no conversation and exited 1, so reopening a saved Workstream failed with `no acknowledgement within 8s`. MC57 holds; these scenarios close the path it left open.

**MC59 a test core never runs in the owner's HOME or session.** Given a `test-support` build, when `Terminals` starts a core, then it is the test-support core or none: a missing `herdr-core-test` fails loud with a coded error and never falls back to `herdr-core` on `PATH`; and every core it starts runs in a scratch `HOME` and state folder with a session name that is not `roundup`, so no path of it reaches `~/.local/state/herdr-core/roundup/`. Tests: `mc59_missing_test_core_fails_loud_without_path_fallback` (a `PATH` holding a marker `herdr-core` and no test core beside the binary, asserting the error and that the marker never ran); `mc59_test_core_uses_scratch_home_and_own_session` (asserting the core's `HOME` and the connect argv's session name). Policy: the fallback to `PATH` stays outside `test-support`, where MC51's `roundup` session is the one the App uses.

**MC60 a core's inherited environment never decides a program's.** Given a holder of the `roundup` session started with `CLAUDE_CONFIG_DIR`, `ROUNDUP_*` or `FAKE_CLAUDE_*` values that are not the App's (a test run left it behind), when the App starts or resumes an Agent, then the program's environment holds the App's `CLAUDE_CONFIG_DIR` and none of the holder's `ROUNDUP_*` or `FAKE_CLAUDE_*` values: each launch names or removes (`env -u`) every variable the holder could carry, as MC16 names for the session leak. Then a saved Workstream reopened on that holder resumes its conversation and acks within the bound. Tests: `mc60_launch_overrides_holder_config_dir` (a real core started with a foreign `CLAUDE_CONFIG_DIR` and `env` as the program, asserting the App's value); `mc60_launch_removes_holder_test_variables` (the same core, asserting no `ROUNDUP_*` or `FAKE_CLAUDE_*` name in the output); `mc60_resume_on_a_polluted_holder_acks` (a test-support core started with a foreign `CLAUDE_CONFIG_DIR` and the fake `claude`, asserting `claude --resume <id>` finds its conversation and the Agent's ack arrives). Policy: the Terminals already running on a polluted holder keep their environment until they restart once and resume through their Run (MC51's policy).

**MC61 a test run leaves nothing under the real herdr-core state.** Given a test that runs a test-support core, when it ends, then nothing was created or changed under the real `~/.local/state/herdr-core`, and no core process of the run remains. Test: `mc61_test_core_run_leaves_real_state_untouched` (snapshots the real state folder's entries and modification times before and after one start, one Terminal and shutdown, asserting both equal; skipped with a printed line when the folder does not exist, where an absent folder is the same assertion). Policy: one quick test on every CI lane, with no real `herdr-core`; it joins MC57's source scan in `mc57_no_test_reaches_the_users_core`.
