# UI: a row the user adds is selected once it appears

Module: `apps/desktop`. Ids: U7916a, U7916b, U7916c. Work Issue: #7916. Terms: Project, Workstream, Agent, Mode, Rail (`GLOSSARY.md`). Journey stage: Enter. This is implementation acceptance; this specification alone changes no App behavior (policy).

Policy: a row the user adds from the App becomes the selected row as soon as it appears in the Rail, by every add path: New Agent (`⌘N`, footer menu, empty Rail, menu bar, pane) and the `⇧⌘N` prompt; New Workstream (footer, chord, strip, empty Rail) and the Switcher's create; New Mode, Group and Adopt Worktree; Save as Mode; a Todo's New Workstream; an imported listing Agent. The row's id arrives only in the creating call's reply, and `rail.changed` carries none, so the App holds the id until the Rail's tree contains it; `select()` drops an id not yet in `rail.tree`. Every add path goes through one such "select once it exists" step in `apps/desktop/src/state/`, replacing the per-path steps (`rail.ts` `openWanted`, `Rail.tsx` `placed`, `CreateMode.tsx`, `AdoptWorktree.tsx`).

Policy: a newer user pick wins. When the user picks another row after the add action and before the new row appears, the new row is not selected and the user's pick stays (U3756a–d, `scenarios/ui-focus-arrival.md`). A press, a focus change or a menu closing is no pick: it neither cancels the selection nor moves focus, which stays as U3756 and U4011 say. U4011's selection clause is the Workstream case of U7916a.

Policy: a row an Agent starts (`agent_spawn`, `rail_createWorkstream`, an Agent's `project.start`) is never selected by this step. A handoff's builder (H7200d, `scenarios/handoff.md`) and `terminal_show` keep their present selection behavior.

## Acceptance

**U7916a every Agent and Workstream add path selects its new row after an intervening press.** Given an open Project and a successful creating reply whose row is not yet in `rail.tree`, when the user adds an Agent by each of `⌘N`, the footer menu, the empty Rail's action, the menu bar and the pane, and by the `⇧⌘N` prompt, and adds a Workstream by the footer, the chord, the strip, the empty Rail's action and the Switcher's create, and, before the tree refresh reveals the row, presses an empty Rail area, focuses the Ask bar, or closes the menu that started the add, then the new row is selected when it appears, its pane is shown, the creating call ran once, and focus stays where the press or focus change put it. Test: parameterized `u7916a_an_added_agent_or_workstream_is_selected_after_a_press` in `apps/desktop/src/rail/u7916_new_row.test.tsx`, mounting the actual App in jsdom with the existing fake Daemon seam and the Rail's connected actions; assert the selected row's id, the pane shown, the creating-call count and the focused element after the row appears.

**U7916b every other user add path selects its new row.** Given an open Project, when the user creates a Mode, creates a Group, adopts a Worktree, saves an Agent as a Mode, creates a Workstream from a Todo (the Todo's New Workstream and its Todos-pane action), or imports a listing Agent, then the new row is selected when it appears in the Rail and its pane is shown; the same press-before-appearance interventions as U7916a leave that result unchanged. Test: parameterized `u7916b_every_other_add_path_selects_its_new_row` in `apps/desktop/src/rail/u7916_new_row.test.tsx`, through the actual App and the fake Daemon seam; the import case runs `apps/desktop/src/state/importState.ts`'s listing Agent add. Existing proofs of Mode, Group and Adopt Worktree selection (`apps/desktop/src/rail/g10_adopt.test.tsx`) are cut when this test covers the same then-clause, per rule 10.

**U7916c a newer pick wins and an Agent's start never selects.** Given each add path of U7916a and U7916b with its row not yet in `rail.tree`, when the user selects another row before the row appears, then the other row stays selected after the new row appears. Given an Agent that calls `agent_spawn`, `rail_createWorkstream` or `project.start`, when the new row appears in the Rail, then the selection is unchanged. A handoff's builder still replaces its selected caller (`h7200d_the_builders_row_replaces_the_callers_and_takes_its_selection` in `apps/desktop/src/rail/handoff.test.tsx`). Test: `u7916c_a_newer_pick_wins_and_an_agents_start_never_selects` in `apps/desktop/src/rail/u7916_new_row.test.tsx`, through the actual App and fake Daemon seam; assert the selected row id before and after the new row appears.
