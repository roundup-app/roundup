# App window width

The owner's 2026-10-12 decision in #1236 sets the supported App window width to at least 1280 px. U430 and `scenarios/ui-drawer.md` remain owned by #1109 and PR #1225; this specification changes neither. The final repository-wide absence of narrower viewport assertions includes that owner's slice once it merges.

**U452 the App opens at least 1280 px wide and cannot shrink below it.** Given the App window declared in `crates/desktop/tauri.conf.json`, when its configuration is read, then:

- Its `minWidth` is exactly 1280 and its initial `width` is at least 1280, in Tauri's logical pixels. Test: `u452_window_width_is_at_least_1280`, in `crates/desktop/tests/`, reads the actual config and asserts both fields on the App window, rather than testing a copied fixture.
- Its height behavior is unchanged: `height`, `minHeight` and `maxHeight` remain absent, as on main at `crates/desktop/tauri.conf.json:9`; no new height bound is introduced. Test: `u452_window_height_is_unchanged` reads that same config and asserts the three fields are absent.

Policy: this slice's implementation PR owns `crates/desktop/` only (AGENTS.md rule 3). It leaves #1236 open until U453 also holds.

**U453 layouts and observers use supported window widths.** Given `scenarios/` and `apps/desktop/src/`, when viewport assertions, test fixtures and capture definitions are enumerated, then:

- Every asserted App window or browser viewport is 1512×950, the one supported size (the fullscreen 14-inch MacBook Pro; owner direction). Replace any other viewport with 1512×950 and keep its seeds, interactions, assertions and colour schemes; deduplicate identical resulting viewports. Rename tests whose names encode the old viewport width and update their scenario references. Rail, Shelf, Drawer and content-column widths are component dimensions, not window viewports, and keep their own bounds. Historical incident descriptions and links to existing evidence are not new viewport assertions. Test: `u453_no_unsupported_viewport`, in `apps/desktop/src/testing/`, scans the scenario acceptance and source viewport definitions, including numeric width arrays, `set viewport`, `innerWidth` fixtures and browser launch sizes, and reports each narrower assertion with its file and line. Its parser tests include those forms and distinguish component dimensions from window dimensions. Exclude `scenarios/ui-drawer.md` from this slice's scan; #1109 owns its migration.
- Layout branches and width caps whose restricting arm can apply only when the window is narrower than 1280 are removed. This includes the window-dependent Rail and Shelf clamps in `apps/desktop/src/resize/widths.ts` and the Shelf span cap in `apps/desktop/src/styles.css`. Keep Rail and Shelf user resize bounds and per-Project persistence, text wrapping, content scrolling and rules that can restrict a layout at a supported width. Drawer rules owned by U430 are settled in #1109. Test: `u453_widths_keep_resize_bounds_without_window_clamps` exercises stored values below, within and above the Rail and Shelf limits, and restoration; `u453_shelf_span_has_no_window_cap` reads the real stylesheet.
- At 1512×950, the only supported window, the real U26 harness renders `first-run`, `agents-10`, `tree-40`, `decisions` and `conflict` in light. On `tree-40`, open and close Todo and Pad Drawers; on `decisions`, inject a failed answer and show its full error on the densest seed. No horizontal document overflow is introduced, and the controls remain reachable. Test: `u453_supported_widths_keep_controls_and_errors_visible` measures rectangles, scroll extents, hit targets and error text in isolated headless Chromium, with before/head captures and Check readings under `artifacts/ux/U453/`.
- The rendered change meets D2 (`docs/design-system.md:126`), D5 (`docs/design-system.md:129`) and D6 (`docs/design-system.md:130`), using only Tokens, and regresses no Check passing on main at the same supported viewport. Test: `u453_supported_widths_keep_checks` compares `window.__checks()` on the same seed, state and scheme for main and the head and records any pre-existing failure. This changes D10's minimum window viewport (`docs/design-system.md:134`) to 1512×950; its contrast and scheme requirements remain. Policy: the one supported size supersedes other observer instructions; their maintained definitions must be migrated in their owning module PRs.
