# Call paths for Rust: rust-analyzer as the second row, with the cost it brings handled (RA1–RA6)

Module: `crates/agents` (the Rust row, the cost handling); `crates/contracts` gains the reply fields `unresolved` and `directions`; `rust-toolchain.toml` stays as `main` has it. Ids: RA1, RA2, RA3, RA4, RA5, RA6. Work order: [#7682](https://github.com/roundup-app/roundup/issues/7682), blocked by #7681 (`scenarios/call-paths.md`, CP1 to CP7). The Flows lens that draws the result is #7683.

Owner, 2026-11-19: call paths are built before the readback, resolved to real symbols by proper tools. Rust is read through rust-analyzer's LSP `callHierarchy`, the same client as TypeScript (CP1 to CP6). Rust has no cheap server: rust-analyzer loads the whole Cargo workspace before it answers, and cargo runs in the tree it loads. This file holds the row, the cargo isolation, the cost levers and the proof. It adds no Daemon method: `agent.callPaths` already takes a `language`, and its reply gains the fields below.

Decisions this specification takes, each held by a scenario below:
- **Rust's row** is `rust-analyzer`, found by running `rust-analyzer --version` in the Agent's Worktree (so a project's `rust-toolchain.toml` picks the toolchain), then on PATH. It counts only with `callHierarchyProvider` in its initialize answer, as CP1 says for every row. roundup installs nothing. `rust-toolchain.toml` is not changed: this repo's pinned toolchain has no rust-analyzer, and adding the component costs an install on every CI lane for one narrow test, while the observation record (RA5) proves the real server once. A Rust-server test that finds no server would fail, never skip, so none runs in CI; the shared logic (CP1 to CP6) is proven on TypeScript and Rust's mapping on recorded server replies (RA4).
- **Cargo.** The trace gives rust-analyzer its own target directory `<Daemon cache directory>/call-paths/target/<commit>/` (the merge base for the old side, the Worktree HEAD for the new), cargo's network off (`CARGO_NET_OFFLINE=true`, `cargo.extraArgs` of `--offline --locked`) and no check on save. Cargo then takes no lock on the Agent's `target/`, never rewrites `Cargo.lock` and never fetches. The target directories are cache entries of CP6's kind: the last 4 merge bases kept.
- **Cost.** The limit for Rust is 120 s per request, not CP5's 30 s, because the cold analysis of this repo is suggested to take tens of seconds; the PR's measurement (RA5) may set it to twice the slowest cold run if that differs, at no less than 60 s. One trace at a time is CP5's queue, shared by every language: a Rust trace and a TypeScript trace wait for each other.
- **The levers**, each kept only when the PR's measurement on this repo shows it cuts a run's time or peak RSS by 20% or more, and each kept lever shows in the reply: (1) the old side cached by commit, always on (CP6); (2) no build scripts, no proc macros, no cache priming, whose loss the reply names as `unresolved: ["macroGenerated"]`; (3) outgoing calls only, if `incomingCalls` is the cost, named as `directions: "outgoing"`; (4) the limit and the queue, always on.
- **No answers cache once the lean options are on.** With `main`'s settings the old side's cold server start on this repo measured 68.2 s to ready (RA5's table in `docs/perf.md`), over 10 s, so the answers cache of the order (RA6 of #7682) returns while they are off (off only when a caller turns the lean options off; they are `Git`'s default since #7824); with them on it measured 8.7 s to the first answer, under 10 s, so it is not built.
- The trigger is decided: only a Trace button starts a Rust run, never the view opening (the owner's choice for #7683, U7683b); TypeScript traces in the background. It changes nothing here: the cache and the limit hold under both.

Observer: Rust tests on Linux with stub servers for process facts (RA2, RA3) and recorded rust-analyzer replies as fixtures for mapping (RA4); no real rust-analyzer in CI. RA5 is an observation record, not a CI test (rule 10). `just perf` for RA5's budget. Never a native Mac capture. No layout or looks are tested.

**RA1 the Rust row finds rust-analyzer or says how to get it.** Given an Agent whose changed files hold Rust, then:
- **Found.** The lookup (CP1) lists `rust` with `server: {found: true, name: "rust-analyzer", version}` when `rust-analyzer --version` run in the Worktree succeeds and the initialize answer advertises `callHierarchyProvider`. Asserted in `ra1_a_found_rust_analyzer_is_listed_with_its_version`.
- **Not installed.** The rustup proxy exists when the component does not, so the failure of `rust-analyzer --version` reads `noServer` with `notInstalled` and the text "rust-analyzer is not installed; `rustup component add rust-analyzer` installs it". Nothing else starts and nothing is downloaded. Asserted in `ra1_a_project_without_the_component_answers_no_server_with_how_to_get_it`.
- **No call hierarchy.** A server whose initialize answer lacks `callHierarchyProvider` reads `noServer` with `noCallHierarchy`. Asserted in `ra1_a_rust_server_without_call_hierarchy_reads_no_server`.

**RA2 the trace takes no lock the Agent needs and writes nothing in the Agent's folder.** Given a Rust trace (a stub `rust-analyzer` that records its environment, arguments and initialize options), then:
- **Own target, offline, locked.** The server runs with `CARGO_TARGET_DIR` under `<Daemon cache directory>/call-paths/target/`, `CARGO_NET_OFFLINE=true`, `--offline --locked` as cargo's extra arguments and check on save off; none of them points into the Worktree. Asserted in `ra2_the_server_gets_its_own_target_directory_offline_and_locked`.
- **Nothing written.** After a trace the Worktree's `target/` and `Cargo.lock` are byte-identical, and `cargo build` in the Worktree finishes while the stub holds the trace open. Asserted in `ra2_the_agents_target_and_lock_file_are_untouched_and_its_build_runs`.
- **A missing dependency.** When the server reports that cargo failed because a dependency is not available offline, the reply is `failed` with the cause `cargoOffline` and cargo's message, and nothing was fetched. Asserted in `ra2_a_missing_dependency_reads_failed_with_its_cause`.

**RA3 a Rust trace is bounded in time and gone when it ends.** Given the Daemon:
- **The limit.** A Rust stub that completes `initialize` and then stays silent ends at the Rust limit as `failed` with `timeout`; the test sets the limit under a second through the Daemon's test configuration. Asserted in `ra3_a_silent_rust_server_ends_at_the_rust_limit_as_failed`.
- **The queue and the process group.** A Rust request and a TypeScript request run one after the other, and cancelling kills the server and every child it started (cargo, a proc-macro server) with its process group. Asserted in `ra3_a_rust_and_a_typescript_request_run_one_after_the_other_and_cancel_kills_the_group`.
- **Nothing resident.** After every outcome the Daemon has no `rust-analyzer` child. Asserted in `ra3_no_rust_analyzer_child_is_alive_after_any_outcome`.

**RA4 the result says no more than the server did.** Given recorded rust-analyzer replies (a fixture of `documentSymbol`, `prepareCallHierarchy`, `outgoingCalls` and `incomingCalls` from one run on a small crate), then:
- **A method under its impl.** `documentSymbol` nests a method under its impl block, so the method's symbol key holds the impl in its container names and a hunk inside it maps to the method, not to the impl. Asserted in `ra4_a_method_is_keyed_under_its_impl_block`.
- **A trait object.** A call through a trait object resolves to the trait's method, and is listed as a call to that method; no implementation is guessed. Asserted in `ra4_a_call_through_a_trait_object_ends_at_the_trait_method`.
- **Levers named.** A reply built with build scripts and proc macros off carries `unresolved: ["macroGenerated"]`, and one built with outgoing calls only carries `directions: "outgoing"` and lists no caller; a reply with neither lever carries neither field. Asserted in `ra4_a_reply_names_the_levers_that_cut_calls`.
- **Std filtered.** A callee in the standard library or under `~/.cargo/registry` is not listed (CP3's filter, for Rust paths). Asserted in `ra4_library_callees_are_filtered_for_rust_paths`.

**RA5 the cost is measured on this repo and one real run is recorded.** Policy and observation, not a CI test (rule 10). The implementation PR's first act, before any lever is kept:
- **Measurement.** rust-analyzer on this repo (about 314,000 lines of Rust, 94,000 vendored), the new tree and the old tree, cold and with the old side cached, with and without each lever of the decisions above: wall time and peak RSS in a table in the PR and in `docs/perf.md`. A lever is kept by its 20% rule, the limit is set by its rule, and the answers cache stands or goes by its 10 s rule (it went).
- **Observation record.** One run of the real server on this repo's Rust crates over three recorded diffs, the added, removed and changed calls checked by hand against `git diff`, and a `cargo build` in the same Worktree finishing while the trace ran, committed as `docs/perf.md`'s record. A missing rust-analyzer on the recording host is a failure of the record, never a skip.
- **Perf (rule 7).** `just perf` shows idle RSS unchanged (10 idle Agents under 150 MB extra) and cold start unchanged; the time and peak RSS of a whole Rust run on top of an idle Daemon are reported in the PR, and the Daemon's children are listed empty after it. Asserted by `just perf`, checked in the implementation PR's review.

**RA6 the cost is re-measured with a populated cargo registry and the two decisions are re-checked.** Policy and observation, not a CI test (rule 10). Work order [#7803](https://github.com/roundup-app/roundup/issues/7803). RA5's first table came from a runner whose registry was empty, so its numbers are a floor. Given a host whose registry is populated (`cargo fetch` online before the offline trace), then:
- **Table.** `docs/perf.md`'s RA5 section holds, for the old tree and the new tree on this repo's real dependencies, the cold time (to ready and to the first answer) and the peak RSS of the server, one row each, with the host (cores, memory, rust-analyzer version, cargo jobs, priority) named.
- **Observation record.** The same section holds the three-diff record RA5 orders: the added, removed and changed calls of the real server over three recorded diffs, checked by hand against `git diff`, with a `cargo build` in the same Worktree finishing while the trace ran. A missing rust-analyzer or an empty registry on the recording host is a failure of the record, never a skip.
- **Answers cache.** The section states whether the old side's cold start is under 10 s, with `main`'s settings and with the lean options on, and the answers cache (the order's RA6 of #7682) returns or stays deleted by that 10 s rule; `scenarios/call-paths-rust.md`'s "No answers cache" decision is edited to match when it returns.
- **Levers.** The section states, for the lean options and for outgoing calls only, the cut in time and in peak RSS against the 20% rule, and each lever's disposition (kept or not) follows; the Rust limit is re-set by its rule (twice the slowest cold run, at no less than 60 s) when a request over two never-traced commits would exceed it.
- **Quiescent.** A Rust trace sends no request after `initialize` until the server reports `quiescent` through `experimental/serverStatus`, so a populated registry answers with real calls, never with every symbol `callable: false`. Asserted in `ra6_a_rust_trace_waits_for_the_server_to_report_quiescent`.
- **Trigger.** The costs are stated as landing on a Trace click, never on opening the view (#7683, decision 7).
Failing input of the order: the old side's cold start is 10 s or more on a populated registry. Asserted by review against the section; no test.
