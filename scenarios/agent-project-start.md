# An Agent opens a Project and starts work there

Acceptance for #5765. Ids: A5765a–A5765f, U5765, I5765. Specification only: all observers named below are planned; merging this file delivers no capability. Journey stages: Enter, Request and Understand (`.agents/data/journey.md`, “What must work”).

The Agent calls its own Daemon through `rup`; the open App chooses the target Project and uses that Project's connection. The user never carries the prompt between Projects.

## Checks on main

1. `crates/agents/src/dispatch.rs`, `Agents::rpc_project_open`, and `scenarios/mcp.md`, M8: `project.open` validates a folder and emits `project.requested`; its null answer acknowledges a request, not completion.
2. `crates/rupd/src/actions.rs`, `Daemon::rpc_action`, `Answerer::relay`, and `scenarios/named-actions.md`, NA6–NA9: one App registers through `action.serve`; relay replies are correlated to its connection; `action.run` is user-only, has a ten-second timeout and reports a lost run as `UNKNOWN_OUTCOME` without retry.
3. `apps/desktop/src/state/projects.ts`, `createProjectsState`: the App owns the open Project tabs and the open operation. `apps/desktop/src/app/seam.ts`, `ProjectCalls`: each RPC connection is bound to one Project.
4. `apps/desktop/src/rail/CreateMode.tsx`, `CreateMode`, and `scenarios/ui-rail.md`, U4547b: New Mode makes a root Agent with its Mode prompt saved, then explicitly restarts that same Agent; it is not `agent.saveAsMode` on an existing Agent.
5. `crates/agents/src/models.rs`, `check_permissions`, and `scenarios/ui-app-settings.md`, U3801: an Agent cannot select a permission mode. The normal choice is App-wide, carried on launches; omission leaves the vendor's own default. No Project-specific permission-setting RPC exists.
6. `docs/design-system.md`, “The checks”, D2, D5 and D6, and `scenarios/ui-visual.md`, U3299a: Tokens, contrast, keyboard access and names rather than opaque ids govern the new confirmation and attribution.

## Contract and relay policy

These are implementation requirements, not new methods shipped by this specification. Follow the Contract recipe: declare in `crates/contracts`, regenerate `contracts/generated/`, register every caller and both `rup` faces atomically, and add new code spellings to `GLOSSARY.md` in that implementation PR. Reuse Project, Agent, Workstream, Mode, Permission mode, Actor and Provenance; introduce no second Project registry.

- Extend `project.open {path}` to return `{path}` only after the App has opened that canonical absolute folder (or established it is already open). This replaces M8's fire-and-forget open and M17's request-only acknowledgement **for open only**. `project.rename` keeps M8's request/Event/null-result behavior. Remove the open Event path as an opening mechanism; keeping it would bypass consent. Update M8's open observers and M17's open formatting assertion to A5765b/c and I5765 in the same implementation PR; preserve the rename assertions.
- Add `project.start {path, kind, name, prompt}` returning `{path, kind, id}`. `kind` is exactly `agent`, `workstream` or `mode`; `id` is the created target Rail row's id, paired with its target path, not a source-Project Agent reference. `name` is nonblank under the existing Rail naming rules and `prompt` is nonblank; preserve prompt bytes. Agent means a new root Agent; Workstream means a new root Workstream with its Door; Mode means U4547b's new root Agent with its Mode prompt saved before its first run, not conversion of a source Agent or selection of an existing Mode. The Mode runs as a regular Agent and coordinates no child work automatically. Starting inside an existing target Home is outside this request.
- Only an identified, existing Agent (Door included) can use the Agent capability. Derive asking Agent id/name and source Project identity/name from the source Daemon's connection and Rail, never caller fields. Reject identity, permission, YOLO, Model, Effort, socket and arbitrary RPC overrides as `INVALID_PARAMS`. Source `auto` or bypass does not enlarge this capability. The user keeps the existing Add controls.
- Reuse `action.serve`'s registered App connection and correlated request/reply transport for the two typed Project requests. Extend its request schema/handler as a discriminated union; do not route through a named action or synthesize keys. NA8 still forbids an Agent's `action.run`. NA7's `done`/`awaiting` cannot represent a created row or final refusal, and NA9's ten seconds cannot bound a user decision: typed Project calls remain pending while their confirmation is live, including beyond ten seconds. Update the RPC client/CLI waiting path accordingly, without changing the timeout or authority of ordinary named actions.
- The App binds each request to its verified source identity and canonical target folder. Only the App's existing target connection may execute the target creation on behalf of that request. Do not connect A's Agent directly to B's socket or grant it B's user authority, Message access or general RPC access. Forward only the typed creation and trusted attribution. Attribution does not make a source numeric Agent id into a target-local spawner or confer Steer/Reach authority. No Message, Route, Held or Takeover semantics change; M1–M10 (`scenarios/proofs.md`) remain unchanged (policy).
- This is the owner's narrow exception to P3's native-request-only interruption rule: confirming an Agent's request to open an unopened folder is an App-owned authorization dialog. It creates no native question, `needs-you`, bell or OS alert. Ordinary startup into an open Project remains silent. U3299a's path-hiding rule has one exception here: the proposed folder's exact path is necessary to authorize opening it. The Rail uses names, not paths or ids (policy).

## Behavioral acceptance

Observer for A5765a–f: real source and target Daemons over isolated sockets, identified source Agent and fake App registered through the actual relay. The fake App uses the real target RPCs; assert target Rail contents, returned identities, startup calls and fake-vendor first input, not merely a mocked success. Use event/reply barriers, not sleeps. Add focused integration cases in `crates/rup/tests/`; App handler behavior is also exercised by U5765. No real Claude, personal profile or Mac-only observation is required.

**A5765a Start in an open Project immediately.** Given A and B are open, A's Agent `builder` and a target path B (including a canonical alias to B), when the Agent calls `project.start` through A for each kind with a distinct name and prompt, then no authorization dialog or chooser is requested, A gains no row, B gains exactly one corresponding root row per call, and each result contains B's canonical path, requested kind and that row's id. An Agent launches once with the exact prompt; a Workstream launches its Door once with that prompt; a Mode persists the exact Mode prompt before the same root Agent starts once with its prompt and regular Agent role, and is classified in MODES. Test: `a5765a_an_agent_starts_each_kind_in_open_b_and_gets_its_id` (table over three kinds; observe persisted Mode prompt and physical fake-vendor input).

**A5765b Opening waits for Open.** Given C is an existing folder absent from the App's open Projects, when A's Agent calls `project.open`, or `project.start` for each kind at C, then exactly one pending confirmation binds that call to the asking Agent, its source Project and C's canonical path. Until the fake App chooses Open, the call has no success result, C has no open tab/Daemon created by this request, no row is created and no vendor launches. The pending confirmation and call remain valid past NA9's ten seconds (use a controlled clock). On Open, the App opens C once; open-only returns C's canonical path and creates no row; start creates/launches the requested row as A5765a and returns its identity. Tests: `a5765b_unopened_c_has_no_effect_until_open` (open-only and all three kinds), `a5765b_confirmation_outlives_the_action_timeout`.

**A5765c Refuse and validation create nothing.** Given the same pending call, when the user chooses Refuse or dismisses its dialog (Escape included), then the result is `FORBIDDEN` with an explicit user-refusal cause and C's path; no Project, row or vendor launch is created. A relative path is `INVALID_PARAMS`; a missing folder or a file is `NOT_FOUND`; a bad kind, blank name/prompt or forbidden override is `INVALID_PARAMS`; validation fails before any prompt or effect. `project.open` on an already open Project returns its path without a confirmation or another open. Tests: `a5765c_refuse_opens_and_starts_nothing`, `a5765c_invalid_requests_fail_before_the_app`, `a5765c_open_b_is_already_complete`.

**A5765d Target permissions cannot be raised.** Given A's caller runs in `auto` or bypass, B's normal Add launch would use an explicit normal permission choice or omit it, and B's vendor configuration differs from A's, when each kind is started in B, then its Agent/Door uses exactly B's normal Add launch permission policy and B's configuration. No source launch flags, permission state, credentials or environment are copied. An omitted mode stays omitted; no YOLO/bypass flag is added. An attempted `permissionMode`, `yolo` or identity override is refused before opening or creating anything. Test: `a5765d_each_kind_uses_bs_normal_permissions_not_as` (table over source modes, target normal choice/omission and kinds; inspect actual launch argv/settings with fake vendor). Policy: “target Project's default” means the target's normal Add behavior under Check 5, not a new per-Project setting. Preserve P4's configured vendor default when omitted; this capability grants no bypass.

**A5765e Attribution survives its maker.** Given a successful start, when B's Rail is read, then the created Agent/Workstream/Mode holds the source Project identity, source Agent identity and their display names captured at creation, distinguishable from any equal local Agent id. After A's caller stops and B reloads, that attribution and row identity remain. Refused requests create no attribution row; target Provenance records the source identity rather than claiming the owner clicked Add. Test: `a5765e_attribution_keeps_the_source_project_and_agent_after_reload`. Its rendering is U5765's policy; never use attribution to broaden permissions.

**A5765f Failure is not refusal or success.** Given no registered App, then either Project call returns `APP_CLOSED` with cause and instruction to open roundup, with no effect. Given a relayed call whose App connection closes or is replaced before the answer, then the caller receives `UNKNOWN_OUTCOME`, never a row id or a claimed user refusal, and no automatic retry occurs. Invalidate any still-pending confirmation; a late click cannot authorize a different request or create work. A known target open/create/start failure returns its cause; if a row already exists, report its target path/id and the failed stage so the caller can inspect it rather than blindly create another. Tests: `a5765f_no_app_fails_without_effect`, `a5765f_lost_app_does_not_retry_or_accept_late_consent`, `a5765f_target_failure_reports_any_created_identity` (table over open/create/start). Policy: requests are separate operations, not an exactly-once retry promise.

**U5765 One confirmation and named Rail attribution.** Given the mounted connected App with A and B open and a pending request for C, when the request arrives, then one shared `ui/Dialog` offers Open and Refuse; keyboard choice reaches the same handler as pointer choice, Escape refuses, and focus returns to the previously focused control. The dialog's accessible description identifies the asking Agent, source Project and exact target folder. While pending, navigating or receiving another request cannot replace the bound request or reuse its consent; additional requests wait their turn. Open calls the existing Project open flow once and then the requested target creation; Refuse calls neither. Tests: `u5765_confirmation_choices_keep_the_request_identity`, `u5765_queued_requests_cannot_share_consent`, in `apps/desktop/src/app/`. An open-target start mounts no dialog and preserves the current Project selection and composing input; test `u5765_open_target_start_preserves_the_current_work`.

It remains readable when the source Agent stops; no raw source ids or Project paths appear there. The confirmation names/path are the authorization facts, not developer details. Failures show cause and recovery visibly without replacing a draft. Moves D2, D5, D6 (Check 6); use existing Tokens, Dialog and Rail patterns, no new motion. ## Scope and regression policy

Implementation owns the typed Project relay in `crates/rupd` and `crates/rpc`, its launch/attribution support in `crates/agents`, contracts and generated callers, `crates/rup` CLI/MCP/help/tests, and the App's Project handler, state, confirmation, Rail attribution, copy and tests (including `crates/desktop`'s existing App relay adapter if its schema needs changing). This is one Contract change; do not ship a caller that still treats open as a fire-and-forget Event. No loop machinery changes, general cross-Project RPC proxy, source Agent conversion, new permission setting, Mode-copy/import, existing-row restart or arbitrary target Home selection. Engineering progress and prerequisite questions belong on #5765.

Keep NA6–NA10's ordinary action authority/lost-answer observers, M8's rename observers, U3801's launch-permission observers, U4547b's Mode creation observers and P11's original-Project/draft identity behavior. P9 permits the explicit Agent tool call and exact first prompt; P4 keeps target vendor setup; P6 keeps every created row in its target Home. Implementation runs `just ready`, only its changed/named tests, vocabulary and scenario-id checks, the required rendered observer, and CI's `check`; this spec's observer is vocabulary/scenario-id checks plus review of every numbered main citation and each then-clause's named test or policy marker.
