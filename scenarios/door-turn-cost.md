# A Door turn only for what the Door must act on

Module: `crates/rupd` (hand-off, `owner_told.rs`) and `crates/messages` (pushes, `pushes.rs`). Terms: Door, Job, Consult, Message, Digest, Hand-off, Wake request (`GLOSSARY.md`). Specification for #6637, owner's pick of 2026-11-07: a child's change wakes its Door only when the Door must act. Policy: no new RPC, Message kind, status or contract change (laws M1 to M10 are not touched); the work is which `rupd` notes may start a turn, and the one existing inbox write carries the rest. A Door turn spends usage (P9), and DCL6's one settled note per quiet period (`scenarios/door-closed-loop.md`) stays as it is.

**DTC1 a Door's own Todo is no Hand-off.** Refines T25 (`scenarios/todos.md`) for a Door. Given a Door `d` whose Todo `d` created for itself (the Todo's `creator` and its owner are both `d`'s Actor) and an idle Event of `d`, then T25 sends no `Next: #<id> <title>` and records no `handed` Change (T26), so no turn starts; a Todo `d` owns that the user created or assigned (T17) is handed at its idle as T25 says, once, and a Todo a Door created and then gave to another Agent is handed to that Agent as before. A Todo `d` created for itself and later reassigned by the user to `d` again is the user's assignment and is handed. Tests in `crates/rupd/tests`, real Daemon and fake `claude`, beside T25's: `dtc1_a_door_that_creates_its_own_todo_gets_no_next_turn`, `dtc1_a_user_assigned_todo_is_still_handed_to_the_door`, `dtc1_a_todo_a_door_gave_another_agent_is_handed_to_that_agent`; each asserts the Door's transcript and the Todo's history, never only a counter. T25(a) to (g) hold for every other owner.

**DTC2 a note about a child wakes the Door only when the Door must act.** Narrows B21, B35, B43 and B49 (`scenarios/messages.md`) for notes `rupd` sends a Door about its direct children. A note is *waking* when it is the child Job's report or end note (B49, DCL5), a question the child sent the Door (B19's source), a child's Kind entering `needs-you` or `error` (B43), or a Message another Actor sent the Door. Every other `rupd` note about a child is *quiet*: a Kind change other than those, a change of `last`, open Todos or Pads, and the Digest of a child on which the Door holds an open Wake request (B41). A waking note is written as U6404a and U6404b say, within 2 s of the Stop that caused it. A quiet note is stored, not written, and starts no turn; when a Door turn starts for any reason (a waking note, a Message, a Wake request firing, the user's prompt, DCL6's settled note), every quiet note waiting is written in the same inbox write, in id order (B7), each child's entries folded to its newest under B22's rules with its weighted change count kept (B22(c)). No quiet note is dropped or rewritten: each reaches the Door on its next turn, after a Daemon restart as before (B21's stopped-Door rule), and a quiet note a child's later change makes obsolete is replaced only by B22's fold. A user's Todo change (T18, T22), a Wake request the Door set and a Message to the Door are never quiet and never wait for another note. Tests: `dtc2_a_last_line_change_of_a_child_under_a_wake_starts_no_door_turn` and `dtc2_a_status_flip_of_a_child_starts_no_door_turn` (`crates/rupd/tests`, real Daemon, fake `claude`: no inbox write and no prompt while the Door idles), `dtc2_quiet_notes_ride_in_the_next_waking_batch` (the quiet entries and the report appear in one transcript entry, in id order, none lost), `dtc2_a_quiet_note_rides_in_a_turn_the_users_message_starts`, `dtc2_a_restart_keeps_the_waiting_quiet_notes` and `dtc2_error_and_needs_you_still_wake_the_door_at_once` (B43's once and at-once rules unchanged); `dtc2_a_report_wakes_the_door_within_2s` (#6404: the Job's `report` is written to the Door's inbox within 2 s of its Stop on the fake clock, whatever quiet notes wait). The B35 and B21 tests on `main` change only where they assert that such a note starts a turn.

**DTC3 observer: the 2026-11-07 case costs one turn.** Given a real Daemon, a fake Door that spawns one Job, creates three Todos for itself and sets a Wake request on the Job, and a fake Job that changes its last line and Status twice before it reports, when the Job reports, then the Door's transcript records exactly one turn started by a `rupd` note, the report's, and that entry also holds the Job's last quiet digest. On `main` before DTC1 and DTC2 the same run counts six, five with nothing to act on. Test: `dtc3_one_job_three_own_todos_and_a_wake_cost_one_turn` in `crates/rupd/tests/`, which counts turns from the transcript and not strings generated.

Policy (balance): the rule is a fixed classification, not a learned or timed one; a Door that wants finer reaction sets a Wake request, a Message or a Todo, each of which stays immediate. That a model acts well on the batch is not proved.
