# Fork data folder

Module: `crates/rupd` (`data.rs` and a new fork module: the copy), `crates/rup` (`rup data fork`), `crates/contracts` (the method and its types). Terms: Project data, Fork (`GLOSSARY.md`; this file adds Fork: a copy of the live data folder, kept until the owner deletes it, that an App started on it never writes back). Principles served: P5 (`PRINCIPLES.md`). Design: ADR 0004, `scenarios/project-data.md` (N1, N4). Tests use an in-process Daemon on a temporary data folder with real SQLite files and a real `rup` (`CARGO_BIN_EXE_rup`) on a temporary socket; no `claude`, network or display. Contract change (rule 4): the RPC method `data.fork` and its params and result types are new, with `rup data fork` its one caller; `GLOSSARY.md` gains Fork in the same PR. Ids: FK5977a–FK5977e.

**FK5977a the copy.** Given a live data folder holding Projects with Agents, Todos, Pads, Messages and History, when a caller sends `data.fork` with `name`, `colour` and a new empty `folder` and no picks, then `folder` holds every Project's `projects/<key>/` content as the live folder holds it (N1): each database, each Agent's launch files, each Pad file; opening `folder` as `ROUNDUP_DATA_DIR` reads the same Todos, Pads, Messages, History and Agents; the result names the Projects, Agents and rows copied. The copy of a Project whose `<key>` the live folder holds keeps the key (N1, N4), so the same Project folder opens its copy. `folder` must not exist or be empty, must not lie inside the live folder and must not contain it; else `INVALID_PARAMS` and nothing is written. Tests (`fk5977a_`): the full copy read back through a second Daemon; the three `folder` refusals leave no file.

**FK5977b the picks.** Given the same live folder, when `data.fork` carries `projects`, a list of `{key, agents, todos, pads, messages, history}` where `agents` is `all`, `none` or a list of Agent ids and each other field is a boolean defaulting to true, then a Project not listed is absent from the Fork, and a listed Project holds exactly what it picked: an unpicked Agent has no row, launch file or Message in the Fork, `todos: false` leaves `todos.db` empty of rows, `pads: false` copies no Pad file or row, `messages: false` and `history: false` leave those databases empty of rows. A Project key or Agent id the live folder lacks is `INVALID_PARAMS` and nothing is written. Every database the Fork holds opens with the current schema (additive migrations only, so the previous build still opens it). Tests (`fk5977b_`): one test per pick against the opened Fork; an unknown key and an unknown Agent id.

**FK5977c a consistent copy of a database in use.** Given a Daemon writing Todos and Messages in a loop, when `data.fork` runs, then each SQLite database is copied with the SQLite backup API (`rusqlite::backup`) or `VACUUM INTO`, never a file copy of the database, its `-wal` or its `-shm`; the Fork's database passes `PRAGMA integrity_check` and holds a prefix of the writes (every row the writer finished before the call began, and no torn row). Pad files are copied with `clonefile` on macOS, with `reflink` where the filesystem supports it, and a byte copy elsewhere. Tests (`fk5977c_`): a writer thread racing the fork, then `integrity_check` and a row-count floor on the Fork; a source-text check is no proof, so the never-a-file-copy clause is proven by a database whose `-wal` holds committed rows absent from the main file and appears whole in the Fork.

**FK5977d the record.** Given a successful `data.fork`, then `<folder>/fork.json` holds `name`, `colour`, `source` (the live data folder's canonical path), `created_ms` and the picks as sent; `colour` is one of the fixed set `red`, `orange`, `amber`, `green`, `teal`, `blue`, `violet`, `pink` (the `ForkColour` enum of `crates/contracts`; the App's Token for each is U4's work, not this Issue's), and any other value is `INVALID_PARAMS` with nothing written; `name` is 1 to 40 characters with no control character. `rup data fork <folder> --name <n> --colour <c> [--project <key>[:agents=<id,..>][:no-todos][:no-pads][:no-messages][:no-history]]...` sends the one call and prints the result; with no `--project` it copies everything. A failed copy removes the partial `folder` it created and leaves the live folder untouched. Tests (`fk5977d_`): the record read back; each refusal; the CLI's flags produce the params of FK5977b through the Daemon's request log; a forced copy failure leaves no `folder`.

**FK5977e the live folder is left as it was.** Given the live data folder with the checksum of every file (hidden files, databases, `-wal`, `-shm`, Agent launch files and Pad files) and its file list, when `data.fork` runs, with and without picks, then the checksums and the file list are equal before and after, and the live Daemon's running Agents, Terminals and Worktrees are untouched: the call starts, stops and signals none. Nothing in the Fork writes to the live folder afterwards: a Daemon opened on the Fork that writes a Todo changes no live file. Tests (`fk5977e_`): checksum of the live folder before and after a full Fork and a picked Fork, taken with the Daemon idle, since a live Daemon's own writes are not the Fork's; then a write through a Daemon on the Fork and the same checksum again.
