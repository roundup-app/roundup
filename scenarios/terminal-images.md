# UI: an image an Agent draws shows in its Terminal (U5984)

Module: `apps/desktop` (the webview). Ids: U5984, U5985, U6144, U6144a, U6144b, U6145, U6146, U7029. Source: the owner's report in #5984: an Agent Terminal shows `cmp.png` as a boxed file name, not the picture. Terms: Agent, Terminal, Door, Bubble, Thread, Pad (`GLOSSARY.md`). Acceptance only.

**U5984 the Terminal answers Kitty graphics and stores the image.** Claude Code 2.1.316 draws a picture inline only when the terminal answers its Kitty graphics query (`a=q`); it takes the iTerm2 path only when XTVERSION names iTerm2 3.5 or later. The App's emulator (`apps/desktop/src/terminal/emulator.ts`) answers neither today, so Claude Code draws the alt text in a box. Given an Agent Terminal on the App's emulator, then:

- *Query.* A Kitty query (`ESC _G i=31,s=1,v=1,a=q,t=d,f=24;AAAA ESC \`) followed by a primary device attributes request gets an `OK` reply for id 31 before the attributes reply. Test: `u5984_the_emulator_answers_the_kitty_query`, in `apps/desktop/src/terminal/u5984_terminal_images.test.ts`, writes both to the emulator and asserts the bytes it sends back.
- *Draw.* A chunked `f=100` PNG transfer (`a=T`, `m=1` chunks, a last `m=0` chunk, including an empty first chunk and a bare final `m=0`) leaves one stored image at the cursor's cell, scrolling with the output and counted in scrollback. The same holds for JPEG, GIF and WebP when the Kitty path carries them as `f=100`, or the surface names the format it cannot draw. Test: `u5984_a_chunked_png_is_stored_as_one_image`.
- *Reopen.* An image the Terminal showed is shown again when the Terminal reopens from its saved output, as other output is. Test: `u5984_a_reopened_terminal_redraws_its_image`.
- *Bounds.* The 16 MB decoded cache and 4 Mpx per Terminal of the existing addon hold; an image over them is dropped with the text intact, and rule 7's keystroke-to-render and idle-RSS budgets hold (`just perf`). Test: `u5984_an_oversized_image_is_dropped_and_text_survives`.
- *No spoofing.* XTVERSION names xterm.js or roundup, never iTerm2. The Daemon never sets `CLAUDE_CODE_FORCE_TERMINAL_IMAGES` (U6144b; the owner retired the forced flag on 2026-11-06). Test: `u5984_xtversion_never_names_iterm2`.
- *No remote image.* No remote image URL from generated text loads anywhere; `apps/desktop/src/plain/renderMarkdown.ts` keeps drawing the alt text for generated images, remote URLs included. Test: `u5984_a_remote_image_url_draws_its_alt_text`.

Integration, for the implementation's `Reuse:` section (rule 9): `@xterm/addon-image` 0.9.0 handles SIXEL and iTerm2 only. Its `0.10.0` betas add partial Kitty graphics and need `@xterm/xterm` `^6.1.0-beta`, while the App pins a patched 6.0.0 (`patches/@xterm__xterm@6.0.0.patch`). Research those betas first, then the open Kitty fixes (xtermjs/xterm.js#6212, open on 2026-11-03: chunked transfers with an empty first chunk or a bare `m=0` draw nothing, and a stale pending transfer swallows the next image; review asks for `a=q` and `a=p` to leave a pending transfer alone). Pick the library path that passes every clause above, port the patch to it, and name for each rejected candidate the missing capability. A hand-written Kitty parser is allowed only when every candidate fails.

Observer: Vitest against the App's emulator, in `just check` (a cheap test, no process). The real-`claude` observer: a real `claude` in an Agent Terminal reads a PNG and draws the picture, not its alt text, on the implementation's revision. Only the user's Mac has a logged-in real `claude`; the build run asks for that observation in the Mac-observer format and records it on the Issue, and the fake cannot satisfy it. Moves D2, D5, D6 only if a visible state changes; Tokens only.

**U6144 a Unicode-placeholder picture shows as pixels.** Source: the owner's report of 2026-11-04 in #6144: a picture Claude Code 2.1.316 draws through its `Image` element shows as a box holding the file name, though U5984 closed. Claude Code sends the picture as `ESC _G a=T,U=1,q=2,f=100,i=<id>,c=<columns>,r=<rows> ; <base64> ESC \`, then writes `r` rows of U+10EEEE cells, each followed by diacritics naming its row and column, in a foreground colour that names the image id (the Kitty graphics spec, "Unicode placeholders"). Given an Agent Terminal on the App's emulator, then:

- *Draw.* That transmission and its rows of placeholder cells leave one placement of the image, `columns` by `rows` cells, over exactly those cells. The cells show pixels, not the placeholder glyph. Test: `u6144_a_placeholder_transmission_places_one_image`, in `apps/desktop/src/terminal/u6144_placeholder_images.test.ts`, writes the fixture to the emulator and asserts the placement.
- *Fixture.* The fixture is Claude Code's own byte form (`U=1` plus placeholder cells), recorded from Claude Code 2.1.316 or built to the spec's placeholder rules (a row diacritic and a column diacritic per cell, the id in the foreground colour, a continuation cell omitting both); no hand-made `a=T,f=100` placement stands in for it. Test: the same.
- *Scroll and reopen.* The placement scrolls with the output and is drawn again when the Terminal reopens from its saved output, as U5984 says. Test: `u6144_a_placeholder_image_scrolls_and_reopens`.
- *Bounds.* The 16 MB decoded cache and 4 Mpx per Terminal hold for a placeholder image, which is dropped with the text intact; rule 7's budgets hold (`just perf`). Test: `u6144_an_oversized_placeholder_image_is_dropped`.

Integration, for the implementation's `Reuse:` section (rule 9): research xtermjs/xterm.js#6198 "Support kitty unicode placeholders (U=1) in addon-image" (open, addon-image only) first and apply it through `patches/@xterm__addon-image@0.10.0-beta.331.patch`. If no library path draws placeholders, the Daemon answers the Kitty query with an error and XTVERSION names iTerm2 3.5 so Claude Code takes the iTerm2 path the addon draws; that reverses U5984's *No spoofing* clause (`u5984_xtversion_never_names_iterm2` and U6146's XTVERSION row change in the same PR).

Observer: Vitest against the App's emulator, in `just check`. The real-`claude` observer: a real `claude` in an Agent Terminal reads a PNG and draws pixels, not its alt text, on the implementation's revision; the run's `--debug` "Terminal capabilities" line is recorded in the PR. Only the user's Mac has a logged-in real `claude` (L46). Moves D2, D5, D6 only if a visible state changes; Tokens only.

**U6145 a query gets no `OK` for a medium the Terminal does not read.** Claude Code's file query (`a=q,t=f`) draws nothing when answered `OK`, and the addon answers `EINVAL:unsupported transmission medium` for it. Given a Kitty query whose `t` is `f`, `t` (temporary file) or `s` (shared memory), then neither the Daemon (`crates/terminal/src/scheme.rs`) nor the emulator replies `OK`; the reply is the error the emulator itself gives, or none, never both an `OK` and an error. A query with `t=d` still gets `OK` for its id (U5984), and a query for a medium the emulator does read gets `OK` only after the emulator can draw it. Tests: `u6145_a_file_query_gets_no_ok` (`crates/terminal`, scheme tests) and `u6145_the_emulator_answers_each_medium` (`apps/desktop/src/terminal/`).

**U6146 every reply to a terminal query claims only what the emulator draws or does.** Given an Agent Terminal, when a program sends each query below, then the reply, or its absence, matches what the emulator handles; the implementation's PR lists each query, its reply and the test:

- XTVERSION names roundup (or iTerm2 3.5 only under U6144's fallback).
- DA1 lists only features the emulator has.
- The Kitty graphics query, per medium (U6145).
- The Kitty keyboard query (`CSI ? u`) is answered only if the emulator reports and obeys the flags.
- DECRPM for modes 2026 and 1016 reports each mode as the emulator supports it: set, reset, or not recognized.
- OSC 11 reports the Terminal's background.
- `CSI 16 t` reports a cell size only if the emulator knows its cell size.
- OSC 7501 is answered only if the App handles it.

A reply that claims a feature the emulator lacks is changed or removed in the same PR. Tests: `u6146_<query>_reply_matches_the_emulator`, one per query, in `apps/desktop/src/terminal/` or `crates/terminal` where the Daemon answers. Observer: Vitest and `cargo nextest`, in `just check`.

**U6144a the Daemon answers a chunk's queries in the order the program wrote them.** Claude Code writes `CSI ? 2026 $ p`, a Kitty query, `CSI 16 t`, `CSI ? 1016 $ p` and DA1 in one write, and DA1's reply ends its wait. Given a Daemon Terminal whose program writes that batch, in one chunk or split inside the Kitty query, then the Kitty `OK` for the query's id reaches the program before DA1's reply. Tests: `u6144a_the_kitty_ok_reaches_the_program_before_da1_in_one_chunk` and `u6144a_the_order_holds_when_the_chunk_splits_inside_the_kitty_query` (`crates/terminal/tests/scenarios/scheme.rs`).

**U6144b a Daemon Terminal's environment claims only this emulator.** Given a Daemon Terminal started from a launcher whose `TERM` is `xterm-ghostty` and whose `TERM_PROGRAM` is set, or whose caller passes them, then the program sees `TERM=xterm-256color` and none of `TERM_PROGRAM`, `TERM_PROGRAM_VERSION`, `CLAUDE_CODE_FORCE_TERMINAL_IMAGES` or another terminal's variables. Test: `u6144b_a_terminal_claims_only_this_emulator` (same file).

**U6144c retired 2026-11-06.** The owner (2026-11-06): Claude Code's image rendering breaks its whole screen in roundup, so the forced flag goes. The forced flag drew Kitty U=1 placeholders that `@xterm/addon-image` cannot draw (xtermjs/xterm.js#6198, open); Claude Code now falls back to text.

**U7029 no pixel size reaches a program the App's emulator did not give.** Source: the owner's report in #7029: clicks in a Claude Code pane land rows away from the pointer once the user zooms text. herdr-core answered `CSI 16 t` with `CSI 6;20;10 t` and `CSI 14 t` with rows × 20 by cols × 10 whatever the App's text size; Claude Code 2.1.316 then reports mouse positions in pixels (`DECSET 1016`) and divides by 20, while the App's xterm sends its own pixels. This tightens U6146's `CSI 16 t` row. Given a Daemon Terminal whose program writes `CSI 14 t`, `CSI 16 t`, `CSI 18 t` and `CSI 19 t`, then:

- *No Daemon pixel size.* The Daemon sends the program no pixel-size reply (`CSI 4;…;… t` or `CSI 6;…;… t`), so a program that gets none stays on cell mouse reports and every click hits the cell under the pointer at every text zoom. The character-area replies (`CSI 8;rows;cols t`, from `18 t` and `19 t`) are the Daemon's own fact and are unchanged. Test: `u7029_the_daemon_sends_no_pixel_size_reply` (`crates/terminal/tests/scenarios/scheme.rs`), which writes the batch through a spawned Terminal and asserts the bytes the program reads hold no pixel-size reply; it fails on `main`.
- *Order and once.* `DECRQM 1016` and DA1 in the same batch still get one reply each, in the order written (U6144a). Test: the same, and `u6144a_the_kitty_ok_reaches_the_program_before_da1_in_one_chunk` with its expected bytes updated.
- *Audit.* Every other query the Daemon answers on its own (`DECRQM`, colours, cursor and device reports) is listed with the side that holds its fact; a reply the emulator that draws the Terminal should give is removed from the Daemon in the same PR. Test: `u7029_each_daemon_reply_names_its_owner` is a table in the PR body, one row per query, not a test; each removal has its own `u7029_` test in the file above.
- *App answer (optional).* If the App's emulator answers `CSI 14 t` and `CSI 16 t` from its measured cell size and again after a zoom, the Daemon still sends none (the first row holds) and the App's reply reaches the program once. Test: `u7029_the_emulator_answers_pixel_sizes_after_a_zoom` (`apps/desktop/src/terminal/`), only if this path is built.

Observer: `cargo nextest` in `just check`, against a spawned Terminal with no App. The real-`claude` observer: on the user's Mac, after a text zoom, a click low in a Claude Code pane selects the row under the pointer (L46).
