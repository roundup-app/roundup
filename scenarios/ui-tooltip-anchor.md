**U2749a the Project root Kind owns its tooltip.** Given the U26 harness with `tree-40` at Project root and a Workstream whose Door has a Kind, when the pointer rests on that entry's Kind glyph, then one shared Tooltip opens, its text is the Kind label and its anchor box contains the pointer. The glyph's element carries the trigger; the full-width overview entry button does not own the Kind tooltip. Moving onto another control shows that control's own tip, not the Kind label. Test: `u2749a_project_root_kind_owns_its_tooltip`, through the mounted overview with the fake App, asserting the opened tooltip's text and anchor containment using controlled element rectangles and pointer events. Do not assert position, size or gap. Preserve U2567a's accessible name and U2567c's selection behavior; the state gains no button role or tab stop (policy).

**U2749b every tooltip uses one anchor rule.** Given a tooltip triggered by a pointer, when it opens, then `ui/Tooltip.tsx` anchors it to the box of the smallest element carrying that tooltip's trigger under the pointer, rather than an enclosing layout container (policy: inspect trigger ownership and the rendered observer below). Descendant SVG paths and decorative children do not become separate owners. A caller intentionally anchoring to a wider element passes that element through a named explicit anchor option; U521's truncated Rail row keeps its whole-row anchor and unchanged full text. Keyboard focus opens against the owning trigger without requiring pointer coordinates. Tests: `u2749b_explicit_row_anchor_keeps_full_text` (the Rail row's named anchor is used and the full name opens), `u2749b_focus_opens_without_a_pointer` (focus opens a shared Tooltip). Existing U521, U501 and U2228a behavior remains (policy).

Given a pointer-opened tooltip whose chosen anchor box excludes the opening pointer, when opening is attempted under `import.meta.env.DEV` or Vitest, then the Tooltip throws; this includes an explicitly supplied anchor. Keyboard-only opening does not run this pointer assertion. Test: `u2749b_pointer_outside_anchor_throws`, exercising the actual Tooltip open path with controlled rectangles and pointer coordinates, in each environment branch. This contract checks ownership, not tooltip geometry; no production throw is required (policy).

**U2749c callers cannot bypass the shared Tooltip.** Given App tooltip callers, when migrated, then there is one `Tip` wrapper, backed by `ui/Tooltip.tsx`; `rail/Tip.tsx` and `ink/Tip.tsx` no longer define competing wrappers. Outside `apps/desktop/src/ui/` and the single selected wrapper file, no caller imports `@ark-ui/solid/tooltip` or renders `Tooltip.Root`. No App JSX element carries a `title` prop: a native tooltip would bypass the anchor rule (policy). `.oxlintrc.json` enables a lint rule enforcing those boundaries.
