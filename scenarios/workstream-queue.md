# Workstreams that own a Todo, start when the user chose, and run under a cap (A3194 to A3197, U3743 to U3745)

Module: `crates/agents`, `crates/todos`, `crates/contracts`, `crates/rupd`, `crates/rup`, `contracts/generated/` and `apps/desktop`. Ids: A3194, A3195, A3196, A3197, U3743, U3744, U3745. Acceptance for #3194. Decided by the user: a queue with a per-Project cap; a Workstream counts as running while any of its Agents is `working`. Builds on A6 (`rail.createWorkstream` persists a Workstream with a stopped Door), A7/A24 (`rail.startDoor`), O3 (the Door's order), T16/T17 (a Todo's owner, `todo.assign`), `todo.move` (a Todo's Home) and U3720 (the owner picker). P9 bounds how: a start spends usage, so only the user's earlier choice starts one.

`GLOSSARY.md` gains **Start choice** (`now`, `queued` or `afterTodo`: the user's pick of when a new Workstream's Door starts), **Queue** (the Project's ordered list of Workstreams whose Start choice has not yet started their Door) and **Workstream cap** (the Project setting `workstreamCap`, the most Workstreams that run at once; `null` is no cap), and **Running** (a Workstream is running while any Agent under it, its Door included, has Status `working`), in the implementing PR (Contract recipe of `.agents/builder.md`).

**A3194 a Todo gets a Workstream to own it.** Contract change (the Contract recipe). New method `todo.startWorkstream {id, name, start}` with `start` one of `{kind: "now"}`, `{kind: "queued"}`, `{kind: "afterTodo", todo: <id>}`; it returns the created Rail node. Given an open Todo `t` with a Home and owner, then in one call: a Workstream named `name` is created as `rail.createWorkstream` does (A6, stopped Door) with O3's order seeded from `t`'s title and body; `t` is moved to it (`todo.move`) and assigned to its Door's Actor (`todo.assign`, T17: the Door's Actor id is the Workstream id); `t`'s history holds both changes; and the Start choice is applied by A3195. A done Todo, an unknown `id`, an empty `name` or an `afterTodo` naming `t` itself or an unknown Todo is `INVALID_PARAMS` or `NOT_FOUND` and changes nothing: no Workstream, no move, no owner. A second Todo may name the same new Workstream's name; each call makes its own Workstream. Logs a `wrote` Touch on `todo:<id>` by the caller. Tests (`a3194_`): `a3194_the_todo_moves_to_the_new_workstream_and_is_owned_by_its_door`, `a3194_a_refused_call_changes_nothing`, `a3194_the_orders_seed_comes_from_the_todo`.

**A3195 the Start choice decides when the Door starts, and the cap gates the queued ones.** Contract change. Given A3194's call, then: `now` starts the Door at once as `rail.startDoor` does (A7), whatever the cap, because the user chose it now (policy); `queued` appends the Workstream to the Queue, and `afterTodo {todo}` appends it with that Todo, and neither starts the Door. A Workstream counts as running per **Running** above; one whose Agents are idle, ended, `needs-you`, `blocked` or `error` does not. A Workstream the Queue just started counts as running from that start until its Door reports its first Status after the launch, so one count change never starts two over the cap. New methods: `project.setWorkstreamCap {cap}` (an integer 1 or more, or `null`; `0`, a negative or a fraction is `INVALID_PARAMS` and changes nothing) returning `null`, with `project.get` gaining `workstreamCap` (`null` for a Project that never set it); `workstream.queue {}` returning `{running, cap, entries: [{workstream, start}]}` in Queue order. `workstream.dequeue {workstream}` takes an entry out and leaves the Workstream with its stopped Door; `workstream.queueMove {workstream, index}` places an entry; `workstream.startNow {workstream}` starts a queued Workstream's Door at once, as `now` does and likewise whatever the cap. Each change emits `workstream.queueChanged`. Tests (`a3195_`): `a3195_now_starts_the_door_over_the_cap`, `a3195_queued_and_after_todo_start_nothing_by_themselves`, `a3195_running_counts_a_workstream_while_any_agent_is_working`, `a3195_a_just_started_workstream_counts_before_its_first_status`, `a3195_an_invalid_cap_changes_nothing`, `a3195_dequeue_move_and_start_now_change_the_queue_once_each`.

**A3196 a queued Workstream starts when a slot frees, in Queue order.** Given a cap `c` and a Queue, then at each count change (a Workstream starts or stops running, or leaves the Rail) and when an `afterTodo` entry's Todo becomes done, the Daemon starts Doors from the head of the Queue until the running count is `c`: an entry is eligible when it is `queued`, or its `afterTodo` Todo is done or gone (a deleted Todo frees its entry as `queued`, policy). An ineligible entry is skipped, never a block for those behind it, and keeps its place. With `cap: null` every eligible entry starts. Each start is `rail.startDoor` with the Workstream's order (O3, A24's returns-or-fails), and is the only start the Queue makes. A start that fails leaves the entry in the Queue at its place, emits one `workstream.queueChanged` with the failure's code on the entry, and does not stop the pass for those behind it. Tests (`a3196_`, a fake clock and fake Statuses): `a3196_a_freed_slot_starts_the_head_in_order`, `a3196_an_after_todo_entry_waits_for_its_todo_and_blocks_none_behind_it`, `a3196_no_cap_starts_every_eligible_entry`, `a3196_a_failed_start_keeps_its_place_and_does_not_stop_the_pass`, `a3196_a_removed_workstream_leaves_the_queue`.

**A3197 a restart and a changed cap start nothing.** Given a Queue and a cap, then the Queue and the cap are stored with the Project (G1's store) and survive a Daemon restart intact, order included; opening the Project starts no Door, and no entry starts until the next count change or done Todo of A3196. `project.setWorkstreamCap` and `workstream.dequeue` or `workstream.queueMove` take effect at the next such change, never start or stop a Workstream by themselves, and lowering the cap stops nothing that runs. Tests (`a3197_`): `a3197_the_queue_and_cap_survive_a_restart_and_start_nothing`, `a3197_changing_the_cap_starts_and_stops_nothing_by_itself`, `a3197_the_next_count_change_uses_the_new_cap`.

**U3743 the owner picker offers New Workstream….** Narrows U3720. Given the owner picker of a Todo row (the plain key `o` or the row's `Assign` word), then one more offer, `New Workstream…`, follows the Agents and precedes `Unassigned`, reachable by Tab, the arrow keys, Enter and Space as the others are. Choosing it closes the picker and opens a dialog (`ui/` dialog primitive wrapping Ark UI, never a hand-written state machine, policy) with a name field prefilled from the Todo's title, and a start choice of three radios in this order: `Start now`, `Start when a slot frees` (selected) and `Start after another Todo`, which reveals a list of the Project's other open Todos. `Create` is disabled for an empty name or an unpicked Todo; it calls `todo.startWorkstream {id, name, start}` once and nothing else, closes the dialog and focuses the Todo's row (found by `#<id>` after the refetch), never `body` (U138). Esc or `Cancel` calls nothing. A refused call keeps the dialog open with the typed values and shows `✕ <message>` in it (U2773a). Tests (`u3743_`, fake App seam): `u3743_the_picker_offers_new_workstream_between_agents_and_unassigned`, `u3743_create_calls_start_workstream_once_with_the_chosen_start`, `u3743_after_todo_needs_a_picked_todo_and_a_name_is_required`, `u3743_esc_cancels_with_no_call_and_a_refusal_keeps_the_values`.

**U3744 the queue is visible on the Rail.** Given Workstreams in the Queue, then each one's Rail row shows, as light text out of the flow (U112: no row changes its top edge, height or wrapping), `queued · <n>` with `n` its place from 1, or `after #<id>` for an `afterTodo` entry; the badge goes when its Door starts or the entry leaves, from `workstream.queueChanged` and a refetch of `workstream.queue` (U15). The Rail row's menu offers `Start now`, `Take out of queue` and `Move up` / `Move down` for a queued row only, each calling `workstream.startNow`, `workstream.dequeue` or `workstream.queueMove` once and nothing else; a failure shows `✕ <message>` in the row's place of U35. Layout and looks are the design critic's. Tests (`u3744_`): `u3744_a_queued_row_shows_its_place_or_its_todo_and_loses_it_when_started`, `u3744_the_row_menu_calls_one_method_per_choice`, `u3744_a_failure_shows_its_cause_on_the_row`.

**U3745 the Project's cap is a setting.** Given the Project settings where U377 puts the Models, then a `Run at most` number field with the label `Workstreams at once` and a `No limit` toggle (selected when `workstreamCap` is `null`) call `project.setWorkstreamCap {cap}` once per commit (Enter or blur with a changed value), with an integer 1 or more or `null`. An entry that is not a whole number of 1 or more is refused in the field with `✕ <message>`, calls nothing and keeps the old cap. The field reads `project.get`'s value, so a Daemon restart shows what was set (A3197). Tests (`u3745_`): `u3745_a_commit_sets_the_cap_once_and_no_limit_sets_null`, `u3745_a_bad_entry_calls_nothing_and_keeps_the_cap`.

**Regression.** Workstream create and Door start tests (A6, A7, A24, O3), Todo Home and owner tests (T16, T17, `todo.move`, U3720) and #3024's idle hand-off keep every clause; nothing here starts a Door except the user's own `now` and A3196's Queue.
