# Receipt and hook storage

Module: `crates/agents`. Terms: Adapter, Signal, Message, Tool call, Read cursor (`GLOSSARY.md`). These clauses preserve B50 receipt semantics, U3780a's tool-call output and B5519a's completed-turn boundary while bounding discarded work. No App, contract, delivery rule or `AgentAdapter` trait change is ordered.

**B5635a receipt scans read only the appended suffix.** Given a transcript with a saved byte cursor at the end of its last complete line, when the existing receipt path scans it again, then:

- An unchanged 30 MiB transcript causes zero transcript content bytes to be read. After each of 100 complete appends, only bytes from that scan's saved cursor to the new end are read; summed reads equal the appended suffix's byte length. The returned Message ids and cursor match those complete lines, in order. Extend `b50_a_transcript_is_read_from_where_it_was_left` in `crates/agents/tests/inbox.rs` for complete-line behavior; add `b5635a_receipt_reads_only_appended_bytes` in the receipt reader's unit tests in `crates/agents/src/claude_code/inbox.rs` for counted reads through the production reading path. Metadata and seek operations are not content reads.
- Both B50 forms remain accepted: a top-level `origin` object and an `attachment.origin` when no top-level origin object exists. A top-level non-peer origin object takes precedence over a nested peer origin. A peer origin with a valid roundup `msg_id` returns its Message id; absent, malformed or foreign origins and malformed JSON lines return none but consume complete lines. Receipt parsing selects those fields and skips unrelated JSON fields, rather than retaining a full JSON value. Extend `b50_the_transcript_records_a_note_as_a_peer_message_under_its_msg_id` in `crates/agents/tests/inbox.rs` and add `b5635a_receipt_fields_and_cursor_failures` beside the reader's unit tests for precedence and invalid inputs.
- A final line without a newline yields no id and leaves its bytes outside the committed cursor; completing it on a later scan yields its id. An offset beyond a truncated file clamps to that file's length; the reader does not silently rescan its earlier contents. An explicit rescan starts from zero and may return earlier ids for the existing delivery layer to deduplicate. An open, seek or read error returns no ids and preserves the incoming cursor, including an error after a complete line was read. `b5635a_receipt_fields_and_cursor_failures` asserts incomplete UTF-8 at the unfinished tail, truncation and injected reader errors; `b5635a_rescan_and_registry_isolation` in `crates/agents/src/events/tests.rs` asserts explicit rescan uses the production scan path and returns the same receipt ids.
- Per-transcript reading is serialized without holding the shared transcript registry lock over file I/O. While transcript A's read is held at an injected reader barrier, transcript B can be registered and scanned to its own completed cursor. Releasing A preserves both cursors and receipt ids. `b5635a_rescan_and_registry_isolation` asserts this with synchronization barriers, not a sleep or elapsed-time performance assertion.
- With a 30 MiB fixture made of complete JSON lines no longer than 1 KiB, with unrelated string/nested fields and no receipt ids, a full initial scan allocates at most 256 KiB in total; an unchanged rescan allocates at most 64 KiB. Fixture creation is excluded. `b5635a_receipt_reads_only_appended_bytes` measures the actual reader/parser work, so a whole-file read or per-line full-value allocation cannot pass merely by returning the correct cursor.

Policy: use standard `File`, `Seek` and `BufReader` and installed Serde. Keep the cursor and per-transcript state as necessary history; do not add a persistent copy of transcript contents. Keep file-change and Signal-driven receipt discovery, explicit rescan and existing observer delivery. This changes no Message status, receipt identity, inbox transport or Terminal input path.

**B5635b tool previews retain bounded temporary storage.** Given an already-parsed hook payload, when the existing tool-call fold handles arguments, a successful result or a failure result, then:

- Output remains U3780a's: null is empty text, strings are used directly, other values use Serde's existing pretty JSON representation. Apply the existing terminal-escape/control removal semantics before cutting. Preserve Unicode; keep newline and tab; remove other control characters, CSI and OSC/DCS/APC/PM/SOS sequences, including the existing behavior for unfinished escapes. Arguments and results are at most 4096 UTF-8 bytes including the existing `… (cut, N bytes more)` mark; when longer, keep the longest character-boundary prefix at or before byte `4096 - 48`, with `N` equal to the exact number of cleaned UTF-8 bytes omitted. An uncut value has no mark. Extend `u3780a_long_arguments_and_results_are_cut_with_a_mark` in `crates/agents/src/claude_code/toolcall.rs` to assert exact omitted counts and unchanged uncut text. Add `b5635b_preview_preserves_cleaned_serialization` there for strings, null, objects, arrays, Unicode, controls and escape sequences, with expected outputs independent of the new implementation.
- Summaries keep the existing tool/field selection and Project-relative path behavior, collapse whitespace to single spaces without leading/trailing spaces and keep at most 200 Unicode characters. Tool names remain cleaned and capped at 64 characters. `b5635b_preview_preserves_cleaned_serialization` covers repeated whitespace, multibyte text, root and non-root paths and unsupported tools; existing `u3780a_pre_tool_use_starts_the_call_with_tool_summary_and_arguments` keeps field selection coverage.
- Streaming the pretty serializer into the cleaner produces the same bytes regardless of writer chunk boundaries, including boundaries inside UTF-8, escape introducers/terminators and runs of summary whitespace. `b5635b_preview_preserves_cleaned_serialization` feeds the production sink the same byte sequence whole, byte by byte and split at each boundary of short fixtures, asserting identical exact text and omitted counts.
- For flat string and fixed-shape JSON inputs of 4 KiB, 64 KiB, 1 MiB and 5 MiB, each measured tool-call fold allocates at most 128 KiB in total, including retained output. Exercise PreToolUse arguments and summaries, PostToolUse results, and PostToolUseFailure's error string and response fallback. `b5635b_preview_allocations_stay_bounded` in the existing tool-call unit tests measures each size/path after payload construction and before any test-side formatting or cloning. This bounds live temporary storage as well as rejecting repeated chunk-sized temporary allocations proportional to input length.

Policy: feed installed Serde's pretty serializer through the existing cleaning semantics into bounded preview/summary storage. Scan discarded text to count omitted bytes exactly. Delete full-string preview intermediates and summary split/collect/join storage. Keep the current/last tracked call; do not add a cache or replace the serializer with a custom JSON formatter. U3780a's call identity, matching completion, failure state and duration rules remain unchanged.

**B5635c unrelated hooks do not copy a completed reply.** Given an Agent with a canonical 1 MiB completed reply, when it receives 200 unrelated Signals, then the completed turn identity, start/end boundary and text stay unchanged, and no completion-sized copy is allocated. `b5635c_unrelated_hooks_do_not_copy_completed_text` in `crates/agents/src/events/tests.rs` sends preconstructed ignored Signals through `Shared::observe`, measuring only observation: no individual allocation is 1 MiB or larger, and total allocated bytes for the 200 Signals exceed the same run with a 1 KiB completed reply by at most 64 KiB. Build each fixture and subscribe/drain its event observer outside the measured region; use the same Signals and count for both sizes. No vendor or Terminal process is started.

Given an accepted nonempty Stop for the same turn, when its text changes, then the canonical reply changes and one `RailChanged` is emitted even if Status does not change; the original completed-turn end boundary is retained. Replaying the same Stop again changes neither completion nor boundary and emits no `RailChanged` for completion. A Stop for a different prompt id does not replace the current completion. `b5635c_completion_changes_are_reported_once` in `crates/agents/src/events/tests.rs` asserts exact text, turn/start/end identity and event counts for initial completion, same-turn correction, unchanged replay and stale Stop, using an injected clock. Retain `b5519a_replayed_completion_keeps_its_original_message_boundary` as the existing replay regression; extend `u5483c_late_final_text_refreshes_rail_without_a_status_change` only where it does not duplicate these assertions.

Policy: determine completion changes where `ClaudeCode` accepts a Stop and return a small internal result to its caller; remove `was_completed` and its pre-observation reply clone. Keep the canonical completed reply and the existing `AgentAdapter` seam. Unchanged replay must not allocate a replacement reply solely to compare it with the canonical text. `b5635c_completion_changes_are_reported_once` measures unchanged replay separately after construction, allowing at most 64 KiB allocated for replay of the 1 MiB text, and verifies its no-change result.

## Gates and observers

Policy: P1's gate asks whether a Message can reach the Terminal or become delivered without the transcript receipt. B5635a preserves receipt ids, cursor behavior and the existing receipt observer, with no new acknowledgement path. P4's gate asks whether vendor parsing moves outside `claude_code/` or `AgentAdapter` gains a fourth seam. Keep receipt/Stop parsing in that Adapter; review the trait diff and the small internal observation result. The implementing PR must answer both gates no.

## Verification

All new cost observers are process-free and exclude fixture/payload construction, test-side copies, assertions and reporting. Allocation measurement must isolate the operation under test from other test threads (for example scoped thread-local counting); process-wide counters polluted by concurrently running tests cannot prove these bounds. Count reads beneath buffering on the real reader/parser path, not from the reported cursor or file length. Report measured bytes and the named bound on assertion failure. Reuse existing test seams and the installed allocation observer support; no new production telemetry is required.

On a prepared checkout, this one command passes in under five minutes:

```sh
cargo nextest run -p agents -E 'test(claude_code::) | test(events::) | test(b50_)'
```

Policy: new unit observers are inside `claude_code::` or `events::`; receipt integration extensions retain the `b50_` prefix so the command selects them. Keep implementation in `crates/agents/src/claude_code/{inbox,toolcall,mod}.rs`, `crates/agents/src/events.rs`, `crates/agents/src/events/tests.rs`, `crates/agents/tests/inbox.rs` and their existing unit tests; target 600–800 changed lines including observers. No dependency, public API or persistent-history removal is required.
