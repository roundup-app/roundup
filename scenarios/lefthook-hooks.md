# Pre-commit hooks by lefthook

Module: root `package.json`, `lefthook.yml`. Source: #3210. Ids: T3210, T3211, T3212, T5456a, T5456b, T5456c. Rule: `.claude/sound/placement/file-stays-under-a-size-cap.md`.

**T3210 a plain install turns the pre-commit hook on.** Given a clean clone, when `pnpm install` runs, then:

- `.git/hooks/pre-commit` exists and is run by lefthook, and `postinstall` (the `@anthropic-ai/claude-code` install) still runs (observer: `ls .git/hooks/pre-commit`, `grep lefthook .git/hooks/pre-commit`, `node_modules/.bin/claude --version`).
- Root `package.json` lists `lefthook` as an exact-version devDependency and a `prepare` script that runs `lefthook install`; `pnpm-lock.yaml` is regenerated by pnpm (policy).
- Root `lefthook.yml` retains the `pre-commit` command `file-stays-under-a-size-cap`, which runs `.claude/sound/placement/file-stays-under-a-size-cap.gate`; T5456a adds safe web lint fixing beside it (policy).

**T3211 an install under CI turns it on too.** Given the loop's runners set `CI=true` and the frozen workflows cannot set `LEFTHOOK`, when `CI=true pnpm install --frozen-lockfile` (the justfile's command) runs, then:

- The same `.git/hooks/pre-commit` exists, because `prepare` runs `lefthook install`, which has no CI skip, unlike the npm package's postinstall (observer: the same `ls` and `grep`, run locally and in a GitHub Actions runner of the loop; the PR names that run).
- No frozen loop file changes: not `.github/workflows/` except `check.yml`, not `.agents/`, `AGENTS.md`, `scenarios/loop-*.md` or `loop/` (policy).

**T3212 the hook enforces the cap.** Given the hook is installed, when a commit adds or grows a file over 1000 lines, then it is blocked with exit 1 naming the file; a commit under the cap passes (test: `loop/rules.test.sh` is frozen, so the observer is a throwaway repo in the PR: stage a 1001-line file and `git commit`, then a 10-line one).

Observer: `just check` and `pnpm install --frozen-lockfile` pass.


## Safe web lint fixes before commit

Source: #5456. This extends T3210's command list; T3211's installation and T3212's size guard remain required. This is build tooling, with no changed product path or new Principles gate. CI's independent lint and merge checks remain required.

**T5456a a commit contains safe web lint fixes.** Given installed dependencies and the repository's installed lefthook pre-commit hook, when a web source file whose only lint violation is a missing blank line before `return` is staged and an ordinary `git commit` runs, then the commit succeeds and `git show HEAD:<file>` contains the inserted blank line. The committed file passes the same non-fixing lint command used by CI. Test: planned `t5456a_commit_contains_the_spacing_fix` in `tools/oxlint/pre-commit.test.mjs`.

Policy — use the installed Oxlint's safe `--fix` mode with the repository configuration, and lefthook `stage_fixed: true`. Do not enable suggestions or dangerous fixes. Limit the lint command and re-staging to staged, existing web files supported by the repository's Oxlint configuration (JavaScript/TypeScript, including JSX/TSX and module variants); preserve ignored/generated paths. With no matching staged files, skip the lint command rather than linting the whole tree. Retain the size guard, dependency installation and all lint rules. Use lefthook's existing file selection, quoting and staging capabilities, not a new hook runner or file-list parser. [Oxlint safe fixes](https://oxc.rs/docs/guide/usage/linter/automatic-fixes.html), [lefthook staged-file selection](https://lefthook.dev/configuration/run/) and [lefthook re-staging](https://lefthook.dev/configuration/stage_fixed/) define these installed capabilities; verify them against the pinned versions during implementation.

Policy — the observer creates an isolated temporary Git repository with this checkout's real hook configuration, size guard, lint configuration/plugin and installed binaries; it installs the hook and runs a real commit. Do not substitute a fake linter or assert only YAML text or the working file: only the committed blob proves re-staging. Cover a filename containing spaces. A separate unstaged file with the same spacing violation must remain byte-for-byte unchanged and absent from the commit; test: planned `t5456a_unstaged_file_stays_out_of_the_commit` in the same test file. Clean up only repositories/processes the observer created. Real Git and hook processes are required by this scenario, so rule 10's process-free substitute cannot prove it.

**T5456b CI rejects spacing violations without changing files.** Given the same otherwise lint-clean source fixture with the blank line missing, when the non-fixing lint entry point used by `lint-web` runs on it, then it exits 1, reports `anti-slop/require-readable-spacing`, and leaves the file bytes unchanged. Running that entry point on the fixed fixture exits 0. Test: planned `t5456b_ci_rejects_unfixed_spacing_without_writing` in `tools/oxlint/pre-commit.test.mjs`. This observes the CI lint seam directly; no hook bypass or push is needed to construct the unfixed fixture.

Policy — `justfile`'s `lint-web` keeps invoking non-fixing lint. No rule is disabled or weakened, no CI job writes or pushes fixes, and no instructions recommend bypassing hooks. No workflow or frozen loop machinery changes are needed.

**T5456c a small commit adds less than five seconds.** Given installed dependencies on a Linux runner and three staged, otherwise lint-clean web source files of at most 100 lines each, one with the T5456a spacing violation, when an ordinary commit runs the installed hook, then the added hook time is strictly below 5000 ms. Test: planned `t5456c_small_commit_hook_stays_under_five_seconds` in `tools/oxlint/pre-commit.test.mjs`.

Policy — measure monotonic elapsed time around real commits after dependency installation and fixture setup. Compare two equivalent isolated fixtures: the baseline uses main's size-guard-only lefthook configuration (Check 1), and the candidate uses the implementation's configuration. Record both elapsed times and their difference; assert candidate minus baseline is below 5000 ms. Include the candidate's first lint invocation; do not hide startup cost with a warm-up. Do not run the whole web lint/typecheck/test suite inside the hook. This scenario requires the real clock and real commit processes; it is not a generic test timeout.

Checks already on main:

1. `lefthook.yml`, `pre-commit.commands.file-stays-under-a-size-cap`: the existing size-guard-only hook configuration.
2. `package.json`, `scripts.prepare` and `devDependencies.lefthook`: hook installation and pinned hook runner.
3. `tools/oxlint/anti-slop/rules/require-readable-spacing.ts`, `requireReadableSpacingRule`, backed by `tools/oxlint/anti-slop/vendor/eslint-stylistic/padding-line-between-statements.ts`, `createPaddingLineRule`: the structural-spacing rule and its whitespace fixer.
4. `.oxlintrc.json`, `rules`: enables `anti-slop/require-readable-spacing` as an error, with the repository's plugin and ignore configuration.
5. `justfile`, `lint-web`, and `package.json`, `scripts.lint`: the CI lint entry point, through `tools/oxlint/anti-slop/web-assertions/lint.mjs` (top-level CLI).
6. `.claude/sound/placement/file-stays-under-a-size-cap.gate` (top-level script): reads staged blobs and exits 1 for a new/grown handwritten file over the cap.

Implementation scope: `lefthook.yml`, `tools/oxlint/pre-commit.test.mjs`, and `tools/oxlint/anti-slop/web-assertions/lint.mjs` solely to include the new observer in its existing fixture invocation, so CI runs the regression tests. Run the observer directly with `node --test tools/oxlint/pre-commit.test.mjs`. Reuse the installed lefthook and Oxlint; add no dependency, custom staging machinery, workflow change or product code. Keep this specification's work Issue open until implementation demonstrates all three scenarios.
