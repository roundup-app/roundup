# Hand off to a builder

Module: `crates/rupd` (the `agent.handoff` call), `crates/agents` (the builder start, Rail placement, caller end), `crates/contracts`, and `apps/desktop/src/rail/` (the menu item). Terms: Agent, Job, Work order, Pad, Reach, Mode, Workstream, Door, Rail (`GLOSSARY.md`). Ids: H7200a–H7200f. Acceptance for #7200 (owner, 2026-11-15: "once you settle you hand over the build phase to a roundup agent and kill yourself").

Contract change (rule 4): `agent.handoff {order, pad}` is a new RPC method with a CLI and MCP tool (`agent_handoff`), and the implementing PR adds **Handoff** (`agent.handoff`, `/handoff`, label "Hand off") to `GLOSSARY.md`. `agent.stop` gains no self-stop.

**H7200a a handoff starts a builder Job that takes the caller's place.** Given a running Agent `c` that holds a settled Work order (O1: title, ask, done, limits) and a Pad `p` holding the detail a builder needs, when `c` calls `agent.handoff {order, pad: "p"}`, then the Daemon starts one Job `b` (A4) whose Work order is `order`, whose first prompt names `p` and holds no copy of `c`'s conversation, and whose Rail parent or Workstream, and position among its siblings, are `c`'s. The result names `b`. `b` is not in `c`'s Reach and is not its child, so ending `c` leaves `b` running (test: `crates/rupd/tests/h7200_handoff.rs::h7200a_the_builder_takes_the_callers_place`). An unknown Pad is `NOT_FOUND` and starts nothing (`h7200a_an_unknown_pad_starts_nothing`).

**H7200b the caller ends only after the builder runs and the caller has its reply.** Given H7200a's call, then the Daemon sends the result first, then stops `c`, and only once `b` is running (its Terminal is up, A4). Given the start of `b` fails, then `c` keeps running, nothing is stopped or moved, and the call returns the error, which `c` shows its user (test: `h7200b_a_failed_start_keeps_the_caller_running`). Given a successful call, the stop of `c` is ordered after the reply (`h7200b_the_caller_is_stopped_after_its_reply`).

**H7200c self-stop stays refused everywhere else.** Narrows M7 (`scenarios/mcp.md`): `agent.stop` and `agent_stop` on the caller itself, and every method M7 lists, still return `FORBIDDEN` for the caller's own id; only `agent.handoff` ends its caller. A user, or an Agent outside the caller, cannot call it for another Agent (`h7200c_agent_stop_on_oneself_is_still_refused`, `h7200c_handoff_acts_only_on_its_caller`).

**H7200d the Rail shows the builder where the caller was.** Given H7200a's success, when the Rail updates, then `c`'s row is gone from `rail.tree` and from the App's Rail, `b`'s row stands at `c`'s former position under the same parent or Workstream, and when `c`'s row was selected, `b`'s row is selected (the App's selection follows the `rail.changed` event; test: `apps/desktop/src/rail/handoff.test.tsx::h7200d_the_builders_row_replaces_the_callers_and_takes_its_selection`). A caller that was not selected leaves the selection unchanged (`h7200d_selection_stays_when_the_caller_was_not_selected`).

**H7200e a Mode stays and restarts.** Given a Mode Agent `m` (a root Agent with a saved first prompt, A4452c) calling `agent.handoff`, then `m` is not stopped and not removed; `b` starts as its own root Agent; and `m` then restarts fresh from its saved first prompt through the `agent.restartMode` path (A4452c, U4547d), typing that prompt once and no other input. A failed builder start restarts nothing (tests: `h7200e_a_mode_keeps_its_row_and_restarts_fresh`, `h7200e_a_failed_start_does_not_restart_the_mode`).

**H7200f the user reaches a handoff by `/handoff` or the Rail menu.** Given any Agent roundup launches, then `/handoff` is a command of roundup's own bundled plugin (LC5), which roundup adds without removing any of the user's (LC2, LC6); it tells the Agent to write the settled Work order, put the builder's detail in a Pad, then call `agent.handoff`, and to run on its own only when the user's words told it to (test: `crates/agents/tests/launch.rs::h7200f_every_launch_carries_the_handoff_command`). Given an Agent's Rail row, when its right-click menu opens, then it offers Hand off, labelled so, while the Agent's Kind is idle or needs-you, and not while it is working, exited, or a Door; choosing it types `/handoff` into that Agent exactly as the user would (A2698a) and sends no `agent.handoff` itself (tests: `apps/desktop/src/rail/handoff.test.tsx::h7200f_hand_off_shows_only_for_an_idle_or_needs_you_agent`, `h7200f_hand_off_types_the_command_into_the_agent`). Where the menu is native (U2694a–e), the same item and conditions apply to it. Policy: the item's place in the menu and its icon follow `docs/design-system.md`, judged by the design critic.

Observer: real-Daemon integration tests in `crates/rupd/tests` with a fake `claude` (no vendor, display or network), and App tests under `apps/desktop/src/rail/`. Laws touched: M7 and M9 (`scenarios/proofs.md`: a Mode restart is a replay and no Message is typed twice); no law is weakened and `docs/messages.md` and `proofs/messages` stay as they are unless the build changes a Message transition, when the Contract recipe applies.
