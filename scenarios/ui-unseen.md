# UI: find an Agent's unseen finish

Module: `apps/desktop` (App state and summaries), `crates/agents` (retained finish count) and `crates/contracts` (one Status field). Ids: U3566a, U3566b, U3566c, U3566d, U5153a, U5153b, U5153c.

Work order: [#3566](https://github.com/saadshahd/roundup/issues/3566). Journey: Understand → Review (`.agents/data/journey.md`, headings “What must work” and “How a Builder closes a gap”). A finish means a published Kind transition directly from `working` to `idle` or `done`; it says that a turn ended, never that its result was accepted or independently checked. A Door is an Agent too. Plain Terminals keep U3704's separate unseen-output behavior.

**U3566a a finish waits to be read.** Given two Agents in an open Project, with A selected and B `working`, when B publishes an `idle` Status, then B's Rail row exposes an unseen state; selecting B clears it. Required CI guard: `u3566a_unselected_finish_is_unseen_until_selected`, one integration test through the fake App seam rendering the real App, emitting `agent.status` and selecting the real Rail row. Assert the accessible state appears and disappears, not its colour, size, CSS or exact copy.

Given the same setup, the following cases are asserted by `u3566a_only_unviewed_finishes_wait`, a parameterized App-seam observer beside the guard:

| Action | Result |
| --- | --- |
| B changes `working` → `done` | B becomes unseen, just as for `idle`. |
| The selected Agent finishes while its Project is active, its pane is displayed, the document is visible and the window has focus | No unseen state remains for that finish. Terminal keyboard focus is not required. |
| The selected Agent finishes with the window blurred or hidden, or its Project inactive | It becomes unseen; a remembered selection in a background Project is not viewing. |
| The user returns to the visible, focused window with that Agent's pane displayed | Its unseen state clears. |
| B is unseen and another Status arrives, including another `working` turn | It stays unseen until viewed. |
| A Status repeats, changes only its label, or goes to `needs-you`, `error` or `blocked` | It creates no new unseen finish. Existing Kind behavior stays intact. |

Given an unseen Agent, opening its pane by Rail pointer selection, Rail keyboard selection, the Switcher or an Agent link clears only that Agent's unseen state (`u3566a_opening_an_agent_marks_only_it_seen`, parameterized through the existing selection paths). Opening only its Project, expanding its Workstream, hovering its row or highlighting a Switcher result does not mark it seen (`u3566a_navigation_without_opening_keeps_unseen`). These tests assert state and selected identity, not layout. Policy: seen changes send no Message, start no program and change no Kind or result acceptance.

**U3566b summaries retain every unread child.** Given unseen Agents in two Workstreams and two open Projects, including matching Agent ids across Projects, then a collapsed Workstream row exposes one unseen state exactly when its Door or at least one of its descendant Agents is unseen, with no unseen state on Project tabs (U5153a). Expanding a Workstream leaves its children unseen. Opening one Agent clears that child's state and clears each aggregate only if it had no other unseen Agent. The state follows the Agent's current Home after a move and never crosses Projects. Observer: `u3566b_summaries_follow_their_unseen_agents`, a parameterized App-seam integration test of collapsed rows, Door finishes, moves and independent Project identities.

Given an unseen finish alongside `needs-you` and `error`, then all existing attention Glyphs, counts and tab actions remain available; the Rail finish mark is additional passive state, never a replacement. Clicking the Project tab selects that Project under its existing contract; unseen finishes add no tab mark or jump action. The Dock badge still counts only `needs-you` and `error` across open Projects, with none at zero (U10 in `scenarios/ui.md`, heading “U10 Dock badge”, and U182 in `scenarios/project-tabs.md`, heading “U182 hover tells the count”). Observer: `u3566b_unseen_is_separate_from_attention`, checking accessible states, navigation and badge calls for unseen-only and mixed states. Policy: U182's attention tooltip and attention-jump rules are unchanged; unseen alone does not create that tooltip or count.

**U3566c reload preserves seen state and discovers missed finishes.** Given an unseen Agent and another whose latest finish was viewed, when the webview reloads with the same App storage, then the first stays unseen until viewed and the second stays seen. An automatically restored selection in an inactive Project or blurred window does not acknowledge a finish; a restored pane actually displayed in the visible, focused active Project does. Given a finish during the reload gap, including a finish followed by another `working` turn, then reconnecting discovers it even when its Status event has left the bounded replay log. Observer: `u3566c_reload_reconciles_finishes_with_seen_state`, a parameterized App-seam test remounting with retained storage and authoritative trees, including a newer finish after an earlier one was seen. Distinct Projects' seen records never acknowledge each other's Agents.

Policy, Contract recipe: add only `finished` to Status, a canonical nonnegative decimal string counting this Agent's published finishes, starting at `"0"`. It increases once for each direct `working` → `idle` or `done` transition, before that Status is published; other transitions, duplicate observations and reads do not increase it. The count belongs to the Agent identity, survives Attempts and Daemon reopen, and never resets on resume. A reconstructed `done` at reopen is not an observed finish. Synthetic Workstream aggregate Statuses carry `"0"`; a Door's own Status carries its own count. A plain Terminal has no such Status. `rail.tree` and `agent.status` carry the same authoritative count. Use no timestamp comparison and infer no finish from Terminal bytes or prose.

Observer: `u3566c_finish_count_survives_attempts_and_reopen`, an in-process `crates/agents` test through public Agent/rail operations and controlled Adapter observations, asserts counting, duplicate/non-finish exclusion, equal-clock transitions, the returned tree/event agreement, resume and reopen. Reuse the existing fake Adapter and clock; no real vendor or browser is required for this contract observer.

Policy: the App stores acknowledged counts per original Project and Agent. An unseen count already acknowledged is not restored by duplicate or older events; existing Attempt/Status-revision guards continue to reject stale live events. With no prior seen record (including migration from an older App), baseline the first tree's count without marking historical work unread, then observe later increases. Existing saved Rail selection and folds still restore. Seen state remains App-owned: no seen RPC or Daemon acknowledgement is introduced. Change all Status producers, callers and fixtures in the implementation PR and regenerate `contracts/generated/` from `crates/contracts`; do not hand-edit it. This adds no Message or Route semantics and changes none of M1–M10 (`scenarios/proofs.md`).

The need for this field is established on main by `crates/contracts/src/common.rs`, `Status` (only current Kind, label and since), `crates/agents/src/rail_view.rs`, `Shared::present` (Status revision absent after reopen), and `apps/desktop/src/app/events.ts`, `connectEvents` (expired replay restarts at the oldest retained event). None retains the last finish when a later working Status replaces it. Extend the existing App storage and Status holders; no parallel event log, polling or new App seam command is required (policy).

**U3566d the finish dot is quiet state beside the name.** Policy, design critic observer only: show one small static dot in `--accent` beside the Agent name and the collapsed Workstream name when their unseen state holds. U5153b replaces the caption-size character with shared Token-only dot geometry, including U3704's Terminal unseen-output dot (`apps/desktop/src/bubbles/styles.css`, selector `.terminal-tab-unseen`). Colour is the scoped difference: Terminal unseen output remains `--grey`, as `scenarios/ui-surfaces.md`, heading “U3704 state rides with the name, apart from the actions”, requires. Add no Token and change no existing Token value.

Policy: the dot carries `data-state` and an accessible state label, “Unread result”, from the App copy catalogue. It has no button role, tab stop, pointer cursor, tooltip action or hover wash. It neither replaces nor recolours the Kind Glyph; it is not Ink. Keep it present on hover and focus, with no action between it and the name, and with U3704's separation from trailing actions. U179's name-and-attention-mark-only rule (`scenarios/project-tabs.md`, heading “U179 the header is the strip”) holds: unread finishes add no Project-tab mark. No counts, banners, Toasts, bells, OS alerts, pulses or automatic navigation announce routine finishes. No motion is added.

Policy, P3 Gate and Observer (`PRINCIPLES.md`, heading “P3 Cards over chatter”): does a routine finish introduce an interruption? It must not. Observe ordinary finishes through the App seam tests above: only passive unread state changes, while `needs-you` remains the attention contract. The Understand/Review journey observer finds an Agent that finished out of view, opens its output through each existing path, and returns after a reload without losing unread work.

Rendered observer (policy, implementation): isolated headless Chromium, a dedicated session and fresh profile, at 1512×950 in dark. Extend `agents-10`, `tree-40` and `tabs-8` with unseen finishes in an inactive Project and a collapsed Workstream, alongside `needs-you` and `error`; include the densest seed with long names and a failed RPC's failure text visible. Inspect rest, hover, focus, collapse/expand, Project switch, Agent open and reload. The critic judges D2 (type/spacing), D5 (contrast) and D6 (states/targets), defined by `docs/design-system.md`, heading “The checks”; no Check passing on main regresses. Run `just capture U3566a,U3566b,U3566c,U3566d`; leave before/after PNGs and Check readings with base/head SHAs under `artifacts/ux/<id>/` as `.agents/data/harness.md`, heading “Captures”, requires. ## Attention-only Project tabs (#5153)

Work order: [#5153](https://github.com/roundup-app/roundup/issues/5153). Module: `apps/desktop` only. Journey: Understand → Intervene → Review (`.agents/data/journey.md`, “What must work”). This specification narrows U3566b and U3566d above and U443 (`scenarios/ui-project-tab-box.md`, “U443 the Tab mark is a small dot after the name”). U443 already replaces U398's KindGlyph drawing; retain its attention meaning, accessible names, click and contrast while replacing its dot geometry below. No RPC, Status, storage or App seam command changes are required. Implementation policy: use the existing attention counts and unseen state; add no second attention store, polling, parser or interaction state machine.

**U5153a only attention marks a Project tab.** Given three open Projects, A active, B with two unviewed finishes but no `needs-you` or `error`, and C with attention, then B has no tab mark or accessible unread-result state while its Agent Rail rows and collapsed Workstream rows retain U3566a/U3566b's unread behavior. In either an active or background Project, a positive error count produces exactly one `error` mark; otherwise a positive needs-you count produces exactly one `needs you` mark; zero of both produces none, irrespective of unread finishes. A Door counts as an Agent; plain Terminal unread output does not count. After the last attention Kind clears, the tab mark clears even if unread finishes remain. Observer: `u5153a_tabs_follow_attention_not_unread_finishes`, a parameterized mounted-App test using the existing fake App and authoritative Rail/Status events; assert accessible states and selected identities, never CSS or layout.

Given B unread-only and C with both attention Kinds, when the user clicks C's mark or uses leader `⇧J` from A, then C opens and its most urgent Agent is selected (`error` before `needs-you`, oldest `since` first); B is skipped. Scrolling B and C out of view exposes an overflow attention indicator for C only, with error taking priority over needs-you. Clicking B's name still opens B without an attention jump. Attention tooltip counts and Dock badge exclude unread finishes; U185's exited-Daemon error mark, cause and recovery remain intact. Observer: `u5153a_attention_routes_ignore_unread_only_projects`, a parameterized mounted-App test of mark click, leader key, overflow action, ordinary name click, tooltip, badge and Daemon exit through existing seams. Revise the tab assertions in `u3566b_summaries_follow_their_unseen_agents` and `u3566b_unseen_is_separate_from_attention` to require absent tab unread state; preserve their collapsed-row, identity and badge assertions.

**U5153b every unread or attention dot shares one small drawing.** Policy, design critic observer only: each dot is a filled circle with both dimensions `--space-1` (4 CSS px at the current Token values) and `--radius-round`; it is not a text `●` sized by the caption font. One shared geometry rule covers Project Tab marks, strip overflow attention dots, Rail Agent and collapsed Workstream unread dots, Overview section-head unread dots, and plain Terminal-tab unseen-output dots. Preserve their meanings and current tones: tab/overflow error red and needs-you amber, Rail unread accent, Overview unread text, Terminal unread grey. Do not replace KindGlyphs, counts, close/minimise controls or other icons with dots. Use existing Tokens only; add no Token and change no Token value. The implementation inventories every call site of these dots and names any retired character or local size rule on the Issue.

Policy, Project-tab placement: put the dot at the visible name's upper-right, including a middle-clipped name. Its left edge is `--space-1` after the name's right edge and its top edge aligns with the name's first line box top within 1 CSS px; it stays inside the tab's hit area, clear of close/recovery controls. Reserve the same space with and without the dot: changing attention among none, needs-you and error moves neither the name nor adjacent tabs/controls by more than 1 CSS px and changes no tab width. Dot appearance never changes the name's clipping. Other surfaces keep their existing state/name placement, trailing-action separation and layout. All dots remain static and visible through rest, hover, focus and selection; a tab mark retains its existing click through the tab trigger, with no extra tab stop. Noninteractive unread dots remain passive. Preserve accessible state labels and existing Overview section semantics. Visual size, placement and stability belong to the critic, never a UI layout assertion.

**U5153c the rendered journey distinguishes attention from unread work.** Policy, rendered observer for the implementation: use an isolated headless Chromium session and fresh profile at 1512×950 in dark, with `agents-10`, `tree-40` and `tabs-8` extended through the fake App seam. Include a background unread-only Project, needs-you-only, error-only and mixed-attention Projects, a collapsed Workstream containing an unread Agent, unread Overview sections and unread plain Terminal output. On the densest seed include long names, both overflow edges and visible failure text from a rejected operation. Observe rest, hover, keyboard focus, selection, Project switch, collapse/expand, Agent open, clearing attention with unread work remaining, and reload. An unread Agent remains findable in the Rail and opening it clears only its unread state; the attention mark and leader `⇧J` still reach the requesting Terminal. Behavioral proof is U5153a together with the retained U3566a–c observers; the critic judges the drawing and no-shift policy in U5153b.

Policy, Checks moved (all defined on main in `docs/design-system.md`, “The checks”): **D2** Token geometry/spacing; **D5** at least 3:1 dot contrast against its actual ground, selected or unselected, retaining U443's light/dark contrast obligation; **D6** existing keyboard access, feedback and at least 24 CSS px control hit heights despite the 4 CSS px drawing. No Check passing on main regresses. Run `just capture U5153a,U5153b,U5153c`; leave paired base/head PNGs and Check readings with SHAs under `artifacts/ux/<id>/` as `.agents/data/harness.md`, “Captures”, requires. The specification PR makes no rendered or native Mac claim; implementation closes on the Linux/Chromium observer and the user reports what they meet on the Mac.

Policy, P3 Gate: can a routine finish interrupt the user or masquerade as a request for attention? It must not. Observer: U5153a's ordinary finish changes Rail unread state without creating a tab/overflow attention mark, badge count or attention jump; no bell, OS alert, pulse or automatic navigation is added.
