# UI: find an Agent's unseen finish

Module: `apps/desktop` (App state and summaries), `crates/agents` (retained finish count) and `crates/contracts` (one Status field). Ids: U3566a, U3566b, U3566c, U3566d.

Work order: [#3566](https://github.com/saadshahd/roundup/issues/3566). Journey: Understand → Review (`.agents/data/journey.md`, headings “What must work” and “How a Builder closes a gap”). A finish means a published Kind transition directly from `working` to `idle` or `done`; it says that a turn ended, never that its result was accepted or independently checked. A Door is an Agent too. Plain Terminals keep U3704's separate unseen-output behavior.

**U3566a a finish waits to be read.** Given two Agents in an open Project, with A selected and B `working`, when B publishes an `idle` Status, then B's Rail row exposes an unseen state; selecting B clears it. Required CI guard: `u3566a_unselected_finish_is_unseen_until_selected`, one integration test through the fake App seam rendering the real App, emitting `agent.status` and selecting the real Rail row. Assert the accessible state appears and disappears, not its colour, size, CSS or exact copy.

Given the same setup, the following cases are asserted by `u3566a_only_unviewed_finishes_wait`, a parameterized App-seam observer beside the guard:

| Action | Result |
| --- | --- |
| B changes `working` → `done` | B becomes unseen, just as for `idle`. |
| The selected Agent finishes while its Project is active, its pane is displayed, the document is visible and the window has focus | No unseen state remains for that finish. Terminal keyboard focus is not required. |
| The selected Agent finishes with the window blurred or hidden, or its Project inactive | It becomes unseen; a remembered selection in a background Project is not viewing. |
| The user returns to the visible, focused window with that Agent's pane displayed | Its unseen state clears. |
| B is unseen and another Status arrives, including another `working` turn | It stays unseen until viewed. |
| A Status repeats, changes only its label, or goes to `needs-you`, `error` or `blocked` | It creates no new unseen finish. Existing Kind and Decision behavior stays intact. |

Given an unseen Agent, opening its pane by Rail pointer selection, Rail keyboard selection, the Switcher or an Agent link clears only that Agent's unseen state (`u3566a_opening_an_agent_marks_only_it_seen`, parameterized through the existing selection paths). Opening only its Project, expanding its Workstream, hovering its row or highlighting a Switcher result does not mark it seen (`u3566a_navigation_without_opening_keeps_unseen`). These tests assert state and selected identity, not layout. Policy: seen changes send no Message, start no program and change no Kind, Decision or result acceptance.

**U3566b summaries retain every unread child.** Given unseen Agents in two Workstreams and two open Projects, including matching Agent ids across Projects, then a collapsed Workstream row exposes one unseen state exactly when its Door or at least one of its descendant Agents is unseen, and a Project tab exposes one exactly when at least one of that Project's Agents is unseen. Expanding a Workstream leaves its children unseen. Opening one Agent clears that child's state and clears each aggregate only if it had no other unseen Agent. The state follows the Agent's current Home after a move and never crosses Projects. Observer: `u3566b_summaries_follow_their_unseen_agents`, a parameterized App-seam integration test of collapsed rows, Door finishes, Project tabs, moves and independent Project identities.

Given an unseen finish alongside `needs-you` and `error`, then all existing attention Glyphs, counts and tab actions remain available; the finish mark is additional passive state, never a replacement. Clicking the Project tab selects that Project under its existing contract; the unseen mark adds no jump action. The Dock badge still counts only `needs-you` and `error` across open Projects, with none at zero (U10 in `scenarios/ui.md`, heading “U10 Dock badge”, and U182 in `scenarios/project-tabs.md`, heading “U182 hover tells the count”). Observer: `u3566b_unseen_is_separate_from_attention`, checking accessible states, navigation and badge calls for unseen-only and mixed states. Policy: U182's attention tooltip and attention-jump rules are unchanged; unseen alone does not create that tooltip or count.

**U3566c reload preserves seen state and discovers missed finishes.** Given an unseen Agent and another whose latest finish was viewed, when the webview reloads with the same App storage, then the first stays unseen until viewed and the second stays seen. An automatically restored selection in an inactive Project or blurred window does not acknowledge a finish; a restored pane actually displayed in the visible, focused active Project does. Given a finish during the reload gap, including a finish followed by another `working` turn, then reconnecting discovers it even when its Status event has left the bounded replay log. Observer: `u3566c_reload_reconciles_finishes_with_seen_state`, a parameterized App-seam test remounting with retained storage and authoritative trees, including a newer finish after an earlier one was seen. Distinct Projects' seen records never acknowledge each other's Agents.

Policy, Contract recipe: add only `finished` to Status, a canonical nonnegative decimal string counting this Agent's published finishes, starting at `"0"`. It increases once for each direct `working` → `idle` or `done` transition, before that Status is published; other transitions, duplicate observations and reads do not increase it. The count belongs to the Agent identity, survives Attempts and Daemon reopen, and never resets on resume. A reconstructed `done` at reopen is not an observed finish. Synthetic Workstream aggregate Statuses carry `"0"`; a Door's own Status carries its own count. A plain Terminal has no such Status. `rail.tree` and `agent.status` carry the same authoritative count. Use no timestamp comparison and infer no finish from Terminal bytes or prose.

Observer: `u3566c_finish_count_survives_attempts_and_reopen`, an in-process `crates/agents` test through public Agent/rail operations and controlled Adapter observations, asserts counting, duplicate/non-finish exclusion, equal-clock transitions, the returned tree/event agreement, resume and reopen. Reuse the existing fake Adapter and clock; no real vendor or browser is required for this contract observer.

Policy: the App stores acknowledged counts per original Project and Agent. An unseen count already acknowledged is not restored by duplicate or older events; existing Attempt/Status-revision guards continue to reject stale live events. With no prior seen record (including migration from an older App), baseline the first tree's count without marking historical work unread, then observe later increases. Existing saved Rail selection and folds still restore. Seen state remains App-owned: no seen RPC or Daemon acknowledgement is introduced. Change all Status producers, callers and fixtures in the implementation PR and regenerate `contracts/generated/` from `crates/contracts`; do not hand-edit it. This adds no Message or Route semantics and changes none of M1–M10 (`scenarios/proofs.md`).

The need for this field is established on main by `crates/contracts/src/common.rs`, `Status` (only current Kind, label and since), `crates/agents/src/rail_view.rs`, `Shared::present` (Status revision absent after reopen), and `apps/desktop/src/app/events.ts`, `connectEvents` (expired replay restarts at the oldest retained event). None retains the last finish when a later working Status replaces it. Extend the existing App storage and Status holders; no parallel event log, polling or new App seam command is required (policy).

Policy: the dot carries `data-state` and an accessible state label, “Unread result”, from the App copy catalogue. It has no button role, tab stop, pointer cursor, tooltip action or hover wash. It neither replaces nor recolours the Kind Glyph; it is not Ink. Keep it present on hover and focus, with no action between it and the name, and with U3704's separation from trailing actions. No counts, banners, Toasts, bells, OS alerts, pulses or automatic navigation announce routine finishes. No motion is added.
