# A side call keeps each Agent's links for its header, and the header shows them (LH1 to LH27)

Modules: `crates/agents` (`claude_code/`), `crates/contracts`, `crates/rupd`, `contracts/generated/`, `apps/desktop/src` (the catalogue only). Ids: LH25 to LH27 (the reshape, [#7961](https://github.com/roundup-app/roundup/issues/7961), key `links-header-reshape`); LH15 (the Terminal icon on any Agent, #7625); LH1 to LH5 (the side call, acceptance for [#7369](https://github.com/roundup-app/roundup/issues/7369), key `links-header-side-call`) and LH6 to LH13 (the view, below, acceptance for [#7370](https://github.com/roundup-app/roundup/issues/7370), key `links-header-view`). Terms: Agent, Daemon, App, link (`GLOSSARY.md`); a **turn stop** is the end of an Agent's turn (A7180a); the **turn text** is what the turn added since the last stop. Source: the owner, 2026-11-17: "it should be the links the user of that specific session would need to see … open pr, open jira ticket, open dev server etc etc anything the user asks for as a link"; "controlled by a side agent that looks at the session as it works … updates the header as on turn stop … return json-render for the header to render it perfectly"; "some use jira other use other things" (no tracker integration: the tracker issue is whatever link the session holds). The view is its sibling [#7370](https://github.com/roundup-app/roundup/issues/7370) (`links-header-view`).

Policy, Must not: no in-app browser or webview; no chat view; the call never opens anything and never names a path; nothing opens without the user's click. The Editor and Terminal entries are the App's own and are not in the set. A new RPC method, event or type follows the Contract recipe of `.agents/builder.md` (rule 4), and its names enter `GLOSSARY.md` in the implementation PR. P9: this call spends the user's usage on the user's ask for links, and runs only when LH1's gate holds.

**LH1 the gate reads the turn text and calls the model only for link-like text.** Given an Agent whose turn stops, when rules read the turn text (the user's prompt, the Agent's replies and tool output since the last stop, read by the Claude Code adapter within a fixed byte bound, P4), then the call of LH2 runs once if the text holds an `http://` or `https://` or `roundup://` URL, `localhost` with a port, a tracker key of the form `ABC-123` (capital letters, a hyphen, digits), or the word "link" in any case; otherwise no model call runs and the Agent keeps its last set (LH4). The call is separate from the stop judge (A7180b): it has no Rail row, changes no Status, and the stop judge's calls and answers are unchanged. Text beyond the bound is cut from the front, so the newest text is kept. Asserted in `lh1_link_like_text_calls_the_model` and `lh1_text_without_a_link_calls_no_model_and_keeps_the_set` in `crates/agents/src/claude_code/links_tests.rs` (a fake model that counts its calls; one case per trigger: URL, `localhost:3000`, `ABC-123`, "link"), and `lh1_the_turn_text_is_bounded_and_the_newest_kept` in the same file.

**LH2 the call returns the Agent's link set as a json-render spec.** Given the turn text that passed LH1 and the Agent's last set, when the call runs through `crates/agents/src/claude_code/one_shot.rs` (A39's seam: Haiku, no tools, no session, within the limit of LH16), then it answers a json-render spec of entries, each of kind `pr`, `tracker`, `dev-server` or `asked`, with a full URL and a tooltip of a few words (at most five words), at most 12 entries. One definition of the entry shape produces both the call's structured-output schema and the App's catalogue for `@json-render/solid`; the Rust side generates it from `crates/contracts`, never a second hand-written copy. The input is data: the call follows no instruction in the text. An answer that does not parse as that shape, or a call that fails or exceeds its time, changes nothing and is logged with its cause. Asserted in `lh2_an_answer_becomes_the_agents_set` and `lh2_a_bad_or_failed_answer_keeps_the_set_and_logs` in `crates/agents/src/claude_code/links_tests.rs` (fake model; the real Haiku call is not run in a test, P9), and `lh2_the_schema_and_the_catalogue_come_from_one_definition` in `crates/contracts/tests/` pinning that the generated `contracts/generated/` entry type and the call's schema are built from the same Rust type.

**LH3 a URL absent from the turn text never reaches the set.** Given an answer entry, when it is accepted, then its URL parses, has the scheme `http`, `https` or `roundup` and no other (`file:`, `javascript:`, `data:` and a bare path are dropped), and appears whole in the turn text or already in the Agent's last set; a URL built from a key (`ABC-123` to a tracker address) or rewritten by the model is dropped. Other entries of the answer stand. No entry holds a path of the Agent's folder or Worktree. Asserted in `lh3_a_url_not_in_the_text_never_reaches_the_set`, `lh3_only_http_https_and_roundup_urls_are_kept` and `lh3_a_key_alone_builds_no_url` in `crates/agents/src/claude_code/links_tests.rs`.

**LH4 the Daemon keeps the last set per Agent and sends it to the App.** Given an Agent with a set, when an accepted answer replaces it, then the Daemon stores that set for the Agent, emits one event naming the Agent and the set, and a read of the Agent's links returns it; a turn that runs no call, a failed call or an unparsable answer leaves the stored set and emits nothing; a valid answer of zero entries is a set of zero entries and replaces it. The set lives as long as the Agent's record and is dropped with it. The App's reading of the event is the sibling's. Asserted in `lh4_an_accepted_answer_replaces_the_set_and_emits_once`, `lh4_a_turn_without_a_call_keeps_the_set_and_emits_nothing` and `lh4_the_link_read_returns_the_last_set` in `crates/rupd/tests/` (fake model, in-process Daemon).

**LH5 the call proposes only.** Given any set, when the Daemon holds or sends it, then no code path of the call opens a URL, starts a process or writes a file; a link opens only when the user clicks its icon (the sibling's click). Policy, held by LH3's dropped schemes and by the call having no tool; no further test.

## The view (LH6 to LH12)

Module: `apps/desktop/src/links/` (the header, its catalogue and its tests). Source: the owner, 2026-11-17: "links are icons, and it the center head should allow expending/collapsing the header - also it shouldn't be what the agent made as that could be noise" (reversed for items made for the user by the owner, 2026-11-20, LH19); "the icon tooltip should be few words to identify what is that icon/link for"; "as the center works the header gets auto collapsed up, a user can expands it - the header overlaps over the center never pushes the center". Terms: Status, Door, Worktree, Code editor (`GLOSSARY.md`). Policy, Must not: no in-app browser or webview; no chat view; the header lists no text the Agent wrote (an entry's tooltip is the call's few words, never the Agent's prose); nothing opens without a click. The overlap of the Terminal's top is the owner's decision: a design check that reads it as a defect changes the header's height, backdrop or collapse, never the overlap. New names (the header, its catalogue) enter `GLOSSARY.md` in the implementation PR. Rule 9: the implementation PR carries a `Reuse:` section; `@json-render/solid` peers `zod ^4`, which sits beside the App's valibot.

**LH6 the header lies over every centre's Terminal and never moves it.** Given the centre of any Agent (a Door's and a Mode Agent's included), when the header shows, collapses, expands or its set changes, then it is laid over the top edge of that Terminal and the Terminal's width, height and offset are the same before and after each change; the header takes no layout space, and the centre is never pushed. The Terminal pane keeps a fixed top inset of about the expanded header's height, so the header lies over that inset and over no row of Terminal text: the first row starts just below it (owner, 2026-11-18, #7527, after a strip of its own above the Terminal was refused: "I don't want to push center can we push the pane only a bit to overlap with the bar"). The inset is fixed: showing, collapsing, expanding or changing the header never changes it, so the Terminal never resizes and the Agent never redraws because of the header. Asserted in `lh6_the_header_overlays_and_the_terminal_size_is_unchanged` in `apps/desktop/src/links/lh_header.test.tsx` (the Terminal's measured box before and after show, collapse, expand and a set change; a Door and a Mode Agent case) and `lh6_the_terminal_keeps_a_fixed_top_inset_the_header_lies_over` (the inset's size is equal in all four states and no less than the expanded header's height; the header's box and the first row's box do not intersect).

**LH7 the Editor and Terminal icons come first, on the Agent's folder.** Given an Agent, when the header shows, then its first two icons are the Code editor and a roundup Terminal (`⌘T`), each with a tooltip of at most five words; a click on the first runs the `editor` action on the Agent's folder (LH25), with the Code editor setting, and a click on the second opens a roundup Terminal there as `⌘T` does (U165, X12); each click opens its target once. Asserted in `lh7_editor_and_terminal_icons_open_once` in `apps/desktop/src/links/lh_header.test.tsx` (a spy on the `editor` action and the Terminal open; one click each), the folder itself being LH26's.

**LH8 the set's entries follow as icons, the header is a fixed catalogue.** Given the Agent's link set of LH4, when the header renders it through `@json-render/solid`, then each entry shows after the two of LH7 as one icon of its kind (`pr`, `tracker`, `dev-server`, `asked`) from `lucide-solid` with its tooltip, and a click opens its URL once through the App's existing open-link path; a spec naming a component outside the catalogue renders nothing for it. The header shows no list of what the Agent made (no Pad, Deliverable or Item rows). Asserted in `lh8_entries_render_as_catalogue_icons_and_open_once` and `lh8_an_unknown_component_renders_nothing` in `apps/desktop/src/links/lh_header.test.tsx`.

**LH9 at most six icons show; the rest are a count that reveals them.** Given a header of more than six icons (LH7's two plus entries), when it shows, then six icons show inline and a `+N` count of the rest follows; activating the count reveals those N, each with its tooltip and click as LH8; six or fewer icons show no count. Asserted in `lh9_more_than_six_icons_show_six_and_a_count` and `lh9_six_or_fewer_show_no_count` in `apps/desktop/src/links/lh_header.test.tsx`.

When the user expands or collapses it, that state holds until the Agent's Status next changes (a new Status revision), and then the Status decides again; a set change alone does not reset it. The handle is a button with an accessible name and `aria-expanded`. Asserted in `lh10_working_collapses_and_other_kinds_show`, `lh10_the_users_toggle_holds_until_the_status_changes` and `lh10_a_set_change_keeps_the_users_toggle` in `apps/desktop/src/links/lh_header.test.tsx`.

**LH11 the header holds on `agents-10` at 1512×950 in dark mode, and the keystroke budget stands.** Given the `agents-10` seed at 1512×950 in dark mode, when the header shows expanded, collapsed and with the `+N` count, then the design critic passes it (D2, D5, D6), and `just perf` shows no keystroke regression above rule 7's 10%. **LH16 the call's limit fits the real CLI with margin.** Found by [#7828](https://github.com/roundup-app/roundup/issues/7828): on the owner's Mac, 2026-11-20, the real call took 3.8 s (the model 1.7 s, the CLI's start the rest) and the 3 s limit killed every one, so no header showed a link. **LH17 a failed call is written where an agent can read it.** Found by [#7828](https://github.com/roundup-app/roundup/issues/7828): the cause went to the Daemon's stderr, which the App keeps no copy of. Asserted in `lh17_a_failed_call_appends_one_line_naming_the_agent_and_cause` and `lh17_a_success_or_no_call_writes_no_line` in `crates/rupd/tests/` (fake model, in-process Daemon, a temp state directory), and `lh17_the_log_keeps_its_last_200_lines` in `crates/agents/src/claude_code/links_tests.rs`.

**LH18 the sets are kept in memory only (policy).** Decided for [#7828](https://github.com/roundup-app/roundup/issues/7828): a Daemon restart, App update included, empties every set (LH4's "as long as the Agent's record" is the Daemon's run); each header fills at that Agent's next stop whose text holds a link. Storing sets with the Agent's record is a separate request if the owner asks for it. No test.

## What the Agent made for the user (LH19 to LH24)

**LH19 the Daemon names the items an Agent made for the user.** Given an Agent `a`, when the App reads `agent.made {id: "a"}`, then it returns a list of items, each of kind `pad` or `file`, with an id the App opens it by and a title, in creation order, holding only: a Pad whose creator is `a` and whose visibility is `shown`; a Deliverable whose `maker` is `a` (a published file, Pad revision or external URL; an external URL is already a link of LH8 and is left out).
