# Rail tree cost

Module: `crates/agents` (`rail_view.rs`, the Claude Code Adapter's overview reader under `claude_code/`) and `crates/rupd` (every holder of the Rail lock). Terms: Rail, Agent, Attempt, Daemon (`GLOSSARY.md`). Principles served: P9. Ids: RO1–RO3. Requested in #5180 (refs #5159, #5172, #5179); amends A6 and A2681a. Adds no RPC method, App seam command or token.

Rule: `rail.tree` is a read of state the Daemon already holds. It never reads a transcript, and a Daemon call never reads a file or parses while it holds a shared lock.

**RO1 an overview is read once, then only what was appended.** Amends A2681a and A2681b. Given a closed Agent whose transcript (A21) is large, when `rail.tree` runs, then its node carries the same overview parts as A2681a gives. The Adapter keeps, per transcript, the parts read so far with the path, byte length and modification time they were read at, and each later read parses only the bytes after the last complete line it read. A transcript that has not changed is parsed for zero bytes. A transcript that is shorter than the length last read, or replaced (its modification time moved back or its first bytes differ), is read whole again. A trailing partial line is not parsed until its newline arrives. Tests in `crates/agents/tests/scenarios/resume.rs` with a temporary conversation directory and a call count of bytes parsed, never a timer:
- `ro1_a_second_rail_tree_parses_no_transcript_bytes`: a fake transcript of at least 30 MB; the first `rail.tree` parses it, a second with nothing appended counts zero bytes parsed and returns equal nodes. This is the CI guard for #5180.
- `ro1_an_appended_reply_parses_only_the_appended_bytes`: after one reply is appended, the count equals the appended length and the node shows the new context used (A2681b).
- `ro1_a_truncated_or_replaced_transcript_is_read_whole`: the count equals the new file's length and the node matches a fresh read.
- `ro1_a_partial_last_line_waits_for_its_newline`: the count excludes the partial line; once its newline is written the line is parsed once.

**RO2 `rail.tree` waits on no file and no parse.** Amends A6. Given Agents with large transcripts, including stopped ones, when `rail.tree` is called, then it reads no transcript: it reads the cache RO1 describes, and an Agent whose overview is not yet cached shows no overview parts (A2681a's omitted fields) until a read outside the Rail lock fills it, announced by `rail.changed`. A transcript that grows while its Agent works is re-read by that background path and never by a caller. Tests: `ro2_rail_tree_reads_no_transcript` in `crates/agents/tests/scenarios/resume.rs` (the call count of RO1 stays zero across `rail.tree` calls while the cache is empty); `ro2_an_uncached_overview_appears_with_rail_changed` (the node gains its parts and `rail.changed` arrives); `ro2_a_growing_transcript_updates_without_a_caller` (an appended reply shows on the next `rail.tree` with no read by that call).

**RO3 no Daemon call does file I/O or parsing under a shared lock.** Given every holder of `Shared::rail()` and of the other locks `crates/rupd` and `crates/agents` take (the Rail, Attempts, Message store), then none reads a file, a transcript or a Project folder, nor parses one, while it holds the lock: `marks.rs` `files` (#5159), `Shared::tree` and `Shared::observe` included. The Builder lists each holder it audited in the PR with the change made or the reason none was needed. Tests in `crates/rupd/tests`: `ro3_pad_list_and_rename_answer_while_rail_tree_is_slow` holds a `rail.tree` pending on a gate in the overview reader and asserts `pad.list`, `rail.rename`, `agent.signal` and `rail.tree` of another Project node answer within 1 000 ms. Observer: on a Project with a 30 MB transcript, `rup rail tree` answers within 100 ms in a debug build, and stays there while that Agent works (read by the Builder or QA with the real Daemon; CI holds the count, not the clock).
