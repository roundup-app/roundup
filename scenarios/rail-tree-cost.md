# Rail tree cost

Module: `crates/agents` (`rail_view.rs`, the Claude Code Adapter's overview reader under `claude_code/`) and `crates/rupd` (every holder of the Rail lock). Terms: Rail, Agent, Attempt, Daemon (`GLOSSARY.md`). Principles served: P9. Ids: RO1–RO5. Requested in #5180 (refs #5159, #5172, #5179); amends A6 and A2681a. Adds no RPC method, App seam command or token.

Rule: `rail.tree` is a read of state the Daemon already holds. It never reads a transcript, and a Daemon call never reads a file or parses while it holds a shared lock.

**RO1 an overview is read once, then only what was appended.** Amends A2681a and A2681b. Given a closed Agent whose transcript (A21) is large, when `rail.tree` runs, then its node carries the same overview parts as A2681a gives. The Adapter keeps, per transcript, the parts read so far with the path, byte length and modification time they were read at, and each later read parses only the bytes after the last complete line it read. A transcript that has not changed is parsed for zero bytes. A transcript that is shorter than the length last read, or replaced (its modification time moved back or its first bytes differ), is read whole again. A trailing partial line is not parsed until its newline arrives. Tests in `crates/agents/tests/scenarios/resume.rs` with a temporary conversation directory and a call count of bytes parsed, never a timer:
- `ro1_a_second_rail_tree_parses_no_transcript_bytes`: a fake transcript of at least 30 MB; the first `rail.tree` parses it, a second with nothing appended counts zero bytes parsed and returns equal nodes. This is the CI guard for #5180.
- `ro1_an_appended_reply_parses_only_the_appended_bytes`: after one reply is appended, the count equals the appended length and the node shows the new context used (A2681b).
- `ro1_a_truncated_or_replaced_transcript_is_read_whole`: the count equals the new file's length and the node matches a fresh read.
- `ro1_a_partial_last_line_waits_for_its_newline`: the count excludes the partial line; once its newline is written the line is parsed once.

**RO2 `rail.tree` waits on no file and no parse.** Amends A6. Given Agents with large transcripts, including stopped ones, when `rail.tree` is called, then it reads no transcript: it reads the cache RO1 describes, and an Agent whose overview is not yet cached shows no overview parts (A2681a's omitted fields) until a read outside the Rail lock fills it, announced by `rail.changed`. A transcript that grows while its Agent works is re-read by that background path and never by a caller. Tests: `ro2_rail_tree_reads_no_transcript` in `crates/agents/tests/scenarios/resume.rs` (the call count of RO1 stays zero across `rail.tree` calls while the cache is empty); `ro2_an_uncached_overview_appears_with_rail_changed` (the node gains its parts and `rail.changed` arrives); `ro2_a_growing_transcript_updates_without_a_caller` (an appended reply shows on the next `rail.tree` with no read by that call).

**RO3 no Daemon call does file I/O or parsing under a shared lock.** Given every holder of `Shared::rail()` and of the other locks `crates/rupd` and `crates/agents` take (the Rail, Attempts, Message store), then none reads a file, a transcript or a Project folder, nor parses one, while it holds the lock: `marks.rs` `files` (#5159), `Shared::tree` and `Shared::observe` included. The Builder lists each holder it audited in the PR with the change made or the reason none was needed. Tests in `crates/rupd/tests`: `ro3_pad_list_and_rename_answer_while_rail_tree_is_slow` holds a `rail.tree` pending on a gate in the overview reader and asserts `pad.list`, `rail.rename`, `agent.signal` and `rail.tree` of another Project node answer within 1 000 ms. Observer: on a Project with a 30 MB transcript, `rup rail tree` answers within 100 ms in a debug build, and stays there while that Agent works (read by the Builder or QA with the real Daemon; CI holds the count, not the clock).

**RO4 a transcript the SDK cannot find is looked up at most once per 30 s.** Given a stopped Agent whose saved conversation has no transcript (it never received a prompt, or its file was removed), when `rail.tree` keeps its overview current (RO2), then the background path asks the Claude Agent SDK for that transcript's path once, and again only after 30 s, never on each 500 ms poll: each ask starts the Node sidecar. A caller that reads the overview itself (A9's first title) still asks at once. Found on 2026-11-13: two such Agents in one Project made its Daemon start about three sidecars a second, a third of a core in a debug build. Test: `ro4_a_missing_transcript_is_looked_up_once_per_retry` in `crates/agents/src/claude_code/overview_cache.rs` (ten polls of paused time count one lookup).

**RO5 a node carries only the fields its kind has.** Amends DCL2 and RO1's reply; refs #6504. Given a `rail.tree` reply, then each node is one `RailNode`: a `NodeBase` flattened under `#[serde(tag = "kind")]` with `Role::{Group, Workstream, Agent}`, and the TypeScript type from `contracts/generated/` (regenerated, never hand-edited) is a union discriminated on `kind`. `NodeKind` has no Terminal, so `Role` has no Terminal variant; a Terminal is `terminal_id` on an Agent or a Door (adding the variant would change an RPC and a Rail fact). Fields per kind, from `RailNode`'s comments in `crates/contracts/src/agent.rs`:
- Base, every kind: `id`, `kind`, `name`, `parent`, `order`, `visibility`, `alert_level`.
- Group: the base alone.
- Workstream (its Door's facts stay on it): the base, `workstream_state`, `auto`, `waiting`, `work`, `attempt`, `status`, `status_revision`, `final_text`, `terminal_id`, `worktree`, `can_resume`, `yolo`, `channel`, `stray`, `model`, `effort`, `inbox`, `tool_call`, `unreachable`, `resume`, `overview`, `start_attribution`.
- Agent: the Workstream's Door facts without `workstream_state`, `auto` and `waiting`, plus `mode_prompt`, `machine`, `can_make_workstream`, `can_save_as_mode`.
- A field of a kind keeps today's value rules inside it (`status`, `attempt`, `worktree` and the other `Option`s of a kind that has them still serialize `null`); a field the kind lacks is absent from the JSON, where today it serializes as `null`, `false`, `[]` or a default. A Group's `attempt`, `status`, `status_revision`, `terminal_id`, `worktree`, `work`, `model`, `effort`, `channel`, `can_resume`, `can_make_workstream`, `can_save_as_mode`, `yolo` and `stray`, and a Workstream's `mode_prompt`, `machine`, `can_make_workstream` and `can_save_as_mode`, change this way. No Rail fact a user sees, no RPC code and no other field changes.
- Every TypeScript reader of a field absent from a kind narrows on `kind` first. The readers that test `attempt !== null` or `=== null` without a kind that has the field read `undefined` as not-null and change: `rail/alertLevel.ts` (`each.kind === "agent" || each.attempt !== null`), `ui/contextMenu.ts` (two reads of `attempt !== null` behind `kind === "agent" ||`), `rail/menu/removal.ts` (`node.worktree === null`, which a Group now lacks), and `state/rail.ts` (`failureKey` and the `attempt !== null` read in the Door failure reset, each on a node of any kind). Readers already behind a `kind === "workstream"` or `"agent"` test (`window/menuBar.ts`, `rail/menu/model.ts`, `state/queue.ts`, `rail/Rail.tsx`, `rail/RailRow.tsx`, `resources/ResourceStrip.tsx`) keep their test and the type checker confirms them.
- `messages::delivery::ended` matches on `Role`, with no test of `status_revision`, `status` or `terminal_id` for a kind that lacks them; for each node it returns what it returns today.
- Cost: the `rail.tree` reply time stays within 10% of `main` on `rail_tree_10_p95_ms` and `rail_tree_40_p95_ms` (`crates/perf/budgets.json`; the stored `main` baselines are 0.265 ms on `linux-boxd` and 0.1345 ms on `macos`, and R16's same-job `main`/head pair applies on an uncalibrated host), the 2 ms limit of the first holding as well. A flattened struct makes serde buffer the map on read, so the `rail.tree` reply parse in the App's tests and `crates/perf` is part of that measurement; a miss fails rule 7 and the implementation keeps the union without `flatten` on the write path (a hand-written `Serialize` per kind) before it loosens the budget.
- One PR, as AGENTS.md rules 3 and 4 allow: `contracts/src/agent.rs`, `contracts/generated/`, the Rail builders in `crates/agents`, `messages::delivery::ended`, `crates/rupd`, `state/rail.ts` and `rail/`. A split leaves a flat `RailNode` and a union live together, which the work order forbids; the estimate is about 1,500 changed lines, of which `contracts/generated/` and test fixtures building `RailNode` (about 700) change mechanically, so no cut gives two PRs of 1,000 lines without two live interfaces.
- Rule and keeper (policy): a contract struct whose field presence depends on its `kind` is a tagged enum with shared fields in a flattened base; clippy `struct_excessive_bools` (default 3) and the compiler keep it.
Tests: `ro5_a_group_node_serializes_only_the_base_fields`, `ro5_a_workstream_and_an_agent_carry_their_kinds_fields` (a real `rail.tree` reply in `crates/agents/tests/scenarios/rail.rs`; the clause's field lists compared with the JSON keys); `ro5_ended_matches_the_old_four_option_test` (`crates/messages`, every kind and Status over the old formula); `ro5_a_group_in_the_tree_is_no_attempt_or_agent` (a new `apps/desktop/src/rail/ro5_group_readers.test.ts`, with a Group in `rail.nodes` through the readers above); the contract's TypeScript compile is the proof of the union, and `just perf` the proof of cost.
