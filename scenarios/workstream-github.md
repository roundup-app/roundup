# A Workstream does GitHub errands through the owner's `gh`, reads state live and asks once (A5168a to A5168d, B5168e, B5168f, B5168g, A5168h)

Module: `crates/contracts`, `crates/rupd`, `crates/rup`, `crates/agents` and `contracts/generated/`. Ids: A5168a, A5168b, A5168c, A5168d, B5168e, B5168f, B5168g, A5168h. Acceptance for #5168. Decided by the user (2026-10-30): the Door gets GitHub tools that run the owner's `gh`; it reads PR and Issue state live before stating or asking about it; a quiet Digest starts no turn. Builds on M5 (every action has a tool or a reason), M7 (Reach), B21/B35/B43 (pushed Digests), B30 (delivery), B24/M9 (the Door's Brief) and B4699b.

`GLOSSARY.md` gains **GitHub tool** (the methods `github.prGet`, `github.issueGet`, `github.prSetBody`, `github.prReady`, `github.prAutoMerge` and the Door's tools `github_pr_get`, `github_issue_get`, `github_pr_set_body`, `github_pr_ready`, `github_pr_auto_merge`) and **Quiet Digest** (B5168f), in the implementing PR (Contract recipe of `.agents/builder.md`).

**A5168a the Door reads a PR or an Issue as GitHub holds it now.** Contract change (the Contract recipe). New methods `github.prGet {number}` and `github.issueGet {number}`, both for the Project's repository (the `origin` remote of its folder, which `gh` resolves), returning `{number, url, title, body, state}` with `state` `open`, `closed` or `merged`; a PR adds `draft`, `autoMerge` (a boolean: auto-merge is enabled), `head` (the head commit) and `mergedAt` (or `null`); an Issue adds `labels` and `stateReason` (or `null`). Each call runs `gh pr view <number> --json …` or `gh issue view <number> --json …` once in the Project's folder and parses its output; nothing is cached, so a body edited on GitHub, a PR marked ready, an auto-merge enabled and a merge each show in the next call. A `number` that is not a positive integer is `INVALID_PARAMS` and runs no `gh`. A number `gh` reports as missing is `NOT_FOUND`. MCP tools `github_pr_get` and `github_issue_get` are offered to Doors only (M5; a Subagent has none); `rup` gets the same two commands. Tests (`a5168a_`, a fake `gh` on `PATH` that records its argv): `a5168a_pr_get_runs_one_view_and_parses_every_field`, `a5168a_issue_get_parses_labels_and_state_reason`, `a5168a_a_second_call_runs_gh_again_and_shows_the_new_body`, `a5168a_a_bad_number_runs_no_gh`, `a5168a_a_missing_number_is_not_found`, `a5168a_only_a_door_is_offered_the_tools`.

**A5168b the Door edits a PR body, marks it ready and enables auto-merge.** Contract change. New methods `github.prSetBody {number, body}`, `github.prReady {number}` and `github.prAutoMerge {number}`, each returning the PR as A5168a's `github.prGet` reads it after the write. `prSetBody` runs `gh pr edit <number> --body-file -` with `body` on stdin (so no quoting reaches a shell); an empty `body` is `INVALID_PARAMS` and runs no `gh`. `prReady` runs `gh pr ready <number>`; `prAutoMerge` runs `gh pr merge <number> --auto --merge`. A PR already not a draft makes `prReady` a no-op, and one with `autoMerge` already true makes `prAutoMerge` a no-op: each reads first, runs no write, and returns the state with no error (a repeat is safe). A closed or merged PR is `CONFLICT` for `prReady` and `prAutoMerge` and runs no write. Each write is a Door-only MCP tool, a `rup` command, and logs no Touch (Touches cover Todos and Pads, policy). Tests (`a5168b_`, fake `gh`): `a5168b_set_body_sends_the_body_on_stdin_and_returns_the_new_state`, `a5168b_ready_and_auto_merge_run_their_one_command`, `a5168b_a_repeat_runs_no_write`, `a5168b_a_closed_pr_is_a_conflict_and_runs_no_write`, `a5168b_an_empty_body_runs_no_gh`.

**A5168c a `gh` failure is a readable error.** Given any GitHub tool, when `gh` is not on `PATH`, exits non-zero, prints non-JSON or is not logged in, then the call fails with `INTERNAL` and a one-line message that names `gh` and holds `gh`'s own first stderr line, at most 200 bytes, with no token, header or environment value. The tool shows that line to the Door, which can then tell the user the real cause. A failed write changes nothing the Daemon holds. Tests (`a5168c_`, fake `gh` that exits 1 with stderr, prints garbage, or is absent): `a5168c_a_non_zero_exit_returns_the_first_stderr_line`, `a5168c_garbage_output_is_an_error_not_a_panic`, `a5168c_a_missing_gh_names_gh`, `a5168c_the_error_holds_no_environment_value`.

**A5168d the tools run the owner's own `gh` and hold no token.** Narrows A5168a and A5168b. Given the Daemon, then every GitHub tool runs the `gh` found on the Daemon's `PATH`, with the Daemon's own environment unchanged and the Project's folder as its directory, so the owner's login, host and scope decide what it may do. roundup stores, reads, sets and passes no token (`GH_TOKEN`, `GITHUB_TOKEN`) and adds no GitHub API library. An Agent gets no more than the owner's `gh` allows and no method beyond A5168a and A5168b: no merge without auto-merge, no close, no comment, no label (policy; a later scenario adds one). Tests (`a5168d_`, fake `gh` that records its environment and directory): `a5168d_gh_runs_in_the_project_folder_with_the_daemons_environment`, `a5168d_no_token_variable_is_set_or_read`.

**B5168e the Door's Brief says to read first and ask once.** Amends B24, M9 and B4699b. Given a Door's rendered Brief, then it (a) lists the five GitHub tools by name with their one-line descriptions (M9: only tools `rup mcp` offers); (b) says to read a PR's or an Issue's state with them before stating it to the user or asking the user to act on it, and to do a GitHub errand it covers itself, never by asking the user to run `gh`; (c) says an ask to the user names only what the user alone can do, and is not restated unless something changed since it was made. Test: `b5168e_the_door_brief_names_the_tools_and_the_ask_once_rule` in `crates/agents/tests/launch/briefs.rs` pins the five tool names and the two rules' tokens in `door.md`, checked by check 1 of Checks on main; model compliance is policy. M9's list-match test keeps passing.

**B5168f a quiet Digest starts no turn.** Narrows B21, B30, B34, B35 and B43; their Message, Kind, bounds and ordering clauses stand. A **Quiet Digest** is a pushed Digest (B21), Rollup (B22) or merge for Door `m` in which no entry has a new `error` or `needs-you` Kind (B43), a newer `last` than `m` was last given for that child, a Todo of that child gone from open to done, or a Message of kind `question` from a child. Given a Quiet Digest `pending` for `m` at `m`'s eligible time (B30), then it is not written to `m`'s inbox by itself and starts no turn: it stays `pending`, counts against B22(b)'s 20, and is written, in id order, with the next Message or non-quiet Digest that is delivered (so nothing is lost and none is delivered twice, B39). A Digest with a new question, finished result, `error` or `needs-you` is delivered as B30 says and starts one turn. Tests in `crates/rupd`, the real Daemon with a deterministic fake `claude` and the fake clock: `b5168f_a_quiet_digest_starts_no_turn`, `b5168f_a_new_question_starts_one_turn`, `b5168f_a_finished_result_starts_one_turn`, `b5168f_a_parked_quiet_digest_rides_the_next_delivery_once`, `b5168f_a_restart_keeps_a_parked_quiet_digest`.

**B5168g no Door or coordinator prompt hands the user a command a GitHub tool does.** Fixes the class. Given every Brief a Door or another coordinator role gets (`door.md`, `agent.md` and any text `crates/agents` renders for one) and the orders `rupd` writes for them, then none tells the user to run `gh pr view`, `gh pr edit`, `gh pr ready`, `gh pr merge --auto` or `gh issue view`, and each such instruction is replaced by the tool that does it. A shell command that no tool covers stays, with the reason in the PR. Test: `b5168g_no_coordinator_brief_asks_the_user_to_run_a_covered_gh_command` pins those five command strings as absent from every rendered coordinator Brief. The sweep's table (prompt, command, tool or reason) goes on #5168 (policy).

**A5168h acceptance on a real conversation.** Policy; the observer is the user's. Given a fresh 12 h Workstream conversation measured as on 2026-10-30, then it holds no ask for work the GitHub tools cover and no unchanged ask repeated after a Digest. The user reports the counts on #5168; no run claims this clause.

**Regression.** M5, M7, M9, B21 to B23, B30, B34, B35, B39, B43 and B4699b keep every clause.
