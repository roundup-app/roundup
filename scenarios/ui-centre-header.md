# UI: one fixed centre header

Acceptance for #4315. Journey stages: Understand, Intervene and Review. The centre reserves one compact navigation row so moving between work and its views leaves the same room for content. Terms: Agent, Workstream, KindGlyph and Token (`GLOSSARY.md`). The test names below are planned implementation observers, not claims of existing behavior. This specification leaves #4315 open for implementation.

Policy — scope: use the existing connected App, Pane, shared UI primitives and view state. With an open Project, cover Ask, an active or closed Agent, a running or stopped Workstream, its Time measurement view and Timeline, plus requested Ask history, Reactions, Made, recovered notes, resources, Project settings, App Settings and import screens. A requested surface that shares the centre retains the row rather than adding another title/close row. Shelf, Drawer, menus and Terminal Bubbles keep their own navigation and lifetime; they are not centre headers. No new RPC, App seam command, domain term or Token is ordered. Settings without an open Project retain their existing dismissal behavior.

**U4315a one row reserves the same space on every view.** Given an open Project in the connected App, when the user starts at Ask, selects an Agent, selects a Workstream, opens Time, switches to Timeline and returns to Ask, then the same centre navigation row remains mounted through every switch, including Ask when it has no sub-links. Repeat with a closed Agent and stopped Workstream. Assert row identity and mounted navigation at the connected-App seam in planned `u4315a_navigation_survives_centre_switches`, in `apps/desktop/src/terminal/`; do not assert pixels in this test.

Given each requested centre screen listed in scope, when it opens and closes through its existing menu or action, then the centre retains that navigation row and the requested screen's accessible identity; no separate view-title/close navigation row mounts below it. Assert row identity, region names and navigation-control containment in planned connected-App test `u4315a_requested_screens_share_navigation`, beside the existing requested-screen observers. Content section headings, measurement values, retry actions and failure feedback remain available (policy; checks 3 and 4).

Policy — geometry and composition: the row's border-box height is `--space-6` (32 CSS px) on every covered view, with no wrapping, view-dependent padding, second navigation row or height animation. This allows the existing 24 CSS px minimum action target with `--space-1` above and below. The row always reserves that height, even when its left side is empty. At fixed window, Rail, Shelf, Drawer and Terminal-bar state, the centre's outer box and the available content viewport immediately below the row have identical x, y, width and height before and after a view switch. Compare the viewport container, not a scrollable child's intrinsic content height. The rendered observer below records these boxes; the design critic judges equality and compactness. This is policy, not a UI geometry assertion (AGENTS.md rule 10).

Policy — one-row content: the selected item's view sub-links sit at the left, with the current view marked using the existing shared flat-tab look (check 2). An Agent's name and state glyph, where currently shown, sit together in this row; the state remains noninteractive and is never separated from the name by an action. The single Back to Ask action sits at the row's right end on every non-Ask centre view, including Time, Timeline and requested screens. Ask keeps the row but has no Back to Ask action. Fold Timeline's back header, Time's title/close navigation and requested screens' duplicate title/close rows into this reservation. Long names truncate without wrapping, hiding navigation or increasing height. The critic judges placement, selection distinction, text/state spacing and absence of duplicate rows (checks 2 and 5).

**U4315b sub-links and Back to Ask navigate without changing the work.** Given a selected Workstream, when the user clicks Time and then Timeline, then each action opens that Workstream's corresponding view, keeps its selected identity and leaves both sub-links available with exactly one selected tab matching the displayed view. From Time, ArrowRight selects and opens Timeline; ArrowLeft returns to Time, with focus following the selected tab. Use the shared Ark tab semantics and flat-tab presentation, not a new keyboard state machine. Assert selected tab roles, focus, displayed region and Workstream identity in planned connected-App test `u4315b_sub_links_switch_by_click_and_arrow`, in `apps/desktop/src/terminal/`. Preserve the existing route back to the Workstream's ordinary view, including Escape and its focus return (policy; check 3).

Given an Agent, Workstream, Time, Timeline or any requested centre screen in scope, when the user activates the row's Back to Ask action outside U4355's pending import commit, then the requested centre screen closes, the Rail selection clears and Ask becomes the centre view with no selected-item view left over. Ask has no Back to Ask control. Assert the resulting view, selection and one action in the shared navigation row in planned connected-App test `u4315b_back_to_ask_clears_centre_navigation`, parameterized across those views; opening and returning starts no Agent, opens no Terminal and sends no Ask or Message. These call-count assertions belong to this test, not a second duplicate test.

Given exact unsubmitted Ask text before navigating to an Agent, Time, Timeline or a requested screen, when the user returns with Back to Ask, then that exact draft remains bound to its original Project and recipient, without a submission. Assert in planned connected-App test `u4315b_back_to_ask_preserves_unsubmitted_work`, extending existing draft observers rather than duplicating their reload/failure cases. Policy: changed settings/import editors retain their existing unfinished-input behavior; returning never saves, discards or submits merely because navigation moved into the shared row (check 4).

Policy — supersession: the shared row replaces only the separate header/navigation composition of checks 1, 3 and 4. For an open Project, Back to Ask replaces the requested screen's header Close action and intentionally returns to Ask rather than the previously selected Agent; update only the contradictory close-control assertions in those existing tests, naming `u4315b_back_to_ask_clears_centre_navigation` as their replacement. Escape keeps its existing previous-view/focus behavior, including Time and Timeline. Preserve measurement retry and stale-data feedback, Timeline lanes and keyboard access, settings/import content and saves, Project ownership, direct Agent access and native attention continuation. No behavior test is removed in this specification PR.

Policy — principles: P1/P3 gates ask whether navigation blocks direct Agent access or native attention's path to its requesting Terminal; retain both through ordinary Rail selection and Needs you. P11 asks whether moving the navigation loses or submits unfinished work; the draft observer above and existing settings/import draft observers cover changed editable paths. P14 asks whether Time gains money or token figures; retain time-only content. This specification changes no delivery or measurement contract and claims no new journey completion.

Policy — rendered observer: implementation uses isolated headless Chromium in a dedicated agent-browser session and fresh profile at 1512×950 in dark mode. Start from `tree-40`, `agents-10`, `door-stopped` and `empty-project`; include a long Agent name and the densest seed with complete failure text visible. On the connected App, record `getBoundingClientRect()` for the row, centre outer box and available content viewport before and after every switch in U4315a, including opening/closing each requested screen, with other panel reservations held fixed. This connected rendered probe fulfills #4315's content-box reading requirement; the readings and paired captures are critic evidence, not UI test assertions. Record the baseline's actual shifts and head's readings without claiming the baseline passes.

Policy — captures: run `just capture U4315a,U4315b` during implementation. Leave before/after PNG images of every covered view, interaction videos and box/Check readings under `artifacts/ux/<id>/{base,head}/`, with immutable baseline/head SHAs, as `.agents/data/harness.md`, heading “Captures”, requires; never commit images/videos. The critic judges numbered Checks D2 (type and space), D5 (contrast) and D6 (control states and targets), all held by check 5, and no Check passing on the same main baseline may regress. Only existing Tokens are used. This specification-only PR requires no captures and makes no native Mac rendering claim; the user reports what they meet on the Mac.

## Import in progress

Acceptance for #4355. Journey stages: Understand and Review. This adds a pending-commit exception to U4315b; it changes no import discovery, authority or outcome contract.

**U4355 Back to Ask keeps a pending import on screen.** Given an open Project with an Agent selected, Import Claude Code work opened through the Project menu, a chosen period and selected eligible sources, when the user confirms Import and `project.importCommit` has not settled, then Back to Ask is disabled in the shared navigation row. Attempting to activate it by pointer or keyboard leaves the Import region mounted with its pending state available; the selected Rail identity, original Project, period and submitted source identities/revisions remain unchanged. Exactly one commit is sent, with no cancellation, retry or deferred return to Ask. Assert in planned connected-App test `u4355_back_to_ask_keeps_pending_import` in `apps/desktop/src/terminal/u4315_header.test.tsx`, using the mounted App and a controlled commit promise through the existing fake App RPC seam (checks 6 and 7). Assert accessible disabled state, region identity, selected identity, exact choices and captured call count; do not test a standalone handler or layout.

In the same test, settle the commit in separate success and all-sources-refused cases. On success, the existing U2875d navigation opens the created work once, without another commit. With all sources refused with a retryable failure, the Import region keeps the failed selections and recovery action, pending ends and Back to Ask becomes enabled. Activating it now closes the page, clears the Rail selection and returns to Ask without another commit; reopening retains the failed choices against the original Project and restoration imports nothing. The attempted return while pending never runs later on its own. Assert these outcomes in `u4355_back_to_ask_keeps_pending_import`; retain U2875d's existing partial-success and retry observers rather than duplicating them.

Policy — boundary and regression: pending means confirmation/commit, not discovery or the listing Agent's lifetime. Back before confirmation, including during discovery, retains U4315b's return behavior and U3815/U3037d's recoverable draft and stale-response rules; retain `u4315a_requested_screens_share_navigation` and the existing U3037d deadline/late-result probes (check 7). Escape retains the Import panel's pending guard (check 6). Closing Project Settings while an import is pending elsewhere still follows U3817; this exception applies only while the Import page itself is displayed. No new RPC, App seam command, domain term, library machinery or Token is required.

Policy — gates and observers: P11's Gate asks whether navigation loses or retargets choices or submits them without confirmation; U4355's exact-choice, Project and call-count assertions observe this path. P3's Gate asks whether routine progress creates attention; preserve existing import progress without a new attention entry or prompt. This is an Understand/Review navigation repair, not evidence of completing the full journey.

Policy — rendered observer for implementation: use `emil-design-eng` and the existing shared control and Tokens. In isolated headless Chromium with a dedicated session and fresh profile, at 1512×950 in dark mode, open Import from `tree-40` with long titles and ten candidates. Capture confirmation pending with disabled Back, then settled success and retryable failure with complete failure text visible on the densest seed. Run `just capture U4355`; leave baseline/head PNGs, interaction video and Check readings under `artifacts/ux/U4355/` as `.agents/data/harness.md`, heading “Captures”, requires. The critic judges D2, D5 and D6 (check 5) and no regression in any Check passing on main. This specification-only PR needs no capture and makes no native Mac claim; the user reports what they meet on the Mac.
