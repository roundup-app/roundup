# Rewind a Workstream to a Checkpoint (A35, U374)

Module: `crates/agents`, `crates/contracts`, `crates/rupd`, `crates/rup`, `contracts/generated/` and `apps/desktop`. Ids: A35, U374. Found by the user's report #808: the user asked to rewind a Workstream to one of its Door's Checkpoints (M10, U355). Decided by the user: the rewind takes every Agent's conversation back, files stay unless the user chooses otherwise when files changed; the user picked this over rewinding chats and files always, and over forking a new branch from the Checkpoint. Decided here (the Issue left it to the spec): a Subagent created after the Checkpoint is stopped and leaves the Rail with its Worktree and branch kept, as A32 does; Messages, Todos and Pads are not rewound; a Checkpoint is rewound to once its marks exist (below). Not clearing a Workstream (A32) and not forking.

`GLOSSARY.md` gains **Rewind** and **Mark** in the implementing PR (Contract recipe). A rewind never types `/rewind` or any command into an Agent (Principle P9 of `PRINCIPLES.md`): it restarts each Agent on a shortened copy of its conversation, as A22 resumes one.

**A35 rewinding a Workstream takes each Agent back to a Checkpoint.** Contract change (the Contract recipe of `.agents/builder.md`): methods `workstream.rewindPlan {id, checkpoint}` and `workstream.rewind {id, checkpoint, files, takeover}`, the event `workstream.rewound {id, checkpoint}`, and the field `rewindable` on each `checkpoint.list` entry (M10). Given a Workstream with a Door and two Subagents (one under the other), each with a Worktree, and a Checkpoint `c` written by `checkpoint.write` (M10), then:
- **Marks.** When `checkpoint.write` succeeds the Daemon records, for every Agent of the Workstream at that moment, a **Mark**: the end of its conversation so far and a snapshot of the working files of its Worktree (tracked and untracked files that git does not ignore). A Mark is kept by the Daemon, is not part of M10's result, and survives a restart. A Checkpoint written before this scenario has no Marks and `checkpoint.list` marks it `rewindable: false`; so does a Checkpoint of an earlier Iteration (A32) and one whose Marks a later rewind made stale. Asserted in `a35_write_records_a_mark_per_agent`, `a35_marks_survive_a_restart` and `a35_an_old_checkpoint_is_not_rewindable`.
- **Plan.** `workstream.rewindPlan` changes nothing and returns `{agents: [{agent, name, takeover, created_after, files_changed: [path]}], files_changed: bool}`: one entry per Agent of the Workstream, `created_after` for an Agent started after `c`, `takeover` for an Agent under Takeover (B6), `files_changed` the paths whose content differs between the Mark's snapshot and the Worktree now (empty for a `created_after` Agent) and the top-level `files_changed` true when any list is non-empty. An unknown `id` or `checkpoint` is `NOT_FOUND`; a `rewindable: false` Checkpoint is `CONFLICT`. Asserted in `a35_plan_lists_each_agent_and_changes_nothing` and `a35_plan_refuses_an_unrewindable_checkpoint`.
- **Files choice.** `workstream.rewind` takes `files` of `"keep"` or `"restore"`, required: a missing or other value is `INVALID_PARAMS` and changes nothing. Whatever the call says, `"keep"` leaves every file byte for byte as it was. `"restore"` sets each Agent's working files to its Mark's snapshot (a changed file takes its old content, a file created since is removed, a file deleted since returns) and moves no branch, `HEAD` or remote: a later commit stays, and a push, an Issue or a PR is never undone. Asserted in `a35_keep_changes_no_file`, `a35_restore_returns_each_worktree_to_its_snapshot` and `a35_restore_moves_no_branch_and_pushes_nothing`.
- **Conversations.** Each Agent that is not `created_after` and not skipped by Takeover is stopped as `agent.stop` does and its next Attempt (A20) resumes a copy of its conversation cut at its Mark, under a new conversation id (A22), so the original conversation file is never edited. Turns after the Mark are not in the copy and so not in the Agent's context. The Agent comes back `idle`, with no prompt typed except the Door's (below). Asserted in `a35_each_agent_resumes_a_copy_cut_at_its_mark`, `a35_the_original_conversation_is_untouched`, `a35_no_slash_command_is_typed` and `a35_a_failed_restart_leaves_the_others_rewound_and_retries`.
- **Later Subagents.** An Agent with `created_after` is stopped deepest first and leaves the Rail; its Worktree directory and branch stay whatever their state (as A32, not `agent.discard`), and `"restore"` does not touch them. Asserted in `a35_a_later_subagent_leaves_the_rail_and_keeps_its_worktree`.
- **Takeover.** An Agent under Takeover is neither stopped nor restored unless `takeover` names it: `takeover` is a list of Agent ids the user chose, default empty, and a name outside the plan's Takeover Agents is `INVALID_PARAMS`. A skipped Agent is returned as `skipped`, keeps its conversation and files, and keeps its Takeover. Naming an Agent is the user's say: its Takeover ends (B6) and it is rewound like any other, and the call is accepted only with the user's proof (H4), never an Agent's. Asserted in `a35_a_takeover_agent_is_skipped_unless_named`, `a35_a_named_takeover_agent_is_rewound` and `a35_an_agent_cannot_name_a_takeover_agent`.
- **The Door is told.** The Door's first prompt after the restart is one text that says: the Checkpoint's title, which Agents were rewound, removed or skipped, and whether files were restored. It is also recorded as a Message from `you` of kind `note` (so the full log of U355 holds it). Asserted in `a35_the_door_is_told_what_was_rewound`.
- **Nothing else.** Messages (including `pending` and `held` ones, which are delivered after the restart as B7 orders), Todos, Pads, Terminals, Checkpoints and the Workstream's id, name and Iteration are unchanged. Every Checkpoint after `c` stays on the Thread and becomes `rewindable: false`. Asserted in `a35_messages_todos_pads_and_checkpoints_stay`.
- **Failure and events.** One call at a time per Workstream (`CONFLICT` otherwise). If a step fails the call returns its error, steps already done stay done, a second call with the same params continues and snapshots restored twice are the same; `workstream.rewound` and one `rail.changed` are emitted once, after the last Agent's `SessionStart`. A rewind logs a `wrote` Touch on `rail:<id>` by the user (M2). Asserted in `a35_one_rewind_at_a_time`, `a35_a_failed_step_retries_without_repeating_work` and `a35_rewound_is_emitted_once_after_the_last_session_start`.

**U374 the user rewinds a Workstream from a Checkpoint.** Narrows U355 (the card gains one word); uses `workstream.rewindPlan`, `workstream.rewind` and `workstream.rewound` (A35); no App seam command, no Token. Given a selected Workstream (U145) in Thread mode (U187) with Checkpoints, then:
- **Action.** Each `[data-checkpoint]` card whose `rewindable` is true has a light `rewind` word beside its time (Tokens only, 24 px hit area, visible focus, U86). A card with `rewindable: false` has none. The word is absent while a rewind is pending. Asserted in `u374_only_a_rewindable_checkpoint_has_the_word`.
- **Plan first.** Choosing it calls `workstream.rewindPlan` once and opens, in place under the card and without moving another row (U46), `rewind to <title>?` with one line per Agent in the plan: `<name>  back`, `<name>  removed` for `created_after` and `<name>  under takeover` with a checkbox `rewind it too`, unchecked. Esc or `keep` calls nothing more. Asserted in `u374_the_plan_lists_each_agent_and_calls_the_plan_once` and `u374_a_takeover_agent_is_unchecked_by_default`.
- **No files changed.** When `files_changed` is false the prompt shows `rewind  keep` only, and `rewind` calls `workstream.rewind` with `files: "keep"` and the checked Takeover Agents. Asserted in `u374_no_files_changed_asks_nothing_about_files`.
- **Files changed.** When `files_changed` is true the prompt first shows `files changed after this` with the paths (at most 5, then `+<n> more`), and offers `chats only` and `chats and files`, neither preselected and `rewind` disabled until one is chosen; they send `"keep"` and `"restore"`. Asserted in `u374_changed_files_ask_which_and_preselect_nothing` and `u374_the_choice_sends_keep_or_restore`.
- **Waiting and result.** While the call is pending the prompt's controls are disabled and nothing leaves the Rail. On `workstream.rewound` the prompt closes and the Checkpoint reads `rewound to here` in `--grey`; the Checkpoints after it stay and lose their word. A failure shows `✕ <message>` and keeps the prompt. Asserted in `u374_pending_disables_the_prompt`, `u374_rewound_marks_the_checkpoint_and_removes_later_words` and `u374_a_failure_shows_its_message`.
- **Strings.** Each label is the shortest that still says everything, derived with the `reduce` skill (policy).
