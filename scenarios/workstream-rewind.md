# The Door rewinds children to a Checkpoint (A35)

Module: `crates/agents`, `crates/contracts`, `crates/rupd`, `crates/rup` and `contracts/generated/`. Id: A35. Source: #808, revised by the owner's choice in #1580 (2026-10-14). Overturned by #1580: A35's App-only invocation and Takeover consent list; U374's Thread Checkpoint button and picker are removed. The Door rewinds one child or every child of its Workstream through a tool, using Checkpoints it wrote. Files stay unless the call explicitly requests restoration. A child created after the Checkpoint is stopped and leaves the Rail, with its Worktree and branch kept as A32 does. Messages, Todos and Pads are not rewound. Issues, pushes and other outside actions are never undone. Not clearing a Workstream (A32) and not forking.

`GLOSSARY.md` gains **Rewind** and **Mark** in the implementing PR (Contract recipe). A rewind never types `/rewind` or any command into an Agent (Principle P9 of `PRINCIPLES.md`): it restarts each Agent on a shortened copy of its conversation, as A22 resumes one.

**A35 the Door rewinds one or all children to its Checkpoint.** Contract change (the Contract recipe of `.agents/builder.md`): a Door-only MCP offering for plan and execution, backed by `workstream.rewindPlan` and `workstream.rewind`, with a child selection and required files choice instead of a Takeover consent list, the event `workstream.rewound {id, checkpoint}`, and the field `rewindable` on each `checkpoint.list` entry (M10). Given a Workstream with a Door and two Subagents (one under the other), each with a Worktree, and a Checkpoint `c` written by `checkpoint.write` (M10), then:
- **Offering and selection.** Only a Door is offered the rewind tool; direct MCP calls by an ordinary Agent are unavailable and have no effect. The Door can select one child (direct or nested) or all its Workstream's children; it cannot select itself, another Workstream or an Agent outside it. The Checkpoint must be one it wrote in that Workstream. Invalid selection is rejected before any effect. Tests: `a35_only_a_door_is_offered_and_can_call_rewind`, `a35_rewind_selects_one_or_all_children`, `a35_rewind_refuses_another_workstream_or_its_door`. The retained Daemon rewind implementation is reused; a missing MCP or contract prerequisite is scoped separately rather than rebuilding it. Any new public tool/type names are added to `GLOSSARY.md` in the implementation PR.
- **Marks.** When `checkpoint.write` succeeds the Daemon records, for every Agent of the Workstream at that moment, a **Mark**: the end of its conversation so far and a snapshot of the working files of its Worktree (tracked and untracked files that git does not ignore). A Mark is kept by the Daemon, is not part of M10's result, and survives a restart. A Checkpoint written before this scenario has no Marks and `checkpoint.list` marks it `rewindable: false`; so does a Checkpoint of an earlier Iteration (A32) and one whose Marks a later rewind made stale. Asserted in `a35_write_records_a_mark_per_agent`, `a35_marks_survive_a_restart` and `a35_an_old_checkpoint_is_not_rewindable`.
- **Plan.** `workstream.rewindPlan` changes nothing and returns `{agents: [{agent, name, takeover, created_after, files_changed: [path]}], files_changed: bool}`: one entry per selected child, `created_after` for an Agent started after `c`, `takeover` for an Agent under Takeover (B6), `files_changed` the paths whose content differs between the Mark's snapshot and the Worktree now (empty for a `created_after` Agent) and the top-level `files_changed` true when any list is non-empty. An unknown `id` or `checkpoint` is `NOT_FOUND`; a `rewindable: false` Checkpoint is `CONFLICT`. Asserted in `a35_plan_lists_each_agent_and_changes_nothing` and `a35_plan_refuses_an_unrewindable_checkpoint`.
- **Files choice.** `workstream.rewind` takes `files` of `"keep"` or `"restore"`, required: a missing or other value is `INVALID_PARAMS` and changes nothing. Whatever the call says, `"keep"` leaves every file byte for byte as it was. `"restore"` sets each selected child's working files to its Mark's snapshot (a changed file takes its old content, a file created since is removed, a file deleted since returns) and changes no unselected child's files, branch, `HEAD` or remote: a later commit stays, and a push, an Issue or a PR is never undone. Asserted in `a35_unselected_children_keep_their_files_and_conversations`, `a35_keep_changes_no_file`, `a35_restore_returns_each_worktree_to_its_snapshot` and `a35_restore_moves_no_branch_and_pushes_nothing`.
- **Conversations.** Each selected child that is not `created_after` is stopped as `agent.stop` does and its next Attempt (A20) resumes a copy of its conversation cut at its Mark, under a new conversation id (A22), so the original conversation file is never edited. Turns after the Mark are not in the copy and so not in the Agent's context. The child comes back `idle`, with no prompt typed. The Door itself is not restarted. Asserted in `a35_each_agent_resumes_a_copy_cut_at_its_mark`, `a35_the_original_conversation_is_untouched`, `a35_no_slash_command_is_typed` and `a35_a_failed_restart_leaves_the_others_rewound_and_retries`.
- **Later Subagents.** A selected child with `created_after` is stopped deepest first and leaves the Rail; its Worktree directory and branch stay whatever their state (as A32, not `agent.discard`), and `"restore"` does not touch them. Asserted in `a35_a_later_subagent_leaves_the_rail_and_keeps_its_worktree`.
- **Takeover.** A selected child under Takeover is never stopped, restarted, removed, restored or otherwise changed by the Door until the user calls `takeover.end`. The plan read also obeys B6. Execution for that child waits in B6's durable action order; the Door cannot end the Takeover or bypass it with a consent list or Terminal input. In an all-children call, children without Takeover can proceed; taken-over children remain visibly waiting and the overall completion event waits for all selected children to finish or receive a recorded drop reason. After release, the child's action runs once or shows why it cannot run; its Checkpoint and selection are revalidated before an effect. Tests: `a35_a_taken_over_child_waits_without_any_effect`, `a35_all_children_rewind_waits_only_for_taken_over_children`, `a35_a_door_cannot_override_takeover`, `a35_release_revalidates_the_checkpoint_and_runs_at_most_once`, `a35_restart_accounts_for_a_held_rewind` exercise B6 through actual Door MCP calls, restart and duplicate release notifications.
- **The Door is told.** The tool result identifies the Checkpoint title, selected children, each child's waiting, rewound, removed or dropped outcome and reason, and whether files were restored. Waiting and failure are distinguishable from completion; final outcomes remain readable after Project reopen. No synthetic first prompt restarts or Steers the Door. Asserted in `a35_the_door_is_told_what_was_rewound` and `a35_rewind_outcomes_survive_reopen`.
- **Nothing else.** Messages (including `pending` and `held` ones, which are delivered after the restart as B7 orders), Todos, Pads, Terminals, Checkpoints and the Workstream's id, name and Iteration are unchanged. Every Checkpoint after `c` stays stored and becomes `rewindable: false`; there is no Thread display. Marks needed by unselected children are not discarded by a selected-child rewind; test `a35_a_selected_rewind_keeps_other_child_marks`. Asserted in `a35_messages_todos_pads_and_checkpoints_stay`.
- **Failure and events.** One call at a time per Workstream (`CONFLICT` otherwise). If a step fails the call returns its error, steps already done stay done, a second call with the same params continues and snapshots restored twice are the same; `workstream.rewound` and one `rail.changed` are emitted once, after the last selected surviving child's `SessionStart`, or recorded drop for a child that cannot run. A rewind logs a `wrote` Touch on `rail:<id>` by the calling Door (M2). Asserted in `a35_one_rewind_at_a_time`, `a35_a_failed_step_retries_without_repeating_work` and `a35_rewound_is_emitted_once_after_the_last_session_start`.
Observer: `a35_` tests in `crates/rup/tests/**` against a real `rupd` with a deterministic fake `claude` that writes a conversation file and a real git repo, comparing files, branches, Rail, argv and conversation files, never a seeded tree. Implementation spans those existing modules in scoped PRs; contract changes update every caller together and regenerate `contracts/generated/`. Laws touched by Takeover/restart handling: M1, M3, M4, M6, M7, M9 and M10 (`scenarios/proofs.md`); implementation keeps `proofs/messages` and `docs/messages.md` agreeing and does not weaken a Message law. Native check, the user's Mac only: with a real `claude`, write a Checkpoint, send a child one distinctive later ask, ask the Door to rewind that child through its tool with `keep`, then ask the child about that later ask; it does not know. The Door retains its own conversation. Repeat while holding that child in Takeover: the rewind has no child effect until give-back, then runs once. The `ask` of the build run names the build and the steps.

U374 is removed by #1580: no App Checkpoint rewind word, picker, files-choice form or Takeover override is required. The implementation removes U374-only code, tests and captures alongside the obsolete App-facing rewind callers; existing Checkpoint storage and A35's Daemon support remain. Test: `a35_rewind_has_no_app_only_caller_or_u374_surface` inventories surviving callers and verifies the removed Thread surface is absent. The user may still use Claude Code's own `/rewind` directly in a child's Terminal; the Door uses its direct tool instead (policy). No visual change is claimed by this specification.
