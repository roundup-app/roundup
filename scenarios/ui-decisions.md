# UI: answer a Decision

Module: `apps/desktop/src/decisions`. Ids: U113, U194. Completes the intervention stage of `.agents/data/journey.md` using H18's real App proof and the existing H2–H10/H14 contracts. It needs neither the Message feed nor F7's interactive-login spike.

**U113 answer the selected Agent's Decision.** Given a Project with pending Decisions, selecting an Agent in the Rail shows its current Decision above its Terminal; selecting a Workstream shows its Door's Decision. Other Agents remain reachable through the existing Rail and attention navigation. No event steals focus or changes selection. A Decision shows the Agent's name, tool and readable arguments; long arguments wrap or scroll inside the Card without widening the pane. The controls are ordinary keyboard-accessible buttons with visible focus and the shared U133 styles. The Card consumes space above the Terminal, with scrollable content bounded to half the centre height; the Terminal keeps the remaining area. Card appearance, removal and height changes refit the existing emulator using U13’s at-most-once-per-frame resize, preserving output and scroll position. Long content and replacement never clip the Terminal or create page-wide overflow.

- An answerable permission Decision offers `allow` and `deny`. An H14 `ask_user` Decision displays its question and exactly its supplied answers. An unanswerable Decision explains that it must be answered in the Agent's Terminal and offers a focus action for that existing Terminal, with no fabricated answer button. An unreadable question payload shows a visible error and Terminal access; it never defaults to allowing anything.
- Subscribe before loading `decision.list`, using the existing connection's event stream. Decisions opened, replaced or cleared during that read are reconciled by id, so an old list cannot resurrect a cleared Card or overwrite its replacement. A webview reload restores the live Decisions. Empty results leave no empty Card.
- Activating an answer sends one `decision.answer` with the selected Decision id, answer and proof obtained from H18's App seam. While pending, its answer buttons are disabled and repeated activation sends no call. A rejected call keeps that Decision and its error visible with a retry. A successful answer removes only the answered id; an older completion never removes a replacement. An external clear removes that id. When a focused Card clears, focus returns to that Agent's Terminal only if focus was still inside the Card; unrelated focus stays put.
- Daemon exit disables answering and shows U25's existing failure state. Reopen uses the new connection and proof. Proofs stay in memory and never appear in DOM text, snapshots, storage or diagnostics. Showing or answering a Decision never sends an answer through `terminal.write`.
