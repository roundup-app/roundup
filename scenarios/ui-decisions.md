# UI: answer a Decision

Module: `apps/desktop/src/decisions`. Ids: U113, U194, U383, U406, U434, U3750, U3772, U3773. Completes the intervention stage of `.agents/data/journey.md` using H18's real App proof and the existing H2–H10/H14 contracts. It needs neither the Message feed nor F7's interactive-login spike.

**U113 answer the selected Agent's Decision.** Given a Project with pending Decisions, selecting an Agent in the Rail shows its current Decision above its Terminal; selecting a Workstream shows its Door's Decision. Other Agents remain reachable through the existing Rail and attention navigation. No event steals focus or changes selection. A Decision shows the Agent's name, tool and readable arguments; long arguments wrap or scroll inside the Card without widening the pane. The controls are ordinary keyboard-accessible buttons with visible keyboard focus and the shared U133 styles (U2770, `ui-pointer-focus.md`). The Card consumes space above the Terminal, with scrollable content bounded to half the centre height; the Terminal keeps the remaining area. Card appearance, removal and height changes refit the existing emulator using U13’s at-most-once-per-frame resize, preserving output and scroll position. Long content and replacement never clip the Terminal or create page-wide overflow.

- An answerable permission Decision offers `Allow` and `Deny`. An H14 `ask_user` Decision displays its question and exactly its supplied answers. An unanswerable Decision explains that it must be answered in the Agent's Terminal and offers a focus action for that existing Terminal, with no fabricated answer button. An unreadable question payload shows a visible error and Terminal access; it never defaults to allowing anything.
- Subscribe before loading `decision.list`, using the existing connection's event stream. Decisions opened, replaced or cleared during that read are reconciled by id, so an old list cannot resurrect a cleared Card or overwrite its replacement. A webview reload restores the live Decisions. Empty results leave no empty Card.
- Activating an answer sends one `decision.answer` with the selected Decision id, answer and proof obtained from H18's App seam. While pending, its answer buttons are disabled and repeated activation sends no call. A rejected call keeps that Decision and its error visible with a retry. A successful answer removes only the answered id; an older completion never removes a replacement. An external clear removes that id. When a focused Card clears, focus returns to that Agent's Terminal only if focus was still inside the Card; unrelated focus stays put.
- Daemon exit disables answering and shows U25's existing failure state. Reopen uses the new connection and proof. Proofs stay in memory and never appear in DOM text, snapshots, storage or diagnostics. Showing or answering a Decision never sends an answer through `terminal.write`.

Observers: `u113_` tests render the real App against the fake App seam, with delayed list/answer/proof promises and opened/cleared events, and assert every race and failure above through visible state and recorded calls. Terminal integration tests assert fitting after Card appearance, replacement and removal, one resize per animation frame, and preserved output/scroll position. A harness seed with multiple Agents includes a permission, an H14 question and an unanswerable Decision; select each using pointer and keyboard. Capture the Card, pending, failure and cleared states at 1280×800, dark. Name the D1–D10 readings before and after and regress no passing Check. The fake proves rendering and interaction; H18's real-Daemon observer proves authentication and answer delivery. No native rendering claim follows from Chromium.

**U3773 an answered permission folds to one line, with Revoke while a Project grant lasts.** Asked by #3309. Given U3772's Card answered, then:
- **Fold.** When `decision.answer` succeeds the Card is replaced, in the same place above the Terminal, by one line: `Allowed once`, `Allowed for this session`, `Allowed for this Project`, or `Denied`, with a check or cross glyph, naming the tool target in short (`rm -rf build`). Only the answer the user gave from this Card folds; a Decision cleared any other way (Terminal answer, `agent-gone`, `replaced`, a Door's answer) leaves no line (H7, H21).
- **Revoke.** `Allowed for this Project` shows a `Revoke` button that calls `decision.revoke` once (pending-disabled; on `NOT_FOUND` the line becomes `Allowed for this Project (already removed)` without the button; any other failure shows U113's error line and keeps the button). On success the line is removed. The other lines show no `Revoke` (H23: no session revoke).
- **Lifetime.** The line stays until the Agent's next Decision opens, the user dismisses it with `Esc` while focus is in it, the Agent is gone, or a webview reload (memory only). It consumes space above the Terminal as U113 does and refits it once per frame.
- **Motion.** The fold from Card to line is the user's own act and may move, 150 ms or less, opacity and height only, easing per `docs/motion.md`; nothing else moves, and under `prefers-reduced-motion` it is instant. Screen readers hear the line as a `status`.
- **Regression.** Nothing allows by default; a cleared Decision still clears as `docs/permission-decisions.md` says.
