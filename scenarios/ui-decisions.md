# UI: answer a Decision

Module: `apps/desktop/src/decisions`. Ids: U113, U194, U383, U406, U434. Completes the intervention stage of `.agents/data/journey.md` using H18's real App proof and the existing H2–H10/H14 contracts. It needs neither the Message feed nor F7's interactive-login spike.

**U113 answer the selected Agent's Decision.** Given a Project with pending Decisions, selecting an Agent in the Rail shows its current Decision above its Terminal; selecting a Workstream shows its Door's Decision. Other Agents remain reachable through the existing Rail and attention navigation. No event steals focus or changes selection. A Decision shows the Agent's name, tool and readable arguments; long arguments wrap or scroll inside the Card without widening the pane. The controls are ordinary keyboard-accessible buttons with visible focus and the shared U133 styles. The Card consumes space above the Terminal, with scrollable content bounded to half the centre height; the Terminal keeps the remaining area. Card appearance, removal and height changes refit the existing emulator using U13’s at-most-once-per-frame resize, preserving output and scroll position. Long content and replacement never clip the Terminal or create page-wide overflow.

- An answerable permission Decision offers `Allow` and `Deny`. An H14 `ask_user` Decision displays its question and exactly its supplied answers. An unanswerable Decision explains that it must be answered in the Agent's Terminal and offers a focus action for that existing Terminal, with no fabricated answer button. An unreadable question payload shows a visible error and Terminal access; it never defaults to allowing anything.
- Subscribe before loading `decision.list`, using the existing connection's event stream. Decisions opened, replaced or cleared during that read are reconciled by id, so an old list cannot resurrect a cleared Card or overwrite its replacement. A webview reload restores the live Decisions. Empty results leave no empty Card.
- Activating an answer sends one `decision.answer` with the selected Decision id, answer and proof obtained from H18's App seam. While pending, its answer buttons are disabled and repeated activation sends no call. A rejected call keeps that Decision and its error visible with a retry. A successful answer removes only the answered id; an older completion never removes a replacement. An external clear removes that id. When a focused Card clears, focus returns to that Agent's Terminal only if focus was still inside the Card; unrelated focus stays put.
- Daemon exit disables answering and shows U25's existing failure state. Reopen uses the new connection and proof. Proofs stay in memory and never appear in DOM text, snapshots, storage or diagnostics. Showing or answering a Decision never sends an answer through `terminal.write`.

Observers: `u113_` tests render the real App against the fake App seam, with delayed list/answer/proof promises and opened/cleared events, and assert every race and failure above through visible state and recorded calls. Terminal integration tests assert fitting after Card appearance, replacement and removal, one resize per animation frame, and preserved output/scroll position. A harness seed with multiple Agents includes a permission, an H14 question and an unanswerable Decision; select each using pointer and keyboard. Capture the Card, pending, failure and cleared states at 1280×800, light and dark. Name the D1–D10 readings before and after and regress no passing Check. The fake proves rendering and interaction; H18's real-Daemon observer proves authentication and answer delivery. No native rendering claim follows from Chromium.

**U406 the Card for `ask_user` shows each answer's tradeoff and a preview, and takes a note.** Asked by #1085 and approved by the user on 2026-10-12 in the Pad `workstream-view-drafts`. Narrows U113's tool clause and its "An H14 `ask_user` Decision displays its question and exactly its supplied answers" and replaces the buttons of that clause; H14 gives the data. Changes the Decision Card of `ask_user` only: a permission Decision keeps today's Card (U383), and the `AskUserQuestion` Card keeps H22's text (U400). It adds no Token and no App seam command; `decision.answer` gains H14's `note`. Given a Decision `{tool: "ask_user", answerable: true, args}` for the selected Agent `workstream`, with `args` holding three answers (the first labelled `A · Brief (recommended)`, each with a description and a preview) and a question of four lines, then:
- **Title.** The Card's title is `workstream asks`, the Agent's name then `asks`, in Ink (bold `--amber`, the `needs-you` Ink); no tool name shows, which narrows U113's "tool" clause too. The question renders as Q3 lays it out, its first line as the heading.
- **Answers.** One row per answer in H14's order: the label, then the description beneath it in `--grey` at `--text-small`. The recommended row shows its label without ` (recommended)` and the word `Recommended` at the right of its row. The rows are one `listbox` with an `option` each, the focused one `aria-selected`, on `--selected`; a row's pointer press focuses it and sends nothing.
- **Focus.** The first row is focused when the Card opens, and opening, replacing or clearing a Card never moves keyboard focus (U113). `ArrowDown` and `ArrowUp` move the focused row, from the list or from the note field, and past the last row `ArrowDown` focuses none (an own answer) and `ArrowUp` from the first row does the same; a further press wraps to the first or last. With none focused the preview is gone and the note field's placeholder is `Your own answer`.
- **Preview.** Below the rows, the focused answer's `preview` drawn as Markdown (Q2 row `q2_decision_preview`; Q3, Q10), on `--sunken` with `--radius-row`, headed by the label. It swaps on focus. An answer with no `preview` shows no box.
- **Note.** A one-line text field under the preview, placeholder `Note for <label>, or your own answer`, bounded as H14 says. `Enter` in it, or the button `Send`, sends `decision.answer {id, answer: <focused label>, note, proof}`, or `answer: null` when none is focused, and an own answer with an empty note leaves `Send` disabled. The field's text stays when focus moves between rows.
- **After you send.** U113's rules hold for the new controls: while pending the rows, the field and `Send` are disabled and a repeat press sends no call; a rejected call keeps the Decision, the field's text and the error with a retry; a success removes only that id; an external clear removes it; focus returns to the Terminal only if it was inside the Card. A Decision with no answers shows the question, the field and `Send`, and no rows.
- **Checks.** Moves D1, D2, D5, D6 and D8 for the new rows, preview box and field, and passes them in both schemes and at 1280×800 (D10); each control shows rest, hover and focus (D6), and the preview box's border is 1 px `--hairline` (D8). No Check passing on `main` regresses.
