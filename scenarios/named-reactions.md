# Named Project reactions

Policy amendment — U2539b (`scenarios/ui-worktree-changes.md`, #3786) narrows NR9's mounting: the named reactions list/create/detail opens on request from the Project menu, not automatically on the resting landing. Authority, inspection/stop/run, failure and draft semantics are unchanged. `u2539b_landing_opens_requested_surfaces_and_returns` proves access; retain NR9's action observers inside that requested surface.

Specification for #2775; feature delivery remains in dependent implementation Issues. Baseline: `2c2a5cbf9` on `origin/main`. P13 governs this feature; P4, P6, P9, P10 and P11 also apply. The owner direction in #2775 is acceptance authority; preserve its dated quotations in every child Issue.

## Interface and ownership

Policy: extend the existing Daemon wake evaluator and `crates/messages` durable Message holder, sharing the Project database transaction for accepted firing plus Message. Keep existing `agent.wake` and B41–B48 unchanged. A reaction is a separate saved definition, not a replacement Wake request or delivery queue. No Model evaluates a condition. No Agent starts on open or recovery.

Policy: implementation adds glossary terms and generated contracts atomically with all callers. Use `reaction.create`, `reaction.list`, `reaction.get`, `reaction.stop` and `reaction.run`, with generated CLI commands and MCP tools from the existing method registry. Creation is immutable: changing a definition means stop and create another identity. No edit RPC or general version store. A client-supplied operation id makes retried create/run requests return the original result; different payload with the same operation id is refused.

Policy: a definition contains Project-scoped id, name, authorizing Actor, Home, exact target Agent id, exact instruction, typed condition, finite positive maximum firings, absolute expiry, and re-arm rule. Default is one firing, no re-arm. Expiry is required, later than activation; invalid or unsupported definitions save nothing. Names are labels, never lookup identities. List/get return saved definition, observation health/cursor, remaining bound, lifecycle state and accepted firing ids linked to Message ids. Store accepted definition bytes and source evidence with the firing, reusing Message history for delivery outcomes.

Policy: user creation may target a Project Agent. An Agent may create only for itself or an Agent it could normally Message in its Reach, and may inspect/stop/run only its own authorized definitions within that Reach. Resolve Actor from the connection, never supplied payload authority. Recheck permission, target identity and lifecycle at firing/run, and existing Message guards at delivery. Removal/revocation disables future acceptance with an inspectable cause. Stop/run by another Agent is forbidden. The user may inspect/stop/run within the Project. Home follows P6; moving never changes trigger or target identity.

## Supported conditions and evidence

| Condition | Authoritative source and identity | Matching and recovery |
|---|---|---|
| Any/all of 1–20 distinct Agents finished | Existing committed `agent.status` Events, Project/Agent ids, Attempt and Event number; capture activation Event head and current Rail state under serialized registration | Same finished Kinds as B41: idle/done/error/needs-you. Remember each named identity's observed completion for all. Current finished state may establish completion after expired history; a removed observed Agent is unavailable, not evidence of completion. Record that the evidence is current state rather than an invented past Event. |
| Named PR head's checks passed | Extend existing Worktrunk collection, not a second forge client; retain forge/repository/PR identity, exact head commit, check-set revision and authoritative completeness/freshness | Activation pins the observed current PR head. Every required check must have a successful conclusion for that exact head; missing, pending, unknown, no-CI, stale, failed and superseded head do not pass. A head change invalidates the reaction visibly; creating a replacement is explicit. Fresh complete current-head evidence can reconcile a history gap; cached UI CI alone cannot. |
| One explicit instant | User-approved full date, local time and UTC offset, stored resolved UTC instant plus displayed time zone/offset | No natural-language guessing. “At 9am” requires a preview with date and offset before activation. One-shot only. Late policy is explicitly `once-before-expiry` or `skip`; recovery applies it once. |

Policy: all/any combine Agent ids only; arbitrary boolean programs and mixed-source expressions are refused before activation. PR and time are separate typed conditions, not Agent polling. Unsupported sources, including output-publication events until a declared authoritative publication capability exists, are refused by name with the missing capability. This is extensible Project-event scope, not a claim that only Agent status can be observed. Published-output support must build on #2774's accepted publication identity/revision rather than infer publication from filesystem changes, Terminal text or an Agent report. #2692 links and #2694 send actions retain their own ownership; neither proves publication. No universal event archive is added.

## Acceptance

Every then-clause below names its planned behavioral observer; these tests do not yet exist. Daemon-facing observers extend `crates/rup/tests/e2e/wake.rs` or its existing E2E module with real temporary Project data and deterministic fake Claude. Lower store fault injection is used only for the otherwise unobservable transaction interruption. App observers use its existing public seam and Vitest integration suites. A spec merge claims no behavioral pass.

**NR1 explicit bounded authority.** Given two Projects and Agents with overlapping names, creating a reaction records exact Project, Home, authorizer, target and instruction; wrong Project/Reach, missing target, duplicate Agent ids, unsupported source, missing expiry, zero bound and unauthorized create/inspect/stop/run refuse without saved definitions or Messages. A retry with the same operation id returns the same definition, while a conflicting payload refuses. Planned test: `nr1_authority_and_retry_preserve_exact_definition`. Maximum firings above one requires NR4's Agent re-arm; PR and time reject repeated mode. Planned test: `nr1_invalid_bounds_save_nothing`.

**Reaction** (`reaction.create`, `.list`, `.get`, `.stop`, `.run`; user label: Reaction): A saved, immutable instruction a declared condition delivers once to a target Agent as a Message: Project, Home, authorizing Actor from the connection, exact target and words, a typed condition (named Agents finished, a PR's checks passed, or one instant; a PR's checks pin the head observed at activation and match only complete fresh `agent.worktreeState` evidence for it, a moved head ending the reaction as `invalidated`), a finite firing bound, an absolute expiry and a re-arm rule. A retried `operation` returns the first definition and a different payload refuses; a refusal saves nothing. To change one, stop it and create another (`scenarios/named-reactions.md` NR1). Not a Wake request, which is an Agent's one-time ask.

**NR2 observed Agent completion.** Given all/any conditions and a finish between registration's state read and Event subscription, each matching set accepts one firing with the named identities, actual evidence and one durable Message containing exactly the saved instruction. An unchanged true condition, duplicate notification, simultaneous finishes and overlapping observers create no extra firing. Already-finished Agents can match on activation. Removed/wrong identities fail visibly rather than substituting names. Planned test: `nr2_agent_conditions_match_once_without_a_model`, counting firing ids, Message ids and vendor prompts, including no prompt for evaluation.

**NR3 durable acceptance and frozen evidence.** Given faults before or after the firing commit and reopen/replay, either neither firing nor Message exists or both exist with the same original ids; recovery completes eligible work once. Stop-and-recreate with new instruction/condition leaves the old accepted definition/evidence/Message unchanged. A write failure is inspectable with retry recovery, never healthy waiting or acceptance without a Message. Planned tests: `nr3_firing_and_message_commit_together` in the existing Message-store tests with transaction fault injection, and `nr3_reopen_preserves_accepted_definition_and_message` through real Daemon/E2E.

**NR4 repeat, stop and target lifecycle.** Given repeat-enabled Agent conditions, re-arm requires every participating Agent to be observed non-finished after the preceding firing, followed by a new qualifying completion set; current true refreshes do not re-arm. Each acceptance increments the durable ordinal and consumes the finite bound; expiry accepts nothing at or after its instant. Explicit run uses an operation id and consumes one remaining firing without claiming the condition matched; it does not advance event cursors or re-arm automatic evaluation. One-shot automatic and manual races share the same remaining bound. Stop and acceptance serialize: if stop commits first no later firing is accepted; otherwise inspection shows the accepted Message and its actual state. A stopped/exhausted/expired reaction refuses run; a new definition is required. A stopped target keeps pending work under existing stopped-Agent rules without starting it; a removed/replaced target disables future acceptance without retargeting. Planned test: `nr4_bounds_rearm_stop_and_target_races`.

**NR5 observation failure and history gaps.** Given source disconnection, failed reads or expired history, inspection shows source, last evidence/cursor, gap and recovery action; no unknown fact matches. Restored authoritative current Agent state or fresh complete pinned-head checks may reconcile state conditions, with the gap still recorded. An occurrence-only source without retained occurrence evidence must remain unmatched and explain missing evidence; no generic current-state fallback is allowed. Unsupported occurrence-only definitions are refused before activation. A reported Agent result proves only that report, never external success. Planned test: `nr5_gaps_require_condition_specific_evidence`, using expired history with both sufficient and insufficient current evidence, interrupted reads and reconnect/replay.

**Reaction observation identity** (`ObservationCause`, `ObservationGap`, `ObservationRecovery`, `ObservationHealth`): Typed facts emitted where a Reaction's observation succeeds or fails. The Observation and retained Watch keep `cause_code`, `gap_code`, `recovery_code` and `health_code` separately from diagnostic prose, cursor, pinned head and evidence. `unknown`, including absent legacy identity, grants no authority and offers a current check; historical prose never supplies identity or a successful match.

**Observation** (a Reaction's `observation`; `reaction_watch`, `project.db` migration 0010): What the Daemon's evaluator knows of an Agents Reaction: the Event `cursor` it decided up to, its `health` (`observing`, or `unavailable` while a read failed or a named Agent or the target is gone), the last `evidence`, and any `gap` with its `recovery`. A Reaction is activated by reading the Event head, then the Rail, then replaying the Events after the head, so a finish in between is replayed. Automatic firings use the operation `auto-<n>`, so a retry after a crash returns the firing already made. A gap, once recorded, stays recorded after current Agent state reconciles it; a named Agent without a state never matches (`scenarios/named-reactions.md` NR2, NR4, NR5).

**NR6 declared time.** Given a resolved date/time/offset preview, acceptance retains that exact instant and zone/offset. Ambiguous or nonexistent local time without an explicit offset, unsupported calendar recurrence, unparseable input and missing missed-time policy refuse. Once activated, later time-zone/DST changes do not reinterpret the stored instant. Wall-clock adjustments cannot accept before that UTC instant; waking/reopening or a forward clock step after it applies the declared late policy once before expiry, otherwise expires without a firing. A backward step never duplicates accepted work. Recheck wall time when a Tokio deadline wakes, on resume and before acceptance; re-arm a deadline if early. Planned test: `nr6_resolved_time_clock_changes_and_missed_policy`, with deterministic clock, sleep, restart, expiry and no backlog; `nr6_preview_requires_unambiguous_time` checks preview/activation identity.

**Preview** (`reaction.preview`; user label: Time preview): The exact date, local time, UTC offset and UTC instant a Reaction's `instant` condition will keep, resolved from a typed date, time and offset before activation. It saves nothing; a Reaction is created with the preview's `at` text and never reinterpreted after a time-zone change. A missed instant follows its late policy once: `once-before-expiry` fires on recovery before expiry, `skip` fires nothing; neither fires at or after expiry (`scenarios/named-reactions.md` NR6).

**NR7 PR checks bind the head.** Given complete authoritative required checks on a pinned head, only that head's complete successful check set matches. Replay/check duplication yields one firing. An old passed head followed by a changed failing head, incomplete pagination, unavailable required-check configuration, stale cache, no-CI, contradictory revision or failed refresh creates no match and exposes its cause/recovery. Head changes require a new reaction, never silent repinning. Planned test: `nr7_checks_require_complete_pinned_head_evidence`, extending the existing Worktrunk release fixtures and exercising the real Daemon reaction seam. Collector identity includes Project, Agent, Worktree, repository and PR; two same-numbered PRs in different repositories cannot cross-match.

**NR10 authoritative PR evidence.** Given the existing public `agent.worktreeState` seam and Worktrunk fixtures, expose repository/PR/head and complete required-check-set identity, freshness and evidence revision alongside existing CI display facts. Incomplete, stale, unknown and unavailable source facts remain explicitly distinguishable and never appear as complete passing evidence; two repositories with the same PR number remain distinct. Extend the existing collector rather than adding another forge client. Planned test: `nr10_public_worktree_evidence_preserves_head_and_completeness` in `crates/agents/tests/scenarios/worktree_state.rs`, with existing release fixtures. This observer requires no reaction implementation; NR7 separately proves the consumer refuses unsafe matches. Contract changes regenerate types and update every caller atomically.

**NR8 normal Message delivery.** Given accepted firings with busy/stopped receivers, permission loss and Attempt changes, normal pending/delivered/dropped rules, batching, Reach and provenance apply. Recovery starts no program. Inspection distinguishes matched condition, accepted firing and Message outcome; delivery never becomes verified work. Agent-authored results are labeled reported. Planned test: `nr8_existing_delivery_guards_and_reported_outcomes`, reusing existing B32/B39/B40/B46 proofs and adding only reaction-to-Message identity assertions. Laws M1–M10 remain unchanged; implementation updates `docs/messages.md` and `proofs/messages` together if their delivery descriptions need extension.

**NR9 inspect and act in the Project.** Given ten Agents and saved reactions, the Project menu opens the named reactions list on request, with a create action; selecting a row opens its detail in the existing centre surface. The form previews authority, Home, exact target, instruction, condition, expiry/bound and resolved time. Detail exposes saved facts, observation failure/recovery and linked Message states; stop/run are explicit actions under NR1/NR4. Opening/reloading or switching Projects renders saved facts without a Model call or automatic run. Failed submits and navigation preserve exact draft plus original identities under P11; acknowledged creation consumes only the submitted revision. Actions support pointer/keyboard and return focus to the opener. Planned App tests: `nr9_create_inspect_stop_run_and_focus` and `nr9_failed_creation_preserves_original_draft`; real Daemon parity has no web test since the owner's flaky-test cut (#4925). No browser, Terminal split, dictation or Agent conversation renderer is introduced.

Policy: NR9 moves D2, D5 and D6 and breaks no Check passing on main. Use existing Ark-backed UI primitives and Tokens. Render Request/Intervene/Review journey stages at 1512×950 in the isolated headless harness, dark, ten Agents, long names, overlapping names, empty list, pending/dropped Messages, unavailable source and failed creation on the densest seed. Capture before/after interaction and Check results under `artifacts/ux/NR9/`; failures must remain readable. No motion clause. Do not claim native Mac observations from Chromium.

## Library fit and implementation seam

Policy: use the existing Tokio runtime's [sleep_until](https://docs.rs/tokio/latest/tokio/time/fn.sleep_until.html) for actual one-shot deadlines, not intervals for Agent conditions. Its [Instant](https://docs.rs/tokio/latest/tokio/time/struct.Instant.html) is monotonic, so persist UTC separately and recheck wall time as NR6 requires. Documentation inspected 2026-10-19 reports Tokio 1.53.3; use the repository's compatible dependency, not an unsolicited upgrade. [Chrono LocalResult](https://docs.rs/chrono/latest/chrono/offset/enum.LocalResult.html) models ambiguous/nonexistent civil time, but no calendar recurrence or IANA-zone parser is required by the accepted explicit-offset preview; do not add it solely for one-shot deadlines. Revisit maintained calendar libraries only when accepted semantics cannot be represented by this form.

Policy: extend Worktrunk's existing collector and release fixtures for forge evidence; never parse vendor Terminal strings or trust UI cache as a forge observation. Extend existing Message persistence and evaluator rather than introducing another scheduler/store, generic event framework, version archive or reporting subsystem. Contract implementation adds names to `GLOSSARY.md`, regenerates contracts and changes all callers together; no hand-edited generated types. No loop machinery changes. Implementation PRs introducing machinery provide their own rule-9 library research and maintenance evidence.
