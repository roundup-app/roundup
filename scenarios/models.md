# The user picks each Agent's Model (A36, A37, M12, U377, U378)

Module: `crates/agents` (the Adapter's lists and the launch, under `claude_code/`, P4), `crates/contracts`, `crates/rupd`, `crates/rup`, `contracts/generated/` and `apps/desktop`. Ids: A36, A37, M12, U377, U378. Builds P8 (`PRINCIPLES.md`) from the user's request (#696, 2026-10-10); P9 bounds how. Decided by the user: a Door picks a child's Model per job, only from a list the user allows ("every child runs the user's default" lost); a change to a running Agent applies now after one confirm ("apply at its next start" lost).

`GLOSSARY.md` gains **Role** (the kind of Agent roundup starts, which a Project's Model and Effort are set for: `door`, `subagent`, `scribe`) in the implementing PR (Contract recipe of `.agents/builder.md`); **Model** and **Effort** are already there. Role is not Kind (a Status). The roles are one list in `crates/agents`, and a role added later joins it and so joins every surface below. Laws M1 to M10 are not touched. Order of the PRs, by rule 3: A36 and A37 (the Adapter and the Daemon, with `crates/contracts`), then M12 (`rup mcp`), then U377 and U378 (the App); each later slice is blocked on the one before (native dependencies).

**A36 an Agent starts on the Model and Effort the user chose.** Contract change (the Contract recipe). New methods, each logging a `wrote` Touch by its caller (M2):
- `models.list {}` returns `{models: [{id, label}], efforts: [{id, label}]}`, the lists the Adapter offers (in `claude_code/`, one table with the `claude --version` it was read on and the doc page, as M4 holds its schema). Outside `claude_code/` an `id` is opaque (P4, rule 6).
- `project.setModels {roles: [{role, model, effort}], allowed: [model]}` returns `null`; `model` and `effort` are an id or `null`. `project.get` gains `models: {roles, allowed}` with one entry per role of the list above, `{role, model: null, effort: null}` for one never set and `allowed: []` for a Project that never had it. An id the Adapter does not list is `INVALID_PARAMS` naming it and changes nothing. It survives a Daemon restart (G1's store).
- `agent.spawn` (`SpawnParams`) and `rail.startDoor` gain `model: Option<id>` and `effort: Option<id>`, absent from an old caller's JSON. `Agent` nodes keep the pair they run on, in `rail.tree`'s `RailNode` as `model` and `effort` (id or `null`), persisted with the Rail.
Given a launch of an Agent of role `r`, then the pair it runs on is the first set of: the call's own (`agent.spawn` or `rail.startDoor`), the Project's for `r`, else none. Model and Effort are chosen apart: a call that sets only a Model takes the Project's Effort. A value that is none is not passed: argv has no `--model` and no `--effort` for it, and its environment gets no variable from roundup. A value that is set is passed as `--model <id>` and `--effort <id>` and also pinned in the Agent's environment as `ANTHROPIC_MODEL` and `CLAUDE_CODE_EFFORT_LEVEL`, replacing whatever the Daemon's own environment holds (Claude Code reads the variable before the flag and before the settings `model`, so the user's choice wins). A value that is none leaves the Daemon's own variable, which is the user's own default (A30's strip list is unchanged). The Door's `rail.startDoor`, an `agent.spawn` by the user or by an Agent, the Scribe's start (P13) and A22's resume all take this path; a resume takes the pair the Agent held (A37).
Tests (`a36_`) in `crates/agents` and `crates/rup/tests/`: `a36_models_list_comes_from_the_adapter`, `a36_set_models_round_trips_and_survives_a_restart`, `a36_an_unlisted_id_is_invalid_params_and_changes_nothing`, `a36_each_role_runs_on_its_project_pair` (door, subagent, scribe), `a36_unset_passes_neither_flag_nor_variable`, `a36_a_calls_pair_beats_the_projects`, `a36_a_set_effort_beats_the_daemons_variable` (the Daemon's environment holds `CLAUDE_CODE_EFFORT_LEVEL=low` and `ANTHROPIC_MODEL=other`; the fake `claude` records the argv and environment it was started with and holds the user's id), `a36_an_unset_value_leaves_the_daemons_variable`, `a36_every_listed_role_is_in_project_get`. Observer: the real Daemon and the fake `claude` (`crates/rup/tests/e2e/fake_claude.py`), which records each launch's argv and environment to a file the test reads, never a seeded tree.

**A37 the user changes a running Agent's Model or Effort.** Contract change (the Contract recipe): `agent.setModel {id, model, effort, confirmed}` returns the Agent's `RailNode`; `model` and `effort` are an id or `null` (back to the Project's). It is the user's: M5 lists it among the methods with a reason (the user's cost, P8), so no tool offers it, and a call by an Agent is `FORBIDDEN` (M2).
- **One confirm.** `confirmed` must be `true`; otherwise the call is `INVALID_PARAMS` naming `confirmed` and changes nothing. A pair equal to the one the Agent holds changes nothing and starts nothing. An id the Adapter does not list is `INVALID_PARAMS`. Asserted in `a37_without_confirmed_nothing_changes`, `a37_the_same_pair_starts_nothing`, `a37_an_unlisted_id_is_invalid_params`.
- **Applies now, as one resume.** Given a running Agent with A21 data, then the Daemon stops it as `agent.stop` does and starts it once by A22's resume path: the same conversation (`--resume <saved id>`), the same directory and Worktree, the new pair as A36 passes it, and no prompt typed. The Agent keeps its id, name, parent, order, Pads, Todos and Routes. The pair is stored on the Agent, so a later A22 resume or A35 restart uses it, and the Project's setting is unchanged. Exactly one launch follows a confirmed change. Asserted in `a37_a_confirmed_change_makes_one_launch_with_resume_and_the_new_model` (the fake `claude`'s launch record: one new launch, `--resume <id>`, `--model <new>`), `a37_the_agent_keeps_its_identity_and_the_project_keeps_its_setting`, `a37_a_later_resume_uses_the_changed_pair`.
- **An Agent that is not running.** An exited Agent only stores the pair; no launch. Asserted in `a37_an_exited_agent_only_stores_the_pair`.
- **Never typed.** No path of this change, or of A36, writes `/model` or `/effort` (or any `/` command) to an Agent's Terminal (P9: `/model <name>` also saves it as the user's own default). Asserted in `a37_no_slash_command_is_ever_typed`: over every scenario of A36 and A37 the fake `claude`'s recorded input holds no line starting with `/`, and a source scan of `crates/agents` and `crates/rupd` finds no `"/model"` or `"/effort"` literal outside this test.
- **Cache.** A change that is not this call changes no Agent's Model, Effort, Brief file, settings file or tool list during its session: `project.setModels` while an Agent runs starts no launch and edits none of its files. Asserted in `a37_project_set_models_does_not_touch_a_running_agent`.
Observer: as A36. Native Mac check: none (the issue says so).

**M12 a Door picks a child's Model from the list the user allows.** Contract change (the Contract recipe; M5's test is amended with it). `agent_spawn` (F3, A28) gains `model: Option<id>`, derived from `SpawnParams` as M1 holds; `agent_context` (E4) gains `models: {allowed: [{id, label}]}` in its result, the Project's `allowed` list with the Adapter's labels. Given an Agent `m` and its `rup mcp`, then:
- **On the list.** `agent_spawn {…, model}` with a `model` in the list starts the child on it (A36: the call's pair), and the child's `RailNode.model` is that id. Without `model` the child takes the Project's Model for the role. Asserted in `m12_a_listed_model_starts_the_child_on_it` and `m12_no_model_takes_the_projects`.
- **Off the list.** A `model` not in the list, or any `model` while the list is empty, is `INVALID_PARAMS` whose message names every allowed id and label (or says none is allowed and to omit `model`), starts no Agent, creates no node and logs no Touch (M7's refusal rule). It holds for every Agent that calls the tool, not only a Door; the user's own `agent.spawn` is limited only by A36's rule (the Adapter's list). Asserted in `m12_an_off_list_model_is_refused_naming_the_allowed`, `m12_an_empty_list_refuses_any_model`, `m12_a_refusal_starts_nothing`.
- **Only in a tool result.** The allowed list is in no file or text the Agent's session holds at start: the Brief file's bytes (E1), the settings file and `tools/list` (descriptions and schemas) are identical for two Projects whose lists differ, and a change of the list while a Door runs changes none of them. The `model` field's description is fixed text that points to `agent_context`'s `models.allowed`. Asserted in `m12_the_list_is_not_in_the_brief_the_settings_or_the_tool_list`, `m12_a_changed_list_reaches_the_door_through_agent_context_only`. The Brief of a Door says (policy) to read `agent_context` and to pick the smallest allowed Model that does a child's job; B24's test of the Brief against the tools is unchanged.
- **M5.** `models.list` and `project.setModels` are Project settings and are listed with a reason (the user's); `project.get` is already a tool and its result gains `models`. `m5_` passes with these.
Observer: the built `rup mcp <agent-id>` over stdio against a real `rupd` and the fake `claude`, as A28's observer runs; the fake records the launch of the child.

**U377 the user sets Models and Efforts for a Project.** Narrows U179 and U138 (the shortcut table); uses `models.list`, `project.get` and `project.setModels` (A36), which the App seam's method list passes through; no new App seam command and no Token. Where it lives: a sheet named `Models` for the open Project, opened by `⌘,` and by `models` in the open Project's tab menu (a right-click menu; U56's row menu is the model). Given an open Project, then:
- **Roles.** The sheet has one row per role the Daemon returns in `project.get`'s `models.roles` (none is hard-coded in the webview), labelled by role, with two selects, Model and Effort, each offering `default` first (the value `null`: nothing is passed, the user's own Claude Code default applies) and then the labels from `models.list`. A row shows what is set. Asserted in `u377_one_row_per_role_from_the_daemon`, `u377_default_is_first_and_means_null`.
- **Door's list.** Below the rows, `Doors may use` holds one checkbox per Model from `models.list`, unchecked for a Project that never had it set, with one line of text saying a Door can start a child only on a checked Model. Asserted in `u377_the_allowed_list_starts_empty`.
- **Saving.** Each change calls `project.setModels` once with the whole state and shows no other effect; a failure shows U80's `✕ <message>` line and the control returns to the stored value. The sheet says (policy) that a running Agent is not changed. Asserted in `u377_a_change_calls_set_models_once_with_the_whole_state`, `u377_a_failure_shows_the_error_line_and_keeps_the_stored_value`.
- **Keyboard and focus.** Every control is reachable by Tab with a visible focus ring, `Esc` closes the sheet and returns focus to where it opened from, and a select has an `aria-label` of its row and its field (U86). Asserted in `u377_the_sheet_is_keyboard_complete`.
- **Worst case.** On the densest seed (a role with a 40-character label, an Adapter list of 20 Models) no label overflows the sheet and none is clipped. Asserted in `u377_long_labels_do_not_overflow`.
Tests (`u377_`) are Vitest against the fake App, as the other `u` scenarios run. Moves: the D checks that the PR names (rule 8).

**U378 the user picks a Model when adding an Agent, and changes it on a running row.** Narrows U191 (the `+ agent` add) and U56 (the row menu); uses `agent.spawn`, `agent.setModel` (A36, A37); no new App seam command and no Token.
- **At the add.** The `+ agent` line's add gains an optional `model…` disclosure with Model and Effort selects (as U377's, `default` first). Left alone, `agent.spawn` is called with `model: null` and `effort: null`, exactly as before. Picked, the call carries them. Asserted in `u378_the_add_passes_nothing_unless_picked`, `u378_a_picked_pair_goes_in_the_spawn_call`.
- **On a running row.** The row menu of a running Agent offers `model…` (an exited row's menu offers it too and stores only, A37). It opens the same two selects, set to the Agent's pair, and an `apply` button, disabled until the pair differs. Asserted in `u378_apply_is_disabled_until_the_pair_changes`.
- **One confirm.** `apply` opens one confirm, not two, whose text names the Agent, the new Model's label and says it re-reads its conversation on the new Model and that this spends more of the user's usage than a normal turn (policy wording, read in review); its buttons are `change` and `cancel`, focus starts on `cancel`, `Esc` cancels. `change` calls `agent.setModel` once with `confirmed: true`; `cancel` calls nothing. A failure shows U80's line and the row keeps its pair. Asserted in `u378_apply_opens_one_confirm_that_names_the_model_and_the_reread`, `u378_change_calls_set_model_once_with_confirmed`, `u378_cancel_calls_nothing`, `u378_a_failure_shows_the_error_line`.
- **Keeps the row.** After a change the row keeps its name and place, and its Status follows the Agent's new Attempt as for any resume (A22, U68). Asserted in `u378_the_row_keeps_its_place_after_a_change`.
Tests (`u378_`) are Vitest against the fake App. Observer for the whole Issue: A36, A37 and M12's real-Daemon tests with the fake `claude`; the user's Mac is not needed.
