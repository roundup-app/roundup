**U7691a a note starts from an item.** Given the open view, a lens fixture and the fake App, then:
- **Which rows.** A row of Modules, Logic or Tests takes a module note; a Flows row (a flow of a trace, or one the readback added, U7689) takes a flow note; a file, in its row or under its header in a scroll, takes a file note, a noise file too. The Overview, Unplaced, Not traced and the generated and lockfile rows take none: no note on the whole change. Decided here, as the Issue's reading that a module or flow is an item the lens lists (#7679, #7683). Asserted in `u7691a_the_rows_that_take_a_note_and_the_ones_that_do_not`.
- **The icon.** The item's header holds an icon button named "Note on module", "Note on flow" or "Note on file", with no visible text; the file's header holds "Note on file". It opens the form under the header, with focus in its field. Asserted in `u7691a_the_header_icon_opens_the_form_under_the_header`.
- **The key.** N with focus on a list row opens that row's form, from a module, flow or file row alike; N with focus in the diff stays a line note (U7676b), and N does nothing in the Overview or on a row that takes no note or while a field, text input or the editor holds focus. The ? list gains "In the list, N notes the module, flow or file." Decided here: the Issue left the key to this run, and N is free on a list row. Asserted in `u7691a_n_in_the_list_opens_an_item_note_and_n_in_the_diff_a_line_note`, and for the typing guard in `u7691a_the_form_has_a_label_and_no_lines_or_replacement`.
- **The form.** The field has the note's text and #7690's Label group of three toggles; it has no Side, Start line, End line or replacement field. Save, or ⌘↵, stores the note under the header; blank text cannot be saved. Asserted in `u7691a_the_form_has_a_label_and_no_lines_or_replacement`.
- **Typed text stays.** Esc with typed text, or a switch to another item or file, keeps the text, label and item, and the note's field shows them when it is reopened with the icon or N; a restart restores them (P11, U2773a). No row says "Unfinished work" and no mark shows it (U7978a). Asserted in `u7691a_esc_keeps_typed_text_and_a_restart_restores_it`.

**U7691b an item note goes in the batch and the Message.** Given the fake App, then:
- **Batch.** The notes bar (U7676d) counts an item note with the line notes, and its list shows the item's kind, name and file count where a line note shows its range, with Edit and Remove. Remove offers Undo for 5 s (U7676d). Asserted in `u7691b_the_bar_counts_an_item_note_and_its_list_names_the_item`.
- **Message.** One Message holds a line note and a module, a flow and a file note, in batch order. An item note's entry holds `"Group:"` (its `kind`, `name` and `files`) in place of `"Lines:"`, with `"Content revisions:"` (each file's `blob`), `"Label:"` only when set and `"User comment:"`; it holds no `"File:"`, `"Base:"`, `"Lines:"` or `"Selected source:"`. A line note's entry is as U2540c and U7690 say; a line note made inside the module's scroll keeps its file, side and line. Paths and names are data, never commands. Asserted in `u7691b_one_message_holds_line_and_item_notes_with_a_group_line`.
- **Sent.** After an accepted send each item note stays, marked "Sent HH:MM", and is never sent twice (U7677e); a note added meanwhile stays unsent; no note gates Landing, Send or a Message (U2540d). Asserted in `u7691b_a_sent_item_note_stays_and_is_never_sent_twice`.
- **Stored.** An item note and its form are stored as their own variants: records saved before this order restore unchanged. Asserted in `u7691b_records_saved_before_item_notes_still_load`.

**U7691c an item note reads Outdated by the blob.** Given a Sent item note, the fake App and a write of the Agent, then:
- **Blob.** A line note's source text is its signal (U7677e); an item note has none, so it reads "Outdated" and folds to one line when any file it recorded now lists another `blob` (#7673, as U7680d reads it) or no longer lists. A write to another file leaves it Sent. An unsent note reads "Not sent", never Outdated, as a line note does. Show all opens it. Asserted in `u7691c_a_write_to_a_file_of_the_item_turns_a_sent_note_outdated_and_an_unrelated_write_does_not`.
- **Left.** A file the change no longer lists counts as a changed blob. Asserted in `u7691c_a_file_that_leaves_the_change_turns_a_sent_note_outdated`.
- **Flows.** A flow note also reads Outdated when a finished trace no longer holds its entry point (its name, `~flow:<entry>`, is not in the Flows list), and one on a flow the readback added when a readback no longer names it; before any trace or readback finishes it reads as its blob says. Decided here, as the Issue's reading. Asserted in `u7691c_a_flow_note_reads_outdated_when_a_new_trace_or_readback_drops_its_flow`.

**U7691d an item note shows where its item is.** Given the lens fixture and the fake App, then:
- **Under the header.** A saved item note sits under the header of the item it names: its module in Modules, Logic and Tests (modules regroup files: the note follows the module's name, never one lens's files), its flow in Flows, its file under the item whose scroll holds the file in each lens; Edit and Remove act on that note only. An item the open lens does not list shows it nowhere there. Identity is the item's `name` (`~flow:<entry>`, `~read:<id>`), never the label a readback can rename. Asserted in `u7691d_a_note_follows_its_module_across_lenses_and_its_flow_in_flows`.
- **The row.** An item's row counts its item notes, in its name for assistive tech and as a count beside its counts; a file note counts on the row of each item that holds the file. It counts item notes only: line notes keep U7679b's mark. Asserted in `u7691d_the_row_counts_its_item_notes`.
- **The list.** The G list (U7690c) holds every item note, in any state, in file order by its first file, before the line notes of that file; Enter opens its first file the lens lists, as U7679b's jumps do, and a note none of whose files the change lists says "No longer changed" and cannot be chosen. Asserted in `u7691d_the_jump_list_holds_item_notes_and_opens_their_first_file`.

**Amended.** U2540b ("Notes retain file paths…"): a note's target is a line range or an item (a file, module or flow), and an item note retains its kind, name, files and each file's blob. U2540c ("its plain-text body includes every note… `Lines:`"): an item note's entry holds `Group:` in place of `Lines:`, U7691b says which keys. U7676d ("The bar counts…"): the bar counts item notes. U7679b ("Marks"): an item's row also counts its item notes (U7691d). U7690c ("The list holds every note"): the list holds item notes. U7675e ("The ? list"): N in the list is listed. Kept: line notes, their original context and one Message per batch (U2540b, U2540c); no note gates Landing (U2540d); #7676's keys in the diff; U7690's label, and its replacement for line notes only.

Not wanted: a note on the whole change or the repository; a new Daemon method; a text button for an action; Plannotator (plannotator.ai) as the review surface, rejected by the owner, 2026-11-18. No test of layout or looks.
