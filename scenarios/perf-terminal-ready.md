**R3841a every Terminal-driving perf run shares setup.** Given a perf run creating a Workstream, when its selected row appears before its Agent Terminal input, then it opens no shell bubble until that Agent input exists; after it appears, the run opens the shell once and proceeds only with that shell's input and readiness. Assert ordering, one shell-open action and the selected shell identity in planned `r3841a_terminal_setup_waits_for_agent_before_opening_shell`, exercising both keystroke and frame entry points with delayed Agent input through the existing App/DOM seams. The Agent program need not print `ready`, become idle or answer a Model request.

Policy: one shared Terminal-ready operation owns this sequence and its bounds. Every perf driver that opens or types into a Terminal uses it, including all frame workloads and the native compatibility probe. Inventory callers on the implementation head, migrate them together and delete their per-run setup/readiness copies; do not create a second helper wrapping the old copies. Idle observation that drives no Terminal needs no readiness wait. Review the call graph; add no test that rereads source text to enforce sharing.

**R3841b readiness survives a late bubble.** Given the run's shell prints a complete `ready` line and starts the 64 KiB/s stream before its bubble/emulator opens, when the shared wait runs and that shell's input becomes available, then setup completes for that shell without another `ready` emission, without restarting its program and without waiting for new output containing `ready`. The same result holds when `ready` arrives after opening. Planned `r3841b_ready_before_or_after_bubble_open_releases_setup` asserts both orders through the shared operation and existing Terminal output/read seams, including a late screen snapshot that no longer contains the scrolled-away line. Exercise the actual readiness implementation, not a stubbed successful wait. No test needs a process or real clock for these orderings.

**R3841c readiness belongs to the measured shell.** Given an Agent Terminal and the run's shell with different ids and inputs, when output is delivered in split chunks or recovered from retained output, then only the shell's complete `ready\n` or `ready\r\n` line releases setup. An Agent's `ready`, `already`, `not ready`, `readying` and an incomplete `ready` do not release it. Keys and the eventual `PERF` or `FRAMES` report address that same shell exactly once; an earlier Agent input or later Terminal creation cannot redirect them. Planned `r3841c_only_the_measured_shell_can_release_setup_and_receive_report` asserts identities, writes and one continuation across live/retained overlap. Retain the unique split-line and parsed-output proofs in Check 3; extend them rather than duplicate them, naming any replacement when editing their test file.

**R3841d missing readiness stays an observer failure.** Given the Agent input never appears, the shell input never appears, or no complete shell `ready` is available, when the existing setup bound expires, then the workload performs no measured actions or keystrokes and reports the failed setup step. Planned `r3841d_missing_readiness_stops_before_workload` uses fake time to assert each case, rejection and zero workload calls. Policy: retain the existing runner's bounded exit 2 and collection diagnostics when no report Terminal is available; preserve Check 4's raw-output/log evidence and tests. Do not synthesize readiness, lengthen bounds to conceal the race, or turn an invalid/unmeasured run into a timing pass.
