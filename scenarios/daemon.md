# Daemon

Module: `crates/rupd` (D1, D7); end-to-end tests in `crates/rup/tests` (D2–D7). Ids: every `D` heading in the file.

D1 and D7 are in `crates/rupd`. D2 to D7 are end-to-end tests of the whole Daemon. They live in `crates/rup/tests`, the only package whose tests can run both the Daemon (a dev-dependency) and the built `rup` binary that hooks and MCP servers call (`CARGO_BIN_EXE_rup`). They run without `claude`: a fake `claude` named by `ROUNDUP_CLAUDE_BIN` plays recorded hook payloads from `spikes/hooks-state/log*.jsonl`. `CLAUDE_CONFIG_DIR` points at a temp dir, so no test ever touches the user's `~/.claude.json`.

**D1 attached.** Given `rupd <project> --attached`, when its stdin closes, then it exits within a bound the test names, and every program it started in a Terminal is gone. Without `--attached`, a closed stdin changes nothing; CI starts `rupd &` with no stdin. The App passes `--attached`, so no Daemon and no Agent outlives the App, even when the App crashes.

**D2 Status end to end.** Given a Daemon whose fake `claude` feeds these hook payloads, in order, to the hook command in its `--settings` file: `SessionStart`, `UserPromptSubmit` (prompt "fix the refresh race"), `PermissionRequest`, `PostToolUse`, `Stop`. `ROUNDUP_RUP_BIN` is the built `rup`. When a subscribed client calls `agent.spawn`, then it receives that Agent's `agent.status` Kinds `idle, working, needs-you, working, idle` in order, and `rail.tree` names the Agent `fix-refresh-race` (A9).

**D3 Todos over MCP end to end.** Given the same Daemon with a fake `claude` that starts the `roundup` server from its `--mcp-config` file and calls `todo_create {title: "split checkout"}` over it, then `todo.list` holds that Todo and `provenance.history {item: "todo:1"}` names that Agent.

**D4 ten idle Agents.** Given ten Agents whose fake `claude` sends `SessionStart` and then sleeps, then the Daemon's resident memory grows by less than 150 MB. This is rule 7's budget for roundup's own share; the real `claude` programs are measured on the laptop at the MVP gate. The test prints the number it measured, for the gate report. Every Agent reaches Idle within one bound of 30 s for all ten together, measured from the first `agent.spawn`; a miss is not a pass, and its failure output names the Agents that were not Idle and each Agent's last status, so a lost event can be told from a slow Daemon. The bound covers only the ten `SessionStart` hooks reaching the Daemon, not the machine's load; a test that passes by waiting longer is not a fix.

**D5 no program outlives the Daemon, children included.** Given `rupd <project> --attached` with an Agent whose fake `claude` starts a background child that writes its pid to a file, and a Terminal whose shell does the same, when the Daemon's stdin closes, then the Daemon exits within D1's bound and the fake `claude`, the shell and both children are gone, checked by pid. Without `--attached` the same close changes nothing, as in D1. Owns `crates/rup/tests/e2e/**`, with fixes in `crates/rupd/**` or `crates/terminal/**` only if it fails today. Stacks after D1 and A17; it keeps `d1_attached` tests green and narrows none.

**D6 a Daemon killed without warning leaves a Project that reopens whole.** Given a Daemon with a Group, two Agents, a Terminal (an Agent's own), three Todos where Todo 2 is blocked by 1, and two Pads (one owned by an Agent, one by the user), when its program is killed with SIGKILL and a new Daemon starts on the same Project folder, then `rail.tree` has the same node ids, names, parents, `order` values and `meta` flags, every Agent is `done` with `terminal_id: null` (A8, A12), `terminal.list` holds no Terminal (X11), `todo.list` has the same three Todos with the same blockers and `done` state, `pad.list` the same Pads with the same owners and text, `provenance.history` still names the Actors of the earlier writes, and the next `todo.create` returns id 4. Owns `crates/rup/tests/e2e/**`. It keeps A8, T5, P7 and A12 green and narrows none; a failure here is fixed in the module that loses data, never by the test.

**D7 a store that cannot be read stops the Daemon, loudly.** Given a Project whose Rail, Todos or Pads file is truncated to a few bytes of garbage, when `rupd <project>` starts, then it exits with a non-zero status within a bound the test names, writes one line to stderr naming that file, accepts no connection, and leaves the file's bytes exactly as they were: it is never replaced with an empty store. A Project with none of the files starts as today. The App shows the Daemon's failure as it does for any exit (S3); D7 asserts only the Daemon's side. Owns `crates/rupd/**` and `crates/rup/tests/e2e/**`; if the failure sits in a module's `open`, that module's crate carries the fix and its test names D7.

**D8 where a Project's application data lives.** Given `rupd <project>` (or the App opening the Project, which starts it the same way), then the Daemon keeps its application data in the Project data folder, outside the Project folder, and writes into the Project folder only what G2 and P5 name.
- The Project data folder is `<data root>/projects/<key>/`: every module's database with its `-wal` and `-shm`, and `agents/` with each Agent's `<id>.settings.json`, `.mcp.json`, `.brief.md` and `.bin/` (A11, E1, F4). `<key>` is the first 16 hex digits of the SHA-256 of the Project's canonical path; the folder holds `project.json` with that path (test `d8_the_key_is_the_canonical_path_hash`, which opens the Project by a symlink and by its real path and finds one folder).
- `<data root>` is `$ROUNDUP_DATA` when set; otherwise the App's `app_data_dir` (`~/Library/Application Support/dev.roundup.app` on a Mac, the folder `crates/desktop/src/store.rs` already uses), and for a Daemon started without the App the same folder by the same rule, so the App and `rupd <project>` find one Project's data in one place. The App passes `ROUNDUP_DATA` in `crates/desktop/src/daemon.rs`, which is the only caller (test `d8_the_app_and_a_bare_daemon_share_one_data_folder`).
- `<Project folder>/.roundup/` is made only by G2 and holds only `worktrees/agent-<id>/`; G2's placement, its `.git/info/exclude` line and A4's trust rule are unchanged (policy, the user's decision of 2026-10-10 in #749).
- `~/.roundup/rupd.sock` stays where it is (`rpc::socket_path`): it is one file in a hidden folder of the home folder, never in a Project, and a Unix socket path is limited to 104 bytes on a Mac, which `Application Support/dev.roundup.app/projects/<key>/` would exceed (policy).
- A Project folder that is moved or renamed has another canonical path, so it opens as a new Project with new data; the old data folder is left whole, never deleted, and `project.json` still names the old path (test `d8_a_moved_project_opens_new_and_leaves_the_old_data`). Re-pointing is not specified.
- Pad files are the exception (P5): `<Project folder>/roundup-pads/`, only with file storage on.
Owns `crates/rupd/**`, the path functions in `crates/agents/**`, `crates/desktop/src/daemon.rs` and the docs named in D12. A `crates/desktop` change needs the user's `just app` on a Mac (`.agents/data/pr.md`).

**D9 opening a Project writes nothing into it.** Given a real Daemon, the fake `claude` (A4) and a Project that has a tracked file, an ignored file and a dotfile, when the test opens it, spawns an Agent, starts a Door (A7), writes a Todo and a Pad, then stops the Daemon, then with `worktrees` off (the default) the Project folder's recursive file list outside `.git/`, hidden files included, with each file's bytes, equals the list before open, `git status --porcelain` prints nothing, and `.git/` gains nothing (test `d9_a_git_project_with_worktrees_off_gains_nothing`). With `worktrees` on the only new paths outside `.git/` are `.roundup/worktrees/agent-<id>/`, one per Agent with a Worktree, `.roundup/` holds nothing else, `git status --porcelain` prints nothing, and the only changes in `.git/` are G2's (`info/exclude`, `worktrees/agent-<id>/`, the `roundup/agent-<id>` branch's ref and reflog; test `d9_a_git_project_with_worktrees_on_gains_only_its_worktrees`). On a folder that is not a git repository the Project folder gains nothing (test `d9_a_folder_that_is_not_a_repository_gains_nothing`). With `pad.setStorage {files: true}` the only new path is `roundup-pads/<name>.md` per Pad (test `d9_file_storage_writes_only_the_pad_files`). Owns `crates/rup/tests/e2e/**`; a failure is fixed in the module that writes the path, never by the test. It keeps D6 and G6 green and narrows none.

**D10 an old `.roundup/` gives up its application data.** Given a Project with a `.roundup/` seeded as D6 seeds one (Group, two Agents, a Terminal, three Todos, two Pads), one Agent with a Worktree at `.roundup/worktrees/agent-<id>` holding an uncommitted file and a commit, and a Pad file in `.roundup/pads/`, when `rupd <project>` starts, then before it accepts a connection:
- everything D6 lists is whole, as D6 asserts it; the Agent's `rail.tree` `worktree.path`, branch and base, the Worktree's uncommitted file bytes and its commit, and `git worktree list` are the same as before, and the Agent resumes (A24) from the Worktree where it was (test `d10_the_old_state_opens_whole`);
- the Pad file is `<Project folder>/roundup-pads/<name>.md` with the same bytes, and Pad storage is still files (test `d10_pad_files_move_to_the_project_folder`);
- `<Project folder>/.roundup/` holds only `worktrees/`, untouched, and `.git/info/exclude` is the same bytes; a `.roundup/` with no Worktree in it is removed, and a Project that never had one is left as it was (test `d10_the_old_folder_keeps_only_its_worktrees`);
- a second start changes nothing (test `d10_a_second_start_changes_nothing`).
The move is staged: databases are copied with SQLite's backup into `<key>.moving/`, then `<key>.moving/` is renamed to `<key>/`, and the old files are removed last, so a Daemon killed with SIGKILL at any step leaves the old `.roundup/` the truth and the next start redoes the move from it (test `d10_a_kill_mid_move_is_redone`). A Project with a `.roundup/` and an existing data folder uses the data folder and leaves the `.roundup/` untouched. Owns `crates/rupd/**` and `crates/agents/**`.

**D11 a failed move leaves the old state whole and says why.** Given D10's Project, when a step fails (failures are an unwritable data folder and a Pad file that cannot be written; a Worktree is never touched), then the Daemon exits non-zero within D7's bound with one line on stderr naming the step and the path, accepts no connection, `<Project folder>/.roundup/` is the same bytes as before, and `<key>.moving/` is removed. The App shows the line as it shows any Daemon exit (S3). The next start, with the cause removed, completes the move (tests `d11_an_unwritable_data_folder_leaves_the_old_state`, `d11_an_unwritable_pad_folder_leaves_the_old_state`, `d11_the_next_start_completes_the_move`). Owns `crates/rupd/**`.

**D12 the text that names `.roundup/` changes with it.** Given D8 to D11, then, in the same PR that implements them and with every caller changed (rule 4), `docs/architecture.md` (Data), ADR 0004 (a dated amendment, not a rewrite), `docs/worktrees.md` (Setting) and `docs/messages.md` name the Project data folder and `roundup-pads/`, and `grep -rn '\.roundup' scenarios docs crates GLOSSARY.md` finds no use as the home of databases, launch files or Pad files (G2's Worktrees, `~/.roundup/rupd.sock`, and the migration code and its tests remain; test `d12_no_text_names_a_project_roundup_folder_for_data`, a `just check` rule; policy for the docs' wording). `GLOSSARY.md` holds **Project data**; `loop/rules.sh vocab` passes. Owns the docs only; no RPC method, event or `contracts/` type changes: the Daemon's start gains the `ROUNDUP_DATA` environment variable and no argument.
