# UI: the Changes header warns when the remote's main has moved and fetches on a click (U7693a–U7693d)

Module: `crates/contracts`, `crates/agents` (the `Git` runner), `crates/rupd` and `contracts/generated/` (U7693a, U7693b); `apps/desktop/src/changes/`, `apps/desktop/src/state/` and the fake App (U7693c, U7693d). Ids: U7693a, U7693b, U7693c, U7693d. Work order: [#7693](https://github.com/roundup-app/roundup/issues/7693), blocked by #7675. Owner, 2026-11-18, picked "Remote main moved" from the Plannotator audit: warn when the remote's main has newer commits than the repository fetched, and fetch them on one click. #7672 compares the Agent's work with the remote's main (`scenarios/ui-changes-remote-main.md`), and a main the repository has not fetched can mislead that comparison.

Contract change (rule 4): the redesign's "no new Daemon method" cannot hold here, so two methods are new. `agent.remoteMain` takes `id` (as `agent.changedFiles` does) and answers `RemoteMain`, a `kind` of `none`, `current` or `moved`. `agent.fetchRemoteMain` takes `id` and answers `FetchedMain` with `commits`. Both act on the Agent's repository, its own Worktree's, else the Project folder's, and both fail with the code `remote_unreachable` and git's cause in full. `GLOSSARY.md` gains the rows **Remote main** (user label "Remote main") and **Fetch**; `contracts/generated/` is regenerated, never hand-edited; every caller changes in the implementation PR: the fake App, `crates/rupd/src/route/policy.rs` (a row each, user only) and `crates/contracts/src/declarations.rs` (`none("…")` for both, so M5 and `scenarios/mcp.md`'s "No tool" list gain them with the reason). Observer: Rust tests on Linux against temporary git repositories with an origin for U7693a and U7693b; Vitest against the fake App for U7693c; the isolated Chromium harness (U26) for U7693d. Never a native Mac capture. Size: about 1,000 changed lines (Contract 250 with the generated files, Daemon 250, App 150, tests 350), inside `.agents/data/work.md`'s about 1,000 for an API change with all its callers. It is one PR: a Daemon half alone would leave two new methods with no caller. If the build run counts more, it asks (`flag:needs-user`), as the Issue says, and opens no partial PR.

Reuse (rule 9), selected: the `Git` runner (`crates/agents/src/worktree/command.rs`), because `git` reads the owner's own credential helpers and ssh config unchanged, stores and passes no token (as A5168d does for `gh`) and runs on the Project's Machine (MC30). Rejected: `git2` 0.21.0 (MIT OR Apache-2.0, 2026-05-18, <https://crates.io/crates/git2>), which `crates/agents` takes with `default-features = false`, so it has no `https` or `ssh` transport; the two features add a TLS and an SSH stack to a Daemon held under C9b's 15 MB (`scenarios/perf.md`), libgit2 asks for credentials through callbacks the Daemon would have to feed, and it opens the repository in the Daemon's own process, which cannot reach a folder on another Machine. `gix` 0.90.0 (MIT OR Apache-2.0, 2026-10-22, <https://crates.io/crates/gix>): the same in-process limit for a Machine's folder, and a network client with the same credential plumbing to build for what `git ls-remote` already answers. Versions and dates read from crates.io on 2026-11-20; verify them again in the implementing PR.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

**Words.** The remote's main is the remote's default branch as the repository last fetched it, the target of `refs/remotes/origin/HEAD` (U7672a's From). `<default>` is that branch's name. A test asserts the App's words through `copy.ts`, never layout or looks (rule 10).

**U7693a `agent.remoteMain` says whether the remote's main has moved.** Given a repository with an origin and an Agent whose repository it is, then:
- **Moved.** One `git ls-remote origin refs/heads/<default>` gives the remote's commit id for `<default>`; the call compares it with the local `refs/remotes/origin/<default>`: equal answers `current`, different answers `moved` (a force push moves it without a descendant). It fetches nothing and counts nothing: `ls-remote` gives an id, not a count, and no `gh api` call is made. Asserted in `u7693a_a_commit_pushed_after_the_clone_reads_as_moved_and_an_unmoved_remote_as_current`, which also asserts the next clause.
- **None.** A repository with no `origin`, or whose `origin/HEAD` is unset (so From is the local default branch, U7672a), answers `none` and runs no network call. Asserted in `u7693a_no_origin_or_no_origin_head_answers_none_and_runs_no_network_call`.
- **Read-only.** After a call the refs, index, working files, `FETCH_HEAD` and config are as before.
- **Unreachable.** A remote that fails, or that does not answer within 5 s, fails with `remote_unreachable` and git's cause in full (U80), never shortened. The test shortens the limit to 300 ms. Asserted for both methods in `u7693b_both_calls_fail_with_their_cause_and_a_failed_fetch_changes_nothing`.
- **Never prompts.** Every call runs with `GIT_TERMINAL_PROMPT=0` and ssh in batch mode (`BatchMode=yes` added to the owner's ssh command), so a remote that asks for a password or passphrase fails with that cause and never waits at a prompt. Asserted with the next clause in `u7693a_no_call_prompts_or_blocks_another_git_read`, with a `git` on the test's `PATH` that records its environment.
- **Not the runner's lock.** Neither method holds the `Git` runner's serialising lock (`Git::hold`) while it waits on the network: an `agent.changedFiles` for the same Project, made while an `ls-remote` or a fetch is in flight, answers without waiting for it. Asserted for both methods in the same test, the `git` on the test's `PATH` also sleeping on `ls-remote` and `fetch`.
- **Machine.** For a Project on a Machine (MC30) both methods run on it through the runner's Machine path, with that Machine's own git credentials. Asserted in `u7693a_both_calls_run_on_the_projects_machine`, with the fake exec of `remote_tests.rs`.
- **The user's.** An Agent actor calling either method is refused with `FORBIDDEN` and no git command runs; both are declared `none("…")`, so `rup mcp` `tools/list` does not gain them (as C7707e). Asserted in `u7693a_an_agent_call_is_refused_and_the_tool_list_does_not_move`.

**U7693b `agent.fetchRemoteMain` fetches the remote's main and nothing else.** Given the repositories above, then:
- **What it writes.** It fetches `refs/heads/<default>` into `refs/remotes/origin/<default>` alone: no other branch, no tag, no config, no `gc`. A commit pushed after the clone is in the repository afterwards and `origin/<default>` reads it. Working files, the index, HEAD, branches and the Agent's folder are as before: no pull, merge or rebase. Asserted with Count in `u7693b_fetch_updates_only_the_remote_main_ref_and_counts_the_commits`.
- **Count.** `commits` is the number of commits the fetch brought onto the remote's main: reachable from its new tip and not from the tip before; 0 when nothing moved, 1 after one push. It counts what was fetched, never how far the Agent's own branch trails, which needs no HEAD and gives the chip one meaning. Asserted in the same test.
- **Stale ref.** Given an Agent whose branch holds a newer main than the repository fetched through `origin` (it fetched it by URL, so `origin/<default>` stayed behind), Tree and Branch (U7672a) list that remote commit as the Agent's change and `agent.remoteMain` answers `moved`; after the fetch neither lists it. Asserted in `u7693b_after_a_fetch_the_comparison_stops_listing_others_commits`. The premise was checked on a temporary repository in the specify run: a fetch through `origin` updates the ref at once, so the test fetches by URL.
- **Fails whole.** A fetch that fails, or that does not finish within 60 s, fails with `remote_unreachable` and git's cause, leaving refs and files as before. The test shortens the limit to 300 ms. Asserted in `u7693b_both_calls_fail_with_their_cause_and_a_failed_fetch_changes_nothing`.
- **Same rules.** The never-prompts, not-the-runner's-lock, Machine and user-only clauses of U7693a hold for this method and are asserted there for both.

**U7693c the header chip warns on a moved main and fetches on a click.** Given the Changes header (U7672c, U7674b) and the fake App, then:
- **One read, after the first state.** After the view's first state draws (U7674e: a diff, an empty list or a failure) the App calls `agent.remoteMain` once for the Agent; no key waits for it, and a late answer for an earlier Agent never shows under another (U2540a). Asserted in `u7693c_opening_reads_once_waits_for_no_key_and_a_late_answer_never_crosses_agents`.
- **States.** One chip sits beside the quiet From label. While checking it shows nothing until 150 ms, then "Checking remote main"; `current` and `none` show nothing and no Fetch (no remote: From is the local default branch, U7672a); `moved` shows "Remote main has moved" and Fetch; while fetching Fetch is busy and says "Fetching"; after a fetch it reads "Fetched N new commits on main" ("Fetched, nothing new" for 0) until the view closes; a failure reads "Couldn't reach the remote", the cause in full and Retry, which repeats the call that failed. The chip is the From label's and speaks for the same repository, the Agent's own (U7672c: one From label for the whole header), whichever group Changes shows; no group has a chip of its own. Asserted, with one and with two groups, in `u7693c_the_chip_draws_each_state_in_plain_words`.
- **Only the click fetches.** `agent.fetchRemoteMain` is called by Fetch alone: not on open, on a timer, on an Agent's write (U5558c's refresh) or by a key; and `agent.remoteMain` is called once per open of the view for an Agent, not per refresh, switch value or file. Asserted in `u7693c_only_the_click_fetches_and_opening_reads_once`, with fake timers.
- **Compares again.** After a successful fetch the view lists the shown switch value again and reads the open file again, once; the click is the user's, so #7675's "never reloads by itself" (U7675b) about the Agent's writes does not apply. The list moves under the reader without moving it (U7675c), and a saved note keeps its original context (U2540b). Asserted in `u7693c_a_fetch_lists_again_and_reads_the_open_file_once`.
- **Keyboard.** Fetch is a button in the header's tab order. No key fetches in this order (R, reserved by #7675, is not used here). Asserted in `u7693c_fetch_is_reachable_by_tab`.
