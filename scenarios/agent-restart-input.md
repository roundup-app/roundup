# Surviving Attempts retain their first-input boundary (A5717)

Acceptance for #5717. Completes the composition of A12a owner recovery, A5556 first-input admission and B5551a receiver recovery. Reattaching a verified surviving Attempt is not a fresh start or an explicit resume/restart (policy). No new RPC, Message kind, delivery status or automatic start is required (policy).

## Checks on main

1. `crates/agents/src/owners.rs`, `Agents::reattach_owners` and `Agents::reattach`: verify the saved Agent, Attempt and owner, then attach without launching a replacement; the reconstructed Run currently sets `input_started` to false.
2. `crates/agents/src/events.rs`, `Shared::apply`: `UserPromptSubmit` marks the running Attempt as having received input. `crates/agents/src/store.rs`, `Agents::admit_input`: authenticated explicit input opens automatic admission through the existing Status lane.
3. `crates/messages/src/inbox.rs`, `NoteInbox for agents::Agents` (`admits`, `submitted`) and `send`: user Messages may supply input; non-user Messages require the receiver's input boundary to be open, and physical writes retain the in-flight/receipt boundary.
4. `crates/messages/src/tests/b_resume_tests.rs`, `b5551a_messages_wait_for_a_surviving_agents_status`: a reopened Message store preserves pending Messages until finite Status and eligible idle, but its fixture does not exercise production first-input admission.
5. `crates/agents/src/spawn.rs`, `a5556c_start_paths_require_explicit_input`: fresh starts and explicit resume/restart reject automatic input while accepting explicit user input.
6. `crates/agents/tests/owner_reopen.rs`, `a5335a_two_restarts_keep_every_live_child` and `a5335d_reopen_keeps_each_launch_count_at_one`: repeated recovery keeps live children without another launch.

**A5717a a surviving Attempt keeps admission after explicit input.** Given an Agent running under a verified Terminal owner, whose Attempt has received explicit input, and eligible pending automatic Messages, when the Daemon is lost without attached shutdown, Agents and Messages reopen, the same owner reattaches and the retained program reports `Stop`, then at eligible idle the pending automatic Messages reach its inbox without another user input, new `SessionStart`, replacement program or Terminal write. Repeating the loss/reopen/reattach/idle sequence preserves this result for that same Attempt.

Observer: new `a5717a_surviving_attempt_retains_automatic_message_admission` in `crates/rupd/tests/`. Parameterize prior explicit input through (a) `SessionStart` followed by the user's Terminal `UserPromptSubmit`, (b) an authenticated user Message physically delivered through the production inbox path, and (c) an explicit creation prompt. Persist and reopen the actual Agent and Message stores twice against the surviving owner. After each reopen, assert the same Agent, Attempt, conversation and owner incarnation, exactly one live Terminal, unchanged launch count and zero recovery/Message Terminal writes. Queue distinct peer Messages, a Digest and an already-accepted Daemon Note before loss and after reattachment; use the existing Message envelope for the latter two, without creating new producer machinery. At completed eligible idle, assert the eligible batch reaches the inbox in Message-id order with original ids, bodies, senders and receiver, remains pending with in-flight records before transcript receipts, and becomes delivered once per id only on those receipts. A later idle and repeated receipts neither resend those entries nor emit another delivery. This rejects the current reset-to-false recovery and any repair that preserves only Terminal-submitted input but forgets explicit inbox or creation input.

Policy: B8/B39/B40/B50 still govern an entry already in flight at loss: recovery retains its original id and receipt/replay semantics; admission restoration neither invents a receipt nor clears or duplicates its durable record. Existing B40/B52 observers hold replay coverage; do not add a second queue or duplicate their transport tests. Previously delivered or dropped Messages stay final. Routes, permissions, readiness and Attempt eligibility continue to apply; retaining prior input alone never bypasses them.

**A5717b a surviving Attempt with no explicit input still waits.** Given the same owner recovery with an Attempt that has never received explicit input, when startup readiness, reattachment and repeated idle observations complete across two Daemon losses, then automatic Messages remain pending under their original identities, no inbox or Terminal input is delivered, and no replacement program starts. When the user then supplies explicit input, that input is accepted and eligible pending automatic Messages may follow it at eligible idle, without another start; they never precede it.

Observer: new `a5717b_surviving_attempt_without_input_keeps_waiting` in `crates/rupd/tests/`, using the same production composition as A5717a. Drive `SessionStart` without `UserPromptSubmit`, queue the same automatic sender classes and reopen twice. Assert zero writes after completed readiness/idle operations, retained Message identities and pending states, unchanged Attempt and launch count. Then deliver one authenticated user Message, assert it is physically written once before any automatic entry, and complete idle/receipt processing to assert normal delivery of the queued ids. This rejects unconditional admission of every reattached owner and counting readiness, stored intent or idle as explicit input.

**A5717c an explicit resume or restart keeps the conversation admitted.** Given an Agent whose earlier Attempt received explicit input, when the user explicitly resumes or restarts it, then the conversation stays admitted (U6260b) and the user's next input is written; an unrelated fresh Agent starts with its own closed boundary. A supplied fresh prompt/order still counts under A5556a.

Observer: extend `a5556c_start_paths_require_explicit_input` in `crates/agents/src/spawn.rs` with an earlier admitted Attempt before the resume/restart cases and a separate fresh Agent. Assert production automatic admission is false and explicit user admission remains possible for each new start. This rejects retaining input as an Agent-wide permanent permission. Keep the existing fresh Door, direct Agent at either Home and Mode-without-opening-prompt rows; no duplicate start-path test is required.

## Observer and regression policy

A5717a/b must compose production `Agents::open`, verified `reattach_owners`, input observations, `Messages` reconciliation/delivery and the `NoteInbox for agents::Agents` admission decision. A fixture that defaults `admits` to true, copies its predicate, sets the recovered input flag directly or replaces owner recovery with a synthetic Rail node cannot prove these clauses. A recording transport may stand in for the vendor inbox only if the production admission and submitted-input decisions still run. Use completed lifecycle/reconciliation/receipt operations as synchronization, not sleeps or an uncompleted background task as evidence of no delivery. A real isolated Terminal owner and fake vendor program are justified here by survival/reattachment and launch/write counts; no real vendor, display or user's Mac is needed (policy).

Implementation scope is existing owner/input persistence and lifecycle seams in `crates/agents/**`, production admission in `crates/messages/**` if needed, and composition observers in `crates/rupd/tests/**`. Prefer extending the current persistence and test fixtures; a new queue, scheduler or protocol is outside this work order (policy). The implementation follows rule 9 for any new machinery and the Contract recipe for a contract change (policy).

Keep A12a (`scenarios/agents.md`), A5335a/A5335d (`scenarios/daemon-restart-children.md`), A5556a–c (`scenarios/agent-lifecycle.md`) and B8/B9/B39/B40/B50/B5551a (`scenarios/messages.md`) unchanged. This specification narrows neither first-input protection nor receipt/replay behavior (policy).
