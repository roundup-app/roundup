# UI: motion contract

Acceptance for the motion specification and dependent product work. This file specifies behavior and evidence; it claims no implementation, visual improvement or performance result. Existing App/fake-App and U26 rendered observers are the seams. No RPC, renderer, loop or permission change is authorized.

## Specification

**U3010a one current motion contract.** Given the accepted scenarios, when motion work is commissioned, then `docs/motion.md` is the single inventory of accepted surface/source/purpose/family/preset/exit/acceptance rows, with retired/deferred ideas separate (policy). Preserve U2580a's immediate key-driven layers, including Enter/Space during pointer motion; U2579a's shared cubic-bezier and durations; active U53/U156 Todo movement, pointer layers, eligible Toasts and the working arc. U404's removed Live line, U405's instant leaf fold, U446's five still Kinds and retired U105 cannot commission new effects (policy). P3/P11 and existing permissions/budgets remain (policy).

Given CSS and programmatic motion, both resolve the same Tokens/presets, with one easing source and one 150 ms Todo duration preset rather than duplicated literals; no `transition: all` is introduced. Every animated layout property names its accepted scenario and rendered cost observer; U430 coordinated centre width is preserved (policy; design critic/source review, not a copied-value test). Duration consolidation is implementation work; this specification changes no production Token or timing.

The contract holds the bounded ease-out/spring comparison, current source/release library decision, lifecycle ownership criteria, trace protocol/tolerances and fixed native workload/thresholds in `docs/motion.md` (policy). Shared lifecycle responsibility is extracted only after existing holders and maintained libraries are assessed: callers declare destination/source/preset; shared completion/cancellation/retention is owned once, while content, focus and business actions stay with their owners. No generic DSL, renderer migration, forwarding wrapper or parallel legacy interface (policy).

Checks retained (policy): D1 (Tokens), D6 (immediate target states), D7 (zero-duration press), D9 (duration membership/reduced motion) and D10 (scheme/contrast support), each defined in `docs/design-system.md`, heading **The checks**, observed by `apps/desktop/src/testing/checks.ts`, function `runChecks`. D9 alone proves neither movement nor smoothness. D2/D5/D6 must pass on the densest visible-failure screen, no Check passing on main regresses. This documentation delivery has no rendered change and moves no Check. Behavioral tests assert actions/focus/identity/calls only; geometry, duration, continuity and feel belong to rendered observation/design criticism (AGENTS rule 10).

Existing regression specifications on main: U2580a in `scenarios/ui.md`; U430 in `scenarios/ui-drawer.md`; U371 in `scenarios/ui-shelf-frame.md`; U53 in `scenarios/ui.md`; U156 in `scenarios/ui-shelf.md`; U446 in `scenarios/ui-rail.md`; U414 in `scenarios/ui-toasts.md`; budgets/native permission in `docs/perf.md`, headings **Perf** and **macOS baseline** and its keystroke-to-render section. ## Layers

**U3010b a layer retargets without delaying input or changing ownership.** Given existing Drawer/Shelf flows in their final accepted modes, then:

- **Input.** Pointer-open a Drawer, reverse at 50% displayed displacement, reopen at 50% of its return, then press Escape. By the first animation frame after Escape it is closed, no exit content awaits completion and focus is at U40's existing return destination. Reopen by pointer, deliver the old completion and observe that new content remains. Enter/Space activation of open/close controls during a pointer slide likewise settles final visibility and existing focus next frame. All U2580a layers keep their instant key policy. Behavioral tests: extend `u2580a_key_close_and_interrupted_slide_leave_no_stale_content` and `u2580a_key_layers_open_and_focus_in_the_next_frame` in `apps/desktop/src/testing/u2580a_key_layers.test.tsx`; add only uncovered cases as `u3010b_latest_action_owns_layer_lifetime` against the same App seam. Never poll until a missed next-frame deadline passes.
- **Identity and effects.** With exact multiline unfinished text and pending submits, reverse, change Project and dispose mid-slide. Retain exact text, original Project/object/recipient and pending/newer revisions. Once closure begins, retained exits accept no new activation or submit. Dispatched work still receives its authoritative acknowledgement/refusal; success consumes only its submitted revision, failure cannot overwrite a newer draft, and restoration sends nothing (P11). Old timers/events cannot affect a new incarnation. Existing focus/RPC/Terminal resize effects occur only as U40/U111/U370/U371/U430 permit: one resize at each settled Drawer/reserved-Shelf opening or closing, none for overlay; no per-frame resize or duplicate cleanup from stale completions. Behavioral tests: `u3010b_exit_preserves_draft_and_submit_identity` and `u3010b_stale_completion_has_no_new_layer_effect`, extending existing unfinished-input coverage rather than duplicating it; retain `u2580a_instant_actions_release_slide_and_fit_once` and `u430_terminal_gets_one_resize_per_slide`.
- **Live preference.** Toggle reduced motion on at the measured halfway point of opening, closing and reversal, and during the working arc. By next frame latest requested visibility/focus/content is settled and no moving/looping effect remains. Turn it off: no completed motion replays. Behavior test `u3010b_preference_change_preserves_destination_and_focus` asserts visibility, content lifetime, focus and effect calls only. The rendered observer judges that movement/loops stop.

Rendered observer (policy): extend the existing U430/U26 layer observer with `docs/motion.md`, headings **Rendered continuity protocol** and **Bounded curve comparison**, including the Inbox Drawer comparison and both Shelf modes. Use `tree-40`, final accepted Shelf modes, densest seed with a refused action visible, dark 1512×950, normal/quarter-speed/reduced-motion variants. Capture three runs per comparison variant with raw timestamped boxes/action sources, 50% reversals, same-time retarget tolerance ≤1 CSS px/0.01 opacity, distinct intermediate samples and no endpoint restart. Run `just capture U3010b`, retaining PNGs/videos under `artifacts/ux/U3010b/`, never committing them. D2/D5/D6 pass and D1/D6/D7/D9/D10 regress none, using U3010a's Check definitions and observer. The critic cites a specific Motion example and observed delay/discontinuity/overshoot or gain; duration membership alone cannot pass. Rendered assertions stay out of behavioral tests.

Native evidence (policy): Chromium proves webview action/rendered outcomes only. Actual WKWebView under-load performance is U3010d, with no new native permission. Preserve the Intervene/Review journey stages and existing keyboard destinations; no new journey completion is claimed.

## Todos

**U3010c Todo structural motion follows the final row identity.** Given final accepted owner-grouped/nested rows and existing Todo mutations, when insertion, completion/removal, supported done folding or reorder occurs, U53/U156's existing 150 ms/`--easing-out` policy applies only to affected structure. U156 keyboard neighbour swaps remain animated; U2580a's instant policy applies to layers, not all Todo mutation motion. Pointer dragging remains direct manipulation; U405 Rail leaf folding stays instant (policy; rendered observer below).

A second insertion, completion or supported pointer move at 50% displacement retargets from displayed positions, including moves between owner groups/dependency depths only through their accepted mutation contracts. Authoritative final order/owner/blockers, exact calls and refusal recovery stay correct; focus follows the same Todo identity, editing text, original Project and pending revisions survive, and scroll position is retained. Removed exit content accepts no new actions; dispatched mutations still reconcile; stale completion cannot remove a distinct replacement. Behavioral tests `u3010c_interrupted_mutations_keep_identity_and_authoritative_order`, `u3010c_removal_keeps_pending_drafts_and_refusal` and `u3010c_preference_change_keeps_focus_and_actions` exercise real App components against the existing fake App. Reuse existing U152/U155, owner/nesting and unfinished-input cases for clauses already proved; tests assert no geometry, duration, exact copy or computed styles. Scroll preservation is judged by the rendered observer.

Rendered observer (policy): extend U53/U156's U26 sampled-position observer and existing `apps/desktop/src/todos/u490a_browser.test.ts` rendered sampling, using `docs/motion.md`'s continuity/comparison protocols. Retain raw row tops, fold height, scroll and identity traces; unchanged rows stay within 1 px, retarget continuity is ≤1 px at the same animation time and ease-out finishes at 150 ±50 ms. Include rapid repeated changes, pointer and existing keyboard swaps, refusal, reduced motion toggled while moving and the third-row-above-first comparison, on the densest final nested fixture; reduced motion settles by next frame without replay. Observe no hover movement (U112), height/wrapping stability (U154) and D2/D5/D6 with failure text visible, retaining all passing Checks via U3010a's Check definitions. Run `just capture U3010c`; pair dark 1512×950 base/head normal-speed and quarter-speed video/traces, plus reduced motion, under `artifacts/ux/U3010c/`, never committing images/videos. The critic cites the Motion layout/spring example and measured discontinuity/delay/overshoot or gain. Neither a duration constant nor a settled screenshot completes it.

Policy: preserve P3/P11, owner/nesting and mutation ownership, existing dnd-kit drag and WAAPI reorder before adding machinery; no alternate store/drag engine or retired Rail motion. No native claim is required by this portable slice; U3010d owns the required Mac observation. U53/U156 observer wording is reconciled to rule 10 without removing accepted motion.

## Actual renderer

**U3010d motion performance names the measured frame stage.** Given final layer and Todo implementations, before optimization fix the workload, baseline and thresholds in `docs/motion.md`, heading **Native performance protocol**. Run all fixed layer/Todo/ten-working-Glyph workloads with its 64 KiB/s Terminal stream, ten-second warmup, 60-second samples, three alternating base/head pairs and 30-second settled idle phase, on the same release-profile Mac/display/power configuration (required Mac evidence, not a behavioral test).

Retain immutable commits/binary/fixture hashes, tools/settings and environment, load, raw scheduling/style/layout/paint samples, separately available compositor/presentation evidence, p50/p95/p99, long-interval counts/rates, cleanup/errors and all failed/incomplete runs. For period P=1000/Hz, each run meets scheduling p95 ≤1.5P, p99 ≤3P, at most 5% >1.5P and none >50 ms; paired median regression ≤10% with the declared resolution floors. Apply the same thresholds independently to measured presentation intervals. Unsupported presentation is unmeasured, never zero/pass; native acceptance stays incomplete. Invalid/busy runs follow declared error/skip rules and are retained/repeated. Fix demonstrated cost/regressions without relaxing thresholds; if no failure occurs, retain evidence instead of inventing optimization (required Mac evidence; `docs/motion.md` result table gives exits 0/1/2 if automated).

Policy: profile U430 centre-width layout, style/paint, Terminal fits and main-thread cost before another engine. Preserve rule 7's cold start <300 ms, key-to-render <16 ms p95, ten idle Agents <150 MB extra RSS and existing 10%/noise/load rules from `docs/perf.md`; report those observers separately. rAF/callback timing is scheduling, not displayed FPS; `just perf` is Daemon work, `just perf-keystroke` is Terminal echo, and Chromium is not WKWebView. Native high-refresh periods remain explicit. No new timing/report test is commissioned unless an implemented report consumer has an uncovered validity behavior; no source-text rereading/copied-threshold tests.

Required Mac procedure (policy): prepare fixture/actions and isolated builds at recorded base/head; request the existing Mac observation with exact build commits, steps and result interpretation. Only the owner's explicit instruction authorizes a native window/input observation; preserve `docs/perf.md`'s `ROUNDUP_ALLOW_WINDOW` rule. An unavailable native observer leaves this implementation acceptance open. This specification itself requires no Mac observation and claims no FPS or optimization.
