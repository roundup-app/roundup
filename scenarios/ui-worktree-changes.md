# UI: an Agent's Worktree branch and changed files (U2539a to U2539d)

Module: `crates/agents` and `crates/contracts` (U2539a's one Daemon method), `crates/desktop` (U2539c) and `apps/desktop/src/changes/` (the webview). Ids: U2539a, U2539b, U2539c, U2539d. Work Issue: #2539; #2540 (diff view and line notes) builds on U2539b and U2539c. Found by the owner (2026-10-18, comparing roundup with Orca): "Open a file at a given line, worktree/branch we should give user this visbility and ability. We should also show them what files in the current agent worktree changed" and "for the worktree changed files we will use the amazing https://trees.software/". Today the App reads `agent.worktreeState` (G3) only in the removal warning (`apps/desktop/src/rail/menu/removal.ts`), nothing lists an Agent's changed files, and `open_in_editor` (U429) takes a directory, no line, and tries `ROUNDUP_EDITOR`, VS Code, then Cursor. Contract change (rule 4): `agent.changedFiles` is a new Daemon method and `open_in_editor` gains an optional `line`; every caller, `scenarios/rpc.md`'s and `scenarios/app.md`'s tables, `GLOSSARY.md` (**Changed file**) and the fake App change in the implementation PR. One view (U2236, ADR 0010): the list opens on demand and closes back to the Terminal; there is no split and no permanent pane. The tree is drawn with `@pierre/trees` (Apache-2.0); the implementation PR's `Reuse:` section names it and its release evidence (rule 9). Observer: Rust tests for U2539a and U2539c on Linux, Vitest against the fake App for U2539b to U2539d, and the isolated Chromium harness (U26) at 1280 by 800 in dark. Never a native Mac capture.

**U2539a `agent.changedFiles` lists what the Agent changed against its Base.** Adds one Daemon method; changes no Token. Given an Agent with a Worktree (G2), then `agent.changedFiles {id}` returns `{files: [{path, status, line}]}`, sorted by `path`:
- **Which files.** A file is listed when the Worktree's working tree differs from the merge base of the Agent's branch and its Base (`Worktree.base`, G3's Base): committed, staged, unstaged or untracked, outside `.roundup/`. A committed change later reverted is not listed. Asserted in `u2539a_lists_committed_staged_unstaged_and_untracked_files` and `u2539a_a_reverted_change_is_not_listed`.
- **Status.** `status` is one of `added`, `modified`, `renamed`, `deleted`, `untracked`; a renamed file lists its new `path` and `from`, its old one. Asserted in `u2539a_reports_each_status`.
- **Line.** `line` is the 1-based first line that differs in the working copy, `null` for a deleted or binary file. Asserted in `u2539a_line_is_the_first_changed_line`.
- **Read-only.** The branch, the Base and the files are the same after the call (G3's rule). Asserted in `u2539a_changes_nothing`.
- **Failures.** An Agent with `worktree: null` fails `no_worktree`; a Worktree directory gone from disk fails `worktree_missing`, as G3 does. Asserted in `u2539a_no_worktree_and_missing_worktree_fail_as_g3_does`.

**U2539b the selected Agent's Worktree and its changed files show on demand.** Webview only. Given a selected Agent (U59) with a Worktree, then:
- **Branch and state.** The shared bottom bar (U469, U444) carries one control labelled with the Worktree's `branch`. Its panel shows the branch, the Base, and `agent.worktreeState` (G3) as `ahead`, `behind` and `dirty`, in `GLOSSARY.md` words. An Agent with no Worktree shows no control. Asserted in `u2539b_the_control_shows_the_branch_and_its_state` and `u2539b_no_worktree_shows_no_control`.
- **Opens and closes back.** Activating the control (or `Esc` inside the panel) opens and closes it; the Terminal stays mounted and is the only other view, and closing returns focus to the control. Selecting another Agent closes it. Asserted in `u2539b_opens_and_closes_back_to_the_terminal` and `u2539b_selecting_another_agent_closes_it`.
- **The tree.** The panel draws `agent.changedFiles` (U2539a) with `@pierre/trees`, folders from the paths, each file with its status as text and a mark, read again on every open. Zero files shows `No changes`; a failed call shows U80's `✕ <message>`. Asserted in `u2539b_the_tree_lists_each_file_with_its_status`, `u2539b_it_reads_again_on_every_open`, `u2539b_no_changes_says_so` and `u2539b_a_failed_call_shows_one_failure_line`.
- **Keyboard.** The tree is one Tab stop; arrows move between rows; `Enter` on a file is U2539d's choice. Asserted in `u2539b_the_tree_is_one_tab_stop`.
- **Looks.** Tokens only; D2, D5 and D6 pass on the densest seed (a 500-file changed list, a 120-character path and the longest branch name), and no Check passing on `main` regresses (the design critic judges placement, AGENTS.md rule 10). Rule 7's budgets hold: the library loads only when the panel first opens (`u2539b_the_library_loads_on_first_open`). Observer: `window.__checks()` in `.agents/data/harness.md`; captures in `artifacts/ux/U2539/` (policy).

**U2539c `open_in_editor` opens a file at a line, and Zed is an editor.** Changes the App seam command of U429: `{path, line?}`. Given an absolute path, then:
- **A file at a line.** A file with `line` launches the first installed editor at that line: VS Code `vscode://file<path>:<line>`, Cursor `cursor://…`, Zed `zed://…` (the schemes `LINE_APPS` in `crates/desktop/src/open.rs` holds). An editor that takes no line opens the file. Asserted in `u2539c_a_file_opens_at_its_line` and `u2539c_an_editor_without_a_line_opens_the_file`.
- **Order.** `ROUNDUP_EDITOR`, then VS Code, Cursor, then Zed (`dev.zed.Zed`, then `dev.zed.Zed-Preview`). Asserted in `u2539c_zed_is_tried_after_cursor` and `u2539c_roundup_editor_still_wins`.
- **Kept.** A directory with no `line` behaves as U429 says, including `NOT_FOUND` with the message `no code editor found; install VS Code, Cursor or Zed, or set ROUNDUP_EDITOR` (the message gains Zed) and the refusals for a relative or missing path. A `line` on a directory is ignored. Asserted in `u2539c_a_directory_still_opens_as_u429_says` and `u2539c_a_line_on_a_directory_is_ignored`.
- **Seam.** `seam.ts`, `tauri.ts`, the fake App and `scenarios/app.md`'s table carry `line`. Asserted in `u2539c_the_command_is_in_the_seam_list`.

**U2539d choosing a changed file opens it in the editor.** Webview only. Given U2539b's panel, then:
- **Choosing.** `Enter` or a double click on a file calls `open_in_editor {path, line}` once, with the Worktree's `path` joined to the file's and its `line`; a deleted file opens nothing and its row says `Deleted`; a folder row only expands. A single click selects. Asserted in `u2539d_enter_opens_the_file_at_its_line`, `u2539d_a_deleted_file_opens_nothing` and `u2539d_a_folder_only_expands`.
- **Failure.** A failed call shows U80's `✕ <message>` and the panel stays open. Asserted in `u2539d_a_failed_open_shows_one_failure_line`.
- **Kept.** The Rail row's `Open in editor` icon (U427, U428) still opens the Worktree folder. Asserted in `u2539d_the_rail_icon_still_opens_the_folder`.
