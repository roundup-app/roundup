# UI: failures are toasts on every screen (U7314a to U7314h)

Module: `apps/desktop` (the webview). Ids: U7314a–U7314h.

Work order: [#7314](https://github.com/roundup-app/roundup/issues/7314). Owner, 2026-11-17: "I don't care about errors unresolvable and not being able to show and dismiss as a toast or something". The owner chose the Todo and Pad views first (U7310d, `ui-item-view.md`, merged), then every other screen. This extends U7310d to each screen that still holds a `ReservedLine` and retires U3807 (`ui-visual.md`) with it.

Policy: webview only; no App command, Daemon method or contract changes. Each screen uses `createMessageToast` (`apps/desktop/src/ink/messageToast.tsx`) and the shared `ui/Toast.tsx` region, as U7310d does; no new toast machinery. The rules of U7310d hold for every id below:

- A failure, conflict or refused change a screen shows beside its content shows as one toast with its existing text, Dismiss, and the recover action its line offered under the same label; activating it runs the same recovery. The toast stays until the user dismisses it or its cause clears, and a newer message is a new toast.
- A status or notice that reports no failure ("Saved", "Looking…", a restored count, a replacement-diff notice) raises no toast. It shows in a plain element mounted only while it holds, so no screen holds blank space for it before or after.
- A failure with no Dismiss (a startup gate, an error boundary's fallback; `Blocked` in `ink/ReservedLine.tsx`) is the screen's content, not a message beside it: it stays as that screen's own view and raises no toast.
- A failure a dialog shows for its own form stays visible beside that form while the dialog is open and is announced once (`role="alert"`, U80); it is a toast when the Toast region shows above the dialog's backdrop, else it renders in the dialog from a plain element mounted only while it holds. Build runs decide which by running U7314c's dialog case and record it on the Issue.
- Each id's test renders one site of the family with a failure and asserts: one toast with Dismiss (and Retry where the line offered a recover action, which runs once), no `ReservedLine` in the screen, and the screen's other elements the same nodes in the same order with the message absent, present and absent. Layout and looks are the design critic's (rule 10).

**U7314a the Rail and Project tabs.** Given a failure in the Rail (its draft, retention, create, save-as, delete and recovery lines; `rail/`), the Project tab (`header/ProjectTab.tsx`), Project settings and the opening prompt, or the bulk delete (`shelf/BulkDelete.tsx`), then it shows as a toast per the rules above and the Rail's rows and footer do not move. Test: `u7314a_rail_failures_show_as_toasts` in `apps/desktop/src/rail/`. The waiting row of U6248c is a status, not a failure, and raises no toast.

**U7314b the Terminal, Ask and Bubbles.** Given a failure in the Terminal's decision list, find bar or `pane-failure` (`terminal/`), the Ask bar, Overview, Deliverables and rows (`ask/`) or a Bubble (`bubbles/`), then it shows as a toast and the Terminal, Ask bar and Bubble keep their size and place. U7211a's Resume line is a notice, floating over one Terminal row, and stays as U7211a says; its failed read ("Unfinished work could not be checked.") with Retry becomes a toast. Test: `u7314b_terminal_and_ask_failures_show_as_toasts` in `apps/desktop/src/terminal/`.

**U7314c the Changes view, the Fork sheet and dialogs.** Given a failure in the Changes view, Diff reader, note form and batch, worktree control (`changes/`; a failed refresh keeps the last count, stale, as U2539b says, while its failure shows as the toast) or the Fork sheet and list (`fork/`, whose `.fork-failure` row in the dialog actions goes, U6264b), then it shows per the rules above and the dialog's actions keep their place. Test: `u7314c_changes_and_fork_failures_show_as_toasts` in `apps/desktop/src/changes/`.

**U7314d the Inbox, the Switcher, Resources and Feedback.** Given a failure in `inbox/`, `switcher/` (its two recovery places, U4681, mount nothing while empty), `resources/` or `feedback/`, then it shows as a toast and the list rows do not move. Test: `u7314d_inbox_and_switcher_failures_show_as_toasts` in `apps/desktop/src/inbox/`.

**U7314e Settings and the importer.** Given a failure in App settings, shortcut, naming, Machines, Add machine and the update row (`settings/`) or the importer (`importer/`: conflict and failure; its "Looking…" and restored count are notices), then it shows as a toast and the settings rows do not move. Test: `u7314e_settings_and_import_failures_show_as_toasts` in `apps/desktop/src/settings/`.

**U7314f the remaining Todo and Pad surfaces.** Given a failure in the Todos list, Capture, Capture panel, New Workstream, the Delegate board, open rows and editable text (`todos/`), the Pads list and content not yet covered by U7310d (`pads/`), or the Drawer's draft recovery and Item drawer (`drawer/`), then it shows as a toast and the list does not move. A retained-draft or retention problem keeps its recovery action and is never cleared to hide it (P11). Test: `u7314f_todo_list_failures_show_as_toasts` in `apps/desktop/src/todos/`.

**U7314g the window and the App.** Given a failure in `App.tsx` (the window, Daemon-exit and Project lines), `window/` (first run, storage recovery, Project centre), `ui/Deferred.tsx`, `ui/NativeAlert.tsx`, `ui/Editable.tsx` or `continuation/`, then a dismissible one shows as a toast, and a `Blocked` one stays as its own screen (the rules above). Test: `u7314g_window_failures_show_as_toasts` in `apps/desktop/src/window/`.

**U7314h `ReservedLine` retires.** Given U7314a to U7314g on `main`, then `rg ReservedLine apps/desktop/src` finds no use outside tests, `ink/ReservedLine.tsx` and its `.reserved-line` rules are deleted, the out-of-flow lines that remain (U7211a's Resume line, `.todo-undo`) use a plain `FloatingLine` in `ink/` named in `GLOSSARY.md` in the same PR, and U3807 and U6264b are retired in `ui-visual.md` and `ui-buttons.md` with each deleted test naming this scenario. Its guard test (`u3807_no_message_renders_outside_the_reserved_line`) becomes `u7314h_no_failure_renders_outside_a_toast`: no file outside `ink/` and `ui/Toast.tsx` sets `role="alert"` on a failure line, and no source file names `ReservedLine`. Policy: the owner's "no screen holds blank space for a message" holds because no message has a reserved place.
