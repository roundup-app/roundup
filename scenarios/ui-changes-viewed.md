# UI: an item is marked Viewed, marking opens the next unviewed item, and a changed item un-marks itself (U7680a–U7680f)

Module: `apps/desktop/src/changes/` (`viewed.ts`, `createViewed.ts`, `ChangesView.tsx`, `ChangedTree.tsx`, `ModuleScroll.tsx`, `copy.ts`), `apps/desktop/src/state/changePlaces.ts`, the fake App and its fixtures. Ids: U7680a, U7680b, U7680c, U7680d, U7680e, U7680f. Work order: [#7680](https://github.com/roundup-app/roundup/issues/7680), blocked by #7679. Owner, 2026-11-18: "clicking viewed should move to next in the lane/filtered review lens"; a per-item Viewed mark, "N of M viewed" in the header, a mark that un-sets itself when the item changes, a marker that is personal and never a gate. No Daemon method, Message or contract change: `ChangedFile.blob` (U7673a) is the content signal, so the App reads no file to mark or to count. Reuse (rule 9): `createSignal` over an immutable `Map`, as `changeTargets.ts` keeps its choice, and `blob` as the listing carries it. The PR's `Reuse:` section names `@solid-primitives/map` and `solid-js/store` as the candidates it considered, with each one's evidence, and says no new machinery was added. Size: about 700 changed lines. Observer: Vitest against the fake App for U7680a to U7680e; the isolated Chromium harness (U26) for U7680f and for the amended U7692b test. Never a native Mac capture.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

**Words.** An item is a module the open lens lists; the Overview and a noise file are no item (U7679c). Decided here ("Open for the specify run"): #7680 reads "the lens's list is the lane" and the owner wrote "move to next in the lane/filtered review lens", so the next item is the next one in the open lens's list, and past its end the next lens in the switch's order that still holds an unviewed item. The App and this specification say lens and list, never lane (GLOSSARY has no such term). A file is viewed when the blob recorded when the user marked it equals its entry's `blob`, a `null` equalling a `null`. An item is viewed when every file it lists in the open lens is. "Viewed" and the words below are asserted through `copy.ts`, never layout or looks (rule 10).

**U7680a Viewed marks the open item, and the header counts them.** Given the lens fixture (U7679) and the fake App, then:
- **Marking.** The open module's header holds a "Viewed" button that shows its state, and V does the same from the list or the diff, never while a note field, text input or the editor holds focus. Marking records the `blob` of each file the item lists in the open lens; pressing again, by button or V, removes those records and moves nothing. A viewed item's list row says "Viewed". Asserted in `u7680a_v_and_the_button_mark_the_open_item_and_the_same_press_un_marks_it`.
- **No item.** The Overview and a noise file show no button, and V does nothing there. Asserted in `u7680a_the_overview_and_a_noise_file_take_no_mark`.
- **Personal.** A mark makes no Daemon call, sends no Message and changes nothing on the Rail or at Landing, and is never sent to the Agent: the fake App's calls are the same before and after a mark (U2540d). Asserted in `u7680a_a_mark_blocks_nothing_and_makes_no_call`.
- **Progress.** The header says "N of M viewed", M being the open lens's modules and N the viewed ones; when N is M it says "All M viewed"; a lens with no module says nothing. A find (U7679d) leaves both as they were: the Issue's reading that a filtered set is built only when the owner names a filter, so the lens's list is what the count and the next item read. Asserted in `u7680a_the_header_reads_n_of_m_viewed_then_all_m_viewed`.

**U7680b marking opens the next unviewed item.** Given three modules and the lens fixture, then:
- **Next.** Marking an item (not un-marking) opens the first item after it in the open lens's list that is not viewed, with focus on its row as J gives it (U7679e). Asserted in `u7680b_marking_opens_the_next_unviewed_item_in_the_lens_order`.
- **Next lens.** When no item after it is unviewed, marking opens the first unviewed item of the next lens in the switch's order that holds one, wrapping; that lens becomes the open lens, and the Agent's lens last used follows (U7679c, U7679b's jump). No pass returns to the open lens: its unviewed items before this one share their files with a lens that follows. Asserted in `u7680b_the_end_of_a_lens_goes_on_to_the_next_lens`.
- **Nothing left.** When no lens holds an unviewed item, the open item and focus stay and the header reads "All M viewed". Asserted in `u7680b_the_last_mark_leaves_focus_where_it_is`.

**U7680c a mark belongs to files, so the lenses agree.** Given the lens fixture, then:
- **Key.** A mark is a file's path and `blob`, kept for the comparison it was made in (the Compare-to value and the group): the Issue's reading that marks belong to hunks keyed by file and content, held at the file's grain because a hunk is known only once its file is read and the lenses read none to count. Marking in Modules marks every file of the module, so Logic and Tests show the same files viewed; marking in Logic or Tests marks that lens's files only, so the module reads unviewed in Modules and in the other lens until its other half is marked. Asserted in `u7680c_a_mark_made_in_modules_shows_in_logic_and_tests_for_the_same_files` and `u7680c_a_mark_in_logic_marks_only_the_logic_files`.
- **Memory.** Marks last the connection's session as U7675f's places do: closing and reopening the view restores them, a new Compare-to value or group shows its own, and none is stored, so an App restart starts with none (P11 holds: a mark is no unsubmitted work). Decided here: the Issue leaves restart open and "closing and reopening restores them" (#7675). Asserted in `u7680c_reopening_restores_the_marks_and_each_comparison_keeps_its_own`.

**U7680d a viewed item that changes un-marks itself.** Given a viewed module and the fake Agent's writes, then:
- **Change.** When a listing shows a marked file with another `blob`, including a rewrite that keeps its `counts`, that file's mark is removed, the item reads unviewed, its header says "Changed since you viewed it" and its row's name says so, until the item is marked again. Asserted in `u7680d_an_edit_to_a_viewed_item_un_marks_it_and_says_so`.
- **Joins, leaves.** A file that joins a viewed item has no recorded blob, so the item reads unviewed and says nothing; a file that leaves the listing loses its mark and says nothing. Decided here: the Issue defines a change as a differing `blob`. Asserted in `u7680d_a_file_that_joins_or_leaves_a_viewed_item_says_nothing`.
- **Unread.** A listing still pending or failed changes no mark. Policy.
