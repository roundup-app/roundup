# UI: pasting an image into a Terminal (U418)

Module: `apps/desktop` (the webview) and `crates/desktop` (the App's shell). Ids: U418, U3560a to U3560e.

**U418 `⌘V` with an image on the clipboard pastes the image's file path, as a File drop does.** Found by #810 and left open by U349 (`ui-daily.md`), whose last clause names this as a separate Issue: today `⌘V` with an image and no text shows `✕ Paste failed: The clipboard contains an image instead of text. Save the image, then drop its file on the pane.` and writes nothing, so a pasted screenshot never reaches an Agent. Design: the webview reads the image's bytes from the clipboard, one new App seam command saves them as a file on the user's Mac, and the pane pastes that file's path exactly as U162 pastes a dropped path, so an Agent such as Claude Code takes the path as it takes a drop (U174, U175). Adds one App seam command, `savePastedImage`, and no Daemon method, nothing under `contracts/` and no Token; it follows the Contract recipe of `.agents/builder.md` (rule 4), its PR needs the review run's approve, and `GLOSSARY.md` gains **Pasted image** in the same PR. Narrows U349's image clause: it stays only for a clipboard image the App cannot save. Given the selected Terminal runs (an Agent's, a shell's or the Door's), the fake App (U11) and a stubbed clipboard, then:

- **The seam.** `savePastedImage({type, bytes})` resolves the absolute path of a new file holding exactly `bytes`, and the webview passes it nothing else. `type` is one of `image/png`, `image/jpeg`, `image/gif`, `image/webp`; the file's extension follows it (`.png`, `.jpg`, `.gif`, `.webp`) and its name is `pasted-<unix seconds>-<8 hex characters>`, so two pastes never share a file and the name holds no clipboard text. The file is in a `roundup-pasted` folder under the OS cache directory (`dirs::cache_dir`), created with mode `0700`, the file `0600`. Policy chosen by this spec: the cache directory because Claude Code reads the path at once and nothing else needs the file later; the Project folder is never written, so a paste dirties no Worktree. Any other `type` is `FORBIDDEN` and writes nothing; `bytes` over 20 MiB is `FORBIDDEN` and writes nothing (policy: about five 4K screenshots, above any screenshot and below a clipboard that holds a whole video frame buffer). Asserted in Rust tests in `crates/desktop` named `u418_saves_the_bytes_under_a_unique_name`, `u418_refuses_a_type_it_does_not_name` and `u418_refuses_bytes_over_the_limit`, and in `u418_the_tauri_adapter_sends_the_bytes_to_save_pasted_image` (`apps/desktop/src/app/`, a stubbed `invoke`), which also reads `m5_seam_commands.test.ts`'s check that the adapter names every command.
- **The paste.** `⌘V` with no text on the clipboard and an `image/*` item that `clipboard.read()` lists reads the first item whose type the seam accepts, calls `savePastedImage` once, and hands the returned path to the emulator's paste exactly once through U162's `pastePaths` (so one single-quoted path, one trailing space, no newline, and the bracketed-paste markers when the program asked for them). `terminal.write` receives those bytes in order and no other write. Text on the clipboard wins: `⌘V` with text and an image pastes the text and saves nothing (U101). Asserted in `u418_a_pasted_image_pastes_its_saved_path`, `u418_text_wins_over_an_image` and, on the real xterm emulator as `u175_a_dropped_image_writes_one_bracketed_paste` builds it, `u418_a_pasted_image_writes_one_bracketed_paste`.
- **No wait of roundup's.** Reading the clipboard and saving the file are the only awaits, both before the paste, and the paste is one synchronous hand-off as U174 says; roundup decodes, converts and resizes nothing. U174's budget does not apply to the save, which grows with the image's size; the pane shows nothing while it runs (the keystroke already echoed nothing, and a spinner would flash for a screenshot). Policy: no new Token and no motion (`docs/motion.md` has no row).
- **A failure says why, in full.** A refused `read()` stays silent as U349 says (the App cannot know an image is there, so this scenario's Given does not hold and nothing is saved). An image item that `read()` listed but whose `ClipboardItem.getType` rejects shows U349's refused-paste line, and a `savePastedImage` rejection shows `✕ Paste failed: <message>` in the same pane notice (U349), so no failure is swallowed; nothing is written to the Terminal. An image type the seam does not accept shows U349's existing image line. Asserted in `u418_an_unreadable_image_item_shows_the_refused_paste_line`, `u418_a_failed_save_shows_its_message_and_writes_nothing` and `u418_an_unsupported_image_type_keeps_the_u349_line`. The notice clears on the next successful copy or paste (U101).
- **Where the paste stops.** An exited Terminal and the state after `daemon-exited` (U25) take nothing and save nothing (U12), and `⌘V` follows U32's rules as U101 states them (focus elsewhere, `⇧⌘V`, `⌥⌘V`). Asserted in `u418_an_exited_terminal_saves_nothing` and `u418_command_v_outside_the_pane_saves_nothing`.
- **The folder stays small.** On each save the shell deletes files in `roundup-pasted` whose modified time is over 7 days old (policy chosen by this spec: far past any Agent turn that reads the path) and no other file. Asserted in `u418_a_save_prunes_files_older_than_seven_days_and_only_those`.
- **Observer.** The webview and the shell legs are Vitest and Rust tests against the fake App (whose `savePastedImage` records its calls and returns a fixed path) and a stubbed clipboard. WKWebView's `clipboard.read()` for an image, and an Agent attaching the path as an image, are the one thing the harness cannot show, so the PR that implements this asks the user for a `macOS:` line: copy a screenshot, press `⌘V` in an Agent's pane running a real `claude`, and report whether the image attached. If the real `read()` returns no image where the system has one, that is a defect to reduce on the Issue, not a pass.

Moves D2, D5.

## One clipboard path

**U3560a clipboard access has one owner.** Policy: every App-authored clipboard read and write, including Terminal shortcuts and every Copy action, goes through one clipboard module. It owns the choice between a DOM clipboard event and native App access; components never choose their own fallback. Ordinary browser/editor copy and paste may retain their default editing behavior, routed without a second insertion or an asynchronous browser clipboard read. The shipped Mac path never depends on `navigator.clipboard` permission, WebKit's Paste callout, a retry chord or a clipboard permission prompt. No polling or clipboard read occurs merely from focus, selection or navigation. Native access stays behind the App seam; any added seam method changes its adapter, fake and every caller together under the Contract recipe, with its names in `GLOSSARY.md`. No Daemon clipboard RPC or vendor-specific integration is added.

Given the desktop source tree, when its clipboard boundary guard runs in a required lint or test lane, then `navigator.clipboard.read`, `navigator.clipboard.readText` and `navigator.clipboard.writeText` outside that one module fail the guard. Test: planned `u3560a_clipboard_access_has_one_owner`, which exercises the guard with each forbidden access in a component and the same access in the allowed module. Passing `navigator.clipboard` to a helper must not provide an alternate production path (policy). If the guard is a command, its contract is:

| Input | Exit |
| --- | --- |
| Direct `navigator.clipboard.read()` outside the module | 1 |
| Direct `navigator.clipboard.readText()` outside the module | 1 |
| Direct `navigator.clipboard.writeText(text)` outside the module | 1 |
| Those accesses confined to the module, or absent | 0 |

Policy: reuse the platform clipboard event API and/or a maintained native clipboard library, researching both before implementation under rule 9. The [Clipboard Event API](https://www.w3.org/TR/clipboard-apis/#clipboard-event-interfaces) exposes event data; [Tauri's clipboard manager](https://v2.tauri.app/reference/javascript/clipboard-manager/) supplies native text and image operations. A fallback inside the module is not permission to keep permission-dependent browser calls in the shipped Mac path. A native image buffer must become a valid encoded image before using U418's byte-saving contract; raw RGBA is not a PNG (policy).

**Clipboard write** (`writeClipboardText`): The App's act of placing the user's selected or action-defined text on the system clipboard. It grants no Agent access to the clipboard.

**U3560b one paste reaches the focused Terminal once.** Given the actual App mounted through its normal fake-App/Daemon seam, with a running Agent Terminal taking user input, when one paste enters through U3560a's production clipboard module, then multiline Unicode text reaches that Terminal's emulator once and its emitted bytes reach only that Terminal's `terminal.write`, in order. For an image-only paste, the module supplies the image to U418's save path once and the returned absolute path reaches the emulator once, quoted with U162's trailing space and no newline. No second insertion comes from the native key, DOM paste event or xterm handler. Test: one planned parameterized App-seam test, `u3560b_paste_reaches_only_the_focused_terminal`, with text and image cases, also run for the Door and plain Bubble Terminal placements. Mounting only Pane or mocking the clipboard module does not prove this clause; inject the platform edge and observe the production module, image-save calls and Terminal writes. Make forbidden asynchronous browser access throw `NotAllowedError` in this test, so success proves the Mac path does not depend on it.

Policy: preserve U101's empty-clipboard, selection-copy, Ctrl-C, modifier, focus, exit and Daemon-exit rules, and U375's retired Watch/Takeover gate (#3563). U418's text-over-image priority, supported image types, save failures, cache permissions, size limit and cleanup stay. U162's native file drops and U175's real-emulator bracketed paste stay. The only U101 shortcut change allowed is leaving the native key event available to obtain a DOM clipboard event; the resulting paste is consumed exactly once. U418's requirement to use `clipboard.read()`/`ClipboardItem.getType` is replaced by U3560a's source; its no-conversion clause still applies to already encoded event images, and permits library encoding of native image buffers. Update the existing tests to inject the chosen platform edge rather than retaining the old browser dependency (policy).

**U3560c editable fields and Copy use the same path.** Given a Pad's source or rich editor, the Ask bar, a plain input, a textarea or an active rename field, with text selected inside existing text, when the user pastes multiline Unicode text, then it replaces only that selection in the focused editor once, preserving the surrounding text and the editor's normal formatting/undo behavior, and sends nothing to a Terminal or Agent. Test: `u101_chords_leave_other_fields_to_the_browser` in `apps/desktop/src/terminal/u101_copy_paste.test.tsx` owns the App routing boundary: copy/paste stays unconsumed in an editable field and sends no Terminal input. The Chromium insertion/undo matrix `u3560c_paste_edits_only_the_focused_field` is retired as a browser/editor default-behavior re-proof (#4970); the editor keeps its native insertion, formatting and undo contract (policy).

Given a Terminal selection, an editable-field selection or an App Copy action, when the user copies, then the selected or action-defined content is written exactly once through the shared path without changing the source or sending Terminal input. Tests: `u3560c_copy_preserves_the_source` in `apps/desktop/src/app/u3560_copy.test.tsx` covers Terminal, Copy Link and retained-draft Copy; `u101_chords_leave_other_fields_to_the_browser` covers the editable-field routing boundary. The Chromium `u3560c_copy_preserves_the_source_editor` matrix is retired as a browser/editor default-copy re-proof (#4970); native editor source preservation remains policy. Policy: migrate every App-authored clipboard caller, including recovery, export/details, links and history, in the same implementation PR; preserve each caller's content contract and error handling. Browser/editor default copy remains allowed under U3560a; it must not race a second App write. No replacement Terminal Paste popover, selection toolbar or native App context menu is introduced; U3529a, U3529b and U3529d in `scenarios/ui-text-selection.md` remain unchanged.

**U3560d a real failure stays visible and recoverable.** Given a clipboard read, write or image save that fails at the selected platform edge, when the user copies or pastes, then the source and any unsent draft remain intact, no partial paste or Terminal write occurs, and the existing surface shows an error naming Copy or Paste, its cause and an available next action; the next successful copy or paste clears the clipboard error. Test: planned parameterized `u3560d_clipboard_failure_preserves_input`, covering those three failing operations and a subsequent success. An empty clipboard remains a silent no-op, not a read failure (U101). This replaces U349's refusal-specific and silent-refused-image-read clauses and U418's refused-read/getType failure clauses; other error placement and unsupported-image behavior stay (policy). Remove `copy.pasteFailedTheSystemClipboardRefusedItPress` and its copy equivalent with their refusal mapper and tests when the new path has no producer for that failure. Do not keep a dead error branch or map genuine native failures to advice to repeat a permission-denied browser read (policy).

**U3560e the intervention journey keeps its observer.** Policy: the implementation's rendered observer uses U26's `agents-10`, `tree-40` and `bubbles` seeds at 1512×950, dark, with a running Agent taking input, a Pad and Ask bar, and a genuine clipboard failure visible on the densest seed. Capture the successful text/image paste and failure/recovery through `just capture`; leave PNGs/videos under `artifacts/ux/<id>/` uncommitted. Check 2 (type and spacing), Check 5 (legibility) and Check 6 (keyboard reachability and targets) in `docs/design-system.md`, heading `The checks`, must hold without regressing another passing Check; use existing Tokens and no new motion. This serves the Intervene stage of `.agents/data/journey.md`: user input reaches the chosen Agent and errors remain actionable. The spec-only PR claims no implementation or native Mac observation.

Policy: Chromium/App-seam evidence proves routing, call counts and editing, not WKWebView pasteboard access. For a native observation, build the implementation PR's exact head with `just app` on the Mac: copy external multiline text and press ⌘V once in an Agent running logged-in Claude Code and in a shell Terminal; copy a screenshot and paste once into the Agent; paste into a Pad, Ask bar and input; copy from those surfaces and an App Copy action into another Mac app; drop a file onto the pane.
