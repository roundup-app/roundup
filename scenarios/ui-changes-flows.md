# UI: the Flows lens lists a flow for each changed entry point, draws its call tree and opens its hunks in call order (U7683a–U7683h)

Module: `apps/desktop/src/changes/` (the lens list, the flow scroll, rows, the call tree, the trace states), `state/` where the method list sits, the fake App and its fixtures. Ids: U7683a, U7683b, U7683c, U7683d, U7683e, U7683f, U7683g, U7683h. Work order: [#7683](https://github.com/roundup-app/roundup/issues/7683), blocked by #7682. Owner, 2026-11-18 to 2026-11-20: "I don't care about file by file I care about flows/paths/modules and mental models"; "Yes, move them earlier - proper tools"; Rust traces "only when you click Trace". The Issue's seven owner decisions hold as written: Flows first in the switch, a flow opens its hunks as one scroll in call order, call paths are built before any readback, proper tools resolve each call, Viewed applies per flow, a flow's row counts its gaps (#7688) and repeats (#7685) once they build, and Rust traces only on Trace. No Daemon method, Message or contract change: the App reads `agent.callPaths` (CP1 to CP4, `scenarios/call-paths.md`) and `agent.compareFile`; a flow or a call path is a personal aid, never a gate and never sent to the Agent. Reuse (rule 9): the list is `ChangedTree` over `@ui-sdk/solid/tree` (U7679, #7852), the switch is `ui/SegmentGroup.tsx`, the scroll is `ModuleScroll` (U7678c) and the call tree is `AppTree` over the same `@ui-sdk/solid/tree`, the tree the Changes list, Rail and Shelf already use; the Ark UI tree view named in the Issue is what that tree wraps, so no second tree library is added. The PR's `Reuse:` section names `@ui-sdk/solid/tree` as selected and `@ark-ui/solid`'s tree view and the one in the Issue as considered, and `diff`'s `parsePatch` and `formatPatch` (installed, as the diff reader already uses) as what cuts a section's hunks; it says no new machinery was added. Size: about 760 changed lines. Observer: Vitest against the fake App for U7683a to U7683g; the isolated Chromium harness (U26) for U7683h. Never a native Mac capture.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

**Words.** The quoted words below are asserted through `copy.ts`, never layout or looks (rule 10). A **flow** is the Issue's call path (`GLOSSARY.md`, Call path): an item that holds hunks. A **section** is one function's hunks inside a flow's scroll. A **language** is a name the lookup of `agent.callPaths` (CP1) gives; the App reads no extension and keeps no table of languages by extension, so a file belongs to a traced language only when a done answer's `symbols` name it (a hunk outside any symbol maps to its file's top level, CP2).

**Fixture.** The flow fixture changes `apps/a/src/run.ts` (entry `run`, which calls `load`, a changed function in `apps/a/src/load.ts`, and a removed call to `old`), `apps/a/src/other.ts` (entry `other`, which also calls `load`), `apps/a/src/types.ts` (a changed type, in no function), `crates/b/src/lib.rs` and `docs/README.md`; the lookup lists `typescript` (found) and `rust` (found, 1 file); the TypeScript answer holds `run` → `load` and `other` → `load`. By U7678b the lens's noise rows are those of the other lenses.

**U7683a Flows is the first lens, and its Overview lists the flows.** Given the lens fixture (U7679), the flow fixture and the fake App, then:
- **Switch.** The lens switch holds "Flows", "Modules", "Logic" and "Tests" in that order, and L and Shift-L step the four in that order, wrapping at its ends; U7679a's clause that the switch holds three lenses reads four. The first-time landing stays U7679c's: Modules, and the lens last used after that. Asserted in `u7679a_the_switch_names_the_four_lenses_in_order_and_choosing_one_changes_the_list` and `u7679a_l_and_shift_l_step_the_lenses_in_switch_order`, each edited to the fourth name; no other assert of an older test changes.
- **Overview.** Flows lists the Overview row first, as every lens does (U7679c); its pane lists the lens's items in list order, each with its name, its file count and `+added -removed` of its files, and a Flows list with no item says "No changes in Flows". Asserted in `u7683a_the_flows_overview_lists_the_flows_in_list_order`.
- **Keys.** J, K, V, the find and Esc act on a flow item as on a module (U7679e, U7680a): the list's rows are items, and a find narrows the files of the flow items it shows. The ? list is U7679e's (it names L, not the lenses). J is asserted in `u7683a_the_flows_overview_lists_the_flows_in_list_order` and V in `u7683g_marking_a_flow_viewed_opens_the_next_unviewed_flow_and_a_shared_file_reads_viewed_in_both`; the other keys are U7679e's and U7680a's, unchanged.

**U7683b the App traces TypeScript when the view opens, Rust only on Trace, and never reads a language by its extension.** Given an Agent with a Worktree and the fake App's `agent.callPaths`, then:
- **Open.** After the view's first paint the App asks the lookup (CP1, no `language`) once, and then one request for each language the lookup lists with a found server, but not Rust: Rust starts nothing (decision 7). A key, the diff and every lens work while a request runs; the request never starts at cold start or before the view opens. Asserted in `u7683b_opening_the_view_asks_the_lookup_once_and_traces_typescript_once_and_rust_never`, which counts the calls by `language`.
- **Trace.** Trace on the Rust row makes one request with `language: "rust"`; Retry on a failed language makes one more for it. Asserted in `u7683f_rust_and_a_language_with_no_server_say_so_and_trace_moves_the_rust_files_into_flows` (Trace) and `u7683f_tracing_shows_after_150_ms_a_failed_trace_says_why_and_retry_asks_again` (Retry).
- **A write.** After a language is done, a write of the Agent (an `agent.toolCall` of a writing tool, `owned.ts`, that is no longer running) dims every done language's flows with "Changed since traced"; the flows stay usable. A write makes no request. Decided here: the App reads the Agent's write events and no per-file `blob`, since a listing is read only when the view refreshes. Asserted in `u7683b_a_write_dims_the_flows_and_a_turn_end_traces_typescript_again_once_and_rust_never`.
- **Turn end.** When the Agent's Status goes to done, idle or error, TypeScript, when its flows are dimmed, is traced again once, so a turn of many writes costs one request; a turn with no write makes none. A dimmed Rust offers Trace and makes no request when the turn ends. Asserted in `u7683b_a_write_dims_the_flows_and_a_turn_end_traces_typescript_again_once_and_rust_never` and, for Rust, `u7683b_a_write_dims_a_traced_rust_and_offers_trace_and_a_turn_end_never_traces_it`.
- **A new comparison.** A change of the To value (U7672c) or a Fetch that moves the merge base (U7693c) drops a running trace's answer, traces TypeScript again and returns Rust to its untraced row. The Daemon finishes the request it started (CP5: one at a time), so cancelling is the App ignoring that answer; the App has no way to stop it (`agent.callPaths` takes no signal). Closing the view does the same. Asserted in `u7683b_a_new_to_value_drops_the_old_answer_and_traces_typescript_again`.
- **Changes.** With the Changes target there is no Worktree to trace (`agent.callPaths` takes `to` of Tree or Branch): the App asks nothing and the lens shows "Choose Tree or Branch to trace calls" with every file under Not traced. Decided here, the Issue leaving it open. Asserted in `u7683b_opening_the_view_asks_the_lookup_once_and_traces_typescript_once_and_rust_never`.

**U7683c the list holds a flow for each entry point, then Unplaced, then Not traced.** Given the flow fixture, then:
- **Flows.** One item for each `flows[].entry`, named by its function's name, in path order of the entry's file and then of its first line; two entries of one name stay two items. A function reached by two entries sits in both flows and shows its hunks in both, one mark (U7683g). Each flow's row counts the files its sections hold and their `+added -removed` (U7610a). A test function is no special case: CP4 names the entry points and the App re-roots none; the Tests lens holds test hunks (U7679b). Decided here: the Issue's reading re-derives what CP4 returns. Asserted in `u7683c_flows_are_named_in_path_order_then_unplaced_then_not_traced_then_noise`.
- **Unplaced.** One item, listed when a symbol of a done answer sits in no flow (a type, a field, top-level code, or a function of a pure call cycle): its scroll holds, for each file those symbols name in path order, the hunks that overlap no flow's section. Asserted in `u7683c_flows_are_named_in_path_order_then_unplaced_then_not_traced_then_noise`.
- **Not traced.** One item, listed whenever a file remains, holding every changed file that is not noise and that no done answer's `symbols` name, in path order: the files of Rust before Trace, of a language with no server, and of no language at all. Its row says "Not traced" and its file count (decision 3 holds: Flows is never empty); the words about each language the lookup lists without a done answer sit in that language's line (U7683f). A language traced done leaves it, so it holds no file twice. Decided here, replacing #7683's settled sentence that the "Rust not traced" row holds only Rust's hunks: the lookup holds counts and no paths (CP1) and the App keeps no table of languages by extension, so before a trace it cannot tell which file is Rust. A language's line names only what the lookup returned (the language and its file count) and never calls a file Rust unless a done answer's `symbols` named it; the item's files are this residual. Asserted in `u7683f_rust_and_a_language_with_no_server_say_so_and_trace_moves_the_rust_files_into_flows` and `u7683c_flows_are_named_in_path_order_then_unplaced_then_not_traced_then_noise`.
- **Noise.** Generated files and lockfiles end the list as quiet rows, the same as in the other lenses. Asserted in `u7683c_flows_are_named_in_path_order_then_unplaced_then_not_traced_then_noise`.
- **None.** When no callable symbol changed there is no flow item and no word about flows, never "0 flows"; the hunks sit under Unplaced. Asserted in `u7683c_flows_are_named_in_path_order_then_unplaced_then_not_traced_then_noise`.

**U7683d a flow opens its hunks as one scroll in call order, each under its file and function.** Given a flow of three changed functions and the fake App's `agent.compareFile`, then:
- **Order.** Choosing a flow opens one scroll of its sections: depth-first from the entry, callees in the order their call sites appear (the order of `tree.calls`); a function reached twice has one section, at its first place. A section is the hunks of its function's file in which a changed line sits inside the function's span (the new span for an added or changed function, the old one for a removed one), under a header naming the file and the function. Reads, file states, reveals, the editor, J, K, ] and [ are U7678c's and U7678d's, over sections; a file in two sections is read twice. Asserted in `u7683d_a_flow_opens_its_sections_in_call_order_each_with_only_the_hunks_that_hold_its_function` and, for the hunk filter, `u7683d_a_section_keeps_only_the_hunks_with_a_changed_line_its_function_holds`.
- **Notes.** The gutter +, N, a drag and Shift-click work in a section as in a module's scroll; a note keeps its file, side and line, the Message names the file, and a section draws only the notes on lines its function holds. Asserted in `u7683d_a_note_in_a_flow_draws_in_the_section_that_holds_its_line`.
- **A file row.** A file row under a flow opens the flow's scroll at its first section of that file. Asserted in `u7683d_a_flow_opens_its_sections_in_call_order_each_with_only_the_hunks_that_hold_its_function`.

**U7683e a flow's call tree shows its changed calls, and Enter opens the hunk.** Given a flow open, then:
- **Tree.** Above the scroll a "Call tree" disclosure, open, holds the `AppTree` of the flow: the entry, below it each call of it that is added, removed or changed in call-site order, marked with its status, and below a call of a changed function that function's own calls in the same way. Asserted in `u7683e_the_call_tree_marks_added_removed_and_changed_calls_folds_the_rest_and_a_row_opens_its_section`.
- **Enter.** Enter (the tree's own key) or a click on a function opens its section; on a call, the section of the called function when it has one in this flow, else the section of the function that makes the call, which holds the hunk where a removed call was. Asserted for a click on a call in `u7683e_the_call_tree_marks_added_removed_and_changed_calls_folds_the_rest_and_a_row_opens_its_section`.
- **Folds.** The unchanged calls of a function fold into one row "N unchanged calls" and its callers into "Called by N", counting those `FunctionCalls.incoming` holds and `incoming_unchanged` counts, which a cap may cut; a function reached twice expands once and elsewhere is a leaf; a function with no call row says "ends here", and no call the server did not resolve is shown. The folds are asserted in `u7683e_the_call_tree_marks_added_removed_and_changed_calls_folds_the_rest_and_a_row_opens_its_section` and "ends here" in `u7683f_rust_and_a_language_with_no_server_say_so_and_trace_moves_the_rust_files_into_flows`.

**U7683f the trace states read quietly and never block.** Given the fake App's `agent.callPaths`, then:
- **Tracing.** A request pending past 150 ms shows the line "Tracing <Language> calls", one for each language running, and none before (`createLate`); keys, the other lenses and the diff work throughout. Asserted in `u7683f_tracing_shows_after_150_ms_a_failed_trace_says_why_and_retry_asks_again`.
- **Failed.** A `failed` answer, or a request that fails, shows "Couldn't trace <Language> calls", its cause and Retry; a lookup that fails shows "Couldn't trace calls" with the same two. Asserted in `u7683f_tracing_shows_after_150_ms_a_failed_trace_says_why_and_retry_asks_again`.
- **No server.** A lookup row with no found server shows "<Language> has no language server" and its file count, and starts no request; its files sit under Not traced (U7683c). Asserted in `u7683f_rust_and_a_language_with_no_server_say_so_and_trace_moves_the_rust_files_into_flows`.
- **Rust.** A change that holds Rust shows the quiet line "Rust not traced" with the lookup's file count for Rust and Trace until Rust is traced; the files it opens are Not traced's residual (U7683c), not a list of Rust files; Trace makes the request (U7683b), shows "Tracing Rust calls" after 150 ms and, when done, Rust's flows replace them. Asserted in `u7683f_rust_and_a_language_with_no_server_say_so_and_trace_moves_the_rust_files_into_flows`.

**U7683g Viewed applies per flow, at the file's grain.** Given the flow fixture, then marking a flow (V or its button, U7680a) records the `blob` of each file it lists, so a file two flows share reads viewed in both, in Modules and in Logic too (U7680c); a flow is viewed when each file it lists is; marking opens the next unviewed item of the lens, as for a module (U7680b); Unplaced and Not traced are items and take a mark, the Overview and a noise file do not. Decided here: a hunk is known only once its file is read, so the mark stays at the file's grain, as U7680c decided. Asserted in `u7683g_marking_a_flow_viewed_opens_the_next_unviewed_flow_and_a_shared_file_reads_viewed_in_both`.
