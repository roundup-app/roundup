# Plain text

Module: `crates/agents` (the pinned style inside the Brief, under `claude_code/`, P4), `apps/desktop` (Drawer and Rail text). Terms: Brief, Work order, Digest, Decision, Message, Pad (`GLOSSARY.md`); `hold:Plain` is the output style `hold/output-styles/plain.md` of `saadshahd/moo.md`. Principles served: P3, P6. No contract change: a Work order holds only `ask` and `limits`; the Steer of O2 and the Drawer change. Reported in #676, #688 and #726. Ids: Q1–Q10.

**Q1 every Agent writes in hold:Plain.** Given any Agent roundup starts (`agent.spawn` (A4), `rail.startDoor` (A7)), then its E1 Brief carries the whole body of `hold/output-styles/plain.md` from `saadshahd/moo.md` commit `595eda0e3b477d1af1daad82f395073d4f912c8d` (plugin `hold` 0.0.9, file sha256 `0f2c26f0cea8ba39af771d2fdb09db6ae4a7a90c64c272a0a0e967f420e9af1e`), vendored byte for byte at `crates/agents/assets/hold-plain.md`, and tells the Agent to write every reply, including direct Terminal prose, in hold:Plain regardless of recipient or tool (Q11). Delivery is the Brief's `--append-system-prompt-file` (E1) because it needs no install, works in any Project and leaves `CLAUDE.md`, `.claude/` and the user's settings with their bytes. A settings file with `outputStyle` is rejected: it names a style file that must sit in the user's `.claude/output-styles`, which E1 forbids writing. Q11 also loads the complete pinned hold plugin from roundup-owned storage without a user install. The pin moves only in a PR that changes the vendored file, its sha256 above and this clause together. Tests: `q1_pin` hashes the vendored file against the sha256 above (policy for the commit); `q1_brief` reads the argv's Brief of a fake `claude` for an ordinary Agent and a Door and finds the vendored body in both. The real-Daemon harness (the observer of B24) asserts the same on a started Agent's Brief.

**Q3 hold:Plain's layout.** Given any text of Q2, then a status reply of rows renders as an HTML table, never as preformatted text; a code fence and inline code stay `--font-mono`. **Q4 a Work order has visible parts.** Given a Work order `{ask, limits}` (O1), then the Drawer for a running Agent, or U83’s inline overview for a closed Agent, shows, top to bottom: the ask; O10's `done when` part when the order has a done condition; if `limits` is not empty, a heading `limits` over a list of each limit as the Agent wrote it. Where an order has no limits, that part and its label are absent. The O2 Steer lists the same parts with `Limits:` in place of `Must not:`; the Door's B24 policy tells it to write each limit as a positive rule.

**Q5 the Rail's one-line order says it in words.** Given a Work order, then `orderLine` (O6) is the ask, then the limits count in words (`no limits`, `1 limit`, `3 limits`), for example `Give a short tour · 3 limits`; it never contains `must not`. A Clarification order stays `Clarifying: <question>`. The line is cut to one line as O6 says. Test: `q5_` over the four forms.

**Q8 reduce drops no fact the reader needs.** Given a fixture of an Agent's long Message to `you` and its reduced form, then (a) the reduced text is shorter than the original in characters; (b) each fact of the fixture's fact list appears in the original and in the reduced text; (c) none of the fixture's padding phrases appears in the reduced text. The fixture is `crates/agents/tests/fixtures/reduce/door-question.md` (original), `door-question.reduced.md` (reduced) and `door-question.facts` (one fact per line, each a literal string the reader needs: a name, a number, a choice, a path). Its original is shaped like the Door's questions to `you` in #729: it opens "On it.", guesses "My guess is that this Workstream is for finishing that, but tell me if it's something else", introduces its list with "Separately:", and holds a list item of about 110 characters that restates the question above it. Its padding phrases are exactly those four. The reduced text keeps every question, each choice offered and each fact the answer needs, and drops what only repeats or fills. The comparison is a check on a stored pair, not a call to a model, so it is deterministic and costs no tokens. Tests: `q8_reduced_is_shorter`, `q8_every_fact_survives`, `q8_no_padding_phrase_survives`, and `q8_the_check_rejects_a_dropped_fact` (a copy of the reduced text with one fact removed fails (b)), so the check is shown able to fail. The pair is refreshed only with a human-read diff of the facts: policy.

**Q9 the Door's own questions follow Q6 and Q8.** Given B24's Door guidance, then it tells the Door to open a question with the question, to state a guess once as a choice to confirm, to write a list as the choices and nothing around them, and to leave out an acknowledgment ("On it."), a connective ("Separately:") and a list item that restates its question. It adds these lines to the Door's role guidance only; an ordinary Agent's Brief gets Q6's instruction and none of this. Test: `q9_door_guidance_names_the_four_paddings` reads the Door's Brief and finds each rule, and `q9_ordinary_brief_has_no_door_guidance` finds none in an ordinary Agent's (B24).

**Q10 the App renders the Markdown an Agent writes.** Found by the user's report #726: a Door's question to `you` showed `**Driftech:**`, `` `story/` `` and `1. ` as typed. Narrows Q3; changes no contract, App seam command or Token. Not the text's length (#688, Q1). Given text of Q2 from an Agent, then every surface of Q2 renders its Markdown through one renderer, `renderMarkdown`, a library the App already ships or one that loads lazily (rule 7), never one renderer per surface:
- **Elements.** Bold, italics, ordered and unordered lists, inline code, code fences, links and tables become `strong`, `em`, `ol`, `ul`, `code`, `pre`, `a` and `table`; no `**`, backtick or list marker shows as a character. Asserted in `q10_markdown_becomes_elements`, which renders the body quoted in #726 in the Decision Card (U113) and finds in it a `strong`, a `code` and an `ol` of three `li`, no `**`, backtick or `1. ` text node.
- **Safe.** An Agent's HTML is shown as text and never runs or injects markup: a body holding `<img src=x onerror=alert(1)>` renders no `img` element and no `onerror` attribute, and a link whose target is `javascript:` has no `href`. Asserted in `q10_html_is_text`.
- **One renderer.** Each surface of Q2 that exists calls `renderMarkdown` and none draws a generated body as a raw string, except `OrderLine`, which is exempt: O6 and Q5 cut it to one line of plain text, so it renders no Markdown and shows no element. Asserted in `q10_one_renderer`, which renders the same body in each surface but `OrderLine` and finds equal markup for it.
- **Weight.** A heavy renderer is not in the entry bundle: cold start stays under 300 ms (rule 7, policy, checked by `just perf`).
