# UI: row state and quick actions

Acceptance for Issues #4275 and #4335, first journey Understand/Intervene/Review. This specification delivers acceptance only; the implementation Issues remain open in Mode: implement. No RPC, App command, code term or motion is added.

**U4275a every Rail and Todo row keeps its state visible.** Given Workstream, Agent and Terminal rows in the Rail and Todo rows in both the Rail and Shelf, including siblings, children and grandchildren, when the pointer leaves, focus moves elsewhere and another row is selected, then each row retains its current state glyph. Idle/open rows retain their existing idle glyph rather than an empty slot. Existing available facts decide the single glyph: error > needs-you > blocked > working > done > idle; native attention keeps its distinct non-colour glyph. When an existing state Event arrives, the row updates without requiring hover, focus or selection. Connected App test to add: `u4275a_state_updates_without_row_activation`, driving state Events and Todo completion/blocker changes and asserting accessible state identities, including idle, without selecting or opening the rows.

Policy — rendered acceptance: in each list, sibling glyphs align within 1 CSS px; each child glyph moves one shared Token indent step right of its parent, as U4335a specifies. Disclosure keeps its own space. Hover, focus and selection never hide, replace or shift the state glyph. State stays beside the name, distinct from trailing actions, and is never a button or tab stop. Pad leaves acquire no invented state. This supersedes U3789d's omission of idle state; existing tree relationships and disclosure behavior remain. U4335a replaces the former fixed-column-across-depth requirement.

**U4275b Rail quick actions return on hover, focus and selection.** Given Workstream and Agent rows with and without a Worktree, when a row is hovered, contains keyboard focus or is selected, then its trailing quick-action group is available. With none of these conditions, the group is hidden in reserved space and cannot intercept pointer activation; Tab reveals it before activation. Policy — the design critic judges reveal/hide and geometry; neither reveal nor hide changes the row height, top or name width. This restores U426's reveal rule and the RowIcons actions held at commit `6faebb45e`, adapted to current Tokens and current action paths:

- Open folder and Open in editor use that Agent's Worktree directory, or the Door's directory for a Workstream; without a Worktree use the Project folder. Reuse the existing App commands and menu action paths. Project tabs and Todo/Pad leaves gain no Rail quick-action group.

Connected App tests to add: `u4275b_quick_actions_use_the_rows_directory` activates folder and editor by pointer and keyboard for Workstream/Door/Subagent rows, with Worktree and Project fallback, asserting one existing App command with the exact directory per activation and no selection/Open side effect; `u4275b_row_actions_keep_menu_semantics` exercises add, Stop, Resume and stopped-Door start/retry, asserting existing calls, applicability, cancellation and confirmations. `u4275b_tab_reaches_quick_actions` in `apps/desktop/src/todos/u490a_browser.test.ts` drives Tab/Shift+Tab, Return and Space through the restored group, asserting focus and one action per activation; row arrow navigation continues to skip action buttons. Other secondary facts keep their existing reveal rules; Todo/Pad rows keep their two-control budget. State is always visible under U4275a, independent of the group.

## Tree nesting geometry

**U4335a Rail and Todo glyphs indent with their parent connections.** Given the expanded Rail on `tree-40`, including a Workstream with nested Agents and siblings, and expanded root/child/grandchild Todos with a sibling at each child depth in both Rail and Shelf, when the rows render at rest, on hover, with keyboard focus and selected, then the following rendered acceptance holds (policy, design-critic observer):

- **Columns.** One shared Token-derived indent step `S` applies to both trees. For every visible parent/child pair, the child's glyph centre x minus its parent's glyph centre x equals `S` within 1 CSS px. Sibling glyph centres share a column within 1 CSS px. Grandchildren add a second step. Hover, focus and selection change none of these positions.
- **Connections.** Each child's incoming dashed trunk has its centreline at its actual parent's glyph centre x, within 1 CSS px, anchored vertically at that parent's glyph centre. Its elbow turns right at the child's glyph centre y, within 1 CSS px, and reaches the child's glyph. Glyph rectangles mask the anchored endpoints: the visible stroke starts at the parent's bottom edge and ends at the child's left edge, with no stroke drawn inside either glyph or any label rectangle. A last child's trunk stops at its elbow; an ancestor trunk continues past intervening descendants only when a later sibling at that ancestor level remains. Every grandchild connects to its own parent, rather than the root or an intermediate column.
- **Shared implementation.** Rail and Todo trees consume one shared style implementation for indent, trunk and elbow geometry. Their markup supplies depth, ancestry/continuation and glyph/row anchors; separate formulas in `rail/styles.css` and `todos/rowButton.styles.css` do not satisfy this clause. Inspect installed Ark TreeView and the existing `ui/TreeView.tsx` before choosing the shared rendering; rule 9 applies to any added machinery. Keep the existing tree primitive and interaction semantics.

Policy — precedence: this replaces only U4275a's fixed glyph column across depths and U4275c's corresponding elbow placement, including the row-rest D5 sentence in `.agents/data/journey.md`, heading “The owner's visual taste”. State visibility/priority, idle glyphs, native attention, quick actions, fixed Todo height, name-only rows and selection/Open separation remain required.
