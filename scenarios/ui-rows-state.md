# UI: row state and quick actions

Acceptance for Issue #4275, first journey Understand/Intervene/Review. This specification delivers acceptance only; the Issue remains open in Mode: implement. No RPC, App command, code term or motion is added.

**U4275a every Rail and Todo row keeps its state visible.** Given Workstream, Agent and Terminal rows in the Rail and Todo rows in both the Rail and Shelf, including siblings, children and grandchildren, when the pointer leaves, focus moves elsewhere and another row is selected, then each row retains its current state glyph. Idle/open rows retain their existing idle glyph rather than an empty slot. Existing available facts decide the single glyph: error > needs-you > blocked > working > done > idle; native attention keeps its distinct non-colour glyph. When an existing state Event arrives, the row updates without requiring hover, focus or selection. Connected App test to add: `u4275a_state_updates_without_row_activation`, driving state Events and Todo completion/blocker changes and asserting accessible state identities, including idle, without selecting or opening the rows.

Policy — rendered acceptance: in each list, the left edges of these glyphs align within 1 CSS px across sibling and nested rows; compare actual viewport coordinates, without subtracting indentation. Nesting/disclosure uses separate space, leaving the glyph column fixed. Hover, focus and selection never hide, replace or shift the state glyph. State stays beside the name, distinct from trailing actions, and is never a button or tab stop. Pad leaves acquire no invented state. This supersedes U3789d's omission of idle state and earlier tree-indent requirements only where they would shift the state column; existing tree relationships and disclosure behavior remain.

**U4275b Rail quick actions return on hover, focus and selection.** Given Workstream and Agent rows with and without a Worktree, when a row is hovered, contains keyboard focus or is selected, then its trailing quick-action group is available. With none of these conditions, the group is hidden in reserved space and cannot intercept pointer activation; Tab reveals it before activation. Policy — the design critic judges reveal/hide and geometry; neither reveal nor hide changes the row height, top or name width. This restores U426's reveal rule and the RowIcons actions held at commit `6faebb45e`, adapted to current Tokens and current action paths:

- Workstream: add Agent, Clear, Open folder and Open in editor; preserve the existing stopped Door's start/retry path.
- Agent: Stop when running, Resume when stopped and resumable, Open folder and Open in editor. Preserve current applicability and confirmation rules rather than restoring obsolete ones.
- Open folder and Open in editor use that Agent's Worktree directory, or the Door's directory for a Workstream; without a Worktree use the Project folder. Reuse the existing App commands and menu action paths. Project tabs and Todo/Pad leaves gain no Rail quick-action group.

Connected App tests to add: `u4275b_quick_actions_use_the_rows_directory` activates folder and editor by pointer and keyboard for Workstream/Door/Subagent rows, with Worktree and Project fallback, asserting one existing App command with the exact directory per activation and no selection/Open side effect; `u4275b_row_actions_keep_menu_semantics` exercises add, Clear, Stop, Resume and stopped-Door start/retry, asserting existing calls, applicability, cancellation and confirmations. `u4275b_tab_reaches_quick_actions` drives Tab/Shift+Tab, Return and Space through the restored group, asserting focus and one action per activation; row arrow navigation continues to skip action buttons. Keep native menu access and explicit Open from U3789a. Hover/focus/selection are alternative reveal triggers, not additional action prerequisites.

Policy — this overrides U3789d/U3789e's no-hover rule and two-control limit for Workstream/Agent Rail quick-action groups only. The group may exceed two controls on hover, focus or selection. Other secondary facts keep their existing reveal rules; Todo/Pad rows keep their two-control budget. State is always visible under U4275a, independent of the group.

**U4275c Todo rows have one height, elbows and names only.** Given root/child/grandchild Todos in both Rail and Shelf, open, blocked and done Todos, a 300-character name and a Todo with a multiline body, blockers, comments and handed-step details, when rows rest, hover, receive focus or selection, then each row presents its Todo name without body or detail previews. Opening that Todo still reads its unchanged body/details; selection never writes or clears them. Connected App test to add: `u4275c_rows_keep_details_in_the_opened_todo`, selecting and explicitly opening the same identities by Return and Open, asserting detail absence in row content, detail presence in the opened destination and no mutation calls from selection/opening.

Policy — rendered acceptance: one fixed Token-derived row height applies to all these Todo rows (row border-box heights differ by at most 1 CSS px). Names occupy one line, truncating rather than increasing height; the full authored name remains accessible through the existing full-name affordance. Children hang from visible tree elbow lines connecting each child to its parent; grandchildren retain their correct parent connection, with the glyph column fixed as U4275a requires. Disclosure, completion, selection, drag and keyboard semantics remain on the installed Ark TreeView and existing row primitives. Keep failure feedback readable and actionable outside the fixed name row; inline rename retains its existing input and recovery behavior. The opened destination retains body, details and editing.
