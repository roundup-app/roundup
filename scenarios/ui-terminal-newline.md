# UI: shift-enter adds a line in a Terminal (U399)

Module: `apps/desktop` (the webview), with `crates/messages` for the count of unsent input. Ids: U399.

**U399 ⇧⏎ in a Terminal adds a line and submits nothing.** Found by the user's report #1073: after a Takeover (B6, U107, U375), `⇧⏎` in the Agent's Terminal submits. No global shortcut is involved: the App registers none, and every `keydown` listener in `apps/desktop/src` needs `⌘` or `⌥` or a key other than `⏎`. `createXtermEmulators` (`apps/desktop/src/terminal/emulator.ts:107`) attaches no `attachCustomKeyEventHandler`, and xterm 6.0.0 encodes `⏎` as `\r` with or without Shift (`@xterm/xterm/src/common/input/Keyboard.ts:100`), so the Agent's program gets a plain `\r`. Narrows U193 (the Thread's input) for the Terminal; changes no contract, App seam command or Token. Given any Terminal of the webview (an Agent's pane under Takeover, the Door's Terminal, a Terminal bubble), when the user presses `⇧⏎` with focus in it, then the Terminal sends the two bytes `\x1b\r` (the bytes `⌥⏎` already sends) through `terminal.write`, once, and the event does not also reach xterm's own encoding, so no `\r` is sent. (a) `⏎` alone, `⌥⏎`, `⌃⏎` and `⌘⏎` send what they send today; `⇧⏎` with `⌘`, `⌃` or `⌥` held also sends what it sends today. (b) A key repeat of `⇧⏎` adds a line each time. (c) During IME composition `⇧⏎` is left to the composition. (d) `⇧⏎` in the Thread's input is U193's and does not change. (e) The Daemon's count of unsent input (B32, `input_effect` in `crates/messages/src/lib.rs`) reads `\x1b\r` as neither a submit nor a clear: it counts as input, so a Message held for `takeover` stays held after `⇧⏎`, and a following `\r` submits as before. Today it reads the `\r` of `\x1b\r` as a submit, which would release a held Message into half-typed input; that changes with this scenario. Laws: M1 and M3 keep holding (`scenarios/proofs.md`); `proofs/messages` and `docs/messages.md` need no change, because B32's rule that only a `\r` that submits ends the count already excludes it. Tests (`u399_`), in `apps/desktop/src/terminal/u399_shift_enter.test.tsx` against the fake App: `u399_shift_enter_writes_escape_carriage_return_once`, `u399_plain_enter_still_writes_carriage_return`, `u399_alt_enter_and_the_other_chords_write_what_they_did`, `u399_a_held_shift_enter_writes_a_line_each_repeat`, `u399_shift_enter_during_composition_writes_nothing`, `u399_the_door_and_a_bubble_terminal_do_the_same`; and in `crates/messages`: `u399_escape_carriage_return_is_neither_a_submit_nor_a_clear`, `u399_a_message_held_for_unsent_input_stays_held_after_shift_enter`. Policy, asserted by no test: `\x1b\r` is the newline Claude Code reads from `⌥⏎`; a run on the user's Mac with a logged-in `claude` confirms that it adds a line in its input.
