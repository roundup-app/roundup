# UI: shift-enter adds a line in a Terminal (U399)

Module: `apps/desktop` (the webview). Ids: U399.

**U399 ⇧⏎ in a Terminal adds a line and submits nothing.** Found by the user's report #1073: `⇧⏎` in the Agent's Terminal submits. No global shortcut is involved: the App registers none, and every `keydown` listener in `apps/desktop/src` needs `⌘` or `⌥` or a key other than `⏎`. `createXtermEmulators` (`apps/desktop/src/terminal/emulator.ts:107`) attaches no `attachCustomKeyEventHandler`, and xterm 6.0.0 encodes `⏎` as `\r` with or without Shift (`@xterm/xterm/src/common/input/Keyboard.ts:100`), so the Agent's program gets a plain `\r`. Changes no contract, App seam command or Token. Given any Terminal of the webview (an Agent's pane, the Door's Terminal, a Terminal bubble), when the user presses `⇧⏎` with focus in it, then the Terminal sends the two bytes `\x1b\r` (the bytes `⌥⏎` already sends) through `terminal.write`, once, and the event does not also reach xterm's own encoding, so no `\r` is sent. (a) `⏎` alone, `⌥⏎`, `⌃⏎` and `⌘⏎` send what they send today; `⇧⏎` with `⌘`, `⌃` or `⌥` held also sends what it sends today. (b) A key repeat of `⇧⏎` adds a line each time. (c) During IME composition `⇧⏎` is left to the composition. (d) Retired by U467 with the Thread's input. (e) Retired by #3563: the Daemon no longer counts the user's unsent input (B32 is retired), so `\x1b\r` has no submit-or-clear meaning to preserve; no Message is written to the Terminal (B3563c). Tests (`u399_`), in `apps/desktop/src/terminal/u399_shift_enter.test.tsx` against the fake App: `u399_shift_enter_writes_escape_carriage_return_once`, `u399_plain_enter_still_writes_carriage_return`, `u399_alt_enter_and_the_other_chords_write_what_they_did`, `u399_a_held_shift_enter_writes_a_line_each_repeat`, `u399_shift_enter_during_composition_writes_nothing`, `u399_the_door_and_a_bubble_terminal_do_the_same`. The two `crates/messages` tests of this clause are retired with the byte counter. Policy, asserted by no test: `\x1b\r` is the newline Claude Code reads from `⌥⏎`; a run on the user's Mac with a logged-in `claude` confirms that it adds a line in its input.
