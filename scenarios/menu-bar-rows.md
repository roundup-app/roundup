# Menu-bar rows read like a native menu

Module: `crates/desktop` (projection in `menu_bar.rs`) and `crates/native` (AppKit rows). Ids: U5959a, U5959b, U5959c, U5970. Work order: [#5959](https://github.com/roundup-app/roundup/issues/5959). Journey: Understand → Intervene (`.agents/data/journey.md`, “What must work”). This revises U5502's “Each Agent row is one line” clause and U5503's one-line row clause in `scenarios/ui-state-alerts.md`, and adds Ready recency; the menu-bar mark itself is unchanged. All tests below are planned observers, not passing claims.

**U5959a each Agent row has two lines, an age pill and a state disc.** Given the menu-bar list with Waiting and Ready Agents, then:

- The heads stay `Waiting` and `Ready` in system grey, as native section headers. Test: `u5959a_heads_are_native_section_headers`, at the native adapter seam.
- Line one is the Agent name in sentence case (hyphens become spaces, first letter capital; other letters literal), with its age as the native menu badge at the right edge; the age text and refresh are U5502's. Line two, grey, is the Agent's Status label (what it needs, or its Live line, shortened as U5502 says), then ` · ` and the Project name; with one open Project U5502's rule still omits the Project name and the separator. Names and labels stay literal text. Test: `u5959a_rows_project_title_badge_and_subtitle`, over the projection with a supplied clock, hyphenated, emoji and non-Latin names, and one and two open Projects.
- The row image is a filled disc in the Kind Glyph tone (`glyphOf` in `apps/desktop/src/ink/glyph.ts`; colours from `apps/desktop/src/tokens.css`): `needs-you` amber with `!`, `error` red with a cross, Ready accent with a check. The symbols differ per state, so the state reads without colour. The colours are palette-coloured SF Symbols that follow light and dark mode. Test: `u5959a_state_picks_disc_symbol_and_tone`, asserting the symbol and tone chosen per state, never pixels. Policy/native rendered observer below.
- No submenus, per-row choices, motion, sound or custom-drawn rows; the row's activation, Project/Agent identity and acknowledgement are U5502's, unchanged. Test: `u5959a_row_activation_is_unchanged`, activating a row through the menu-event seam.

**U5959b Ready keeps only the last hour.** Given Ready Agents whose unseen results arrived at different times, then:

- Waiting keeps every waiting Agent. Ready keeps the Agents whose latest unseen finish or publication is at most one hour old at the supplied time (exactly 60 min is kept). Older Ready Agents leave the rows and fold into one `n earlier…` command, which opens roundup, chooses nothing and acknowledges nothing, as `n more…` does. Their results stay unseen, and an Agent that gets a new result returns to the rows. Test: `u5959b_ready_rows_keep_the_last_hour`, with ages 59 min, 60 min, 61 min, a Waiting Agent older than an hour, and a later finish on an older Agent.
- The seven-row limit still applies across both groups after the recency cut, taking Waiting before Ready as U5502 orders. The commands are `n earlier…` for hour-old Ready Agents, then `n more…` for rows over the limit, then `Open roundup`; n is the Agent count each holds, and a command with n = 0 is omitted. An Agent counts once. A group with no row left omits its head, and with no row at all `Nothing for you` shows, even when only `n earlier…` remains. The mark `●`, `•`, `○` keeps U5502's rule over the full eligible list, so an hour-old Ready Agent still gives `•`. Test: `u5959b_limit_and_commands_after_the_cut`, with 0, 7, 8 and ten Agents, old Ready Agents only, and overflow in each group.

**U5959c the Dock list takes the same rows.** Given the Dock section of U5503, then its Agent rows use U5959a's look and its list uses U5959b's recency cut: the first five rows after the cut, the heads outside the limit, `n earlier…` then `n more…` (n counted against five) then `Open roundup` as U5503 orders. The Dock keeps no second membership. Tests: `u5959c_dock_rows_share_the_menu_bar_look` and `u5959c_dock_applies_the_hour_cut_and_five_row_limit`, against the same projection input as U5959a/b. The `set_menu_bar` command in `scenarios/app.md` carries each entry's separate subtitle and state so the adapter builds the two lines; every caller changes in the same PR, and no Message, Route, Held or Takeover law changes.

**U5970 the hour cut follows the clock.** Given a Ready Agent whose latest unseen finish or publication is under an hour old and no other Agent event, when the clock passes the hour while the App stays open, then the menu-bar list and the Dock list drop its row and count it in `n earlier…` without any event, and the mark keeps `•` (U5959b). Tests:

- `u5970_ready_row_folds_when_the_hour_passes`, in `apps/desktop/src/app/u5502_connected_menu.test.tsx` beside the other `watchMenuBar` tests, with a supplied clock and fake timers: a Ready Agent 50 min old appears as a row, then after 10 more minutes (60 min, kept) and one more tick (over 60 min) the `set_menu_bar` call replaces it with `1 earlier…` in both `entries` and `dock`.
- `u5970_the_next_cut_is_scheduled_not_polled`, same file: the App schedules one timer for the earliest moment a kept Ready row turns over an hour old, re-arms it after each projection, and none while no Ready row is within the hour; it sends nothing when no row changed, and a later finish on the Agent, which resets its age, moves the timer.

Policy: the timer is cleared when the watcher is cleaned up, and it reads the same supplied clock as the projection.

Policy/native rendered observer, reported by the user on their Mac, in light mode, dark mode, grayscale and with a highlighted row: open the menu-bar list and the Dock menu with Waiting (`needs-you` and `error`), recent Ready and hour-old Ready Agents; see two-line rows, a grey pill age at the right edge, amber `!`, red cross and teal check discs, grey system heads, `n earlier…`, and no difference between states in grayscale beyond the symbol. Chromium cannot show a native menu, so this specification and the implementation's tests claim no Mac observation. No webview path changes, so no capture is required.

Policy, Integrate: Tauri's `tauri::menu` items take plain text only, so the rows use AppKit's `NSMenuItem` `subtitle`, `badge` (`NSMenuItemBadge`) and `sectionHeaderWithTitle`, and an `NSImage` symbol with a palette configuration, through `objc2-app-kit` 0.3 in `crates/native`, the sole native FFI owner. Rule 9: the implementation PR carries the `Reuse:` section; candidates to compare are Tauri's `tauri::menu` and `muda` (the menu crate Tauri uses) against the installed `objc2-app-kit`; evidence must show which of them lacks `subtitle`, `badge`, section headers or palette symbols. Gates: P3 (no motion or sound), P9 (zero turn-producing calls) and P12 (row identity unchanged) as U5502 states them.
