# Todo bodies keep the shared reading width

Acceptance for #5705. Makes U4698b's Todo measure explicit (`scenarios/ui-item-view.md`, heading U4698b) while preserving U5574a/b's Pad-only typography and measure. Journey stage: Review — read a resulting Todo from its Workstream. This specification supplies acceptance, not rendered implementation evidence.

**U5705 nonempty Todo bodies keep their reading column.** Policy, rendered acceptance: given `tree-40` at 1512×950 with default interface scale, a Todo containing several paragraphs of ordinary prose and a Pad containing the same prose, when the user opens the Todo expanded, then its body editor uses the shared reading-width Token and document gutters, without inheriting the Pad-specific width cap. The title, formatting toolbar and body retain U4698b's common document left edge. The Todo measure is unchanged by opening a Pad first and then reopening the Todo.

Policy: compare the editor's actual rendered column, not only its declared `max-width` or an empty body placeholder. Use enough prose to wrap multiple full lines. The reported 579px versus 713px is diagnostic context, not a new pixel constant or Token value. The accepted Todo measure remains U4698b's shared 68ch target at sufficient available width; the Pad-specific measure applies only to Pads. Inspect ancestor constraints as well as the editor so a second narrower cap cannot satisfy this acceptance merely by changing the computed rule.

Policy, regressions: when the same Todo is minimised and expanded again, its body uses available width with existing Token gutters, without horizontal page scrolling, lost text or displaced formatting controls. When the Pad is opened in each size, its accepted Pad measure, type scale, spacing and block-handle gutter remain as on the matching main baseline. Preserve existing Pad width choices wherever implemented; this repair adds no control, preference, Token or typography redesign. Keep title/body editing, Markdown, autosave, draft restoration, focus, permissions, and Todo/Pad identity and Home unchanged. No RPC, App command, storage or domain-model change is ordered.
