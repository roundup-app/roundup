# Send feedback… files a GitHub Issue (U7210a to U7210f)

Module: `apps/desktop/src`, `crates/desktop`, `crates/rupd`, `crates/contracts` and `contracts/generated/`. Ids: U7210a, U7210b, U7210c, U7210d, U7210e, U7210f. Acceptance for [#7210](https://github.com/roundup-app/roundup/issues/7210). Decided by the owner (2026-11-15): "notice the send feedback option, we should have it in our command list and roundup menu, mac native menu"; the owner picked that it files a GitHub Issue. Overturns FB1 to FB6, U6381a, FB8 and FB9 of the earlier Feedback report (a comment on #6163 with logs, a kept folder, a retry and a setting); FB7 and FB10 (`scenarios/feedback-facts.md`) hold, since the versions line reads the build id they stamp.

Policy, Must not: no service other than the owner's `gh` and GitHub; no log, Pad or Terminal output is attached unless the owner typed it into the text; no environment value, token or output of `gh auth` is read, stored or sent.

**U7210a Send feedback… is in the command list, the application menu and on `⇧⌘F`.** Given a connected Project, when the owner searches the command list (`switcher.open`) for "feedback", then the row **Send feedback…** is listed and choosing it opens the dialog (U7210b); when the owner chooses **Send feedback…** in the application menu (beside About and Update available; enabled while a Project is open, as `Fork for development…` is), then the App seam event `open-feedback` (no payload, `scenarios/app.md`) opens it; `⇧⌘F` still opens it as the registry action `feedback.open`, so a focused Terminal does not receive it and Help lists it. A request while the dialog is open or its shot is being taken does nothing. Tests: `u7210a_the_command_list_offers_send_feedback`, `u7210a_the_menu_event_opens_the_dialog`, `u7210a_the_chord_opens_the_dialog_and_a_terminal_does_not_receive_it`, `u7210a_a_second_request_opens_nothing_more` in `apps/desktop/src/feedback/`; `u7210a_the_application_menu_holds_send_feedback_and_emits_open_feedback` in `crates/desktop/src/menu/tests.rs`.

**U7210b one small dialog asks what happened.** Given the dialog, then it shows a multi-line field labelled "What happened?" with focus in it, a checkbox **Attach screenshot** on by default, a read-only line `roundup <version> (<commit>) · herdr-core <version> · macOS <version>`, and the buttons Close and Send; herdr-core's part of the line is left out when no core answers. Send waits for text that is not blank and for `feedback.check` (U7210e), reading **Checking gh…** until it answers; while it waits it is `aria-disabled`, never the `disabled` attribute, its reason is its title and pressing it sends nothing. Escape and Close dismiss it, discard the text and return focus to where it was. Tests: `u7210b_the_dialog_shows_the_field_the_checkbox_the_versions_and_two_buttons`, `u7210b_send_waits_for_text`, `u7210b_escape_and_close_dismiss_and_restore_focus` in `apps/desktop/src/feedback/`.

**U7210c Send files one Issue through the owner's `gh`.** Given the dialog with text, when the owner presses Send, then `feedback.send {text, shot?, versions}` runs the `gh` on the Daemon's `PATH` once, as A5168d says: `gh issue create --repo roundup-app/roundup --title <title> --body-file -`, with `--attach <png>#<alt>` when a shot is sent, and answers `{number, url}`. The title is the first line of the text that is not blank, trimmed and cut to 70 characters; the body on stdin is the text, a blank line, then the versions line. While `gh` runs Send reads **Sending…** and the dialog stays open, and Close still closes it; when the call ends the dialog closes and a notification names the Issue number and opens its URL on click, also when the owner cancelled meanwhile. When the call fails, the dialog stays open with the failure inline (A5168c's one line naming `gh`), the text and the checkbox as they were. `feedback.send` is the owner's: M5 lists it under No tool, and an Agent's call is `FORBIDDEN`. Tests (`u7210c_`, a fake `gh` on `PATH` that records argv, stdin and environment): `u7210c_send_runs_one_issue_create_with_the_body_on_stdin_and_the_shot_attached`, `u7210c_the_title_is_the_first_line_cut_to_70_characters`, `u7210c_no_shot_runs_no_attach`, `u7210c_a_failure_names_gh_with_its_first_stderr_line`, `u7210c_no_token_variable_is_set_or_read`, `u7210c_an_agent_is_forbidden` (`crates/rupd`); `u7210c_send_closes_the_dialog_and_the_notification_opens_the_issue`, `u7210c_a_failed_send_keeps_the_dialog_with_the_error_and_the_text`, `u7210c_the_app_stays_usable_while_it_files` (`apps/desktop/src/feedback/`); and `m5_every_app_action_has_a_tool_or_a_reason`.

**U7210d the screenshot is the window as it was, under 2 MB, and older `gh` sends without it.** Given the request (U7210a), then the App captures the roundup window as drawn before the dialog, Terminal canvases included, and the dialog opens after the capture. The capture sits behind a seam (`feedback_capture` in `crates/desktop`, a fake in tests); a PNG over 2 MB (2,000,000 bytes) is scaled down until it fits. A failed capture opens the dialog with no shot and one line saying why; Send still works. With the checkbox off no shot is sent. Given `gh` older than 2.103, which has no `--attach`, then `feedback.check` answers `attach: false`, the dialog says in one line that the screenshot is not sent, and `feedback.send` runs no `--attach`. Tests: `u7210d_a_shot_over_2_mb_is_scaled_under_it`, `u7210d_a_shot_under_2_mb_is_unchanged` (`crates/desktop`); `u7210d_an_older_gh_attaches_nothing`, `u7210d_gh_2_103_attaches` (`crates/rupd`); `u7210d_the_shot_is_requested_before_the_dialog_mounts`, `u7210d_a_failed_capture_opens_the_dialog_without_a_shot`, `u7210d_the_checkbox_off_sends_no_shot`, `u7210d_an_older_gh_says_so_and_sends_no_shot` (`apps/desktop/src/feedback/`).

**U7210e no `gh`, or `gh` signed out, offers Copy instead of Send.** Given the dialog, when `feedback.check` answers that `gh` is missing or signed out, then the dialog says which in one line and shows **Copy**, its primary button, instead of Send and the **Attach screenshot** checkbox, which changes nothing there; Copy puts the text and the versions line on the clipboard. `feedback.check` runs `gh --version` and `gh auth status` and reads herdr-core's version from its `hello`; it reads no token. Tests: `u7210e_check_names_a_missing_gh_a_signed_out_gh_and_a_ready_one`, `u7210e_check_reads_the_herdr_core_version` (`crates/rupd`); `u7210e_without_gh_the_dialog_says_so_and_copies_the_text_and_versions`, `u7210e_signed_out_says_so` (`apps/desktop/src/feedback/`).

**U7210f the earlier Feedback report is gone.** Given `main`, then there is no `feedback.retry`, no kept-report folder, no Feedback Issue setting and no log in what is sent. Policy: the compiler, the contract (`contracts/generated/`) and M5's list hold it; no test asserts an absence.
