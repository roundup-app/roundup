# UI: Bubbles outlive the Terminal tab host

Acceptance for #4424. Journey stage: Intervene — a Terminal opened by keyboard stays available for input. This extends U469 and U4322b without changing tab eligibility, ownership, opening guards or menu actions. The implementation uses the existing connected Project, Bubbles, Screens and fake App seams; no new RPC method, App seam command, Token or glossary term is ordered (policy).

**U4424a a keyboard-opened Terminal needs no tab host.** Given an open Project with one selected Workstream and no Terminals, mount `Bubbles` with its existing shared Screens and Pane but without a `.resource-agent` sibling. When the user presses ⌘T once and the normal `terminal.open` reply and `terminal.changed` arrive, then exactly one `terminal.open` names that Workstream, the returned Terminal's Bubble is connected to the document and shown, and its emulator owns keyboard focus. Typing through that emulator sends one `terminal.write` to the returned Terminal with the exact bytes. No `terminal.close` or Agent start is sent. Planned Vitest observer: `u4424a_cmd_t_opens_and_accepts_input_without_a_tab_host` in `apps/desktop/src/bubbles/u4424_host.test.tsx`, using the fake App and injected emulator, not a mocked Bubble or an assertion on a view flag.

**U4424b replacing the tab host keeps the shown Bubble.** Given a mounted `Bubbles` with a `.resource-agent` sibling and one keyboard-opened, shown Terminal, retain that Terminal's Bubble element and emulator and deliver output to it. When the sibling is removed while Bubbles, Pane, Project and Terminal remain mounted, then the same Bubble element stays connected and shown, the same emulator is not disposed, and its previously delivered output is retained. Output delivered while the host is absent still reaches that emulator, and input through it still writes the exact bytes to that Terminal. When a new `.resource-agent` sibling is mounted in the old sibling's place, those same Bubble and emulator identities and retained output remain; input still reaches that Terminal. Neither host change calls `terminal.open` or `terminal.close`, starts an Agent, or writes anything except the input explicitly typed in the probe. Planned Vitest observer: `u4424b_tab_host_replacement_keeps_the_bubble_and_terminal` in `apps/desktop/src/bubbles/u4424_host.test.tsx`. Control only the host sibling's presence through a fixture signal; do not unmount Bubbles or simulate a Daemon failure. Assert connectivity during the absent interval as well as after replacement: a surviving emulator alone does not prove a surviving Bubble.
