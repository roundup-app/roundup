# UI: rename a Terminal in its tab

**U511a Terminal names edit in place and survive a webview reload.** Work Issue: #2177. Journey stage: Intervene (`.agents/data/journey.md`, “What must work”): keep direct Agent access while naming a Workstream shell or the selected Agent's Run. Terms: Terminal, Bubble, Run, Workstream (`GLOSSARY.md`). This is implementation acceptance; the specification changes no rendered surface (policy).

Scope (policy): own `apps/desktop/src/bubbles/`, with the minimum shared Ark Editable wrapper in `apps/desktop/src/ui/` if none exists. Reuse the shared Menu for the context action. Do not restyle the tab strip's border or grey pill, Project tabs, resource strip or Bubble geometry. No RPC, contract, App seam command, domain name or Token change is needed. Preserve U469's visibility, close, open, keyboard, eligibility and overflow behavior, except that interacting with the name's editor consumes editing gestures and keys rather than toggling the Bubble. An input must not be nested in a button (policy).

- **Entry.** Given a shown or minimised Terminal tab, when its name is double-clicked, then that name becomes one inline, single-line text field at the same location, focused with the entire current displayed name selected. The tab's context menu is the system menu (U2694a) and offers `Rename` and `Close`; choosing `Rename` enters the same field, from the pointer or from the keyboard route of U2694a. The shared in-app Menu and its `role="menu"` tests (`u511a_rename`, `u511a_browser`) are retired, and `u2694b_rename_starts_the_in_place_edit_of_each_object` proves `u511a_context_rename_uses_the_same_editor`. Editing does not close a Terminal, start a drag, write to its emulator or change which Bubble is shown; the two clicks of the double-click must not leave a different visibility state. Single-click outside editing retains U469's tab activation. Tests: `u511a_double_click_selects_the_current_name`, `u511a_context_rename_uses_the_same_editor` (pointer and keyboard cases), `u511a_edit_entry_preserves_terminal_visibility` and the existing U469 visibility observer; planned in `apps/desktop/src/bubbles/u511a_rename.test.tsx` and `u511a_browser.test.ts`.
- **Commit and cancel.** Given the field open, Enter or a click outside commits the trimmed value once and closes the field; Escape closes it with the prior name and no save, including when blur follows. Empty or whitespace-only input clears the custom name and restores the default; unchanged input closes without a write. The default remains the current Terminal title trimmed, falling back to its program, as `apps/desktop/src/bubbles/places.ts`, `nameOf`, defines on main. Editing keys and text never reach `terminal.write` or trigger a Bubble shortcut. Enter during IME composition does not commit. Clicking another tab or `New Terminal` commits before that control performs its own normal action, without swallowing the click. Enter/Escape return focus to the edited tab; clicking away leaves focus at the clicked target. Tests: `u511a_enter_commits_once`, `u511a_click_away_commits_before_the_target_action`, `u511a_escape_then_blur_keeps_the_previous_name`, `u511a_empty_restores_the_default`, `u511a_unchanged_closes_without_writing`, `u511a_editing_keys_do_not_reach_the_terminal`, `u511a_composition_enter_keeps_editing` and `u511a_completion_preserves_expected_focus`, in the planned files above.
- **One name for one Terminal.** Given a successful rename, the tab text, full hover title, visibility button's accessible name, `Close <name>` accessible name and Bubble header/name all show the same saved name. Renaming one of two identically named Terminals affects only that Terminal id. The name survives minimise/restore, selection away/back and a webview reload in the same window with the same live Daemon, alongside the existing saved Bubble places. Later program-title updates do not overwrite a custom name; clearing it reveals the current default and subsequent title updates again. A closed Terminal's name is not inherited by another Terminal, including a reused id after a Daemon restart. Terminal lifetime is unchanged: no Terminal or name restoration across Daemon restart is promised (`GLOSSARY.md`, “Terminal”). Tests: `u511a_every_name_surface_updates`, `u511a_duplicate_names_are_independent`, `u511a_name_survives_selection_and_webview_reload`, `u511a_custom_name_survives_title_updates` and `u511a_closed_or_restarted_terminals_do_not_inherit_names`, in the planned files above. Use the existing storage boundary; do not add another storage helper (policy).
