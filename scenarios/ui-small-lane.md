Do not edit another lane, `ui/`, `keys/`, `tokens.css`, manifests, lockfiles, contracts or the App seam. `orders/` is excluded. Missing shared capability is a native prerequisite against UI epic #1647, never a local primitive. Shared-provider work described below belongs to that prerequisite, not the lane (policy).

Direction: #1606. Require the merged implementations of #1629, #1627, #1630 and #1608 (registry implementation #1869), not their specification closures. Retain current Token names; #1852 is not planned and is neither a prerequisite nor work to revive (policy). This specification introduces no domain names or new product behaviour. Planned tests below are implementation obligations, not claims of passing tests on this specification head.

Lane acceptance (policy): #2004 implements U501 (controls, copy and registry scope), U502 (Splitter adoption), U503 (Toast adoption) and U493 (regressions, captures and budgets). U491/U492 specify the shared-provider prerequisite, not lane callers. Verify delivered shared capabilities before migration; a closed specification alone is not evidence of implementation. The lane preserves Decision outcomes, resource polling/formatting, Bubble interactions, Markdown bytes and opt-in keystroke measurement through the existing live scenarios in all nine directories (policy).

The Understand and Intervene stages of `.agents/data/journey.md` require readable Status and resources, quiet routine progress and an actionable Decision. Preserve those behaviours and the Review stage's readable outcomes; this migration claims no new storage or real Agent outcome (policy).

**U501 Owned controls, keys and copy use shared infrastructure.** Given every control in the nine owned directories, including conditionally revealed controls, when reached by pointer and keyboard, then each icon-only button has a nonempty accessible name and a shared Tooltip showing that name on hover and focus (`u501_controls_have_names`, planned browser observer in `ink/`, with a caller inventory and reveal steps for all nine directories). Every icon-only button uses `ui/IconButton`, tooltip `ui/Tooltip`, menu `ui/Menu`, modal `ui/Dialog`, confirmation `ui/AlertDialog`, and any tabs or segmented choices the matching Ark component (policy). Ark owns component navigation, focus trapping, dismissal and focus return (policy).

Given a multiline failure or truncated resource label, when hovered and keyboard-focused, then the full unchanged content is exposed by a shared Tooltip (`u501_full_content_is_available`, planned in `ink/`, covering `resources/`). This replaces U80's native-title requirement in `scenarios/ui-surfaces.md`, heading `U80 one failure line`, for the shared owned error renderer and its callers, and native resource titles only; alert role, immediate one-line rendering, Ink, full message, replacement and clearing remain unchanged. Authored names, paths, Markdown, Terminal output, returned errors and numeric data remain content, not catalogue keys (`u501_copy_preserves_content`, planned in `ink/`, exercising every owned formatter/renderer). All App-authored visible strings, placeholders and accessible names come from `copy.ts`; only entries used by this lane change (policy).

Given focus in a Bubble or another owned shortcut scope, when its existing shortcut is pressed, then only the registry-selected action runs; Help or a higher layer suppresses underlying actions, and disposal or Project switching leaves no stale callback (`u501_shortcuts_follow_focus`, planned in `bubbles/`, using the real registry). Move App shortcuts to `keys/` subscriptions in the owned scope; Ark owns component arrows/Escape and the Terminal/editor keeps its native typing. No owned ad hoc keydown listener or parallel JSX shortcut dispatcher remains (policy). The opt-in keystroke probe in `perf/` may observe key timing as measurement, never dispatch App actions or become enabled in ordinary builds; preserve its existing K1/K2 opt-in and accounting tests (policy).

**U502 Resize edges use Ark Splitter without changing widths.** Given a Project at 1512×950, when the Rail edge is Tab-focused and ArrowRight then ArrowLeft are pressed, then its width increases and decreases by 16 px, its named vertical separator reports the current pixel value, and each press commits once (`u502_rail_arrow_keys_resize`, planned headless browser test in `resize/`). Given the Shelf open, its edge has the inverse arrow direction, 240–560 px limits and 320 px reset; closing it removes the edge from the Tab order (`u502_shelf_keys_and_visibility`, same observer).

Given either edge, when dragged then released, then width follows the pointer within its limits and commits at the end; Escape restores the starting width, and selection and scroll positions remain unchanged (`u502_drag_commit_and_cancel`, planned in `resize/`). Keep U389/U390's current Terminal fit/call behaviour and subsequent scenario amendments, including at most one refit per shown Terminal at Rail drag end (`u502_resize_preserves_terminal_fit`, same observer with fake App call records). Keep existing persistence, narrow layout and no-horizontal-scroll observers (policy).

Both edges rendered by `resize/` use a shared `ui/` wrapper over Ark Splitter; delete the hand-written pointer capture/move/up/cancel and keyboard state machine in `ResizeEdge.tsx` (policy). A shared-provider prerequisite must expose controlled pixel widths, limits, preview/end notifications, accessible separator semantics and these keyboard/reset/cancellation capabilities without requiring lane edits to App layout or another directory. If integration requires a layout owner outside scope, file that scoped prerequisite; do not expand lane ownership (policy). Library navigation belongs to Ark, not the shortcut registry (policy).

**U503 Toasts use the shared library lifecycle and keep event policy.** Given the real shared Toast provider and an eligible event, when shown, focused, hovered, activated and dismissed, then U410–U414 in `scenarios/ui-toasts.md` still hold: event exclusions, selected-Agent suppression, one chime, away holding without replayed sound, replacement/coalescing, at most three visible cards including the summary, five-second restart after hover/focus, Escape dismissal, correct target navigation and visible missing-target error (`u503_shared_toast_preserves_lifecycle`, planned in `toasts/`, retaining existing independent event-policy proofs). Given no event and after the last Toast leaves, when pending work is inspected, then no Toast DOM, pending timers, polling loop or audio object remains (`u503_shared_toast_idle_runs_nothing`, planned in `toasts/`, mounting the real provider). Measure the real adopted provider with U493's budgets. ## Shared providers

Scope (policy): U491 and U492 belong to #2003 under UI epic #1647. They own only `apps/desktop/src/ui/` and its own entries in `apps/desktop/src/copy.ts`, independently of the lane migration. No lane callers, App layout, contracts or App seam change. A manifest/lockfile change is allowed only when a real installed-Solid API probe proves the required API absent, with measured evidence and the shared UI owner's review. These scenarios preserve the Understand, Intervene and Review journey stages described above; they introduce no domain names (policy).

**U491 Shared Splitter adapts controlled pixel widths to Ark.** Given the real shared wrapper mounted with controlled widths, limits, reset values, direction, accessible names and preview/end callbacks, when the owner changes a width or the measured root changes between 1512 px, then the separator reports the current pixel width and limits, and subsequent resizing uses the new values without a remount (`u491_controlled_pixels_follow_owner_and_root`, planned real-wrapper browser observer in `ui/`). Exercise Rail 288 px, limits 252–480 px, and Shelf 320 px, limits 240–560 px; clamp to available room as the existing width controls do (same observer). Both separators have a nonempty accessible name, vertical orientation and pixel-valued current/minimum/maximum semantics (same observer).

Given a focused separator, when ArrowRight/ArrowLeft are pressed, then the Rail grows/shrinks by 16 px and the Shelf shrinks/grows by 16 px; Shift changes the step to 64 px, Home/End select the effective minimum/maximum, and Enter or double-click restores the configured reset width. Each completed action emits one end callback at its final clamped pixel width (`u491_keys_limits_and_reset`, planned real-wrapper browser observer in `ui/`). Given a drag, when the pointer moves beyond either limit then releases, then preview callbacks track clamped pixel widths and one end callback carries the final width; Escape during a drag restores its starting width with a preview and emits no committed end callback (`u491_drag_preview_end_and_escape`, same observer). Disposal during a drag leaves no pending frame or interaction listener and no later callback (same observer). A hidden or disabled Shelf edge is absent from the Tab order (`u491_hidden_edge_is_not_focusable`, same observer).

Given a fixture in `ui/` using the real Layout, existing width controls and U507's host binding, when the shared adapter binds from either edge with the Shelf reserved, overlaid or closed, then Ark measures the actual 1280/1440 px root, resolves its real panels and resizes the intended region while both layout grids and the absolute Shelf placement remain intact (`u491_existing_layout_binding`, planned real-wrapper browser observer in `ui/`). Exercise default widths and the 1280 px Rail 480/Shelf 560 overlay case from U507; keep selection, draft and scroll position through preview, commit and cancel (same observer). Importing those existing surfaces into the fixture does not authorize editing them (policy). No App caller must replace its layout, and no narrow edge may serve as the measured root (policy). Persistence and Terminal fitting remain the lane's responsibility; callbacks must let it retain U502's end-only commit/refit behavior (policy).

Use installed Solid Ark Splitter primitives and their real machine for resizing/navigation; adapt pixel units, host binding and reset/cancel behavior through that API, never a second pointer/keyboard state machine (policy). Probe the installed `useSplitter`, root/provider, panel and trigger APIs in an actual Solid mount; stub missing test-platform geometry only in unit probes, and verify real geometry in the browser tests above. Record the version, exercised APIs and any failure/repair on the Issue (policy). A mock library or a source-text assertion cannot satisfy these observers (policy).

**U492 Shared Toast owns the real Ark lifecycle, not domain policy.** Given a real mounted shared provider configured by a caller, when the caller creates, updates/replaces by identity, activates or dismisses a card, then the real Ark Toast lifecycle renders the supplied name/content, updates without duplicate cards, invokes activation once and removes dismissed content after exit (`u492_configurable_provider_lifecycle`, planned real-wrapper test in `ui/`). The caller can supply ordering, visibility limit, content, identity and activation/dismissal callbacks; exercise the lane's newest-first three-card limit with a caller-supplied summary counted as one card (same observer). Dismissed or replaced cards must not replay later from Ark's overflow queue (same observer). Event eligibility, selected-Agent suppression, chime throttling, away holding, coalescing and summary calculation stay in the lane; the provider neither subscribes to domain events nor creates audio (policy). No second lifecycle engine or parallel expiry timer is allowed (policy).

Given a card with a five-second duration, when 4999 ms elapse, then it remains; at 5000 ms it starts dismissal (`u492_five_second_expiry`, planned real-wrapper fake-clock test in `ui/`, waiting for exit before checking removal). Given hover or focus within the card, when more than five seconds elapse, then it remains; after both hover and focus leave, it receives a fresh full five seconds, not the unelapsed remainder (`u492_hover_focus_restart_full_duration`, same observer, including overlapping hover/focus and repeated enter/leave). The timer stays paused while either condition holds (same observer).

Given the real provider in a headless browser, when reached by Tab, then each actionable card has the same accessible words as its supplied visible name/content, is announced in a polite live region and activates exactly once by click, Enter or Space, invoking the caller and dismissing the card (`u492_accessible_activation`, planned real-wrapper browser observer in `ui/`). Escape with focus within a card dismisses it without activation (`u492_escape_dismisses`, same observer). Missing-target navigation and its visible failure remain caller policy, not shared-provider behavior (policy).

Given a newly mounted empty provider, and again after the last card exits or the provider unmounts, when DOM and pending work are inspected, then no Toast DOM, pending expiry/animation timer, scheduled frame, polling loop or audio object remains; advancing the clock creates no card or callback (`u492_idle_and_disposal_run_nothing`, planned real-wrapper fake-clock test in `ui/`, testing unmount while hovered/focused as well). ## Reuse evidence

U491/U492 select installed Solid Ark Splitter and Toast, sharing the existing `ui/` dependency rather than adding a primitive layer (policy). U507 adds only Layout bindings, not a primitive (policy). For Splitter, its root/panel API is linked below and the existing real-library Layout observer demonstrates the grid binding. [Corvu Resizable](https://corvu.dev/docs/primitives/resizable/) is a Solid alternative with controlled panels, but its documented Shift-arrow behavior expands/contracts fully rather than the required 64 px step. Its [npm metadata](https://registry.npmjs.org/@corvu%2fresizable) reports 0.2.5, last modified 2025-05-04; it is not selected because it also cannot supply this work order's required Ark API. No custom interaction engine is authorized.

Policy: consume the established wrappers; this lane adds no primitive. [Ark Splitter](https://ark-ui.com/docs/components/splitter) exposes controlled panels and resize callbacks; [Ark Toast](https://ark-ui.com/docs/components/toast) exposes duration, updates and maximum-visible policy. Ark is already installed at `^5.39.3`; its [Solid npm release metadata](https://registry.npmjs.org/@ark-ui%2fsolid) dates 5.39.3 to 2026-10-05. [Kobalte Toast](https://kobalte.dev/docs/core/components/toast/) is a maintained Solid alternative ([0.13.14, 2026-09-07](https://github.com/kobaltedev/kobalte/releases/tag/%40kobalte/core%400.13.14)), but is not selected: introducing a second primitive layer violates this work order's required Ark/shared-wrapper boundary. These are capability candidates, not measured performance claims; the shared-provider work must verify the installed Solid APIs and budgets before adoption.
