# Resource use: memory, CPU and disk per Agent

Module: `crates/rupd` (the sampler and the method), `crates/contracts` (the method and its types), `apps/desktop` (the strip). Terms: Agent, Worktree, Project, Resource use (`GLOSSARY.md`; this file adds Resource use). Ids: D8, U408.

Found by the user's report #1099: Agents can be eager and hungry, and roundup shows neither their memory and CPU nor their Worktrees' disk. Contract change (rule 4, the Contract recipe of `.agents/builder.md`): the new RPC method `project.resources`, the types `Resources` and `AgentResources`, and the term **Resource use** in `GLOSSARY.md`; no other method, event or App seam command changes, and no Token is added. The Rail draws none of it (the user's direction), and the Drawer and the Shelf are untouched.

**D8 the Daemon samples an Agent's Resource use when asked.** Given a Daemon whose Project holds an Agent (a fake `claude` that starts one child program and sleeps) and an Agent with no Worktree, when a client calls `project.resources` (no params), then the result is `{agents: [{id, memory_bytes, cpu_percent, disk_bytes}], total: {memory_bytes, cpu_percent, disk_bytes}}`, with one entry for each Agent whose program is running and none for an Agent that is `done`, and:

- **Memory and CPU cover the tree.** `memory_bytes` is the resident memory, and `cpu_percent` the share of one core since the previous sample (so 100 is one full core and a busy tree may exceed it), summed over the Agent's program and every program it started, however deep, found by parent links from the Agent's program (H21 knows an Agent by the same ancestry). A child that exits drops out of the next sample; one that is still running counts. The first call after an Agent starts reads `cpu_percent: 0`, because there is no earlier sample to subtract.
- **Disk is the Worktree.** `disk_bytes` is the recursive size of the Agent's Worktree directory (G1), and `null` for an Agent with no Worktree, never `0`. A Worktree the Agent no longer has on disk reads `null`.
- **Totals.** `total.memory_bytes` and `total.cpu_percent` are the sums over `agents`, and `total.disk_bytes` the sum of the non-null `disk_bytes` (`null` when every one is `null`). A Project with no running Agent returns `agents: []` and zeros, with `disk_bytes: null`.
- **No work unless asked.** The Daemon samples inside the call and in no other place: no timer, thread or watch runs between calls. Two calls less than one second apart return the first call's numbers. A disk size is recomputed at most once in 30 s for one Worktree, and the walk does not hold the call past 1 s: a size not ready returns the last one, or `null` before the first. The cost is bounded by rule 7 (`AGENTS.md:29`): `just perf` shows no regression above 10% and D4's ten idle Agents still grow the Daemon by under 150 MB, with `project.resources` called once a second for the whole of D4.
- **Reads nothing from the Agent.** The sampler reads the operating system's program table and the Worktree's file sizes only; it sends the Agent nothing and changes no Status, Message or file in the Project (N2).

Tests (`d8_`, in `crates/rup/tests/e2e/`, with the unit tests beside the sampler in `crates/rupd`): `d8_memory_and_cpu_sum_the_whole_tree` (the fake `claude` starts a child that holds 50 MB and spins; the entry's memory exceeds the child's and its CPU exceeds 50), `d8_a_child_that_exits_leaves_the_sum`, `d8_disk_is_the_worktrees_size_and_null_without_one`, `d8_totals_add_the_agents`, `d8_a_done_agent_has_no_entry`, `d8_the_first_cpu_reading_is_zero`, `d8_two_calls_within_a_second_share_one_sample`, `d8_nothing_runs_between_calls` (the Daemon's thread count and CPU time do not grow over 3 s with no call) and `d8_ten_idle_agents_with_sampling_stay_under_the_budget` (D4's body with the call added). The contract test in `crates/contracts` asserts the method's name and the two types; every caller of `contracts/generated/` is regenerated, never hand-edited.

**U408 the Resource strip shows each Agent's use and the Project's totals.** Given an open Project and a selected Agent (U59), when the centre shows its pane, then a one-line strip sits between the pane and the Thread (U145), outside the Rail, the Shelf, the Drawer and the Rail's rows (so no `tree-40` row or width changes, U393):

- **Words.** The strip reads `memory 412 MB · cpu 18% · disk 2.1 GB` for the selected Agent and, at its trailing end, `project 1.4 GB · 61% · 3.2 GB`, in `--font-ui` at one type step (D2) in `--grey` (D5). Sizes use 1000-based units to one decimal from `KB` up (`812 KB`, `4.2 MB`, `2.1 GB`); CPU is a whole percent. A `null` disk reads `disk –`, in the Agent part and the Project part alike. While no result has arrived the strip reads `–` for each value; after a failed `project.resources` it keeps the last values and adds `not updating` in `--text` (U80's one line is not used), and the next success removes it. No value is ever `NaN`, `undefined` or a negative number.
- **Which Agent.** For a selected Agent that is `done`, or a selected Workstream, Terminal or nothing, the strip shows only the `project` part; for an Agent that is running it shows both. A Door counts as an Agent here. With no Project total either (no running Agent), the strip is not drawn and the pane keeps the height it has without it.
- **Current while shown.** The webview calls `project.resources` when the strip first shows and then every 2 s while it is shown and the window is visible; it stops on hide, on closing the Project's tab and on `daemon-exited` (U25), and no call is pending twice at once. A response that arrives after the selection changed is dropped. With the strip not drawn the webview makes no call at all.
- **Quiet.** The values change in place with no animation and no layout shift: each number sits in a `tabular-nums` span whose box is held at the width of its widest allowed text, so a changing digit moves nothing. The strip is not a click target (D6, D7 do not apply), takes no focus, and is `aria-hidden="false"` with `role="status"` and `aria-live="off"`, so a screen reader reads it on demand and is not interrupted every 2 s. The Agent part's `title` holds the full words (`resident memory`, `CPU of one core`, `Worktree on disk`).
- **No new surface.** Rail rows, Live lines, Glyphs, the tab strip and the Shelf are unmoved; no Token, shadow, border or hue is added (D1, D3, D8); the Checks of `docs/design-system.md` that pass on `main` still pass in both colour schemes and at 700 by 800 (D10).
