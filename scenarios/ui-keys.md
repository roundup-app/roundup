# UI: App shortcuts from every focus place

Acceptance for #4324. Journey: Enter (start an Agent, open a Terminal, capture work), Intervene (Ask and shortcut Help). This file specifies U4324a and U4324b; implementation remains in #4324. It claims no shipped behavior.

Scope (policy): `apps/desktop/src/keys/` (Help, places, registry and connected-App observers), `apps/desktop/src/todos/Capture.tsx` and mounting in `apps/desktop/src/App.tsx`. **U4324a Help opens from every non-text-entry place.** Given the mounted App with no modal layer, when the user presses `?` with focus on a non-editable element, then one Help dialog opens and takes focus, including from a Todo row in triage, the ordinary Shelf, Rail, centre frame, Drawer controls, header controls and the first-run surface with no Project open. The selection and triage mode stay unchanged; no Todo mutation, Agent start, Ask send or Terminal write occurs. Escape closes only Help and returns focus to the exact origin. Assert these outcomes in the `?` rows of planned `u4324b_app_chords_follow_focus` below; do not add a second connected-App test for the same cases.

Given focus in an input, textarea, select, contenteditable element or its descendant, or inside a Terminal emulator (Agent pane or Bubble, including its non-editable screen), when `?` is pressed, then Help stays closed, the App does not prevent the event and the text field or Terminal retains the key. Given an existing modal layer, `?` remains with that layer; Help's own `?` close action stays U54's. Assert the exclusions in the same table's negative rows; retain U479's modal-ownership observer.

Policy amendment: supersede only the opening-place restriction of U54 (`scenarios/ui.md`, heading `Todos motion and keyboard help`) and U481 (`scenarios/ui-shortcuts.md`) and U2241's description of that restriction. Non-editable Drawer and first-run origins now qualify; editable fields, Terminals and modal layers remain excluded. Other U54/U481 content, focus return, suppression, daemon-exited availability and drift clauses stand. The implementation updates the body/nowhere exclusion in `u54_question_mark_in_a_terminal_a_text_field_or_nowhere_opens_nothing` to retain only the text-entry exclusions; its former body clause is superseded by this scenario, not silently lost (policy, rule 10).

**U4324b App chords keep their action across focus places.** Given the whole mounted App, normal answering App/Daemon seams, a connected Project with a selected Workstream (Project-root context for the nonmodal Ask landing), no pending creation and no modal layer, when the user dispatches one non-repeat chord below on the element that actually holds focus, then its stated action occurs once, regardless of which listed focus place owns that element. App-handled chords prevent their default and reach no Terminal handler or `terminal.write`; they neither submit nor discard an existing Ask draft. Assert in one planned table-driven connected-App test, `u4324b_app_chords_follow_focus`, under `apps/desktop/src/keys/`.
