# UI: Todo triage mode, one key per action (U3751 to U3755)

Module: `apps/desktop` (the webview). Ids: U3751 to U3755. Acceptance for #3195; U3474a–U3474e specify #3474. Webview only: no App command, no Daemon method, no Todo state and nothing under `contracts/` changes; the mode calls `todo.assign`, `todo.move`, `todo.setBlockers` and `todo.complete` as U3720, U157, U3709 and U361 say, and `todo.comment` as U3741 says. The owner chose a keyboard mode in the Shelf's Todos tab, not a board view. Works on the final rows (U3721 to U3724, U3730) and the owner groups (U3736). Obeys U2241 and U2773 (a refused change keeps the user's input and shows its cause).

**U3751 `t` enters Todo triage mode and `Esc` leaves it where it started.** As widened by U3474a, given the visible Todos tab with focus on any non-editing surface of that view, when the user presses the plain key `t` (no `⌘`, `⌃`, `⌥`, no `⇧`; registered once in the registry's Shelf scope, with its Help and key-hint rows, never a local `keydown` listener, policy) or presses the button, then the list enters triage mode: the Shelf's root carries `data-triage="on"`, the focused row stays focused (the first open row when none was), and no Todo, Pad, selection or open Drawer changes. `Esc` leaves the mode, sets `data-triage="off"` and returns focus to the row button that held it at entry, found by `#<id>` (U138: never `body`); when that Todo is gone or done, to the nearest open row. Leaving by `Esc` calls nothing. The mode is a webview state of the Todos tab: switching tab, Project or Rail selection leaves it, and it is not saved. `t` does nothing while focus is in a text field, the Drawer's editor, a naming field or a dialog, with a modifier held or on a repeated keydown. Tests (`u3751_`): `u3751_t_enters_the_mode_and_keeps_focus_and_data`, `u3751_esc_returns_focus_to_the_entry_row_or_the_nearest`, `u3751_t_is_ignored_in_fields_and_with_modifiers`.

**U3752 the mode shows its keys while it is on.** Given triage mode on, then one line of key hints is visible in the Shelf, out of the flow of the rows (U112: no row changes its top edge, height or wrapping), listing `j k` move, `a` assign, `w` workstream, `Tab` nest, `⇧Tab` un-nest, `x` done, `c` comment, `Esc` leave, each as a `keys/KeyChip` derived from the same registry rows the keys run from, never typed twice; it is gone when the mode is off. The keys are listed in Help and U2541b's hints for the Shelf place only as the mode's rows. Tests: `u3752_the_hint_line_is_the_registry_rows_and_leaves_with_the_mode`. Layout and looks are the design critic's.

**U3753 one key per action on the focused row.** Given triage mode on and a row button of an open Todo focused, when the user presses a plain key (no `⌘`, `⌃`, `⌥`; `⇧` only where named), then exactly this happens, each registered once in the registry's Shelf scope and active only while the mode is on:

- **`j` and `k`** move focus to the next and the previous open row in list order, across owner groups (U3736), stopping at the first and last row; nothing is called.
- **`a`** opens U3720's owner picker for the row, with U3743's `New Workstream…`, and choosing calls `todo.assign` once, or U3743's dialog, as they say.
- **`w`** opens one list of Homes as a popover below the row, as U3720's does: `Project root`, then each Workstream on the Rail in Rail order, the Todo's current Home left out; choosing calls `todo.move {id, home}` once (`home` the Workstream's Rail id, or `null` for the root, T12) and nothing else.
- **`Tab` and `⇧Tab`** are U3709's, unchanged and not needing the mode.
- **`x`** calls `todo.complete {id}` once; focus moves to the next open row, or the previous one when it was last, and stays on the list (U138).
- **`c`** focuses the comment field of the Todo's Drawer (U3741), opening the Drawer when closed; the typed comment is sent there, and `Esc` in the field returns to the row with the mode still on.

Outside triage, picker focus still follows the chosen row after the refetch. In triage, U3474b replaces that return rule: after a successful pick and its refetch, focus advances to the next valid row. A key does nothing on a done row, while focus is in a text field or a dialog, or on a repeated keydown (`x` never completes two Todos). Tests (`u3753_`): `u3753_j_and_k_move_focus_across_groups_and_call_nothing`, `u3753_a_and_w_call_assign_and_move_once_each`, `u3753_x_completes_once_and_focus_moves_on`, `u3753_c_opens_the_comment_field_and_esc_returns_to_the_row`, `u3753_the_keys_do_nothing_outside_the_mode`.

**U3754 a refused change keeps the mode, the row and the cause.** Narrows U2773 and U3711. Given triage mode on, when `todo.assign`, `todo.move`, `todo.setBlockers` or `todo.complete` fails (`CONFLICT`, `NOT_FOUND`), then the list is as `todo.list` returns it, focus stays on the row, the mode stays on, and `✕ <message>` with the Daemon's message shows in place of the row's `also waits on` line (U35) until the next change to the list; a typed comment keeps its text (U3741). The webview makes no check of its own. Tests (`u3754_`): `u3754_a_refused_key_keeps_mode_focus_and_shows_the_cause`.

**U3755 `Esc` in the comment field keeps an unsent draft.** Narrows U3753 and U3741. Given triage mode on, when the user presses `c` on a row, types a comment and presses `Esc`, then focus returns to the row, the mode stays on, no `todo.comment` call is made, and pressing `c` again focuses the field with the typed text still in it. The draft is dropped only by sending it or by leaving the Todo (policy). Tests (`u3755_`): `u3755_esc_in_the_comment_field_keeps_the_draft`.

Policy: implementation boundary is `apps/desktop/src/shelf/`, `todos/`, `keys/`, `copy.ts` and the named regression callers; reuse `ui/` pickers, popover and `keys/KeyChip` and add no state machine beyond the one mode flag. `t`, `j`, `k`, `a`, `w`, `x` and `c` collide with no Shelf key on `main` (U3720 owns `o`, U3723 `d`/`e`, U3721 `m`). Regression: U152, U3708 to U3711, U3723 and the owner-group drag tests pass unchanged. `c` waits on the Todo comments Issue #3192 (U3741) for its Drawer field.

Observer: the named Vitest cases against the fake App; one headless U26 Chromium session at 1512×950, dark only (U3725), on `tree-40`, pressing the keys with `agent-browser` and reading calls; the mode's looks go to the design critic. Moves: D2, D5, D6. Linux/Chromium is the rendered observer; the user reports what they meet on the Mac.


## Continuous triage and App shortcut audit (#3474)

These clauses widen U3751 and replace U3753's focus return after successful mutations; they retain its action meanings, modal ownership, typing guards and U3754/U3755's refusal and unsent-comment behavior. Tests below are planned implementation observers, not claims that main passes them.

**U3474a T enters from the Todos view.** Given the Shelf's Todos tab is visible and no dialog, menu or other modal layer owns keys, when the user presses plain, non-repeating, non-composing `t` with focus on a Todo row, the Triage button, the Todos tab, a group heading/control, another non-editing Shelf control, or the page body after a row loses focus, then triage turns on and focuses the held open row, else the first visible open row. The button has `aria-pressed=true` and the Shelf has `data-triage="on"`; entry changes no Todo, selection or Drawer. Clicking Triage has the same result. When already on, clicking the button or pressing Escape from these non-editing targets turns it off, with U3751's return focus and no mutation. If no open row exists, entry/exit focus is the Triage button. Test: `u3474a_enters_and_leaves_from_each_todos_target` in `apps/desktop/src/todos/u3751_triage.test.tsx`, parameterised by starting focus and keyboard/pointer entry. U3751's field, modifier and repeat exclusions remain; extend `u3751_t_is_ignored_in_fields_and_with_modifiers` to contenteditable, composition, menus and dialogs, and a hidden Todos tab. Do not take plain T from a focused Terminal, Pad editor or another view merely because the Shelf is visible (policy; the test asserts no entry or prevented default there).

**U3474b an action leaves the next key ready.** Given triage on and at least three visible open rows across owner groups, when the user completes a successful action using only keys, then focus is on a connected, visible open row after its acknowledged update and list refetch; triage stays on and its button stays pressed. For Done (`x`), Nest (`Tab`), Un-nest (`Shift+Tab`), Owner (`a`, also the existing `o` owner path), Home/Move (`w`) and a submitted Comment (`c` then the existing submit chord), choose the first surviving visible open row after the acted-on row in the pre-action rendered order, else the nearest surviving row before it, else the acted-on row if still visible and open, else the Triage button. Capture this order before mutation, including before a picker or comment field takes focus. This applies when assignment regroups a row, moving it removes it from the current Home, nesting hides it beneath a fold, and when a DOM node survives but loses native focus. The picker or editor owns typing until selection/submit/cancel; do not advance while the user is still choosing or writing. Escape cancelling a picker or comment returns to its original row without advancing or mutating, preserving U3755's draft. `j`/`k` keep U3753's next/previous order and endpoint clamping, with the destination ready for the next action. Test: `u3474b_two_key_actions_keep_working` in `apps/desktop/src/todos/u3751_triage.test.tsx`, one table of these actions followed by `x` on the resulting row, including forward and last-row fallback fixtures. Assert the first action's changed Todo fields/comment or navigation destination, then the second completion's distinct intended id and the final store; for a sole remaining row, assert the defined fallback. Update superseded assertions in `u3753_a_and_w_call_assign_and_move_once_each`; retain assertions proving the RPC contracts.

**U3474c a missing target recovers without an accidental mutation.** Given triage on with focus on a non-editing Todos control or the page body, when the user presses any triage action key without a focused open row, then that press focuses the first visible open row and performs no mutation, opens no picker and sends no comment; the next press acts on that row. Include `j`, `k`, `a`, `o`, `w`, `Tab`, `Shift+Tab`, `x` and `c`. With no open rows, the same keys leave triage on, focus the Triage button and make no mutation; after an open row appears, the first key focuses it and the next acts. Escape still exits while empty. Test: `u3474c_recovers_a_missing_or_empty_target` in `apps/desktop/src/todos/u3751_triage.test.tsx`, parameterised by key and empty/no-focus setup, asserting calls, active target and pressed/mode state. A field, open picker, dialog or Terminal remains its own keyboard owner; recovery never steals its typing (policy, covered by U3474a's exclusion observer).

**U3474d every shown shortcut has a reachable action.** Given each runtime shortcut presentation in the App, when its advertised chord is pressed from the non-editing focus locations where that presentation is visible, then its advertised action runs exactly once on its intended target. **U3474e list mutations preserve a keyboard target throughout the App.** Given a keyboard mode or list in Todos, Switcher, Changes, Shelf (Todos and Pads), menus or Ask, when an ordinary in-App action removes or moves its focused/highlighted item and the surface remains open, then the next supported navigation/action key immediately acts on a valid item: the next surviving item in the pre-action order, else the preceding one, else the surface's existing empty-state control/input. Preserve a surviving current item for non-triage lists when their existing scenario requires it; U3474b defines triage's advance rule. For an input with an active descendant, keep the input focused and point its active descendant at a surviving option, or clear it when empty. Tests: `u3474e_mutation_keeps_the_next_key_live`, parameterised at each affected module's existing behavior-test seam; assert actual active focus/descendant and the next key's effect. Reuse existing proofs for passing sites. The implementation PR lists every found/fixed site and names each observer (policy); do not invent a mutation for a read-only list merely to add a test.

## Picker cancellation (#3487)

**U3487a closing a picker ends its pending advance.** Given triage on with at least four visible open Todos in rendered order A, C, B, D, when the user opens A's owner picker with `a` or `o`, or its Home picker with `w`, and dismisses it with Escape or a press outside, then the picker closes, focus returns to A without advancing, triage stays on with its button pressed, and no Todo mutation occurs. Any advance captured for that picker ends on close; it cannot be used by a later action (policy). Test: `u3487a_dismissing_a_picker_keeps_its_row` in `apps/desktop/src/todos/u3751_triage.test.tsx`, table-driven by picker entry and dismissal. Assert active row, mode/button state, unchanged Todos and mutation call counts; do not inspect closure variables.

**U3487b a later action uses only its own row and order.** Given U3487a's fixture after dismissal, when the user acts on B, then focus after the acknowledged change and list refetch follows B's action, never the cancelled action on A: choosing an owner through B's picker or a Home through B's picker advances to D under U3474b; creating a Workstream through B's owner picker's `New Workstream…` naming dialog returns to B under U3743's existing naming return. Each path changes only B, once, with its chosen owner/Home or Workstream name/start; A and C stay unchanged. The next `x`, dispatched at the actual active element without a helper refocusing it, completes D for a picker choice or B for naming, never C from A's former order. Tests: `u3487b_a_later_picker_choice_uses_its_own_order` and `u3487b_naming_after_cancel_never_uses_the_cancelled_rows_order`, both in `apps/desktop/src/todos/u3751_triage.test.tsx`. The naming test uses the existing New Workstream interaction and `todo.startWorkstream` handler from `apps/desktop/src/todos/u3743_new_workstream.test.tsx`, not a direct call to an internal callback. Keep the chosen owner group unfolded so B and D remain visible.

A successful selection retains its own in-flight advance through acknowledgement/refetch even though the menu closes; cancellation retains none. Preserve U3474b's successful picker advance, U3754's refused-call cause and U3755's unsent comment draft. Reuse the current picker, naming and Todos behavior-test seams; no new focus machinery, RPC, App seam command, Token or glossary term.
