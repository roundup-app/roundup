# Workstream cost and time

Module: Workstream measurement in `crates/agents`, with vendor interpretation only in its Adapter; `crates/contracts`, generated contracts and Daemon/public CLI callers; dashboard interaction in `apps/desktop`. Ids: U3016a–U3016f.

Outcome: from a Workstream, understand its observed cost, consumed model tokens and elapsed/attributed time while work runs, then inspect the largest contributors without leaving that Workstream. Journey stages: Understand and Review (`.agents/data/journey.md`). This file specifies acceptance; #3016 owns implementation progress and engineering observations.

Policy: this specification PR changes scenarios only. Implementation follows the Contract recipe for the measurement types, read/update interface and every caller, adding new public code terms to `GLOSSARY.md` in that PR. This file's model-token labels are App copy, distinct from the visual Token. Reuse existing observation, Project storage, Event subscription and App seams; extend observations within the existing Adapter seams rather than add a fourth seam. No vendor strings, paths or record parsing escape the Adapter. Before new machinery, apply rule 9 and record the library evidence in the implementing PR. No Model, network pricing lookup, vendor command, prompt, Agent start or settings/Brief/tool-list rewrite is needed to collect or view measurements. No new billing integration, transcript viewer, budget enforcement, scheduler, Workstream nesting or motion is requested.

**U3016a measurements have a source and one owner.** Given two Projects with identical display names and vendor records for a Door, its Agents and vendor-internal children, when measurements are collected, then each accepted contribution identifies the original Project, Workstream Home at observation, Agent, Attempt when known, opaque source identity/revision, observation time and coverage. The Door is included. A vendor-internal child belongs to its enclosing roundup Agent unless it is already represented by a distinct roundup Agent; a source contribution is counted once, never both as child and inclusive parent. Unresolvable attribution is shown as unavailable, not assigned by matching a title or directory name. An unsupported source explains which measurements it cannot provide. Historical work predating collection is labelled uncovered unless source records establish it. Assert `u3016a_sources_are_scoped_and_counted_once` through real Daemon/public CLI reads with isolated vendor fixtures, including two same-named Projects, inclusive parent totals, child records, missing Attempt identity and unsupported data.

Given a user Home move or Agent removal, then earlier contributions remain with their recorded Workstream; later contributions follow the new Home, and removed/stopped makers remain named in historical detail. Moving an Agent never copies its earlier consumption into another Workstream. Explicit Workstream/Project removal retains its existing deletion policy and does not recreate data. Assert `u3016a_moves_and_removal_keep_recorded_attribution` through the same public seams, including rename, restart and a contribution arriving after a move. For a source record spanning a move whose split is not observable, show the unsplittable contribution once at its recorded Home and disclose that limitation rather than invent a split.

Policy: before implementation, inspect the pinned vendor's supported local measurement sources in isolated configuration and record sanitized fixture provenance, field meanings, inclusive-parent behavior, deduplication identities, live availability and clock semantics on #3016. The existing last-request context-size reader is not a cumulative-consumption source. A missing source capability calls for an engineering repair or scoped prerequisite, not invented data or completion with every field unavailable. Completion requires observed token consumption and all four time categories in supported source fixtures, plus the real collection path in U3016f; genuinely unsupported historical spans remain explicit.

**U3016b consumption and money do not overclaim.** Given complete request measurements for Agent A of 100 uncached input, 20 output, 400 cache-read and 50 cache-write tokens, and Agent B of 200 uncached input, 30 output and zero in both cache categories, then the Workstream shows 300 input, 50 output, 400 cache read, 50 cache write and 800 total. Each category is disjoint: input excludes both cache categories. Cumulative counters contribute their delta within the same source identity; request/stream revisions replace that request's contribution rather than add it again. A resumed Attempt reading earlier conversation records does not charge them again. Reset counters, duplicate stream chunks and inclusive totals cannot create negative or duplicate consumption. Assert `u3016b_token_totals_reconcile_by_source` through public reads with replayed records, a counter reset, a revised request, a resume and parent/child duplication.

Given source-reported money, then show its currency and source as reported cost, without claiming it is the user's subscription bill. Given only a usable rate basis, show a separately labelled reference estimate with its rate version/date, currency and category basis; never mix reported money and an estimate into an unlabelled sum or treat cache reads as free. Unknown Model/rate, cache-write rate class or currency conversion means the affected cost is unavailable. Partial coverage shows the known subtotal and the missing coverage; missing values are never zero. Measured zero remains zero. Display rounding never changes the underlying totals or rank. Assert `u3016b_cost_basis_and_missing_coverage_are_explicit` through public reads with known per-category rates, reported money, unknown rates, multiple currencies, partial coverage and measured zero. Policy: no subscription-limit percentage, remaining balance or actual invoice amount is inferred from reference rates.

**U3016c time accounts for concurrency and uncertainty.** Given recorded Attempt intervals, then elapsed time runs from the Workstream's first observed Attempt start to the observation time while an Attempt is active, otherwise to the latest Attempt end. It includes gaps between Attempts and is labelled elapsed since first start; before a start it is zero, while an unknown historical start is unavailable. Resuming extends the same history. Summed Agent time is separately labelled as a sum across Attempts and may exceed elapsed time; no chart or percentage presents that sum as a partition of wall time. Assert `u3016c_elapsed_and_parallel_time_are_distinct` using an injected clock through public reads, including a stopped Door, restart, idle gap and resumed Agent.

Within each Attempt, split observed duration into disjoint agent time, tool time, waiting for human, coordination overhead, other observed time and unmeasured time. Agent time requires positive evidence of model execution, not merely Kind `working`. Tool time is the union of tool-execution intervals within that Attempt, not the sum of overlapping tools. Waiting for human runs only while a valid Decision blocks that Agent, ending on its resolution, cancellation or Attempt end. Coordination overhead requires an observed blocking routing/handoff wait with the corresponding roundup Message identity; it is not every pending Message, generic `blocked` time, model work composing a message or an unexplained residual. For overlapping evidence use human wait, tool execution, coordination wait, model execution in that precedence. Known idle/startup time is other observed time; gaps without evidence are unmeasured. Different Attempts remain parallel and are summed independently. Assert `u3016c_time_categories_use_observed_intervals`: A and B run during [0,10) seconds; A has tool intervals [2,6) and [3,5), a Decision [6,8), a blocking coordination wait [8,9), and positive model execution elsewhere; B has model execution throughout. Expect elapsed 10 s, summed Agent time 20 s, agent execution 13 s, tools 4 s, human wait 2 s, coordination 1 s, and no other/unmeasured time. Also probe overlapping category evidence, an unanswered Decision, a nonblocking pending Message and an unexplained gap; expect precedence and explicit unmeasured duration.

Given a duplicate, late or out-of-order interval, wall-clock adjustment, sleep or Daemon outage, then no interval becomes negative or is counted twice; a late observation revises the aggregate for its original identity. Active durations use a monotonic clock within one clock lifetime. Across an outage or incomparable clocks, retain observed intervals and expose the uncovered gap rather than claim model/tool execution continued. Assert `u3016c_clock_gaps_and_late_intervals_are_honest` with injected clocks and persistence reopen; no real-time sleep is needed.

**U3016d realtime updates survive reconnect and failure.** Given an open dashboard, when a complete supported source record becomes locally available or its source event arrives, then collection accepts it within two seconds while the Daemon is awake. Once accepted, the subscribed view reflects its revision within one second in an isolated local observer without manual refresh. Active observed durations advance at least once per second while visible; hiding or closing the dashboard stops its display timer without stopping collection. Repeated open/close and Project switches leave at most one subscription and display clock for the current view. Collection does not reread all historical records on every update. Assert `u3016d_observations_update_one_live_view` on the App seam with fake time, checking data revisions, subscription/timer counts and teardown; record the source-to-Daemon collection delay separately in U3016f rather than hiding it in this one-second bound.

Given duplicate/reordered Events, a lost subscription, failed read, Daemon exit or restart, then durable source identities keep the same totals after replay. A reconnect first reconciles a coherent snapshot/revision and then follows newer updates; an older response cannot replace newer data or data from another selected Workstream/Project. A failed collection/read keeps the last good measurement visibly stale with last observation time, the cause and a retry action. Initial loading, no work yet, unsupported measurement and stale data are distinct states; an empty successful response does not mean a failed read succeeded. Assert `u3016d_reconnect_reconciles_without_double_counting` through the real Daemon/public seams with persistence and replay, and `u3016d_stale_reads_keep_original_identity_and_retry` on the App seam with reversed responses and failure injection.

**U3016e show what consumes the most.** Given U3016b's measurements, when the user opens the token breakdown, then it initially ranks Agents by total consumed tokens descending (A 570, B 230), including the Door and stopped/removed contributors. Equal values use stable Agent identity order. Each row exposes all four categories, coverage and the same unrounded contribution as the Workstream total; all rows together reconcile with that total. Choosing output ranks B 30 before A 20; choosing input, cache read or cache write ranks that selected category. Unknown values appear after known values and remain identified as unknown. Cost and time detail use the same attribution and disclose their basis, coverage and parallel-time semantics. Assert `u3016e_rank_and_totals_share_contributions` through public reads and `u3016e_category_choice_changes_the_rank` through keyboard/pointer App actions.

Given many contributors, then the initial view shows the first 20 ranked rows and the full contributor count, with an explicit way to load subsequent rows. Pages of one revision have no gaps or duplicates and reconcile with that revision's totals; newer observations invalidate/reconcile the pages rather than silently mix snapshots. No top-N limit discards stored contributions or makes the remaining detail inaccessible. Loading more preserves selection/focus; failure preserves visible rows and offers retry. A contributor opens its existing Agent view when still available, otherwise explains that its Agent was removed without opening another Agent. Assert `u3016e_paging_and_navigation_keep_all_contributors` with 1,005 contributors, tied values across page boundaries, an intervening revision, a failed next page and a removed Agent.

**U3016f an ordinary Workstream dashboard.** Given a selected Workstream, when the user opens its cost-and-time action by pointer or keyboard, then the centre shows that Workstream's dashboard with cost, four token categories and elapsed/summed time first, followed by expandable contributor/time detail. The Workstream name and measurement coverage identify the scope once; changing Workstream or Project changes the measurement identity and never briefly shows the previous scope's values as the new one's. Escape/back returns to the originating view and focus. Starting/stopped/failed Door states keep their existing actions, direct Agent access remains reachable, and opening the dashboard launches/sends nothing. Dashboard updates neither steal focus nor announce routine progress as a Decision, bell or assertive alert. Existing editable drafts and original recipients survive entering/leaving it. Assert `u3016f_dashboard_navigation_preserves_work_and_focus` on the App seam, checking actions, focus, zero starts/prompts and exact drafts across navigation and failed reads.

Given the real Daemon and isolated fake-vendor measurement fixtures, then the headless real harness opens a Workstream, observes measured token/cost updates and model/tool/Decision/coordination intervals, drills into the largest contributor, injects a collection/read failure, reconnects and reopens the Project with the same totals. Another Workstream and another Project remain isolated. Assert `u3016f_real_collection_to_dashboard_survives_reopen`; feed the actual collection path, not dashboard-only seeded success values.
