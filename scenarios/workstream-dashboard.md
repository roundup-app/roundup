# Workstream time

Module: Workstream measurement in `crates/agents`, with vendor interpretation only in its Adapter; `crates/contracts`, generated contracts and Daemon/public CLI callers; the time view in `apps/desktop`. Ids: U3016a–U3016m; U3016b, U3016h are retired.

Outcome: from a Workstream, understand where its Agents' time went and who waited on the user, as one chart, while work runs, then inspect the largest Agents without leaving that Workstream. Journey stages: Understand and Review (`.agents/data/journey.md`). This file specifies acceptance; #3016 owns the original implementation progress and engineering observations; #3534 owns the U3016k dashboard and idle-time amendments; #3574 owns the removal of cost and tokens and the time chart (U3016e, U3016g, U3016l, U3016m, P14 in `PRINCIPLES.md`).

Policy: this specification PR changes scenarios and `PRINCIPLES.md` only; the implementation PR follows the Contract recipe for the measurement types, read/update interface and every caller, and edits `GLOSSARY.md` and `scenarios/mcp.md` as U3016l lists. roundup computes and shows no cost, price or token counts (P14): Claude Code's own `/cost` and `/usage` already cover them, and no Issue asking for them is built; its answer is P14. Reuse existing observation, Project storage, Event subscription and App seams; add no fourth Adapter seam. No vendor strings, paths or record parsing escape the Adapter. Before new machinery, apply rule 9 and record the library evidence in the implementing PR. No Model, vendor command, prompt, Agent start or settings/Brief/tool-list rewrite is needed to collect or view measurements. No transcript viewer, budget enforcement, scheduler, Workstream nesting or motion is requested.

**U3016a measurements have a source and one owner.** Given two Projects with identical display names and vendor records for a Door, its Agents and vendor-internal children, when measurements are collected, then each accepted contribution identifies the original Project, Workstream Home at observation, Agent, Attempt when known, opaque source identity/revision, observation time and coverage. The Door is included. A vendor-internal child belongs to its enclosing roundup Agent unless it is already represented by a distinct roundup Agent; a source contribution is counted once, never both as child and inclusive parent. Unresolvable attribution is shown as unavailable, not assigned by matching a title or directory name. An unsupported source explains which measurements it cannot provide. Historical work predating collection is labelled uncovered unless source records establish it. Assert `u3016a_sources_are_scoped_and_counted_once` through real Daemon/public CLI reads with isolated vendor fixtures, including two same-named Projects, inclusive parent totals, child records, missing Attempt identity and unsupported data.

Given a user Home move or Agent removal, then earlier contributions remain with their recorded Workstream; later contributions follow the new Home, and removed/stopped makers remain named in historical detail. Moving an Agent never copies its earlier time into another Workstream. Explicit Workstream/Project removal retains its existing deletion policy and does not recreate data. Assert `u3016a_moves_and_removal_keep_recorded_attribution` through the same public seams, including rename, restart and a contribution arriving after a move. For a source record spanning a move whose split is not observable, show the unsplittable contribution once at its recorded Home and disclose that limitation rather than invent a split.

**U3016c time accounts for concurrency and uncertainty.** Given recorded Attempt intervals, then elapsed time runs from the Workstream's first observed Attempt start to the observation time while an Attempt is active, otherwise to the latest Attempt end. It includes gaps between Attempts and is labelled elapsed since first start; before a start it is zero, while an unknown historical start is unavailable. Resuming extends the same history. Summed Agent time excludes observed idle intervals and all time after an Agent stops; it is separately labelled as a sum across Attempts and may exceed elapsed time; no chart or percentage presents that sum as a partition of wall time. Assert `u3016c_elapsed_and_parallel_time_are_distinct` using an injected clock through public reads, including a stopped Door, restart, idle gap and resumed Agent.

Within each Attempt, exclude observed idle intervals and time after its Agent stops from summed Agent time and every category, including other and unmeasured (the shared boundary rule is U3768b). Split the remaining duration into disjoint agent time, tool time, waiting for human, coordination overhead, other observed time and unmeasured time. Agent time requires positive evidence of model execution, not merely Kind `working`. Tool time is the union of tool-execution intervals within that Attempt, not the sum of overlapping tools. Waiting for human runs only while a valid Decision blocks that Agent, ending on its resolution, cancellation or Attempt end. Coordination overhead requires an observed blocking routing/handoff wait with the corresponding roundup Message identity; it is not every pending Message, generic `blocked` time, model work composing a message or an unexplained residual. For overlapping evidence use human wait, tool execution, coordination wait, model execution in that precedence. Positively observed startup remains other observed time; idle is never other observed time. Gaps without evidence remain unmeasured, never inferred working time. Different Attempts remain parallel and are summed independently. Assert `u3016c_time_categories_use_observed_intervals`: A and B run during [0,10) seconds; A has tool intervals [2,6) and [3,5), a Decision [6,8), a blocking coordination wait [8,9), and positive model execution elsewhere; B has model execution throughout. Expect elapsed 10 s, summed Agent time 20 s, agent execution 13 s, tools 4 s, human wait 2 s, coordination 1 s, and no other/unmeasured time. Also probe overlapping category evidence, an unanswered Decision, a nonblocking pending Message and an unexplained gap; expect precedence and explicit unmeasured duration.

Given one Attempt with model execution during [0,2), observed idle during [2,7), tool execution during [7,10), and its Agent stopping at 10 s, when time is read at 10 s and again at 20 s, then elapsed remains 10 s, summed Agent time remains 5 s, execution is 2 s, tools 3 s, and human wait, coordination, other and unmeasured are all zero. The idle interval contributes to none of them and no category grows after stop. Assert `u3016c_idle_and_stopped_time_are_not_agent_time` in `crates/agents/src/measurement.rs` with an injected clock and the real stop transition, not a test double of the aggregation. Retain the unknown-end honesty and stopped-clock observer of U3016i.

Given a duplicate, late or out-of-order interval, wall-clock adjustment, sleep or Daemon outage, then no interval becomes negative or is counted twice; a late observation revises the aggregate for its original identity. Active durations use a monotonic clock within one clock lifetime. Across an outage or incomparable clocks, retain observed intervals and expose the uncovered gap rather than claim model/tool execution continued. Assert `u3016c_clock_gaps_and_late_intervals_are_honest` with injected clocks and persistence reopen; no real-time sleep is needed.

**U3016d realtime updates survive reconnect and failure.** Given an open dashboard, when a complete supported source record becomes locally available or its source event arrives, then collection accepts it within two seconds while the Daemon is awake. Once accepted, the subscribed view reflects its revision within one second in an isolated local observer without manual refresh. While the Workstream is live (U3016i), active observed durations advance at least once per second while visible; hiding or closing the dashboard stops its display timer without stopping collection. Repeated open/close and Project switches leave at most one subscription and display clock for the current view. Collection does not reread all historical records on every update. Assert `u3016d_observations_update_one_live_view` on the App seam with fake time, checking data revisions, subscription/timer counts and teardown; record the source-to-Daemon collection delay separately in U3016f rather than hiding it in this one-second bound.

Given duplicate/reordered Events, a lost subscription, failed read, Daemon exit or restart, then durable source identities keep the same totals after replay. A reconnect first reconciles a coherent snapshot/revision and then follows newer updates; an older response cannot replace newer data or data from another selected Workstream/Project. A failed collection/read keeps the last good measurement visibly stale with last observation time, the cause and a retry action. Initial loading, no work yet, unsupported measurement and stale data are distinct states; an empty successful response does not mean a failed read succeeded. Assert `u3016d_reconnect_reconciles_without_double_counting` through the real Daemon/public seams with persistence and replay, and `u3016d_stale_reads_keep_original_identity_and_retry` on the App seam with reversed responses and failure injection.

Given many Agents, then the initial view shows the first 20 ranked rows and the full Agent count, with an explicit way to load subsequent rows. Pages of one revision have no gaps or duplicates and reconcile with that revision's totals; newer observations invalidate/reconcile the pages rather than silently mix snapshots. No top-N limit discards stored contributions or makes the remaining detail inaccessible. Loading more preserves selection/focus; failure preserves visible rows and offers retry. An Agent's row opens its existing Agent view when still available, otherwise explains that its Agent was removed without opening another Agent. Assert `u3016e_paging_and_navigation_keep_all_contributors` with 1,005 contributors, tied values across page boundaries, an intervening revision, a failed next page and a removed Agent.

**U3016g the time is one chart of where each Agent's time went.** Given a Workstream with elapsed 9 h 49 m and three Agents, A with 12 m of summed Agent time (model 6 m, tools 4 m, waiting for human 2 m), B with 3 m (model 3 m) and C with 40 s (model 30 s, coordination 10 s), then the centre reads top to bottom: a header with the Workstream name and its state line (U3016j), one line `9h 49m elapsed · 15m 40s Agent time`, and one chart. There is no Cost, Tokens, List price or Weekly limit tile, row or line, no rank Tabs, no ratio and no Live/Stopped badge (U3016k, U3016l). The view's name, its entry control and its region are "Time". Assert `u3016g_dashboard_reads_in_the_ordered_layout` on the App seam by role and order, never geometry.
- Form: one horizontal stacked bar per Agent, all on one shared zero-based duration scale whose full width is the longest row's summed Agent time (U3016c: summed Agent time, never elapsed time). Within a row the segments run in a fixed order: waiting for human, tools, coordination, Agent work, other, unmeasured. Waiting for human is first so that every row's wait starts at the one baseline and its lengths compare by position, which is how "who waited on me" reads at a glance; the row's end reads "where did the time go" and its length "who spent the most". The Agent name leads each row and its summed duration follows the bar, right-aligned in fixed-width figures. Policy (design record, the spec run's choice with the `dataviz` skill and Tufte's data-ink and small-multiple rules): a heat map of Agents × category loses the comparison, since colour intensity ranks values far less exactly than length and it gives each Agent's total no place; Agents × time of day answers "when", needs a per-interval bucketing the contract does not carry, and shows nothing of "who waited"; one bar per Agent partitions each Agent's own summed time, which U3016c allows (it forbids a partition of wall time), and uses the least ink per value.
- Marks: a segment exists only for a category with positive measured duration; a zero or unknown category has no segment, no gap and no label. Each segment's accessible name is `<Agent>, <category>, <duration>, <share of that Agent's time>`, so the value is available by keyboard focus and by hover; a duration is also written inside a segment when it fits. Categories use Tokens (U4), one fixed hue per category, never red/green alone. A row whose Agent has no positive category shows no bar and one `—` as its duration (unknown) or `0s` (measured zero) (U3016b's distinction survives for time).
- Category key: one line above the chart naming each category with positive time in at least one row, in the segment order, with its Workstream total and share of summed Agent time (`Waiting on you 2m · 13%`). It carries the only percentages: each divides by summed Agent time, never elapsed time (U3016c). A category with no positive time is absent from the key.
- Empty: with no positive duration in any row the chart region shows one line, "No work measured yet", and no key or row. Loading, no work yet, unsupported and stale remain the distinct states of U3016d.
- Notes: a partial figure (history not measured, unknown Attempt end) keeps one mark beside the affected duration that opens its note (U3016k); no "How this is measured" disclosure, gap-count heading, coverage prose or revision number renders.
- Numbers: durations in their top two units (`9h 49m`, `4m 12s`); whole percentages with `<1%` below one percent; unavailable is `—`, never `0`; no raw float, raw seconds or internal term (an id, enum name or code term) is on screen. Rounding is display only.
Assert, on the App seam: `u3016g_chart_has_one_mark_per_nonzero_category_per_agent` (the three Agents above render segments A 3, B 1, C 2, nothing for a zero or unknown category, and no cost, token or limit text or role anywhere), `u3016g_segments_share_one_scale_and_one_order` (the accessible values and the order of A's segments; the scale itself is the design critic's), `u3016g_key_totals_divide_by_summed_time` (key totals and shares over unsorted, zero, dominant and empty inputs, the denominator being summed Agent time), `u3016g_numbers_use_display_units_and_never_show_unavailable_as_zero` over 0, 1 s, 59 s, 3,599 s, 0.4%, unknown and measured zero.
