# Unfinished input

Module: `apps/desktop`, retaining the existing Daemon delivery boundary. Ids: U2773a–U2773h, U3021a–U3021d. These are acceptance specifications, not implementation evidence. P11 governs every surface below; P4/P9 preserve the opaque vendor editor and authorized delivery.

## Policy and lifecycle

**Policy.** A draft is unsubmitted user-entered content and its associated selections, original Project path, object identity and recipient identity. Retain the exact editor value, including leading/trailing whitespace, newlines, combining characters and emoji; an existing submit contract may transform the submitted value but must not transform recovery text. Capture all fields of a form together. Names and current selection are never replacement identities. Preserve selection/caret when reopening the same editor; background restoration never steals focus. Explicit reopening uses that surface's existing focus contract.

Persist ordinary drafts locally per Project and surface using existing holders and validated storage facilities where possible. No age-based expiry or silent oldest-first eviction. Acknowledged submission or explicit discard removes only the selected revision. Existing autosave remains authorized by the edit, not by restoration: reopening a recovered dirty draft offers an explicit resume/save action before any write. Closing, Escape and switching hide work; they are not discard. This supersedes earlier Escape/cancel clauses only where they would destroy an unsubmitted edit (including U511a rename); Escape still sends nothing and returns focus as before. Existing blur/Enter commits remain authorized submit actions, subject to acknowledgement of the matching revision. Existing explicit cancel/revert actions must identify that they discard the selected edit. A deleted, renamed or unavailable original remains recoverable by its original identity; recovery offers copy or explicit discard, never recreation or retargeting without a new user action.

Bound durable retention to 10 MiB of UTF-8 serialized draft data per Project. At the bound, preserve existing records and the complete new in-memory work, report which draft cannot be retained across reload, and offer copy, retry and selected discard. Do not truncate text to fit. Per-field existing input limits still apply. Pending submitted snapshots and failed revisions count toward the bound and cannot be silently evicted. A missing storage record is empty; malformed, incompatible or unreadable data is a visible restore failure, with its original stored bytes left intact for recovery. Declared credential fields keep their existing secret policy: no new automatic persistence in disk, logs or captures. No vendor editor state is serialized or reconstructed.

Recovery is attached to the owning surface and Project: current draft first, separately selectable failed/pending revisions with original destination and status. Selecting an older revision cannot overwrite newer work. U3021a narrows Project-local recovery to work at risk; other retained work remains recoverable from its own editor. Restore sends zero mutations; unknown submit acceptance remains unknown, never labelled failed or retried automatically. A user-initiated retry first uses the existing acceptance/reconciliation seam where available; it must not duplicate a known accepted effect.

Policy: implementation adds the following seven rules, attributed to #3021, under “The owner's visual taste” in `.agents/data/journey.md`; subsequent UI PRs are judged against them. This specification merge claims no implementation or completed rendered observer.

- Every string answers the user (#3021). A rendered text node is one of: text the user typed; a name the user gave, or one that names the item elsewhere in the App; a time; a `GLOSSARY.md` user-label state with its KindGlyph; an error that names its cause and its fix; a control's label; a section head. No other text renders: no id, revision or storage key, no path of the open Project, no fallback label for an unmapped field (`Stored value`), no statement that roundup did not check something (`Original availability not verified`). The critic names each text node's kind on the seed; a node of no kind is a block.
- Every control changes something. Pressing a control in the seed changes what is on screen, calls an RPC or writes the clipboard. A control that would change nothing in that state does not render (with one revision, no `Inspect`). An item offers at most one `Copy`, which copies all its text.
- Typing moves nothing else. While the user types into a field whose saves succeed, no element outside that field mounts, unmounts or changes its text. Observer: type 20 characters with acknowledged saves; a MutationObserver on the App root, outside the field, records nothing.
- History is opt-in. Past changes, revisions and logs open collapsed, as one line with their count and a disclosure; entries render only after the user opens it. Each entry reads `<past-tense verb> <value> · <time>`, plus the actor when it is not the user (`Renamed to jbkhnj`, `Marked done`), never `Field: value`.
- A state is never a bare control word. No text node outside a control equals a control label from the App copy catalogue (`Done`, `Open`, `Copy`, `Discard`); section heads are exempt.
- Choosing from other items is a menu. Picking one item from a list of others (a blocker, an Agent, a Model) opens the shared `apps/desktop/src/ui/Combobox.tsx`: floating, anchored to its trigger, filtered by typing, closed by Escape with focus back on the trigger. It never expands the list inline in the page.
- Actions sit on their row. A row's text actions sit on the baseline of the row's first line, within 1 px.
