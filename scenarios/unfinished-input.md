## Policy and lifecycle

**Policy.** A draft is unsubmitted user-entered content and its associated selections, original Project path, object identity and recipient identity. Retain the exact editor value, including leading/trailing whitespace, newlines, combining characters and emoji; an existing submit contract may transform the submitted value but must not transform recovery text. Capture all fields of a form together. Names and current selection are never replacement identities. Preserve selection/caret when reopening the same editor; background restoration never steals focus. Explicit reopening uses that surface's existing focus contract.

Persist ordinary drafts locally per Project and surface using existing holders and validated storage facilities where possible. No age-based expiry or silent oldest-first eviction. Acknowledged submission or explicit discard removes only the selected revision. Existing autosave remains authorized by the edit, not by restoration: reopening a recovered dirty draft offers an explicit resume/save action before any write. Closing, Escape and switching hide work; they are not discard. This supersedes earlier Escape/cancel clauses only where they would destroy an unsubmitted edit (including U511a rename); Escape still sends nothing and returns focus as before. Existing blur/Enter commits remain authorized submit actions, subject to acknowledgement of the matching revision. Existing explicit cancel/revert actions must identify that they discard the selected edit. A deleted, renamed or unavailable original remains recoverable by its original identity; recovery offers copy or explicit discard, never recreation or retargeting without a new user action.

Bound durable retention to 10 MiB of UTF-8 serialized draft data per Project. At the bound, preserve existing records and the complete new in-memory work, report which draft cannot be retained across reload, and offer copy, retry and selected discard. Do not truncate text to fit. Per-field existing input limits still apply. Pending submitted snapshots and failed revisions count toward the bound and cannot be silently evicted. A missing storage record is empty; malformed, incompatible or unreadable data is a visible restore failure, with its original stored bytes left intact for recovery. Declared credential fields keep their existing secret policy: no new automatic persistence in disk, logs or captures. No vendor editor state is serialized or reconstructed.

Recovery is attached to the owning surface and Project: current draft first, separately selectable failed/pending revisions with original destination and status. Selecting an older revision cannot overwrite newer work. Recoverable unavailable objects have a Project-local recovery entry. Restore sends zero mutations; unknown submit acceptance remains unknown, never labelled failed or retried automatically. A user-initiated retry first uses the existing acceptance/reconciliation seam where available; it must not duplicate a known accepted effect.
