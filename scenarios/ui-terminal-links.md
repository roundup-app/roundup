# UI: opening links and paths from a Terminal (U365)

Module: `apps/desktop` (the webview). Ids: U365, U365b.

**U365 a plain click on a web link or file path in a Terminal opens it.** Owner amendment #5582 replaces Cmd+click with an unmodified primary click. Applies to every Agent, Door and shell Terminal, including Bubbles. Reuse the existing `findTargets`, path resolution and `openTarget` App seam; no new RPC, App seam command, Token or domain term is specified (policy). Ask-row and Overview Message acceptance extends U505 (`scenarios/ask-bar.md`) below. Acceptance only; this specification claims no implementation. Given a Terminal that printed `https://example.com`, `/abs/path/a.ts` and `src/a.ts:42`, then:

- **Recognised text.** A web link is `http://` or `https://` up to the next whitespace, without trailing `.`, `,`, `;`, `)` or quotes. After removing surrounding punctuation and an optional numeric `:line` or `:line:column`, an absolute path must contain another `/` after its leading `/`, or end in a file extension: a dot followed by an ASCII letter and zero or more ASCII letters or digits. A relative path must hold a `/` or end in that same extension. `/` alone is no target. Recognition uses the printed text only; existence is checked on opening, as below (policy). Thus `/abs/path/a.ts`, `src/a.ts:42`, `README.md`, `/tmp/moo-identity/taste/heading-logo-board.png`, `/abs/folder`, `/abs/folder/` and `/tmp/` remain paths; a root-level extensionless folder is printed with its trailing `/` (for example `/tmp/`), while a root-level extensionless file needs an explicit relative spelling such as `./LICENSE` against `/` to be recognised. Bare `/word` and `/word:word`, including `/clear`, `/context` and `/hope:compose`, are plain text. This is a syntax rule, with no command-name list and no filesystem lookup during recognition or hover (policy). Asserted in the amended `u365_recognises_links_and_paths` and retained `u365_trailing_punctuation_is_not_part_of_a_link`.
- **Slash commands stay plain text.** Given `/clear /context /hope:compose /word /word:word` printed in any Agent, Door or shell Terminal, including Bubbles, hovering and primary-clicking those ranges calls no `openTarget`; no missing-path error appears. They have no link underline or hand cursor (rendered policy). The same text in Ask rows and read-only `TargetText` has no link anchor; ordinary row selection remains U505's. Recognising and hovering this text or a recognised target starts no Agent, sends no Ask or Message and types no prompt (P9). Asserted in proposed `u365_slash_commands_stay_plain_text` in `apps/desktop/src/terminal/u365_browser.test.ts` using a mounted real emulator and fake App call log, and proposed `u365_ask_slash_commands_stay_plain_text` in `apps/desktop/src/ask/u365_links.test.tsx` using the mounted Ask row and read-only text; the rendered observer judges underline and cursor. These complement the amended recognition test, rather than substituting a direct `ILink.activate` call for hover/click.
- **Plain click opens once.** With no key held, one primary press/release on a recognised range, with no drag, calls `openTarget` exactly once for the complete target. Every cell of the target is clickable, including each wrapped row; adjacent whitespace and excluded punctuation open nothing. Asserted in proposed `u365_plain_click_opens_once` (path and URL cases, every Terminal kind) and the amended `u365_wrapped_and_dense_lines_find_each_target` (activate from each wrapped row). These replace the obsolete `u365_cmd_click_opens_once` and `u365_a_plain_click_selects_and_opens_nothing` expectations, not the recognition, resolution or refusal proofs.
- **Selection keeps its gestures.** Dragging across a target selects text and calls no `openTarget`; double-clicking selects a word and calls no `openTarget`, including from the first click of the pair. Single-click activation must distinguish these gestures before opening (policy; no fixed delay is prescribed). Asserted in proposed `u365_drag_selects_without_opening` and `u365_double_click_selects_without_opening`, through real pointer sequences, with the fake App's call log read after gesture disambiguation settles. U101's copy behavior remains required; retain `u101_command_c_copies_only_selected_text_and_control_c_still_types`.
- **Hover works without a modifier or a second movement.** On the first hover over a recognised target, no key held, the entire target underlines and the pointer is a hand (rendered policy). Keep the pointer stationary over a cell, then separately print a target beneath it, scroll a target beneath it, and resize so a target occupies that cell. Each time, once xterm has rendered the new buffer, the current target is available and one click opens that target exactly once without another pointer movement. If the cell now holds plain text, clicking opens nothing. Proposed `u365_stationary_hover_tracks_output_scroll_and_resize` drives the mounted real emulator and fake App, observing the updated target through activation; no direct provider call or fake-emulator `clickLink` stands for this interaction. The rendered observer below judges underline, cursor and complete wrapped hit area.
- **Mouse reporting cannot swallow a link.** With xterm mouse reporting enabled by the Terminal program, a plain click on a recognised path or URL calls `openTarget` once and sends no mouse-report bytes to that program. A click outside a recognised target still reaches the program through its existing mouse reporting. Asserted in proposed `u365_links_open_in_mouse_reporting_mode` and `u365_other_clicks_keep_mouse_reporting`, using the mounted real emulator, fake App and recorded `terminal.write` calls.
- **A web link opens in the browser.** `openTarget {kind: "url", url}` opens the URL in the user's default browser. Only `http` and `https` are accepted by `openTarget`; any other scheme is refused and opens nothing. Amendment #5772: an Overview Message also renders existing `roundup://` object links as native anchors. These bypass `openTarget` and use `watchNativeOpen` with the existing `link.read` authorization; an Agent/Workstream link selects and focuses its exact centre Terminal under U5742c, and a refusal opens nothing and exposes its cause. This exception grants no other scheme permission. Asserted in `u365_a_web_link_opens_in_the_browser` and `u365_other_schemes_open_nothing`.
- **A path opens in the editor.** `openTarget {kind: "path", path, line}` opens the file in the user's default app for it, and Finder reveals a folder. A `:line` goes with the file; the App passes it to an editor that takes a line and ignores it otherwise. Policy chosen by this spec: the default app, never a setting, because no scenario asks for a choice and a setting can be added when one does. Asserted in `u365_an_absolute_path_opens_with_its_line` and `u365_a_folder_opens_in_finder`.
- **A relative path resolves against the Agent's Worktree** (the Rail node's `worktree.path` from `rail.tree`, G2), or against the Project folder when the Agent has none; the Door's Terminal resolves against the Project folder. The webview resolves it before `openTarget`, which receives only absolute paths. Asserted in `u365_a_relative_path_resolves_against_the_worktree` and `u365_without_a_worktree_it_resolves_against_the_project`.
- **A path that does not exist opens nothing and says so.** The App checks existence; a missing path returns `NOT_FOUND`, the webview shows `<path> does not exist` in U80's line style, and no app is launched. Asserted in `u365_a_missing_path_opens_nothing_and_says_so`.
- **One handler.** The Door, Agent and shell Terminals, including Bubbles, use the same recognition and opening handler, differing only in the base folder. Asserted in `u365_the_door_and_an_agent_share_one_handler`.
- **Densest seed.** A line holding 20 links and paths, one wrapped across two rows, finds each by its cells, and a wrapped link opens as one target. Asserted in `u365_wrapped_and_dense_lines_find_each_target`.

**U365b a printed web address without a scheme opens in the browser, and every link form a Terminal shows has one target.** Applies to every Agent, Door and shell Terminal, including Bubbles, Ask rows and read-only `TargetText`. Reuse U365's `findTargets`, path resolution and `openTarget`; no new RPC, App seam command, Token or domain term (policy). Given a Terminal in Project `shark-tank-alternative` that printed `legislation.gov.uk`, `www.example.com/a`, `example.co.uk/x?y=1`, `README.md` and `notes.io`, then:

- **A bare domain is a link.** A token is a bare domain when it has no leading `/`, `./`, `../` or `~/`, no `@`, no `:line`, and its host (the text before the first `/`, `?` or `#`) is two or more dot-separated labels of letters, digits and hyphens whose last label is on the public suffix list (the ICANN section; private suffixes such as `github.io` do not count). Recognition uses a bundled list and the printed text only: no remote request and no filesystem lookup during recognition or hover (policy). Its target is `https://` plus the token, without the trailing punctuation U365 strips. Asserted in `u365b_a_bare_domain_is_a_link`, a table test over `findTargets`.
- **An existing path wins.** Opening a bare domain first asks `openTarget` for the path U365 resolves (base per U365); only a `NOT_FOUND` answer is followed by `openTarget {kind: "url", url: "https://" + token}`. A file or folder named `README.md` or `notes.io` next to the Project therefore opens as that path, and `legislation.gov.uk` with no such file opens `https://legislation.gov.uk` once, showing no failure line. When the path is missing and the URL is refused, the failure line shows the URL's cause, not `<path> does not exist`. Asserted in `u365b_an_existing_file_named_like_a_domain_opens_the_file`, `u365b_a_missing_file_falls_back_to_https` and `u365b_a_refused_fallback_shows_its_cause`, against the fake App.
- **Not a domain stays as U365 has it.** A token whose last label is not a public suffix and that is not a path by U365's syntax (`foo.notatld`, `a.b`, `v1.2`, `file.txt`-style paths excepted) is no link, as today; `file.txt` stays a path. Asserted in `u365b_a_non_suffix_token_stays_plain_text`.
- **Audit.** Each form opens its target or is no link; the PR records the audit as this table with the test that proves each row, and fixes every row that differs:

| Printed form | Target |
|---|---|
| `http://` / `https://` URL | itself via `openTarget {url}` (U365) |
| OSC 8 hyperlink | its URI when `http` or `https`, via `openTarget {url}` and never xterm's `window.confirm`/`window.open`; any other scheme opens nothing |
| bare domain, with or without path or query | the rule above |
| `mailto:a@b.co`, `a@b.co` | no link (`openTarget` refuses non-http schemes; no address is a path) |
| `/abs/a.ts`, `src/a.ts`, `README.md` | the path per U365 |
| `~/notes/a.md`, `~/` | the path under the user's home folder, expanded by the App's path check, never joined to the base |
| `src/a.ts:42`, `src/a.ts:42:7` | the path with its line (U365) |

  Asserted in `u365b_every_link_form_maps_to_its_target`, a table test through the mounted emulator's link finder and `openTarget` call log, one row per line above, plus `u365b_osc8_http_opens_through_open_target`.
- **Scope.** The webview's `terminal/links.ts` and `terminal/screens.ts` change; `crates/desktop/src/open.rs` changes only for the `~/` expansion. Library choice is rule 9's: research `linkify-it`, `tldts`, `psl` and the xterm web-links addon before any matcher; a library must work offline (policy).

**openTarget**: The existing App seam command (`open_target`) that opens a web link in the browser, or an absolute path in its default app (a folder in Finder), when the user clicks a recognised target in a Terminal, Ask row or Overview Message; a missing path is `NOT_FOUND`, a scheme but http and https is `FORBIDDEN` (U365).
