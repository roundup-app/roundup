# UI: opening links and paths from a Terminal (U365)

Module: `apps/desktop` (the webview). Ids: U365.

**U365 Cmd+click on a web link or a file path in a Terminal opens it.** Found by the issue #945: the Terminal (`apps/desktop/src/terminal/emulator.ts:3-5`, loading the fit, unicode11 and webgl addons) shows a printed link or path as plain text and the App has no way to open either. Adds one App seam command, `openTarget` (Contract recipe; `GLOSSARY.md` gains **openTarget** in the same PR), and one xterm link provider shared by every Terminal pane: each Agent's and the Door's Claude Code Terminal, the Bubbles included. Changes no Daemon method and no Token. Given a Terminal that printed `https://example.com`, `/abs/path/a.ts` and `src/a.ts:42`, then:

Definition (relocated): **openTarget**:
The App seam command (`open_target`) that opens a web link in the browser, or an absolute path in its default app (a folder in Finder), when the user Cmd+clicks one printed in a Terminal; a missing path is `NOT_FOUND`, a scheme but http and https is `FORBIDDEN` (U365).

- **Recognised text.** A web link is `http://` or `https://` up to the next whitespace, without trailing `.`, `,`, `;`, `)` or quotes. A path is an absolute path (`/…`) or a relative one holding a `/` or ending in a file extension, with an optional `:line` or `:line:column`. Text that is neither is no link. Asserted in `u365_recognises_links_and_paths` and `u365_trailing_punctuation_is_not_part_of_a_link`.
- **Cmd+click opens, a click does not.** Cmd+click (`metaKey`) on a recognised range calls `openTarget` once. A plain click, or Ctrl, Shift or Alt without Cmd, calls nothing and selects text as before (U101's copy is unchanged; `u101_command_c_copies_only_selected_text_and_control_c_still_types` keeps passing). While Cmd is held the range under the pointer is underlined and the pointer is a hand; with Cmd up neither shows. Asserted in `u365_cmd_click_opens_once` and `u365_a_plain_click_selects_and_opens_nothing`.
- **A web link opens in the browser.** `openTarget {kind: "url", url}` opens the URL in the user's default browser. Only `http` and `https` are accepted by the App; any other scheme is refused and opens nothing. Asserted in `u365_a_web_link_opens_in_the_browser` and `u365_other_schemes_open_nothing`.
- **A path opens in the editor.** `openTarget {kind: "path", path, line}` opens the file in the user's default app for it, and Finder reveals a folder. A `:line` goes with the file; the App passes it to an editor that takes a line and ignores it otherwise. Policy chosen by this spec: the default app, never a setting, because no scenario asks for a choice and a setting can be added when one does. Asserted in `u365_an_absolute_path_opens_with_its_line` and `u365_a_folder_opens_in_finder`.
- **A relative path resolves against the Agent's Worktree** (the Rail node's `worktree.path` from `rail.tree`, G2), or against the Project folder when the Agent has none; the Door's Terminal resolves against the Project folder. The webview resolves it before `openTarget`, which receives only absolute paths. Asserted in `u365_a_relative_path_resolves_against_the_worktree` and `u365_without_a_worktree_it_resolves_against_the_project`.
- **A path that does not exist opens nothing and says so.** The App checks existence; a missing path returns `NOT_FOUND`, the webview shows `<path> does not exist` in U80's line style, and no app is launched. Asserted in `u365_a_missing_path_opens_nothing_and_says_so`.
- **One handler.** The Door's Terminal and Agent Terminals use the same provider, differing only in the base folder. Asserted in `u365_the_door_and_an_agent_share_one_handler`.
- **Densest seed.** A line holding 20 links and paths, one wrapped across two rows, finds each by its cells, and a wrapped link opens as one target. Asserted in `u365_wrapped_and_dense_lines_find_each_target`.

Observer: `u365_` Vitest cases in `apps/desktop/src/` against the fake App, whose `openTarget` records its calls, and a Rust test of the seam command's scheme and existence checks. WKWebView's own modifier clicks are the one thing the harness cannot show, so the PR that implements this asks the user for a `macOS:` line with a real Cmd+click on a link and a path.
