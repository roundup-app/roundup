# UI: capture a thought from the keyboard (U3713 to U3716)

Specification for #2898. Owner's goal: seamless, quick thought capturing. Journey stage: Enter (`.agents/data/journey.md`). Implementation acceptance, not shipped behaviour.

Scope (policy): `apps/desktop/src/keys/` (`chords.ts`, Help, hints), `apps/desktop/src/todos/` for the field, `apps/desktop/src/copy.ts`, one mount line in `App.tsx`. No RPC, App seam command, Token or GLOSSARY term: it calls `todo.create {title}` (T1) with no owner, which T16 shows as `Unassigned`. Reuse (rule 9): the field is a `ui/` primitive wrapping Ark UI; the key is a `LEADER` row read by Help, the leader panel and the hint line (U2240, U2241), never a parallel list.

**U3713 `⌘K` then `T` opens the capture field.** Given an open Project and no modal layer, when the user presses `⌘K` then `T` (U2239's rules: key position, Caps Lock neutral, from anywhere including a watched Agent's pane), then a one-line field opens focused and empty, over the centre and without changing the selection. `T` is a free letter of `LEADER` and holds `⌘K  T  Capture a Todo` in Help (U54) and the leader panel (U2240). It adds no app-scope modifier chord (U2241 holds: the modifier sweep still passes), and a key press inside the field reaches no Terminal. Tests (`u3713_`, `apps/desktop/src/keys/`): `u3713_leader_t_opens_a_focused_empty_field_without_changing_selection`, `u3713_help_and_panel_list_the_key_from_the_table`, `u3713_the_modifier_sweep_still_passes`.

**U3714 Enter files an Unassigned Todo and closes the field.** Given the open field (U3713) holding non-blank text, when the user presses `⏎`, then `todo.create {title}` is called once with the trimmed text and no owner, in the active Project, the field closes at once and focus returns to the element that held it before `⌘K`; the new Todo's row shows before the Daemon's reply (the reply then confirms it, or U3715 applies). A blank field files nothing and stays open. Escape closes with no call and the same focus return. The capture costs `⌘K`, `T` and the text, then `⏎`. Tests (`u3714_`): `u3714_enter_creates_one_unassigned_todo_shows_its_row_and_restores_focus`, `u3714_blank_enter_calls_nothing`, `u3714_escape_calls_nothing_and_restores_focus`, and `u3714_capture_in_two_chords_on_tree_40` (a headless real-browser test under `apps/desktop/src/keys/` in the isolated agent-browser session of `.agents/builder.md`, recording zero pointer events). A native Mac look is not asserted; the user reports what they meet on the Mac.

**U3715 a failed create keeps the text and says why.** Narrows U3714's closing; U2773a and U2773b hold. Given a `todo.create` that fails, when its reply arrives, then the optimistic row is removed, the field is open again holding exactly the typed text (a newer text typed meanwhile stays current and the failed one stays recoverable, U2773b) and shows U80's one failure line with the cause. Escape then discards the draft. Tests (`u3715_`): `u3715_a_rejected_create_reopens_the_field_with_the_text_and_the_cause`, `u3715_text_typed_during_a_pending_create_survives_its_rejection`.

**U3716 `⇧⏎` files and keeps the field open.** Given the open field with non-blank text, when the user presses `⇧⏎`, then `todo.create` is called once as U3714 says, the field stays open, focused and empty, and the Todo's row shows at once; a failure (U3715) puts the text back. Focus return waits for the field's close. Tests (`u3716_`): `u3716_shift_enter_files_and_leaves_an_empty_focused_field`, `u3716_a_failed_shift_enter_restores_the_text`.

Look (policy): the field's rendered state meets D2, D5 and D6 (`docs/design-system.md`, heading `The checks`) in dark and increased contrast with the failure text visible; only Tokens; the design critic judges it (rule 10). Moves D2, D5, D6.
