# UI: capture a thought from the keyboard (U3713 to U3716, U3737 to U3740)

Specification for #2898. Owner's goal: seamless, quick thought capturing. Journey stage: Enter (`.agents/data/journey.md`). Implementation acceptance, not shipped behaviour.

Scope (policy): `apps/desktop/src/keys/` (`chords.ts`, Help, hints), `apps/desktop/src/todos/` for the field, `apps/desktop/src/copy.ts`, one mount line in `App.tsx`. No RPC, App seam command, Token or GLOSSARY term: it calls `todo.create {title}` (T1) with no owner, which T16 shows as `Unassigned`. Reuse (rule 9): the field is a `ui/` primitive wrapping Ark UI; the key is a `LEADER` row read by Help, the leader panel and the hint line (U2240, U2241), never a parallel list.

**U3713 `⌘K` then `T` opens the capture field.** Given an open Project and no modal layer, when the user presses `⌘K` then `T` (U2239's rules: key position, Caps Lock neutral, from anywhere including a watched Agent's pane), then a one-line field opens focused and empty, over the centre and without changing the selection. `T` is a free letter of `LEADER` and holds `⌘K  T  Capture a Todo` in Help (U54) and the leader panel (U2240). It adds no app-scope modifier chord (U2241 holds: the modifier sweep still passes), and a key press inside the field reaches no Terminal. Tests (`u3713_`, `apps/desktop/src/keys/`): `u3713_leader_t_opens_a_focused_empty_field_without_changing_selection`, `u3713_help_and_panel_list_the_key_from_the_table`, `u3713_the_modifier_sweep_still_passes`.

**U3714 Enter files an Unassigned Todo and closes the field.** Given the open field (U3713) holding non-blank text, when the user presses `⏎`, then `todo.create {title}` is called once with the trimmed text and no owner, in the active Project, the field closes at once and focus returns to the element that held it before `⌘K`; the new Todo's row shows before the Daemon's reply (the reply then confirms it, or U3715 applies). A blank field files nothing and stays open. Escape closes with no call and the same focus return. The capture costs `⌘K`, `T` and the text, then `⏎`. Tests (`u3714_`): `u3714_enter_creates_one_unassigned_todo_shows_its_row_and_restores_focus`, `u3714_blank_enter_calls_nothing`, `u3714_escape_calls_nothing_and_restores_focus`, and `u3714_capture_in_two_chords_on_tree_40` (a headless real-browser test under `apps/desktop/src/keys/` in the isolated agent-browser session of `.agents/builder.md`, recording zero pointer events). A native Mac look is not asserted; the user reports what they meet on the Mac.

**U3715 a failed create keeps the text and says why.** Narrows U3714's closing; U2773a and U2773b hold. Given a `todo.create` that fails, when its reply arrives, then the optimistic row is removed, the field is open again holding exactly the typed text (a newer text typed meanwhile stays current and the failed one stays recoverable, U2773b) and shows U80's one failure line with the cause. Escape then discards the draft. Tests (`u3715_`): `u3715_a_rejected_create_reopens_the_field_with_the_text_and_the_cause`, `u3715_text_typed_during_a_pending_create_survives_its_rejection`.

**U3716 `⇧⏎` files and keeps the field open.** Given the open field with non-blank text, when the user presses `⇧⏎`, then `todo.create` is called once as U3714 says, the field stays open, focused and empty, and the Todo's row shows at once; a failure (U3715) puts the text back. Focus return waits for the field's close. Tests (`u3716_`): `u3716_shift_enter_files_and_leaves_an_empty_focused_field`, `u3716_a_failed_shift_enter_restores_the_text`.

Look (policy): the field's rendered state meets D2, D5 and D6 (`docs/design-system.md`, heading `The checks`) in dark and increased contrast with the failure text visible; only Tokens; the design critic judges it (rule 10). Moves D2, D5, D6, D8.

# UI: capture with one chord (U3737 to U3740)

Specification for #3191. Owner's goal: add a Todo with one quick shortcut, from anywhere. Extends U3713 to U3716; they hold. Journey stage: Enter (`.agents/data/journey.md`). Implementation acceptance, not shipped behaviour.

Scope (policy): `apps/desktop/src/keys/` (`chords.ts`, Help, hints), the capture field of `apps/desktop/src/todos/`, `apps/desktop/src/copy.ts`. No RPC, App seam command, Token or GLOSSARY term. Reuse (rule 9): the chord is one `CHORDS` row read by Help and the hint line, never a parallel list; the field stays U3713's `ui/` primitive. Not an OS-wide shortcut: it works only while roundup is focused.

**U3737 `⇧⌘T` opens the capture field from anywhere in an open Project.** `⇧⌘T` is free: `CHORDS` holds `⌘T` (a new Terminal, U2241) and no `meta+shift+KeyT`. Given an open Project and no modal layer, when the user presses `⇧⌘T` (key position, Caps Lock neutral, as U2239) with focus in the Rail, the Shelf, an Agent's pane, a Pad or the Ask bar, then U3713's field opens focused and empty over the centre, the selection is unchanged and the event's default is prevented; a second `⇧⌘T` while it is open changes nothing. Given a modal layer open, it does nothing. `⌘K` then `T` opens the same field as U3713 says. Tests (`u3737_`, `apps/desktop/src/keys/`): `u3737_the_chord_opens_a_focused_empty_field_from_each_surface_without_changing_selection`, `u3737_the_chord_does_nothing_under_a_modal_layer`, `u3737_leader_t_still_opens_the_same_field`.

**U3738 the chord in a Terminal never reaches the Agent.** Narrows U2241's list of kept chords: it gains `⇧⌘T` and nothing else. Given a Terminal focused (a Bubble, a watched Agent's pane in take-control, the Door's Terminal), when the user presses `⇧⌘T`, then the field opens (U3737), the Terminal's key handler receives no key and `terminal.write` is called with no bytes; while the field is open its key presses reach no Terminal (U3713), and `⎋` returns focus to the Terminal. Every other `⌃`, `⌥` and `⌘` chord reaches the Terminal as U2241 says. Tests (`u3738_`): `u3738_the_chord_writes_nothing_to_the_terminal_and_focus_returns_on_escape`, and U2241's `u2241_no_other_chord_is_taken_at_app_scope` and `u2241_help_lists_exactly_the_kept_keys`, edited so their allowlist gains `meta+shift+KeyT` only (U2242's byte tests pass unchanged).

**U3739 the chord is listed with the other shortcuts.** Given Help (U54) and the hint line (U2230), when they render, then `⇧⌘T  Capture a Todo` is a row read from the `CHORDS` table, beside the existing `⌘K  T` row, and the leader panel (U2240) keeps its `T` row. Tests (`u3739_`): `u3739_help_and_hints_list_the_chord_from_the_table`.

**U3740 the field shows the Owner and Home the new Todo gets, and files it so.** Narrows U3714's "no owner" and U3716 for a selection; U3733 and U2744a's Add clause give the owner and Home. Given the open field, when the Rail selection is an Agent `a`, then a line beside the field reads `For <a's Rail name>` and `In <a's Workstream name>` (`In Project root` when `a` has none), and `⏎` calls `todo.create {title, owner: a's Actor}` once, then `todo.move` to `a`'s Workstream as U3733 says. With a Workstream selected the line reads `Unassigned` and `In <its name>`, and the Todo is created Unassigned, then moved to it; with the Project root, Overview or a Terminal selected it reads `Unassigned` and `In Project root` and the call is U3714's. The line follows a selection that changes while the field is open, and what it reads is what is filed. `⇧⏎` files the same way and the line stays. A refused create or move keeps the text and shows U3715's failure line. Every string is in `copy.ts` as a user label. Tests (`u3740_`): `u3740_the_line_names_the_owner_and_home_from_each_selection`, `u3740_enter_files_what_the_line_says`, `u3740_the_line_follows_a_selection_change_while_open`, `u3740_a_refused_move_keeps_the_text_and_shows_the_cause`.

Look (policy): the field with its line meets D2, D5 and D6 (`docs/design-system.md`, heading `The checks`) in dark and increased contrast with the longest Agent and Workstream names and the failure text visible; only Tokens; the design critic judges it (rule 10). Moves D2, D5, D6, D8.
