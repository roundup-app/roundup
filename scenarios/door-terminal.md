# The Door is the user's Terminal

Source: the owner's report and choices in #1497 (2026-10-13), amended by the owner's choice in #1580 (2026-10-14). Terms: Workstream, Door, Agent, Terminal, Bubble, Run, Checkpoint, Work order, Kind, Rail, Brief (`GLOSSARY.md`). Acceptance only; work ownership and dependencies live in GitHub Issues. No implementation is claimed by this specification.

The owner chose one Door per Workstream, a Door that delegates implementation and can act on its Workstream children as the user can, and children showing their questions and permission prompts in their own Terminals. These choices replace the custom Workstream view. Checkpoint storage and `checkpoint_write` stay as M10 in `scenarios/mcp.md`; the Door's Checkpoint rewind tool belongs to #808 (A35 in `scenarios/workstream-rewind.md`); U374's picker is removed. The Workstream working row belongs to the removed view, so #1116 has no remaining surface to implement. #1097 keeps its shared Glyph and Rail work; its application to Workstream-view rows goes.

Implementation uses scoped PRs within one module directory and about 2000 changed lines (rule 3): Agent launch/Brief (`crates/agents`), MCP offering (`crates/rup`), desktop removal and terminal selection (`apps/desktop`), and the Daemon hold and rewind prerequisites. GitHub Issues hold their dependencies. The #1580 specification amends acceptance first; implementation follows it. Overturned by #1580: the earlier ban on Door Terminal writes and answers, and removal of child Takeover controls. B6 in `scenarios/messages.md` specifies the Daemon prerequisite that holds every Door action on a taken-over child. Any missing implementation prerequisite is a scoped Issue, never an unobserved assumption or an expansion into another module.
