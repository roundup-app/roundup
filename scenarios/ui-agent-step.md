**U454 the Daemon reports the latest real step and the current turn.** Given a Door and a child Agent running through the real Daemon with a fake `claude` that emits the existing Signals and appends realistic session transcript records, when their turns run, then:

- `UserPromptSubmit` begins a turn, clears the previous step and tokens, and records its start once. `PreToolUse`, `PostToolUse` and repeated reads of the same transcript do not restart its clock. A second prompt begins a fresh turn rather than accumulating the previous turn. Test: `u454_a_turn_starts_once_and_the_next_turn_resets_it`.
- The latest `PreToolUse` supplies the tool and target: `Read` with `file_path: /project/src/Thread.tsx` yields `Reading Thread.tsx`; `Bash` with `command: just check` yields `Running just check`; `Edit` or `Write` with `file_path: /project/styles.css` yields `Editing styles.css`. A later tool replaces the earlier step; `PostToolUse` keeps it until another tool begins or the turn ends. Test: `u454_the_latest_tool_and_target_are_the_step`.
- Before a tool starts the step is absent. An unrecognized tool shows its tool name with no invented target; a missing target shows only the action (`Reading`, `Running` or `Editing`). No playful verb, reasoning text or terminal escape sequence is copied into the step. Test: `u454_missing_and_unknown_tools_do_not_invent_a_step`.
- Tokens are the turn's generated output tokens, matching the downward count in the report, not input, cached input, context size or plan Usage. Sum output usage from distinct assistant transcript records belonging to this turn, count a repeated record only once, and add later records incrementally. A missing count is absent, not zero; an observed zero is zero. Partial final records wait for completion; malformed records do not discard the last valid count or stop later valid records being read. Test: `u454_output_tokens_are_incremental_and_not_double_counted`.
- `Stop` freezes the turn's end and duration even though the Adapter returns the Agent to `idle`. A late transcript usage record can finish the count without moving that end. An Interrupt or failure freezes elapsed time but does not claim successful completion. With no observed turn, return no fabricated start, step, end or count. Test: `u454_stop_freezes_the_turn_without_changing_kind`; test: `u454_an_interrupt_failure_or_missing_turn_is_not_a_success`.
- The Door's observations belong to its Workstream row and a child's to that child; switching sessions never attributes one Agent's step or usage to another. Test: `u454_door_and_child_observations_stay_separate`.

Observer: Rust Adapter tests and real-Daemon integration tests named above probe the actual wire response after each Signal and transcript append, including two consecutive turns. Contract serialization alone is insufficient.

**U455 the Workstream row says what its Agent is doing.** Given U424's rows in the selected Workstream, including its Door, and U454's observations, then:

- A working row is its U446 Glyph, name, step, elapsed time and known tokens, in that order: `Reading Thread.tsx · 12m 56s · 51k tokens` after the name for 776 elapsed seconds and 51,000 output tokens. Under 60 seconds time is `Ns`; thereafter it is `Nm Ns`, with whole seconds floored and minutes unbounded. Tokens below 1,000 are the integer; at or above 1,000 they are thousands rounded to one decimal, with a trailing `.0` removed (`1.5k`, `51k`). Absent step or count omits that part and its separator; elapsed time still appears for an observed turn. Test: `u455_working_rows_show_step_elapsed_and_known_tokens`.
- A successfully ended turn reads `Done in 13m 1s · 2:05 AM` for 781 elapsed seconds ending at local 02:05, using the user's local clock format. This summary appears when that Agent's row is visible, including inside U424's open done fold; ending a turn changes no membership rule or Digest content. The duration and end time do not tick. Tests: `u455_an_ended_turn_shows_frozen_duration_and_local_time`, `u455_completion_keeps_the_existing_done_fold`.
- The name and whole step remain text, never HTML. A long step is cut with an ellipsis and its own `title` holds the entire step. A 60-character name and a 2,400-character command, non-Latin text and emoji never wrap the row, clip its Glyph, create horizontal page scrolling or increase its height. Updating step, time or count moves no row above it. Tests: `u455_long_names_and_steps_stay_on_one_line`, `u455_updates_move_no_row_above`.
- The Rail gains no step, duration, token count or completion line. No grey reasoning line is drawn under a step. A blocked, needs-you or error Glyph and its existing actionable text are preserved; an unsuccessful ending never reads `Done in`. Tests: `u455_the_rail_and_reasoning_line_are_absent`, `u455_attention_and_failure_are_not_overwritten`.

**U457 ten working Agents add no keystroke work or clock-wide repaint.** Given ten working Agents, their incremental transcripts and a visible row for each, when the Thread's input receives keystrokes and one second elapses, then transcript reads and progress RPC calls are independent of keystrokes: typing issues neither, and unchanged transcripts are not rescanned from their beginning. Clock ticks update only the elapsed-time text, not the name, step, tokens, Glyph, neighbouring row or whole Thread; the shared Glyph's independent compositor animation remains U446's. Closing the view and Drawer leaves no progress tick subscribed by either. Tests: `u457_typing_reads_no_transcript_or_progress_rpc`, `u457_usage_reads_only_new_transcript_bytes`, `u457_a_tick_updates_only_visible_elapsed_text`, `u457_closed_views_release_their_ticks`.
