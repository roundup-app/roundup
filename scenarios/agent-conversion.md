# Turn an Agent into a Workstream or a Mode (A5214a, A5214b, U5214, A5324, U5324)

Module: `crates/contracts`, `crates/agents`, `crates/rupd`, `apps/desktop/src/rail/` and `contracts/generated/`. Ids: A5214a, A5214b, U5214, A5324, U5324. Acceptance for #5214. Decided by the owner (2026-10-31): "we should be able to convert an regular agent to a workstream or a mode"; the Workstream keeps the chat. Builds on A22 (resume), A2693a (resume with a mode restarts a running target), A4452c (a Mode's saved first prompt) and #5213's rule that a menu offers only what the Daemon carries out.

## Checks on main

1. `crates/agents/src/resume.rs`, `Agents::resume`: an explicit mode restarts a running Agent or Door on its saved conversation; a Workstream is accepted only with a mode.
2. `crates/agents/src/door.rs`, `Agents::start_door`: starts a Door under a Workstream.
3. `crates/agents/src/rail_view.rs`: sets `can_resume` from the saved conversation and the exited state.
4. `apps/desktop/src/rail/menu/model.ts`, `createRailMenu`: builds the Rail menu entries for a row.

**A5214a Make a Workstream keeps the Agent's conversation.** Contract change (the Contract recipe). New method `agent.makeWorkstream {id}`, returning the new Workstream's `RailNode`; `GLOSSARY.md` gains its code term in the same PR. Given an Agent with a saved conversation that is not a child of a Workstream and not a Door, when the owner calls it, then the Agent's node becomes a Workstream node in the same Rail place (parent and order) with the same id, name, Terminal history and conversation id, that conversation is its Door, and the Workstream can start children (test `a5214a_the_agent_becomes_a_workstream_with_its_conversation`). A running Agent is restarted once on the same conversation, as `agent.resume` with a mode does, so it picks up the Door's Brief and tools; one launch, no typed prompt, no Model turn beyond the resume (`a5214a_a_running_agent_restarts_once_on_its_conversation`). An exited Agent converts without a launch and `agent.resume` with a mode on the new Workstream then succeeds (`a5214a_an_exited_agent_converts_without_starting`). A child of a Workstream, a Door, a Workstream and an Agent with no saved conversation are refused with `CONFLICT` and unchanged (`a5214a_other_nodes_are_refused_unchanged`). Policy: owner-only authority (an Agent cannot call it); the Agent's Todos, Pads and Messages keep their owner (P6).

**A5214b Save as Mode keeps the Agent unchanged.** Contract change (the Contract recipe). New method `agent.saveAsMode {id, name}`, returning the new Mode's `RailNode`; `GLOSSARY.md` records any new term. Given an Agent started by roundup, when the owner calls it with a non-empty name, then a Mode of that name exists (a Workstream in the Modes section) holding the Agent's Brief, tools, extras, Model and Effort, and a Workstream or Agent started in it carries the same Brief, tools, extras and Model (test `a5214b_the_mode_holds_the_agents_brief_tools_extras_and_model`). The Agent keeps its node, running state, conversation and settings (`a5214b_the_agent_is_unchanged`). An empty name is `INVALID_PARAMS` and creates nothing; an Agent that roundup did not start (it keeps the user's full setup, LC8) is refused with `CONFLICT` and creates nothing (`a5214b_a_bad_name_or_a_foreign_agent_creates_nothing`).

**U5214 the Rail menu offers both only where the Daemon accepts them.** Given a Rail on `agents-10` and `tree-40` (U26), when the owner opens the menu of an Agent row, then **Make a Workstream** and **Save as Mode…** appear exactly when `agent.makeWorkstream` and `agent.saveAsMode` would be accepted for that row (a table test over Agent running and exited, Agent with and without a conversation, child of a Workstream, Door, Workstream and Group; `u5214_offered_entries_match_the_daemon_guard`). Choosing Make a Workstream calls the method and the row shows as a Workstream with its name unchanged (`u5214_make_a_workstream_calls_the_method`). Choosing Save as Mode… asks for a name in a dialog from `ui/`, calls the method on confirm, shows the new Mode under MODES, and leaves the Agent row as it was; Escape or cancel calls nothing (`u5214_save_as_mode_asks_for_a_name`). A refused call shows the Daemon's message. The design critic judges the menu in light and dark (policy); no test checks looks.

**A5324 The Rail node says which conversions the Daemon accepts.** Contract change (the Contract recipe). `RailNode` gains `can_make_workstream` and `can_save_as_mode`, both booleans, true on an Agent node only; `GLOSSARY.md` records both in the same PR, and every caller of `RailNode` changes with them. Given any node, then `can_make_workstream` is true exactly when `agent.makeWorkstream` passes its guard on that node (root Agent, not a Door, a saved conversation, whether running or exited), and `can_save_as_mode` is true exactly when `agent.saveAsMode` passes its guard (an Agent roundup started); both read the guards `make_workstream` and `save_as_mode` run, so the two cannot differ (test `a5324_flags_match_the_guards`, a table over running and exited Agents with and without a saved conversation, started by roundup or not, child of a Workstream, Door, Workstream and Group). A freshly started root Agent whose conversation is not yet saved reports `can_make_workstream` false, and true on the Rail event that follows the save (`a5324_a_new_agent_gains_the_flag_when_its_conversation_saves`).

**U5324 the Rail menu offers conversions by the node's flags.** Given a Rail on `agents-10` and `tree-40` (U26), when the owner opens the menu of an Agent row, then **Make a Workstream** appears exactly when `can_make_workstream` is true and **Save as Mode…** exactly when `can_save_as_mode` is true, whatever the row's running state; `canMakeWorkstream` and `canSaveAsMode` in `apps/desktop/src/rail/menu/model.ts` read the flags and no other field (test `u5324_entries_follow_the_node_flags`, replacing the running-state rule of `u5214_offered_entries_match_the_daemon_guard` for these two entries). Right-clicking a freshly started root Agent before its conversation is saved shows no **Make a Workstream**, and an Agent roundup did not start shows no **Save as Mode…** (`u5324_unsaved_and_foreign_agents_get_no_entry`).
