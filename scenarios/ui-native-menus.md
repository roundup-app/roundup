# UI: native context menus (U2694a to U2694e)

Module: `apps/desktop` (the webview) and `crates/desktop` (the Tauri host, one App seam command). Ids: U2694a to U2694e. Implements #2694; needs LK1 to LK3 (links, #2692) and A2693a (`agent.resume {id, mode}`, #2693). The user decided: a right-click opens the macOS system menu (an `NSMenu`), never an in-app menu, and the menu teaches the keys. Adds **Context menu** to `GLOSSARY.md`; changes no Daemon method and no Token. Narrows U56, U367, U421, U511a, U183, U184, U140 and B50's use of `message.send`.

**U2694a one system menu, built from one model.** Contract change (rule 4): one App seam command, `show_context_menu {items, x, y}`, in `crates/desktop`, built on Tauri's menu API (`tauri::menu`, on `muda`) and popped up at the pointer (`x`, `y` in window CSS pixels), or under the focused row for the keys. `items` is a list of `{id, label, shortcut?, enabled, children?}`; the reply is the chosen `id`, or `null` when the menu closes with no choice. A submenu is a `children` list. Every caller changes in the same PR: the webview's one `contextMenu(model)` helper (`apps/desktop/src/ui/`) is the only caller, and each object below only builds a model.
- **Models, not markup.** A menu model is a pure function of the object and the Project's state, so each object's items are asserted without a menu. Tests (`u2694a_`, Vitest against the fake App): `u2694a_each_object_builds_its_items` (rows below), `u2694a_choosing_an_item_runs_its_action_and_null_runs_nothing`, `u2694a_the_helper_is_the_only_caller_of_the_command`.
- **A chord is text, never an accelerator.** `shortcut` is part of the item's label text (the chord as `CHORDS` or `LEADER` shows it, `keys/chords.ts`: `F2`, `⌘⌫`, `⌘⏎`, `⌘K W`), and the host sets no `NSMenu` key equivalent, so no menu item fires from the menu bar. Test: `u2694a_no_item_carries_an_accelerator` (the host builds each item with no accelerator) and `u2694a_a_shown_chord_is_the_one_the_webview_binds` (each shown chord is found in `CHORDS`, `LEADER` or `rail/keys.ts`). An action with no chord shows none.
- **Not an in-app menu.** `RailMenu.tsx`, the Terminal tab menu in `Bubbles.tsx` and their `role="menu"` tests (`u56_menu`, `u367_confirm`, `u511a_rename`, `u511a_browser`) are removed in the same PR; no `role="menu"` is drawn by roundup for these objects. Their then-clauses are proved by the tests below. U367's confirm and U56's `stop and remove` confirm stay inside the app as a dialog (`role="alertdialog"`, U184's pattern), because a native menu cannot be replaced by one.
- **Keys.** `ContextMenu` or `⇧F10` with focus in the Rail opens the native menu under the focused row and selects it, as U56 says; with focus in the pane the keys reach the Terminal. Test: `u2694a_the_menu_key_opens_the_focused_rows_menu_and_the_pane_keeps_it`.
- **Reuse (rule 9).** Selected: Tauri's menu API (`tauri`/`muda`). Rejected: the in-app Ark UI menu, which is not a system menu and so is not read by VoiceOver as one (`AXMenu`). The PR carries the `Reuse:` section.

**U2694b the items of each object.** Each object's menu lists its existing actions, in this order, with Rename wherever the object can be renamed. A disabled item is shown greyed, never hidden.

| Object | Items (chord shown) |
|---|---|
| Workstream row | Rename `F2` (U140), Restart, Start YOLO, Stop, Resume, Clear (U350's prompt), Send to Agent ▸, Copy Link, Remove `⌘⌫` |
| Agent row (an Agent, a Door, a Subagent) | Rename `F2`, Restart, Start YOLO, Stop, Resume, Send to Agent ▸, Copy Link, Remove `⌘⌫` |
| Project tab (U180) | Rename `F2` (U183), Copy Link is absent (a Project has no link kind), Close (U184) |

Stop, Resume and Remove follow U56: Stop is offered for an Agent or Door that runs and does what U14 did; Resume for an exited Agent; a Group offers Remove only; a Terminal's Stop is absent. A Pad and a Todo have no Rename item where U58 and U461 give them no editable name in place; where they do, Rename starts that in-place edit. Every action calls what its in-app form called: `agent.stop`, `agent.resume`, `rail.remove`, `rename_project`, `close_project`, `todo.complete`, the delete of U460, and the Rail's rename (U9). The remove confirm (U56, U367) and U184's close question are asked as before, and nothing is called before the answer. Tests (`u2694b_`): `u2694b_the_items_of_each_object` (the table; the Project tab has no Copy Link), `u2694b_rename_starts_the_in_place_edit_of_each_object` (row U9, tab U183, Terminal U511a, Pad, Todo), `u2694b_stop_resume_remove_call_what_they_called_and_confirm_as_before`, `u2694b_close_asks_as_u184_asks`, `u2694b_a_group_offers_remove_only`, `u2694b_a_removed_object_refetches_on_not_found`.

**U2694c Send to Agent and Copy Link carry a link.** Given an object with a link (LK1: a Pad, a Todo, an Agent, a Workstream, a Terminal), then:
- **Copy Link** writes its link `roundup://<kind>/<id>?project=<key>` to the clipboard and calls nothing else. Test: `u2694c_copy_link_writes_the_link`.
- **Send to Agent ▸** lists the Project's Agents, one item each by name in Rail order. Choosing one calls `message.send` (B1) to that Agent with kind `note` and a body of two lines: the link, then the command that reads it, `rup link read <link>` (for example `roundup://pad/notes?project=<key>` and `rup link read roundup://pad/notes?project=<key>`), so the receiving Agent needs nothing else. The Message holds no copy of the content (LK2 reads it at the time). Delivery is B50's: over the Claude inbox, never typed (B2 types only a `question`), and held while the user has unsent input (B32). An Agent that cannot receive (exited) is listed disabled. The object's own Agent is listed like the rest. Tests: `u2694c_send_to_agent_sends_a_note_with_the_link_and_the_read_command`, `u2694c_an_exited_agent_is_listed_disabled`, `u2694c_send_to_agent_lists_the_projects_agents_in_rail_order`.
- A failed call shows U80's `✕ <message>`. Test: `u2694c_a_failed_send_shows_the_failure_line`.
- Outside check (real Claude Code, E10): an Agent sent only that Message quotes the Pad's, Todo's or Terminal's current content. Observer: the real-Claude test lane of `scenarios/test-real-claude.md`, `u2694c_real_claude_quotes_the_linked_content` (policy: it runs there, not in `check`).

**U2694d Restart and Start YOLO.** On an Agent row and a Workstream row (its Door), running or exited, Restart calls `agent.resume {id, mode: "normal"}` and Start YOLO calls `agent.resume {id, mode: "yolo"}` (A2693a): the same session, Restart with normal permission prompts and YOLO off. The item matching the Attempt's current mode is disabled. The YOLO marker is drawn by the row, not by the menu. A `CONFLICT` or `NOT_FOUND` shows U80's `✕ <message>`. Tests: `u2694d_restart_calls_resume_normal_and_start_yolo_calls_resume_yolo`, `u2694d_the_item_of_the_current_mode_is_disabled`, `u2694d_both_show_on_a_running_or_exited_agent_and_a_door`, `u2694d_a_failed_resume_shows_the_failure_line`. Outside check: after Start YOLO the transcript keeps the session id and shows `permissionMode` off `default` (A2693a).

**U2694e a right-click is a click, a drag is a Pull.** Narrows U421. A right-button press and release that never reaches U421's 8 px opens the native menu on release at the pointer, for the object under it (a Rail row, a Project tab, a Terminal tab, a Pad, a Todo); on anything else the browser's own `contextmenu` is as before. A right-button drag past 8 px still starts U421's Pull and opens no menu, and the `contextmenu` after its release is cancelled. A press with a menu open closes it as a click elsewhere does. Tests: `u2694e_a_right_click_opens_the_menu_on_release`, `u2694e_a_right_drag_past_the_threshold_pulls_and_opens_no_menu` (both in `apps/desktop/src/bubbles/`).

**Observer and Mac check.** Tests are behaviour only: no layout test; the native menu has no webview layout. The system menu cannot be seen in Chromium, so one outside check needs hands: `flag:needs-mac` ask, the builder's only Mac gate. Steps: (1) build from the PR's merge commit and run `just app` on the Mac; (2) right-click a Rail Workstream row, an Agent row, a Project tab, a Terminal tab, a Pad and a Todo, one after another; (3) with VoiceOver on (`⌘F5`), `VO` + `Shift` + `M` opens the menu under the cursor; (4) each menu must be read as a menu (the `AXMenu` role in Accessibility Inspector), list its items from U2694b with their chords as text, and run none from the menu bar. A menu that is not read as a system menu fails U2694a.
