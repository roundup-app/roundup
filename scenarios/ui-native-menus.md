# UI: native context menus (U2694a to U2694g, U3812)

Module: `apps/desktop` (the webview) and `crates/desktop` (the Tauri host, one App seam command). Ids: U2694a to U2694g, U3812. Implements #2694; needs LK1 to LK3 (links, #2692) and A2693a (`agent.resume {id, mode}`, #2693). The user decided: a right-click opens the macOS system menu (an `NSMenu`), never an in-app menu, and the menu teaches the keys. Adds **Context menu** to `GLOSSARY.md`; changes no Daemon method and no Token. Narrows U56, U367, U421, U511a, U183, U184, U140 and B50's use of `message.send`.

**U2694a one system menu, built from one model.** Contract change (rule 4): one App seam command, `show_context_menu {items, x, y}`, in `crates/desktop`, built on Tauri's menu API (`tauri::menu`, on `muda`) and popped up at the pointer (`x`, `y` in window CSS pixels), or under the focused row for the keys. `items` is a list of `{id, label, shortcut?, enabled, children?}`; the reply is the chosen `id`, or `null` when the menu closes with no choice. A submenu is a `children` list. Every caller changes in the same PR: the webview's one `contextMenu(model)` helper (`apps/desktop/src/ui/`) is the only caller, and each object below only builds a model.
- **Models, not markup.** A menu model is a pure function of the object and the Project's state, so each object's items are asserted without a menu. Tests (`u2694a_`, Vitest against the fake App): `u2694a_each_object_builds_its_items` (rows below), `u2694a_choosing_an_item_runs_its_action_and_null_runs_nothing`, `u2694a_the_helper_is_the_only_caller_of_the_command`.
- **Native shortcut column.** U4322b supersedes the text-only/no-accelerator rule. Single-step `shortcut` values become native accelerators through the Project menu’s shared conversion, with plain labels and no persistent application-menu installation. Tests: `u4322b_items_carry_native_accelerators`, `u4322b_popup_accelerators_stay_in_the_popup`, and `u2694a_a_shown_chord_is_the_one_the_webview_binds`. An action with no chord shows none. U4322b requires separate native sequence hints; a sequence never becomes an accelerator.
- **Not an in-app menu.** `RailMenu.tsx`, the Terminal tab menu in `Bubbles.tsx` and their `role="menu"` tests (`u56_menu`, `u367_confirm`, `u511a_rename`, `u511a_browser`) are removed in the same PR; no `role="menu"` is drawn by roundup for these objects. Their then-clauses are proved by the tests below. U367's confirm and U56's `stop and remove` confirm stay inside the app as a dialog (`role="alertdialog"`, U184's pattern), because a native menu cannot be replaced by one.
- **Keys.** `ContextMenu` or `⇧F10` with focus in the Rail opens the native menu under the focused row and selects it, as U56 says; with focus in the pane the keys reach the Terminal. Test: `u2694a_the_menu_key_opens_the_focused_rows_menu_and_the_pane_keeps_it`.
- **Reuse (rule 9).** Selected: Tauri's menu API (`tauri`/`muda`). Rejected: the in-app Ark UI menu, which is not a system menu and so is not read by VoiceOver as one (`AXMenu`). The PR carries the `Reuse:` section.

**Context menu** (`show_context_menu`, `MenuItem`, `MenuEntry`, `Item`, `project_kind`, `context_menu`): The macOS system menu (`NSMenu`) a right-click or `ContextMenu` key opens on a Rail row, a Project tab, a Terminal tab, a Pad or a Todo; the webview builds its items and the host pops it up (U2694a). One-step shortcuts use the same native accelerator conversion as the Project menu (U4322b); popup items are never installed in the application menu. Adjacent `group` values produce native separators; unavailable actions and empty submenus are omitted. `creation` captures a Workstream Home for its existing Add flow (`createIn`, `finishCreation`, `useCreation`).

**U2694b the items of each object.** U4322a replaces this inventory’s flat order and Add entries with grouped applicable actions; unavailable actions are omitted, including empty submenus. The inventory below records the existing operations; retained confirmations, receiver identity and dispatch remain as specified.

A Pad and a Todo have no Rename item where U58 and U461 give them no editable name in place; where they do, Rename starts that in-place edit. The remove confirm (U56, U367) and U184's close question are asked as before, and nothing is called before the answer. Tests (`u2694b_`): `u2694b_the_items_of_each_object` (the table; the Project tab has no Copy Link), `u2694b_rename_starts_the_in_place_edit_of_each_object` (row U9, tab U183, Terminal U511a, Pad, Todo), `u2694b_stop_resume_remove_call_what_they_called_and_confirm_as_before`, `u2694b_close_asks_as_u184_asks`, `u2694b_a_group_offers_remove_only`, `u2694b_a_removed_object_refetches_on_not_found`.

**U2694c Send to Agent and Copy Link carry a link.** Given an object with a link (LK1: a Pad, a Todo, an Agent, a Workstream, a Terminal), then:
- **Copy Link** writes its link `roundup://<kind>/<id>?project=<key>` to the clipboard and calls nothing else. Test: `u2694c_copy_link_writes_the_link`.
- **Send to Agent ▸** lists the Project's Agents, one item each by name in Rail order. Choosing one calls `message.send` (B1) to that Agent with kind `note` and a body of two lines: the link, then the command that reads it, `rup link read <link>` (for example `roundup://pad/notes?project=<key>` and `rup link read roundup://pad/notes?project=<key>`), so the receiving Agent needs nothing else. The Message holds no copy of the content (LK2 reads it at the time). Delivery is B50's: over the Claude inbox, never typed, and pending until the inbox receipt. An Agent that cannot receive (exited) is omitted. U3515a/b (`scenarios/ui-target-pickers.md`) supersede self-target and exhausted-action behavior: the source Agent (the Door for a Workstream link) is excluded; with no eligible other receiver, U4322a omits Send to Agent. Tests: `u2694c_send_to_agent_sends_a_note_with_the_link_and_the_read_command`, `u2694c_an_exited_agent_is_listed_disabled`, `u2694c_send_to_agent_lists_the_projects_agents_in_rail_order`.
- A failed call shows U80's `✕ <message>`. Test: `u2694c_a_failed_send_shows_the_failure_line`.
- Outside check (real Claude Code, E10): an Agent sent only that Message quotes the Pad's, Todo's or Terminal's current content. Observer: the real-Claude test lane of `scenarios/test-real-claude.md`, `u2694c_real_claude_quotes_the_linked_content` (policy: it runs there, not in `check`).

**U2694d Restart and Start YOLO.** On an Agent row and a Workstream row (its Door), running or exited, Restart calls `agent.resume {id, mode: "normal"}` and Start YOLO calls `agent.resume {id, mode: "yolo"}` (A2693a): the same session, Restart with normal permission prompts and YOLO off. The item matching the Attempt's current mode is omitted under U4322a. The YOLO marker is drawn by the row, not by the menu. A `CONFLICT` or `NOT_FOUND` shows U80's `✕ <message>`. Tests: `u2694d_restart_calls_resume_normal_and_start_yolo_calls_resume_yolo`, `u2694d_the_item_of_the_current_mode_is_disabled`, `u2694d_both_show_on_a_running_or_exited_agent_and_a_door`, `u2694d_a_failed_resume_shows_the_failure_line`. Outside check: after Start YOLO the transcript keeps the session id and shows `permissionMode` off `default` (A2693a).

**U2694e a right-click is a click, a drag is a Pull.** Narrows U421. A right-button press and release that never reaches U421's 8 px opens the native menu on release at the pointer, for the object under it (a Rail row, a Project tab, a Terminal tab, a Pad, a Todo); on non-text App chrome no other menu opens (U2694f). Terminal emulators and editable/selectable text are excluded under U3529a/b (`ui-text-selection.md`). A right-button drag past 8 px still starts U421's Pull and opens no menu, and the `contextmenu` after its release is cancelled. A press with a menu open closes it as a click elsewhere does. Tests: `u2694e_a_right_click_opens_the_menu_on_release`, `u2694e_a_right_drag_past_the_threshold_pulls_and_opens_no_menu` (both in `apps/desktop/src/bubbles/`).

**Observer and Mac check (U2694a to U2694e).** Tests are behaviour only: no layout test; the native menu has no webview layout. The system menu cannot be seen in Chromium, so one outside check needs hands: `flag:needs-mac` ask, the builder's only Mac gate. Steps: (1) build from the PR's merge commit and run `just app` on the Mac; (2) right-click a Rail Workstream row, an Agent row, a Project tab, a Terminal tab, a Pad and a Todo, one after another; (3) with VoiceOver on (`⌘F5`), `VO` + `Shift` + `M` opens the menu under the cursor; (4) each menu must be read as a menu (the `AXMenu` role in Accessibility Inspector), list its items from U2694b with their one-step chords in the native shortcut column, preserving the focused editor/Terminal’s keys after dismissal (U4322b). A menu that is not read as a system menu fails U2694a.

**U2694f non-text App chrome suppresses the browser menu.** Amended by #3529: the blanket webview suppression and its editable-field/Terminal cases are retired. Given the mounted App with or without a Project, when a cancelable `contextmenu` targets non-text App chrome (Rail rows, gaps/indentation, empty Rail, Project header, non-text centre/Shelf/Drawer space), then the browser default is cancelled. Editable and selectable text, including descendants of objects that have a menu, keep the WebView text menu; Terminal emulators own their gestures under U3529a/b. Amend `u2694f_contextmenu_is_cancelled_across_the_mounted_app` in `apps/desktop/src/bubbles/u2694e_right_click.test.tsx` to the chrome-only cases; U3529a proves the exclusions.

When the target has an App object context menu under U2694a–e, that handler requests its native menu exactly once. A gap/empty non-text surface requests none and opens/restores no Terminal. Retain `u2694f_suppressing_the_default_keeps_the_objects_native_menu` and `u2694f_empty_space_opens_no_menu_or_terminal`. Policy: the #3529 implementation removes the blanket capture-phase cancellation, not the object's own menu suppression. No App native or drawn context menu is added inside a Terminal.

**U2694g a Rail context click never activates a row.** Requested by #3036. Narrows U56's selection-on-menu-open clause for pointer gestures, and U2694e's definition of a context click. Given an open Project with one row selected and no Bubble shown, when the user context-clicks a selected or unselected Workstream, Agent branch or Agent leaf, using either a right-button click (`button: 2`) that never reaches U421's 8 CSS px threshold or macOS Ctrl-click (`button: 0`, `ctrlKey: true`), then exactly one U2694a native menu is requested for the clicked row. Opening it is not row activation: selection and expanded branches stay as they were, no Bubble opens, restores or moves, no Agent starts or resumes, and no Terminal opens or receives input. An ensuing compatibility `click` from Ctrl-click must not activate the row either. Test: `u2694g_context_click_requests_only_the_target_rows_menu` (Vitest, actual App and fake App seam; table of gesture, selected/unselected row and branch/leaf, including Ctrl-click movement of at least 8 CSS px, dispatching the full pointer/mouse/contextmenu/click sequence, including a contextmenu before release).

When that menu is dismissed without choosing, the prior selection and pane stay; when an action is chosen, it addresses the clicked row, even if another row remains selected. Tests: `u2694g_dismissal_keeps_the_prior_selection_and_pane`, `u2694g_the_chosen_action_uses_the_clicked_row` (same seam; choose Stop on an unselected running Agent and assert one `agent.stop` for that Agent and none for the selected one). Policy: only opening/dismissing the pointer menu loses U56's automatic selection; an explicitly chosen action retains its existing confirmation and selection rules, including U68 Resume. Keyboard menu invocation remains U2694a's.

Policy: this does not remove or retune Pull. An unmodified mouse right-button drag starting outside Terminal emulators and editable/selectable text that reaches 8 CSS px, even if it returns to its start, still pulls and opens no menu; under 8 px it is a context click, and Ctrl-click never pulls, even with movement. Retain the existing U421 threshold, modified-press and release tests, and U2694e's native-menu/Pull tests; amend only their browser-default allowances and pointer-selection assertions where these two scenarios supersede them. Ordinary primary clicks, disclosure clicks and keyboard selection keep their existing behavior.

**U3812 a menu item that cannot act is hidden.** U3515b (`scenarios/ui-target-pickers.md`) makes Send to Agent the exception: it stays visible disabled without children when no eligible receiver remains. Its supersession also replaces the zero-recipient omission and blanket no-disabled assertions below; unrelated items retain this scenario. Amends U2694b's "A disabled item is shown greyed, never hidden": the system menu has no place to state a reason, so an item that cannot act is left out; every other clause of U2694b stands, and so does the order of the items that remain. The Queue menu's `Move up` and `Move down` are PR #3413's. Given a Rail row's menu (U2694b) and a Todo's menu (U2694b, in the Rail's Pads and in the Todos tab), then the model holds: `Restart` only when the node is running in YOLO, `Start YOLO` only when it is not in YOLO, `Stop` only while it runs, `Resume` only when it can resume and does not run; `Complete` only for a Todo that is not done. A row with none of these still lists `Rename` (where it can be renamed), `Copy Link` and `Remove`; a done Todo lists `Copy Link` and `Delete`. In Rail row menus and Todo menus in both the Rail's Pads and the Todos tab, `Send to Agent ▸` appears in its existing position only when at least one running Agent in the Project can receive the link. Its submenu lists only those eligible recipients, never an empty submenu or a disabled recipient entry; their Rail order, link content and delivery action remain U2694c's. No item of the Rail row and Todo menus is built with `enabled: false`, and choosing a listed item runs its action as before. Tests (`u3812_`, Vitest against the fake App, on the models): `u3812_a_row_menu_lists_only_the_actions_its_state_allows` (a stopped, a running, a YOLO, a resumable Workstream row), `u3812_a_done_todo_menu_has_no_complete_in_the_pads_and_the_todos_tab`, `u3812_no_item_of_the_row_and_todo_menus_is_built_disabled`, `u3812_zero_eligible_recipients_omits_send_from_row_and_both_todo_menus` (Rail rows and Todos in both locations, including done Todos; no running Agent can receive the link; no Send item or empty submenu), `u3812_multiple_eligible_recipients_lists_only_them_in_rail_order` (Rail rows and Todos in both locations, including done Todos; multiple running recipients plus an exited Agent; Send is present with only eligible, enabled recipients in Rail order). Policy: implementation remains owned by Issue #3414; this amendment specifies behavior only. The `u2694b` assertions of a greyed item change in the same PR. Layout and looks are the design critic's.

**U4462 a sequence hint sits in the key-equivalent column.** Requested by #4462; narrows U4322b's "separate native sequence hints" and amends nothing else. Given any native menu that carries a sequence hint (`⌘K P`, `⌘K S`, `⌘K I`, `⌘K W`), the installed Project menu or a `show_context_menu` popup, then:
- **One column.** The hint's right edge lines up with the right edge of the native key equivalents (`⌘N`, `⇧⌘T`) of the same menu, in both the installed menu and the popup. The right-aligned stop is derived from the menu's own key-equivalent column, not from `title_width + hint_width + 2em`. A menu whose items carry no key equivalent places the hint at the stop AppKit would give one. Test: `u4462_the_hint_stop_is_the_key_equivalent_edge` (a pure function of measured widths and the column edge, `crates/native/src/menu.rs`).
- **One look.** The resting enabled hint is drawn in `tertiaryLabelColor` and the menu font at the key-equivalent size: vibrant menu material brightens `secondaryLabelColor` above the native key equivalents (Issue #4965, Mac observation 8). A disabled item dims its hint with the title using `disabledControlTextColor`. Test: `u4462_the_hint_uses_the_tertiary_tone_and_menu_font` (macOS lane of `check`, reading the attributes `decorate` sets).
- **One path.** The menu-bar menus and `show_context_menu` both decorate through `decorate`; no menu mixes two columns. Test: `u4462_installed_and_tracked_menus_use_one_decoration`.
- **Native first (rule 9).** `NSMenuItem` and `muda`/Tauri accept one key plus modifiers as a key equivalent and no two-step chord, so the sequence stays an attributed-title hint (U4322b); the PR names this in `Reuse:`.

Observer (policy): on the Mac App, open the Project menu and a Terminal tab's popup; `⌘K P` shares `⌘N`'s right edge and grey, with the menu font, and a disabled item dims. The design critic judges the Mac capture; Chromium cannot show the native menu, and the user reports what they meet on the Mac.
