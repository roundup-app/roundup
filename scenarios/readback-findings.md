Decisions this specification takes (the Issue's "My reading" points, each kept and tested unless it says narrowed):
- **The label is `issue` or `nit`.** Both are labels of #7690 (U7690a), so Keep sets a note's label with no new word. A finding states a defect, so `question` is not offered; `issue` is a defect that changes what the code does, `nit` one that does not (a repeat, a name, a missed simplification). No high, medium, low scale: it would sit beside #7697's risk (RB11), and a second scale on one screen reads as two answers to one question.
- **One method, no Daemon state.** `agent.findDefects {id, to?}` runs one blocking call and answers with its result, as `agent.explain` does (RB13); the Daemon keeps none, so nothing survives a Daemon restart and closing the view cancels nothing it holds. A held result would add a start method, a state method, RB7's signature and RB12's rules for the same five states, which the App already draws for explanations (U7698e). The Issue's states are the App's (U7700b); the view stays usable because the call is one the view awaits, never one it blocks on.
- **The pass is not the overview run.** Its input is the hunks of the diff, as RB1 names them, and nothing else: no flows, no last message, no conversation, so it finds a defect in the diff alone and never a gap (RB4).
- **A finding** is `{path, start, end, source, text, label}`: `path` and new-side lines `start` to `end` the diff holds, `source` those lines as the hunk holds them (RB16), `text` one sentence, `label` `issue` or `nit`. Only new-side lines: a defect lives in what the Agent wrote. The model answers `{hunk, start, end, label, text}`; the Daemon keeps the path, not the hunk id (U7689b: the App cannot place hunk `n`).
- **Dropped, never refused.** A finding whose hunk id the input lacks, whose range is not wholly inside that hunk's new side, whose label is neither word, or whose text is empty, or that comes beyond the twelfth, is dropped; an empty list is a pass that found none. Twelve is the Daemon's cap on "a finding for every line".
- **Kept for the session, in the App.** Each Agent's result is kept with its Changes view's other places (U7675f), as U7698e keeps answers: closing the view mid-pass loses nothing, the answer lands in memory, and a restart of the App drops it. A result belongs to the comparison it was asked on: another `to` shows none.
- **Stale.** The pass is stale when the listing's set of `(path, blob id)` is no longer the set it was started on (RB7's signature, read in the App); a stale pass stays, with "Changed since readback" and an icon button named "Find again". A finding greys on the notes' rule (U7699b): when the file's text at its lines no longer reads as its `source`; a write elsewhere leaves it.
- **Keep and Drop.** Keep saves the finding as the user's own unsent note on its lines, with its label, its sentence as the text and the source the comparison holds at those lines (U2540b), editable like any note and sent only by the user's Send in the batch Message (U2540c); the finding then leaves the list. Drop removes it and leaves no note. A greyed finding offers Drop only. A full batch (200 notes) leaves the finding where it was.
- **Where it shows.** Under the last line of its range, after a note, a gap, a move and an explanation, as a block credited "Read back from the diff" with its label word, its sentence and the two icon buttons; in the Overview, under the readback, as the pass's block: the start action, the states and the list of findings, each a link to its line, or, when its file left the listing, the same words with no link and Drop only (as #7688 does for gaps); and as a count on its item's row (U7685c's `placeCounts`). Undecided findings enter no note count and no batch.

**RB18 only the user's call starts a pass, and its input is the hunks.** Given an Agent with a Worktree of its own whose diff is a new `a.rs` and a changed `seed.txt`, and a last message `MARKER-LAST`, when `agent.findDefects {id}` is called, then the fake `claude` is launched once and its stdin holds `hunks`, each `{id, path, text}` (`a.rs#1`, `seed.txt#1`), and no other key, and not the last message. An Agent actor's call is refused with `FORBIDDEN` and a shared checkout fails with `no_worktree` (RB2), each with no launch. Every other method launches nothing, as `rb2_only_the_start_method_launches_the_call` proves. Asserted in `rb18_the_pass_reads_the_hunks_only` and `rb18_an_agent_actor_and_a_shared_checkout_have_no_pass` (Rust, fake `claude` that records stdin).

**RB19 each finding names a place the diff holds, one sentence and a label.** Given a step answering findings for `a.rs#1`, then `agent.findDefects` answers `{state: "found", findings: [{path: "a.rs", start, end, source, text, label}]}`, `source` the new-side lines `start` to `end` joined by newlines. Asserted in `rb19_each_finding_carries_path_range_source_sentence_and_label`.
- **Dropped.** An entry whose hunk id is in no hunk, whose range runs outside that hunk's new side, whose label is neither `issue` nor `nit` or whose text is empty is dropped and the answer stays `found`. Asserted in `rb19_a_finding_the_diff_does_not_hold_is_dropped`.
- **Capped, or none.** Of fifteen valid entries the first twelve are kept; `{"findings": []}` answers `found` with none. Asserted in `rb19_at_most_twelve_findings_are_kept_and_none_is_no_failure`.

**RB20 a failed pass says why and keeps no result.** Given the same Agent, then an answer that is not a JSON object with `findings` answers `{state: "failed", kind: "badAnswer", cause}`; a diff over RB8's cap answers `tooLarge` with the cap in the words and launches zero times; a failed call answers `call` with the Role's call error and no token, price or usage figure, which `rb5_a_failure_cause_carries_no_usage_figure` proves for the one call. Asserted in `rb20_an_answer_that_is_no_findings_object_fails_with_its_cause` and `rb20_a_diff_over_the_cap_fails_naming_the_cap`.

**U7700a only the user starts a pass.** Given the Changes view on the Tree target with the fake App, then:
- **Not asked.** Opening the view, a turn that wrote, a Fetch, `R` (the readback), selecting lines and a second of waiting call `agent.findDefects` zero times. Asserted in `u7700a_only_the_user_starts_the_pass_and_a_comparison_without_a_tree_offers_none`.
- **Ask.** The Overview's icon button named "Find defects" (no visible text; its tooltip the same words) calls `agent.findDefects` once with the Agent's `id` and the open `to`; a click while the pass runs calls nothing more. Asserted in the same test.
- **Not offered.** On the Changes target (no Worktree: RB2) the button does not show. Asserted in the same test.

**U7700b every state of the pass is drawn.** Given the Overview, then:
- **Not run.** A quiet line says no pass has run, beside the button. Asserted in `u7700b_every_state_is_drawn_and_the_view_stays_usable`.
- **Running.** "Looking for defects…" with role status; J, K, the lens and the tree answer as without it. Asserted in the same test.
- **Done.** The count of findings to keep or drop and the list (U7700e); a pass that found none says so. Asserted in the same test.
- **Stale.** A change of the listing's `(path, blob id)` set adds "Changed since readback" and an icon button named "Find again", which calls `agent.findDefects` once and replaces the result. Asserted in the same test.
- **Failed.** The cause in words and an icon button named "Retry", which asks once; the cause holds no token, price or usage figure. Asserted in the same test.

**U7700c a finding draws under its line and counts in its item's row.** Given a done pass of two findings in one file and the module open, then each draws under the last line of its range as a block credited "Read back from the diff" with its label word ("Issue" or "Nit") and its sentence, after a note, a gap and an explanation on the same line; its module's row counts "2 findings"; the notes bar and the note count hold none and the batch holds none. Asserted in `u7700c_a_finding_draws_under_its_line_and_counts_in_its_row_and_joins_no_batch`.

**U7700d Keep makes the user's own note, and Drop leaves none.** Given those findings, then:
- **Keep.** The icon button named "Keep as note" saves an unsent note on the finding's range with its label and its sentence as the text, retaining the source the comparison holds there; the finding leaves the list and the row's count falls. The note edits, removes and sends as any note: nothing reaches the Agent until the user's Send, which sends one Message holding the note's `"Label:"` (U7690a) and `"User comment:"`. Asserted in `u7700d_keep_makes_an_unsent_editable_note_that_sends_only_on_send`.
- **Drop.** The icon button named "Drop finding" removes the finding and makes no note, call or Message; undecided findings are in no Message. Asserted in the same test.
- **Full batch.** With 200 unsent notes Keep saves nothing and the finding stays. Asserted in `u7700d_a_full_batch_leaves_the_finding`.

**U7700e a finding follows its lines and its file.** Given a done pass, then:
- **List.** The Overview lists each finding as its label word, its place and its sentence; a click on one whose file is listed opens that file. Asserted in `u7700e_a_finding_whose_lines_changed_greys_and_a_gone_file_is_listed_unlinked`.
- **Changed lines.** When the file's text at a finding's lines stops reading as its `source` the block dims, says "Changed since readback" and offers Drop only; a finding on other lines of the file stays as it was. Asserted in the same test.
- **Gone file.** A finding whose file left the listing stays in the list with no link and offers Drop. Asserted in the same test.

**U7700f a pass outlives the view for the session.** Given a pass, when the user closes the Changes view and opens it again, then the result shows with no call; a pass still running when the view closes lands its answer in memory, shown on return; another `to` shows none. The Daemon is asked only by the user's click (P9). Asserted in `u7700f_a_pass_outlives_the_view_for_the_session`.
