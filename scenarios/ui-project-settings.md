# UI: Project settings open as a center view

Acceptance for #3280, from the user's request: "we need to have project settings view that users could open from the overview". Module: `apps/desktop/src/` (`rail/`, a shared settings shell). Ids: U3764–U3766. Webview only: no App command, no Daemon method, nothing under `contracts/`, no new Token. Replaces the dialog of U3745 as the place the Workstream cap lives; U3745's field, toggle, refusal and call-once clauses stay. Shares the center-only sizing rule of #3278 (U3761).

**U3764 Project settings open in the center.** Given the Overview in the Rail, when the user activates `Project settings`, then the center shows the Project settings view in place of what it showed, like an opened Terminal: the Rail and the Shelf stay visible and usable beside it, and no dialog opens. The view is the shared settings shell, a title, a close control and named groups, which App Settings (the next Issue) reuses (policy). Tests: `u3764_project_settings_open_in_the_center_beside_the_rail_and_shelf`. Observer: the design critic on `just capture U3764` at 1512×950, dark, `tree-40`, with failure text visible on the densest seed (no test asserts geometry, rule 10).

**U3765 the Workstreams group holds the cap.** Given U3764's view, then the first group is named **Workstreams** and holds `Run at most N Workstreams at once` and `No limit` with U3745's behaviour unchanged: one `project.setWorkstreamCap {cap}` per commit (Enter or blur with a changed value), `null` for `No limit`, a bad entry refused in the field with `✕ <message>`, calling nothing and keeping the old cap, and the field reads `project.get`'s value on open. Tests: the existing `u3745_a_commit_sets_the_cap_once_and_no_limit_sets_null`, `u3745_a_bad_entry_calls_nothing_and_keeps_the_cap` and `u3745_no_limit_shows_when_the_project_has_no_cap` in `apps/desktop/src/rail/u3745_workstream_cap.test.tsx`, retargeted at the view; `u3765_the_first_group_is_named_workstreams`.

**U3766 closing returns the center.** Given U3764's view, when the user activates the close control or presses Escape, then the center shows what it showed before the view opened, with focus back on the `Project settings` control; opening it again re-reads `project.get`. Tests: `u3766_close_returns_the_center_to_what_it_showed`.
