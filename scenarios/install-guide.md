# Install guide

Module: `README.md`. Ids: IG7150a–IG7150d. Work order: [#7150](https://github.com/roundup-app/roundup/issues/7150). Terms: Channel, Fork, Daemon (`GLOSSARY.md`). Describes `scenarios/channels.md` (CH7077a, CH7077c–CH7077e, CH7077g) and `scenarios/dev-feed.md` (DF7078b, DF7078e); neither changes. The guide is policy text: no test rereads it, and its observers are the commands it gives, run against the current releases.

**IG7150a Install section.** Given `README.md`, then it has an "Install" section that replaces the `just app <project>` line in Status as the way in, one block per Channel and one closing line pointing contributors at `just app <project>` (Source). It states the needs: macOS on Apple Silicon (the bundles are `aarch64` only), and `claude` and `herdr-core` 0.1.20 or newer on the login-shell `PATH` (CH7077d, CH7077g). It says Stable and Dev install side by side and never share data (CH7077a), and that both update themselves from Settings › Updates, which "Update available" in the application menu opens (CH7077e, U7208f). Policy, observer: a reader with no checkout follows it to a running App.

**IG7150b Stable block.** Given the Stable block, then it says the newest `v0.1.0-alpha.<n>` release holds the bundle and the `alpha` release's `latest.json` names it (DF7078e), and gives `gh release download`, untar into `/Applications` and open `roundup.app`. It also says in one line that until the first `just promote` no Stable release exists, instead of giving a command that fails then. Policy, observer: with a Stable release published, each command runs as written; today `gh release list` shows `v0.1.0-alpha.23021`.

**IG7150c Dev block.** Given the Dev block, then it says the rolling `dev` release holds one `roundup-dev_0.1.0-dev.<n>_aarch64.app.tar.gz` (DF7078b) and gives download and untar into `/Applications`. It then gives the Fork command with the `rup` inside the bundle, `"/Applications/roundup Dev.app/Contents/MacOS/rup" data fork ~/.roundup/forks/dev --name Dev --colour violet` (CH7077c), and says that without the Fork Dev starts nothing. It says to run it in a Terminal inside the running Stable App, because `rup data fork` copies the live data through Stable's Daemon, whose socket the App puts in a per-process temp path (`Config::locate`), so a plain shell fails with "no Daemon answered at ~/.roundup/rupd.sock"; the order is install Stable, open it, run the fork there, then open Dev. An App Terminal carries `RUPD_SOCKET` because Terminals inherit the Daemon's environment (S1, `scenarios/app.md`); the guide may rely on it, and `rup ping` in that Terminal names the Daemon it reached (CL1, `scenarios/rup-ext.md`). Policy, Mac observer: on a Mac with no Dev Fork, the Dev block end to end ends in a running Dev App on the Fork named Dev, and `echo $RUPD_SOCKET` in a Stable Terminal prints a path.

**IG7150d the guide only describes.** Given the guide merged, then `scenarios/channels.md` and `scenarios/dev-feed.md` are byte for byte as before, and `just app <project>` still works as the contributor line says.
