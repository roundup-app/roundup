# UI: Worktree state, CI and PR (U2556a to U2556d)

Work Issue: #2556. This specifies data in roundup's own UI, never a Terminal running worktrunk. Journey: Understand and Review (`.agents/data/journey.md`). Builds on U2539b's on-demand Worktree view; implementation must depend on its implementation Issue #2549, not merely its completed specification #2539.

Ownership: `crates/agents` owns read-only collection and caching through its existing git execution facilities; `crates/contracts` owns an additive extension of `agent.worktreeState`; `apps/desktop/src/rail/` and the Worktree view consume one Project-scoped client cache. No new RPC method, App seam command, Token, Glyph, Message or Worktree lifecycle operation. Implement the contract, regenerated clients, fake App and every caller together (rule 4). No new public domain name is needed: Worktree state retains its glossary meaning. Worktree status never authorizes Landing or removal from cached facts.

```text
existing Base-relative git read ─┐
wt JSON local / full reads ──────┴→ Daemon cache → agent.worktreeState
                                                → shared client cache → Rail / Worktree view
```

**U2556a one read-only source preserves Base-relative state.** Given an Agent with a Worktree, when `agent.worktreeState {id}` is called:

- Keep G3's `ahead`, `behind`, `dirty`, `no_worktree` and `worktree_missing`. Ahead/behind measure the recorded Base, not the default branch or upstream; dirty excludes `.roundup/`. The existing git read remains authoritative for these three fields, including removal and Landing guards. Worktrunk divergence/dirty/line totals must not overwrite them. Exercise a Base different from default and upstream, staged/unstaged/untracked files and `.roundup/`-only changes. Planned test: `u2556a_base_state_is_authoritative` in `crates/agents/tests/scenarios/worktree_state.rs`.
- Add optional `ci` and `pr` fields. `ci`, when present, is `{state, stale}`; state is `passed`, `failed`, `running`, `no-ci`, `conflicts`, `error` or `unknown`. `pr`, when present, is `{number, stale}` with a positive integer. Omission means unavailable, never success or zero. Missing/null upstream values are unavailable; an unrecognized CI enum maps to `unknown`. Review states must not masquerade as check results. Preserve explicit upstream staleness in `ci.stale`; also mark retained CI and PR results stale after a failed refresh or 60 seconds without successful refresh. Planned test: `u2556a_optional_network_facts` in the same file.
- Execute `wt list --format=json` with the Project as cwd and fixed argv, no shell and no screen. Match only a registered Agent Worktree's canonical path and branch in this repository, never its display name, row index or branch alone. Unowned, branch-only, duplicate/ambiguous and mismatching entries enrich no Agent. A directory reassigned to another branch cannot inherit its former CI/PR. Compare refs and file bytes before/after collection. Planned test: `u2556a_path_identity_and_read_only_collection` in the same file.
- Use recorded real outputs from the supported worktrunk version to pin the JSON adapter, including local and full output, empty results, missing/null fields and malformed JSON. Support v0.80.0's actual schema; verify it from that release rather than assuming today's online schema is identical. Unknown top-level schema, wrong field types, invalid numbers or truncated/oversized output fail enrichment without corrupting local state. Ignore unrelated extra fields. Planned test: `u2556a_supported_json_and_rejected_shapes` in the same file. Fixture provenance records executable version and exact argv (policy).

**U2556b optional enrichment stays off interaction paths.** Given an open Project with Agents:

- Publish local Base-relative state without awaiting worktrunk or network. Collect local JSON and `wt list --format=json --full` in background, using the same identity mapping. Disable LLM summaries and custom executable columns through the supported worktrunk configuration/flags; inspect the pinned release to choose those arguments. Execute no repository hooks or user-configured generation command as a side effect of status collection. Planned test: `u2556b_collection_cannot_run_configured_commands` in `crates/agents/tests/scenarios/worktree_state.rs`, with sentinel commands configured in an isolated real-wt fixture.
- Coalesce refresh requests across all Agents and both views: at most one local and one full collector per Project, no per-row processes. While the Project is visible refresh local facts at most once per 5 seconds, network facts at most once per 60 seconds; opening the view can request a coalesced refresh, never bypass the network interval. End polling on Project close and cancel its collectors. Bound each collector to 10 seconds and 8 MiB stdout; kill/reap its process group on timeout/cancellation. A failure retries on the next scheduled interval, with no tight loop. Planned test: `u2556b_refresh_is_bounded_and_coalesced` in the same file, using controlled completion and time.
- Missing `wt`, unsupported schema, nonzero exit, timeout, offline forge or missing login preserves local state and clears unavailable network fields; a prior valid network result may remain only with stale status. Never install worktrunk, request login, open a Terminal or interrupt with a toast. The Worktree view exposes unavailable/stale state as text. Planned tests: `u2556b_failures_preserve_local_state` in the Rust file and `u2556b_unavailable_and_stale_are_explained` in the Worktree view's Vitest suite.
- Late replies after Agent removal, branch/path replacement, Project close or Project switch never populate the new identity's cache. Planned test: `u2556b_late_results_do_not_cross_identity` in the Rust file and client cache suite (each tests its own seam).
- Rule 7 holds with ten visible Agents and a repository containing 117 registered worktrees while the full collector is stalled: cold start below 300 ms, keystroke-to-render p95 below 16 ms, extra idle RSS below 150 MB, no regression above 10%. Observer: `just perf` (`docs/perf.md`), plus a controlled stalled collector in the isolated headless harness; record timings and process counts. Policy: implementation evidence must measure these, not infer them from async code.

**U2556c quiet Rail Chips leave the Glyph alone.** Given Agents with and without Worktrees:

- Each Worktree row shows an ahead Chip only for a nonzero Base-relative count, a CI Chip when available, and `#<number>` when a PR is known. No Worktree means no Chips. CI states have text/marks distinguishable without colour; `no-ci`, `error`, `unknown` and stale must not read as passed. Chips are state, with accessible state descriptions and `data-state`, no button role, Tab stop, pointer cursor or click action. Planned test: `u2556c_chips_are_accessible_state` in the Rail's Vitest suite.
- A CI transition changes no Kind, Glyph, Status, selection, focus, keyboard navigation or row action. A click on the state area selects the Agent as the row does; it launches no browser or Terminal. Exercise passed/failed/running and delayed completion while typing. Planned test: `u2556c_updates_preserve_agent_interaction` in the same suite.
- Policy: state rides beside the name before trailing actions, stays visible on hover/focus, and uses existing Tokens and Chip styling. Moves D2, D5 and D6; no Check passing on main regresses. Design observer, not layout assertions in Vitest: isolated headless U26 harness at 1512×950, dark, ten Agents including every Kind, long branch/name, huge count, missing fields, failed refresh and a failed CI on the densest seed. Capture before/after interaction and `window.__checks()` readings to `artifacts/ux/U2556/`; failure text must remain readable. No new motion is specified.

**U2556d the Worktree view and Rail agree.** Given U2539b's Worktree view and a Rail row for the same Agent, both read the same client cache entry keyed by Project, Agent and Worktree identity. The view retains branch, Base, behind, dirty and changed-file behavior and adds the same ahead, CI and PR facts, including unavailable/stale explanations. A refresh updates both consumers from one result; opening the view does not start an independent enrichment pipeline. Selecting another Agent or switching Projects never flashes the former Agent's network facts. Planned test: `u2556d_both_views_share_facts_and_identity` in the Worktree view's Vitest suite. Policy: the rendered observer above includes both views and U2539b's open/close/focus interaction; this specification claims no implemented view or native Mac observation.

## Reuse decision

- Select [Worktrunk](https://github.com/max-sixty/worktrunk), MIT/Apache-2.0, [v0.80.0 released 2026-09-27](https://github.com/max-sixty/worktrunk/releases/tag/v0.80.0), for optional forge enrichment and worktree discovery. Its [list documentation](https://worktrunk.dev/list/) describes machine-readable output. Pin compatibility using release fixtures; live docs may describe a later schema. Do not reproduce its forge client or render its terminal output.
- Considered [git2](https://docs.rs/git2/latest/git2/) / [git2-rs](https://github.com/rust-lang/git2-rs), the Rust libgit2 bindings ([crates.io](https://crates.io/crates/git2), stable 0.21.0; package updated 2026-10-06). It provides local repository facts but no forge CI/PR aggregation, so it cannot replace worktrunk for this outcome. Existing roundup git execution already supplies the required Base-relative safety facts; adding a second local git engine would not solve the missing capability. Verify current release evidence in any implementation PR introducing new machinery.

Specification delivery changes only acceptance. Implementation ships these clauses together, after #2549, or files scoped implementation prerequisites without closing the overall outcome early. Both lints and related implementation tests are required by the Code recipe; this document asserts no performance or visual pass.

R2965 observer requirement for U2556b: `u2556b_timeout_ends_a_stalled_collector`: a real child stalls and its output pipes must close when the ten-second collector deadline expires. Controlled completion cannot detect a child or inherited output handle surviving timeout.
