**U3513a every hint line offers three actions and more.** Given the actual App mounted through its existing fake-App seam, when focus moves to each eligible context in the table, then every hint line offered for that context contains at most three action entries, in the listed order, followed by exactly one Help entry whose key is `?`. A pair such as `J K` is one entry. An unavailable action is omitted without substituting another action; a line with fewer than three available actions still ends in `?`. Triage shows its own line without a second generic Shelf line. Changing focus updates the context without changing the selected item. Test: `u3513a_every_hint_line_ends_in_contextual_help` in `apps/desktop/src/keys/`, one parameterised App-seam guard covering every table row, its relevant availability variants and every rendered hint-line instance. For each case it asserts the entry limit, the final `?` and opens Help by dispatching `?` at the actual active element, asserting that context's complete action identities, including those absent from the line. Do not assert exact copy or layout in this test.

In triage this includes move, assign, Workstream, nest, un-nest, done, comment and leave. Component navigation and scoped actions remain discoverable even when not App-scope registry actions. **U3513d one quiet line, no boxes.** Given every U3513a context at 1512×950 on `tree-40` in dark mode and increased contrast, when its hint line renders, then it reads as one line of plain text, with lowercase action labels, entries separated by ` · ` and final `? more`.
