# UI: Todo assignment, Pad Homes and Pad folds (U3733 to U3736, U4457, U7499a to U7499c, U7637a)

Module: `apps/desktop` (the webview), plus `crates/rup` and the Brief for U7499c. Acceptance for #3023 and, for U7499a to U7499c, #7499. Builds on U3717 to U3720 (Todos by owner), T16/T17 (a Todo's owner) and P4 (shared Pads). No RPC, App seam command, Token or `GLOSSARY.md` change: `todo.create {owner}` and `todo.assign` exist, and T17 records Todo assignment in T15's history. Pad operations record the caller in Touches, without granting exclusive access.

**U3733 a Todo made while an Agent is selected is that Agent's.** Narrows U3719 and U2744a's Add clause. Given the Todos tab with Agent `a` selected in the Rail, when the user commits a title in the tab's new-Todo field (the empty-tab path included), then `todo.create` is called once with `owner` set to `a`'s Actor, then `todo.move` with `a`'s Workstream as today (the Project root when `a` has none: no `todo.move`), and the Todo shows in `a`'s group after the refetch. A group plus (U3719) still creates for its own group's owner. With a Workstream, the Project root, Overview or a Terminal selected, the call is exactly what U2744a and U3719 say and the `owner` stays what they give (Unassigned from the empty-tab path). A refused create (`NOT_FOUND` because `a` left the Rail, any error) keeps the typed title in the field and shows `✕ <message>` (U2773, U3719). Tests (`u3729_`): `u3729_a_todo_made_under_an_agent_is_owned_by_it_and_listed_in_its_group`, `u3729_a_workstream_or_root_selection_keeps_todays_owner`, `u3729_a_refused_create_keeps_the_title_and_shows_its_cause`.

**U3734 an Agent's view lists what it made and what it owns.** Narrows U2744a's Scope clause for an Agent selected: a Todo is in scope when `creator` is `a` or `owner` is `a`'s Actor. Pads remain Project-wide by Home (U3736). Without this a Todo the user just made for `a` (creator: the user) would vanish from the view it was made in. In Overview and a Workstream's view placement and grouping stay U3717's; in `a`'s view the open Todos are grouped by owner like any other scope (U3717), so `a`'s group holds the Todos it owns and the other groups the ones it made and gave away. Reassigning a Todo away from `a` that `a` did not make removes it from `a`'s view after the refetch; one `a` made stays. Tests (`u3730_`): `u3730_an_agent_view_lists_todos_it_owns_and_made`, `u3730_a_reassigned_todo_leaves_the_view_unless_the_agent_made_it`.

**U3735 creating a Pad uses the selected Home.** Given any Rail selection, when the user creates a Pad, then the App calls `pad.create` once and `pad.move` only as U2744a's Add clause requires; the result appears once in that Home's group. A refused create or move preserves the typed name and reports which step failed; an already-created Pad remains discoverable. Tests `u3735_create_uses_home_only` and `u3735_failed_create_or_move_preserves_name` (planned connected App tests under `apps/desktop/src/pads/`).

**U7499a the Pads tab folds internal and idle Pads inside each Home group.** Work order: [#7499](https://github.com/roundup-app/roundup/issues/7499). The owner, 2026-11-18, on the Pads tab with 33 Pads: "I think this is becoming a mess"; chosen from lo-fi drafts: fold rows at the end of each group, the Rail's labels `internal` and `idle`, and a minor coloured mark instead of words. Amends U3736 and U2744a: the Project-wide membership and the Home groups stay. Given a Home group, then the Pads tab lists, in U3736's order, the Pads above the folds, then up to two fold rows:
- `N internal` holds the group's Pads whose `visibility` is `internal` (P7499a). `N idle` holds its `shown` Pads that are read (U7499b) or that no one has written for 7 days. A `shown` Pad written within 7 days that the user has not read since sits above the folds. "Written" means `updated_at` changed; the age uses the App's clock when the list renders, with no timer. Test: `u7499a_a_pad_sits_in_the_fold_its_visibility_and_age_choose` in `apps/desktop/src/pads/`, over a fake App with a stubbed clock and Pads that are `internal`, read, 8 days old and fresh-unread.
- Both fold rows start closed; a fold with no Pads draws no row; the group header count stays the group's total, and each fold's count equals the Pads it holds. Test: `u7499a_folds_start_closed_and_counts_match`.
- The fold row is one component shared with the Rail's fold row (`apps/desktop/src/rail/Rail.tsx`, the idle and internal branch): the same count, label, chevron, click and keys as U5483b; the Pads fold has no status glyph. A Pad row is not an Agent row, so the shared part is only the fold row. Test: `u7499a_the_pads_fold_row_is_the_rails_fold_row` renders the Rail's row and the Pads' row from the one component and asserts the same roles, names and `aria-expanded` after a click and after Right and Left (U5483b's keys); `u5483b_click_opens_and_closes_the_branch` keeps passing.
- A Pad above the folds carries one small dot in a fixed slot just before its age, so dots line up down the list, in the shape of `.unread-dot` (U5153b): `--accent` when the user has never read it, a second Token colour when it changed since their last read. Its accessible name is `New` or `Changed since you read it`; it adds no words to the row. Tests: `u7499a_a_never_read_pad_has_the_new_dot` and `u7499a_a_pad_changed_since_the_read_has_the_changed_dot` assert the names and that the slot exists on every row above the folds; both colours meet 3:1 on resting and selected rows, light and dark (policy: the design critic reads Check D5, U3725 for dark-only captures).
- Keyboard moves and selection skip rows inside a closed fold; an open fold's rows join the walk. Test: `u7499a_arrow_keys_skip_a_closed_fold`.
- Drag works only among the Pads above the folds. `pad.reorder` takes its `before` from the group's full Home order, folds included, so a Pad dropped before another keeps its place there. Test: `u7499a_reorder_sends_before_from_the_full_home_order`, asserting one `pad.reorder` call and its `before`.
- Only the Pads tab folds: `pad.list`, links, the Switcher and Todo refs list and open every Pad as before. Policy: covered by `p7499a_an_internal_pad_lists_reads_and_resolves_like_a_shown_one`.

**U7499b the App keeps what the user has read, and the open Pad stays put.** Work order: [#7499](https://github.com/roundup-app/roundup/issues/7499). The owner: "opening counts as read, selecting doesn't count as open". Given the Pads tab, then:
- Per Project, the App keeps the Revision of each Pad, by incarnation, that the user last read, as it keeps unread finishes (U3566, `apps/desktop/src/state/unseen.ts`), in the same App storage and surviving a reload (U3566c). No RPC reads or writes it. A Pad is read when that Revision equals its current one. Test: `u7499b_the_read_record_survives_a_reload_per_project` in `apps/desktop/src/pads/`, with the same Pad name in two Projects.
- The record takes the Pad's current Revision when the Drawer opens on it (a double-click, Enter, its Open button, the Switcher, a link), when the user saves in it, and when the Drawer leaves it, so a write the user saw while the Pad was open counts as read. Tests: `u7499b_each_way_of_opening_records_the_revision` (one case per way), `u7499b_a_save_records_the_revision`, `u7499b_a_write_seen_while_open_counts_as_read_on_leaving`.
- Selecting a row (a click, ⌘-click, ⇧-click, the arrow keys, focus) never records. Test: `u7499b_selecting_a_row_never_counts_as_reading`.
- The first answered `pad.list` of a Project with no saved record, even an empty one, counts every Pad in it as read. After that a Pad missing from the record is unread, except one the user creates, which is read at its creation. Tests: `u7499b_the_first_list_counts_every_pad_as_read`, `u7499b_a_later_pad_missing_from_the_record_is_unread`, `u7499b_a_pad_the_user_creates_is_read`.
- A Pad recreated under a deleted Pad's name is another incarnation and so unread. Test: `u7499b_a_recreated_name_is_unread`.
- The open Pad (the one the Drawer shows) keeps its place while open. A Pad opened from a closed fold (a link, the Switcher) lists above the folds while open, `internal` too, as the Rail lifts its selected row out of a closed fold (U6238a); the fold's count leaves it out and no fold opens by itself. Leaving means the Drawer closes or shows another item; the Pad then goes where U7499a puts it. Tests: `u7499b_the_open_pad_never_moves_while_open`, `u7499b_a_pad_opened_from_a_closed_fold_lists_above_the_folds`, `u7499b_leaving_a_pad_returns_it_to_its_fold`.

Policy: the owner's "selecting doesn't count as open" is the only rule for the read mark; the record holds no timer. Journey Review: `u7499b_` Vitest cases drive the fake App; the real-Daemon observer is `u7499b_an_agent_write_after_a_read_returns_the_pad_above_the_folds` in `apps/desktop/src/testing/`, starting the real `rupd` as U166 does, with a Pad created by an Agent, read by the user, then written by the Agent.
