# UI: an Agent owns what the user makes while it is selected (U3729 to U3732)

Module: `apps/desktop` (the webview). Acceptance for #3023. Builds on U3717 to U3720 (Todos by owner), T16/T17 (a Todo's owner) and P4 (`pad.setOwner`). No RPC, App seam command, Token or `GLOSSARY.md` change: `todo.create {owner}`, `todo.assign` and `pad.setOwner` exist, and a change of owner is already recorded in history (T17's `owner` change in T15's history for a Todo; a `wrote` Touch on `pad:<name>` by the caller, listed by `provenance.history`, for a Pad).

**U3729 a Todo made while an Agent is selected is that Agent's.** Narrows U3719 and U2744a's Add clause. Given the Todos tab with Agent `a` selected in the Rail, when the user commits a title in the tab's new-Todo field (the empty-tab path included), then `todo.create` is called once with `owner` set to `a`'s Actor, then `todo.move` with `a`'s Workstream as today (the Project root when `a` has none: no `todo.move`), and the Todo shows in `a`'s group after the refetch. A group plus (U3719) still creates for its own group's owner. With a Workstream, the Project root, Overview or a Terminal selected, the call is exactly what U2744a and U3719 say and the `owner` stays what they give (Unassigned from the empty-tab path). A refused create (`NOT_FOUND` because `a` left the Rail, any error) keeps the typed title in the field and shows `✕ <message>` (U2773, U3719). Tests (`u3729_`): `u3729_a_todo_made_under_an_agent_is_owned_by_it_and_listed_in_its_group`, `u3729_a_workstream_or_root_selection_keeps_todays_owner`, `u3729_a_refused_create_keeps_the_title_and_shows_its_cause`.

**U3730 an Agent's view lists what it made and what it owns.** Narrows U2744a's Scope clause for an Agent selected: a Todo is in scope when `creator` is `a` or `owner` is `a`'s Actor; a Pad when its owner is `a` (as today). Without this a Todo the user just made for `a` (creator: the user) would vanish from the view it was made in. In Overview and a Workstream's view placement and grouping stay U3717's; in `a`'s view the open Todos are grouped by owner like any other scope (U3717), so `a`'s group holds the Todos it owns and the other groups the ones it made and gave away. Reassigning a Todo away from `a` that `a` did not make removes it from `a`'s view after the refetch; one `a` made stays. Tests (`u3730_`): `u3730_an_agent_view_lists_todos_it_owns_and_made`, `u3730_a_reassigned_todo_leaves_the_view_unless_the_agent_made_it`.

**U3731 a Pad made while an Agent is selected is that Agent's.** Narrows U2744a's Add clause for Pads. Given the Pads tab with Agent `a` selected, when the user names a new Pad, then `pad.create` is called once, then `pad.setOwner {name, owner: a's Actor}` once, then `pad.move` to `a`'s Workstream as today, and the Pad shows in `a`'s group after the refetch. With any other selection the calls are today's (the user owns the Pad). A refused step (`CONFLICT` on a taken name, `NOT_FOUND`, `FORBIDDEN`) keeps the typed name in the field and shows `✕ <message>`; when only `pad.setOwner` is refused the Pad exists and is the user's, and the message says so. Tests (`u3731_`): `u3731_a_pad_made_under_an_agent_is_owned_by_it_and_listed_in_its_group`, `u3731_another_selection_keeps_the_user_as_owner`, `u3731_a_refused_step_keeps_the_name_and_shows_its_cause`.

**U3732 the Pads tab groups by owner and the owner can change.** Mirrors U3717, U3718 and U3720 for Pads. Given the Pads tab in any scope, then the Pads in scope are grouped by owner once each: Me (the user), then one group per Agent on the Rail that owns one, in Rail order, then Unassigned (a Door or Extension owner, or an Agent no longer on the Rail), with the same labels, header counts, folding, empty-group and Unassigned-folded rules as the Todos tab; within a group Pads keep P3 order. Pressing a Pad row button and moving 4 px or more drags it through `ui/sortable.tsx`, and releasing over another group calls `pad.setOwner {name, owner}` once and nothing else (Unassigned is offered only as a drop onto a Pad that has no owner on the Rail, so it is not a target); the row stays until `pad.changed` arrives and `pad.list` is refetched. The plain key `o` on a focused Pad row, registered once in the Shelf scope and listed in Help and the key hints like U3720's, and the row's `Assign` word open the owner list (`Me` and each Agent on the Rail, the Pad's current owner left out) and choosing calls `pad.setOwner` once; focus returns to the row (U138). A refused reassign keeps the row in its group and shows `✕ <message>`. The Pad's Home (P12) never changes by an owner change. Pad groups by Home and maker (U2744a Overview placement) are replaced by these for Pads; U2744a's Scope clause is unchanged. Tests (`u3732_`): `u3732_pads_group_by_owner_once_each`, `u3732_drag_to_a_group_calls_set_owner_once`, `u3732_o_and_the_assign_word_open_the_owner_list_and_return_focus`, `u3732_a_refused_reassign_keeps_the_row_and_shows_its_cause`, `u3732_home_is_unchanged_by_an_owner_change`, `u3732_the_key_is_registered_and_listed_in_help`.
