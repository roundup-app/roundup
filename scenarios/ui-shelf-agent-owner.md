# UI: Todo assignment and Pad Homes (U3733 to U3736, U4457)

Module: `apps/desktop` (the webview). Acceptance for #3023. Builds on U3717 to U3720 (Todos by owner), T16/T17 (a Todo's owner) and P4 (shared Pads). No RPC, App seam command, Token or `GLOSSARY.md` change: `todo.create {owner}` and `todo.assign` exist, and T17 records Todo assignment in T15's history. Pad operations record the caller in Touches, without granting exclusive access.

**U3733 a Todo made while an Agent is selected is that Agent's.** Narrows U3719 and U2744a's Add clause. Given the Todos tab with Agent `a` selected in the Rail, when the user commits a title in the tab's new-Todo field (the empty-tab path included), then `todo.create` is called once with `owner` set to `a`'s Actor, then `todo.move` with `a`'s Workstream as today (the Project root when `a` has none: no `todo.move`), and the Todo shows in `a`'s group after the refetch. A group plus (U3719) still creates for its own group's owner. With a Workstream, the Project root, Overview or a Terminal selected, the call is exactly what U2744a and U3719 say and the `owner` stays what they give (Unassigned from the empty-tab path). A refused create (`NOT_FOUND` because `a` left the Rail, any error) keeps the typed title in the field and shows `✕ <message>` (U2773, U3719). Tests (`u3729_`): `u3729_a_todo_made_under_an_agent_is_owned_by_it_and_listed_in_its_group`, `u3729_a_workstream_or_root_selection_keeps_todays_owner`, `u3729_a_refused_create_keeps_the_title_and_shows_its_cause`.

**U3734 an Agent's view lists what it made and what it owns.** Narrows U2744a's Scope clause for an Agent selected: a Todo is in scope when `creator` is `a` or `owner` is `a`'s Actor. Pads remain Project-wide by Home (U3736). Without this a Todo the user just made for `a` (creator: the user) would vanish from the view it was made in. In Overview and a Workstream's view placement and grouping stay U3717's; in `a`'s view the open Todos are grouped by owner like any other scope (U3717), so `a`'s group holds the Todos it owns and the other groups the ones it made and gave away. Reassigning a Todo away from `a` that `a` did not make removes it from `a`'s view after the refetch; one `a` made stays. Tests (`u3730_`): `u3730_an_agent_view_lists_todos_it_owns_and_made`, `u3730_a_reassigned_todo_leaves_the_view_unless_the_agent_made_it`.

**U3735 creating a Pad uses the selected Home.** Given any Rail selection, when the user creates a Pad, then the App calls `pad.create` once and `pad.move` only as U2744a's Add clause requires; the result appears once in that Home's group. A refused create or move preserves the typed name and reports which step failed; an already-created Pad remains discoverable. Tests `u3735_create_uses_home_only` and `u3735_failed_create_or_move_preserves_name` (planned connected App tests under `apps/desktop/src/pads/`).

**U4457 the Rail has no item leaves or Pad assignment control.** Policy: retain the absence of Pad/Todo Rail leaves; retire the Agent-specific Pads opener and its count, expansion and target-group requirements. The Project-wide Pads tab remains reachable by the existing Shelf action. The current `rail/pads/AgentPads.tsx` also counts Todos created by the Agent and opens their Todos view: retain that Todo-only count, name and navigation, removing only the Pad contribution and destination. Delete the file only if its remaining Todo behavior has another caller/home. Planned connected App test `u4457_pads_open_from_shelf_without_agent_control` proves access from the Shelf, no Agent Pad contribution or Rail item leaves, and unchanged Todo-only control activation for an Agent that created Todos. Retire the old opener-only tests; keep their no-leaves proof in this test.

**U3736 Pads group by Home only.** Given Pads created by the user and several Agents, including removed/stopped Agents and Agents in other Workstreams, then the Pads tab lists every Pad of the current Project once, independent of Rail selection. Nonempty Workstream groups follow Rail order; a Project root group comes last; each group uses P3 name order. There are no Agent subgroups, Me/Unassigned groups or assignment affordances. Rename or remove an Agent without changing Pad placement; rename a Workstream and its group follows its name; move a Pad and only its destination Home group gains it. Empty groups do not render. Tests `u3736_pads_group_by_home_once_each` and `u3736_pad_home_events_refresh_groups` (planned connected App tests under `apps/desktop/src/pads/`) cover the membership/order, empty Project, folding, events and Project isolation; retain existing U2744a Project-wide membership tests where they prove the same clause rather than duplicate them.

Given a Pad row/menu and its open Drawer, then it has no transfer action, mark, person label or assignment shortcut; its text and drawing blocks remain editable for the user regardless of who created it. Read, rename, edit, export, Send to Agent, Home move and delete/undo retain their existing semantics. Tests `u3736_pad_actions_need_no_transfer` (planned connected App test) and the amended U147/U149/U3789f tests prove calls, focus and draft/conflict preservation. Todo assignment and Todo shortcuts are unchanged (policy).
