# UI: late panes and Terminals preserve the user's newer focus choice

Module: `apps/desktop`. Ids: U3756a, U3756b, U3756c, U3756d, U4011. Work Issues: #3756, #4011. Terms: Project, Workstream, Agent, Terminal, Bubble, Rail (`GLOSSARY.md`). Journey stages: Enter and Intervene. This is implementation acceptance; this specification alone changes no App behavior (policy).

## Focus rule and scope

Policy: an App-initiated focus move belongs to the user action that requested its destination. If, after that action and before its focus move executes, the user opens, restores, selects or focuses another surface, the older action loses permission to move focus. Its successful result may still appear, but must not focus itself, fold the newer Bubble or change the user's newer selection. Losing permission is permanent for that action: returning to the original element, or focus temporarily becoming `document.body` during a mount, does not renew it. Background arrivals have no permission to move focus. A later explicit user activation of an already available destination may focus it normally. No fixed delay determines which action wins.

Policy: audit every production path under `apps/desktop/src` that moves focus when a pane, editor or Terminal appears: direct `focus`, `autofocus`, library initial-focus options, emulator `show` defaults, mount/effect callbacks, queued microtasks and animation-frame or readiness callbacks. Trace the triggering action through the last callback; checking only the first call is insufficient. Record the inventory, each path's owner and its behavioral observer or reason it cannot outlive a newer user choice on #3756. Repair every violating path in that inventory, including paths outside the centre pane and Bubbles. Test harness/performance-only drivers are not production focus owners. This is a bounded focus repair, not a replacement focus trap, shortcut engine or Terminal renderer. Existing Ark wrappers and xterm focus controls remain the first options; any added machinery follows AGENTS.md rule 9. No new RPC or App seam command is required.

## Acceptance

**U3756a a late supervisor Terminal leaves the user's Terminal focused.** Given an open Project, when the user creates a Workstream, opens a Terminal with `⌘T` after the Workstream is selected but before its supervisor's Terminal appears, and types into that Bubble, then the supervisor's later Terminal appearance leaves the exact Bubble emulator focused and open, the selected Workstream unchanged and the Bubble's Terminal alive. A further typed marker reaches only that Bubble's Terminal once, not the supervisor's; output emitted after the supervisor appears is parsed by the real emulator and remains readable without minimising/restoring or refocusing the Bubble. Test: planned `u3756a_late_door_terminal_keeps_the_newer_bubble_and_input`, in `apps/desktop/src/bubbles/`, an isolated headless browser test mounting the actual App with the production emulator. Coordinate Workstream selection, the Bubble's readiness and the later normal Rail update through the existing fake App seam, without a 200 ms sleep. Assert focus identity, open/minimised state and Terminal write identities/counts; inspect emulator text for the output marker, not render counters or geometry. The rendered observer below proves the screen continues drawing.

**U3756b every older appearance yields to a newer user choice.** Given each independently scheduled production focus-on-appearance path found by the audit, when its initiating action runs, the user opens or focuses a different surface, and the older mount, Terminal readiness, successful reply or queued focus callback completes, then the exact newer element keeps focus, its Bubble stays open if it owns one, its exact unsubmitted text and destination stay unchanged, and the older completion sends no input. Exercise the newer choices as a restored Bubble, an editable Drawer, the Ask bar and a Rail row; include the centre pane's late Terminal and the delayed rich Pad editor initialization. Test: planned parameterized `u3756b_older_appearance_cannot_replace_a_newer_focus_choice`, under `apps/desktop/src/`, through the actual App and existing fake App seam, with a real browser for library/editor focus. Cover each distinct scheduling path; a synchronous-only path needs its inventory justification, not a duplicate test. Also initiate a Terminal open, focus a Drawer before the successful `terminal.open` reply, and deliver both normal reply/list orders: the Terminal is retained and available without folding the Drawer or taking focus. Test: planned `u3756b_a_late_user_terminal_open_keeps_the_newer_drawer`, in `apps/desktop/src/bubbles/`. These clauses narrow earlier unconditional focus-on-open wording in U165/U524 only when a newer user action intervenes.

**U3756c returning to the origin does not revive an old focus move.** Given an older appearance has not completed, when the user opens another surface and then returns focus to the original control before that completion, then the completion leaves the original control focused and sends no input. Repeat when the newer surface replaces its own focused DOM node during mounting and focus temporarily falls to `document.body`: the old appearance still takes no focus and folds no newer Bubble. Test: `u3756c_returning_to_origin_or_body_does_not_rearm_old_focus` (origin/body cases) in `apps/desktop/src/bubbles/u3756_app_focus.test.tsx`, mounting the actual App in jsdom with the existing fake Daemon/emulator seams and controlled completion. The distinct browser-node replacement is asserted by `u3756c_a_new_drawer_editor_mount_keeps_body_unclaimed_by_the_older_terminal` in `apps/desktop/src/bubbles/u3756_focus.test.ts`. Comparing only the current active element with a captured origin, or allowing every body-focused completion, must fail this test.

**U3756d initial and explicit focus still work.** Given no newer user action intervenes, when a selected Agent's or supervisor's Terminal first becomes ready, then it receives focus and a typed marker reaches that Terminal once. Given a user-requested Terminal with both reply/list arrival orders, when it becomes ready without intervening navigation, then its Bubble takes focus and receives a typed marker once. Given the user explicitly selects an available Agent Terminal or restores a Bubble after an older completion was suppressed, then that destination takes focus and receives input normally. Tests: planned `u3756d_initial_and_explicit_terminal_focus_still_work`, under `apps/desktop/src/`, against the actual App; reuse existing U165/U524 observers where they already assert a clause rather than duplicating their proof. Background Agent Runs and list/output refreshes leave the current focus and selection alone, as asserted by existing `u164_a_new_run_bubble_never_moves_selection_or_focus` in `apps/desktop/src/bubbles/u164_bubbles.test.tsx`; extend that proof only for an uncovered arrival path. Preserve explicit outside-press minimisation, intentional navigation out of a Bubble, scoped `⌘B`, close focus return and modal focus containment (policy).

## Workstream creation keeps selection separate from focus

**U4011 a new Workstream is selected after an intervening press.** Given an open Project and a successful `rail.createWorkstream` reply whose Workstream is not yet in `rail.tree`, when the user clicks either an empty Rail area or the Ask bar before the normal tree refresh reveals that Workstream, then its new row becomes selected and `rail.startDoor` is called exactly once for that Workstream, with no second creation call. Neither selection nor the supervisor Terminal becoming ready moves focus into that Terminal. In the Ask-bar case, the exact Ask input remains focused, and a marker typed after Terminal readiness appears only in that input, with no `terminal.write` call. Test: parameterized `u4011_new_workstream_selection_preserves_newer_focus` in `apps/desktop/src/bubbles/u3756_app_focus.test.tsx`, mounting the actual App in jsdom with the existing fake Daemon/emulator seams and initiating creation through its connected Rail action. The repeated production-emulator startup/output-render observer is retired under T3779c; U3756a retains real-emulator drawing coverage. Assert the selected row identity, creation/start call identities and counts, focus and typed input after both the row and the Terminal are ready; a test ending at row appearance does not prove the focus clause.

Policy: these two presses choose no other Rail row. They revoke the pending Terminal focus move, not the requested Workstream selection or supervisor start. A later explicit selection of another Workstream or Agent retains the focus rule above. With no intervening user action, normal initial Terminal focus remains U3756d's acceptance. Keep creation/start failure recovery and explicit Terminal activation unchanged. The implementation belongs to the Enter journey stage: creating a Workstream must leave its row selected and its supervisor reachable while respecting the user's newer input focus.

Policy: control the ordinary successful create/tree/start/Terminal-readiness ordering through the existing App seam; inject no RPC failure for U4011's behavioral proof.
