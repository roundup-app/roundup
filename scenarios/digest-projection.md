# Digest projection for one source comparison

Acceptance for #5641. This specification changes how Digests are computed, without changing what a Door or coordinating Agent receives. Implementation stays in `crates/messages/src/digest.rs` and `crates/messages/src/digest/tests.rs`, targeting 450–700 changed lines. No RPC, contract, persistence schema or domain term changes (policy).

**B5641a index Sources once.** Given one supplied `Sources`, when `Seen::changed` compares every coordinating Agent and its direct children, then each source collection is traversed once to build its index, each Pad resource key is formed once per Pad, and entry rendering performs zero whole-source scans. Assert with planned `b5641a_sources_are_indexed_once_per_comparison` in `crates/messages/src/digest/tests.rs`: count actual source-row visits and Pad-key constructions at their execution sites, including work done by entry, completion, question, historical-comparison and farewell paths. For each indexed collection the visit count equals its input length; key constructions equal the Pad count. Traversals of derived columns for sorting, deduplication and rendering do not count as another source pass; a repeated source traversal does. Instrumentation is test-only and must fail if rendering or comparison resumes a whole-source scan.

Policy: build one transient projection per comparison, with dense node indices, parent/child ranges, creator-attributed open-Todo counts, Message candidates keyed by child and recipient, and sorted/deduplicated writer–Pad index pairs. Keep compact columns separate from borrowed text payloads; do not clone Message bodies, Pad text or final text into the projection. Precompute exact `pad:<name>` keys, rather than formatting them in a join. Use the projection for `ask`, `entry_of`, `baseline`, `changed` and farewells; remove repeated joins and per-parent child vectors. Parent order and each parent's child order remain supplied Rail order. Question evidence must retain the time bounds used by completion logic; one unbounded latest Message for a child cannot supply both recipient selection and question suppression. Research installed Rust collections and maintained library alternatives under rule 9 before adding this machinery; record the selection and specific rejections in the implementation PR's Reuse section.

**B5641b preserve exact entries and pushes.** Given equivalent fresh `Seen` histories and the same ordered sources, when the old and projected implementations perform the same sequence of reads and comparisons, then their complete Digest entries and ordered pushes are equal at each step, including receiver, child identity, formatted body and whether no push occurs. Planned `b5641b_projection_preserves_entries_and_pushes` in `crates/messages/src/digest/tests.rs` asserts exact outputs against expectations captured from the pre-implementation revision, with the baseline SHA and fixture parameters recorded on the Issue. Cover these cases as named rows of that observer, reusing existing tests where they already prove a row:

- Two parents, including a non-Door coordinator, interleaved children in Rail order, an Agent without Status, and more than 20 direct children. Preserve the read limit/`more` entry, pushed parent/child order and B20 authorization.
- Open and completed Todos with Agent, user and Extension creators, including another actor kind sharing a child's id; moving Home does not change creator attribution.
- Pads written by different children, a Pad with several writers, repeated writes, read-only Touches and missing Pads. Match the entire writer id and entire resource key, including names sharing prefixes and multibyte names. Preserve the current Touch actor-id matching semantics; do not substitute Pad Home for write evidence.
- Equal Pad `updated_at` values retain supplied Pad order before the existing newest-four cut. Deliver/read, change a Pad at the same timestamp, then at a later timestamp: the named cursor and next Pad list stay equal to the baseline. Keep all existing entry/name/line cuts and `[cut]` markers.
- Messages from the child to different recipients, from other actors with the same id and Messages whose supplied order differs from id or timestamp order. Preserve selection by Message id for the exact Agent sender/recipient pair, and source-order tie behavior. The projection must not use a Message to another recipient as `last`.
- Live-turn final text with a matching Attempt, mismatched Attempt, and ended Attempt; a note before, at and after the completed-turn end; and explicit questions before and at/after the turn start, including a question to a different recipient followed by a newer ordinary note. Preserve `question_since`'s existing lower time bound and sender scope, final-text freshness, suppression and replay. Keep B5519a's later-turn note behavior.
- No-change comparisons, idle/working flips, a changed Todo or Pad, an attention transition, a stale binding after a newer attention entry, and an end transition with a short/oversized/missing summary. Preserve B19/B21/B23/B35/B49 and A5482c, rather than changing eligibility to simplify indexing.

**B5641c retain delivery history across Sources.** Given a baseline, a parent read or a push recording a child's entry, when the next call supplies freshly constructed Sources with changed or removed live data, then no previous projection supplies a live lookup, while already-told evidence still supplies exactly the existing suppression, retry and farewell behavior. Planned `b5641c_fresh_sources_keep_delivery_history` in `crates/messages/src/digest/tests.rs` exercises successive independently owned fixtures: accept a push, replay unchanged input, release a refused push and retry, move a child, remove it, and remove its Door. Assert exact entries/receivers and no additional pushes after successful delivery, including the historical last entry on removal and no farewell to a gone Door. Reuse the B21/B23 tests below for clauses they already assert. Include a completed turn followed by replacement Sources and a stale binding after a newer entry; retain completion replay suppression and binding ordering.

Policy: every projection index and borrow expires with its Sources; no projection cache persists across calls or Daemon events. Public `Sources` ownership stays unchanged, including owned Touches and completed-turn data. Delete only redundant `Told.kind` and `Told.todos`, reading their values through `Told.entry`. Keep `Told.entry`, binding/completion evidence, delivered Pad timestamps and read cursors, including their existing persistence and release behavior: live Sources cannot reconstruct historical delivery. No unsafe lifetime extension or public measurement API is commissioned.

**B5641d measure downstream event work.** Given pure deterministic fixtures with 10 and 40 Agents, 100 Pads, 1000 Touches and Message histories of 100, 1000 and 10000 rows, when a baseline and then an unchanged event are compared, then the unchanged event returns no pushes and still satisfies B5641a's visit/key counts, independent of Agent count. Planned `b5641d_no_change_work_and_allocations` in `crates/messages/src/digest/tests.rs` runs this matrix through the real Digest paths, with multiple coordinating parents, recipient-specific Messages, repeated writer–Pad pairs and irrelevant older history. Measure baseline construction and unchanged comparison separately; exclude fixture construction and assertion/report formatting from the measured region. Assert unchanged output rather than inferring it from timing.

The same observer records cumulative allocated bytes, allocation count and elapsed time for baseline and unchanged comparison. Run identical fixtures against the pre-implementation revision and implementation head in prepared checkouts, using the same build profile, allocator instrumentation and machine. Record both SHAs, command, OS, fixture sizes, exact-output comparison, counts and byte/time deltas on #5641. Count reallocations consistently and isolate the measurement from parallel tests; use an existing maintained allocation observer or instrumented allocator under rule 9 rather than infer bytes from collection capacities. Comparison must include projection allocation and destruction, not only rendering. No wall-clock speedup threshold is imposed; actual source-visit counts prove removal of the multiplied joins, and measured bytes expose temporary-memory trade-offs (policy). No claim of reduced allocation bytes may be made without that comparison (policy).

Policy: keep the observer in the existing Digest tests, with no real Daemon, vendor, browser, disk database, sleep or cross-event cache. Each added pure test stays below five seconds on CI. The prepared-checkout command below, including these fixtures, finishes in under five minutes. `rail_tree_40_p95_ms` measures a different boundary and cannot stand in for this downstream event observer. This is CPU/allocation measurement, never vendor usage, money or token measurement (P14).

## Gates and validation

Policy: P3's gate asks whether the refactor creates attention from routine progress or changes native attention; B5641b's exact push/suppression comparisons and the retained attention tests are the observer. P10's gate asks whether the same work produces extra Messages/turns; identical ordered pushes and replay counts are this module's observer. Existing Daemon batching/transport observers retain authority over actual inbox turns; no transport or attention behavior changes. This internal refactor adds no journey or visual surface.

Implementation verification is one command:

```sh
cargo nextest run -p messages --lib -E 'test(digest::)'
```

Exit 0 with B5641a–d and retained Digest tests passing is acceptance. A test failure exits nonzero and leaves its named clause unmet; a run at or beyond five minutes leaves the runtime clause unmet (policy). Existing tests are reused rather than copied; any edited test file follows AGENTS.md rule 10. Progress, measured evidence and unresolved engineering questions belong on #5641, never in a scenario Work table (policy).
