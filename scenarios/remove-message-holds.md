# Messages without delivery holds

Module: `apps/desktop`, `crates/messages`, `crates/agents`, `crates/rupd`, `crates/rup`, `crates/contracts`, generated contracts and Message proofs/documentation. Source: #3563, including the owner's 2026-10-23 choice to remove every hold. Ids: B3563a–B3563f. Journey: Understand and Intervene (`.agents/data/journey.md`). This specification orders implementation; it claims no delivered behavior.

Policy: this file supersedes the conflicting clauses identified below. The implementation removes their retired acceptance, code and tests together, preserving each unrelated clause. #3564 owns removal of roundup's question/permission views and their remaining custom machinery; that ownership does not permit this implementation to retain a Message hold. No new scheduler, queue, composer or substitute approval state is introduced. The waiting list reads the existing Message store.

Then ordinary typing reaches that Agent's Terminal once, without acquiring or releasing any delivery mode. Switching Agents and back preserves target selection. Test to implement through the existing App seam: `b3563a_direct_input_needs_only_terminal_focus` in `apps/desktop/src/terminal/u3780_note_queue.test.tsx`, asserting focus, Terminal calls and recipient across the switches. Retain the U12 observer for ordered bytes and refusal after exit.

Policy: delete the control/watch distinction that prevents ordinary Terminal typing, its overlay, toggle commands, Help entries and calls; direct-access shortcuts may select/focus but never toggle a delivery mode. Keep existing unrelated shortcut bindings and modifier/repeat rules. Delete the queue's current-step strip and all Pause/Resume controls, including when the queue is empty, plus their exclusive copy, styles, state and handlers. Remove `copy.nowStep`, `copy.paused`, and `copy.resume` only where exclusive to the retired feature; retain an independently used action such as resuming a stopped Agent under its own copy key. A real turn/step observation used elsewhere is not retired by removing this strip.

**B3563c every Message to an Agent uses the Claude inbox.** Given a live Agent at its existing eligible delivery time (idle, or B37's live-error case), an auto Route and each authenticated sender (user, Agent, Extension, Daemon) with each Message kind (note, question), when sent, then every Message reaches the receiving Attempt's Claude inbox with its original Message id, kind, body, sender and reply identity, and zero Terminal writes or prompt calls. Queue several while busy; the next eligible delivery sends them in id order. Repeat with unsubmitted user Terminal bytes: delivery occurs at the same eligible event without submit, clear, focus change or user approval, and no Message bytes enter that input. Test to implement by extending the real delivery matrix in `crates/rupd/tests/b50_note_inbox.rs`: `b3563c_all_senders_use_the_inbox_while_terminal_input_is_unsent`. Assert actual socket entries, recorded Terminal bytes and persisted Messages after each handshake; a transport classifier alone is insufficient.

After the inbox write, each Message remains pending with its durable in-flight record until its matching transcript receipt; only that receipt makes it delivered and emits one delivery event. Repeated receipts, thirty idle edges and restart neither deliver twice nor create another Message. Tests: extend the existing receipt/restart observers in `crates/rupd/tests/b50_note_inbox.rs` as `b3563c_receipt_and_restart_preserve_each_message_once`, covering both kinds and a user sender. Use the existing fake Claude and real Daemon; no vendor model or user desktop. Policy: direct user Terminal bytes and non-Message launch/Steer commands keep their own contracts; Message delivery never falls back to them. User-addressed Messages retain B10's direct storage semantics, not an Agent inbox.

Given an unavailable or mismatched inbox, the Message remains durable pending, its cause is visible to the sender/queue, and no Terminal fallback occurs. When that same receiving Attempt's inbox becomes usable, the next eligible event retries the same id in order, with the receipt boundary above. Test to implement by replacing the retired unavailable-inbox wait assertions in `crates/rupd/tests/b50_note_inbox.rs`: `b3563c_unavailable_inbox_keeps_pending_identity_and_reports_the_cause`. Include missing, mismatch, recovery and restart; manual delivery is retired with `message.deliver`, so nothing bypasses authentication or receiver identity. Policy: pending denotes undelivered work, not a new hold reason/status or a user release requirement.
