# Spots

Module: `crates/contracts` and `contracts/generated/` (two Daemon methods, the scan's result), `crates/agents` (the store, the post, the read), `crates/rupd` (policy), `crates/rup` (the MCP tool, its fixtures), `crates/agents/src/claude_code/brief.rs` (the Brief's line, its fixtures), the fake App's handlers. Ids: C7704a, C7704b, C7704c, C7704d, C7704e, C7704f, C7704g. Work Issue: [#7704](https://github.com/roundup-app/roundup/issues/7704); the App's half is `scenarios/ui-changes-spots.md`. Owner, 2026-11-18: other tools, such as a linter or a test run, place marks on lines, each tagged with where it came from. Terms: Agent, Worktree, Tree, Changed file (`GLOSSARY.md`).

Policy, owner's decisions (2026-11-18): a **Spot** is the general mark: lines `path` `start`-`end` of the working copy that a source points at, with a `message` or an `other` place. A source is the repeat scan (`{kind: "repeats"}`) or a tool (`{kind: "tool", name}`, such as oxlint or a test run). A repeat is a Spot whose source is the repeat scan, and no `Repeat` type, field or method names it. Spots are information only: they never gate Landing (U2540d), cost no model and no tokens (P14), and roundup starts no linter and reads no tool's own file. A tool calls the method through `rup` and its MCP tool, which every Agent has, so nothing outside `crates/agents/<vendor>/` reads a vendor record (P4). "Mark" stays the report mark of `GLOSSARY.md`; no public name holds it.

Policy, kept in memory (the specify run's call on a restart): the Daemon keeps posted Spots as it keeps Readbacks, so a restart drops them and a tool's next post brings them back. Spots hold no input of the user (P11).

Policy, names (Contract recipe, rule 4): `Spot {source, path, start, end, message?, other?, stale}` (lines 1-based, inclusive; `other` is a `SpotPlace {path, start, end}`, the repeat scan's place of old); `agent.repeatScan` answers `ScanSpots {spots, complete}` (its old hit types end); `agent.postSpots {id, source, spots: [{path, start, end, message}]}` answers nothing and is the tool `agent_postSpots`; `agent.spots {id, group?}` answers `Spots {spots}`. `group` is the owned group the Changes view reads an Agent with no Worktree through (U7853a, U7955a). Each new name goes in `GLOSSARY.md` in this PR.

**C7704a the repeat scan's result is a Spot whose source is the repeat scan.** Amends C7684a to C7684c: `hits` is `spots`, each old hit a `Spot` with `source` `{kind: "repeats"}`, the same `path`, `start`, `end` and `other`, no `message` and `stale` false. Tests: the C7684a tests, as amended.

**C7704b a post is stored under its source and read back.** Given a temporary Git repo with an Agent's Worktree holding `src/a.rs` of 9 lines, when the Agent calls `agent.postSpots {id, source: "oxlint", spots: [{path: "src/a.rs", start: 3, end: 5, message: "unused variable"}]}`, then the user's `agent.spots {id}` answers one Spot with `source` `{kind: "tool", name: "oxlint"}`, that path, lines and message, no `other` and `stale` false. Test: `c7704b_a_post_is_read_back_under_its_source`.

**C7704c a source's next post replaces its earlier Spots.** Given the Spots of C7704b and a post from `tests` on `src/a.rs`, when `oxlint` posts again with one Spot, then the read holds that Spot and the one of `tests`, and the earlier one of `oxlint` is gone; an empty post from `oxlint` leaves only the one of `tests`. Test: `c7704c_a_second_post_replaces_its_source_and_keeps_another`.

**C7704d a write to the file makes its Spots stale.** Given the Spots of C7704c on `src/a.rs` and one on `src/b.rs`, when the Agent changes a byte of `src/a.rs`, then the read marks the Spots of `src/a.rs` `stale` and not those of `src/b.rs`. The reading is git's blob id of the file at the post against the file now (U7673a). Test: `c7704d_a_write_to_the_file_makes_its_spots_stale`.

**C7704e a post outside the Tree is refused with its cause.** Given the same repo, when a post names a path that is absolute outside the Worktree, climbs out with `..`, is missing, or has `end` under `start` or `start` 0, a blank source, an empty or over-500-character message, or the post holds over 200 Spots, then it is refused with `INVALID_PARAMS` whose message starts with `outside_tree`, `no_file`, `bad_range`, `bad_source`, `bad_message` or `too_many`, and no Spot of any source changes. Test: `c7704e_a_post_outside_the_tree_is_refused_with_its_cause_and_stores_nothing`.

**C7704f an Agent with no Worktree posts and is read through its group.** Given an Agent with no Worktree of its own whose recorded writes sit in a repository on a branch (U7955a), when it posts a Spot on a file of that repository and the user calls `agent.spots {id, group: {repo, branch}}`, then the read holds the Spot with its path relative to that checkout; a post on a file of a repository it wrote nothing in is refused with `outside_tree`, and a read of a group it wrote nothing in with `unsafe_path`. Test: `c7704f_an_agent_without_a_worktree_posts_and_is_read_through_its_group`.

**C7704g an Agent posts and only the user reads.** Given an Agent actor, when it calls `agent.postSpots` for itself it succeeds and `rup mcp` `tools/list` gains `agent_postSpots` and no other tool; when it calls `agent.spots` it is refused with `FORBIDDEN` and no Spot is read, the method being declared `none("…")` in `declarations.rs`; a post for another Agent is refused with `FORBIDDEN`: an Agent posts only its own Spots. Test: `c7704g_an_agent_may_post_and_only_the_user_reads`.

Reuse (rule 9), selected: plain fields through the installed `serde`, `schemars` and `specta` of `crates/contracts`, the one candidate that adds no document format, no dependency and no `rupd` size (C9b). Rejected: `serde-sarif` 0.8.0 (MIT, 2025-05-09, <https://crates.io/crates/serde-sarif>, 3.3 million downloads), which types whole SARIF documents (runs, rules, levels, many locations) when a Spot has four fields, so it widens the method to a tool's own report and its last release is 18 months old; `lsp-types` 0.97.0 (MIT, 2024-06-04, <https://crates.io/crates/lsp-types>), whose ranges are 0-based UTF-16 positions of a language server, not lines, and whose last release is 29 months old. A tool that writes SARIF maps each result to a path, a line range and a message itself.

Observers: `cargo nextest` on Linux (every test above). No test checks layout or looks (rule 10). Line budget: about 1,000 changed lines with the App's half (Contract and store 300, App 250, tests 300, rup and Brief 100), under the API-change allowance of `.agents/data/work.md`.
