# Workstream timeline

Module: dashboard-style view in `apps/desktop`; reads existing Events and Rail only. Ids: U3768a–U3768h.

Outcome: from a Workstream, see at a glance what each of its Agents did over the last 30 minutes, which Agent started which, and which one waits on the user. Journey stages: Understand and Intervene (`.agents/data/journey.md`). This file specifies acceptance.

Policy: this specification changes acceptance only. The look is rebuilt from AffectUI's public Agent Lanes documentation (`https://www.affectui.com/llms-full.txt`); it is a paid Pro item, so no code is copied. Solid fills and Tokens only: no shimmer, pulse, gradient or new colour. No new RPC, Daemon storage or vendor string: the view reads the Event log (`events.subscribe`, D10, D11) and the Rail, and uses existing Kind Glyph colours. It opens from the Workstream view as a second action beside the cost-and-time action (U3016f), as one centre view, never a split of panes. Roundup records no hand-off but Subagent parentage, so a line joins only a parent Agent (the Door included) to a Subagent it started. Before new machinery, apply rule 9 (a charting or timeline library, or a plain SVG/CSS lane, with evidence) in the implementing PR; the rendering owns no state machine. Scenarios hold acceptance only.

**U3768a one lane per Agent over the last 30 minutes.** Given a Workstream whose Door and two Subagents have `agent.status` Events within the last 30 minutes, when the user opens its timeline by pointer or keyboard, then the centre shows one lane per Agent of that Workstream, Door first and each Subagent after its parent, with a time axis ending at "now" and starting 30 minutes earlier. Another Workstream's Agents never appear. Each lane retains its Agent's Rail name in its accessible identity. Assert `u3768a_lanes_cover_agents_of_the_workstream` on the App seam by role, identity and order, never geometry. Policy, observed by the design critic: the Door's lane has no visible name; each Subagent's lane shows its Rail name unless it equals the view title. A Workstream with only its Door has no visible lane name. Suppressing a visible label never removes the lane or its accessible identity.

Given any App view with a text "Back" return control, when it renders, then that control is the same shared exit icon button, with the one-word accessible name and tooltip "Close", no visible "Back" text, and its existing return action. This includes the timeline, cost-and-time dashboard, change reader and reaction views, including their missing-item and creation states; audit every `copy.back`, `copy.reactionBack` and other text "Back" return control. Pointer, Enter and Space activate it once; Escape returns to the originating view and focus, leaving the Rail selection unchanged. Assert `u3768a_exit_is_a_named_icon_button` at the App seam for the shared return control in each affected view, checking button role, accessible name, absence of "Back" text, tooltip on hover/focus and the existing return action. Extend `u3768a_the_pane_opens_the_timeline_and_escape_returns_focus` for return by icon and Escape. Existing view-specific navigation and unfinished-input tests remain the observers of their return paths. Policy: reuse `ui/IconButton.tsx` and its Ark tooltip; use one shared exit rendering, with no new navigation state machine. Returning must preserve existing drafts and recipient identities (P11).

**U3768b blocks show Kind over time.** Given an Agent whose Status went `working` at 10:00, `needs-you` at 10:12 and `working` at 10:15, when the view shows 10:30 while the Attempt is still running, then its lane holds blocks `working` 10:00–10:12, `needs-you` 10:12–10:15 and a `working` block from 10:15 whose end is "now" and grows with it. Each block carries its Kind as an accessible name and the Kind's existing Glyph colour, never colour alone. A new Attempt starts a new block even when the Kind repeats. Time before the Event log reaches back (it keeps the last 10 000 Events) remains unknown, never inferred as `idle` or counted as running time; it has an accessible unknown indication with no painted span or shading. Assert `u3768b_blocks_follow_kind_changes_and_attempts` with an injected clock and replayed `agent.status` Events, including a repeated Kind across Attempts. Retain `u3768b_a_log_shorter_than_the_window_leaves_an_unknown_span` as the observer of accessible unknown history; its name denotes missing history, not painted filler. Policy: colour and the absence of shading are judged under U3768h, never by unit tests.

Given an Agent running from 10:00 until its observed stop at 10:10, when `blocksOf` is read at 10:20, then the final block ends at 10:10, no block extends beyond it and the sum of block durations is ten minutes. An idle-with-no-work observation closes the open block at its Status `since` and starts none; a stopped Attempt starts no block, including when its final Kind is `error` rather than `done`. Later reads add neither spans nor duration. A later resumption starts at its own observed start, leaving the intervening idle/stopped interval blank. Assert `u3768b_a_stopped_agent_has_no_span_after_its_stop` directly on `blocksOf` with fake time and table cases for a normal stop, an error stop, idle without work and a later resumption; no browser or real clock is needed.

Policy: timeline blocks and `crates/agents/src/measurement.rs` consume one shared definition of when work ends and idle contributes nothing, with both language consumers derived from that authority; two independently maintained Kind lists or stop predicates fail review. The boundary is the observed Attempt end or idle Status `since`, never the later read time; Kind alone must not turn an ended Attempt into a running one. Preserve the stop boundary in the timeline's samples when folding existing Events and Rail facts. A shared contract change follows the Contract recipe and regenerates its consumers; no new RPC is needed. Idle/stopped intervals contribute zero to summed Agent time and every time category, including Other and unmeasured; exclude them from the sum rather than reclassifying them. Startup evidence and U3016c's distinction between elapsed wall time and summed Agent time remain. Extend `u3016c_elapsed_and_parallel_time_are_distinct` in `crates/agents/src/measurement.rs` through public measurement reads with a working interval, an idle interval and a stop, then read ten minutes later: only the working interval contributes to summed Agent time, no category contains idle/stopped time, and the ended Attempt's duration does not grow. Retained evidence and its attribution are preserved. This is also the measurement regression required by the dashboard work order; it needs no duplicate guard.

**U3768c a line joins a parent to its Subagent.** Given the Door started Subagent S at 10:05 and S started Subagent T at 10:09, then a line leaves the parent's lane at that time and ends at the start of the child's first block (Door to S, S to T), and no other lines exist: two Agents with no parent link, and a Claude Code in-process subagent (not a Subagent, GLOSSARY.md), have none. The line is an element with an accessible name `<parent> started <child>`. A Subagent removed from the Rail keeps its lane and line for the window while its Events remain in the log, named as historical. Assert `u3768c_lines_follow_subagent_parentage` through the App seam with a Rail of three levels and a removed Subagent.

**U3768d a block waiting on the user opens its Decision.** Given an Agent with `needs-you` whose Decision is open, then its current block is a button named `Decision for <name>`; activating it by pointer, Enter or Space opens that Decision (U113) and focus moves into it. Escape closes the Decision and returns focus to the block. An earlier `needs-you` block whose Decision has been answered, and any block of another Kind, is not a button. Assert `u3768d_waiting_block_opens_its_decision` on the App seam: activation by pointer and keys, focus in and back, and a block that stops being a button once answered.

**U3768e the window slides only while work runs.** Given the view shows an Agent with Kind `working`, and the window is visible, then the time axis advances toward "now" and the open block grows, redrawn at least once per second. Given every shown Agent has stopped or its Kind is not `working`, or the window is hidden, then no display clock runs and the view holds still, showing the last redraw; returning visible or a new Kind change resumes or redraws at once. Closing the view, changing Workstream or changing Project leaves no clock or Event subscription of the old scope, and the view costs nothing while closed (rule 7). Assert `u3768e_the_window_slides_only_while_an_agent_runs` on the App seam with fake time and visibility, checking clock and subscription counts across running, all-stopped, hidden, close and Project switch.

**U3768f motion is the slide only, and reduced motion redraws.** Given the view, then its only movement is the window's slide with time (U3768e); an Agent finishing, a Kind change, a new line, no block and no lane shimmers, pulses or fades. Given `prefers-reduced-motion`, then the window does not slide: the view redraws at each Kind change, and at the one-second redraw only the open block's end moves, in whole steps. A live preference change takes effect by the next frame without replaying anything. `docs/design-system.md`'s direction names the timeline's slide beside a user's act and an Agent finishing a visible Todo (U3010c) as the allowed motion. Assert `u3768f_only_the_slide_moves_and_reduced_motion_redraws` on the App seam with the motion preference toggled mid-run. Policy: the direction sentence is read in review.

**U3768g the lane shows history from before the App connected.** Given the Daemon kept an Agent running while the App restarted at 10:20, with saved `agent.status` Events `working` 10:00, `needs-you` 10:12 and `working` 10:15, when the user opens the timeline at 10:30, then the lane holds the same blocks as U3768b (`working` 10:00–10:12, `needs-you` 10:12–10:15, an open `working` block from 10:15) and no unknown span before 10:00 beyond what the log lacks. The view reads the saved Events through `events.subscribe` with `after` when its log is created, then follows live Events, and a replayed Event shown once is never doubled by a live one. Assert `u3768g_log_replays_saved_events_on_creation` on the App seam with a fake `events.subscribe` that records its `after` and a restart-shaped replay, checking the blocks and that a repeated Event adds none.

**U3768h the tracer shows work and leaves empty time blank.** Given the owner's single-Door case (working, a wait, more work, then a stop), a Workstream with Subagents, and the densest `tree-40` seed with a 60-character Agent name and an actionable failure, when the timeline is rendered at 1512×950 in dark mode, then the following visual acceptance holds. Policy: the design critic observes every row against Tufte's data-ink principle, Few's directly comparable lanes and the AffectUI Agent Lanes reference above; no unit test asserts appearance.

| Surface | Acceptance |
| --- | --- |
| Empty time | No border box, track fill, idle filler or gap/unknown shading. Time before known history, between Attempts and after a stop is blank. Parentage lines retain only the meaning U3768c specifies. |
| Axis | One hairline with four quiet tick labels at ten-minute intervals across the 30-minute window, ending at "now"; no chart grid or boxed axis. |
| Spans | Solid existing Kind Token fills; no gradient, shimmer, pulse or decorative border. A span shows its user-label Kind directly when the full label plus Token padding fits; a shorter span omits visible text and retains its accessible Kind name. No clipped or overlapping labels, legend or substitute filler. |
| Lanes | Height and vertical spacing use the Rail Agent row's existing Tokens (`apps/desktop/src/rail/styles.css`, `.rail-row`); names and spans share that row rhythm. U3768a's title deduplication holds with one Door and with Subagents. |
| Controls and failures | Exit and Decision controls remain reachable by keyboard, with visible focus and readable text; the cause and next action of the seeded failure stay visible on the densest seed. No new control or hover background box. |
