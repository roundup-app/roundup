# Terminal type matches Soloterm

Module: `apps/desktop` (Terminal rendering, Tokens, bundled font assets and App Settings integration). Ids: U3517a–U3517f. Acceptance for #3517; this specification delivers no rendering change or performance observation.

Scope (policy): keep xterm.js and its existing WebGL/DOM choice. Bundle JetBrains Mono with its OFL notice; change Terminal-only family, metrics and theme Tokens and their consumers, not the Rail's typography or the App's other surfaces. New Tokens follow U4's Contract recipe. No RPC or App seam change is required. U3517d integrates with U3803/U3805/U3806 in #3281, an implementation prerequisite; this Issue does not build App Settings itself. U59 and U102 below are explicitly revised by this work order. U3707's unchanged-cell-metrics requirement governs its controls migration, not this requested metric change.

The first journey's Understand and Intervene stages retain readable Agent output, visible failures and working control input. P11 applies to font loading, theme changes and refitting: no loss or delivery of unfinished input. Gate: can changing the rendering lose or alter unsent Terminal input or send it? Observer: U3517d's exact-text and write-count comparison. Other Principles gain no behavior here (policy).

**U3517a the default font ships with the App.** Given a fresh App with no Terminal font preference and no installed JetBrains Mono, when an Agent pane, a Door pane or a shell Bubble first shows output, then each uses the bundled JetBrains Mono face, including regular, bold, italic and bold italic, without a network request. The existing `ui-monospace, "SF Mono", Menlo, monospace` stack remains the fallback for unavailable glyphs. Font readiness precedes the first authoritative fit; an output stream arriving while it loads keeps its bytes and order, and the fitted size sent to the Daemon uses the loaded face. Planned behavioral test: `u3517a_font_readiness_preserves_output_and_fits_once_ready`, through the real emulator and existing App seam, holding font readiness before releasing it. Policy observer: inspect the built App's local font assets, recorded upstream version/hash and bundled OFL notice; in an isolated headless browser with network disabled and no installed face, inspect loaded font resources for each style. Glyph shapes and fallback legibility belong to U3517f's critic, not style assertions in a UI test (rule 10).

**U3517b the default grid has Soloterm's pitch.** Given the loaded default face and no saved size override, when the real emulator is shown, then its line pitch is 18–20 CSS px (19 px target; physical screenshot pixels divided by device pixel ratio), and its grid meets U3517f's row/column comparison. Policy: start calibration from Ghostty's macOS 13 pt default and unadjusted cell metrics; do not assume native points and xterm's CSS `fontSize` are interchangeable or that `fontSize × lineHeight` alone determines rendered pitch. Record the chosen numeric xterm `fontSize`, `lineHeight` and `letterSpacing`, their units, bundled font version, measured cell width/height and pixel ratio in the implementation's evidence. Define all three as Terminal Tokens, with one default-size source for the emulator, settings and zoom reset. Choose values from the rendered measurements rather than changing the window or hiding output to hit the counts. Planned behavioral test: `u3517b_loaded_metrics_drive_terminal_resize`, asserting U13's `terminal.resize` contract after first show and a resize, with the real emulator. Pitch, glyph size, clipping and horizontal spacing are measured by the design critic on U3517f's fixture, never asserted by a UI geometry test (rule 10).

**U3517c both schemes use the Ghostty references.** Given a Terminal with no program colour overrides, when Dark or Light is selected, or System changes its effective scheme, then existing and newly opened emulators use the reference scheme below, and `terminal.scheme` reports that same background and foreground, including before any pane is attached (X17). Planned behavioral test: `u3517c_scheme_changes_reach_open_new_and_unattached_terminals`, through the existing App/Daemon scheme seam; retain X17's real colour-query tests. Policy: foreground, background, cursor, cursor text, selection background, selection foreground and all 16 ANSI slots are Terminal Tokens; the viewport and canvas agree. Program-requested colours remain untouched. The critic compares default text, selected text, the cursor and normal/bright ANSI swatches against the pinned references, including a bold/italic sample; no UI test copies palette constants as proof.

Dark reference (policy): Ghostty's unconfigured defaults in [Config.zig](https://github.com/ghostty-org/ghostty/blob/22f100c6367045bb5fc86172f837047dee2f7670/src/config/Config.zig) and [color.zig, `Name.default`](https://github.com/ghostty-org/ghostty/blob/22f100c6367045bb5fc86172f837047dee2f7670/src/terminal/color.zig): background `#282c34`, foreground `#ffffff`, the source's 16 default ANSI colours, default cursor resolved to foreground with background-coloured text, and selection's documented inverse foreground/background. Light reference (policy): Ghostty offers theme selection rather than an automatic light default. Use its shipped **Tomorrow** light theme, a light companion to the Tomorrow-family default ANSI palette, pinned to [the theme source](https://github.com/mbadolato/iTerm2-Color-Schemes/blob/74e6e762b83c9ede7bb5ec9dce855cc8aed54f3b/ghostty/Tomorrow), including its explicit cursor and selection values. This is a chosen light reference, not a claim that Ghostty automatically selects it. Verify these references against the Soloterm capture during implementation; record a mismatch on #3517 and investigate Soloterm's effective configuration rather than claiming a visual match from terminfo alone. Upstream defaults and sizing semantics: [Ghostty option reference](https://ghostty.org/docs/config/reference); font licensing: [JetBrains Mono OFL](https://github.com/JetBrains/JetBrainsMono/blob/master/OFL.txt).

U59/U4 narrowing (policy): Terminal default text and roundup-owned controls still meet 4.5:1. The fixed reference ANSI slots and program-authored colours are faithful Terminal content, exempt from U59's former per-ANSI contrast floor and U4/D5's text floor only for those cells; do not brighten the reference palette to pass a contrast test. App-authored notices, focus rings and controls retain every Check. Existing tests that require the retired palette/size equality with the Rail are updated or cut with a clause-retirement mapping; unrelated assertions survive (rule 10).

**U3517d settings and Project zoom share the new default.** Given U3803's empty family preference and unset size, when the user opens App Settings or a Terminal, then both use U3517a/b's defaults. Given a committed custom family or size, then U3803's live update and U3806's restart persistence still apply to open and future Terminals; clearing the family restores bundled JetBrains Mono. Given Project A has no zoom override, when `⌘+`/`⌘-` changes size, then it moves by 1 CSS px from the effective app-wide default, within U102's existing Token-defined bounds; `⌘0` removes A's override and restores the current app-wide default. An existing valid saved Project zoom is preserved as an absolute size, including across upgrade; changing the app-wide default leaves it alone until reset. Project B's override is independent. A reset with no app-wide size preference uses U3517b's Token. Content, scrollback, logical scroll position and exact unsubmitted input survive these changes, and no `terminal.write` occurs merely because settings, font readiness or zoom changes. Tests: `u3517d_settings_and_project_zoom_share_the_default` (commit, clear, grow, shrink, reset, second Project and reload through the existing settings/Pane seams), `u3517d_rendering_changes_keep_input_and_scrollback` (real emulator buffer plus App write count). U102's modifier, focus, daemon-exit and resize-call guards remain covered by its existing tests (regression).

**U3517e the bundled default meets the budgets.** Given the implementation build with its bundled default face loaded, when the existing performance observers run, then `just perf` passes the unchanged rule 7 limits and regression comparisons, and the native keystroke observer measures p95 < 16 ms. Observer: `just perf` per `docs/perf.md`, heading “Perf”, and `just perf-keystroke` per its heading “Keystroke-to-render in WKWebView” and K1–K3 (`scenarios/perf.md`). Record commit, command, host identity, font readiness, renderer, samples, drops and reports. A Daemon measurement is not keystroke evidence; neither a skip nor an observer error is a pass. No baseline, budget or probe weakening is authorized (policy). The native probe runs only on an explicitly requested Mac observation with its existing window opt-in; a Linux Builder never launches it or substitutes Chromium timing (policy).

**U3517f the rendered comparison matches.** Given Soloterm and roundup on the same Mac, each running the same `claude` version in the same folder at the same window width, theme and display scale, with default Terminal preferences and no Project zoom, when their output has settled on the same content, then the row counts differ by at most one and the column counts differ by at most one; glyph shapes, size, pitch, horizontal spacing, foreground/background, cursor, selection and ANSI samples match the reference. Observer: native side-by-side captures read by the design critic, not a UI assertion. Record both App versions, roundup commit, actual content rectangles, window dimensions, scale, font settings and both row/column counts; compare equivalent content areas and do not compensate for font differences by resizing one window. Capture Dark; inspect Light against Tomorrow without committing Light images. This Mac observation and U3517e's native timing are explicit remaining acceptance until observed, never satisfied by a seeded success string or Linux screenshot (policy).
