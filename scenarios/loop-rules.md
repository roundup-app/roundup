# Loop rules

Module: `loop/rules.sh` and the workflows each id names. Each id's cases are its `L<n>` tests in `loop/rules.test.sh`, or in the test file the id names.

| Exit | Means |
|---|---|
| 0 | holds |
| 1 | a rule is broken; stderr names it |
| 2 | bad input or usage, before any network call |
| 4 | `gh` or `git` failed, or `gh` exceeded `LOOP_GH_TIMEOUT` (20 s, fractions allowed); never read as a pass |

**L41 tokens.** `tokens` scans every `.css` file and every `.ts` and `.tsx` file under `apps/desktop/src/` except `tokens.css`, `terminal/emulator.ts` and test files (`*.test.*`, `testing/`), and fails naming `<file>:<line> <property>` for each look literal. A look literal is a value that sets one of these without `var(--…)`: a colour (`color`, `background`, `background-color`, `border*`, `outline*`, `fill`, `stroke`, `caret-color`, `text-decoration-color`) holding a `#` hex, an `rgb(`, `rgba(`, `hsl(`, `hsla(`, `oklch(`, `color-mix(` or a bare colour name other than `transparent`, `inherit`, `currentColor`, `none`, `initial` or `unset`; a `font-size` or `border-radius` holding a number with a unit; a `box-shadow` other than `none`; or a `transition*` or `animation*` duration holding a number with `ms` or `s` other than `0s`. In a `.ts` or `.tsx` file only the text of `style={{…}}` objects is read, where `fontSize`, `borderRadius`, `boxShadow`, `color`, `background`, `backgroundColor` and `borderColor` hold the same values. A comment is not read. Exit 0 and no output when nothing is found, 1 with one line per literal, 2 with an argument. **L95 Architect sweep.** `rules.sh architect-words` scans every line of `scenarios/` and `docs/` for the pattern `\b[Aa]rchitects?\b` and passes when none matches. A match is exempt in two cases only: the text after it begins with `/` (a branch `architect/<topic>`) or is exactly `-swarm`, `-b` or `-c` ending at a non-word, non-hyphen character (a host name `architect-swarm`, `architect-b`, `architect-c`); or the line lies in this L95 block, from its heading line to its `Tests:` line. It exits 1 naming each `file:line` and 2 when run outside a checkout.
- *Exit codes.* 0: no match. 1: at least one match, each printed as `file:line`. 2: not run inside a git checkout.
- *Rewrites.* A Contract approval reads "the Contract change rule in `.claude/skills/change-rules/SKILL.md`" (`AGENTS.md` rule 4), whose approver is review's approve; a proofs law change reads "`scenarios/proofs.md` M1 to M10"; a direction question reads a question to the user; an owner, author or reader of a document reads "the Builder run" for writing it and "the review run" for judging it.
- *Role words.* Any line of any file in `scenarios/` or `docs/` that matches fails, including `architect-approved`, `architect-owned` and `architect-reviewed` (`l95_a_role_mention_fails_naming_file_and_line`).
- *Identifiers.* `architect/u22-drag-tdd`, `architect-swarm`, `architect-b` and `architect-c` alone pass (`l95_branch_and_host_names_pass`).
- *Dead citation.* A line citing `.agents/architect.md` matches the pattern and fails (`l95_a_cited_architect_prompt_fails`).
- *Meaning kept.* Each rewritten line keeps its approval requirement: a Contract change still needs an approve other than its author's, and `rules.sh` accepts the PR exactly when it did before (policy).

Tests: `l95` in `loop/rules.test.sh`.

**L97 unique scenario ids.** `rules.sh scenario-ids` reads every line of every `scenarios/*.md` that begins `**<ID> ` (a letter run, then digits, then an optional lowercase letter, as `**U179 `, `**L82 `, `**X1 `) and passes when no `<ID>` heads two lines, in one file or across files. **L116 reuse before custom code.** Rule 9 applies the user's reuse direction to hum's plan, build and review roles. Scope: `AGENTS.md`, `.claude/skills/change-rules/SKILL.md`, `.claude/skills/pr-shape/SKILL.md`, `.hum/roles/review.md`. It migrates no existing UI or helper.
- *Research before custom code* (policy). Before adding machinery, a change researches at least two maintained libraries, with source links and release/maintenance evidence. Rule 9 covers modules, dialog, menu, tooltip, tabs, tree, drag, toast, focus handling, keyboard shortcuts, parsers, protocols, stores and clock helpers. A selected library is named; every rejected candidate has a specific missing capability, licence restriction, size cost, rule 7 measurement or lack of recent releases. Writing it quickly is no rejection reason. Custom code requires every candidate to fail. The research also applies to new machinery added within existing files.
- *Library primitives* (policy). `change-rules`, Code, builds interactive UI from `apps/desktop/src/ui/` primitives wrapping `@ui-sdk/solid`; each new primitive wraps a library component rather than implementing a state machine. Existing custom UI migrates in its own work item.
- *Independent rejection* (policy). hum's review role rejects under rule 9 custom code where an installed dependency, the platform or a maintained library covers the need, and a workaround of one. It never sees the pull request text, so the `Reuse:` section of `pr-shape` is for the human reader.

**L119 tests earn their place.** Rule 10 applies the user's test-value direction to hum's build, fix and review roles. Scope: `AGENTS.md`, `.claude/skills/change-rules/SKILL.md`. It cuts tests only in a test file a change adds or edits.
- *A kept test catches a break* (policy). A test stays only if it fails when the behaviour its scenario names breaks, and no other test already fails for that break.
- *What catches nothing* (policy). A test with no assertion, one that checks only a test double, one that repeats another test's proof, and one that rereads workflow, justfile or prompt text without pinning a token, permission or merge-gate boundary. A PR that adds or edits a test file cuts them from that file.
- *A safe cut* (policy). Each cut names the test that still proves its then-clause, or the scenario's retirement.
- *Review rejects* (policy). hum's review role rejects a new test that catches nothing or costs more than it catches (`.hum/roles/review.md`).

Tests: none; a test that rereads `AGENTS.md` is one rule 10 cuts.

**L120 a merge loses no work.** `merge-loss [main-ref]` (default `origin/main`) takes the merge base `git merge-base <main-ref> HEAD`, the newest main the branch holds, takes the branch's own files from `git log --no-merges --name-only --format= <base>..HEAD` and exits 1, listing them, for each file in `git diff --name-only <base> HEAD` that is not one; such a file changed only through a merge, so its work is lost for certain. It exits 0 otherwise. The `rules` job runs it on each `pull_request` event. hum's review role judges the diff against the item's scenarios and never sees the pull request text (rule 5), so a change the item does not order is a finding. Tests: `L120` in `loop/rules.test.sh`: a branch of its own files passes, a deletion made in an own commit passes, a merge that drops a main hunk in an untouched file fails naming it, a file main changed after the branch's last merge of main passes.

**L122 a flaky older test retries once.** The user's words: "WE need to avoid writing flaky tests". Scope: `check.yml`, `.config/nextest.toml`, `apps/desktop/vite.config.ts`, `loop/affected.py`, `tools/e14/observe.py`, `docs/harness.md`. The owner dropped the stress job on 20 Oct: it slowed merges more than it caught races.
- *Retry* (hard). A Rust or web test lane retries a failed test once (nextest `retries = 1`, vitest `retry: 1`). A test that passed only on its retry stays out of the failure count and appears under "Flaky" in the lane's job summary. The tests of the isolated group in `.config/nextest.toml`, which assert a product's time bound, retry 0 times.
- *Record* (hard). Each lane uploads the JUnit report of every test it ran, with its result.
- *Wait on state* (policy). `docs/harness.md`: a test waits on the state it reads, never on a fixed sleep or a padded timeout; a run that sees a flaky test fixes the wait, never the bound.

Tests: the retry counts are config entries, which rule 10 leaves untested. `l122` in `tools/e14/observe.test.py`: a test that passed on retry is listed flaky and its last interval kept.
