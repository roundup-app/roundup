# Loop API budget

Acceptance for #1644's dependent implementation. This specification changes no workflow. L114 amends L23's API-refusal behavior for exhausted primary limits and L104's observer start events only; all other clauses remain.

## Checks on main

1. Intake triggers and hourly recovery: `.github/workflows/build.yml:10`.
2. One pick at a time: `.github/workflows/build.yml:43`.
3. Trusted reads already obtain an App token: `.github/workflows/build.yml:59`.
4. Activity's two start events and five observed workflows: `.github/workflows/activity.yml:7`.
5. Busy reads five statuses and every unfinished run's jobs: `loop/builder.py:576`.
6. Held reads dependencies per PR: `loop/builder.py:677`.
7. Queue GraphQL already contains dependencies: `loop/orders.py:295`.
8. Build completion frees an individual slot: `.github/workflows/build-issue.yml:3`.

**L114 API budget.** The loop continues intake after a token reset without exhausting its hourly budget through reads proportional to open Issues or PRs.

- **Measurement.** Every loop job that calls GitHub logs workflow, run, job, timestamp, token source, resource, `used`, `remaining` and `reset` before its first API operation and after its last, including failed jobs. It measures each token it actually uses, without logging credentials. A reset starts a new interval; overlapping jobs' shared-counter differences are not summed as independent requests. A recording of the job's own requests supplies the per-workflow count; rate counters cross-check totals and expose unattributed traffic. Missing samples are reported as missing, never zero. Measurement requests count toward load. Tests: `l114_each_api_job_records_both_samples`, `l114_shared_counters_and_resets_do_not_double_count`, `l114_missing_samples_are_not_zero` in `loop/workflows.test.py` and `loop/builder.test.py`.
- **Bounded intake.** One pick uses at most 120 REST attempts, including retries, instrumentation, job reads, repair dispatches and matching-ref reads; GraphQL requests are reported separately. Fixtures with 1, 100 and 1,000 open Issues and PRs assert the ceiling. Held uses the complete dependency data from the queue read, with no per-PR REST dependency read. Busy makes one unfinished-run list request and reads jobs only for `in_progress` runs. If a page, dependency connection or the remaining request allowance cannot establish all occupied slots or blockers, intake emits a notice and no new build matrix; it does not treat missing data as free capacity. Deferred repairs stay eligible on the next pick, retaining existing priority and ordering. Tests: `l114_pick_rest_attempts_have_a_ceiling`, `l114_held_reuses_queue_dependencies`, `l114_busy_reads_only_in_progress_jobs`, `l114_incomplete_reads_defer_without_duplicate_dispatch` in `loop/builder.test.py` and `loop/orders.test.py`.
- **Activity.** Activity starts on `completed` of the same five workflows, retaining manual dispatch, five-minute refreshes, run links and change-only writes. A queued or running role on a PR's head appears within five minutes while the observer is running. Keep `in_progress` only if a recorded start-to-status sequence demonstrates that completed-only violates that existing L104 guarantee; the request table includes the retained event's cost. Tests: `l114_activity_preserves_live_status_with_completed_events` in `loop/workflows.test.py` and `loop/builder.test.py`; live sequence is the Observer below.
- **Exhaustion.** A primary rate-limit HTTP 403 during pick prints an Actions notice identifying the resource and reset when available, returns exit 0 and a valid empty matrix, and makes no further dispatch. Previously accepted dispatches are not repeated. A subsequent hourly pick after reset resumes eligible work. Permission-denied 403, persistent API errors and incomplete GraphQL responses still fail visibly; secondary limits retain bounded retry behavior within the ceiling. Tests: `l114_primary_exhaustion_defers_until_reset`, `l114_other_api_refusals_still_fail`, `l114_partial_dispatch_is_not_repeated` in `loop/builder.test.py`.
- **Token decision (policy).** Compare the measured post-change hourly total against 600 requests for each shared token budget. Reuse the existing trusted read-only App path before requesting another App. If a full measured hour still exceeds 600, move the affected permitted calls to an installation token obtained with `actions/create-github-app-token`, preserving role permissions and main-owned gate definitions. If creation or credentials require the user, file one L79 `flag:needs-user` question with setup steps; never repeatedly ask. No token change grants a model status, checks, administration or Actions write authority.
- **Triggers.** Preserve every build, fix, review and critic trigger and per-Issue completion dispatch in Checks 1 and 8; only Activity's observer events may change as above. Queue ordering and `.github/workflows/qa.yml` are unchanged. Tests: `l114_all_work_triggers_survive`, `l114_token_routing_preserves_role_permissions` in `loop/workflows.test.py`.

## Observer

Implementation records two complete UTC hours, one before and the first complete hour after merge, with commit, interval, workflow run links, request records, counter samples and Activity start-to-status timestamps. Its PR body has one row per workflow (including build-issue's build and after jobs attributed once to build), columns for before/after run counts, REST attempts, GraphQL requests, measurement overhead and unattributed requests. Unavailable baseline evidence stays explicitly unavailable; estimates cannot demonstrate acceptance. Since the first post-merge hour cannot precede merge, attach that evidence to the implementation PR and Issue afterward; keep the implementation Issue open until it passes.

The post-merge hour has no loop job failing with rate-limit HTTP 403, its per-token measured load is at most 600, and the Activity sequence meets L104's running-observer guarantee. The observer script prints one row per failure, naming workflow/run, assertion and exit code, then exits 1 if any assertion fails and 0 otherwise. Test: `l114_hour_observer_reports_each_failure` in `loop/builder.test.py`. A deferred primary limit is reported even though pick exits 0; it cannot demonstrate the budget pass.

Implementation owns `.github/workflows/build.yml`, `.github/workflows/build-issue.yml`, `.github/workflows/activity.yml`, `loop/builder.py`, and `loop/orders.py`'s read paths and their tests. If instrumentation of another workflow requires edits outside this scope, file a scoped prerequisite with native blocking dependencies rather than expanding ownership. No scenario Work table schedules that work.
