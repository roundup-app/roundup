# UI: notes on Pad text (U7705a to U7705e)

Module: `apps/desktop/src/pads/`, the fake App and fixtures. Ids: U7705a–U7705e.

Work order: [#7705](https://github.com/roundup-app/roundup/issues/7705). Owner, 2026-11-18: select text in a Pad an Agent wrote, add a note, and send it back quoting the selection. Rejected by the owner: Plannotator or any browser tab, a plan-approval step, a thread, an outline for long Pads, notes stored in the Pad text.

```text
Pad Drawer → select text → Add note → Save → Send note: <Agent>
                                        ↳ one message.send from you, quoting the selection
```

Policy: webview only. No Daemon method, contract or Message law changes: `message.send` and `provenance.history` exist, and M1–M10 (`scenarios/proofs.md`) stay. No Terminal write. Delivery is U2540c's (`scenarios/ui-diff-notes.md`, heading **U2540c**): existing delivery rules alone decide when it reaches the Agent. The selection and its toolbar come from `@milkdown/crepe` and `@milkdown/kit` (installed); the field anchors with Ark UI's popover or `@floating-ui/dom`, and the PR's `Reuse:` section names the one used (rule 9). No test checks layout or looks (rule 10): the design critic judges them from `just capture U7705a U7705c`. When a design check reads this surface as a defect, change how it is drawn, never the decision.

**U7705a selecting text offers a note.** Narrows U20 (`scenarios/ui.md`, heading **U20**): editing and autosave hold. Given an open editable Pad Drawer (U20), when the user selects a non-empty range of text in the document, then an `Add note` action is offered for that selection and reachable by keyboard. Activating it opens a labelled field; `Save` keeps the note, `Cancel` or Esc keeps nothing, and blank text cannot be saved. An empty selection offers nothing. Selecting, opening the field and saving write nothing to the Pad: no `pad.write`, and the Pad's text and Revision are unchanged. Test: `u7705a_selecting_text_offers_a_note_and_writes_nothing` in `apps/desktop/src/pads/` (fake App: select, activate, Save with text, assert one saved note, zero `pad.write` calls; Cancel and blank save keep none).

**U7705b one note, one Message to the Pad's maker.** Given a saved note, when the user activates `Send note: <Agent>`, then the App calls `message.send` once, a note from `you`, to the receiver below, and nothing sends without that click. Its plain-text body holds, as data and never commands: `Pad:` the Pad's name, `Revision:` the Revision the note was made on, `Quoted from Revision N:` followed by the selected text, and `User comment:` followed by the exact note text. The quote is the markdown source of the selection where the editor can give it, else its plain text. The label names the receiver. Receiver: the Actor of the newest `wrote` Touch in `provenance.history {item: "pad:<name>"}` (the fetch U5 and U20 already make on open; `read` Touches never count). When that Actor is an Agent on the Rail, it is the receiver. When it is the user, or an Agent no longer on the Rail, or the history holds no `wrote` Touch, the action asks the user to pick a receiver from the Agents on the Rail and sends only after the pick. Tests: `u7705b_send_calls_message_send_once_to_the_last_writer_with_pad_revision_quote_and_note`, `u7705b_nothing_sends_without_the_click`, `u7705b_a_user_or_departed_last_writer_asks_for_a_receiver` in `apps/desktop/src/pads/` (fake App; the first asserts the exact body fields and receiver, the second that Save alone makes zero `message.send` calls).

**U7705c an unsent note is kept per Pad.** Applies P11 (`PRINCIPLES.md`, heading **P11**). Given an unsent note on a Pad, then it survives closing and reopening the Drawer and opening another Pad, in this App run; it is dropped only by `Send` accepted or its own Remove, and Remove affects only the chosen note. Notes of one Pad never show on, or send to the receiver of, another Pad. When an Agent rewrites the Pad (`pad.changed`, U36) before the send, the note keeps the Revision it was made on, the draft is untouched (U36), and the Message says `Quoted from Revision N` with that N, never the newer one. Send follows U2540c's outcomes: while unresolved, repeat activation sends nothing; accepted clears only the sent note; a rejection or unknown acceptance keeps it and shows the failure with an explicit retry, never an automatic resend. Tests: `u7705c_an_unsent_note_survives_closing_the_drawer`, `u7705c_an_agent_rewrite_keeps_the_notes_revision`, `u7705c_send_outcomes_keep_or_clear_the_note` in `apps/desktop/src/pads/` (fake App; the rewrite test raises the Revision through `pad.changed` from an Agent and asserts the Message names the original Revision and the draft is unchanged).

**U7705d a long selection stays usable.** Given a selection of 2,000 characters, then the note field opens, Save and Send stay reachable, and the Message quotes all 2,000 characters unaltered. Test: `u7705d_a_2000_character_selection_is_quoted_whole` in `apps/desktop/src/pads/` (the body's quote equals the selected text). How it is drawn, truncated or scrolled in the field is the critic's (policy).
