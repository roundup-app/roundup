# UI: one icon and one key per created kind (U5215 to U5217)

Specification for #5215. Owner report (2026-10-31): the Rail footer's Agent button draws the "boring wrong circle" and the buttons show no key. Journey stage: Enter (`.agents/data/journey.md`). Implementation acceptance, not shipped behaviour. Module: `apps/desktop/src/` (`rail/`, `keys/`, `ui/`, `copy.ts`). No RPC, App seam command or Token; no `GLOSSARY.md` term.

**U5215 one map names the icon of each created kind.** Class fix: `apps/desktop/src/rail/Rail.tsx` names the Agent icon twice (the section, `bot`, and the footer button, `circle`). Given the three kinds Workstream, Mode and Agent, then one map from kind to icon (Workstream `messages`, Mode `workflow`, Agent `bot`) is the only place a component names those icons; the Rail sections, the footer buttons, the row and context menus, the `⌘K` entries and Help read it, so a kind shows the same icon everywhere. `circle` stays only for status marks. Tests (`u5215_`, `apps/desktop/src/rail/`): `u5215_each_footer_button_shows_its_sections_icon`; `u5215_no_component_names_a_kinds_icon_directly`, a guard that fails when any `.tsx` under `apps/desktop/src/` passes `messages`, `workflow` or `bot` to `Icon` as a literal instead of reading the map (status marks and other uses of those names outside the three kinds are listed in the guard with the reason); `u5215_menus_entries_and_help_read_the_map`.

**U5216 Workstream and Mode each have a chord.** Amends U2241's allowlist by exactly `⌥⌘N` (new Workstream) and `⇧⌘M` (new Mode), both rows of `CHORDS` (`presses`: `alt+meta+KeyN`, `meta+shift+KeyM`), outside `inRail`. Both follow U32's chord rules: handled by the webview, physical key, Caps Lock neutral, other modifier sets do nothing, a key repeat acts once, and neither acts while a create is in flight, after `daemon-exited`, or when the buttons' `aria-disabled` holds (no spawn capacity). Given an open Project, `⌥⌘N` calls what the Workstream button calls (`rail.createWorkstream`) once, and `⇧⌘M` opens what the Mode button opens (the Mode creation field). `⌘N` still creates an Agent. Neither chord is a macOS default (⌘N, ⇧⌘N, ⌥⌘M, ⌥⌘D, ⌘H, ⌘Q, ⌘Space, ⌘Tab), a leader key or an existing `CHORDS` row; the Terminal keeps every other key (U2241's sweep). Help (U54) and the `⌘K` entries list both with their keys; `u4322b` native accelerators carry them where the menu offers the action. Tests (`apps/desktop/src/keys/`): `u5216_alt_cmd_n_creates_a_workstream_once`, `u5216_shift_cmd_m_opens_the_mode_field`, `u5216_a_repeat_or_a_busy_create_acts_once_or_not_at_all`, `u5216_help_and_the_k_entries_list_both_chords`, and `u2241_no_other_chord_is_taken_at_app_scope` in `u2241_nothing_else.test.tsx` gains exactly these two presses, keeping its full modifier matrix.

**U5217 the footer buttons show their key.** Given the Rail footer, then the Workstream, Mode and Agent buttons each show their kind's icon (U5215) and their chord (`⌥⌘N`, `⇧⌘M`, `⌘N`) as the existing `KeyChip` (read from `CHORDS`, never typed again), and each exposes the chord as its `aria-keyshortcuts` (`Alt+Meta+N`, `Shift+Meta+M`, `Meta+N`) while keeping its `aria-label`. Activating a button by click or `Enter` does what its chord does (U5216, U32).
