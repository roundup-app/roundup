# UI: creation icons and keys (U5215 to U5217, U5557a to U5557c)

Specification for #5215. Owner report (2026-10-31): the Rail footer's Agent button draws the "boring wrong circle" and the buttons show no key. Journey stage: Enter (`.agents/data/journey.md`). Implementation acceptance, not shipped behaviour. Module: `apps/desktop/src/` (`rail/`, `keys/`, `ui/`, `copy.ts`). No RPC, App seam command or Token; no `GLOSSARY.md` term.

**U5215 one map names the icon of each created kind.** Class fix: `apps/desktop/src/rail/Rail.tsx` names the Agent icon twice (the section, `bot`, and the footer button, `circle`). Given the three kinds Workstream, Mode and Agent, then one map from kind to icon (Workstream `messages`, Mode `workflow`, Agent `bot`) is the only place a component names those icons; the Rail sections, the footer buttons, the row and context menus, the `⌘K` entries and Help read it, so a kind shows the same icon everywhere. `circle` stays only for status marks. Tests (`u5215_`, `apps/desktop/src/rail/`): `u5215_each_footer_button_shows_its_sections_icon`; `u5215_no_component_names_a_kinds_icon_directly`, a guard that fails when any `.tsx` under `apps/desktop/src/` passes `messages`, `workflow` or `bot` to `Icon` as a literal instead of reading the map (status marks and other uses of those names outside the three kinds are listed in the guard with the reason); `u5215_menus_entries_and_help_read_the_map`.

**U5216 Workstream and Mode each have a chord.** Amends U2241's allowlist by exactly `⌥⌘N` (new Workstream) and `⇧⌘M` (new Mode), both rows of `CHORDS` (`presses`: `alt+meta+KeyN`, `meta+shift+KeyM`), outside `inRail`. Both follow U32's chord rules: handled by the webview, physical key, Caps Lock neutral, other modifier sets do nothing, a key repeat acts once, and neither acts while a create is in flight, after `daemon-exited`, or when the buttons' `aria-disabled` holds (no spawn capacity). Given an open Project, `⌥⌘N` calls what the Workstream button calls (`rail.createWorkstream`) once, and `⇧⌘M` opens what the Mode button opens (the Mode creation field). `⌘N` still creates an Agent. Neither chord is a macOS default (⌘N, ⇧⌘N, ⌥⌘M, ⌥⌘D, ⌘H, ⌘Q, ⌘Space, ⌘Tab), a leader key or an existing `CHORDS` row; the Terminal keeps every other key (U2241's sweep). Help (U54) and the `⌘K` entries list both with their keys; `u4322b` native accelerators carry them where the menu offers the action. Tests (`apps/desktop/src/keys/`): `u5216_alt_cmd_n_creates_a_workstream_once`, `u5216_shift_cmd_m_opens_the_mode_field`, `u5216_a_repeat_or_a_busy_create_acts_once_or_not_at_all`, `u5216_help_and_the_k_entries_list_both_chords`, and `u2241_no_other_chord_is_taken_at_app_scope` in `u2241_nothing_else.test.tsx` gains exactly these two presses, keeping its full modifier matrix.

**U5217 the footer buttons show their key.** Given the Rail footer, then the Workstream, Mode and Agent buttons each show their kind's icon (U5215) and their chord (`⌥⌘N`, `⇧⌘M`, `⌘N`) as the existing `KeyChip` (read by action name from `CHORDS`, never typed again, including the `aria-keyshortcuts` value; U5557a supplies the empty Rail and first-run coverage), and each exposes the chord as its `aria-keyshortcuts` (`Alt+Meta+N`, `Shift+Meta+M`, `Meta+N`) while keeping its `aria-label`. Activating a button by click or `Enter` does what its chord does (U5216, U32). The design critic judges the look at 1512×950 in dark mode on `tree-40` with a failure line visible, using Tokens only; unit tests prove icon, chord, shortcut and action only. Tests (`apps/desktop/src/rail/`): `u5217_each_footer_button_exposes_its_chord_as_its_shortcut`, `u5217_a_button_runs_the_action_its_chord_runs`. Observer: Vitest cases above, then `just capture U5217`, dark only, to `artifacts/ux/U5217/` with `window.__checks()` for D2, D5 and D6 and no passing Check on `main` regressed. Moves: D2, D5, D6.


## Buttons and chips use SF Mono

Acceptance for #5557; implementation is pending. Journey stage: Enter. The empty Rail teaches the same creation actions as the footer, including New Workstream's `⌥⌘N`. This amends U2541 in `scenarios/ui-shortcut-hints.md` (not `ui-shelf-keys.md`), U5217 above and U131 in `scenarios/ui-visual.md`.

**U5557a creation chips name the action they start.** Given the empty Rail and the Rail footer, when they render, then each creation button's chip text equals the live `CHORDS` row selected by the action's `name`: New Agent → `agent.new`, New Workstream → `workstream.new`, New Mode → `mode.new` (footer only). The first-run Choose folder button likewise reads `project.choose-folder`. Every `aria-keyshortcuts` value on these controls is derived from that same row's live `presses`, never a display-string lookup or a separately typed accelerator. With default keys, New Workstream shows `⌥⌘N` everywhere; `⇧⌘N` continues to mean Agent with prompt. Rebinding a recordable action updates both its chip and any exposed shortcut without remounting. Tests planned in `apps/desktop/src/rail/u5557_chips.test.tsx`: `u5557a_empty_rail_chips_match_the_actions_they_start`, `u5557a_choose_folder_chip_matches_its_action`, `u5557a_rebinding_updates_the_chip_and_shortcut`. Render the real components through the existing fake App/Rail fixture and compare chip text and shortcut contracts to the named rows, not copied expected strings. Extend `u5217_each_footer_button_exposes_its_chord_as_its_shortcut` in `apps/desktop/src/rail/u5217_create_keys.test.tsx` to compare all footer chip text and shortcuts to their action rows; it is this clause's footer observer, not a second test. U5217's action-equivalence test remains the click/chord observer.

**U5557b one renderer and one source for key text.** Given all App chip callers, when they render, then every chip passes through `keys/KeyChip`, including `ink/EmptyState`; no other production component emits a key `kbd`. Every action chip and exposed `aria-keyshortcuts` reads its action's `CHORDS` entry by identity. Existing leader sequences, alternatives and navigation hints retain their registry-defined meaning, sourced from `keys/chords.ts`; recorded keys continue to come from the existing shortcut settings. Policy: no copied chord literal at a chip, hint, EmptyState action or shortcut-attribute call site, including one hidden behind a local constant, copy entry or display-string lookup. Test planned in `apps/desktop/src/keys/u5557_source.test.tsx`: `u5557b_every_chip_uses_keychip` extends the existing U2541 renderer observer to EmptyState and all current callers; assert rendering ownership, not CSS. Production source under `apps/desktop/src/` has a CI guard, in the existing typecheck or lint lane, that rejects such copied key text outside `keys/chords.ts`. A `string` prop or structurally forgeable row by itself is insufficient. Test fixtures may supply literal inputs; they cannot exempt production call sites. Verify the guard by temporarily introducing a literal chip and a literal shortcut attribute in production: both fail the selected gate, and removing them restores success. If a lint is chosen, its negative fixtures prove these two failures; if types already reject them, add no redundant runtime test. This is guard policy, not a requirement to change frozen loop machinery.

**U5557c buttons and chips use mono with an even thin key gap.** Given any roundup-owned button label or key chip, when it renders, then its text uses the existing `--font-mono` stack (`ui-monospace`, SF Mono on macOS), including nested labels that otherwise inherit `--font-ui`. Inside each press's single chip, adjacent modifier glyphs and the terminal key have the same thin gap, `calc(var(--space-1) / 4)` (1 CSS px at current Tokens). `Tab`, `Esc` and other multi-letter key names remain one key, with no gaps between their letters. No inserted whitespace changes the chord's text or accessible shortcut. A press remains one `kbd`; sequences and alternatives keep U2541d's chip boundaries and inter-chip gap. Policy: only Tokens and Token calculations; no font asset or new Token; preserve existing chip ink, label hierarchy, focus, disabled and press behavior. This adds the intra-chip gap exception to U131/D2 and button-label/key-chip exceptions to the mono restrictions of U360/D13 and U425/D16; every other clause remains. Update the existing Check observers to recognize only these exceptions. Font, gap, baseline, clipping and contrast are design-critic acceptance, never unit layout assertions (AGENTS.md rule 10).
