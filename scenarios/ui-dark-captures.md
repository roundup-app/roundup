# UI: rendered captures use dark only (U3725)

Specification for #2907. Owner's goal: no wasted light-mode screens. Implementation acceptance, not shipped behaviour. Scope (policy): scenario capture Observers and `.agents/data/harness.md`. Light stays a supported scheme in the App; only the evidence stops. No product, contract or loop-machinery change.

**U3725 every rendered capture is dark.** Given any rendered capture a build, fix, design-critic or QA run takes, then its colour scheme is dark: no standard screen in `.agents/data/harness.md` names light (`agents-10` and `conflict` are dark, `agents-10` keeping `prefers-contrast: more`), and the Check readings taken only for light are not taken. Increased-contrast and reduced-motion captures stay where a scenario names them, in dark. No scenario capture Observer asks for light, including requests worded "light and dark", "dark and light", "both schemes" or "each scheme". Non-capture behavioral and Token tests continue to exercise supported schemes. Policy: observed by `rg -i "light|both.{0,30}(schemes?|themes?)|each.{0,30}(schemes?|themes?)" scenarios/ .agents/data/harness.md` finding no capture or Check request for light (the Token table's light values, the `terminal.scheme` method, the U4 token scenarios and the Chromium Token-contrast tests U441 and U443 still name the scheme, since they define or compute it and are not captures).
