**U2230 one list feeds the hint line, Help and the key handlers.** Given the mounted App, when a hint names a key, then that key is a row of `CHORDS` in `keys/chords.ts`, the same row Help displays and the registry binds, and pressing it runs the action the hint names. A row carries the focus places where it is shown as a hint and its order; no hint text or key symbol lives outside the table. **Hint line**: The first line of the bottom bar, naming the two to four chords that act where keyboard focus is; each is a `CHORDS` row of `keys/chords.ts` (`scenarios/ui-shortcut-hints.md`).

**U2230a the line follows focus.** U2742d adds the registered ⌘B switch to Agent/Bubble hints; the following retirement concerns the old cycling action, not that switch. _Retired in part by U2238 to U2241: `⌘1`, `⌘↑`, `⌘↓`, `⌘B`, `⌘.` and `⇧⌘⌫` are gone, so a Terminal Bubble shows no line and a watched Agent's pane shows only the take-control chord._ Given an open Project, when focus is in a watched Agent's pane, then the line shows two to four hints: the take-control chord (#2223), the key back to the Rail, and the keys to the previous and next Agent. In a Terminal Bubble it shows minimise, close and next Bubble. In the Rail it shows the keys that act on the focused row. When focus moves, the line shows the new place's hints at once; in a place with no hints, or while a modal layer such as Help is open, the line is empty. Keys are written as macOS symbols (`⌘ ⇧ ⌥ ← ↑`), each followed by its label. Tests: `u2230a_hints_follow_focus` (Rail, watched Agent, Terminal Bubble, no place, Help open) and `u2230a_hint_keys_are_symbols_with_labels`.

## Clickable Hint line (#4690)

Work order: #4690. Journey: Intervene (`.agents/data/journey.md`, heading `What must work`): the user can run the action taught beside the focused region without opening Help. This specification defines implementation acceptance and leaves the Issue open (policy).

Scope (policy): `apps/desktop/src/keys/`, including `HintLine.tsx`, `KeyHint.tsx`, `Leader.tsx`, `chords.ts`, `registry.ts`, their styles and behavioral observers. Sharing currently raw hint bindings also permits edits to `apps/desktop/src/shelf/keys.ts` (D/E/M/Escape), `apps/desktop/src/todos/ownerAssignment.ts` (numbered assignment), `apps/desktop/src/todos/Todos.tsx` (triage entry/exit), and `apps/desktop/src/switcher/Switcher.tsx` (leader K and its existing search exclusions), plus related behavior tests. Those owner edits share existing commands and guards only; they add no action or key. Existing Hint line styles outside `keys/` may change only to accommodate the button targets and whole-hint fitting. No RPC, App seam command, Token, domain term or dependency is added. The work order explicitly selects the platform's native `<button type="button">`; reuse `KeyHint` and `KeyChip`, with no new primitive or state machine (policy).

**U4690 a hint runs the same registered action once.** Given the mounted App, an open Project and focus at each place with Hint line rows, when the user clicks a hint's key or label, then exactly the action bound to that table row runs once against that Project and focus context, through `captureActions`, with the same guard, target, confirmation, focus destination and failure feedback as its key. The click calls no `terminal.write`. Asserted by planned connected-App test `u4690_each_hint_runs_its_key_action_once` in `apps/desktop/src/keys/u4690_clicks.test.tsx`: for every rendered CHORDS row, compare fresh key and pointer runs using mounted production owners and only the existing fake App/Daemon/emulator seams. Assert RPC method/arguments/count, selected identity, relevant roles and focused destination. Include Rail Remove confirmation and cancellation, Agent/Terminal switching, Ask, Shelf assignment, delete, export, maximise/restore, close, and triage entry/exit in the states where their hints render. The leader and numbered rows use U4690b/d's cases in that same suite rather than duplicating their proofs (policy).

Mechanism (policy): associate a hint with its actual `CHORDS` or `LEADER` row, never its translated label or a second command catalogue. Migrate a raw registration needed by a hint to the existing named-action registration and share its guard and implementation between pointer and key. `captureActions` must resolve the same active layer/region and winning owner as keyboard dispatch, including overlapping leader A owners; invoking every matching registration is forbidden. Revalidate availability and captured Project/object identities before running, with no fallback target. Do not manufacture or dispatch a DOM key event, call a second handler implementation from the hint, or weaken a key's scope to make it clickable. Keep the Switcher's existing exclusions when exposing additional named registrations (policy).

**U4690a a pointer hint preserves the described focus.** Given focus in a Rail row, Agent emulator, Bubble emulator, Shelf row or Pad outside its Editor, when the user presses and releases a Hint line button, then pointer-down never focuses the button or another region, the action reads the original focus, and any surviving original focus remains there unless the action's key deliberately moves it. An action opening a dialog, picker, Ask or another Terminal keeps that key's destination; closing/cancelling returns focus by the existing action path, rather than an unconditional return that steals focus from the opened surface. Exact unfinished draft text and input selection remain unchanged unless that action explicitly submits or discards them. Asserted by planned `u4690a_pointer_keeps_source_focus_and_action_destinations` in `apps/desktop/src/keys/u4690_browser.test.ts`, using real pointer down/up and production focusable controls; include a Shelf-row assignment hint that opens a portalled picker, then dismiss that picker. Normal hints retain native Tab access and Enter/Space activation; keyboard activation invokes once using the last described region, not the button as an action target. While the leader is armed, its displayed keys are the keyboard choices and Tab retains U2239's cancellation. Asserted by planned connected-App `u4690a_native_button_activation_uses_described_context`; hidden overflow hints are not tab stops.

**U4690b clicking the leader is a two-step command.** Given a normal Hint line and no modal layer, when the user clicks its `⌘K` hint, then the existing leader becomes armed with no action or focus change and the line shows the available `LEADER` rows.
