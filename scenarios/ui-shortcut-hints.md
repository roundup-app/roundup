# UI: shortcut hints (U2230 to U2230b, U2541 to U2541c)

Module: `apps/desktop/src/keys` and `apps/desktop/src/app`. Ids: U2230, U2230a, U2230b, U2541, U2541a, U2541b, U2541c. Terms: Agent, Terminal, Bubble, Rail (`GLOSSARY.md`). Direction: Issues #2230 and #2541 (the owner, 2026-10-18, after comparing Orca's `ShortcutKeyCombo`: "agree on your porposals to enhance key hints"); U2541 to U2541c replace #2230's "no box, pill, outline or background" and widen #2366's count to two to four hints per place; the keyboard route to message a running Agent is #2223's, and the bottom bar's space is #2225's.

The hint line serves the Intervene stage of `.agents/data/journey.md`: the user learns the keys that act where focus is, without opening Help. This specification defines implementation acceptance; it claims no shipped hint line.

Scope (policy): `apps/desktop/src/keys/`, `apps/desktop/src/app/`, `apps/desktop/src/copy.ts` and only the hint line's rules in `apps/desktop/src/styles.css`.

Scope of U2541 to U2541c (policy): `apps/desktop/src/keys/`, `apps/desktop/src/app/`, `apps/desktop/src/copy.ts`, `apps/desktop/src/tokens.css`, `docs/design-system.md` and the hint line's rules in `apps/desktop/src/resources/styles.css`. No RPC or domain model change. No RPC, App seam command or domain model change is required. Dependencies: #2223 supplies the take-control chord and #2225 the bottom bar's width; both are native blocked-by Issues of the implementation.

**U2230 one list feeds the hint line, Help and the key handlers.** Given the mounted App, when a hint names a key, then that key is a row of `CHORDS` in `keys/chords.ts`, the same row Help displays and the registry binds, and pressing it runs the action the hint names. A row carries the focus places where it is shown as a hint and its order; no hint text or key symbol lives outside the table. Tests: `u2230_every_hint_names_a_bound_chord` (for every place, each hint's keys equal a `CHORDS` row's and pressing its presses runs that row's action) and an extension of the U54 drift observer in `apps/desktop/src/keys/u54_help.test.tsx` (a row shown as a hint has a Help row).

**U2230a the line follows focus.** _Retired in part by U2238 to U2241: `⌘1`, `⌘↑`, `⌘↓`, `⌘B`, `⌘.` and `⇧⌘⌫` are gone, so a Terminal Bubble shows no line and a watched Agent's pane shows only the take-control chord._ Given an open Project, when focus is in a watched Agent's pane, then the line shows two to four hints: the take-control chord (#2223), the key back to the Rail, and the keys to the previous and next Agent. In a Terminal Bubble it shows minimise, close and next Bubble. In the Rail it shows the keys that act on the focused row. When focus moves, the line shows the new place's hints at once; in a place with no hints, or while a modal layer such as Help is open, the line is empty. Keys are written as macOS symbols (`⌘ ⇧ ⌥ ← ↑`), each followed by its label. Tests: `u2230a_hints_follow_focus` (Rail, watched Agent, Terminal Bubble, no place, Help open) and `u2230a_hint_keys_are_symbols_with_labels`.

**U2230b the line drops hints from the end.** Given the densest seed (`tree-40`, an Agent with 8 Runs) at 1280×800 and 700×800, when a place's hints show, then fewer hints drop from the end when the bar has no room for all (#2225). Use light/dark and increased contrast. Moves D2, D5 and D6, defined by `docs/design-system.md`, heading `The checks`; only Tokens are used and no Check passing on main regresses. Tests: `u2230b_hint_line_drops_from_the_end`, a headless real-browser test under `apps/desktop/src/keys/`, and `u2230b_hint_line_uses_only_tokens` (`loop/rules.sh tokens` passes). These browser results establish webview behaviour; the user reports what they meet on the Mac.

**U2541 keys sit in one chip component.** Given the Hint line, Help and the ⌘K leader panel, when each shows a key, then it is drawn by one component, `KeyChip` in `apps/desktop/src/keys/`, which takes the key string of a `CHORDS` or `LEADER` row and draws each symbol inside one chip; no other markup in the App draws a key (`.hint-keys`, `.help-keys` for chords and `.leader-keys` go). The chip is `--font-ui` at `--text-small` weight 500, `--text` on a fill Token, no border, `--radius-chip` (4 px), 5 px side padding and 16 px tall; the label beside it stays `--grey`. `KeyChip` wraps a plain `<kbd>`: Ark UI offers no key-chip primitive (checked at build time). Tests: `u2541_one_component_draws_every_key` (Hint line, Help and leader panel each render their keys through `KeyChip`; a grep-style assertion that no other component emits the chip class) and `u2541_chip_is_token_only` (`loop/rules.sh tokens` passes with the new fill and radius Tokens added to `apps/desktop/src/tokens.css` and `docs/design-system.md`).

**U2541a the chip reads in every theme.** Given light, dark and increased contrast at 1280×800 and 700×800 on the densest seed (`tree-40`), when the Hint line shows, then the chip fill is about 6% black on light and 8% white on dark, the chip text meets D5 (4.5:1) against the fill, the chip fits the line's 16 px height with no clipping, and hints still drop from the end whole (U2230b). Moves D2, D5 and D6. Test: `u2541a_chip_contrast_and_fit`, a headless real-browser test under `apps/desktop/src/keys/`. These results establish webview behaviour; the user reports what they meet on the Mac.

**U2541b two to four hints in every place.** Given an open Project, when focus is in the Rail, a watched Agent's pane, a Terminal Bubble, a Pad (outside its Editor), a Drawer or the Switcher, then the line shows two to four hints from `CHORDS` rows whose `hint.at` names that place, in table order, each pressing to the action its label names (U2230). With Help open it shows none. The implementation fixes the places and their hints from the keys that exist after U2238 to U2241; a place with fewer than two bound keys shows none rather than inventing one. Tests: `u2541b_every_place_shows_two_to_four_hints` and the existing `u2230_every_hint_names_a_bound_chord`, which covers the new places.

**U2541c a Pad's Editor shows its formatting keys.** Given focus in a Pad's Editor and the Pads editor work having bound blocks, bold and italic, when the line shows, then it shows those keys from `CHORDS` rows with `hint.at.editor`. Until those keys are bound, `editor` has no rows and the line stays empty there. Policy for ordering: the Issue that binds the Editor keys implements this scenario and is a native blocked-by of the implementation; it adds the rows, and no key symbol lives outside the table. Test: `u2541c_editor_hints_follow_bound_keys`.
