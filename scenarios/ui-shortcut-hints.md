# UI: shortcut hints (U2230 to U2230b, U2541 to U2541e, U2570a to U2570c)

Module: `apps/desktop/src/keys` and `apps/desktop/src/app`. Ids: U2230, U2230a, U2230b, U2541, U2541a, U2541b, U2541c, U2541d, U2541e, U2570a, U2570b, U2570c. Terms: Agent, Terminal, Bubble, Rail (`GLOSSARY.md`). Direction: Issues #2230 and #2541 (the owner, 2026-10-18, after comparing Orca's `ShortcutKeyCombo`: "agree on your porposals to enhance key hints"); U2541 to U2541c replace #2230's "no box, pill, outline or background" and widen #2366's count to two to four hints per place; the keyboard route to message a running Agent is #2223's, and the bottom bar's space is #2225's.

The hint line serves the Intervene stage of `.agents/data/journey.md`: the user learns the keys that act where focus is, without opening Help. This specification defines implementation acceptance; it claims no shipped hint line.

Scope (policy): `apps/desktop/src/keys/`, `apps/desktop/src/app/`, `apps/desktop/src/copy.ts` and only the hint line's rules in `apps/desktop/src/styles.css`.

Scope of U2541 to U2541c (policy): `apps/desktop/src/keys/`, `apps/desktop/src/app/`, `apps/desktop/src/copy.ts`, `apps/desktop/src/tokens.css`, `docs/design-system.md` and the hint line's rules in `apps/desktop/src/resources/styles.css`. No RPC, App seam command or domain model change is required. Dependencies: #2223 supplies the take-control chord and #2225 the bottom bar's width; both are native blocked-by Issues of the implementation.

**U2230 one list feeds the hint line, Help and the key handlers.** Given the mounted App, when a hint names a key, then that key is a row of `CHORDS` in `keys/chords.ts`, the same row Help displays and the registry binds, and pressing it runs the action the hint names. A row carries the focus places where it is shown as a hint and its order; no hint text or key symbol lives outside the table. Tests: `u2230_every_hint_names_a_bound_chord` (for every place, each hint's keys equal a `CHORDS` row's and pressing its presses runs that row's action) and an extension of the U54 drift observer in `apps/desktop/src/keys/u54_help.test.tsx` (a row shown as a hint has a Help row).

**U2230a the line follows focus.** U2742d adds the registered ⌘B switch to Agent/Bubble hints; the following retirement concerns the old cycling action, not that switch. _Retired in part by U2238 to U2241: `⌘1`, `⌘↑`, `⌘↓`, `⌘B`, `⌘.` and `⇧⌘⌫` are gone, so a Terminal Bubble shows no line and a watched Agent's pane shows only the take-control chord._ Given an open Project, when focus is in a watched Agent's pane, then the line shows two to four hints: the take-control chord (#2223), the key back to the Rail, and the keys to the previous and next Agent. In a Terminal Bubble it shows minimise, close and next Bubble. In the Rail it shows the keys that act on the focused row. When focus moves, the line shows the new place's hints at once; in a place with no hints, or while a modal layer such as Help is open, the line is empty. Keys are written as macOS symbols (`⌘ ⇧ ⌥ ← ↑`), each followed by its label. Tests: `u2230a_hints_follow_focus` (Rail, watched Agent, Terminal Bubble, no place, Help open) and `u2230a_hint_keys_are_symbols_with_labels`.

**U2230b the line drops hints from the end.** Given the densest seed (`tree-40`, an Agent with 8 Runs) at 1280×800 and 700×800, when a place's hints show, then fewer hints drop from the end when the bar has no room for all (#2225). Use light/dark and increased contrast for `u2230b_hint_line_drops_from_the_end`; captures and critic Check readings use dark only (U3725). Moves D2, D5 and D6, defined by `docs/design-system.md`, heading `The checks`; only Tokens are used and no Check passing on main regresses. Tests: `u2230b_hint_line_drops_from_the_end`, a headless real-browser test under `apps/desktop/src/keys/`, and `u2230b_hint_line_uses_only_tokens` (`loop/rules.sh tokens` passes). These browser results establish webview behaviour; the user reports what they meet on the Mac.

**U2541 keys sit in one chip component.** Given the Hint line, Help and the ⌘K leader panel, when each shows a key, then it is drawn by one component, `KeyChip` in `apps/desktop/src/keys/`, which takes the key string of a `CHORDS` or `LEADER` row and draws each symbol inside one chip; no other markup in the App draws a key (`.hint-keys`, `.help-keys` for chords and `.leader-keys` go). The chip is `--font-ui` at `--text-small` weight 500, `--text` on a fill Token, no border, `--radius-chip` (4 px), 5 px side padding and 16 px tall; the label beside it stays `--grey`. `KeyChip` wraps a plain `<kbd>`: Ark UI offers no key-chip primitive (checked at build time). The new fill and radius Tokens go in `apps/desktop/src/tokens.css` and `docs/design-system.md`; `loop/rules.sh tokens` in `just check` already proves no other value is used. Test: `u2541_one_component_draws_every_key` (Hint line, Help and leader panel each render their keys through `KeyChip`).

**U2541a the chip reads in every theme.** Given dark and increased contrast at 1280×800 and 700×800 on the densest seed (`tree-40`), when the Hint line shows, then the chip fill is about 6% black on light and 8% white on dark, the chip text meets D5 (4.5:1) against the fill, the chip fits the line's 16 px height with no clipping, and hints still drop from the end whole (U2230b). Moves D2, D5 and D6. Observer: paired captures in `artifacts/ux/U2541/` and `window.__checks()` for each state, judged by the design critic; no test, since contrast, size and clipping are looks (AGENTS.md rule 10). U2230b's existing test covers dropping whole hints.

**U2541b two to four hints in every place.** Given an open Project, when focus is in the Rail, a watched Agent's pane, a Terminal Bubble, a Pad (outside its Editor), a Drawer or the Switcher, then the line shows two to four hints from `CHORDS` rows whose `hint.at` names that place, in table order, each pressing to the action its label names (U2230). With Help open it shows none. The implementation fixes the places and their hints from the keys that exist after U2238 to U2241; a place with fewer than two bound keys shows none rather than inventing one. Tests: `u2541b_every_place_shows_two_to_four_hints` and the existing `u2230_every_hint_names_a_bound_chord`, which covers the new places.

**U2541c a Pad's Editor shows its formatting keys.** Given focus in a Pad's Editor and the Pads editor work having bound blocks, bold and italic, when the line shows, then it shows those keys from `CHORDS` rows with `hint.at.editor`. Until those keys are bound, `editor` has no rows and the line stays empty there. Policy for ordering: the Issue that binds the Editor keys implements this scenario and is a native blocked-by of the implementation; it adds the rows, and no key symbol lives outside the table. Test: `u2541c_editor_hints_follow_bound_keys`.

**U2541d one chip per press, one pair per alternative.** Direction: Issue #3377 (owner: "why these hints look undesigned and awful?"); it narrows U2541's "each symbol inside one chip": a chord's modifiers and key are one chip. Given a `CHORDS` or `LEADER` row, when `KeyChip` draws its `keys`, then a chord such as `⇧Tab` or `⌘K` is one `<kbd>` holding the modifiers and the key, a sequence of presses is one `<kbd>` per press, and an alternative (`J K`, `J / K`) is two `<kbd>` in one pair with a `--space-1` gap, never the gap between hints. Every site that shows `KeyChip` with a label (Hint line, Help, the leader panel, the Shelf's triage hints, Tooltip, Switcher, Pane) draws it through one shared hint component `KeyHint` in `apps/desktop/src/keys/`, and no site keeps its own layout (`.triage-hints` and `.hint` rules for chip and label go). Test: `u2541d_a_chord_is_one_chip_and_an_alternative_one_pair` (`⇧Tab` and `⌘K` render one `kbd`; `J K` renders two `kbd` in one pair element; every `KeyChip` caller renders through `KeyHint`, extending `u2541_one_component_draws_every_key`).

**U2541e hints never break and read quietly.** Given the triage hints, Help, the leader panel and a Tooltip with a chord at 1512×950 and at the Shelf's narrowest width (163 px, U363) on `tree-40`, dark and increased contrast, when they show, then a chip stays on its label's line, hints sit in an aligned column grid or one row that drops whole hints when narrow (U2230b), never halves of a hint; chip text matches the label's size and baseline in muted ink at the line's height, with no fill that out-weighs the words, the label `--grey` and the chip slightly stronger; the gap is `--space-1` between chip and label and `--space-4` between hints. Moves D2, D5 and D6 (`docs/design-system.md`, heading `The checks`); only Tokens are used. Observer: `just capture U2541e` in dark, `window.__checks()` and the design critic judge looks; no test asserts layout, colour or size (rule 10). Policy: this replaces U2541's chip fill and 16 px height where they conflict.

## Tooltips name their key

Direction: #2570 (owner, 2026-10-18): the Rail's `+ agent` tooltip reads `New Agent` followed by `⌘` and `N` chips, using U2541's `KeyChip`. This extends the Intervene stage's key teaching to the action under the pointer or keyboard focus. Scope (policy): existing files in `apps/desktop/src/ui/`, `apps/desktop/src/rail/`, `apps/desktop/src/keys/` and `apps/desktop/src/copy.ts`, plus behavioural tests beside those files. No RPC, App seam command, new shortcut, domain model or new tooltip-bearing control.

Inventory on main (policy): qualification is by the action the tooltip-bearing control runs, not by matching label text. These are all `CHORDS` rows in `apps/desktop/src/keys/chords.ts`, constant `CHORDS`:

| Action | Existing tooltip-bearing control | Result |
|---|---|---|
| New Agent | Every Workstream row's `+ agent`, `apps/desktop/src/rail/RowIcons.tsx`, `RowIcons` | `New Agent`, then the New Agent row's key chips |
| New Agent with a prompt | None | No tooltip added |

| Remove | None (Rail menu action) | No tooltip added |

The row's folder, editor, stop, clear and disclosure controls have no `CHORDS` action. Bubble close and minimise are `LEADER` actions, not `CHORDS` actions. Row/name, Project title, resource-name, failure and unavailable-send explanations describe content or availability, not a keyed action. All keep their existing tooltip content. If main adds a tooltip-bearing control for a `CHORDS` action before implementation, that control also qualifies under U2570a; extend this inventory in that implementation PR.

Mechanism (policy): extend existing `Tooltip.Content` to accept an optional `Chord` row association and append `KeyChip` with that row's `keys` after its children. Existing `IconButton` and Rail `Tip` forward the optional association without putting it on the DOM. Callers select the actual `CHORDS` row explicitly; do not infer it from a translated label, parse a key from copy, duplicate key symbols, or maintain a second shortcut table. The Rail's add control supplies the New Agent row and uses `copy.newAgent` for tooltip text; its accessible name and click action stay unchanged. Remove the inline shortcut in `copy.addAgentN` when its last caller migrates. Reuse Ark Tooltip and the existing `KeyChip`; add no key markup, tooltip implementation, parser or registry.

**U2892a every dimmed backdrop includes the Hint line.** Given the actual App with an open Project and visible Hint line, when any dialog or other layer with a dimmed backdrop opens, then the backdrop covers the whole window, including the Hint line and Terminal tabs. The Hint line is dimmed with the rest of the background and, where that backdrop uses blur, blurred by the same filter. Alternatively the foreground dialog may show its own applicable keys inside its layer; background hints must never paint as an undimmed or unblurred band above the backdrop. Policy: fix layer ownership and bounds, never hide the strip with a timer, duplicate a filter over the strip or introduce a second backdrop state. Do not add dimming to surfaces that have no dimmed backdrop. Reduced transparency retains dimming and removes blur; foreground content remains opaque and unfiltered. Appearance is judged by the rendered observer below, not a stylesheet assertion.
