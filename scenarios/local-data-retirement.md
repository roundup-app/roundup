# Current local data only

Specification for [#5467](https://github.com/roundup-app/roundup/issues/5467). Terms: App, Daemon, Project data, Saved work (`GLOSSARY.md`). Until release 0, local application data need not survive a schema change. This specifies removal and refusal, not an implementation or an observed pass.

**N5467a older local data is refused before loading.** Given a file-backed store built by a proper prefix of its production schema sequence, with sentinel rows, when the current store opens it, then opening fails before application rows load or any migration runs. The error says the local data is incompatible with this build, names the absolute folder containing that store, and tells the user to close roundup and delete that folder to start fresh. It never reports an empty or partly restored Project as success. Repeating open produces the same refusal; schema, version and sentinel rows remain unchanged (`n5467a_older_store_is_refused_without_changes`, planned in-process parameterized tests at the existing store-open seams).

Cover Project `storage::open` in `crates/rupd/src/storage.rs` and live standalone Agents, Todos, Pads, Messages, Digest and Provenance opens through their existing `schema::open` / `digest_schema::open`. Audit current callers first: a store without an older production prefix uses a version-zero database with an application table and sentinel, not an empty database. Include a nonempty unversioned historical database. A current database with a different table/column shape, even at the same version, is refused under N5420a; newer versions retain N5088a's refusal. Metadata inspection for rejection is permitted; reading application rows to convert or partially restore them is not (policy).

Given that older Project database, when the real in-process Daemon open is called, then its returned error retains the same folder and manual reset instruction and no usable Daemon is returned (`n5467a_daemon_reports_the_reset_folder`, planned in `crates/rupd/tests/store_migrations.rs`). Never retry that failed open by creating a replacement database, suppress its failure or register a partially opened Project (policy).

**N5467b no reader upgrades an older local representation.** Policy: remove every runtime path that reads, converts, repairs or imports a superseded local application representation, together with tests proving successful historical opens and their exclusive fixtures/helpers. Audit Rust stores and SQL hooks, Project startup/folder movement, App/plugin/browser persistence and native preference readers. Starting pointers are `crates/provenance/src/migration.rs`, `crates/rupd/src/storage.rs`, `crates/rupd/src/data.rs`, `crates/messages/src/schema.rs`, `apps/desktop/src/state/storage.ts` and `crates/desktop/src/store.rs`; the inventory is not exhaustive. Record the implementation base SHA, each discovered path/caller, its removal or current-only purpose, and the retired test or surviving current-behaviour proof on #5467. Inspect the diff and remaining callers; add no source-text test for deletion.

Policy: an absent database and an empty database with no application objects remain fresh inputs. An existing nonempty store is accepted only in the current representation; migration SQL may still build the current schema from empty input, including the build-time fresh image. Never replay a proper migration suffix on an existing older store, construct historical reference schemas to adopt it, repair the skipped-Pad drift, decode retired stored variants, or migrate browser localStorage keys into the native store. Do not squash, renumber or rewrite the fresh-creation SQL sequence or replace the installed migration library. An existing current-schema database follows its ordinary reopen path without applying historical row-repair hooks.

Policy: N3's old `.roundup/` application-file mover is retired. Detect old application storage by its paths/metadata, refuse with its location and manual reset instructions, and leave it untouched; `.roundup/worktrees/` alone is not old application storage and remains usable. If obsolete application data shares a folder with Worktrees or user files, the error must say to preserve those before removing the obsolete data. Never tell the user to delete their Project, Worktrees or unrelated files. N17's old per-store files outside the selected store remain ignored and unchanged; their contents are not inspected or imported. Explicit import of vendor conversations through the current Import capability, user-requested Pad file reads and current-schema crash recovery are not upgrades (policy).

Given only old browser `roundup:*` preference/draft keys and an otherwise empty current native store, when production App persistence initializes, then initialization reports incompatible saved data and the absolute folder containing the obsolete webview data to delete after closing roundup before any editor or ordinary App surface loads. No old value is parsed, imported, removed or replaced, no native value is written, and a second initialization still refuses (`n5467b_old_browser_storage_is_refused`, planned in `apps/desktop/src/state/u3787f_storage.test.ts`, using its existing storage adapter). The named folder must actually contain the obsolete data: deleting only the current plugin file must not be suggested as a fix for browser keys that would survive it. Resolve the location through the existing Tauri/platform capability, not a guessed platform path. After the test adapter simulates the user removing that obsolete storage, initialization from empty input succeeds through the unchanged fresh path (same test). Current valid native records and current-schema drafts keep their own recovery, conflict and failure contracts (policy).

**N5467c fresh creation and current reopen stay unchanged.** Given fresh Project, standalone and in-memory stores, when the same current callers create, write and reopen them where persistence applies, then current operations return the written values: retain `n20_current_store_opens` in `crates/rupd/tests/store_migrations.rs` and `n16_all_stores_share_one_project_database` in `crates/rupd/src/storage_tests.rs`. Retain the fresh-image equivalence and unique-identity assertions in `r3696c_a_fresh_project_db_equals_the_migrated_one_with_its_own_identity` in that file, changing its comparison side to apply the full sequence once to empty input. Retire its historical-prefix upgrade and injected upgrade-rollback subcases. Preserve the embedded-image path, identities, fallback for genuinely fresh input and build-time SQL application (policy). A current-schema draft for a retired UI surface is still current data; its existing Copy/Discard recovery does not authorize a historical decoder.

**N5467d historical upgrade acceptance is retired.** Policy: the amendments in this PR retire B3563e and the historical-open clauses in the retirement inventory. The implementation removes the corresponding successful-upgrade tests, including `crates/messages/tests/b3563e_migration.rs` and `b3563e_upgrade_preserves_messages_and_never_replays_old_actions` in `crates/rupd/tests/store_migrations.rs`; keep `n20_current_store_opens` in that file. Retired clauses do not weaken current Message identity/receipt/finality, current drafts, publication identity/revocation, removal safety or Worktree ownership protections. For any further upgrade clause found by the audit, amend its owning scenario in the implementation PR under this work order rather than preserve a compatibility exception.
