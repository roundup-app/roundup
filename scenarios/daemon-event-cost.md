# Daemon event cost

Module: `crates/rupd`, `src/{digest,owner_told,auto}.rs` and the existing `src/{tests,auto_tests}.rs` unit tests. Ids: EC5637a–EC5637d. Work order: [#5637](https://github.com/roundup-app/roundup/issues/5637). Terms: Rail, Todo, Actor, Message, Hand-off (`GLOSSARY.md`). Principles: P10 (one idle batch).

These clauses preserve notification behavior while bounding per-event work. The test names below are implementation acceptance, not claims that tests already exist. Existing regression checks are numbered separately. No public RPC or contract changes.

**EC5637a Agent-state decisions read only the Rail.** Given pending Todo notifications ready to flush, or idle Agents ready for hand-off, when each selected decision reads Agent state, then it reads the Rail through a narrow internal operation on Check 1's Reader/Module seam. Each decision makes zero `pad.list`, `todo.list`, `message.list` or Touch-history reads; it neither constructs a `World` nor reads completed text (policy: independent review traces both call paths). Other required operations remain: `todo.hand` records the chosen Todo before hand-off delivery, `message.send` sends notices, and comment processing reads `todo.comments`. The zero-read assertion concerns unrelated snapshot reads, not these operations.

- `ec5637a_owner_flush_reads_only_rail` and `ec5637a_owner_handoff_reads_only_rail`, in `owner_told.rs`: call production `flush` and `hand_off` using recording Modules; assert the exact addressed Message bodies, allowed calls and zero unrelated Module reads. The hand-off fixture has two idle Agents and records `todo.hand` then `message.send` for each in first-idle order; repeated idle events in one batch produce one hand-off per Agent. Flush still precedes hand-off for an idle batch (policy, Check 9).
- `ec5637a_owner_required_rail_failure_sends_nothing` in `owner_told.rs`: fail `rail.tree`; assert no Message is sent and no `todo.hand` occurs. Pending owner notices remain available for the next successful flush. Keep required-read/admission failure handling; an unknown required state cannot authorize delivery (policy).

**EC5637b Todo notification allocations exclude unused payloads.** Given otherwise identical prebuilt Todos with empty bodies or 1 MiB bodies, when initializing `Told` and recording the same created, updated and restored Events, then bytes allocated by notification-state construction and each update do not increase with body size. Test: `ec5637b_owner_state_allocations_ignore_body_size`, in `owner_told.rs`, measures only the production fold calls, excluding fixture/Event creation, fixture cloning, measurement setup and output collection; compare allocated bytes for the paired inputs after identical warm-up. Compare the exact eventual notice bodies too. Keep owner, blockers and the title data needed to produce Check 6's current output, including the latest title and its existing character limit.

Policy: retain no full Todo in notification state, no unused body/reference fields and no before/after full-Todo clones. Historical state remains: comment progress and first-read cutoff, ordered pending changes, and first-idle order. This is a projection of the current fold, not a persistent World or Message index. Review the representation and measured call boundaries; a source-text test is not evidence of allocation independence.

**EC5637c notification history survives the smaller representation.** Given Check 5's owner changes and replies, when the fold records changes, deletion, restore and comments arriving before the Todo is known, then its exact notices, recipients and deduplication are unchanged. Retain Check 6's existing tests rather than duplicating their assertions. Add `ec5637c_owner_delete_restore_preserves_pending_rules` for deletion clearing Todo/comment progress, deleted Todos contributing no output, restore creating no assignment notice and subsequent changes using the restored title. Add `ec5637c_owner_comments_before_todo_keep_progress` for an earlier Agent author's reply notification queued before its Todo arrives: a later Todo event supplies the title without losing that pending reply or telling the already-read comment twice. Both live in `owner_told.rs` and assert exact emitted bodies, not only pending-map contents.

Policy: Check 5's self-change suppression, assignment/unblocking, comment authors and cutoff, T25 selection/order, T26 durable hand-off and Check 9's idle batching remain unchanged. No historical notification state is retired to save memory; unrelated source reads alone disappear. Existing regression observers remain required through CI; the focused command below does not replace them.

**EC5637d Auto indexes notice identities once per pass.** Given open Unassigned Todos homed in eligible Auto Workstreams and retained Message history, when production `auto::tell` runs, then each candidate's identity is formed exactly once from its Todo id and Check 7's latest qualifying history sequence (zero when absent). With multiple candidates, a temporary sorted index borrows each eligible Message's first line exactly once and answers membership without rescanning history for every candidate. Tests in `auto_tests.rs`:

- `ec5637d_auto_many_candidates_index_history_once`: use at least 128 candidates and 512 retained history rows, with both already-noticed and new identities. Count identity formation and history first-line extraction at the production operations, not in a parallel test-only algorithm: one formation per candidate and one extraction per eligible row. Assert exact new Message bodies, recipients and candidate order. The index stores borrowed first lines, not cloned Message bodies (policy: representation review).
- `ec5637d_auto_zero_and_one_candidate_avoid_sorting`: table-driven zero/one-candidate passes build no sorted index; zero formats no identity and examines no history first line; one formats one identity and uses a borrowed linear membership scan, examining each eligible row at most once. Assert the exact notices or their absence as well as the operation counts.
- `ec5637d_auto_identity_preserves_actor_and_history_predicates`: table-drive the current protocol through production `tell`. Only exact `Actor::daemon()` equality and a body beginning with the exact identity followed by `\n` suppress a notice. A bare identity without a newline, CRLF in place of that newline, a longer/different identity, an identity on a later line, a different Actor kind/id/parent, or display text alone does not suppress it. Retained Dropped Messages still suppress their identity; Message recipient and delivery state add no new filters. Owner-history rows qualify exactly when `after.owner` is absent and `before` is absent or has an owner; select the last such row, ignoring later unrelated changes. Compare full emitted bodies and counts, including reassignment to Unassigned producing a new identity and repeated passes producing none for an existing identity.

Policy: the temporary index is discarded after each pass. Keep Check 8's eligibility, history and restart behavior. Required Rail/Todo/Message/history reads still propagate their failures through `tell`; identity comes only from the existing protocol and authenticated Actor, never a title or other display text. No persistent Message index, World cache or additional store is introduced.

## Verification

Policy: use in-memory fixtures at the existing Module seam, no child process, PTY, browser, real vendor or Model for new acceptance tests. Test operation counts and allocated bytes, not wall-clock speedups. Test-only counters observe production operations. Keep fixture and instrumentation work within the Issue's module scope; the implementation applies rule 9 before adding machinery. Wake's full-World path and Digest behavior stay unchanged; lazy Wake reads need a separate consistency design. No current `just perf` metric isolates these per-event costs.
