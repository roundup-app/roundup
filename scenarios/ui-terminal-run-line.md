# UI: run a printed shell command with one click (U7889)

Module: `apps/desktop` (the webview), plus `crates/rupd` and `crates/contracts` only if U7889c needs a method. Ids: U7889a–U7889e. Owner picks (2026-11-22, #7889): a click runs the line at once; the target is a ▶ beside the line, shown on hover; each line has its own ▶; one shell per Agent, reused, and a second only while every one is busy. Acceptance only; this specification claims no implementation. Reuses X11, X12, X15 (`scenarios/quick-terminal.md`, `scenarios/ui-terminal-turns.md`), U165, U365 (`scenarios/ui-terminal-links.md`) and U514.

Policy: the ▶ is a `apps/desktop/src/ui/` primitive; the Reuse section of the PR names the libraries considered (rule 9). A new RPC method or App seam command follows the Contract recipe and its name goes in `GLOSSARY.md`. The first journey's Intervene stage gains a faster way to act on what an Agent printed. Gate: can a click run something the user did not point at, or type into an Agent's own Terminal? Observer: U7889a and U7889c's tests.

**U7889a which lines get a ▶.** Given an Agent or Door Terminal that printed a prose line, a fenced block labelled `sh`, `bash`, `zsh` or `shell` holding `$ brew upgrade ollama && brew services restart ollama` and `ollama run inkling-2-mini`, and a block labelled `ts`, then the pointer over a line of the shell block shows one ▶ beside that line only, each line having its own; prose, inline code and the `ts` block show none, including a prose line in the same colour as the block and a prose line whose text equals no block line. A leading `$ ` is dropped from the command; a line ending in `\` joins the next into one command. Claude Code prints blocks without their fences, so the blocks are read from the Agent's conversation record that the Daemon already reads (`crates/agents/src/claude_code/conversation.rs`), never from screen colours; a ▶ shows only on a screen line that matches a line of such a block in the record, a wrapped long line included, and a line whose match is unsure gets none (policy). Planned behavioural test: `u7889a_one_play_mark_per_shell_line_and_none_in_prose`, with a fake Agent's output and record, asserting the marks by role and count, not position.

**U7889b the click runs the command and leaves the rest of the Terminal alone.** Given a ▶ beside a command, when the user clicks it, then that command and Enter are typed once into an Agent-owned shell (U7889c), and nothing is written into the Agent's own Terminal; with no click nothing runs; selecting text and a plain click on a link or file path still behave as U365 says. Planned tests: `u7889b_click_writes_the_command_once_to_the_shell_never_the_agent`, and `u7889b_no_click_writes_nothing`.

**U7889c the Agent's shell is reused, and a second opens only while every one is busy.** Given an Agent with Terminals owned by it (X11), when a ▶ is clicked, then the App types the line only into a login shell (X12) of that Agent, in its Worktree else its folder, whose prompt is free by its shell marks (X15); when every shell of the Agent is busy (`sleep 30` running, an `ollama run` chat) one more is opened, X11's cap of 8 per owner holding, and the next click after that command ends reuses a free shell. Twenty clicks on quick commands, made one at a time, leave one Terminal for that owner in `terminal.list`. The choice of shell and the typing happen in one step with no other Terminal listing between them, so two quick clicks never type into one busy shell (policy). Planned tests: `u7889c_twenty_quick_clicks_leave_one_shell` and `u7889c_click_while_sleep_runs_opens_a_second_then_reuses_a_free_one`, in the fake-Agent harness of `scenarios/quick-terminal.md`.

**U7889d the click shows the shell.** Given a click that ran a command, then that shell's Bubble is shown, restored when minimised, and focused as a Bubble the user opens is (U165), and the run is its own command row (U514) with its exit code once it ends. Planned test: `u7889d_click_restores_and_focuses_the_shell_bubble`; the command row and exit code are U514's test.

**U7889e the ▶ is reachable and legible.** Given the densest seed at the scenario's viewport, then the ▶ is a button with an accessible name naming its command, reached by keyboard from the Terminal's line focus as well as by hover, and meets D2, D5 and D6 (`.agents/data/harness.md`) with Tokens only (rule 8); its looks are the design critic's, not a UI test's (rule 10). Planned test: `u7889e_play_mark_is_a_named_button_reachable_by_keyboard`.
