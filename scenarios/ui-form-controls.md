# UI: finished shared form controls

Module: `apps/desktop` (webview). Work Issue: #4382. Journey stages: Enter (Project settings) and Intervene (App settings and work assignment). This is implementation acceptance; this specification alone changes no rendered control (policy).

## Direction and boundaries

Policy: keep Solid, Ark and the thin shared wrappers required by `docs/adr/0009-app-component-layer.md`, heading “The App component layer”. Use the Kobalte documentation demos as the appearance reference, translated into App Tokens, rather than adopting Kobalte or copying its literal colours and sizes. References: [text field](https://kobalte.dev/docs/core/components/text-field/), [Select](https://kobalte.dev/docs/core/components/select/), [Combobox](https://kobalte.dev/docs/core/components/combobox/), [Checkbox](https://kobalte.dev/docs/core/components/checkbox/), [Switch](https://kobalte.dev/docs/core/components/switch/), [Radio group](https://kobalte.dev/docs/core/components/radio-group/) and [Slider](https://kobalte.dev/docs/core/components/slider/).

Policy: the owner's 2026-10-27 direction in #4382 supersedes U3528's no-ring requirement and the no-box taste rule only for the form controls below. Their frames and focus rings are required. Unrelated buttons, tabs, rows, panes and dialogs retain U3528; transient pressed backgrounds remain forbidden. The dark-and-light comparison below is a specific exception to U3725/U3725a and the harness's dark-only capture rule; other captures remain dark. Update the applicable design documentation and style enforcement during implementation so these exceptions are represented without weakening unrelated Checks.

Policy: one shared style per control lives under `apps/desktop/src/ui/`; Tokens remain in `apps/desktop/src/tokens.css`. Audit callers across the App, including App settings, Project settings, Import and the Delegate board, and remove their local control-paint overrides. Screens may arrange fields and supply labels, values, descriptions and errors; frame, padding, placeholder, focus, indicator, disabled and invalid paint belong to the shared control. Include `Field`, textarea, `Form` field composition and existing numeric inputs in that audit. Record the caller inventory and any engineering remainder on #4382, never in a scenario Work table. No new settings, RPC, App seam command, domain term or animation is commissioned.

## Acceptance

**U4382a form controls share a finished frame and state language.** Given the App at 1512×950 with App settings and Project settings available, when the user opens each page, focuses and edits its fields, opens each choice popover and changes its choices, then the following visual policy holds in dark and light. The design critic judges every row against its linked Kobalte demo; these are visual observations, not computed-style, layout or exact-copy tests.

| Control | Required appearance (policy) |
| --- | --- |
| Text field and textarea | A visible 1 CSS px border encloses the field, with Token inner padding, a distinct placeholder tone and a clear focus ring. A visible label sits above; supplied description or validation error sits below and remains readable. Text and caret are not clipped. |
| Select and Combobox picker | The trigger uses the text field's frame and focus language, with a trailing chevron. The anchored listbox popover has a visibly highlighted row and a check on the chosen row; highlight and chosen value remain distinguishable when they are different rows. The Combobox search field uses the shared field treatment. Existing command/search Combobox uses retain their actions rather than gaining a fictitious selected value. |
| Checkbox | A framed box, with a check when checked, a dash when indeterminate, and neither mark when unchecked; the label sits beside it. A circle or filled dot does not substitute for the box/check. |
| Switch | A visible track and separate thumb, with distinct on/off track colours and thumb positions; the label sits beside it. A checkbox or text glyph does not substitute for track and thumb. |
| Existing Radio group | Framed radio marks, a visible selected mark and the same focus language, with labels beside the choices. |
| Slider, wherever the App uses one | A visible track and thumb, distinguishable current value and the same focus language. If the implementation inventory finds no App slider, record that fact on #4382; this work adds no slider setting or unused primitive. |
| Every control above | Enabled, disabled, invalid and focused-invalid presentations are distinguishable. Disabled controls keep a readable label and value but do not present as enabled. Invalid controls expose a visible error cue and supplied error text, not colour alone. Focus rings remain visible against their touching grounds in both schemes, including invalid controls; focus and validation do not move neighbouring content. |

Policy: extend the existing Ark wrappers only as needed to expose their indicator, thumb, indeterminate, disabled and invalid parts/states. Ark owns keyboard, pointer, focus, labeling and validation semantics; retain the App's existing controlled-value acknowledgement and focus-return permissions. Reuse the installed Ark components and platform field semantics first; any new machinery still needs AGENTS.md rule 9 evidence. Shared styling applies to production callers, not just a demonstration fixture.

Behavioral then-clauses and observers:

- Given each enabled shared control, when the user edits text, toggles by pointer or Space, selects a radio with arrows, or opens a picker, filters, navigates and selects with the keyboard, then the same chosen value and callback/RPC identity and count as before reach its caller. Escape dismisses the picker and returns focus according to its existing permission; it does not submit the surrounding form. Test: planned parameterized `u4382a_shared_controls_keep_ark_interactions` in `apps/desktop/src/ui/`, covering only behavior not already asserted by the unchanged existing tests below. Test slider keys and pointer value changes only if a production slider exists.
- Given disabled controls and enabled invalid fields, when the user attempts pointer/keyboard activation or corrects invalid input, then disabled controls emit no value-change call, while invalid fields remain editable and expose their associated error through Ark's accessible relationships. Checkbox indeterminate state is exposed accessibly and activation reaches the caller once. Test: planned `u4382a_disabled_invalid_and_indeterminate_semantics` in `apps/desktop/src/ui/`; parameterize the control types rather than asserting paint. A fixture may supply states that no current settings value can naturally reach, without inventing production validation rules.
- Given an unfinished settings field, when the user closes and reopens settings or reloads, then its exact unsubmitted value is retained without applying it. Existing test: `u3806_unsubmitted_fields_survive_close_and_reload_without_applying` in `apps/desktop/src/settings/u3806_preferences.test.tsx`, unchanged. Controlled Switch acknowledgement and disabled pointer behavior remain asserted by `u3310_pointer_requests_one_change_and_waits_for_the_caller_from_%s` and `u3310_disabled_pointer_invokes_nothing` in `apps/desktop/src/ui/u3310_switch.test.tsx`, unchanged; keyboard reachability remains asserted by `u3310_the_switch_is_a_labelled_keyboard_reachable_switch` in `apps/desktop/src/ui/u3310_browser.test.ts`, unchanged.

Policy: existing behavior tests keep passing unchanged. Add only uncovered behavior assertions; when a test file must change, apply AGENTS.md rule 10 and identify the surviving proof for every cut. No test is added for colour, geometry, copy, ring presence or the text of this specification.

## Rendered observer and gates

Policy: implementation uses an isolated headless agent-browser session and fresh test profile against the existing App harness. Never attach to the user's browser or desktop. Use 1512×950 and matched base/head renderer, pixel ratio, seed and state; record immutable SHAs. Start from `tree-40`, open App settings and Project settings, and capture their resting and keyboard-focused controls, each open picker with a highlighted row different from the chosen row, and visible validation feedback. Include a failed call with its failure text visible on the densest seed. Also inspect Import and the Delegate board so local overrides cannot hide a shared-style regression.

Policy: compare base and PR head side by side for App settings and Project settings in both dark and light, alongside the corresponding Kobalte demos. Supplement those real pages with a rendered fixture of the actual shared wrappers for any missing control/state, including checkbox indeterminate and every control's disabled, invalid and focused-invalid state. Fixture evidence supplements, never replaces, the settings pages. The critic records pass/fail for each appearance-table row and state, naming the control, page/fixture and scheme on failure; “looks finished” alone is not a result.

Policy: run `just capture U4382a` for the dark captures and take the explicitly commissioned light comparisons through the same isolated observer. Leave base/head screenshots, interaction recordings and Check readings under `artifacts/ux/U4382a/`, with scheme and state in filenames, following `.agents/data/harness.md`, heading “Captures”, except for this named light exception. Never commit images or videos. This specification-only PR requires no rendered capture. The observer proves Chromium/webview appearance and behavior; the user reports what they meet on the Mac.

Policy: applicable Principle gates are P3 (does styling introduce an interruption?) and P11 (does changing a field or focus path lose unfinished input?). Observe settings editing and picker dismissal without routine attention, and exact draft retention through the named tests. No Daemon, vendor or native behavior change is claimed.
