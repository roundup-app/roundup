# UI: the readback draws a changed flow as a statechart you can step (U7709a–U7709f)

Module: `apps/desktop/src/changes/` (the diagram's text, the chart in the Overview, Save as Pad), `apps/desktop/src/pads/` (the viewer's controls and loader, which the Pad's own mount keeps as they are), `crates/agents` (one sentence of step one's prompt), the fake App and its fixtures. Ids: U7709a, U7709b, U7709c, U7709d, U7709e, U7709f. Work order: [#7709](https://github.com/roundup-app/roundup/issues/7709), blocked by #7546 (the block and viewer, `scenarios/pads.md`, SC1 to SC8), #7547 (Pad save's model and dump, P7547a to P7547c) and #7548 (the brief), all merged. Owner, 2026-11-19: "the readback picks the simplest form for each change; it draws a statechart only when a flow changed", and the statechart is #7546's block and viewer, which the readback's Agent writes the data of. Owner, 2026-11-26: "use proper icons I don't like textual actions": every action of the Changes view is an icon button with no visible text, its tooltip and accessible name from `copy`, and a status line stays words. No Daemon method, Message, App seam command or contract change: `Account.diagram` is free text (RB3), so the block rides in it and the Daemon never reads it. The App changes the way it draws a diagram; step one's prompt gains one sentence. A readback is a personal aid, never a gate; its text is never sent to the Agent, and the App shows no token, price or usage figure (P14). Reuse (rule 9): U7709f.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

Decisions this specification takes (the Issue's "My reading" points, each kept and tested unless it says narrowed or policy):
- **Where the block rides.** The readback's Agent writes a fenced `statechart` block (SC1's JSON) inside the account's `diagram`. The App splits the text with the `marked` lexer it already holds: a `code` token whose language is `statechart` is a chart; every other token is the diagram's text as U7688c reads it (`parseDiagram`), a call line, a Before or After line or words. The Daemon neither reads nor checks a block, and never fails a run on one (as RB3 says of the diagram); roundup never checks the chart (SC1). Order of charts as written.
- **Kept: a changed flow with a model and its dump.** The prompt asks for a block only when the hunks hold a committed dump of a TLA+ model's checked states and steps and the changed code of the flow it checks; the readback never writes a model or runs a check, since its call has no tool (Glossary: Readback). Narrowed: the reader sees only the hunks (RB1), so "committed at the diff's head" reads as "in the diff". P7547b and P7547c already fail a changed `step` whose dump is stale, so a changed behaviour arrives with its dump's hunks; a change of the flow's code that leaves the dump alone gets the usual diagram. Policy (no test rereads the prompt, rule 10); what the App does with either answer is U7709a and U7709b.
- **Narrowed: no script.** #7548's brief has an Agent turn the dump into the block with a script; the readback's call has none, so its Agent reads the dump's hunks and writes the merged block's words itself. The App reads the result as SC6 does and trusts nothing about it.
- **Kept: any other changed flow draws as it did.** A diagram with no block is U7688c's figure and words, and the diff with no flow change shows no chart (U7709b).
- **Narrowed: no table.** The Issue's "a sentence, a table or a diagram" is met by the overview and the notes (sentences), the diagram and the chart. The account has no table and the Bar names none, so none is built.
- **One viewer.** The chart is #7546's viewer, `mountStatechart`: the same XState machine, layout (`elkjs`) and loader (`visualKinds`) as a Pad's, requested only when a block is drawn. Only the controls differ: where the Pad's viewer draws Back, Start over, Walk to the break and Details as words, the Changes view draws them as icon buttons (the 2026-11-26 decision, which binds this view and no other). The chart's own words stay: a state's label, a move's label (an arrow and the button under the chart named for the same step), the rules, the bar and the details.
- **No second stepper.** U7703's stops step the parts of the calls the diagram draws; a block's states are not parts, and a stop that names one is dropped as one that names an undrawn part is. The chart steps itself.

**U7709a a diagram that holds a statechart block draws the chart, and the user steps it.** Given the Changes view on the Tree target with the fake App, and an `agent.readback` answering `read` whose `diagram` holds one block of four states (a start, a move to a second state, a far state and a state that breaks the rule `r1`), then:
- **Drawn.** The Overview's readback shows the block's `summary`, its rules with their verdicts and "Written by <writtenBy> from its TLA+ check", then the chart with the start state lit, in the diagram's place and above the account's gaps. The block's JSON text is not shown.
- **Step.** A click on a move out of the lit state, in the chart or under it, lights that move's target; Back and Start over undo as SC3 holds; Walk to the break ends lit on the red state with the bar naming the rule (SC4); Details shows the lit state's values and where the check stopped (SC5).
- **Asks nothing.** Drawing and stepping call `agent.readbackStart`, `agent.explain` and every other Daemon method zero more times (P9).
Asserted in `u7709a_a_diagram_with_a_statechart_block_draws_the_chart_and_the_user_steps_it`, which uses the same layout stand-in as `sc_statechart.test.tsx`.

**U7709b any other diagram draws as before, and loads nothing of the chart.** Given the fixture, then:
- **Calls only.** A diagram of `run -> load` lines draws U7688c's figure and words, shows no chart, and the chart's loader (`renderers.statechart`, XState, `elkjs`) is requested zero times; so does a diagram with no call and a result with no diagram.
- **Both.** A diagram holding a block and call lines draws the chart and the figure of the calls, the lines of words around the block stay words, and the stops of U7703 step the calls' parts alone (a stop that names a state of the block is dropped).
Asserted in `u7709b_a_diagram_without_a_block_draws_as_before_and_requests_no_chart_loader` and `u7709b_a_block_and_calls_draw_both_and_the_stops_keep_to_the_calls`.

**U7709c the chart's controls in the Changes view are icon buttons.** Given the chart of U7709a, then Back, Start over, Walk to the break and Details are buttons with no visible text, each drawing an `Icon` glyph of `apps/desktop/src/ink/Icon.tsx` and keeping the Pad viewer's words as its accessible name and tooltip (through `ui/IconButton`, from `copy`); Walk to the break is absent when every rule holds and disabled with its reason at a red state or with no way to one, as SC4 holds; Details keeps `aria-expanded`. A Pad's chart keeps its text buttons, and the Pad's tests pass unedited. Asserted in `u7709c_the_charts_controls_are_icon_buttons_with_their_names` (the Pad's own `sc3_*` and `sc4_*` tests stand for the Pad).

**U7709d a stale readback keeps its chart, and a block that fails to read shows its cause.** Given the fixture, then:
- **Stale.** On `stale` the chart stays inside the account that is dimmed (`data-stale`) with "Changed since readback" and still steps; a new `read` answer draws it again at its start state.
- **Failed block.** A block that is not JSON, names a `start`, step end or `breaks` id that no state or rule holds, or lacks a field SC1 names shows its source as text with one line naming the cause (SC6), and the rest of the readback, a call figure included, draws as usual.
Asserted in `u7709d_a_stale_readback_keeps_its_chart_and_a_bad_block_shows_its_cause`.

**U7709e Save as Pad keeps the block.** Given a read result whose diagram holds a block and calls, then the Pad U7702 saves holds, under its diagram heading, the block as a fenced `statechart` block whose source is the block's text byte for byte, the calls' flowchart as before, and the words around the block as before, so the Pad draws the chart with SC1 to SC5. Asserted in `u7709e_save_as_pad_writes_the_statechart_block_byte_for_byte`.

**U7709f the rendered readback with the chart.** Given the U26 harness, dark App, at 1512 by 950 and at 388 wide, on the 14-module fixture of U7679f with a fake `agent.readback` whose diagram holds the block, then the readback draws with the chart at its start and after Walk to the break, each in its own browser session (#7924). D2, D5, D6 and every Check passing on `main` still pass. Run `just capture U7709f`; evidence under `artifacts/ux/U7709f/`, uncommitted. Policy; the design critic judges layout and looks, never a Vitest test (rule 10). Rule 7 stands: XState and the layout load once, when the first block draws, and this specification makes no measured performance claim. Reuse (rule 9): the chart is #7546's viewer, whose Reuse section chose `xstate` 5.33.4 over `@zag-js/core` 1.48.0 and `robot3` 1.4.0 and `elkjs` 0.9.3 over `dagre`; the block is split with the installed `marked` lexer, not a hand-written fence scan (the Pad editor's `remark` chain is not loaded in the Changes view); the icons come from the installed `@lucide/solid` set. No library is added, and the PR says so. Policy.

**Amended.** U7688c ("Diagram": the figure draws only from the text outside a statechart block); U7702e (the diagram section gains the block's fence, U7709e); U7703 ("One stepper, not two": its stops step the diagram's calls and the chart steps itself); RB3 ("`diagram` may hold fenced `statechart` blocks, which the Daemon never reads"); SC11's "script" for a readback (above). Kept: the Pad's viewer, its tests and its text controls, the readback's states, gaps and stops as built.

Not wanted: a checker, TLA+ or hunch run inside roundup, or a model written by a readback; an automatic readback (P9); editing the chart; a text button for any action here; a token, price or usage figure; a motion on a key action (#7675). No test of layout or looks.
