**Machine page** (`Machines` in App Settings): the Settings page that lists the Machines, adds one and removes one. It is not a sidebar, a Rail level or a dispatch panel.

**MC70 App Settings has a Machines page.** Amends MC2 and MC3. Given App Settings (U3799), then its page list holds **Machines**, and the page shows **This Mac** first, then each other Machine herdr-core lists in the order it lists them, and an **Add machine** field. **This Mac** has no action. Each other Machine row holds its name, **Online** or **Offline** (MC74) and **Remove** (MC71), and **Update** only under MC75. The page is quiet: no chart, no capacity figure, no alert. A Machine shows on this page and as a chip or status on an Agent, and nowhere else: no sidebar, no Rail level, no dispatch panel (P16 holds). The user adds a Machine from this page by the field and the owner's Door still adds one by `machine.add` (MC2): `machine.add` is callable by the App as well as a Door, and MC2's "shows no Add-machine dialog" holds, since the field is a page, not a dialog. Tests: `mc70_machines_page_lists_this_mac_first_then_the_others` (by role: the page's first row is This Mac with no button, the next rows are the listed Machines in order, each with **Remove**); `mc70_no_machine_sidebar_rail_level_or_dialog` (by role, with the page open and closed: no sidebar, Rail level, panel or dialog names a Machine); `mc70_machine_add_is_callable_by_the_app_and_a_door` (the method's caller list in `crates/contracts`).

**MC71 Remove forgets the Machine in herdr-core.** Given a Machine row, when the user activates **Remove**, then roundup calls herdr-core's `machine.rm` for that name through a new App method `machine.remove` (the pinned schema has `machine.rm`, MC72), the row leaves the page, and no Agent, Terminal, Project or Spool of roundup is deleted: Agents on it show offline (MC15) and its Spool stays (MC26). The user is asked once to confirm, naming the Machine, because the action cannot be undone from the App; cancelling changes nothing. **This Mac** has no **Remove**, and `machine.remove` of this Mac's name returns a coded error. A refused `machine.rm` keeps the row and shows herdr-core's `hint` inline on it. Tests: `mc71_remove_calls_machine_rm_after_confirm_and_drops_the_row` (against a fake herdr-core: one `machine.rm`, name equal, row gone); `mc71_cancel_removes_nothing` (no call); `mc71_remove_keeps_agents_and_their_projects` (the Agent's row stays, offline); `mc71_this_mac_cannot_be_removed` (no button; the method returns a coded error and calls nothing); `mc71_a_refused_rm_keeps_the_row_with_the_hint`.

**MC72 the schema names every method the page calls.** Given the checked-in schema (MC55), then the pinned version's schema holds `machine.rm`, and the page's Update (MC75) is served by the herdr-core CLI `herdr-core machine update <name>` (0.1.21), which `connect` has no method for. The gap is named here: roundup calls no `machine.update` over `connect` until a schema holds one (policy), and runs the CLI on this Mac, through the user's own ssh and no other path (P15). The implementation bumps the pinned herdr-core and its schema to 0.1.21 and every MC55 check still holds. Tests: `mc72_remove_uses_a_method_in_the_pinned_schema` (the method name `machine.remove` sends appears in the checked-in schema's methods); `mc72_update_runs_the_cli_with_the_machine_name` (a fake `herdr-core` binary on a temp path records `machine update <name>`, and nothing else is run).

**MC73 adding takes an ssh host and fails inline.** Given the **Add machine** field, when the user enters an ssh host and submits, then roundup calls `machine.add` with it (MC2), the field clears and the Machine appears as a row; an empty or whitespace-only entry submits nothing. When the host fails (ssh refused, not found, herdr-core missing, `unsupported_generation`, MC4's causes), then the page shows the coded error's `hint` beside the field, keeps the typed text and adds no row, with no alert, toast or dialog. Tests: `mc73_add_calls_machine_add_and_shows_the_row`; `mc73_empty_entry_submits_nothing`; `mc73_a_failing_host_shows_the_hint_inline_and_keeps_the_text` (by role, with no alert raised and no row added).

**MC74 an unreachable Machine is no Machine for a rule that needs another.** Amends MC33 and MC34, and MC15's status. Given a Machine whose `reachable` is false (MC15), then its row shows **Offline** and keeps **Remove**; a Machine with `reachable` true or absent shows **Online**. A rule worded "only when another Machine exists", "when a Machine is online" or "at least one other Machine" counts only the reachable ones: an unreachable Machine adds no chip to an Agent on this Mac, no choice in the start form's Machine field (MC76), and no pick for MC33; a named but unreachable Machine still fails the start as MC34 says. Today's dead entry `roundup-ci-control` (deleted 2026-11-13) is such a Machine: with it the only other one listed, this Mac's Agents show no Machine chip. Tests: `mc74_unreachable_machine_is_offline_and_removable`; `mc74_an_unreachable_only_machine_leaves_no_chip_on_a_local_agent` (against `createMachines`: one unreachable Machine, `any()` is false); `mc74_a_reachable_machine_brings_the_chip_back`.

**MC75 Update shows only for an older herdr-core.** Given a Machine whose herdr-core `version` (its hello, read when roundup connects) is older than this Mac's, then its row offers **Update**; a Machine at the same or a newer version, or one whose version is unknown, or an offline one, offers none. Activating it runs MC72's CLI for that Machine, shows **Updating…** on the row and disables the action meanwhile; on success the row reads the new version and the action is gone; on failure the row shows the CLI's last line inline and offers **Update** again, with no alert. Tests: `mc75_update_shows_only_when_the_machine_is_older` (older, equal, newer, unknown and offline); `mc75_update_runs_once_and_clears_on_success` (a double activation runs one CLI); `mc75_a_failed_update_shows_the_line_and_offers_it_again`.

**MC76 the start form's machine pick shows only while another Machine is online.** Amends MC34. Given the start form, then its **Machine** field shows only while at least one other Machine is online (MC74); with none, the field is absent and the start is as MC33 says. Adding a reachable Machine from the page (MC73) shows the field without a reload; removing the last one, or every other Machine going offline, hides it and clears any name the user had chosen. Tests: `mc76_the_start_machine_field_needs_an_online_machine` (by role: absent with none, with only an offline one, present with one online); `mc76_a_chosen_machine_clears_when_it_goes_away` (`nameStart` is empty after the removal).

Policy: the page and the start field read the same list as the Rail's Agent chips (`state/machines.ts`), so the three agree. The App reads `machine.list` while the page is open and on the coarse tick, never faster (MC62 holds). The page's visible words are App words; `machine.remove` and `machine.update` join `GLOSSARY.md` with the implementation, by the Contract recipe of `.agents/builder.md`.
