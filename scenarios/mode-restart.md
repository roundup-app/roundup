# Retry a failed Mode Agent restart (A4665)

A user-requested Mode Agent restart can be retried with the same request after the fresh run fails to start. `agent.restartMode` retains A35's prompt reservation and the Agent lifecycle contract; this scenario specifies recovery without adding an automatic launch path.

## Checks on main

1. `crates/rupd/src/restart.rs`, `Daemon::restart_mode`: `agent.restartMode` reserves the Mode prompt before stopping the Agent's run and persists `Starting` before requesting a fresh Agent run.
2. `crates/agents/src/door.rs`, `Agents::restart_mode`: a fresh run waits at most 15 s for its matching `SessionStart`; on timeout it stops that Agent and confirms the Terminal exited before returning a retryable cause. A timeout alone is not proof that cleanup succeeded.
3. `crates/rupd/tests/support/mode_prompt.rs`, `u4547d_restart_uses_the_saved_prompt_and_preserves_contents`: a successful restart retains the Mode Agent and its children, Todos and Pads, types its saved prompt once, and completed-request replay keeps the same Attempt.
4. `crates/rupd/tests/support/mode_prompt.rs`, `a4452c_failed_recording_retries_without_another_physical_write` and `a4452c_unknown_input_outcome_never_retypes_on_retry`: recording retry does not type again, and an uncertain physical write is never replayed.

**A4665 a failed fresh run keeps the request retryable.** Given a root Mode Agent and a user restart request, after its saved prompt is reserved and `Starting` is persisted, make the fresh run fail either before any program starts or because its matching `SessionStart` does not arrive within the existing 15 s bound. Establish that no program from that failed run remains before allowing another launch. When the first call returns, it reports the start failure, no prompt from that attempt has been typed or recorded as delivered, and the same request retains its original reserved text (test: `a4665_failed_start_retries_same_request`).

Given that failed request, when the start failure is removed and the user retries `agent.restartMode` with the identical Mode Agent id and request id, then the call starts one fresh Attempt and completes instead of remaining in an unknown outcome. It requires neither another Restart action nor a new request id. After matching `SessionStart`, the reserved prompt is typed byte for byte once and recorded as one delivered user note. A subsequent replay of the completed request returns the same successful Attempt, starts no program and types or records nothing again.

Observer: extend the existing real-Daemon harness in `crates/rupd/tests/support/mode_prompt.rs`, using its fake vendor and public `agent.restartMode`. Parameterize the test over pre-launch refusal and missing `SessionStart`, each with a whitespace-sensitive multiline Mode prompt. For the timeout case, observe the failed program's termination before the successful retry; missing `SessionStart` must reach the real lifecycle wait and cleanup path, not a fabricated coordinator error. Change the Mode's configured prompt after failure and before retry, then assert that the original reserved bytes, not the new setting, are typed and recorded. Count launches, live programs, Terminal input and delivered prompt notes across failure, successful retry and completed replay; assert at most one live Agent run at every observed launch. Use the existing harness bounds and event observers; no real vendor, browser or new public seam is required. The named test asserts every behavioral then-clause above; existing Checks 3–4 retain their independent proofs.

Policy: only the user's explicit restart authorizes a fresh run (P9); failure never schedules an automatic launch. A persisted `Starting` record alone, a lost reply or a cleanup failure is not evidence that starting another program is safe. Unknown launch liveness remains unknown until authoritative reconciliation establishes no program remains; never reset all `Starting` records to retryable merely on reopen. `Typing` remains fenced as Check 4 requires. Preserve the original reservation until successful release, the root Mode Agent and its user-owned children/Todos/Pads (P6), user-only authority and Message ordering and Attempt guards. M1–M10 remain unchanged; any implementation changing Message contracts names affected laws and keeps `docs/messages.md` and `proofs/messages` agreeing. No automatic retry policy or general crash-recovery scheduler is requested.
