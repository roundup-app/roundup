# UI: the readback names and explains the flows the code found, and adds the flows the code cannot see (U7689a–U7689g)

Module: `apps/desktop/src/changes/` (the flow items' name and account, the added items, the Not traced row's words, the Flows lens's states), the fake App and its fixtures. Ids: U7689a, U7689b, U7689c, U7689d, U7689e, U7689f, U7689g. Work order: [#7689](https://github.com/roundup-app/roundup/issues/7689), blocked by #7688 and #7683 (both merged). Owner, 2026-11-18 and 2026-11-19: "I don't care about file by file I care about flows/paths/modules and mental models"; "Yes, move them earlier - proper tools". Owner, 2026-11-26: "use proper icons I don't like textual actions": every action here is an icon button with no visible text, its tooltip and accessible name from `copy`; a status line stays words. The Issue's three decisions hold as written: review by flows, explanations from a readback and never from the Agent that wrote the code, and call paths built from the code before any readback. No Daemon method, Message or contract change: the App reads `agent.readback` (RB3, RB5), built by #7687 and carried by #7688. A readback is a personal aid, never a gate; its text is never sent to the Agent and the App shows no token, price or usage figure (P14). Reuse (rule 9): #7683's lens, rows and call tree, #7688's readback state and its icon button; no machinery is added, and the PR says so.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

**Words.** The quoted words below are asserted through `copy.ts`, never layout or looks (rule 10). A **readback flow** is a `ReadFlow` of the Account (RB3): `id`, `name`, `source` and `steps`, each step a `note` and the hunk ids that hold it. A hunk id is `<path>#<n>` (GLOSSARY: Hunk id). A flow's **explanation** is its steps' notes in order: `ReadFlow` has no other prose.

**Fixture.** The flow fixture of U7683 on the Tree target, and a fake `agent.readback` whose Account holds: `code-1` named "Run loads the data" (source code, steps over `run.ts#1` and `load.ts#1`), `code-2` named "Other loads it too" (code), `added-1` named "Shout is checked" (source readback, one step over `lib.rs#1`), and `unplaced: ["types.ts#1"]`.

**U7689a a code flow gains the readback's name and explanation, and keeps what the code found.** Given a read or stale readback, then:
- **Name.** A flow's row, and its line in the Overview, show the readback's name for it, and the function's name stays on the row as a quiet second line. Asserted in `u7689a_a_code_flow_gains_the_readbacks_name_and_explanation_and_keeps_what_the_code_found`.
- **Explanation.** The open flow's header shows "Read back from the diff" and its steps' notes in order, above the call tree. Asserted in the same test.
- **Kept.** The flow's entry, call tree, files, hunks and call order are the trace's, whatever hunks the readback's steps list for it, so a readback never moves a hunk out of a flow the code found and never reorders one; a readback that does is refused by the Daemon with a cause (RB3), which the Overview shows as the failure of U7689d. Asserted in the same test, with an Account whose steps list `code-1`'s hunks in another order.
- **Join.** Decided here, since `ReadFlow` carries no entry: `code-N` is the Nth flow of the trace the Daemon read, in the trace's order (RB1), which the App rebuilds as the Nth flow of its finished traces, before the list sorts them by path. The Daemon keeps only the last trace done and skips a flow with no hunk, so the App takes the name only when the files of the hunk ids the readback gives for that id are the files the flow lists; else the flow keeps its function's name and no account. Asserted in `u7689a_a_name_applies_only_when_the_readbacks_hunks_name_the_flows_files`.

**U7689b the readback adds the flows the code cannot see, then Unplaced.** Given a read or stale readback, then:
- **Added.** Each readback flow with source `readback` is an item after the code's flows, in the order the readback gave, its row marked "From the readback", holding the files its hunk ids name, in step order, whole. Decided here, narrowing the Issue's "hunks": a hunk id counts a file's hunks as git does (three lines of context) and the diff reader draws jsdiff's (four), so the App cannot place hunk `n`; only the id's path is sound, and an added item's scroll draws each file whole. A path no listed file has, or a noise file's, is dropped, and a flow left with no file is not listed. Asserted in `u7689b_a_read_adds_flows_the_code_cannot_see_replaces_not_traced_and_ends_with_unplaced`.
- **Not traced.** My reading, kept: a read or stale readback replaces #7683's Not traced item, since the readback places those files: the files of a language with no server, and Rust before Trace (U7683f), sit in the added flows or in Unplaced. A Trace done later leaves the readback as it was (RB7 judges the diff alone); the code's flows follow their own trace state. Asserted in the same test and in `u7689b_rust_files_with_no_trace_are_placed_by_the_readback`.
- **Unplaced.** One item, last of the items, holding the files of the Account's `unplaced` hunk ids in path order and, in each, the hunks no code flow draws (U7683c); it replaces the code-found Unplaced, listed only when an id names a listed file. Asserted in `u7689b_a_read_adds_flows_the_code_cannot_see_replaces_not_traced_and_ends_with_unplaced`.
- **Twice.** My reading, kept: a file that two items hold shows in both and its Viewed mark is the one mark of its `blob` (U7683g); a flow the readback adds may hold a file a code flow holds. Asserted in `u7689e_marking_a_flow_viewed_opens_the_next_unviewed_one_an_added_flow_included_and_a_shared_file_reads_viewed_in_both`.

**U7689c before a readback Not traced says how to see those files.** Given the flow fixture and no readback, then:
- **Words.** On the Tree and Branch targets the Not traced row says "Read back to see them", and its pane holds the same line over an icon button named "Read back changes" that starts the readback (U7688a); R does too. Asserted in `u7689c_not_traced_offers_the_readback_on_tree_and_branch_and_none_on_changes`.
- **Changes.** On the Changes target (U7688a) the row and the pane say nothing of a readback, and no button shows. Asserted in the same test.
- **After.** Once a readback runs, the words and the button leave the row and the pane. Asserted in the same test.

**U7689d reading and failed leave the code's flows as they were; stale dims the readback's words.** Given the fixture, then:
- **Reading.** From the start the Flows lens shows "Reading back…" and the code's flows stay as they were. Asserted in `u7689d_reading_and_failed_leave_the_code_flows_as_they_were_and_retry_reads_again`.
- **Failed.** A failed readback, or one the Daemon refused (RB3), shows "Couldn't read back these changes" with its cause and an icon button named Retry that starts a run; the flows stay as the code found them and gain no name. Asserted in the same test.
- **Stale.** My reading, kept: when the Daemon answers `stale` the names, the explanations, the added flows and Unplaced stay, dimmed, their rows reading "Changed since readback"; the code's flows follow their own trace state (U7683b), never the readback's. Asserted in `u7689d_a_stale_readback_dims_the_names_and_explanations_and_leaves_the_code_flows`.

**U7689e Viewed counts the added flows.** Given a read readback, then "N of M viewed" (U7680a) counts the added flows and Unplaced in M, and the marks on the code's flows stay as U7683g built them; marking a flow opens the next unviewed item of the lens, an added one included, and a file two items hold reads viewed in both. Asserted in `u7689e_marking_a_flow_viewed_opens_the_next_unviewed_one_an_added_flow_included_and_a_shared_file_reads_viewed_in_both`.

**U7689f the readback is a personal aid.** The view sends no Message and saves no note or Pad from a flow's name or explanation, edits none of the text, and gates no Landing or Viewed mark on it. Policy: nothing here carries the readback's words anywhere but the screen.
