# UI: target pickers offer a change (U3515a to U3515d)

Module: `apps/desktop` (the webview). Acceptance for Issue #3515. This specification delivers no implementation. A target picker chooses an existing receiver, Home, owner, blocker or parent for an action, including a submenu, drag destination or keyboard equivalent. Navigation lists, content inspection, creation forms and settings that display the current value are not action target pickers (policy). Audit all existing entry points in this class; the inventory below is a starting set, not permission to leave another picker unchanged (policy).

**U3515a Send to Agent excludes its source across the Project.** Amends U2694c (`scenarios/ui-native-menus.md`). #3529 retires U515’s selection-send path; these receiver rules apply to object links. Given Project A with source Agent `a` in Workstream W1, another Agent `b` in W1, Agent `c` in W2, another Agent at the Project root, and Project B with its own Agent, when the user opens Send to Agent for `a`'s link, then every other receiver in Project A allowed by the existing Message delivery rules is offered once in Rail order, including W2 and root receivers, and neither `a` nor Project B's Agent is offered. Collapsing W2 or selecting W1 does not remove its receivers. Doors count as Agents: a Workstream link excludes its own Door; an Agent’s link excludes that Agent regardless of the selected Rail row. A user-opened shell or Run has no Message receiver as its source, so ownership alone excludes no Agent. A Todo, Pad or published-output link is not its maker's or owner's Agent link and does not exclude that Agent merely for owning or making it. Existing receiver eligibility, link bodies, delivery, draft identity and one-receiver direct-send behavior remain in force (policy).

Tests (planned, Vitest through U11's mounted App seam): `u3515a_send_offers_other_project_receivers_in_rail_order` opens the object-link paths against that fixture, with W2 collapsed and `b` selected; `u3515a_source_identity_follows_the_object_not_selection` covers Door, Agent, shell, Run, Todo, Pad and published-output sources; `u3515a_choosing_another_agent_sends_once` chooses `c` on the link paths and asserts exactly one `message.send` to `c`, with the existing body contract and no Terminal write or Agent start. Extend the existing mounted caller suites rather than proving only a candidate-list helper (policy).

**U3515b no eligible target leaves a disabled action and no submenu.** Supersedes U3812's omission rule only for Send to Agent, and U2694c's self target. Given a Project whose only Agent is source `a`, or whose other Agents cannot receive under the existing delivery rules, when the user opens any Send to Agent entry point for `a`, then its action is present and disabled, has no submenu or receiver list, and pointer activation, Enter, Space and menu keys make no Message, Terminal-write or Agent-start call and open no receiver picker. A native menu entry has `enabled: false` and no `children`; a webview action exposes its disabled state to accessibility. No disabled receiver row substitutes for excluding a target. The same disabled/no-list/no-action rule applies to any target picker after every candidate has been excluded. Filtering a nonempty eligible list down to no text matches is the existing search-empty state, not an exhausted candidate set (policy).

Test: `u3515b_exhausted_target_actions_do_nothing` (planned, mounted App seam) exercises the entry points and keys above with the only-source fixture and with an exited peer, asserting the disabled state, absent submenu/list and zero action calls. For a picker whose commands include a real alternative such as New Workstream, that command remains usable; it is not an existing no-op target and does not justify displaying an excluded owner (policy).

**U3515c every action target changes the selected items.** Given the App's existing target pickers, when opened or reached by their drag/keyboard equivalents, then:

| Action | Excluded targets | Planned mounted App-seam test |
| --- | --- | --- |
| Move a Todo or Pad to a Home, wherever a move action exists | Its current Workstream or current Project root | `u3515c_home_moves_offer_only_other_homes` |
| Assign a Todo or Pad, including owner-group drag and keyboard assignment | Its current owner, compared by Actor identity, including Me and Unassigned where supported | `u3515c_assignment_offers_only_changed_owners` |
| Add a blocker | The Todo itself, an existing blocker, or a Todo that depends on it directly or transitively | `u3515c_blockers_exclude_self_existing_and_transitive_cycles` |
| Nest or reparent by list, drag or keyboard, including Rail moves and Todo nesting | The item itself, any descendant, and a destination that preserves both current parent and order | `u3515c_nesting_excludes_self_descendants_and_unchanged_placement` |
| An existing bulk target action | A target leaving every selected item unchanged, or invalid for any selected item; for an offered target, call the action only for selected items whose value changes | `u3515c_bulk_targets_change_only_selected_items_that_need_it` |

The tests use both excluded candidates and a valid alternative: opening never offers an excluded candidate, trying an excluded drag/key destination makes no mutation call, and choosing the alternative changes exactly the chosen item once through its existing RPC. For nesting, include a grandchild as well as a direct child and allow a sibling reorder that changes order without changing parent. For bulk, use two items already at one destination, then a mixed selection where only one needs the offered change; leave unselected items untouched. Exhaustion follows U3515b. Existing legal destinations and existing confirmation, permission and failure behavior stay in force (policy). This audit fixes existing actions; it does not add a missing Pad Home menu or a new bulk move/assignment feature. Record each absent action as absent on the Issue, not as an unimplemented scenario or a fabricated picker (policy).

**U3515d one App-seam guard covers exhausted target pickers.** Given a mounted App fixture for each existing picker with only its own identity/current value as the raw candidate, when one table-driven test attempts to open each picker through its real UI entry point and keyboard equivalent, then each action is disabled, opens no submenu/list, never lists that candidate and makes no action call. Test: `u3515d_only_self_disables_every_target_picker` (planned, one Vitest test at the App seam, not separate tests of candidate helpers). Its table covers every existing menu/trigger variant discovered in U3515c and the Send callers below, and documents which sole candidate is excluded. The fixture can specialize by picker: the only Agent is the source, the only Home is the current Project root, the only owner is the current owner, and the only Todo is itself. Preserve real creation alternatives and permission rules; when an action has an always-available changing alternative, assert that alternative remains usable and the excluded existing target is absent instead of claiming the entire action is exhausted (policy). Drag/keyboard-only destinations are attempted through their existing path and assert no mutation; no artificial trigger is added for the guard (policy).
