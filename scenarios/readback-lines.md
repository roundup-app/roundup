Decisions this specification takes (the Issue's "My reading" points, each kept and tested unless it says narrowed):
- **One run, one step.** Step one of #7687's run also writes the explanations; no second step, no second call. A diff over RB8's cap fails as before.
- **Shape.** The model gives `{hunk, start, end, text}`: a hunk id, new-side line numbers inside that hunk and one or two sentences. The Daemon keeps `{path, start, end, source, text}`: `path` the hunk's path and `source` the new-side lines `start` to `end` as the hunk holds them, joined by newlines. Narrowed from the Issue: the hunk id does not reach the App (U7689b: the App cannot place hunk `n`; only the path is sound), so the result keeps the path and the lines.
- **Dropped, never refused.** An explanation whose hunk id the input lacks, whose range is not wholly inside that hunk's new side, whose `text` is empty or that comes beyond the twelfth is dropped, as RB4 drops a gap; a missing `explanations` key is none. The aid never fails a paid run. Twelve is the Daemon's cap on "no explanation of every line".
- **Grey is the notes' rule.** An explanation greys when the file's text at its lines no longer reads as `source` (U2540b's older-context rule), not when the file's blob id changes: a write elsewhere in the file leaves it. Narrowed from #7698, whose answers grey on the file's blob id, because here the result holds the source it was written against.
- **Ask again is #7698's ask.** It calls `agent.explain` for that range in `words` and the new answer replaces the explanation under its lines; it then follows U7698c's blob-id rule.
- **Shown by default.** A `read` or `stale` result draws its explanations with no second action: the user's start of the readback (R) was the ask, a toggle adds a control and a state the owner did not ask for, and an explanation draws quietest. The set is small (twelve), so no switch is needed to hide it. Decided here; the Issue left it to the specify run.
- **Stack.** Under one line a note comes first, then a gap, then an explanation; only a note is editable.

**RB16 the result carries explanations the diff holds.** Given a fake `claude` whose step-one answer holds `explanations` for `a.rs#1`, then `agent.readback` answers `explanations` as `[{path: "a.rs", start, end, source, text}]`, `source` the new-side lines of `a.rs` from `start` to `end` joined by newlines. Asserted in `rb16_a_read_run_carries_each_explanation_with_the_lines_it_explains` (Rust, fake `claude`).
- **Dropped.** An entry whose hunk id is in no hunk of the input, whose range runs outside that hunk's new side, or whose text is empty is dropped and the run stays read; an answer with no `explanations` key reads with none. Asserted in `rb16_an_explanation_the_diff_does_not_hold_is_dropped`.
- **Capped.** Of fifteen valid entries the first twelve are kept. Asserted in `rb16_at_most_twelve_explanations_are_kept`.

**RB17 the explanations follow the result's rules.** A write that changes the diff makes the result `stale` with its explanations kept (RB7); a start replaces them, a restart drops them (RB12); reading them launches the fake `claude` zero times (RB2). Asserted in `rb17_explanations_stay_with_a_stale_result_and_start_no_call`.
