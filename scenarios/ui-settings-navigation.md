# UI: Settings page navigation and rows

Acceptance for #4686. This specification delivers no implementation. Scope (policy): `apps/desktop/src/settings/`, the shared `ui/Tabs.tsx` and `ui/Tabs.css` wrapper, and `apps/desktop/src/copy/settings.ts` for category, Back and hint labels. Keep existing App seams, settings, persistence and Tokens; no new RPC, command, preference, Token or motion. Project settings and other Tabs consumers retain their behavior (policy).

**U4686a Settings pages form one categorised left list.** Given App Settings opened through its existing menu event or `⌘,`, with or without a Project, when the user activates each page, then exactly one associated tabpanel is exposed, containing that page's existing controls. Keep Agents, Terminal, Shortcuts and Appearance in their existing order. Extend `u4277a_sections_work_by_pointer_and_keyboard_project_%s` in `apps/desktop/src/settings/u3799_app_settings.test.tsx`; do not add another proof of page selection.

Policy: the left navigation spans the Settings view's available height, beside a single content column. Its small category headings group Agents under Agents, Terminal under Terminal, and Shortcuts and Appearance under General, in that order. Headings are not page controls or tab stops. This groups only existing settings; no additional pages are requested. The active page has one vertical accent bar using existing Tokens, with space reserved so selection moves no text. Labels, headings, list placement, bar and full-height layout are design-critic observations, not exact-copy or geometry assertions in UI tests.

**U4686b Back returns to the preceding view.** Given Settings opened from a focused element in the preceding center, when the user activates Back, then Settings closes, that center returns and focus returns to that element. Reopening preserves existing saved values and exact unfinished font-field text without applying it. Retarget `u3800_close_returns_the_center_and_focus` to Back and retain its Escape path; extend `u3806_unsubmitted_fields_survive_close_and_reload_without_applying` in `apps/desktop/src/settings/u3806_preferences.test.tsx` to close through Back. Preserve Escape ownership: a child picker or shortcut recorder handles its own Escape before the Settings view closes (policy).

Policy: `← Back` replaces App Settings' header Close action and sits at the top left of the navigation, above the Settings title and category list. Back uses the existing close action, without opening another window or dialog. Shared-shell changes preserve Project settings' existing close/focus behavior. Placement and visible label are critic observations.

**U4686c Arrow keys select pages through the list.** Given focus on a page in the left list, when the user presses ArrowDown or ArrowUp, then focus and selection move together to the next or previous page, crossing category boundaries and exposing the associated panel without Enter. Category headings are skipped. When the user presses Tab from the selected page, then focus reaches that page's controls. Extend `u4277a_sections_work_by_pointer_and_keyboard_project_%s` for both directions across each category boundary and keep its pointer and panel-association assertions. Verify the real Tab path in the existing `u4277a_u4277b_u4277c_requested_screens_dark` browser observer in `apps/desktop/src/settings/u4277_rendered.test.ts` rather than simulating browser Tab traversal in jsdom.

Policy: keep installed `@ark-ui/solid` vertical Tabs through `ui/Tabs`, with automatic activation, roving focus and its boundary behavior. Arrows belong to the focused list, not an App-wide handler; fields, pickers and the shortcut recorder retain their own keys. No replacement navigation state machine. Read installed capabilities and satisfy rule 9 before adding machinery.

**U4686d Each setting has a labelled, described control.** Given any selected page, then every existing setting control has an accessible label and an associated hint describing its effect or default. Observer: planned `u4686d_controls_have_labels_and_descriptions` at the mounted App seam in `apps/desktop/src/settings/`, covering permission mode, engine/model when a Project is open, font family/size, quick-add recorder and appearance mode. Assert label and description association, not exact wording or appearance. This test proves only the new accessible descriptions; existing observers continue to prove control behavior (policy).

Policy: each page presents its settings in visibly titled sections. Each setting row places the label and a one-line hint on the left and its existing control on the right; the shortcut recorder and its applicable Reset share their setting row. Hints describe the setting and form part of its label/description, not unrelated explanatory prose. Section titles describe the contained settings; no empty section or invented setting. Labels, hints and controls fit within `--measure` and the available center width without horizontal scrolling, overlap or clipping. Existing refusal and recovery messages remain fully visible below their related control or group, rather than being truncated to the hint's one line. Visual structure is critic policy.

**U5243a Search lists each matching setting with its place, control and description.** Given App Settings with a search field above the page list, when the user types a query, then the page list is replaced by one result per matching setting, ranked best first by `fuzzysort` over the setting's label, description and page and group names, each result showing its place as `<page> › <group>` (for example `Terminal › Font`), the setting's own live control, and its description; an empty query restores the page list and the selected page. A query matching nothing shows one empty-state line and no control. Test: planned `u5243a_search_results_show_place_control_and_description` at the mounted App seam in `apps/desktop/src/settings/`, asserting a result's place text, that it contains one control with the label and description association of U4686d, and the empty-query restore; not ranking order beyond the best match first, nor appearance (policy).

**U5243b A result's control changes the setting like the page's control.** Given a search result, when the user changes its control (types a font size, picks a mode, records a chord), then the same save, refusal, draft retention and Terminal effect happen as through the page's control, and clearing the query shows the page's control holding the same value. Each setting has one live control at a time: a result mounts the setting's control rather than a copy of its state (policy). Test: planned `u5243b_a_result_control_edits_the_same_setting` in `apps/desktop/src/settings/`, extending the `u3806_` persistence and `u3804_` refusal observers through a result rather than repeating them.

**U5243c Typing in search moves nothing outside the results.** Given focus in the search field, when the user types, presses Backspace or clears it, then focus stays in the field, the selected page, Project, Terminals and any unfinished field text are unchanged, no setting is applied, and ArrowDown moves focus into the first result's control without selecting a page; Escape clears a non-empty query before it closes Settings (U4686b). The field turns spellcheck, autocorrect and autocapitalize off (U3787d X4). Test: planned `u5243c_search_typing_changes_nothing_but_the_results` in `apps/desktop/src/settings/`, asserting the selected tab, an unsubmitted font draft, the field's three attributes and Escape order. U4686a–d keep their observers unchanged.

Policy: scope is `apps/desktop/src/settings/AppSettings.tsx`, `SettingsShell.tsx` and `copy.ts`; reuse the installed `fuzzysort` and the existing `ui/` field primitive; no new RPC, command, preference or Token. Group names come from the page headings U5242a exposes. Result layout is the design critic's (`just capture U5243a`, 1512×950, dark; Moves D2, D5, D6).
