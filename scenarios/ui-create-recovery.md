# UI: keep failed Agent starts actionable

Acceptance for #5629, extending U5217/U5555 in `scenarios/ui-create-keys.md`. Journey stages: Enter and Intervene (`.agents/data/journey.md`, “What must work”). Implementation follows #5555's Create menu; this specification changes no product code.

**U5629 opening Create preserves a failed Agent start.** Given an open Project, starting available and no prompt field open, when `⌘N` makes one `agent.spawn` call that rejects with `Spawn refused. Check setup and retry.`, then the Rail exposes that cause and its Retry action. From this state:

- Opening Create by pointer, or by focusing its button and pressing Enter or Space, keeps the same cause and recovery action available; it makes no additional `agent.spawn`, `rail.createWorkstream` or `rail.startDoor` call and opens no Mode dialog. Pressing Escape without choosing closes only the menu, returns focus to Create and leaves the same failure and Retry reachable. Selection remains the original Workstream. Test: `u5629_open_and_escape_keep_the_failed_start`, parameterized over the three opening methods in `apps/desktop/src/rail/u5217_create_keys.test.tsx` through its connected App/fake RPC fixture. Assert the initial failure and every subsequent endpoint in this test, rather than adding another initial-error-only test.
- After that open/Escape sequence, activating Retry once makes exactly one further `agent.spawn` call with the original Project, prompt, Model and Effort arguments and `parent: null`. No Workstream is created or Door started. On acknowledged success the returned Agent is selected and that failure and Retry disappear. Test: `u5629_retry_after_escape_repeats_only_the_failed_start` in the same test file, comparing the two recorded spawn arguments rather than copying defaults.
- Alternatively, after that open/Escape sequence, activating the failure's Dismiss removes its feedback and Retry without making any creation/start call or changing the selected Workstream. Test: `u5629_dismiss_after_escape_clears_only_feedback` in the same test file. Dismiss does not discard retained input or draft revisions (policy: existing P11 recovery rules remain).

Policy — boundaries: opening or cancelling a menu does not acknowledge a failed start. Keep existing explicit Dismiss and successful-retry behavior. Do not broaden other command-error lifetimes, change creation choices/chords/guards, or add an RPC, App seam command, Token or glossary term. Selecting a creation choice retains U5217's existing action semantics; it is outside this scenario's no-choice path. Reuse the shared Ark Menu, Rail failure/retry state and existing test fixtures; no new menu or recovery state machine is required. Any added machinery still follows AGENTS.md rule 9.

Policy — Principles and observers: P9 asks whether opening/cancelling spends an unrequested turn; the no-start call assertions answer no. P11 asks whether routine navigation loses unfinished work or recovery for its original Project/object; the preserved failure and original-argument Retry assertions, with existing draft observers, answer no for this changed path. This is the Enter-stage failed-start recovery and Intervene-stage actionable-error check, not a full-journey completion claim.

Policy — rendered observer: implementation uses an isolated headless U26 browser session and fresh profile at 1512×950, dark only, on dense `tree-40`. Select a Workstream, reject the next `agent.spawn` with the named cause, and record failure → Create open → Escape → Retry success; repeat from a fresh failure for Dismiss and for keyboard menu opening. Wait on menu roles, failure feedback and acknowledged calls, never fixed sleeps. The full cause and recovery controls stay readable; the critic judges stacking, occlusion, focus and targets. Moves D2, D5, D6; every Check passing on the paired main baseline remains passing. Run `just capture U5629`; leave paired base/head screenshots, interaction video and Check readings under `artifacts/ux/U5629/` per `.agents/data/harness.md`, “Captures”; never commit images or videos. No capture is required for this specification-only PR. Chromium observes the webview; the user reports what they meet on the Mac.

**U7129 retry resends the failed revision.** Narrows U2773b. Given revision A sent from the Rail's prompt field and refused, and newer text B typed in the composer before Retry, when the user activates Retry on the failure line, then exactly one further send carries A's prompt and destination, never B. B stays the current draft in the composer and remains separately recoverable (U2773b), and A's revision is consumed only by its own acknowledged send. Test: `u7129_retry_resends_the_failed_revision_not_the_newer_draft` in `apps/desktop/src/rail/u2773_drafts.test.tsx` through its connected Rail fixture, run for a new-Agent prompt and for a note to a Door, comparing the recorded arguments of the two sends and asserting the composer still holds B. No RPC method, App seam command, Token or glossary term changes.
