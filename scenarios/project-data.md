# Project data

Module: `crates/rupd` (the data folder, the move), with `crates/agents`, `crates/todos`, `crates/pads`, `crates/messages` and `crates/provenance` opening their files where `rupd` says, `crates/desktop` passing the folder, and end-to-end tests in `crates/rup/tests`. Terms: Project, Worktree, Agent (`GLOSSARY.md`; this file adds Project data). Principles served: P5 (`PRINCIPLES.md`). Design: `docs/architecture.md` (Data), ADR 0004, `docs/worktrees.md`. Tests use `rupd` as a real process, a fake `claude` (`ROUNDUP_CLAUDE_BIN`, A4), a temporary Project folder and a temporary data folder, and a real `git` for the git cases. Contract change (rule 4): the App's start of a Daemon passes the data folder in the environment (`ROUNDUP_DATA_DIR`) and `crates/desktop` is the one caller; no RPC method changes. Ids: N1–N4.

**N1 the data folder.** Given a Project folder, when a Daemon opens it, then the Project's databases (`agents.db`, `todos.db`, `pads.db`, `messages.db`, `provenance.db`, `digest.db` and every other module file, each with its `-wal` and `-shm`), each Agent's launch files (A4, A11, E1, F4: `agents/<id>.settings.json`, `.mcp.json`, `.brief.md` and `.bin/`) and Pad files (P5) live in `<data>/projects/<key>/`, never under the Project folder. They are readable by any process of the user and hold no secret (the Daemon knows an Agent by its process ancestry, not by a file). `<data>` is `ROUNDUP_DATA_DIR` when set, else the App's data folder for `dev.roundup.app` (`~/Library/Application Support/dev.roundup.app/` on macOS, the same folder `crates/desktop/src/store.rs` uses), so `rupd <project>` started without the App keeps its state there too. The App sets `ROUNDUP_DATA_DIR` to its own `app_data_dir`. `<key>` is the Project's canonical path (symlinks resolved) as `<folder name>-<first 16 hex digits of the SHA-256 of that path>`: the same folder reached by two paths has one key, and two folders with one name have two. A4's trust rule is unchanged (the working directory must lie inside the Project folder; settings, MCP and Brief files are named by flags and need no trust), and A13 reads "the `agents` folder under the Project's data folder". `~/.roundup/rupd.sock` (`RUPD_SOCKET` unset) stays where it is: it is in the home folder, never in a Project folder, so no Project shows it. Tests (`n1_`): open a Project and read each path above under the data folder; two paths to one folder give one key; a Daemon with `ROUNDUP_DATA_DIR` unset and `HOME` set to a temporary folder writes under that folder's `dev.roundup.app` data path and nowhere in the Project.

**N2 a Project folder is left as it was.** Given a Project folder with its recursive file list (hidden files included) and, for a git Project, `git status --porcelain`, when a real Daemon opens it with Worktrees off, spawns an Agent, starts a Door (A7) and writes a Todo and a Pad, then the folder's recursive file list equals the list before open and `git status --porcelain` is empty; a folder that is not a git repository gets no `.roundup/` either. With Worktrees on (G1), the only new paths outside `.git/` are `.roundup/worktrees/agent-<id>/`, one per Agent with a Worktree, and `git status --porcelain` is empty because G2 still adds `.roundup/` to `.git/info/exclude`. `.roundup/` appears only when G2 makes a Worktree, and holds only `worktrees/`. Tests (`n2_`): the three cases above, each through the built `rupd` and `rup`, and a fresh repository with no global excludes file for the git cases. Narrows G2, A13 and A18: A18's "`.roundup/agents` holds no file that was not there before" reads the Project's data folder.

**N3 retired.** N5467b (`scenarios/local-data-retirement.md`, #5467) removes import/movement of old `.roundup/` application data. Refuse that old storage visibly and preserve it, Worktrees and unrelated files; N1/N2/N4 still govern current placement and Project isolation.

**N4 a moved Project.** Given a Project whose folder the user then moves or renames, when a Daemon opens it at the new path, then the new path has a new key (N1) and the Project opens empty: roundup does not guess that two folders are one Project, and it writes nothing to the folder to remember it. The old key's folder in the data folder is left untouched, so moving the folder back restores the Project whole. Tests (`n4_`): write a Todo, rename the folder, open it and read `todo.list` empty, rename it back and read the Todo.
