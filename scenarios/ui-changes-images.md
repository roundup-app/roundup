# UI: a changed image shows its old and new versions, with the size change (U7694a–U7694c)

Module: `crates/contracts`, `crates/agents` (the read), `crates/rupd` and `contracts/generated/` (U7694a); `apps/desktop/src/changes/` and the fake App (U7694b, U7694c). Ids: U7694a, U7694b, U7694c. Work order: [#7694](https://github.com/roundup-app/roundup/issues/7694), blocked by #7675. Owner, 2026-11-18, picked "Images before and after" from the Plannotator audit: today a changed image shows #7675's binary notice and nothing to look at, and Agents change screenshots and assets. Decided: a changed image shows its old and new versions one above the other, with a note on the size change.

Contract change (rule 4): `FileContent` (`scenarios/ui-diff-notes.md`, "File comparison") gains an `Image` kind, `{ revision, mime, size, data }`: `mime` is `image/png`, `image/jpeg`, `image/gif` or `image/webp`, `size` the side's bytes, `data` the exact bytes in base64, left out when `size` is over the limit, and `revision` the SHA-256 of the bytes as for the other kinds. No new method: `agent.compareFile` stays the one read of a file's bytes (`u7672a_compare_file_keeps_its_limit_and_takes_no_endpoint`). `contracts/generated/` is regenerated, never hand-edited; every caller of `FileContent` changes in the implementation PR: the fake App, its fixtures, and the stored-note schema in `apps/desktop/src/changes/notes.ts`, which accepts the `image` kind and never stores its `data` (a draft holds no picture bytes: P11, and the 10 MiB retention limit). `GLOSSARY.md`'s File comparison row already names `FileContent`. Observer: Rust tests on Linux against temporary git repositories for U7694a; Vitest against the fake App for U7694b; the isolated Chromium harness (U26) for U7694c. Never a native Mac capture. Size: about 700 changed lines (Contract and Daemon 250, App 200, tests 250).

Reuse (rule 9): the platform first for display: a `Blob` URL and an `<img>`, no library, and the webview gives the pixel size once the image decodes (`naturalWidth`, `naturalHeight`), so no crate reads dimensions. For the format, selected: `imagesize` 0.15.0 (MIT, 2026-07-09, <https://crates.io/crates/imagesize>), whose `image_type(&[u8])` names PNG, JPEG, GIF and WebP from a header and answers the one question asked. Rejected: `infer` 0.22.0 (MIT, 2026-07-15, <https://crates.io/crates/infer>), a matcher for every file type, archives, fonts and documents included, where the Daemon needs four image signatures, and a Daemon held under C9b's 15 MB (`scenarios/perf.md`) carries the whole table; it is no `rupd` dependency today (Tauri's crates pull it into the desktop build only). Base64 is the workspace's `base64`, already in `crates/rupd`. Versions and dates read from crates.io on 2026-11-20; verify them again in the implementing PR, which measures C9b and rule 7 (`docs/perf.md`) with a response of two 4 MiB images.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

**Words.** "Old" and "New" label the two versions (U2540b's side words). The size note is `sizeText`'s (`apps/desktop/src/resources/format.ts`, U408) file sizes and the decoded pixel sizes, "800×600 → 1200×900 · 42.0 KB → 88.0 KB". A test asserts the words through `copy.ts`, never layout or looks (rule 10).

**U7694a `agent.compareFile` returns a changed image's bytes.** Given a temporary git repository and an Agent's Worktree (U2540a), then:
- **Both versions.** A PNG changed in the Worktree answers `Image` on both sides, each with its `mime`, `size`, `revision` and `data`; a PNG of exactly 4 MiB on each side arrives whole through the Daemon's socket, about 11 MiB of base64. Asserted in `u7694a_a_changed_png_returns_both_versions_bytes_and_sizes`.
- **One side.** An added image has `Absent` on the old side and a deleted image on the new side (U2540a). Asserted in `u7694a_an_added_or_deleted_image_has_an_absent_side`.
- **Over the limit.** A side over 4 MiB that is an image answers `Image` with its `size` and no `data`, while the read fits the runner's 16 MiB output budget; beyond that budget the read fails with that cause, as U2540a's oversized files do. Asserted in `u7694a_a_side_over_the_limit_returns_its_size_without_bytes`.
- **Content decides.** An image is non-text bytes that begin with a PNG, JPEG, GIF or WebP signature, never a file name: a text file named `.png` stays `Text`, other binary files (an archive, a `.heic`) stay `Binary`, and an SVG is text and stays `Text`, so it shows as the text diff it is today, with its line notes; a live SVG is never drawn. Asserted in `u7694a_content_decides_and_text_svg_and_other_binary_stay_what_they_were`.
- **Kept.** The 4 MiB limit, the refusals of absolute paths, traversal, administrative paths, symlinks and special files, and the read-only rule (U2540a) hold; a text comparison carries no image bytes. Kept: `u2540a_refuses_paths_outside_the_worktree` and `u2540a_read_changes_nothing`.

**U7694b the pane shows a changed image's two versions.** Given the open view and the fake App's `agent.compareFile`, then:
- **Changed.** A changed image shows its old version above its new, labelled "Old" and "New", and beneath them the size change. Equal halves collapse: equal pixel sizes show once, and the note shows file sizes alone until both pictures decode. Asserted in `u7694b_a_changed_image_shows_old_above_new_with_the_size_change`.
- **Added or deleted.** An added image shows one picture, "New", and a deleted image one, "Old", each with its sizes. Asserted in `u7694b_an_added_or_deleted_image_shows_one_picture`.
- **Renamed or mode only.** An image whose two sides carry the same `revision` shows what U7675b shows for a rename or a mode-only change and no picture; one renamed and changed shows both versions. Asserted in `u7694b_a_renamed_or_mode_only_image_shows_what_7675_shows`.
- **Over the limit.** An image side over the limit shows U7675b's too-large words, without Show anyway, and both byte sizes, "Old 5.2 MB → New 6.1 MB". Asserted in `u7694b_over_the_limit_says_too_large_and_gives_both_sizes`.
- **Does not decode.** A picture the webview cannot decode says "Couldn't show this image" with its file size, and the other version still shows. Asserted in `u7694b_a_picture_that_does_not_decode_says_so`.
- **No line note.** An image offers no gutter +, and N does nothing on it (U7676b); a note on an image is #7691's note on a file, built after. Asserted in `u7694b_an_image_offers_no_line_note`.
- **Lifetime.** The pictures come from `data` through `Blob` URLs that the pane revokes when it leaves the file and when the view closes; opening a text file creates none. Asserted in `u7694b_leaving_the_image_revokes_its_urls_and_a_text_file_creates_none`.
- **Kept.** An image changed on disk offers Reload and never reloads by itself, like any file (`u7675b_a_file_changed_on_disk_offers_reload_and_never_reloads_itself`); the reader library loads only on demand (U2540d), and an image needs none.

**U7694c the rendered images at 1512 by 950.** Given the U26 harness, dark App, then old above new, an added image, an image over the limit and a 4,000 px image draw, the last fitting the pane's width with no sideways scroll, and D2, D5, D6 and every Check passing on `main` still pass. Run `just capture U7694c`; evidence under `artifacts/ux/U7694c/`, uncommitted. Policy; the design critic judges layout and looks, never a Vitest test (rule 10).

**Amended.** U2540a's "File comparison" ("Text is UTF-8 without NUL; other bytes are binary"): non-text bytes that begin as a PNG, JPEG, GIF or WebP are an image carrying its bytes (`u2540a_nontext_empty_and_failed_reads_remain_navigable` keeps its binary proof for other bytes). U7675b's Binary and mode-only clause: a binary file that is not such an image says it is binary; its Too-large clause: an image over the limit also gives both byte sizes. #7672's and #7673's "one bytes read": it stays one read, no second method. The Issue names U2539a's text-only read; U2539a has no such clause, and the read's text-only wording is U2540a's "File comparison", amended here. Kept: the 4 MiB limit, #7675's other file states, notes and their recovery (U2540b).

Not wanted: a pixel diff, a swipe slider, a blended view, zoom or crop, side-by-side, image editing, a live SVG; a new Daemon method; Plannotator (plannotator.ai) as the review surface, rejected by the owner, 2026-11-18. No test of layout or looks.
