# UI: Terminal tabs at the centre's bottom

Policy amendment — U4313a below keeps the Terminal bar mounted even with zero Terminals and moves the Rail’s New Terminal action to the bar, replacing U4274c’s Rail entry and nonempty-Project mounting condition. U4313b below restores the approved frame geometry. U4274c (`scenarios/ui-navigation-always.md`) restores the Place and stable height bar without a navigation request whenever the open Project has a Terminal, including a minimised or exited Terminal; tab eligibility still follows U469/U524. The shared bar/portal host and Terminal lifetimes stay stable. U2539b still keeps routine Resource values inside requested inspection. All tab actions, selection/ownership, keyboard access and failure recovery remain required. U524 (`scenarios/ui-terminal-open-root.md`) supersedes Open and missing selection's refusal: New Terminal opens at the Project root too. These amendments replace only the contradicted mounting and no-selection assertions (policy).

Direction: #1499, including the user's choice of bottom tabs and of a message when no Workstream is selected; Resource placement continues #1203.

Policy: this scenario supersedes U164's chip dock and simultaneous visible Bubbles, U165's silent no-selection opening and cycling through chips, U421's restoration alongside other Bubbles, and U444's separate Resource strip line. Their other clauses remain acceptance, including Run ownership, transparency, geometry, snapshots, Terminal lifetime, chord guards, Pull gestures and resource sampling. **U469 bottom tabs control one Bubble at a time.** Given an open Project, then:

- **Place and stable height.** One bar is the centre stack's last line, below the Terminal pane, with the same side alignment as U444. Its left holds Terminal tabs and a trailing `+`; its right holds U444's Resource strip, showing only the selected running Agent's values, with no Project label or totals (#1963); with any other selection its resource region is empty. No chip dock or second resource line remains. Asserted by `u469_the_bar_is_the_last_line_and_no_dock_remains`.
- **Which tabs.** Every Terminal eligible under U164's selection rule has exactly one tab, whether its Bubble is shown or minimised, in U165's start order: the Workstream's Terminals when that Workstream or a row under it is selected, plus the selected Agent's Runs. An Agent's own pane, an ownerless Terminal and another Agent's Runs are not tabs. Each tab shows the same name and unseen-output dot (U3704) as U164's chip, plus `×`; an exit changes no mark and preserves its tab and readable last screen. Selecting another Workstream replaces the tabs with that Workstream's eligible Terminals and never closes the previous ones. Asserted by `u469_tabs_include_shown_and_minimised_terminals_in_start_order`, `u469_selection_swaps_workstream_tabs_and_only_the_selected_agents_runs`, and `u469_exit_updates_the_tab_and_keeps_the_last_screen`.
- **Show and minimise.** Activating a minimised Terminal's tab shows its Bubble at its saved place and size, focuses its emulator, and minimises any Bubble previously shown. Activating the shown Terminal's tab minimises it and leaves focus on that tab. The shown tab alone has `aria-pressed="true"`; every other tab has `aria-pressed="false"`. The Bubble's own Minimise uses the same state and keeps its tab. Minimising sends no close or kill call. At most one eligible Bubble is visible after every opening, restore, cycle, Pull, selection change or reload. Selection away and back preserves geometry and the remembered shown Terminal when still eligible; invalid saved states with several unminimised Bubbles resolve to the latest-started eligible one. A new Run adds its tab without moving selection or focus; it starts minimised if another Bubble is already shown, otherwise shows unfocused as U164 requires. Asserted by `u469_tabs_show_one_bubble_and_toggle_the_shown_one_off`, `u469_minimise_keeps_the_terminal_running_and_its_saved_geometry`, `u469_selection_and_reload_restore_at_most_one_bubble`, and `u469_a_new_run_keeps_selection_focus_and_the_existing_shown_bubble`.
- **Close.** Activating a tab's `×` uses the Bubble's existing Close path: one `terminal.close {id}` for that Terminal, even if running or minimised. It does not activate the adjacent tab or restore that Bubble, and duplicate activations while the close is pending make no second call. Success removes that Terminal's tab and Bubble; failure retains both states and shows the existing failure message. Closing the shown Bubble leaves the others minimised. When the closed control held focus, focus returns to the next remaining tab in start order, else the previous tab, else `+`; a failure keeps focus on the retained control. Asserted by `u469_tab_close_calls_once_without_toggling_or_restoring`, `u469_failed_close_keeps_the_tab_bubble_and_visible_failure`, and `u469_close_returns_focus_to_a_remaining_control`.
- **Open and missing selection.** The trailing `+`, named `New Terminal`, follows the same opening path as `⌘T`: one `terminal.open` for the resolved Workstream, with the returned Bubble shown and focused and the previous one minimised. U165's in-flight, chord and Daemon-exit guards and failure behavior remain. With an open Project but no selection resolving to a Workstream (including an empty Project), either activation makes no `terminal.open` call and shows exactly `Select a Workstream first` as an accessible status without moving focus. The `+` stays present when there are no tabs. A successful open or selection of a Workstream clears that message. Asserted by `u469_plus_and_cmd_t_share_one_opening_path_and_show_the_new_bubble`, `u469_plus_and_cmd_t_without_a_workstream_show_the_selection_message`, and `u469_open_guards_and_failures_preserve_the_existing_bubble`.

Other emulator keys and Help remain U165's. U421's Pull selects its existing last-focused/latest-started target, or opens one if needed, restores only that Bubble and minimises the previously shown one, leaving all tabs present.
