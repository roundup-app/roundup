# UI: turns in a shell Terminal (X15, U514)

Module: `crates/terminal` (X15) and `apps/desktop` (the webview; U514). Ids: X15, U514. #3529 retires U515/U516 selection sending; shell marks and command selection remain.

Scope (policy): the shell a user opens (`terminal.open`, X12) and the Quick Terminal (`scenarios/quick-terminal.md`). An Agent's or a Door's Claude Code Terminal gets no integration and no turns, because it is not a shell. Plain text selection stays as U101 and U110 say; nothing here changes them. `GLOSSARY.md` gains **Shell mark** (OSC 133 and OSC 7 sequences from the shell), **Turn** (code term; user label "command") in the implementing PR (Contract recipe, rule 4). The existing **Block** (a Checkpoint part) is a different thing, so no code name uses it for a Turn. The only Daemon change is X15's environment; there is no new RPC method, nothing under `contracts/` and no new App seam command.

**X15 a shell the user opens emits shell marks.** Given `terminal.open` (X12) starting `$SHELL -l` whose basename is `zsh`, `bash` or `fish`, then the Daemon adds the integration before the shell reads its first line and the user's own startup files still run:

- **Injection.** zsh starts with `ZDOTDIR` pointing at a Daemon-written folder whose startup files source the user's own (`$ROUNDUP_USER_ZDOTDIR`, else `$HOME`) and then the integration; bash starts with `--rcfile` naming a Daemon-written file that sources `/etc/profile`, the first of `~/.bash_profile`, `~/.bash_login`, `~/.profile`, then the integration; fish gets the integration as a `vendor_conf.d` file through `XDG_DATA_DIRS`. The files live in the Project's data folder under `shell-integration`, mode `0700`, rewritten at each `terminal.open`. Policy chosen by this spec: environment injection only, so no file of the user's is edited. The integration scripts are adapted from the open-source ones the research below finds (VS Code, kitty, WezTerm, Ghostty), with their licences kept; the implementing PR's `Reuse:` section (rule 9) names the candidates, links and release evidence before any script is written. Asserted in `x15_zsh_bash_and_fish_get_the_integration_and_keep_the_users_startup_files` in `crates/terminal/tests/`; a shell absent from the runner makes its case print `skipped: <shell> not installed` and the PR names the shells that ran.
- **The marks.** After injection a prompt prints `OSC 133;A` before the prompt, `OSC 133;B` after it (where typing starts), `OSC 133;C` when the command starts running and `OSC 133;D;<exit code>` when it ends, and `OSC 7;file://<host><path>` after each prompt, all terminated by `BEL` or `ST`. Policy: those are the sequences iTerm2, VS Code and WezTerm read, so a Turn's edges are the same bytes those programs mark. Asserted in `x15_a_command_prints_the_four_marks_with_its_exit_code_and_the_directory`, running `true` and `false` and `cd` in a real shell and reading `terminal.read` (X13) output with the marks present in the raw log (the log keeps raw bytes, X13 clause 1).
- **Nothing else changes.** The shell's visible output, `terminal.title` (X4) and the screen are the same as without the marks, and a shell that is not `zsh`, `bash` or `fish`, a command given to `terminal.spawn` and an Agent's Terminal get no environment change and print no mark. A nested shell or `ssh` that does not print the marks gives no Turn (U514). Asserted in `x15_other_shells_and_spawned_programs_get_no_injection`.
- **Observer.** Rust tests in `crates/terminal/tests/` against real shells, `just check`, and the real-Daemon run (the U144 harness) opening a Terminal and reading `echo hi`'s marks back.

**U514 each command in a shell Terminal is a Turn the user selects from its gutter.** Given a shell Terminal of X15 whose output has the marks, with the real xterm emulator (`apps/desktop/src/terminal/emulator.ts`), then:

1. **Turns come from the marks.** The emulator registers xterm's OSC handlers (`parser.registerOscHandler` for 133 and 7, with markers and decorations from xterm.js itself; the implementing PR's `Reuse:` section considers xterm's shell-integration code in VS Code and the `@xterm` addons before writing a parser) and keeps one Turn per `A`…`D` span: prompt line, command, output, the exit code of `D`, the directory of the last `OSC 7` before `C`, as rows by marker so scrollback, resize and reflow keep them. A Turn still running (no `D`) is a Turn with no exit code. The Turns of the scrollback that xterm drops are dropped with it. Asserted in `u514_a_turn_spans_its_prompt_command_and_output` and `u514_a_turn_keeps_its_rows_through_resize_and_scrollback`.
2. **The gutter.** Each Turn shows a gutter at its left edge, one narrow strip (`Token` colour only, rule 8) covering the Turn's rows, and a hover tint on the whole Turn. The gutter is a `button`-role strip with the `aria-label` `Select command`. Asserted in `u514_browser_the_gutters_select_turns`.
3. **Click selects, Shift-click extends.** A click on a Turn's gutter selects that Turn's rows (prompt, command and output) with xterm's selection, so `⌘C` copies exactly that text (U101). Shift-click on another Turn's gutter selects from the first selected Turn through the clicked one, in order. A click inside the text, or on a Turn's gutter while text is dragged, does what U101 and U110 say. Asserted in `u514_a_gutter_click_selects_the_whole_turn`, `u514_shift_click_extends_over_the_turns_between` and `u514_the_copied_text_is_the_turns_text`.
4. **No marks, no gutter.** A Terminal whose output holds no mark (a shell of another kind, `ssh`, an Agent's Terminal) shows no gutter and offers no Turn selection, and drag selection, `⌘C` and U110 work as before. A Terminal whose marks stop (a nested `ssh` begun after Turns) keeps its earlier Turns and makes no Turn of the unmarked output. Asserted in `u514_a_terminal_without_marks_has_no_gutter_and_plain_selection_works` and `u514_unmarked_output_after_marks_is_no_turn`.
5. **Look.** The gutter follows #2173's native look (no box, no border on hover, only the tint of U170) and uses only Tokens; dark, D2, D5 and D6 at the scenario's viewport. Policy: no motion (`docs/motion.md` has no row). Observer: the Chromium run of `apps/desktop/src/terminal/u514_browser.test.ts` against the harness, with the densest seed (40 Turns, a 5 000-line output and a 200-column line); the shell leg is Vitest against the real emulator.
