# UI: select a command turn in a Terminal and send it to an Agent (X15, U511, U512, U513)

Module: `crates/agents` (X15), `apps/desktop` (U511 to U513). Ids: X15, U511, U512, U513. Found by the user's request #2178: a Terminal's command turns should be selectable, and a selection should reach a running Agent so the user can share what a shell printed. A **turn** is one prompt line, its command and its output, from one shell prompt to the next. No Daemon method, no contract type, no App seam command and no Token is added: the send is the existing `message.send` (B1) from the user, delivered by B2 and B30. Changes no Agent's Terminal: only a Terminal the user opens (X12) gets marks.

Reuse (rule 9), decided here for the implementation PRs. Marks: the OSC 133 sequences `A` (prompt start), `B` (command start), `C` (output start) and `D;<exit>` (end) that iTerm2, VS Code, WezTerm and Ghostty read. Selected: **xterm.js** (already a dependency, `@xterm/xterm` 6) for the reader: `parser.registerOscHandler` takes 133 and 7, `registerMarker` anchors a turn to the buffer and `registerDecoration` draws its gutter; no new package. Selected for the shell side: VS Code's `shellIntegration-rc.zsh`, `shellIntegration-bash.sh` and `shellIntegrationEnv`-style launch (MIT, https://github.com/microsoft/vscode/tree/main/src/vs/workbench/contrib/terminal/common/scripts), vendored and trimmed to 133 and 7. Rejected: kitty's shell integration (GPL-3.0, cannot be vendored); WezTerm's `wezterm.sh` (MIT, https://github.com/wez/wezterm) as the second source only, because it sets no `D;<exit>` for bash without `bash-preexec`; fish 4.0 and later emit OSC 133 natively, so fish gets only a launch flag. The implementing PR confirms each release date and licence in its `Reuse:` section; a candidate that fails there is replaced, not hand-written.

**X15 the App starts the user's shell with OSC 133 marks.** Given `terminal.open` (X12) for a Workstream, when the shell is `zsh`, `bash` or `fish` (its basename), then the Terminal's shell prints, around each prompt and command, `ESC ] 133 ; A BEL` before the prompt, `B` after it, `C` when the command starts and `D;<exit code>` when it ends, and `ESC ] 7 ; file://<host><cwd> BEL` after each command; the user's own rc files still run first and their prompt, aliases and environment are unchanged.

- **How.** zsh: the Daemon sets `ZDOTDIR` to a folder under its data directory whose `.zshenv`, `.zprofile`, `.zshrc` and `.zlogin` source the user's own (`$USER_ZDOTDIR`, else `$HOME`) and then load the hook. bash: it starts `bash --rcfile <wrapper> -i`-style (login kept, `--login`), the wrapper sources `/etc/profile`, the first of `~/.bash_profile`, `~/.bash_login`, `~/.profile`, then the hook, which wraps `PROMPT_COMMAND` and `PS0`. fish: it passes `--init-command` that enables the marks if the fish version does not emit them itself. The scripts are files in the repository, copied to the data directory when the Daemon starts; no user file is edited and none is written to `$HOME`.
- **Any other shell** (`sh`, `dash`, `nu`, an unset `$SHELL`) starts as X12 says today with no change and no mark. Over `ssh` or in a nested shell that does not source the hook, no mark arrives and U511 offers no block selection.
- **Marks leave no trace in a plain read.** The marks are OSC, so X4's parser and the plain-text read (`scenarios/plain-text.md`) strip them; `terminal.title` is unchanged.
- **Not for Agents.** `agent.run`, an Agent's Claude Code Terminal and the Door's Terminal start exactly as before, with no `ZDOTDIR` and no changed argv.

Tests (`crates/agents/tests/`, real `zsh`, `bash` and `fish` where installed, skipped by name when one is missing, and the hook files alone otherwise): `x15_zsh_prints_marks_around_a_command` (`echo hi; false` in a spawned shell prints `A`, `B`, `C`, output `hi`, `D;1` in that order), `x15_bash_prints_marks_around_a_command`, `x15_fish_prints_marks_around_a_command`, `x15_the_users_rc_still_runs` (a `ZDOTDIR` rc that exports a variable is seen), `x15_other_shells_start_unchanged` (`/bin/sh` argv and env equal X12's), `x15_an_agent_terminal_gets_no_hook`, `x15_marks_are_not_in_the_plain_read`.

**U511 a turn is one selectable block.** Given a Terminal whose output carries X15's marks, then:

- **Turns come from the marks.** The webview reads `A`, `B`, `C` and `D` and anchors each turn to xterm markers: it starts at the line of `A` and ends at the line before the next `A` (or the last line, for the turn still running). The turn holds the prompt line, the command and the output. A turn that scrolled out of the 10 000 lines (U34) is gone. A snapshot restore (U103) or a reload keeps the lines and shows no block for them, because the marks are not in the snapshot; later turns are marked again. Asserted in `u511_a_turn_runs_from_one_prompt_to_the_next`, `u511_a_running_turn_ends_at_the_last_line` and `u511_a_scrolled_out_turn_has_no_block`.
- **The gutter.** Each turn has a one-cell-wide gutter at the left edge of its first row, a 16 px click target, drawn only while the pointer is over the Terminal or a block is selected, in Tokens (a hairline in the secondary text Token; a selected turn in the selection Token). Clicking it selects the whole turn as one text selection from the first cell of its prompt to the last cell of its output, with trailing blank rows trimmed; the pointer is the default arrow, as native macOS gutters. A plain click in the text still starts an ordinary selection and never selects a turn. Asserted in `u511_a_gutter_click_selects_the_whole_turn` and `u511_a_text_click_selects_no_turn`.
- **Extend.** Shift-click on another turn's gutter selects from the earlier turn's start to the later turn's end, with every turn between; `⌘`-click toggles nothing (one range only). Asserted in `u511_shift_click_extends_over_the_turns_between`.
- **No marks, no blocks.** A Terminal that printed no `A` shows no gutter and no block; plain text selection, U101's copy and U365's links work as before, unchanged. Asserted in `u511_without_marks_there_is_no_gutter` and by `u101_` and `u365_` passing unchanged.
- **What a turn knows.** A turn holds the command text (the cells between `B` and `C`), the exit code of `D` when it arrived, and the working directory of the latest OSC 7 before its `A`. An unfinished turn has no exit code. Asserted in `u511_a_turn_knows_its_command_cwd_and_exit_code`.
- **Densest seed.** 200 turns of 50 rows with a 1 000-row turn: gutters exist only for the visible rows, a click on the 1 000-row turn selects it in one frame, and keystroke-to-render stays under rule 7's 16 ms p95. Asserted in `u511_two_hundred_turns_keep_the_keystroke_budget`.

**U512 Send to agent.** Given text selected in a Terminal, whether by a gutter click (U511) or by dragging, then:

- **Where it appears.** A `Send to agent` item shows in the Terminal's context menu (a right-click with a selection; with no selection the menu has no such item), as a small button beside the selection's last row (an Ark UI Popover, anchored to the selection), and on `⇧⌘S`. A right-click that does not move keeps the rules of `scenarios/ui-bubble-pull.md`: a Pull needs a drag. The shortcut follows U32's chord rules and is added to the list in `scenarios/ui-shortcuts.md`. With no selection the shortcut does nothing. Asserted in `u512_a_selection_offers_send_in_the_menu_the_button_and_the_shortcut` and `u512_no_selection_offers_nothing`.
- **Who it lists.** The picker lists the running Agents of this Project (a Rail node of Kind `agent` or `door` with a live Attempt, not `done`, not the Terminal's own Agent) by the name the Rail shows, with the Kind glyph, selected by arrow keys and `⏎`. With exactly one, the send goes to it at once, without a picker. With none, the item shows `No running agent` disabled. Asserted in `u512_the_picker_lists_running_agents_only`, `u512_one_agent_is_sent_to_straight_away` and `u512_no_agent_disables_the_item`.
- **The note.** The picker holds an optional one-line field, `Add a note`; `⏎` in it sends. An empty note adds nothing. With one Agent and the straight-away send there is no field: holding `⌥` opens the picker, with the note field, for the single Agent. Asserted in `u512_a_note_is_optional_and_one_line` and `u512_option_opens_the_picker_for_one_agent`.
- **The confirmation.** After `message.send` returns, the pane shows `Sent to <agent name>` on U80's one line (U349's pane notice) for 3 s, then clears; the selection stays. A failed send shows `✕ Not sent: <message>` and keeps the selection and the note. Asserted in `u512_the_pane_says_which_agent_got_it` and `u512_a_failed_send_keeps_the_selection_and_the_note`.
- **Policy: the control is a native menu and a Popover, Tokens only,** with U510's hover rules for its button (no hover fill). Moves D2, D5, D6; no Check passing on `main` breaks.

**U513 what the Agent receives.** Given U512's send, then the webview calls `message.send {to: <agent id>, kind: "note", body}` once, from the user (B1), and the Message is delivered as B2 and B30 say: typed at the Agent's next `idle`, never interrupting a turn; a busy Agent receives it at its turn's end together with any other pending Message. The `body` is, in order and each part only when present:

1. the note, one line;
2. a blank line when a note is present, then a line `Terminal excerpt:` (with the turn's command, a line `$ <command>` is added, then `cwd: <cwd>` and `exit: <code>` when known; for a selection that spans several turns, each turn gets its own such header lines before its text);
3. the excerpt in a fenced block: three backticks, a language-free fence, the selected text with the rows' trailing spaces trimmed and `\r\n` as `\n`, and three backticks; a fence longer than any backtick run inside the text is used so the text cannot close it.

A selection made by dragging, with no turn, carries only the note and the fenced text, and no command, cwd or exit line. The text of a selection over 8192 bytes (B1's bound, counting the whole body) is not sent: the pane shows `✕ Not sent: the selection is too long (limit 8 KB)` and nothing leaves; policy chosen here: refuse, never silently cut, because an Agent that reads half an output may act on it. An empty selection sends nothing. Asserted in `u513_the_body_is_note_header_and_fenced_excerpt`, `u513_a_drag_selection_has_no_command_lines`, `u513_a_fence_longer_than_the_text_s_backticks`, `u513_a_selection_over_8192_bytes_is_refused_whole` and `u513_the_message_is_a_note_from_the_user_to_the_chosen_agent`.

- **A busy Agent.** Given an Agent that is `working`, then the Message is `pending` until `idle` and the pane's confirmation reads `Sent to <name>` all the same; the Message's status is B2's. Asserted in `u513_a_working_agent_gets_it_at_idle` (real Daemon, fake `claude`: the Terminal sees the body as one paste after `idle`, and no interrupt).
- **The history.** The Message is in `message.list {to: <agent id>}` with the user as `from`, and the Agent's own Claude Code conversation shows it as the user's prompt. No other history surface is added. Asserted in `u513_the_message_shows_in_the_agents_message_list`.
