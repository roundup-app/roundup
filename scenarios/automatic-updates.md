# Open surfaces update themselves

Acceptance for #5558. This specification amends DV5, U504's heading actions, NR9, U2540b's content refresh and U3523a/d's listing refresh. It delivers no runtime behavior. Journey stages: Understand and Review; a result published by an Agent becomes discoverable without leaving the window or finding a reload action.

All test names below are implementation obligations, not claims that tests already exist. Extend existing proofs instead of duplicating them. App tests assert behavior, roles, selected identities, calls and contracts; the critic owns appearance and exact copy.

**U5558a Made follows committed publications.** Given a connected App with Made expanded, when an authenticated Agent publishes through the real Daemon's `deliverable.publish`, then that exact publication appears without a click, window-focus event or navigation. Removing it through `deliverable.remove` drops that exact row without a click. Tests: `u5558a_publication_appears_without_input` and `u5558a_removal_disappears_without_input`, extending the connected real-Daemon seam in `apps/desktop/src/ask/dv5_real_daemon.test.tsx` with the subscription established before mutation. Observe the row by recorded id, including two same-titled records; removal leaves the other record intact.

Policy: the Daemon emits a publication Event only after the mutation commits; Made reads `deliverable.list` on that Event. Include every metadata-changing publication path, including Home moves and lifecycle rehoming, in the signal coverage before removing Made's window-focus reload. No unrelated `rail.changed` reload remains when the publication signal covers those paths. Test `u5558a_events_follow_committed_changes` at the public Daemon subscription seam checks publish/remove/move and lifecycle rehoming readback, and no publication Event for a refused mutation or an idempotent replay that changes nothing. Preserve DV1–DV6's Project/access/removal rules. Event coverage removes the focus fallback rather than adding a second reload path.

**U5558b Reactions follows saved changes.** Given Reactions open with an exact-identity detail selected, when its saved observation, firing or stopped/expired state changes through the Daemon, then both its list entry and open detail show the saved state without a click or window-focus event. Test `u5558b_saved_changes_update_open_detail` through the connected App seam with deterministic saved records and the actual chosen Event; include a changed firing/observation on the same id so an old `reaction.get` result cannot keep masking the new list result. The automatic read performs no `reaction.run`, Agent start or Message send; assert zero such calls in that test.

Policy: use an existing authoritative Event if it covers each saved change, otherwise add one Reaction Event emitted after commit, covering creation, Stop/Run outcomes, observation/firing changes and expiry. A notification alone never evaluates a condition or fires a Reaction. An explicit Stop/Run and its Event must not cause duplicate reloads. Keep NR9's exact maker/target, honest accepted-work outcome and authority proofs. Test `u5558b_signal_covers_saved_changes` through the public Daemon subscription seam reads back each changed record after its notification, including expiry using the existing deterministic clock seam; an unchanged observation emits no new change notification.

**U5558c the open Diff reader follows the Worktree.** Given an open comparison for one Agent and relative path, when the existing shared Worktree refresh in `apps/desktop/src/state/worktrees.ts` completes after that file changes, then the reader displays the new comparison without a click. Test `u5558c_worktree_refresh_updates_open_comparison` at the connected App seam in `apps/desktop/src/changes/`, exercising that existing refresh signal and asserting the new content revision and exact `agent.compareFile` id/path. Include a second edit while `dirty` remains true: equal ahead/behind/dirty facts cannot suppress a content read. A different Agent's update cannot read into this reader; closing the reader stops its comparison reads (assert in the same signal-subscription test).

Given a saved note and an unsaved note draft on the old comparison, when that update arrives, then the saved note retains its original Base, revisions, range and source text, the draft retains its exact text and original comparison, and no Message is sent. Test: amend the existing `u2540b_refresh_keeps_original_context` in `apps/desktop/src/changes/u2540b_notes.test.tsx` to use the automatic signal instead of the retired button, extending its proof for the unsaved draft; retain its scenario prefix. Policy: Back, Close, binary/empty states, explicit failure Retry and on-demand renderer loading remain U2540a/d's contract. No new diff timer or file watcher is introduced.

**U5558d Import follows its Agent's listing.** Given Import open for Project A and its listing Agent, when that Agent completes `import.list` and saves a new candidate listing, then the existing actor-matched `rail.changed` signal triggers one `project.importDiscover` read of that saved listing and the candidates appear without a click. Test `u5558d_listing_signal_updates_candidates` in `apps/desktop/src/importer/` through the connected App seam, supplying the listing signal after the panel is open. It asserts the listing Agent/Project and new candidate identities, zero reads for another Agent's signal, and no newly selected candidate. Retain existing initial discovery and period-change behavior.

Given unapproved selections, when an automatic discovery returns changed or removed source revisions, then selection verification is reconciled under U3523d and commit remains an explicit user action for the verified selected identities; the original prompt stays intact. Test `u5558d_new_listing_revalidates_existing_choices`, extending the current App import/draft seam. Assert zero `project.importCommit` and zero Agent starts from the update. Policy: consume the saved listing, never repeat SDK/CLI discovery merely to display it; retain one active listing, existing deadlines, supersession and late-result refusal. Automatic updates do not authorize watching or polling vendor session storage.

**U5558e automatic reads are bounded and recoverable.** Given any of these four open surfaces with successful data, when its automatic reload fails, then the last successful list/detail/comparison remains visible with its actual cause in the existing failure surface. A later successful signal clears that reload cause and replaces the data. Test `u5558e_failed_reload_retains_data` in each surface's App test module as a table over its read failure/success outcomes; retain one proof per surface. No failure turns existing content into a successful empty result or discards note/import drafts. Explicit failure Retry may remain; it is not a routine Refresh control.

Policy: no surface in the App offers a manual Refresh button. Remove the Refresh action members and words from `sharedCopy.ts`, `ask/copy.ts` and `importer/copy.ts`, and update their consumers, including Reactions/Diff copy re-exports and recovery text that tells the user to press Refresh. Retained recovery wording points to an action that exists. The existing desktop type check must reject references to the removed catalogue members; do not add a test that repeats a type-check proof. The implementation's rendered observer verifies the four surfaces' available actions, including failed reloads.

Policy: add no timer, polling loop or file watcher. Reuse the App's Event subscription and existing Worktree refresh, with cleanup when its owner closes. After initial load, each relevant Event causes at most one reload read per affected open surface; unrelated Events cause none. Reactions derives its list and selected detail from that result or Event data rather than duplicating reads for the same change. The Diff reader may read once per completed existing Worktree refresh for its Agent, including content-only edits; it adds no polling cadence. Tests U5558a–d assert these call counts after the signal's read settles, including Stop/Run deduplication for Reactions. Do not use sleep-based readiness. The PR names the signal and read used by each surface. `just perf` must hold in its qualified environment: cold start <300 ms, ten idle Agents <150 MB extra RSS and no regression above 10%; qualification failure is no passing measurement. Keep the keystroke-to-render <16 ms p95 bound; `docs/perf.md` reserves its native measurement for an explicit user request, so this Issue orders no new native run.

## Contract and scope

Policy: implement publication and any necessary Reaction Event through the Contract recipe: declare in `crates/contracts`, regenerate `contracts/generated/`, add the concrete code names to `GLOSSARY.md`, and update every emitter, subscriber, contract declaration/fingerprint and affected fake/test caller in the same PR. This specification chooses no new wire identifier or payload. No Message, Route, Held or Takeover semantics change; laws M1–M10 remain unchanged. Reuse existing storage transactions and Event transport; no new store, scheduler, vendor parser or watcher.

Implementation scope: the existing publication and Reaction storage/mutation owners under `crates/rupd/src/` (including expiry/observation writers), existing Event contracts/export, generated contracts and glossary; the four existing App surfaces and their state owners under `ask/`, `reactions/`, `changes/`, `importer/` and `state/`; shared/cross-surface copy consumers and existing focused test/harness seams. No new authoring flow, changed import authority, section composition or loop machinery. Apply rule 9 before adding any machinery. Progress, implementation scope expansions and engineering questions belong on #5558.
