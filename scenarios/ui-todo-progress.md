# UI: Todos track progress and tick with motion (U3767 to U3771)

Module: `apps/desktop` (the webview). Ids: U3767 to U3771.

Webview only: no App command, no Daemon method and nothing under `contracts/` changes; `todo.complete` and `todo.reopen` are called as U361 and U461a say. Requested by #3300: the Shelf's Todos look and move like AffectUI's Progress Tracker (https://www.affectui.com/components/progress-tracker, free, MIT; its source, `https://www.affectui.com/r/progress-tracker.json`, lists `"dependencies": []`). Only its CSS ideas are used; the item is React-only, so no code is copied and the PR credits it. Narrows U361 (the tick box's look), U3010c (Todo motion) and `docs/design-system.md`'s direction sentence. U3010c's 150 ms fold and row slide, U53 and U156 keep their behaviour.

Decided here: the list is the Todos tab's list in the Shelf's current scope (U2744a), once; owner groups (U3717) get no bar of their own. The total is every Todo in that scope, open and done; the done count is those with `done`. A scope with no Todo shows no bar.

**U3767 the Todos list shows a progress bar with a done/total count above it.** Given the Shelf's Todos tab on `tree-40`, `agents-10` and `first-run` (U26), light and dark for non-capture observers (captures and critic Check readings use dark only, U3725), at 1280 by 820 and 1280 by 800, when a test reads the rendered tree, then:

- **Bar.** Above the first group, one Ark UI `Progress` (linear; wrapped in `apps/desktop/src/ui/`, not hand-written) with role `progressbar`, `aria-valuemin` 0, `aria-valuemax` the total, `aria-valuenow` the done count, and the accessible name `Todos done`. Its fill is drawn with `transform: scaleX(done/total)`, never an animated width. Test: `u3767_the_bar_reads_done_over_total`.
- **Count.** Beside the bar the text `<done>/<total>` in the quiet secondary type. It changes only when `todo.updated` arrives and `todo.list` is refetched (U15); a tick that has not been refetched or has failed (U35) leaves the bar and count as they were. Test: `u3767_the_count_follows_the_refetched_list`.
- **Empty.** A scope with no Todo shows neither bar nor count and reserves no space for them; one with Todos and none done shows `0/<total>` and an empty fill. Test: `u3767_an_empty_scope_shows_no_bar`.
- **Kept.** The bar and count take no focus, hold no button and call nothing; `todo.*` calls of every row action are unchanged and U112 holds (no row's top edge moves because a pointer hovers). Test: `u3767_the_bar_calls_nothing_and_takes_no_focus`.

Observer: Vitest `u3767_` cases on the fake App seam; captures at 1280 by 820 go to `artifacts/ux/U3767/`. Moves: D1, D2, D5, D6.

**U3768 the tick box draws its tick; it is still the one native control.** Narrows U361's Tick box. Given the open and done Todos of U3767's seeds, when a test reads the rendered tree and computed style, then the tick box (`todos/TickBox.tsx`, `rowButton.styles.css`) is still the native `input type="checkbox"` of U361 with its accessible name, 24 px hit area, visible focus, Space to toggle and tab order; no second checkbox exists. Its tick is drawn by an SVG path or a CSS mask on that input's box, as a stroke whose dash offset runs from full (hidden) to zero (drawn), and its ring is the same box's outline or border; a native checkbox glyph cannot draw a stroke, which is why the box is restyled. A done Todo mounted done shows the drawn tick and the settled ring with no motion; an open one shows neither tick nor offset stroke. The ticks keep D3's contrast on both states and the box stays 16 px. Tests: `u3768_the_tick_is_the_one_native_checkbox`, `u3768_a_done_row_mounts_with_the_tick_drawn`. Observer: Vitest `u3768_` cases; the rendered stroke is the design critic's (rule 10). Moves: D1, D2, D3, D5.

**U3769 a finishing Todo plays one motion; nothing else on the Shelf moves.** Given the Shelf showing the Todos tab (U3767), when:

- **User ticks or unticks.** The user ticks an open Todo (click or Space): once `todo.updated` arrives and `todo.list` is refetched (U15), that row draws its tick, pops its ring, grows a strike across its label, the bar fill grows to the new `done/total` and the count rolls in. Unticking (U461a) plays the same in reverse. The ordering and delays within it are the Tokens' of U3770. Test: `u3769_ticking_plays_the_tick_ring_strike_bar_and_count`, `u3769_unticking_plays_the_reverse`.
- **An Agent finishes a visible Todo.** `todo.updated` arrives for a Todo in the shown scope that an Agent completed (not the user's own tick): its row and the bar play the same motion. A Todo outside the scope or inside a folded group plays none and the bar and count still settle to the new values with no motion. Test: `u3769_an_agent_finishing_a_shown_todo_plays_the_motion`, `u3769_a_finish_out_of_view_moves_nothing`.
- **No motion at rest.** Opening the Shelf, a Rail switch (U2744a's scope change), first mount and a refetch that changes no `done` state show the end state at once: every done row with its tick, strike and ring settled, the bar at its final fill, the count at its final text; no row stagger, no card rise, no auto-play and no shine sweep. The marker the observer reads is `data-motion="play"` on a row or bar, present only while a motion plays and never on mount. Tests: `u3769_opening_and_switching_show_the_end_state_without_motion`, `u3769_a_refetch_with_no_change_plays_nothing`.
- **A burst retargets.** Several Todos finish in one burst, or a second finish arrives mid-motion: no motion queues, none restarts from the start, and each running one retargets from its current state to the new one, so the bar fill and count reach the last `done/total` without passing back through a stale one, and every row ends settled. Test: `u3769_a_burst_retargets_and_ends_on_the_last_state`.
- **Reduced motion.** Under `prefers-reduced-motion` the end state appears at once for each of the above: no `data-motion="play"` that moves anything, durations 0 (D9, `docs/design-system.md` heading **The checks**, `apps/desktop/src/testing/checks.ts` function `runChecks`), and the preference changing mid-motion settles it at the next frame as `u5_a_change_of_the_preference_is_followed` in `apps/desktop/src/app/reducedMotion.test.tsx` holds for other motion. Test: `u3769_reduced_motion_shows_the_end_state`.
- **Kept.** Ticking is one key or click with the `todo.*` calls of U361 and U461a unchanged; focus follows U138; the done fold and the row slide of U3010c keep their 150 ms behaviour and tests (`u138_*`, `u155_*`, `u3010c_*` run unchanged). Test: `u3769_the_calls_and_focus_are_unchanged` (the cited cases, run unchanged).

Observer: Vitest `u3769_` cases on the fake App seam, reading `data-motion` and computed `animation-duration`; the U26 harness with `agent-browser` (headless, fresh profile) ticks a Todo on `tree-40`, completes one as an Agent through the fake App and samples the bar's fill and the count at quarter-speed, three runs per variant, captures to `artifacts/ux/U3769/`. Moves: D6, D7, D9.

**U3770 the motion reads its timings from Tokens.** Narrows U3010a's one-easing-source rule. `apps/desktop/src/tokens.css` gains, with no literal elsewhere (D1, D2): `--ease-todo` (`cubic-bezier(0.22, 1, 0.36, 1)`), `--ease-pop` (an overshooting curve for the ring pop), and one duration for each effect: tick draw, ring pop, strike grow, bar fill, count roll, plus the delays of the tick and the strike. `--duration-todo` (150 ms) stays and keeps the fold and the row slide. Starting values are AffectUI's, and the design critic accepts or shortens them in the implementing PR; the PR adds a row for each to `docs/motion.md` and the Tokens to `docs/design-system.md`'s Tokens table, so D9 (each duration within 25% of `docs/motion.md`) holds.

| Effect | Starting value |
|---|---|
| tick draws, stroke dash offset 1 to 0 | 420 ms, 160 ms delay |
| ring pops, scale 0.9, 1.06, 1 | 560 ms |
| strike grows, background size 0 to 100% | 620 ms, 220 ms delay |
| bar fills, `scaleX` | 1100 ms |
| count rolls in | 560 ms |

Plain CSS only: no motion library and no JavaScript timer drives any of it; a transition or CSS animation on `transform`, `opacity`, `stroke-dashoffset` and `background-size` only, never `transition: all` (U3010a). Tests: `u3770_no_literal_duration_or_ease_outside_tokens` (D1 on the rendered Todos), `u3770_the_effects_resolve_the_token_durations`. Policy: the final values are the design critic's. Moves: D1, D9.

**U3771 the direction sentence and the worst case.** `docs/design-system.md`'s direction changes "nothing that moves unless the user did something" to "nothing moves unless the user acted or an Agent finished a Todo the user can see" (policy; the design critic and review read the document). Given U3767's seeds and U359's and U361's worst-case fixtures (300-character title, a one-letter, emoji and non-Latin title, 0 and 200 Todos, all done, none done), at a Shelf width of 163 px and of 480 px, then the bar and count never wrap or clip, the count shows `200/200` and (and no bar for an empty scope, U3767) without moving a row, and the design critic judges that D2, D5, D6, D9, D10 and D12 pass with no Check passing on `main` regressing (AGENTS.md rules 8 and 10). Cold start and keystroke budgets hold (rule 7, `docs/perf.md`). Tests: `u3767_the_bar_reads_done_over_total` runs on the harness's `Demo data / Worst case` toggle (`break-ui`); captures in `artifacts/ux/U3771/`. Moves: D2, D5, D6, D9, D10, D12.
