# boxd agent runners

**L121 snapshot runners retain agent memory.** The owner's interactive instruction authorizes this loop change. Build, fix, review and critic agent jobs run on separate, isolated boxd machines from the prepared `roundup-ci` snapshot; GitHub's existing job permissions, admission and merge gates hold.

- A signed `workflow_job` webhook for the configured repository, trusted workflow and configured ref admits one queued job. An invalid signature, another repository, an untrusted event/ref/workflow, or a label inconsistent with the run is refused before provisioning. Redelivery and controller restart never start a second machine for a job. Each runner has a job-specific label and accepts exactly one job. Capacity bounds simultaneous machines.
- The snapshot includes the pinned toolchain and agent programs, no agent login, registered runner identity, conversation or project memory. An agent machine has no boxd integration metadata, controller credential or runner-administration token. Packages are reconciled against the current lockfile; installed tools are verified before the agent starts. No job silently falls back to a GitHub-hosted agent runner.
- Each job starts a fresh agent process. Conversation files survive the machine under their Issue/PR and role; a build and its fixes share the Issue's history. Project auto-memory is enabled and retained per repository and role. Builder/fix, review and critic memory never mix. Retained archives include no login/configuration files and are private on the controller. Unsafe archive paths or links are rejected. Concurrent project-memory edits preserve both revisions rather than silently overwriting one.
- Completion, failure and cancellation save conversation, auto-memory and runner diagnostics before deleting the machine and its registration. A save failure is visible and retains the machine for retry. Recovery reconciles GitHub's job status, including a missed completion webhook, and retries cleanup. An absolute machine lifetime bounds compute leakage if the controller is unavailable; this emergency deletion cannot promise unsaved history. No raw transcript is published as a GitHub artifact.
- The controller records webhook receipt, machine readiness, runner registration and job start times. A live job proves snapshot startup, fresh runner execution, retained memory restoration and deregistration/deletion. Snapshot refreshes follow tool versions and keep the GitHub runner within its supported update age.

Observers: `loop/boxd/*.test.*`, the existing workflow permission tests, and the live job/controller record described in `loop/boxd/README.md`.
