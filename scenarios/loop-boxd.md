# boxd agent runners

**L121 optional snapshot runners retain agent memory.** Agent jobs use GitHub-hosted runners by default. The owner can opt a build Issue into boxd with the repository variable `BOXD_ISSUES`, or a PR's fix, review and critic jobs with `BOXD_PRS`, each a JSON array of numeric IDs. Unset variables, empty arrays and IDs outside the arrays use GitHub-hosted runners. Opted-in jobs run on separate, isolated machines from the prepared `roundup-ci` snapshot; GitHub's existing job permissions, admission and merge gates hold.

- A signed `workflow_job` webhook for the configured repository, trusted workflow and configured ref admits one queued job. An invalid signature, another repository, an untrusted event/ref/workflow, or a label inconsistent with the run is refused before provisioning. Redelivery and controller restart never start a second machine for a job. Each runner has a job-specific label and accepts exactly one job. Capacity bounds simultaneous machines.
- With the repository variable `BOXD_LIGHT` set to `1`, the short jobs around agent jobs run on boxd too: build's `pick`, the `task` of fix, review and critic, the `after` of build and fix, and the `post` of review and critic. Each is admitted only from the workflows that carry it, starts with no memory and keeps none, and takes free capacity before agent jobs. Any other value keeps them on GitHub.
- The snapshot includes the pinned toolchain and agent programs, no agent login, registered runner identity, conversation or project memory. An agent machine has no boxd integration metadata, controller credential or runner-administration token. Packages are reconciled against the current lockfile; installed tools are verified before the agent starts. No job silently falls back to a GitHub-hosted agent runner.
- Each job starts a fresh agent process. A boxd review or critic job starts with no conversation or project memory, and none of it is retained (AGENTS.md rule 5). For opted-in build and fix jobs, conversation files survive the machine under their Issue/PR; a build and its fixes share the Issue's history. Project auto-memory is enabled and retained per repository for the builder role. Smoke-test memory remains separate. GitHub-hosted jobs retain their existing fresh-memory behavior. Retained archives include no login/configuration files and are private on the controller. Unsafe archive paths or links are rejected. Concurrent project-memory edits preserve both revisions rather than silently overwriting one.
- Completion, failure and cancellation save runner diagnostics, plus a build or fix job's conversation and auto-memory, before deleting the machine and its registration. A save failure is visible and retains the machine for retry. Recovery reconciles GitHub's job status, including a missed completion webhook, and retries cleanup. An absolute machine lifetime bounds compute leakage if the controller is unavailable; this emergency deletion cannot promise unsaved history. No raw transcript is published as a GitHub artifact.
- The controller records webhook receipt, machine readiness, runner registration and job start times. A live job proves snapshot startup, fresh runner execution, retained memory restoration and deregistration/deletion. Snapshot refreshes follow tool versions and keep the GitHub runner within its supported update age.
- The required `rules` check always reports on a PR. Its boxd package installation and regression suite run only for changes to runner code, agent integration, workflows/setup, package configuration or this contract. Unrelated product/documentation changes skip that setup and suite. These tests add no post-merge run.

Observers: `loop/agent-runners/*.test.*`, the existing workflow permission tests, and the live job/controller record described in `loop/agent-runners/README.md`.
