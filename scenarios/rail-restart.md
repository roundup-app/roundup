# Restart an Agent on its saved conversation (U7191a, U7191b, U7191c, U7191d, U7191e, U7191f, U7191g, U7191h, U7493a)

Module: `apps/desktop/src/rail/` (the menu) and `crates/agents/` (the resume path), and for U7191d to U7191h `crates/rupd/`, `crates/messages/` and `crates/terminal/`. Ids: U7191a, U7191b, U7191c, U7191d, U7191e, U7191f, U7191g, U7191h, U7493a. Acceptance for #7191, #7493 and #7903. Owner's 2026-11-15 pick: Restart resumes the same conversation, not a fresh one; a fresh-conversation restart is out of scope. A Mode is the exception (owner, 2026-11-18): its Restart stays the saved-prompt `agent.restartMode` (A35, A4665) and its stopped row's play icon is Resume (U7493a).

## Checks on main

1. `apps/desktop/src/rail/menu/model.ts`, `lifecycleEntries` and `restart`: the `restart` entry shows only on a running YOLO Agent and calls `agent.resume {id, mode: "normal"}`, which switches the mode; `startYolo` is its mirror.
2. `crates/contracts/src/declarations.rs`, `"agent.resume"`: an explicit `mode` stops a running Agent or Door first and resumes its conversation; an omitted `mode` requires an exited Agent.
3. `crates/agents/src/resume.rs`, `Agents::resume`: the one launch path with A22's acknowledgement and rollback; `agent.extras_add` (`crates/agents/src/dispatch.rs`) already relaunches with the conversation.
4. `apps/desktop/src/rail/menu/model.ts`, `needsConfirmation` and `requestStop`: a `working`, `needs-you` or `blocked` Door asks once before stopping; any other running Agent stops at once.
5. `crates/rupd/src/restart.rs`, `restart_mode`: a Mode Restart holds one `message_restarts` row per Agent (`SessionRestart` `Reserved`, `Starting`, `Typing`, `Started`, `Acknowledged`, `Released`); any error from `mode_prompt` leaves `Typing`, and only `UNKNOWN_OUTCOME` from the start leaves `Starting`.
6. `crates/messages/src/store.rs`, `reserve_restart` and `end_restart`: a new request key is refused with "another restart reserved this receiver" while a hold is open (`released IS NULL`); only `end_restart`, on Rail removal, clears one. A daemon restart keeps it.
7. `crates/agents/src/door.rs`, `mode_prompt` and the Mode start: "did not become ready; nothing was typed" and "Attempt is no longer live" are the two errors that prove nothing was typed.
8. `crates/terminal/src/error.rs`: a core error arrives as `internal: <code>: <err>` with the codes `core_closed`, `core_silent` and `core_missing`; `crates/terminal/src/spawn.rs` holds the Terminal's `core_id`, its herdr-core address.

**U7191a Restart resumes the same conversation.** Narrows U2694d and U4322a (its run group keeps Restart first). Given an Agent row of any kind but a Mode (Door, Workstream, child; a Mode is U7493a) in any status whose conversation the Daemon holds, when the user chooses Restart from its right-click menu, then:

- The Agent's program stops and starts again resuming that conversation in the permission mode it ran in, through the one `agent.resume` path with an explicit `mode`; no third relaunch path is added, and `agent.extras_add` shares that launch code. Rust test: `u7191a_restart_resumes_the_same_conversation` (stops the old run, starts one resuming the same conversation id with the same mode, same Rail row id, a fresh Terminal id; the fresh run reads current settings and tools).
- The Rail menu calls `agent.resume {id, mode}` once with the Agent's current mode. Vitest: `u7191a_restart_calls_resume_with_the_current_mode`.
- Restart on an exited row handles an unknown outcome as the deleted `resume()` did: given the reply is lost after `agent.resume` was sent, then the row refreshes and shows the failure inline (U80's `✕ <cause>`) and choosing Restart again sends the same request id, so the Daemon starts no second run. Vitest: `u7191a_an_exited_restart_with_a_lost_reply_retries_the_same_request`.
- Restart on an exited row selects that row. Vitest: `u7191a_restarting_an_exited_row_selects_it`.
- The exited row's play icon (a Mode's is U7493a) is labelled Restart, like its menu action, and runs the same one action (no separate `resume` icon action remains; `RowIcons.tsx`, `copy.resume`, `isResumable` and `requestResume` are deleted when nothing else calls them). Vitest: `u7191a_the_exited_row_icon_is_labelled_restart`.
- The former YOLO-only `Restart` entry, which switched a YOLO Agent to normal, is relabelled `Start normal` (the mirror of `Start YOLO`) so the menu holds one Restart. Vitest: `u7191a_yolo_to_normal_is_start_normal`.

**U7191b Restart is offered only with a conversation to resume, and asks only when interrupting work.** Given the menu of a row, then:

- Restart is present only when the Daemon reports a saved conversation for that Agent (a running Agent that has started one, or an exited one with `can_resume`); otherwise it is absent, never greyed out, except that a Mode with no saved conversation keeps Restart, its only way to start (`agent.restartMode`, A4452c; `u4547d_restart_controls_share_the_focused_mode_action`). The row carries that fact on `RailNode` (Contract recipe: `GLOSSARY.md`, `contracts/generated/` and every caller in the same PR). Vitest: `u7191b_restart_is_absent_without_a_conversation`; Rust test for the fact: `u7191b_the_row_reports_a_conversation`.
- An idle, done or stopped Agent restarts at once. A `working`, `needs-you` or `blocked` Agent asks once first, by the same rule and function as Stop (`needsConfirmation`); declining calls nothing. Vitest: `u7191b_restart_asks_only_when_it_interrupts_work`.

**U7191c a failed Restart says why.** Given the Daemon cannot find the conversation or the program does not start, when the user chooses Restart, then the row shows U80's `✕ <cause>` and the Agent never shows a silent idle; A22's rollback leaves the Terminal and row as before and the same Restart can be chosen again. Rust test: `u7191c_a_failed_restart_names_the_cause`; Vitest: `u7191c_the_row_shows_the_restart_failure`.

**U7191d a failed Restart frees its hold.** Given a Mode Agent whose herdr-core was killed during a Restart, leaving its hold in `Reserved`, `Starting` or `Typing` (from any request key, before or after an App reload or a Daemon restart), when the user chooses Restart once, then the Mode starts: a new user Restart takes over a hold whose old program has stopped (it stops that program first, check 5), so no "restart is held for another" refusal is shown and no Agent is removed. This also clears holds already stuck, with no migration. A start or prompt failure that proves nothing was typed (check 7) frees the hold at once. A hold whose prompt may have been typed is U7191g's. Audit: the Retirement hold (`crates/messages/src/delivery.rs`, the removal reconcile that calls `end_restart`) and resume cleanup (`crates/agents/src/resume.rs`, `Slot::ResumeCleanup`) are each shown to free on the same failure or are fixed the same way, and each is listed in the PR body. Rust tests, one per hold state, each failing on `main`: `u7191d_a_restart_after_a_core_kill_takes_over_a_reserved_hold`, `u7191d_a_restart_after_a_core_kill_takes_over_a_starting_hold`, `u7191d_a_restart_after_a_core_kill_takes_over_a_typing_hold`; and `u7191d_a_start_failure_that_typed_nothing_frees_the_hold`, `u7191d_the_retirement_hold_frees_after_a_failure`, `u7191d_resume_cleanup_frees_after_a_failure`.

**U7191e a closed core connection is reopened once.** Given the Daemon's herdr-core connection closed (`core_closed`, `core_silent` or `core_missing`) when a Mode starts or restarts, then the connection is reopened and the start tried once more before anything is typed; a second failure is U7191f's. Rust test: `u7191e_a_closed_core_connection_is_reopened_and_the_start_retried_once`; `u7191e_a_second_core_failure_is_not_retried_again` (the start runs twice, never three times).

**U7191f a start or Restart failure names what failed.** Given a start or Restart that fails, then its error names the Agent, its Terminal's `core_id` and the core error code, in the App's failure line and as one line in `rupd.log`. The App's fixed copy for `core_closed`, `core_silent` and `core_missing` (`apps/desktop/src/app/failureOf.ts`) keeps its words and adds the Agent and address. Rust test: `u7191f_a_failed_start_logs_one_line_naming_agent_core_id_and_code`; Vitest: `u7191f_the_failure_line_names_the_agent_and_core_address`.

**U7191g a prompt is never typed twice.** Given a Restart whose Mode prompt was typed but no receipt came (an outcome truly unknown), when the user chooses Restart again on the same request, then nothing is typed and the refusal names the Agent, its Attempt and the Terminal address. A new user Restart still stops that program and starts a fresh one (U7191d), so the prompt reaches a program only once. Rust test: `u7191g_an_unknown_outcome_is_refused_naming_agent_attempt_and_terminal`; `u7191g_a_prompt_is_typed_once_per_program`.

**U7191h the hold has a checked model.** A TLA+ model of the hold (states `none`, `Reserved`, `Starting`, `Typing`, `Started`, `Acknowledged`, `Released`; actions: Restart, herdr-core killed, App reload with a new key, Daemon restart, Rail removal), checked with everystate over every order of the faults, holds: no reachable state refuses a Restart without the refusal naming what blocks it; a prompt is typed at most once per program. The spec sits beside the tests at `crates/rupd/tests/restart_hold/RestartHold.tla`. Test: `u7191h_the_restart_hold_model_checks` (runs the checker when installed, and the Rust tests above hold each transition the model names).

**U7493a a Mode restarts fresh; its play icon resumes.** Amends U7191a, whose Mode bullet is removed. Given a Mode Agent row (a root Agent holding a saved Mode prompt, A4452c), then:

- Restart (its menu entry, the `R` key and a running Mode's restart icon) always calls `agent.restartMode` once: a fresh run that types the saved prompt once (A4452c), whether or not a conversation is saved, and never `agent.resume`. Vitest: `u7493a_a_mode_restart_always_runs_restart_mode`.
- A stopped Mode's play icon is named Resume and calls `agent.resume` for its saved conversation, typing no prompt. Vitest: `u7493a_a_stopped_mode_play_icon_resumes_its_conversation`.
- A stopped Mode with no saved conversation shows no play icon: its Restart is its one start, so no icon named Resume restarts and no icon repeats Restart. Vitest: `u7493a_a_mode_without_a_conversation_has_no_play_icon`.
- Every other Agent keeps U7191a; U7191b's Mode exception (Restart present with no saved conversation) and its confirmation rule stand. Vitest: `u7493a_other_agents_keep_restart_on_resume`.

```text
Stopped Mode row:  ▷ Resume -> same conversation    Restart -> fresh run, saved prompt
Running Mode row:  Restart -> fresh run, saved prompt
```

Policy — rendered observer: `just capture U7191a U7191b U7191c U7191f U7493a` in dark mode, the menu open on a working Door (the question) and an idle one, and the failure line on the densest seed (`tree-40`); the design critic judges them. Native look-and-feel is the user's to report on the Mac.

Policy — Mac: on the owner's Mac, kill herdr-core during a Mode Restart, press Restart once, and the Mode starts with no App reload and no Agent removal; the user reports it (L46).
