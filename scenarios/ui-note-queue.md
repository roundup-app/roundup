# UI: an Agent's waiting Messages (U3780 to U3784, U3787)

Module: `apps/desktop` (the webview); U3782 also owns the existing `crates/messages` drop contract. Ids: U3780 to U3784, U3787. Work Issues: #3305 (queue), #3518 (remove the field). Journey stages: Understand and Intervene (`.agents/data/journey.md`).

The user types to an Agent in Claude Code's own input in its Terminal. The waiting-Message queue remains below the Terminal, with row actions and Pause/Resume (Takeover, B6). It reads Messages, not a second store; B3, B32 and B50 to B52 keep their delivery and transport rules. U3787 retires the separate note field and its draft behavior. U12, U107 and U531 still govern Terminal typing and control. Removing a field adds no RPC method or App seam command and changes no Message law.

Contract policy (AGENTS.md rule 4): U3782 changes `message.drop` (B3) and every caller in the same PR; no other contract, App command or `GLOSSARY.md` term is added, and the App prose terms go in `copy.ts`. U3782's `drop` of a `pending` Message touches laws M1 (a dropped Message is never typed, and one with an in-flight record is not dropped), M5 and M6 (`dropped` stays terminal and carries the reason `removed`); `proofs/messages/model.bend` gains the event, `LAWS.bend` weakens no law, and `docs/messages.md` agrees.

Pause holds delivery, not the running turn: the Agent finishes the step it is on and takes nothing until `Resume`; stopping a turn is `agent.interrupt`, as before.

**U3780 the queue lists the selected Agent's waiting Messages below its Terminal.** Given a watched Agent's pane (U12), when it shows, then:

- The queue lists, oldest first (B7), every Message to this Agent in `pending` or `held` that the user sent, plus Messages from other Agents or Routes held by ask-first or Takeover (U3783, B6, B32). The list is read from `message.list` and `message.sent`, `message.held`, `message.delivered` and `message.dropped`, never from a second store. Each row shows the Message's first line with `…` when more follows and the whole text as its accessible description; a count `N waiting` heads a queue of two or more. Test: `u3780_the_queue_is_the_agents_waiting_messages_in_order`; the other-Agent Takeover case is asserted by `u3783_takeover_held_agent_messages_stay_in_the_queue`.
- With no rows and no Pause or failure to show, the queue draws nothing: no empty state or reserved height. While paused, Resume remains reachable even if no rows remain; a failed row action or Pause/Resume keeps its cause visible beside the queue. Tests: rename the existing empty-queue case to `u3780_an_empty_queue_draws_nothing`; `u3782_resume_remains_reachable_without_rows`; existing `u3782_pause_and_resume_are_takeover_and_show_its_state` and `u3782_remove_drops_one_message_and_keeps_the_rest` retain their failure assertions. The design critic observes the absence of reserved height.
- Selecting another Agent shows only that Agent's queue; switching back restores only the original Agent's waiting Messages. Test: replace the draft-specific part of `u3780_two_agents_never_share_a_queue_or_a_draft` with `u3780_two_agents_never_share_a_queue`.

Observer: Vitest on the existing fake App seam (`apps/desktop/src/terminal/noteQueueHarness.tsx`); the design critic judges D2, D5 and D6 at 1512×950 in dark mode. Captures: `artifacts/ux/U3780/`.

**U3781 note-field submission is retired.** Policy: Enter-to-queue, ⌘Enter-to-send-now, field-specific shortcuts and hints, blank/oversize submission handling, pending-submit suppression and per-Agent field drafts are retired by U3787. No replacement composer or hidden key-opened field is introduced. Delete their tests; U12 and U531 retain Terminal typing and control, and B1/B2 retain Message sending outside the removed field.

**U3782 each waiting note is removable with ×, and Pause and Resume hold the Agent.** Given a queue of two notes (U3780), then:

- The `×` on a row (a `ui/IconButton` named `Remove note: <first line>`, with a `ui/Tooltip`) calls `message.drop {id}` once; the row leaves when `message.dropped` arrives; the other rows keep their order and focus moves to the next row's `×`, or to this Agent's Terminal when none is left. A note that was `delivered` meanwhile cannot be removed: the `CONFLICT` shows beside the queue and the row goes with `message.delivered`. Test: `u3782_remove_drops_one_message_and_keeps_the_rest`.
- Contract change: `message.drop` (B3) also accepts a `pending` Message the user sent, when no in-flight record exists (B39(a)); it becomes `dropped` with the reason `removed`, nothing is typed, `message.dropped` is emitted, and the same call on a `pending` Message of another sender or with an in-flight record stays `CONFLICT`. Only the user may call it. Tests in `crates/messages/src/tests/`: `u3782_drop_of_a_pending_user_message_types_nothing`, `u3782_drop_is_refused_once_the_prompt_is_in_flight`.
- `Pause` (a `ui/` toggle button in the queue's header) calls `takeover.begin {agent}` once; `Resume` calls `takeover.end {agent}` once. While paused, notes sent are `held` for `takeover` (B32), the header reads `Paused`, and a queue with rows keeps them; `Resume` releases them as one batch in id order (B6, B32). The control is the same state as `You control` (U107): pausing shows it, taking control shows `Resume`, and each is undone by `takeover.end`. A failed call leaves the button as it was and shows the cause. Test: `u3782_pause_and_resume_are_takeover_and_show_its_state`.
- Pause does not stop the turn: no `agent.interrupt` is called. `Pause` and `Resume` are not offered for an Agent whose Kind is `done` or `error` (B6: `CONFLICT`). Test: `u3782_pause_stops_no_turn_and_is_absent_for_a_finished_agent`.

Observer: Vitest `u3782_` cases; Rust tests named above; `just proofs` prints `ALL PROOFS CHECK`. Moves: D5, D6, D7.

**U3783 a Door's or the decision-maker Model's note waits in the same queue when its Route or Takeover holds it.** Given a note to the Agent from a Door or the decision-maker Model (B50: it goes through the inbox, never the Terminal), then by the Route (B5):

- `auto`: the note is delivered by B50 and does not appear in the queue, unless Takeover holds it under B6/B32; a Message held for `takeover` appears until released or removed. Test: `u3783_takeover_held_agent_messages_stay_in_the_queue`. `drop`: it is dropped (B4) and does not appear. `ask-first`: it is `held` (B3), appears as a row marked with the sender's Rail name (or `Model`, in App prose `decision-maker`), and offers `Allow` (`message.deliver {id}` once, B3: the transport stays the inbox, B50(f)) and `×` (`message.drop {id}` once). Test: `u3783_only_an_ask_first_note_waits_for_the_user`.
- Such rows sort with the user's notes by id (B7). A Pause does not hide them; `Resume` does not release an `ask-first` row (B6). `Allow` on a row whose inbox is unusable shows B51's cause and leaves the row. Test: `u3783_allow_delivers_one_and_resume_leaves_ask_first_rows`.

Observer: Vitest `u3783_` cases plus a real-Daemon case (`u3783_a_real_door_note_waits_under_ask_first`). Moves: D5.

**U3784 a note glides into the step that takes it.** Given a queue (U3780) and the Agent's step line (U456's formatter, shown in the queue header as `Now: <step>`), then:

- When `message.delivered` arrives for a row the user can see, that row moves with a transform to the step line and fades, in one `--duration-note` with `--ease-note` (Tokens added to `tokens.css`); the remaining rows close up in the same time. It plays when the Agent takes the note, including after `Allow` or `Resume`; it never plays on mount, on selecting another Agent, on reopening the pane or when the queue was off screen. Test: `u3784_a_taken_note_glides_once_and_a_mount_plays_nothing`.
- Several notes taken at once glide as one group, no stagger; a later delivery retargets from the current state and never queues a backlog. A removed note leaves at once without gliding to the step. Test: `u3784_a_batch_glides_together_and_a_removal_does_not`.
- No timer or clock decides when the glide starts or ends: it is a CSS transition on the row's state, and the row leaves on `transitionend`, or at once under `prefers-reduced-motion` (D9). Only `transform` and `opacity` animate. Test: `u3784_reduced_motion_removes_the_row_with_no_transition`.
- Policy: `docs/design-system.md` carries the same carve-out as #3300: nothing moves unless the user acted or an Agent took a note the user can see.

Observer: Vitest `u3784_` cases with `matchMedia` forced; `just capture U3784` for a video of one delivery; the design critic accepts or shortens the duration. Moves: D2, D5, D9.

**U3787 the Terminal is the Agent pane's only prompt input.** Given a Project with two running Agents, when the user selects each Agent and returns to the first, with an empty queue and again with waiting Messages, then the Agent pane renders no `textarea` outside its Terminal. One App-seam test, `u3787_the_agent_pane_has_no_textarea_outside_the_terminal`, asserts this through the existing Pane/App harness, scoped to the Agent pane and excluding only the Terminal emulator subtree. It waits for the selected Agent's Terminal and Message list to be ready before asserting; it must fail against the old note field. The emulator's own input is allowed. U12's existing typing observer continues to prove that vendor input reaches `terminal.write`.
