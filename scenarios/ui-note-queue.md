# UI: an Agent's waiting Messages (U3780 to U3783, U3787; U3784 retired)

Module: `apps/desktop` (the webview); U3782 also owns the existing `crates/messages` drop contract. Ids: U3780 to U3784, U3787. Work Issues: #3305 (queue), #3518 (remove the field). Journey stages: Understand and Intervene (`.agents/data/journey.md`).

The user types to an Agent in Claude Code's own input in its Terminal, with no delivery mode to acquire (B3563a). The waiting-Message queue remains below the Terminal, with a remove action per row. It reads Messages, not a second store; B50 to B52 keep their delivery and transport rules. U3787 retires the separate note field and its draft behavior. U12 and U533 still govern Terminal typing and keyboard focus. Removing a field adds no RPC method or App seam command and changes no Message law.

Contract policy (AGENTS.md rule 4): U3782 changes `message.drop` (B3563b) and every caller in the same PR; no other contract, App command or `GLOSSARY.md` term is added, and the App prose terms go in `copy.ts`. U3782's `drop` of a `pending` Message touches laws M1 (a dropped Message is never delivered, and one with an in-flight record is not dropped), M5 and M6 (`dropped` stays terminal and carries the reason `removed`); `proofs/messages/model.bend` gains the event, `LAWS.bend` weakens no law, and `docs/messages.md` agrees.

Retired by #3563 (B3563a): the Pause and Resume controls, the `Now:` step strip, the `Paused` header and the step-target glide. Stopping a turn is `agent.interrupt`, as before.

**U3780 the queue lists the selected Agent's waiting Messages below its Terminal.** Given an Agent's pane (U12), when it shows, then:

- The queue lists, oldest first (B7), every Message to this Agent in `pending`, whether the user, another Agent, an Extension or the Daemon sent it (B3563b). The list is read from `message.list` and `message.sent`, `message.delivered` and `message.dropped`, never from a second store. Each row shows the Message's first line with `…` when more follows and the whole text as its accessible description; a count `N waiting` heads a queue of two or more. Test: `u3780_the_queue_is_the_agents_waiting_messages_in_order`; `b3563b_pending_messages_stay_in_the_selected_queue` in `apps/desktop/src/terminal/u3780_note_queue.test.tsx` covers two Agents, user and other-Agent rows, id order, event updates, removal on delivery and an empty list, with no Route approval action.
- With no rows and no failure to show, the queue draws nothing: no empty state, strip or reserved height. A failed row action keeps its cause visible beside the queue. Tests: `u3780_an_empty_queue_draws_nothing`; `u3782_remove_drops_one_message_and_keeps_the_rest` retains its failure assertion. The design critic observes the absence of reserved height.
- Selecting another Agent shows only that Agent's queue; switching back restores only the original Agent's waiting Messages. Test: replace the draft-specific part of `u3780_two_agents_never_share_a_queue_or_a_draft` with `u3780_two_agents_never_share_a_queue`.

Observer: Vitest on the existing fake App seam (`apps/desktop/src/terminal/noteQueueHarness.tsx`); the design critic judges D2, D5 and D6 at 1512×950 in dark mode. Captures: `artifacts/ux/U3780/`.

**U3782 each waiting note is removable with ×.** Given a queue of two notes (U3780), then:

- The `×` on a row (a `ui/IconButton` named `Remove note: <first line>`, with a `ui/Tooltip`) calls `message.drop {id}` once; the row leaves when `message.dropped` arrives; the other rows keep their order and focus moves to the next row's `×`, or to this Agent's Terminal when none is left. A note that was `delivered` meanwhile cannot be removed: the `CONFLICT` shows beside the queue and the row goes with `message.delivered`. Test: `u3782_remove_drops_one_message_and_keeps_the_rest`; `u3782_removing_the_last_row_moves_focus_to_the_terminal`.
- Contract: `message.drop` (B3563b) accepts a `pending` Message the user sent, when no in-flight record exists (B39(a)); it becomes `dropped` with the reason `removed`, nothing is delivered, `message.dropped` is emitted, and the same call on a `pending` Message of another sender or with an in-flight record stays `CONFLICT`. Only the user may call it. Tests in `crates/messages/src/tests/`: `u3782_drop_of_a_pending_user_message_sends_nothing`, `u3782_drop_is_refused_once_the_entry_is_in_flight`.
- Retired by #3563: U3782's Pause and Resume clauses (`takeover.begin` and `takeover.end` calls, the `Paused` header, the reachable `Resume` with no rows, the finished-Agent absence) and their tests, `u3782_pause_and_resume_are_takeover_and_show_its_state`, `u3782_resume_remains_reachable_without_rows` and `u3782_pause_stops_no_turn_and_is_absent_for_a_finished_agent`.
