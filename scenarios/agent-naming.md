# Agent naming controls

Acceptance for #4688. Specification only; no implementation or rendered result is claimed. This extends A9 and A28 in `scenarios/agents.md`; those rules remain the fallback and explicit-name contract respectively. Progress and engineering questions belong on the Issue.

Policy — precedence: Automatic renaming defaults on. Off suppresses prompt-derived and title-derived Rail renames, including for already-running Agents, without changing any current name. An explicit name at creation (A28), or an explicit `rail.rename`, remains allowed in either state. User-entered names win over automatic naming. A Door never renames its Workstream automatically. Turning on does not replay an earlier prompt or title. A9 still consumes the first submitted prompt when off: a later prompt cannot become a delayed first-prompt rename. Conversation titles remain separate metadata, as A2681b already requires; on adds no new title-to-Rail rename feature.

Policy — naming guide: an editable natural-language instruction, not an executable template or a parser. The default asks for three hyphen-separated words in role-verb-object order, for example `reviewer-checks-tests`, within A28's 32-character name limit. Exact default wording is presentation copy, not a new validation grammar. A custom guide replaces that instruction; A28 validation and U176 sibling suffixes still apply. The guide shapes names supplied by Agents, never A9's deterministic fallback. Model compliance is an instruction policy; tests observe the instruction delivered and exercise names through real tools, without asserting that a fake model independently follows prose.

**U4688a Global naming controls in Settings.** Given App Settings opened with or without a Project, when the user opens Agents, then a labelled switch exposes Automatic renaming and an associated text field exposes the naming guide. Both have accessible descriptions. With no saved values, the switch is on and the guide conveys the default policy above. The user can change the switch by pointer and keyboard, edit the guide and commit it with Save; typing, blur and navigation do not apply it. Whitespace-only input is refused without replacing the last saved guide, with an accessible cause and correction. A successful save survives App reload and is read by every open Project; opening another Project uses the same values. Changing either preference starts or prompts no Agent and renames no existing node by itself. Off keeps the guide editable and saved for later use.

Observer: planned `u4688a_global_naming_controls` in `apps/desktop/src/settings/`, at the mounted App seam, asserts control semantics, committed values across two Projects and reload, refusal, and absence of launch/prompt/rename calls. Assert associations and effects, not exact wording, default-string equality or geometry. Extend existing persistence proofs where they already assert the same behavior rather than adding duplicate tests (policy).

**U4688b Naming-guide drafts and failed saves remain recoverable.** Given an unfinished guide containing line breaks and non-Latin text, when the user changes Settings page, closes and reopens Settings, changes Project or reloads the App, then the exact draft returns without being applied. Given a save rejected by storage or the Daemon, then the previous committed guide remains effective, the exact draft remains editable, and the control exposes the failure and a retry. A successful retry commits that revision once. An older failed save cannot overwrite a newer draft. During successful typing, nothing outside the field mounts, unmounts or changes its text.

Observer: planned `u4688b_guide_drafts_and_retry` in `apps/desktop/src/settings/` extends the existing settings draft/reload seam, comparing exact draft and saved values and acknowledged save calls, including a newer edit before an older refusal. Extend the existing rendered Settings observer for the outside-field MutationObserver typing probe (policy).

**A4688a The Daemon honours the global switch.** Given two Projects and Agents both running before and started after Automatic renaming is saved off, when their first prompt is submitted and Terminal title observations arrive, then their Rail names are unchanged and no rename event or B2704a rename note is produced for those observations. Given a first prompt already consumed while off, when on is saved and another prompt or title arrives, then no past rename is replayed. Given on and a new unnamed Agent, when its first prompt is submitted, then A9 still produces `fix-refresh-race` from `Fix the refresh race in token.ts`; later prompts do not rename it. A prompt with no eligible words still consumes its first-prompt opportunity without changing the name. Persisted off survives a Daemon restart, applies before the first post-restart observation and is shared by both Projects without an App connection.

Observer: planned `a4688a_global_switch_controls_prompt_renaming` in `crates/rupd/tests/`, through the public settings seam selected by implementation and the real Daemon with fake vendor observations. Count committed Rail names, rename events and notes, covering a Signal parked during startup as well as a running Agent. Keep the existing A9 algorithm tests; do not duplicate their Unicode/truncation proof (policy).

**A4688b Explicit names and manual renames retain precedence.** Given either switch value, when `agent_spawn` supplies `name`, then A28 trims and validates it, U176 adds the first free sibling suffix within 32 characters, and the first prompt never replaces it. Given a user `rail.rename` before the first prompt, including while startup is pending, then it wins over both the fallback and guide-driven self-naming. Given off, when the user explicitly renames an Agent, then the rename still succeeds and B2704a delivers its ordinary note once. Neither prompts nor guide edits rename a Door's Workstream.

Observer: extend `crates/agents/tests/scenarios/naming.rs`'s existing A9/A28/U176 behaviors across switch values, preserving their scenario prefixes; planned `a4688b_manual_rename_while_off_notifies` in `crates/rupd/tests/` checks only the new off/notification interaction. No automatic self-name instruction authorizes replacing a user-entered or explicit spawn name (policy).

**A4688c Agents receive the guide at launch.** Given a saved guide `Use three words: role, verb, object; join them with hyphens`, when an Agent, Door or Scout starts, then its own E3 start-up text includes that guide beside its current Rail name and states whether automatic self-naming is enabled. With on, it instructs an unnamed Agent to choose its own task name through the existing rename capability, respecting A4688b; with off, it instructs it to keep its name rather than rename itself automatically. An Agent already given an explicit name is told to keep it. The `agent_spawn` tool description available to that session includes the same guide for choosing a child's `name`, retaining A28's optional-name fallback and validation. Supplying `reviewer-checks-tests` through the public tool creates that child; omitting `name` retains A9 when on and the current name when off. A child receives the guide in its own start-up text as well.

**A4688d Guide edits preserve the running session's cache.** Given a running session with guide G1, when the user saves G2, then that session's repeated `tools/list`, Brief file and vendor settings file are byte-identical to their pre-edit values; no restart, extra prompt or rename occurs. The next launch, including a new child or a resumed Attempt, receives G2 in its start-up text and session's tool description. A fresh unnamed Agent with no supplied name still uses A9's fallback when on. The switch's Daemon enforcement in A4688a applies immediately; it does not require rewriting a running session's instructions.

Launch a second Agent and resume an exited one to observe G2. Keep variable naming instructions out of the shared Brief file (policy, P9/P10).

## Title-case names and the user's final word

Acceptance for #6380. Specification only; the implementation is built from the Issue once these scenarios are on `main`. Policy — precedence: U6380a to U6380c amend this file's policies and A9, A28, U167 and U176 where they differ. The three-hyphenated-words default and the 32-character limit become the title-case default and 42 characters; "A Door never renames its Workstream" no longer holds. Names already on the Rail stay as they are.

**U6380a Names are title case, at most 42 characters.** Given a fresh Daemon or a stored guide equal to the old default wording, then the naming guide reads "Use distinguishable meaningful name in title-case; at most 42 characters."; any other saved guide is kept. Every name limit is 42 characters: A28's spawn name, a rename and U176's suffix. Names roundup makes are title case: A9 on "Fix the refresh race in token.ts" gives "Fix Refresh Race" (the first three remaining words, each capitalised, joined by a space, cut to 42 characters with no trailing space), a new Agent is "New Agent", a new Workstream is "New Workstream" then "New Workstream 2" (U167), and a sibling suffix is " 2", " 3", within 42 characters. A name of 42 characters is accepted and one of 43 is `INVALID_PARAMS`. Names stay unique among siblings (U176), and Message destinations keep their machine ids (E2704a).

Observer: `u6380a_names_are_title_case_within_42` in `crates/agents/tests/scenarios/naming.rs` (A9 result, 42 and 43 characters, a taken 42-character name's suffix) and `crates/rupd/tests/` (a fresh Daemon's guide, a stored old default read as the new one). Update the `a9_`, `a28_`, `u176_` tests in `crates/agents/src/name.rs` and `crates/agents/tests/scenarios/naming.rs`, and the `u167_` tests in `apps/desktop/src/rail/u167_default_name.test.tsx`, whose strings change; cut any these make redundant (rule 10). No existing row is renamed (policy).

**U6380b A Workstream is named like an Agent.** Given Automatic renaming on and a new Workstream named "New Workstream", when its Door's first prompt "Fix the refresh race in token.ts" is submitted, then the Workstream is renamed "Fix Refresh Race" by A9's rule and `rail.changed` is emitted; a later prompt does not rename it. A Workstream whose name is no longer its placeholder is not renamed. The Door's start-up text carries the naming guide and tells the Door to name its Workstream after its task once, through `rail_rename`. Given Automatic renaming off, then nothing renames the Workstream (A4688a).

Observer: `u6380b_a_door_names_its_workstream` in `crates/agents/tests/scenarios/naming.rs` (first prompt, later prompt, switch off; replaces `a9_a_door_keeps_its_workstreams_name`) and `crates/agents/tests/launch/briefs.rs` (the Door's start-up text holds the guide and the Workstream instruction; extends `a28_a_doors_brief_says_to_name_each_child`).

**U6380c A name the user gave stays until the user changes it.** Given a row the user renamed with `rail.rename`, or created with a name the user typed, then the row is marked as named by the user. The Daemon refuses every automatic rename of it with `FORBIDDEN` "the user named this row; keep its name" and makes no rename event or note: A9's first-prompt rename, a title rename, the Agent's own `rail_rename` and its Door's. The Agent's start-up text says its name is the user's and to keep it. A second user `rail.rename` works and keeps the mark. The mark survives a Daemon restart. Only the user renames it again.

Observer: `u6380c_a_user_named_row_keeps_its_name` in `crates/rupd/tests/` (real Daemon: the Agent's and its Door's `rail_rename` refused with the code and message, name and event count unchanged; A9 leaves a user-named Workstream; a second user rename works; restart keeps the mark) and `crates/agents/tests/launch/briefs.rs` (the start-up text says to keep the name).

## An app-supplied name is not the user's

Acceptance for #6414. Specification only; the implementation is built from the Issue once these scenarios are on `main`. Amends U6380c: only a name the user typed marks a row as named by the user.

**U6414a An imported Agent is named by its first prompt.** Given Automatic renaming on and an Agent that the import flow spawned with its own name "Import", when the user submits that Agent's first prompt "Fix the refresh race in token.ts", then the row is renamed "Fix Refresh Race" by A9's rule and `rail.changed` is emitted; a later prompt does not rename it. The row is not marked as named by the user, so the Agent's own `rail_rename` succeeds, as does a user `rail.rename`, which then marks the row (U6380c). Given a spawn whose name the user typed, then the mark is set and U6380c holds as written. The Daemon tells the two apart by what the caller says, never by the name's text: a name the app supplies is sent without the user-named mark, and an `agent.spawn` with no such statement keeps today's meaning.

Observer: `u6414a_an_app_named_agent_takes_its_first_prompt_name` in `crates/rupd/tests/` (real Daemon: an app-named spawn is renamed by its first prompt, then its `rail_rename` succeeds; a user-typed name stays and `rail_rename` is refused with U6380c's code and message) and a new `apps/desktop/src/rail/importState.test.ts` (the import flow's `agent.spawn` call carries the app-supplied marker; a name typed in the New Agent dialog does not). Extend the U6380c observer's fixture rather than adding another (policy).

**U6463a U6414a's observers hold both sides of the mark.** Given the U6414a fixture, when an app-named Agent has taken its first-prompt name, then its own `rail_rename` succeeds; given an Agent spawned with a name the user typed, then its own `rail_rename` is refused with U6380c's `FORBIDDEN` code and message "the user named this row; keep its name". Given the New Agent dialog submitting a name, then its `agent.spawn` call carries no `appNamed`, while the import flow's call does.

Observer: `u6414a_an_app_named_agent_takes_its_first_prompt_name` (extends the U6380c fixture in `crates/agents/tests/scenarios/naming.rs`) asserts the self `rail_rename` after the rename and the refused `rail_rename` on the user-typed name; `apps/desktop/src/rail/importState.test.ts` asserts the New Agent dialog's spawn has no `appNamed` (policy: no new fixture, no new test file).
