# The Door chooses which children the Rail shows

Specification for #5531. First-journey stages: Understand and Intervene (`.agents/data/journey.md`, **What must work**). This is acceptance for a later implementation, not evidence that the feature exists. Reuse U5483a–c's idle-branch implementation after #5483; its completed-turn protection metadata is already on main, but its rendered folding is not. The earlier lane-wide scope/validation in `scenarios/ui-rail-lane.md` does not govern this slice (policy).

Decision (policy): keep separate internal and idle branches, sharing U5483's projection and Ark TreeView machinery. Internal is a Door's presentation choice; idle is an automatic status/time fold. Shown children retain today's behavior, including U5483's idle fold. An internal child belongs only to the internal branch, even when also idle/done. Neither branch changes Home, Kind or work execution. No child is hidden completely.

**U5531a the Door sets a child's Rail visibility.** Contract acceptance: introduce `RailVisibility` with wire values `shown` and `internal`, `SetVisibilityParams {id, visibility}`, RPC `agent.setVisibility` and Door MCP tool `agent_set_visibility`. `id` names the child, never the caller; caller identity comes from the authenticated connection. The method returns the updated `RailNode`, whose `visibility` carries the choice; absent data on an old stored node means shown. Add these code spellings to `GLOSSARY.md` in the implementation PR, with user labels `shown` and `internal`; this specification declares no executable method or generated contract (policy). Visibility is distinct from Home/Placement.

Given a Door and its direct Agent children, when its tool marks one internal, then the result and `rail.tree` report internal; marking it shown returns shown. Repeating the same choice succeeds without duplicating or moving the child. The choice survives Daemon restart and Project reopen, without starting a program. Test: `u5531a_door_tool_round_trip_and_reopen` in `crates/rup/tests/mcp.rs` (planned), extending check 3's real-Daemon/stdio MCP fixture with a fake vendor. Read authoritative Rail state, not a mock setter. Preserve id, parent, sibling order, Attempt and Terminal identity across each call and reopen; compare launch counts before/after reopen.

Given a non-Door Agent, another Workstream's Door, or a target that is the caller, a Workstream or a nested child rather than that Door's direct child, when it calls the method, then the call is refused with `FORBIDDEN`, changes nothing and emits no mutation event or wrote Touch. Unknown ids are `NOT_FOUND` before authority checks. A malformed visibility is `INVALID_PARAMS`. The tool is offered only to Doors; direct RPC checks enforce the same boundary. User and Extension calls retain their existing authority over Agent nodes, but cannot mark a Workstream internal. Test: table-driven `u5531a_visibility_authority_is_enforced_by_the_daemon` in the same MCP file, including an RPC attempt bypassing the tool list, permitted User/Extension calls on Agent nodes and refusal for Workstream targets. Existing M7 reference resolution applies, without broadening Reach (policy).

Given F3's `agent_spawn`, when a Door supplies optional `visibility: internal`, then the first returned/published child node is internal, without a transient shown node. Omission and explicit shown start shown, including old callers' JSON. Other Agents retain F3's ability to spawn shown children but cannot supply internal; refusal creates no child or program. Test: `u5531a_spawn_visibility_is_atomic_and_defaults_shown` in the same MCP file, comparing results, tree/event nodes and launch counts. F3's parent fixing, order, name and Model rules remain unchanged (policy).

Existing data defaults shown; persist explicit changes through existing Project data. No new App command is needed. An existing child moved by the user out of this Door's Home resets to shown and immediately leaves its former internal branch; the former Door loses authority. Test: `u5531a_user_home_move_clears_the_old_doors_visibility` in the existing `crates/agents/tests/scenarios/rail.rs` harness. Do not change Message, Route, Held or Takeover semantics; laws M1–M10 remain unchanged, as do `proofs/messages` and `docs/messages.md` (policy).

**U5531c attention returns an internal child to the shown list immediately.** Given an internal child, when it becomes needs-you or error, gains an unanswered outgoing question Message or a Clarification order, or gains U5483c's completed-turn protection, then its authoritative visibility becomes shown and the next rendered update places it outside both folded branches, without waiting for an idle timer or disclosure. The count decreases in that update; the zero-count branch disappears. A collapsed Workstream retains its normal attention rollup and user-controlled disclosure; promotion does not force it open. Test: table-driven `u5531c_attention_promotes_internal_children_without_a_timer` in the visibility test file. Reuse U5483c's authoritative Agent/Attempt/turn evidence, including nonempty final assistant text and unknown completed-turn text; do not add punctuation classification, Terminal parsing, another question service or native answer UI (policy). Initial working children can be internal; absence of a completed-turn observation while working is not itself a question.

Given that promotion, when attention is answered or the child resumes working, then it stays shown until the Door explicitly marks it internal again. Calling internal while native attention, error or U5483c protection is still active returns `INVALID_PARAMS` naming the active reason, with no mutation; shown always remains available. After work resumes and the protection is cleared under U5483c, a new internal call succeeds. Test: `u5531c_promotion_stays_shown_until_a_new_safe_door_choice` in `crates/rup/tests/mcp.rs`, using authoritative state transitions and checking RPC outcomes and Rail serialization. Done/idle alone does not promote an internal child with authoritative known-empty final text and no question. Test: `u5531c_known_empty_settled_internal_child_stays_internal` in the visibility test file. This safety rule deliberately preserves U5483c's conservative treatment of ordinary final statements (policy).
