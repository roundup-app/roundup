# A stop that asks the user something shows `needs-you` (A7180a to A7180e)

Modules: `crates/agents` (`stop_judge.rs`, `claude_code/`, `events.rs`) and `crates/messages` (`delivery.rs`). Ids: A7180a to A7180e.

Source: the owner, 2026-11-15 (#7180): children in a Workstream asked a question in their last message, went `idle`, and the owner had to hunt for them. Amends P3 (`PRINCIPLES.md`) and A5482c (`scenarios/native-questions.md`) in this PR. Words: a **stop** is the end of an Agent's turn; the **last message** is the text the vendor reports for it (A5482c's seam).

**A7180a rules read a stop's last message.** Given any Agent (a Door, a Workstream's Agent, a Mode or a child) whose turn ends with nothing holding it, then its last message is read by rules, with no model call. A question, a list of choices or a statement that the Agent waits on the user makes it `needs-you`; a report of finished work leaves it `idle`; anything the rules cannot tell goes to A7180b. The rules read only the closing paragraph (and the paragraph above a closing list) of the last 4000 bytes, skip code, and do not count a `?` inside a URL. A phrase of the rules' ask lists in a sentence that negates it ("nothing", "no", "not", "n't", "never" or "nobody" before the phrase) never makes the Agent `needs-you` by the rules alone: the rules read it as a report, or hand it to A7180b. "Nothing is waiting on you.", "Nothing needs you right now.", "No input needed from you.", "I don't need you to do anything." and "Not blocked on you." leave it `idle`; "I'm waiting on you to pick one." and "Should I ship it?" make it `needs-you`. Tests: `a7180a_a_denied_ask_is_no_ask`, `a7180a_rules_tell_an_ask_from_a_report`, `a7180a_a_long_label_is_cut`, `a7180a_a_stop_that_asks_shows_needs_you_with_its_question`, `a7180a_a_stop_that_reports_stays_idle_and_calls_no_model`. Observer: `cargo nextest run -p agents`, a fake model that counts its calls.

**A7180b one model call reads what the rules cannot.** Given a stop the rules cannot tell, then the Agent shows `idle` meanwhile, and one `claude -p` call on Haiku (A39's one-shot seam) answers within 20 s whether the message asks the user something. An answer that asks makes the Agent `needs-you` with that question. A failed call, a late answer or an answer that asks nothing leaves it `idle`; a failure is logged with its cause, on stderr and as a line of `stop-check.log` in the Daemon's state directory (its last 200 lines, as `links.log` keeps them, LH17), holding the time, the Agent's id and name and the cause, none of the message. The limit is 20 s because the real call took 5.5 to 10 s wall (API 1.9 to 4.1 s) on the owner's Mac, where 3 s killed every one (#7965); an unclear Stop therefore reads `idle` for up to 20 s, typically 6 to 10 s, then turns `needs-you` if the answer asks; the call holds no lock, so no other Agent, Status or event waits. An answer for a turn the Agent has left changes nothing. Tests: `a7180b_an_unclear_stop_shows_idle_then_the_models_question`, `a7180b_a_model_that_fails_or_finds_no_ask_leaves_the_agent_idle`, `a7180b_an_answer_after_3_s_and_within_the_limit_shows_needs_you`, `a7180b_a_late_answer_leaves_the_agent_idle` (a fake model past 20 s), `a7180b_a_failure_is_written_to_the_stop_check_log`, `a7180b_an_answer_for_a_turn_the_agent_left_is_dropped`. Observer: `cargo nextest run -p agents` with a fake model and a paused clock; the real Haiku call is not run in a test (P9).

**A7180c the label says what it asks, and the next turn clears it.** Given a `needs-you` from a stop, then its label is `asks: ` and the question, at most 120 characters. Any later turn (a prompt, a tool call, a Message) moves the Agent on from it. The Agent sits at its prompt, so a Message to it is delivered, and a lead's `note` answers a child's question as A5482c says; a native dialog's `needs-you` still takes no Message and no Agent's Terminal writes. The owner may also mark it done (U7915a). Tests: `a7180c_the_next_turn_clears_needs_you`; delivery is held by the existing A5482c observers `a5482c_plain_text_question_reaches_the_lead_and_gets_an_inbox_answer` and `a5482b_owner_answers_only_in_the_leads_terminal`. Observer: `cargo nextest run -p agents` and `-p rupd`.

**A7180d every turn-ending path reads it the same way.** Given a stop that background work holds `working` (DCL3), when the work ends, then the Agent shows `needs-you` if its last message asked, else `idle`. Tests: `a7180d_a_stop_kept_working_by_a_process_shows_needs_you_when_it_ends`. Observer: `cargo nextest run -p agents`.
**A7180e a closing `card` block with questions is an ask.** Given a stop whose last message ends with a fenced ```` ```card ```` block (the hunch card `merge_cards` reads in `crates/agents/src/claude_code/conversation.rs`) whose JSON holds a non-empty `questions` list of strings, then the Agent is `needs-you` by rules, with no model call, labelled with the first non-empty question (A7180c's cut). A card whose `questions` is empty or missing, a card that is not the last block, or one whose JSON does not parse is no ask by this clause, and the rules read the rest as A7180a says. Tests: `a7180e_a_closing_card_with_questions_is_an_ask`, `a7180e_a_card_without_questions_is_no_ask`. Observer: `cargo nextest run -p agents`, a fake model that counts its calls.

Policy: no change to what an Agent outputs or is told; no model call when the rules decide; no new Status kind; no new RPC or contract. Gates (policy): P3 — a report stays `idle` and raises nothing; only an ask raises `needs-you`. P4 — the vendor's hook payload is read only in `crates/agents/src/claude_code`; `stop_judge.rs` takes text. P9 — the model call spends usage only for a stop the rules cannot tell, and the Issue asks for it.
