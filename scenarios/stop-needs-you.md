# A stop that asks the user something shows `needs-you` (A7180a to A7180d)

Modules: `crates/agents` (`stop_judge.rs`, `claude_code/`, `events.rs`) and `crates/messages` (`delivery.rs`). Ids: A7180a to A7180d.

Source: the owner, 2026-11-15 (#7180): children in a Workstream asked a question in their last message, went `idle`, and the owner had to hunt for them. Amends P3 (`PRINCIPLES.md`) and A5482c (`scenarios/native-questions.md`) in this PR. Words: a **stop** is the end of an Agent's turn; the **last message** is the text the vendor reports for it (A5482c's seam).

**A7180a rules read a stop's last message.** Given any Agent (a Door, a Workstream's Agent, a Mode or a child) whose turn ends with nothing holding it, then its last message is read by rules, with no model call. A question, a list of choices or a statement that the Agent waits on the user makes it `needs-you`; a report of finished work leaves it `idle`; anything the rules cannot tell goes to A7180b. The rules read only the closing paragraph (and the paragraph above a closing list) of the last 4000 bytes, skip code, and do not count a `?` inside a URL. Tests: `a7180a_rules_tell_an_ask_from_a_report`, `a7180a_a_long_label_is_cut`, `a7180a_a_stop_that_asks_shows_needs_you_with_its_question`, `a7180a_a_stop_that_reports_stays_idle_and_calls_no_model`. Observer: `cargo nextest run -p agents`, a fake model that counts its calls.

**A7180b one model call reads what the rules cannot.** Given a stop the rules cannot tell, then the Agent shows `idle` meanwhile, and one `claude -p` call on Haiku (A39's one-shot seam) answers within 3 s whether the message asks the user something. An answer that asks makes the Agent `needs-you` with that question. A failed call, a late answer or an answer that asks nothing leaves it `idle`; a failure is logged with its cause. An answer for a turn the Agent has left changes nothing. Tests: `a7180b_an_unclear_stop_shows_idle_then_the_models_question`, `a7180b_a_model_that_fails_or_finds_no_ask_leaves_the_agent_idle`, `a7180b_a_late_answer_leaves_the_agent_idle`, `a7180b_an_answer_for_a_turn_the_agent_left_is_dropped`. Observer: `cargo nextest run -p agents` with a fake model and a paused clock; the real Haiku call is not run in a test (P9).

**A7180c the label says what it asks, and the next turn clears it.** Given a `needs-you` from a stop, then its label is `asks: ` and the question, at most 120 characters. Any later turn (a prompt, a tool call, a Message) moves the Agent on from it. The Agent sits at its prompt, so a Message to it is delivered, and a lead's `note` answers a child's question as A5482c says; a native dialog's `needs-you` still takes no Message and no Agent's Terminal writes. Tests: `a7180c_the_next_turn_clears_needs_you`; delivery is held by the existing A5482c observers `a5482c_plain_text_question_reaches_the_lead_and_gets_an_inbox_answer` and `a5482b_owner_answers_only_in_the_leads_terminal`. Observer: `cargo nextest run -p agents` and `-p rupd`.

**A7180d every turn-ending path reads it the same way.** Given a stop that background work holds `working` (DCL3), when the work ends, then the Agent shows `needs-you` if its last message asked, else `idle`. Tests: `a7180d_a_held_stop_that_asked_shows_needs_you_when_the_work_ends`. Observer: `cargo nextest run -p agents`.

Policy: no change to what an Agent outputs or is told; no model call when the rules decide; no new Status kind; no new RPC or contract. Gates (policy): P3 — a report stays `idle` and raises nothing; only an ask raises `needs-you`. P4 — the vendor's hook payload is read only in `crates/agents/src/claude_code`; `stop_judge.rs` takes text. P9 — the model call spends usage only for a stop the rules cannot tell, and the Issue asks for it.
