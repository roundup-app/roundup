# Project tabs: the header is a strip of open Projects (#653)

Module: `crates/desktop` (S8–S10) and `apps/desktop` (the webview; U179–U186). Ids: S8, S9, S10, U179, U180, U181, U182, U183, U184, U185, U186, U382, U6239a, U6239b, U6239c, U6239d, U6371a, U6371b, U6544a, U6544b, U6544c, U6993. Decided by the user (2026-10-10, #653): "roundup" leaves the header; the header becomes horizontal tabs, one per open Project, each with only the Project's name and one circle; no boxes, borders or underline; counts stay off the tab. Chromium shows the webview against the fake App (as U131 does), so the observer is a rendered page, never a native Mac capture (#389).

The App holds several Daemons, one per open Project, so the App seam and the Daemon's lifetime change, not only the header. This is a contract change (rule 4, the Contract recipe of `.agents/builder.md`): S8 changes every caller in one PR, and `GLOSSARY.md` holds **Project tab** and **Tab mark** (added with this file). Ids stay per Project (G7); nothing in `contracts/` changes and no Daemon method changes. Native macOS window tabs are not used: Tauri 2.12.1 does not expose AppKit's `NSWindowTab.accessoryView`, so a native tab cannot carry the circle and the strip lives in the webview.

Engineering calls, each made here so the implementation run asks nothing:

- **Several Daemons.** The App keeps a map from Project path to its running Daemon and socket (S1's rules per entry). A Daemon is the Project's; closing its tab ends it (S8).
- **Keys.** `⌘1`/`⌘2` stay the focus keys (U41) and `⌥1..9` reach the Terminal (U12); the tab strip takes neither. Tabs take `⇧⌘[` and `⇧⌘]` (previous and next, the Safari, Ghostty and Warp convention) and `⇧⌘J`. `⌘J` stays inside the open Project, because its count is the one the user sees. `⌃Tab` is not taken (the HIG lists it as a focus move).
- **Overflow.** Names shorten with `…`, then the strip scrolls; a hidden tab with a circle is still shown at the strip's edge (U184).
- **Order.** Tabs keep the order they were opened in, and a new tab goes last; no key or drag reorders them, and attention never does (wireframes decision 3).
- **The name.** Stored per Project path in the App's data folder beside `recent_projects` (S10); no better owner exists, because the Daemon would need a Project it has not opened and the webview's saved state (U100) is per window.
- **A restart** reopens the Projects that were open, in their order, with the one that was open last selected (S10, U186).

## App seam, several Projects (S8, S9, S10)

**S10 names and the open list survive a restart.** Given the App's data folder (S6), then:
- `rename_project {path, name}` for an open Project stores `name` for that path, trimmed, and returns `{name, path}`; afterwards `projects`, `open_project` and `recent_projects`' consumers show it. A name of 1 to 40 characters is stored; an empty or all-space name removes the stored name, so the Project is named after its folder again (S1); a longer name or one with a line break is `INVALID_PARAMS` naming the limit. A path that is not open is `CONFLICT`. The stored name is per path, so the same folder always comes back with its name.
- The open Projects, in order, are stored in the data folder when `open_project` or `close_project` succeeds. At launch the App starts a Daemon for each stored path that is still a directory, in order, one at a time, then for `roundup <project>` when given (selected last: it ends the list, or keeps its place when already there). A path that no longer is a directory is dropped. A Daemon that fails to start leaves its Project in `projects` with `running: false`, so the tab shows U25's state and `Reopen`; it never stops the others from opening or the App from launching.
- A failed write of the names or the list never fails the call (S6). Tests (`s10_`) use a temporary data folder and a fake `rupd`: rename and restore, the limit, the empty name, the stored order after open and close, a vanished folder, one failing Daemon among three.

**U179 the header is the strip.** Given the App, then the header holds no `roundup` text and no Project text outside the strip. Each tab is `role="tab"` in a `role="tablist"`, the open one has `aria-selected="true"`, and the Mark has a text `aria-label` (`Needs you` or `Error`) so colour is never the only cue. **U180 the Tab mark.** Given the Kinds of the Agents in a Project (`rail.tree`, as U10 counts), then its tab shows one mark: `◉` in red Ink when any Agent has Kind `error`; else `●` in amber Ink when any has Kind `needs-you`; else nothing. `●` is the Rail's own needs-you Glyph. `◉` is not the Rail's error Glyph `✕`: the ring is the tab's own shape for error, so the mark stays distinct from `●` without colour. A plain ring `○` is never a Tab mark, because `○` means working in the Rail (U4). A Door counts as an Agent as U10 does; Terminals never count (U164). The mark is one character, the same size on every tab, and never carries a number. Every open Project is counted, not only the one on screen, from its own Daemon's `rail.tree` and `rail.changed` (U179's webview subscribes to each Project: `subscribe {path}`). The mark clears at once when the Agent's need is answered (`PRINCIPLES.md` P3) or its Kind changes; there is no snooze and no dismiss. The ambient mark never animates; the one ~400 ms pulse of a Kind becoming `needs-you` (`docs/motion.md`, "Needs-you arrival") is unchanged and runs on the Rail row only. Tests (`u180_`): error over needs-you, needs-you alone, working and blocked and idle and done give nothing, a Terminal gives nothing, a background Project's mark, the mark clearing when the Agent's Kind changes, the characters and Inks, no number.

**U181 clicking a tab.** Given two or more open Projects, then a click on a tab's name makes that Project the open one: the Rail, the Shelf and the pane show that Project (each Project keeps its own selection, collapsed Groups and drawer state, as U100 keeps them), and no call is made to a Daemon that is not shown.
