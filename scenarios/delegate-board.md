# The Delegate Board: hand Todos to Agents (A3308, U3308 to U3311)

Module: `crates/todos`, `crates/agents`, `crates/rupd`, `crates/rup`, `crates/contracts`, `contracts/generated/` and `apps/desktop`. Ids: A3308, U3308, U3309, U3310, U3311, T4902. Acceptance for #3308, amended by #4902: Auto lets the Door pick each unassigned Todo's owner and may start a Subagent for it, every hand-off showing as it happens. Todos have no duration field or availability calculation. Builds on U3717 to U3720 (Todos grouped by owner), T16/T17 (`owner`, `todo.assign`), A3195 (Workstream cap) and the existing carve-out for Agent hand-off motion. The look is rebuilt from AffectUI's public Delegate Board docs (`https://www.affectui.com/llms-full.txt`); no code is copied (policy). Drag stays on the existing `@dnd-kit/solid` through `ui/sortable.tsx` (policy). This specification retires T29 and U3365; implementation acceptance follows below, with planned tests explicitly named.

**A3308 Auto lets the Door hand out unassigned Todos.** Given a Workstream with its Door running, when the user calls `workstream.setAuto {id, auto: true}`, then `auto` persists on the Workstream (default `false`, also after a current-schema Daemon restart; N5467d retires the Workstream-before-field adoption clause and `a3308_an_old_workstream_defaults_to_auto_off`), `rail.tree` carries it, and `workstream.updated` is emitted once; setting the value it already has changes nothing and emits nothing; an unknown id is `NOT_FOUND`. While `auto` is true, each open Todo in that Workstream with `owner: null` reaches its Door once as a plain-text Message (B33) naming the Todo id and title; Todos already unassigned when Auto turns on reach it too, in T10 order. The Door answers with `todo.assign {id, owner}` for an Agent of that Workstream (recorded in the Todo's history as T17 says), or starts a Subagent (A7) that it then assigns the Todo to; the Subagent start obeys the Workstream cap (A3195) like every start. A Todo owned by `Actor::user()` never moves under Auto, nor does one already owned by an Agent. With `auto` false nothing is sent, and turning it off stops further Messages (hand-offs already made stay). A Todo is sent once per time it becomes unassigned: a restart replays nothing already sent. Each hand-off emits `todo.updated` like any assign, so the Board shows it as it happens (U3311). Tests: `a3308_set_auto_persists_and_emits_once`, `a3308_auto_on_sends_each_unassigned_todo_to_the_door_once`, `a3308_me_and_agent_owned_todos_never_move`, `a3308_auto_off_sends_nothing`, `a3308_a_restart_resends_nothing`, `a3308_the_door_assign_is_recorded_in_history`, `a3308_a_subagent_start_obeys_the_cap`.

**U3309 hand a Todo to an Agent by number key or Assign.** _The Return lift/drop clause is replaced by U3789e (`ui-shelf.md`), as ordered by #3816; Return opens the Todo (U3789a)._ Narrows U152 and U3720. Given the Todos tab with a Todo row button focused, then each Agent header shows a digit 1 to 9 by its name in Rail order (a tenth Agent shows none); a plain key `1` to `9` (no `⌘`, `⌃`, `⌥`, no `⇧`; registered in the registry's Shelf scope, listed in Help and the key hints, never a local `keydown` listener, policy) calls `todo.assign {id, owner}` once with that Agent's Actor and nothing else; a digit with no Agent does nothing; the Todo's own owner does nothing and calls nothing. `o` on the focused row, or Assign in its native menu, opens the existing owner picker (U3720); arrows choose a destination, Return assigns once, and Escape cancels without a call and returns focus. These keys do nothing in a text field, on a done Todo's row or with a modifier held. A refused assign shows `✕ <message>` as U3720 says and the Todo stays in its group. `o` and the Assign word of U3720 keep working. Tests (`u3309_`): `u3309_a_digit_assigns_to_that_agent_once`, `u3309_a_digit_without_an_agent_or_for_the_own_owner_calls_nothing`, `u3720_choosing_assigns_once_and_returns_focus_to_the_row` and `u3720_esc_and_click_outside_close_and_restore_focus`, `u3309_focus_returns_to_the_row`, `u3309_the_keys_are_inert_in_fields_with_modifiers_and_on_done_rows`, `u3309_the_digits_are_registered_shelf_bindings_listed_in_help`.

**U3310 the Auto switch.** Narrows A3308. Given the Todos tab in a Workstream's scope, then a labelled switch `Auto` (role `switch`, Ark UI through `ui/`, `aria-checked` the Workstream's `auto`) sits in the tab's head with the text `Door hands out unassigned Todos`; pressing it (Space or click) calls `workstream.setAuto` once with the new value and shows the new state after `workstream.updated`, not before. In the Overview or a scope with no Workstream the switch is absent. A refused call keeps the old state and shows `✕ <message>`. While Auto is on, an Unassigned group reads as handled by the Door (`the Door is handing these out`).
