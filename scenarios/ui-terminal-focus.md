# Terminal input follows keyboard focus

Module: `apps/desktop`. Ids: U5552a–U5552f. Acceptance for #5552; this specification delivers no fix or reproduction claim. Journey: Intervene (`.agents/data/journey.md`).

Policy: a user input action belongs to the visible Terminal whose emulator owns keyboard focus, or to the focused editable field. A selected Rail row, a cached Terminal id, a mounted emulator or a hidden xterm textarea is not authorization to receive input. Clicking or using an existing keyboard switch to open an Agent's Terminal must hand focus to that Terminal before it takes input. Restoring other Terminals must not take that focus. Keep the existing direct-access shortcuts; add no control mode.

Policy: audit every App path for typed keys, IME commit, text paste, pasted images, dropped files and Ask sends, following each to its delivery boundary. Fix every path that can admit user Terminal input without that Terminal owning focus. Preserve the identity of bytes already accepted while focused; a later switch must never retarget them. Focus is required when accepting new user input, not a reason to replay or redirect an earlier accepted write. Background program output and protocol replies are not user input. Existing authorized Daemon prompt/Message/Ask placement contracts remain: Ask is an explicit placement request, not a direct Terminal paste, and Messages never type into a Terminal. No RPC or App seam extension is prescribed.

## Acceptance

**U5552a paste after restart reaches only the focused program.** Given one real temporary Project with at least two running Agents whose distinct fake vendor programs record received input, and the actual App with real xterm emulators, open both Terminals and reload the webview while keeping the Daemon and programs alive. When the user clicks to open the first Agent's Terminal and pastes distinctive multiline Unicode text, then only its program receives that text, once and in order. Repeat for the second Agent using the existing keyboard switch, then switch back by click and paste a third distinct payload. Each action reaches only its focused program; the other program's input log is unchanged. Test to implement: `u5552a_restored_paste_reaches_only_the_focused_program`. Use the existing real-Daemon harness and an isolated headless agent-browser session with a fresh profile; pass text through the production clipboard module's DOM/platform edge, not `emulator.paste`, `onInput` or a direct write RPC. Assert actual program input as well as per-id write calls; distinguish bracketed-paste framing from the payload. Wait for focus ownership and program receipts, never fixed sleeps. Record that webview reload observes restoration, not a native App restart.

**U5552b an unfocused Terminal cannot admit user input.** Given two mounted Terminal emulators, with B focused after A and B have both been shown, when A's retained input callback emits new bytes, then there is no write to A or B. The same holds with A still visible but focus in an editable field, and with A hidden. B's focused callback still delivers its bytes exactly once to B. Test to implement: `u5552b_unfocused_terminal_cannot_write`, a table-driven App-seam test with injected emulator callbacks, no browser or Daemon process and no real clock. This is the cheap CI guard for the class; it must fail if the production focus admission check is removed, rather than asserting a helper or test double alone.

**U5552c keys and IME keep the focus destination.** Given the mounted App and two running Agent Terminals, when switching by click and by keyboard and entering ordinary keys or committing an IME composition in the newly focused Terminal, then only that Terminal receives the resulting bytes once, in order. An unfinished composition in the former Terminal cannot commit into either Terminal after focus leaves it. Test to implement: `u5552c_keys_and_composition_follow_focus`, parameterized at the App/emulator seam for key and composition paths. Exercise the production key/composition handlers; invoking only a fake emulator's input callback proves U5552b, not this clause. Keep existing composition and Shift-Enter rules.

**U5552d paste cannot escape its focus owner.** Given two running Terminals with real emulators in the mounted App, when pasting text or an image into the focused Agent, Door or shell Bubble, then one paste reaches only that Terminal, with U418's saved-image path and U175's framing. Given focus moves to another Terminal or an editable field while clipboard decoding or image saving is pending, when that operation completes, then it writes to neither Terminal, steals no focus and does not replay when the old Terminal is reopened; the existing feedback offers a fresh paste in the intended Terminal. Test to implement: `u5552d_paste_keeps_focus_owner`, parameterized over text/image and unchanged/moved focus at the injected platform edge. Use the production clipboard module and record image-save calls, actual emulator bytes and write ids; do not replace the module. Existing selection replacement and native editor undo remain policy. `u101_chords_leave_other_fields_to_the_browser` remains the zero-Terminal-write observer for an editable field.

**U5552e a drop focuses its destination before writing.** Given two running Terminals and a focused editable field or the other Terminal, when a native file drop lands on the visible Terminal's unobscured body, then that destination takes keyboard focus before its paths are accepted and receives the quoted paths once, with no newline and no write to the other Terminal. A drop on a hidden or covered Terminal writes nothing and steals no focus. Test to implement: `u5552e_drop_focuses_only_its_destination`, through the existing App file-drop edge and real emulator; assert focus at the write boundary, destination and bytes. This refines U162's focus-return ordering; its outside-pane, empty, exit, quoting and no-refit rules remain.

**U5552f Ask cannot leak into Terminal input.** Given two previously opened Agent Terminals and the Ask field focused, when pasting or typing into Ask, then no Terminal receives those bytes. When explicitly sending that Ask, then one `ask.send` carries the captured text and placement identity, with zero App `terminal.write` calls and no transfer of focus to a hidden Terminal. Test to implement: `u5552f_ask_has_no_direct_terminal_write`, through the mounted App seam, asserting both the request and the absent direct writes. Existing authorized Ask placement and Daemon delivery remain unchanged; the focus audit follows that path and records its distinction from emulator input on the Issue.

## Gates and observers

P11's gate asks whether a changed input path loses or alters unfinished work or its original recipient, sends on restore or changes focus during background restoration. Observe exact payloads, recipient ids, write counts and focused elements in U5552a–f; retain existing draft recovery and Ask placement contracts. No vendor editor reconstruction or new draft persistence is ordered.
