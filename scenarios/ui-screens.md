# UI: Settings sections and requested screens

Acceptance for #4277. This specification delivers no implementation. Scope: `apps/desktop/src/settings/`, the Changes draft recovery view and the screen modules audited below. Existing App seams, persistence, Tokens and `ui/` primitives remain the implementation boundaries; no new RPC, App command, domain term or motion is requested (policy).

**U4277a Settings has reachable sections and a bounded content column.** Given Settings opened through its existing menu event or `⌘,`, with or without an open Project, when the user clicks each section, then Agents, Terminal, Shortcuts and Appearance are reachable in that order, and the corresponding controls are available in the selected section. Given focus on the section list, when the user presses ArrowDown or ArrowUp, then focus and the selected section move together to the adjacent section, and Tab reaches that section's controls. Use the installed Ark vertical Tabs semantics through a shared `ui/` primitive, including its selected state and panel association (policy). Observer: `u4277a_sections_work_by_pointer_and_keyboard`, planned at the mounted App seam beside `apps/desktop/src/settings/u3799_app_settings.test.tsx`, exercising all four sections and both Project states. Opening again keeps one Settings view; closing or Escape with no child picker open returns to the preceding center and focus, under the existing U3800 observer (policy).

Policy: the section list sits beside one content column; the selected section's form width is at most `--measure`, further bounded by the available center width. The list, labels, values, disclosures and recorder fit at 1512×950 without horizontal scrolling or clipping. The critic measures this width against the Token in `apps/desktop/src/tokens.css`, not a new hard-coded limit. This refines U3799's four-group presentation into four sections; it does not remove any group's settings or change their app-wide meaning.

Policy: selectors use the shared Ark Select or existing searchable Combobox as appropriate; font size uses the installed Ark NumberInput, font fields use Ark Field, and the shortcut recorder has a labelled, focusable designed control with distinct resting, recording and refusal states. New wrappers belong in `ui/` and wrap the installed components rather than implementing replacement state machines. All control styling uses Tokens and the existing button kinds, without browser-default select chrome, boxed hover backgrounds or local style overrides of library behavior. Read installed capabilities first; any added machinery carries rule 9's Reuse evidence in the implementation PR.

Given a selected section, when the user chooses a permission mode, engine/model or appearance mode, commits a valid font family/size, records a valid shortcut, cancels recording, resets it or enters an invalid size/clashing chord, then the setting, refusal, cancellation and persistence outcomes remain those of U3801–U3806. Retarget their existing observers to navigate to the relevant section before interacting; do not duplicate their proofs (policy). Given exact uncommitted font text, when the user changes sections and returns, then the text remains without applying it merely by restoring the section; `u4277a_section_navigation_keeps_unsubmitted_font_text` is a planned mounted App-seam observer beside the existing preferences tests. Preserve Enter/blur commit behavior and existing close/reload retention; section navigation does not authorize discarding a draft (policy).

**U4277b Recover Changes drafts has a real empty state.** Given an open Project with zero Changes drafts, including no forms, notes, submissions, recovered revisions, unreadable retained records or retention error, when the user opens Recover Changes drafts through the existing Project menu command, then recovery remains open until explicitly dismissed and exposes no Copy action or draft-row actions. Observer: `u4277b_empty_recovery_has_no_copy_action`, planned beside `apps/desktop/src/changes/u2540b_notes.test.tsx` through the mounted App seam. Policy: the body renders exactly one empty-state line, `No drafts to recover`, instead of a blank row or serialised empty record. Its heading appears inside its own surface; no duplicate recovery trigger/title leaks below or outside that surface. Close/Escape retains the existing focus-return behavior (policy).

Given retained Changes work, when the user opens recovery and copies a chosen record, then the clipboard retains that record's exact text and original Project/recipient identity, and opening or copying sends nothing. Existing U2773e recovery-action observers remain the proof; navigate through the Project menu where needed rather than adding a duplicate test (policy). Empty-state classification never hides unreadable retained work or a retention failure: their existing recovery actions remain usable and their cause remains visible (policy). A filled recovery still permits its existing resume/discard operations and never discards another revision; the existing Changes retention observers below remain required (policy).

**U4277c every requested Project-menu screen is audited.** Policy: open Ask history, Resources, Made, Workstreams, Terminal tabs and Import Claude Code Work through their existing Project-menu App seam, as well as Settings and Recover Changes drafts. Audit each for the same three faults: content/form columns expanding beyond `--measure` or the available center/surface; unstyled native fields rather than the appropriate shared library control; and empty data rendered as blank content rows or actions with nothing to copy/open. Long authored values may wrap or use the existing truncation/full-value affordance; they cannot widen the screen or cover its controls. Do not constrain a Terminal's program-authored grid to prose line width (policy).

For each screen, exercise zero records and a nonempty fixture: Ask entries, resources for an eligible selected Agent, Made publications, Workstreams, Terminal tabs and Import candidates respectively. Resources' empty fixture keeps an eligible Agent selected so its menu command is enabled. Filled fixtures use distinct item identities and long names; Import includes selection and a partial-failure result. A loaded empty state has one meaningful empty-state line, no placeholder content row and no content action without a target; real creation, refresh, close and recovery actions remain available. Loading and failure are not successful empty results (policy). Empty-state wording and layout are critic evidence, not exact-copy or geometry assertions in UI tests (policy).

Policy: record each screen's caller, empty/filled capture locations, each fault and its disposition on #4277. Fix every discovered fault in the implementation PR, or file one child work Issue listing all remaining faults with affected screens/files, concrete reproduction inputs, acceptance and named observers. Link that child from #4277; no remainder is recorded only in a PR body or scenario Work table. The deferral option applies to the other six audited screens, not U4277a/b. Audit and before/after captures still cover every screen even when a repair is deferred. For repaired behavior not already proved, add only the uncovered interaction/role/call-count assertion beside that screen's existing tests, with the `u4277c_` prefix; a visual-only repair needs critic evidence, not a new test (policy).
