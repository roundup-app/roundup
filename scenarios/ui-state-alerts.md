# UI: state choices and per-Agent alert levels (U5232a to U5232k, U5501)

Modules: `crates/desktop` (the App seam command, U5232f, U5232g) and `apps/desktop` (`rail/DockBadge.tsx`, `settings/`, the attention dispatch). Ids: U5232a to U5232k.

Source: the owner studied Rex (Superlogical's Mac terminal multiplexer; https://www.superlogical.com/rex/docs/llms-full.txt), where each program state picks its own notification, sound and badge and the notification opens the session; the owner accepted this lesson on 2026-10-31 (#5232). Implementation: #5233 (App, `crates/desktop`), then #5234 (webview). Narrows U10 and U182 (the Dock badge counts the states the owner chose), U410 and U413 (the Toast's sound follows the same choice) and `docs/wireframes.md` decision 4 ("no macOS banners"); amends P3 (`PRINCIPLES.md`) in this PR. Words: a **State alert** is the macOS banner roundup raises for an Agent whose Kind became a state the owner turned it on for (`GLOSSARY.md`); "notification" is the Avoid word of Signal. The five states are the Kinds `working`, `blocked`, `needs-you`, `error` and `done`; `idle` has no choice and raises nothing.

**U5232a defaults keep today's behaviour.** Given a fresh App, then each state holds three choices, `Alert`, `Sound` and `Dock badge`, and exactly these are on: `Dock badge` for `needs-you` and `error` (U10, U182), and `Sound` for `needs-you` and `error` (U410's sound). Every other choice is off, and in particular `Alert` is off for all five states. With these defaults, replaying `spikes/hooks-state/*.jsonl` through the webview calls `stateAlert` never, plays no sound for `working`, `blocked` or `done`, and leaves the Dock badge at the count of Agents in `needs-you` or `error` (P3). Tests: `u5232a_defaults_equal_todays_behaviour`, `u5232a_routine_progress_raises_nothing_by_default`. Observer: Vitest against the fake App and the replay.

**U5232b Settings holds the choices.** Given App Settings (U3799), then a group `Alerts` lists the five states in the order `Working`, `Blocked`, `Needs you`, `Error`, `Done`, each row with three switches `Alert`, `Sound` and `Dock badge` (Ark `Switch` through `ui/`, each named `<state> <choice>`, reachable by Tab and toggled by Space). A change takes effect at once, survives a reload, shows in every open Project tab, and an unreadable or invalid field falls back alone to its U5232a default (U3806, whose list now includes this group). Tests: `u5232b_the_group_lists_five_states_with_three_switches`, `u5232b_a_switch_works_by_keyboard`, `u5232b_a_change_survives_a_reload_and_reaches_every_tab`, `u5232b_an_invalid_field_falls_back_alone`. Observer: Vitest against the fake App; the look is the design critic's (dark only, U3725; moves D2, D5, D6).

**U5232c each choice follows the state.** Given a choice on for a state, when an Agent's Kind becomes that state, then: `Dock badge` counts that Agent while it stays in the state (the badge shows the number of Agents in states with `Dock badge` on, in every open Project, and clears at zero, U10); `Sound` plays one sound; `Alert` makes one `stateAlert` call (U5232f) with title the Agent's name as the Rail shows it and body the state's label (`Working`, `Blocked`, `Needs you`, `Error`, `Done`), never a prompt, transcript or file text. A choice that is off does none of its part. Nothing fires for an Agent whose Kind is already that state on load, for a repeat of the same Kind, or for `idle`. Turning a `Dock badge` switch on or off recounts at once. Tests: `u5232c_each_choice_acts_only_when_on`, `u5232c_the_alert_names_the_agent_and_the_state_only`, `u5232c_load_repeat_and_idle_raise_nothing`, `u5232c_the_badge_recounts_and_clears_at_zero`. Observer: Vitest against the fake App with a fake clock.

**U5232d one alert per Agent in a while, and not over the Agent being read.** Given roundup in front with Agent X selected (U413's test: `document.hasFocus()` false or `visibilityState` hidden means away), when X's Kind becomes a state with `Alert` or `Sound` on, then no `stateAlert` call and no sound happen for X; for another Agent they do, but `Alert` is raised only while roundup is away (in front, U410's Toast and U412 carry `needs-you` and `error`, and the other states raise a sound only). Per Agent, at most one `stateAlert` call and one sound happen in any 5 s of the fake clock; a Kind change inside the window raises neither and is not queued, and the badge still counts it. A different Agent is not limited by it. Policy: 5 s is the owner-visible limit (decided here). Tests: `u5232d_the_selected_agent_in_front_raises_nothing`, `u5232d_alert_only_while_away`, `u5232d_one_alert_and_one_sound_per_agent_per_five_seconds`, `u5232d_another_agent_is_not_limited`. Observer: Vitest against the fake App with a fake clock.

**U5232e clicking an alert opens that Agent.** Given a State alert for Agent X, when the user clicks it, then the App brings the window to the front and emits `state-alert-clicked` with X's id; the webview then selects X's Rail row and shows its Terminal as a click on the row does (U412), also in a Project tab that was not showing (the tab becomes current). A click for an Agent since removed shows U80's one failure line and selects nothing. Tests: `u5232e_a_click_selects_the_agent_and_shows_its_terminal`, `u5232e_a_click_switches_to_the_agents_project_tab`, `u5232e_a_click_for_a_gone_agent_shows_the_failure_line`. Observer: Vitest against the fake App (which emits the event); the native click is U5232g's Mac observation.

**U5232f the App seam command.** Given the App seam table (`scenarios/app.md`, Contract recipe of `.agents/builder.md`), then it gains one command `stateAlert({agent, title, body, alert, sound})` and one event `state-alert-clicked({agent})`, both in `GLOSSARY.md` and in `crates/contracts`/`contracts/generated/` with every caller in the same PR, built on the official `tauri-plugin-notification` unless the Reuse section of that PR names a missing capability (a click callback or a sound-only call); `setDockBadge` and the menu commands are unchanged. With `alert` true the App shows one macOS banner with the App icon, `title` and `body`; with `sound` true it plays the system sound once; with both false it does nothing and returns an error `invalid`. The App raises nothing of its own: with no `stateAlert` call from the webview, no banner or sound happens. Tests: `u5232f_alert_and_sound_reach_the_notifier_once_each`, `u5232f_both_false_is_invalid`, `u5232f_nothing_fires_without_a_call`, `u5232f_set_dock_badge_is_unchanged`. Observer: `cargo nextest run -p desktop` against a fake notifier; the contract probe is the review run's.

**U5232g permission and the Mac observation.** Given macOS has not yet allowed roundup's banners, when the first `stateAlert` with `alert` true runs, then the App asks for permission once through the plugin; a refusal returns an error carrying the cause, `stateAlert` with `sound` alone still plays, and the webview shows the cause once as U80's failure line (no retry loop, no second line per Agent). Tests: `u5232g_the_first_alert_asks_permission_once`, `u5232g_a_refusal_returns_its_cause_and_sound_still_plays`, `u5232g_the_webview_shows_a_refusal_once`. Policy/native observer: on the user's Mac, turn `Alert` and `Sound` on for `Done`, finish an Agent while another app is in front, see one banner naming the Agent, hear one sound, click the banner and see that Agent's Terminal; a Chromium fake cannot establish the banner, the sound or the click. The user reports what they meet on the Mac.

**U5232h what stays as it was.** Given any settings, then deleting an item raises no State alert (U3787a), a native request still makes its Agent `needs-you` and its attention entry still opens the requesting Terminal (P3, A3564a, A3564e), and no `stateAlert` call is made for a Todo, Pad or Shelf change. Tests: `u5232h_deletion_raises_no_alert`, `u5232h_native_attention_still_opens_the_requesting_terminal`, `u5232h_only_a_kind_change_calls_state_alert`. Observer: Vitest against the fake App.

**U5232j the permission prompt never freezes the App.** Given macOS has not yet allowed roundup's banners and the owner leaves the permission prompt unanswered, when the first `stateAlert` with `alert` true runs, then the command waits for the answer off the App's main thread: the window keeps answering keys, clicks and resizes, and every other command answers at once while the prompt is open. A second `stateAlert` during the wait neither opens a second prompt nor blocks; it returns the pending answer's outcome, and `sound` alone still plays at once. When the owner answers, the banner is raised once on allow, and a refusal reaches the webview as U5232g's single failure line. An unanswered prompt ends after 60 s as a refusal whose cause names the timeout. Tests: `u5232j_an_open_prompt_leaves_the_main_thread_free`, `u5232j_a_second_alert_during_the_prompt_asks_nothing_more`, `u5232j_an_unanswered_prompt_ends_as_a_timeout_refusal`. Observer: `cargo nextest run -p desktop` against a fake notifier whose permission answer is held by the test; the freeze itself on the user's Mac is reported by the user.

**U5232i a denied permission returns its cause.** Given the owner has denied roundup's notifications in macOS (before or after the App asked), when a `stateAlert` with `alert` true runs, then the App reads the native notification authorization state before sending, returns an error carrying the cause (`notifications denied in System Settings`) without sending, and the webview shows that cause once as U80's failure line (U5232g); a `stateAlert` with `sound` alone still plays and returns Ok; an allowed or not-yet-asked state sends as U5232g says. The plugin's `permission` result is never taken as consent when the native state reads denied. Tests: `u5232i_a_denied_state_returns_its_cause_without_sending`, `u5232i_denied_does_not_stop_the_sound`, `u5232i_an_allowed_or_undetermined_state_sends` (Rust, the native state read behind a seam the test fakes). Policy/native observer: on the user's Mac, deny roundup's notifications in System Settings, finish an Agent with `Alert` on, and see the one failure line; the user reports what they meet on the Mac.

**U5232k an alert sent while the prompt is open is not lost.** Given macOS has not yet allowed roundup's banners and the permission prompt is open and unanswered (U5232j), when a `stateAlert` with `alert` true runs, then it waits for the prompt's answer as U5232j says and never returns Ok without a banner: on allow, it raises its own banner once; on a refusal or the timeout, it returns that cause (U5232g). The same holds for the first call and for a second one during the wait: each raises one banner on allow, and none is dropped. `sound` alone still plays at once. Tests: `u5232k_an_alert_during_the_prompt_is_raised_on_allow`, `u5232k_an_alert_during_the_prompt_returns_the_refusal`, `u5232k_no_alert_returns_ok_without_a_banner`. Observer: `cargo nextest run -p desktop` against a fake notifier whose permission answer is held by the test.


## Per-Agent alert levels

Acceptance for #5501. Journey: Understand and Intervene — silence chosen Agents, inspect what was held, and open the original requesting Terminal. This is a specification; its merge delivers no alert-level implementation. Existing U5232 behavior remains except for the explicit level overrides below. Implementation adds any new code names to `GLOSSARY.md` in its Contract PR; the labels here are App copy, not new RPC identifiers.

**U5501 the user chooses what each Agent can raise.** Given an open Project with Agents in two Workstreams, then the following clauses hold. Each test below is planned, not evidence that this feature already exists.

- **Levels and lifetime.** Each Agent, including a Workstream's Door, starts at `Default`. `Default` uses Settings > Alerts exactly as U5232 specifies. `All` enables banner and sound for every actual Kind transition, including `idle`; this overrides U5232c's idle exclusion only for `All`. Banner contents remain Agent name and state label only, with `Idle` for `idle`. U5232d's foreground, selected-Agent and five-second guards still apply to `All`; it does not force a banner over the foreground App or replay skipped transitions. Its Dock badge choice remains the Settings choice. `Quiet` overrides every alert channel as specified below. A level takes effect after acknowledgement, survives Project close/reopen and Daemon restart, and follows the same Agent through a Home move; selecting a level starts or resumes no Agent. Changing global Settings never overwrites an Agent's level. Tests: `u5501_levels_override_only_their_channels` (connected App, fake App notifier and fake clock; exercise all six Kinds, disabled global choices, selection and the five-second boundary), `u5501_levels_survive_reopen_restart_and_home_move` (real Daemon public calls), `u5501_settings_changes_keep_each_agents_level` (connected App).

- **Agent and Workstream menus.** Right-click an Agent row to choose `Alerts` → `All`, `Default` or `Quiet` in its existing native context menu (extends U4322a’s edit group after Rename). The current choice is checked. Existing keyboard context-menu access reaches the same choices. A Workstream row offers the same submenu, applying one acknowledged user action to its Door, if present, and every Agent recursively inside that Workstream at the time of the action. Agents outside it do not change. This is a bulk change, not inheritance: an Agent added or moved into it later retains its own level. A later per-Agent choice changes only that Agent. For a Workstream whose covered Agents agree, check that level; when they differ, check none. An empty Workstream changes no Agent and has no checked choice. Opening or dismissing a menu changes nothing and does not select or start the clicked Agent. Tests: `u5501_menus_change_only_the_clicked_scope` (mounted App through the existing native-menu seam; different selected and clicked rows, pointer and keyboard, exact targets and call counts), `u5501_workstream_bulk_change_includes_its_door_and_nested_agents` (real Daemon public calls, two Workstreams and a nested Workstream), `u5501_bulk_choice_is_not_inherited_and_allows_an_agent_override` (real Daemon public calls), `u5501_mixed_and_empty_workstreams_have_no_checked_choice` (mounted App).

- **Only the user sets a level.** The authoritative Daemon operation checks the authenticated Actor before changing anything, following `Agents::save_as_mode`, not a caller-supplied user flag or a hidden menu. Every non-user Actor's request is refused with `FORBIDDEN`, both for its own Agent and for another Agent or Workstream; no level changes and no success event is emitted. Public MCP/CLI calls from an Agent cannot bypass the check by supplying a user Actor or extra parameters. Invalid levels and wrong-Project targets fail without changing any Agent. A rejected user change leaves the acknowledged level in force and shows U80's cause once at the originating surface. Tests: `u5501_non_user_calls_cannot_change_any_level` (real Daemon/public MCP and CLI, authenticated identities, compare before/after and events), `u5501_bad_level_or_project_changes_nothing` (real Daemon public calls), `u5501_a_refused_choice_keeps_the_level_and_shows_its_cause` (connected App with rejected RPC).

- **Quiet has no unsolicited output.** A Quiet Agent contributes zero banners, sounds, Toasts, Dock count and menu-bar mark/list entries. Apply the filter before dispatch and aggregation across all open Projects, including background tabs and a Workstream's Door; a quiet needs-you/error Agent cannot light a parent aggregate. A Todo-edit Toast attributable to that Agent is filtered too. Switching an already waiting Agent to Quiet immediately recounts the Dock and any existing menu-bar projection and removes its visible or away-queued Toasts; returning to the App does not replay them. Switching out of Quiet recounts current aggregates but emits no catch-up banner, sound or Toast. Other Agents retain their outputs. Quiet changes neither the Agent's Kind nor the ordinary Rail glyph/Live line, native vendor prompt, direct access or ability to answer in its Terminal. Tests: `u5501_quiet_filters_all_outputs_across_projects` (connected App, fake App command counts, Toast queue and aggregate projections; quiet Door, Agent and non-quiet control), `u5501_quiet_removes_existing_and_away_queued_toasts_without_replay` (connected App and fake clock), `u5501_quiet_keeps_native_attention_answerable` (real Daemon/fake vendor through the existing native-attention observer). Menu-bar implementation is separately owned by #5502; until present there is no menu-bar output to filter, and its integration must consume this same authoritative level.

- **What is held.** While Quiet, every actual Kind transition that would produce an Alert, Sound, Dock contribution or needs-you/error Toast at `Default` creates one held row, even if more than one channel qualifies. Evaluate the current Settings and U410's state-Toast eligibility before foreground/selection and the five-second guard; Quiet has no visible dispatch to rate-limit. A Todo edit by the Quiet Agent that would meet U410's user-created-Todo rule also creates one held row. Routine transitions with every Default channel off and no Toast eligibility, initial load, a repeat of the same Kind, deletion, and changing the level or Settings alone create none. These rows are a review list, not U413's queue of Toasts awaiting foreground. Tests: `u5501_quiet_holds_one_row_per_eligible_event` (connected App with fake clock; multiple enabled channels, foreground selection, rapid distinct transitions, Todo edit and every excluded trigger). Policy: Default is the counterfactual level used for Quiet, irrespective of the Agent's previous level; existing held rows are not reclassified when Settings change.

- **Held content and acknowledgement.** At the Rail foot, a nonempty Project-scoped list has opener `n held`, counting rows, not Agents. Opening it reveals newest-first rows, each with the event's Kind glyph, original Agent identity/name, event-time Live line and time. An empty list mounts neither opener nor rows. Names and Live lines are literal text, never interpreted markup, prompts, Message content or transcript extracts. Rows remain through reload and Project reopen and keep their event-time content when the Agent changes again; equal timestamps keep receipt order. Activating a row selects its original Agent in its original Project and opens its Terminal through U5232e's existing path, then clears all held rows for that Agent alone. Opening that Agent from the Rail or another existing navigation path also clears its rows; merely opening the list or selecting a Workstream does not. A failed open shows U80's cause and retains the rows; a removed Agent's row reports that it is unavailable and never opens a replacement. Leaving Quiet does not erase held rows or replay them. Tests: `u5501_held_rows_keep_event_identity_content_and_order_across_reopen` (connected App, fake clock, two Agents, literal markup-like Live text and reload), `u5501_opening_an_agent_clears_only_its_held_rows` (connected App, held-row/Rail/existing alert-click entry points), `u5501_a_failed_or_gone_target_open_preserves_held_rows` (connected App). Policy: the design critic checks the copy, glyph, time presentation and empty rendering; behavior tests check identities, data, roles, navigation and calls, never exact copy or geometry.

- **Existing attention and delivery remain.** With every Agent at Default, U5232 and U410/U412/U413 continue to hold. With Quiet set, a native request still makes its Agent needs-you, and opening its Terminal still permits the original vendor continuation; Quiet silences the interruption, not the request. No held row becomes a Message, changes a Route or Held delivery rule, answers a prompt, accepts work or spends a Model turn. Tests: retain the existing regression observers in Checks 1–4; `u5501_quiet_keeps_native_attention_answerable` also asserts zero Message delivery or prompt-answer calls from choosing a level or opening the held list. Policy: no Message/Route/Held/Takeover contract changes are ordered by this feature.

- **Rendered observer.** Policy: use existing `ui/` primitives wrapping Ark UI for webview interactions, the existing native context-menu builder and Tokens only. Agent rows at non-Default show the secondary word `all` or `quiet`, alongside their existing Kind glyph; Default has no level word. A Workstream shows that word only when all its covered Agents agree on the same non-Default level; a mixed or empty Workstream shows no level word. The level is a setting, never a second Kind glyph. This explicitly adds the setting word to the normal resting-row budget while preserving quick-action reveal and current failure feedback. At 1512×950 in dark mode, inspect `tree-40` with mixed levels, long names, several held rows and a refused choice visible, plus `agents-10` with all Kinds. D2, D5 and D6 hold, and no Check passing on main regresses. Run `just capture U5501`; leave PNGs/videos under `artifacts/ux/U5501/`, never committed. The headless observer proves webview behavior and the native-menu model only; the user reports native appearance/banner/sound behavior on the Mac. No Mac observation is needed to merge this specification.

Applicable Principle gates and observers (policy): P3 — only user-enabled state choices/levels interrupt, Quiet dispatches nothing, and a native request still opens its original Terminal; observe connected-App output counts and the real-Daemon continuation above. P1 — direct Agent access remains possible and neither choosing a level nor reading held rows writes a Message into a Terminal; observe navigation identities and zero delivery/input calls. No new editable surface, published deliverable or named reaction is introduced.
