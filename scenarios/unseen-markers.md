# An unseen marker shows only where the user must act

Specification for #6119. Module: `apps/desktop` (App state and summaries). Ids: U6119a, U6119b, U6119c, U6119d. First-journey stages: Understand and Intervene (`.agents/data/journey.md`). This is acceptance for a later implementation, not evidence that the feature exists.

Decision (policy): the owner deals with a Workstream through its Door (#5758, T27 row, 2026-11-04). A marker is drawn only for something the user must read or answer; a Workstream's child Agents are the Door's to handle, so they draw no unseen marker of their own. A child that needs the user shows it on its Door's row. No new Status kind and no new Token (`--accent` and `--grey` as U3566d and U3704 set them).

**U6119b a Workstream's child shows no dot, its Door shows what needs the user.** Given a Workstream with a Door and a child Agent, and a top-level Agent, when the child publishes a finish while another Agent is selected, then no Rail row carries the unseen state and the collapsed Workstream row does not either; when the top-level Agent or the Door does the same, its row does (U3566a). Given the child then reaches `needs-you` (a question or permission ask) or `error`, then the Door's row and the collapsed Workstream's row show that Kind and the Project tab counts it, as today. Selecting the child, expanding the Workstream or moving the child out of the Workstream (its Home changes, U3566b) follows the child's current Home: it shows a dot once it is top-level and unseen, none while it is a child. A finish the user cannot see as a dot is not lost: it stays counted by `Status.finished` and the Door reports it in its own finish (policy). Test: `u6119b_a_child_finish_is_not_unseen_and_its_need_reaches_the_door` in `apps/desktop/src/state/u6119_unseen_markers.test.tsx` (planned), through the fake App seam and the real Rail, asserting the accessible unseen state and Kind, never colour or geometry. The Door row's finished state reuses #5933 where it has landed (policy).

**U6119c the other markers follow the table.** Given a Workstream child with a Terminal, a plain Terminal and a top-level Agent's Terminal, each producing output while not viewed, then only the plain Terminal's and the top-level Agent's shell tabs show unseen output and the child's does not (`createScreens::unseen`). Given a child's unread finish and a top-level Agent's, then the menu bar lists a Ready row for the top-level Agent only; a child in `needs-you` is still a Waiting row; the Dock count and the Project tab mark and edge count are the same with and without the child's finish. Tests, each beside the marker in `apps/desktop/src/state/u6119_unseen_markers.test.tsx`: `u6119c_a_child_terminal_tab_shows_no_unseen_output`, `u6119c_menu_bar_ready_rows_skip_workstream_children`, `u6119c_project_tab_and_dock_count_only_what_needs_the_user`. Real Agent Terminals stay reachable as today (policy): the child's Terminal opens from its row and its Bubble tab still lists it; only the dot is absent.

**U6119d the change hides nothing the user must answer.** Given a child with a pending question, a permission ask, an `error` and a finished Door in one Project, when the markers are drawn, then each is shown exactly as before: the Kind Glyph on the Door's row, the Project tab mark and count, the Waiting menu bar rows and the Dock count, and the Door's own dot. It must not, and the unseen dot stays passive state. P1, does hiding the dot make an Agent unreachable directly? Row selection, the Switcher and Terminals stay as today.
