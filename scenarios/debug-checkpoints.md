# Checkpoints in debug builds

A Door records Checkpoints in the development App using the same SDK-owned conversation lookup as a packaged App. This specifies the debug runtime repair; it changes neither Mark contents nor rewind authority.

**A4691a a debug Door records a Checkpoint without a sidecar override.** Given a checkout with `pnpm install` completed, an installed Node runtime, and no `target/debug/sidecar`, when the developer runs `just build-debug`, then the debug `rupd` and `rup` binaries and their adjacent usable sidecar are prepared. When that debug Daemon starts with `ROUNDUP_SIDECAR_DIR` removed from its environment, and a Door with a saved conversation calls `checkpoint_write`, then the call succeeds, `checkpoint.list` includes the Checkpoint as rewindable, and its durable Marks contain the saved conversation records. The original saved conversation bytes remain unchanged. Assert `a4691a_debug_checkpoint_uses_the_adjacent_sidecar` in `crates/rup/tests/debug_checkpoint.rs` (planned): use a real debug Daemon, isolated Project/data/vendor storage, a deterministic fake Claude that saves a conversation, the real SDK and the existing public Door MCP/RPC seams. Inspect the stored Mark through existing storage test support; checking only the returned Checkpoint id or a sidecar file's existence is insufficient.

Policy: choose debug preparation, not a Rust reconstruction of vendor storage paths. Add `just build-debug` as the shared debug preparation command: build `rupd` and `rup`, then reuse `tools/sidecar/bundle.sh target/debug/sidecar --local-node`. Make `just app` run that command after its dependency installation and before starting the App; a failed build or sidecar preparation ends the command nonzero and opens no App. Direct debug-Daemon users run `pnpm install` followed by `just build-debug`. Bare `cargo build` remains compilation only. Review the recipe wiring; do not add a test that rereads justfile text. The local Node requirement is development-only; packaged builds retain their pinned bundled runtime and notices (check 4).

Observer: start with the debug sidecar absent in an isolated checkout/build directory, run the actual shared preparation command, then run `a4691a_debug_checkpoint_uses_the_adjacent_sidecar` against that prepared executable. Do not use `test-support`'s system-Node shortcut, `Launcher::with_sidecar`, or the normal e2e fixture's `ROUNDUP_SIDECAR_DIR` override for this observer. Do not manually bundle the sidecar in its success fixture: removing the preparation step must make this observer fail. Keep all created Daemons, fake vendor processes, sockets and files owned by this run; no native App, user login or Model call is needed. This Daemon observer proves the Checkpoint action in the first journey's Review stage, not native rendering or a new UI surface.

**A4691b an incomplete debug sidecar gives a working repair.** Given a debug Daemon with isolated saved conversation storage and no sidecar override, and an adjacent sidecar missing `node` or `list.mjs` (one case per missing entry), when its Door calls `checkpoint_write`, then the failure names the missing path and instructs the developer to run `pnpm install` followed by `tools/sidecar/bundle.sh <sidecar-directory> --local-node` from the checkout root, using the actual adjacent sidecar directory. It retains the option to point `ROUNDUP_SIDECAR_DIR` at a complete folder; reinstalling roundup alone is insufficient debug guidance. The failed recording leaves the original conversation unchanged and publishes no successful Checkpoint. After the stated commands repair that directory, retrying the same action succeeds and yields a rewindable Checkpoint with its Mark. Assert `a4691b_missing_debug_runtime_is_repairable` in the same planned integration file, as one table over the two missing entries. Use copies of the already-built debug executable in private temporary directories for these destructive packaging fixtures; never remove the shared build's runtime while other tests use it. Run the actual repair, not a stub command. If the implementation's existing missing-conversation test already proves refusal leaves no Checkpoint, retain that proof rather than duplicating it (check 2).

Policy: preserve explicit `ROUNDUP_SIDECAR_DIR` precedence and existing override-based fixtures. Do not silently use a release folder, guess a conversation path, treat failed lookup as an empty conversation, start a conversational Agent during lookup, or change release packaging. Missing debug preparation is an actionable failure, not permission to weaken U4251c's SDK storage authority.
