# Dev feed and promote

Module: `.github/workflows/check.yml`, `justfile` (`promote`), `tools/release/` (the promote script and its tests). Ids: DF7078a–DF7078g. Work order: [#7078](https://github.com/roundup-app/roundup/issues/7078), blocked by [#7077](https://github.com/roundup-app/roundup/issues/7077) (`scenarios/channels.md`: Channels, feeds, key, `just app-bundle`, CH7077f). Terms: Channel (`GLOSSARY.md`). Direction (owner, 2026-11-13): Stable moves only when the owner promotes a Dev build; promote is a command, never a menu item; free signing. Tests start no network, no real `gh` and no macOS build: the promote tests run `tools/release/promote.py` against a fake `gh` on `PATH`.

Names: the **Dev version** is `0.1.0-dev.<n>`, `<n>` the `check.yml` run number of the push (CH7077f). The **Stable bundle** of that run is `0.1.0-alpha.<n>`, so the Stable version a promote publishes is fixed before any promote runs. The **artifact** is the workflow artifact `stable-0.1.0-dev.<n>` holding the Stable update archive and its `.sig`. The **Dev feed** is `latest.json` on the rolling `dev` release; the **alpha feed** is `latest.json` on the `alpha` release (`tauri.dev.conf.json`, `tauri.stable.conf.json`). A feed is Tauri's static updater JSON: `version`, `pub_date` and, for the runner's platform, `url` and the `.sig` text as `signature`.

**DF7078a only a green main publishes.** Given a `check.yml` run, when it is a `pull_request` or `workflow_dispatch` run, or a push to `main` on which any lane (`plan`, `rust`, `mac-clippy`, `mac`, `mac-package`, `web`, `chromium`) or `check` did not succeed, then it builds no signed bundle and writes no release. On a green push to `main` the bundle jobs wait for every lane and `check`, and the `publish` job waits for the bundle jobs. `publish` holds the only `contents: write` in the file; every other job and the workflow default hold `contents: read` or less. A failed `publish` never fails `check`, so a feed problem is not a red `main`. Tests (`tools/release/check.test.py`, `df7078a_`): parse `check.yml`: the only job with `contents: write` is `publish`; `publish`, and each bundle job, is `if`-gated to a `main` push and needs every lane and `check` (through the bundle jobs); `check` does not need `publish`; no step outside `publish` names `gh release`. Policy, observer: a `pull_request` run and a red `main` run in Actions show `publish` skipped and the `dev` release unchanged.

**DF7078b each green main reaches the Dev feed.** Given a green push to `main`, when `publish` runs, then the Dev bundle (`just app-bundle dev <run number>`, signed with `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`) is uploaded to the `dev` release with `--clobber`, then its `latest.json` (version `0.1.0-dev.<n>`, `url` the bundle's asset on the `dev` release, `signature` the bundle's `.sig`) is uploaded last, then assets of older Dev versions are deleted, so the feed never names a bundle that is missing and the release holds one Dev build. The Dev App offers the newest green `main` build. A newer push cancels the older run (`scenarios/ci-mac.md`); a run cancelled before its `latest.json` upload leaves the feed on the build it held. Tests (`df7078b_`, `tools/release/promote.test.py` for the feed builder `tools/release/feed.py`): the feed JSON holds the version, the asset's URL and the signature text for given inputs; the upload order is bundle, `latest.json`, deletions. Policy, observer: after a green `main` push, `gh release view dev` lists one bundle and a `latest.json` naming it.

**DF7078c the Stable bundle waits as an artifact.** Given the same push, when `publish` has uploaded the Dev feed, then it uploads the artifact `stable-0.1.0-dev.<n>` with the Stable bundle (`just app-bundle stable <run number>`, version `0.1.0-alpha.<n>`, built from the same commit and signed with the same key) and its `.sig`, and no Stable file reaches any release. The artifact exists only for a Dev version whose Dev feed upload succeeded. Its retention is 90 days. Policy, observer: a green `main` run lists the artifact; the `alpha` release is unchanged.

**DF7078d promote refuses what the Dev feed never shipped.** Given `just promote <dev version>` run with the owner's `gh`, when the argument is not `0.1.0-dev.<n>` with `<n>` a positive integer, then it exits 2 before any call. When no artifact `stable-<dev version>` exists (the build was never pushed, was red, failed before its Dev upload, or expired), it exits 3 naming the version and the newest artifact it found, and creates and rewrites nothing. Tests (`df7078d_`): a malformed argument exits 2 with no `gh` call; a version with no artifact exits 3 with no `gh release` call.

**DF7078e promote ships the same bytes.** Given the artifact for `0.1.0-dev.<n>`, when `just promote 0.1.0-dev.<n>` runs, then it downloads the artifact into a new empty directory, creates release `v0.1.0-alpha.<n>` holding the Stable bundle and its `.sig` unchanged, and only then rewrites the alpha feed (`version` `0.1.0-alpha.<n>`, `url` the new release's bundle asset, `signature` the `.sig` text) on the `alpha` release with `--clobber`, creating that release when it does not exist. The SHA-256 of the release's bundle asset, read back from `gh`, equals the artifact's; a difference exits 4, leaves the alpha feed as it was and deletes the new release. The Stable App offers only promoted builds: nothing but `promote` writes the alpha feed. Tests (`df7078e_`): the release is created from the downloaded files byte for byte; the feed is written after the release and names it; a read-back with a different hash exits 4 with the feed untouched and the release deleted.

**DF7078f every alpha release stays, and promote repeats safely.** Given release `v0.1.0-alpha.<n>` already exists, when `just promote 0.1.0-dev.<n>` runs again, then it creates nothing and deletes nothing: when the release's bundle hash equals the artifact's (or the artifact has expired) it rewrites the alpha feed from the release's own assets, which is a rollback to that build when the feed names a newer one, and exits 0; when the hashes differ it exits 5 and changes nothing. No command deletes an alpha release. Tests (`df7078f_`): a second promote makes no `gh release create` or `delete` call and rewrites the feed; a differing hash exits 5; promoting an older version after a newer one points the feed at the older release.

**DF7078g settled questions.** The Stable version needs no promote-time rebuild or renumbering because the run number fixes `0.1.0-alpha.<n>` at build time (CH7077f). Bundles build on macOS runners in parallel jobs (one per flavour), so no macOS job grows past `scenarios/ci-mac.md` CI5458d's 1500 s; `publish` runs on Linux. Promote's `gh` is the owner's login: the repo secrets reach only `check.yml` on `main`, and the signing key never leaves it. Retention of the artifact is the only expiry of promote's source; the `dev` release keeps one build by design.
