# Remove question bubbling

Module: `crates/messages`, `crates/contracts`, `crates/rupd`, `crates/rup`, `proofs/messages`, generated contracts, `docs/messages.md`, `GLOSSARY.md` and `scenarios/`. Source: #3692, the remainder of #3564 (`scenarios/native-questions.md`). Ids: B3692a–B3692c. This specification orders implementation; it claims no delivered behavior.

Policy: a question to an Agent is one ordinary Message. No Daemon timer passes it up the Rail and no held question waits for the user; the user answers in the asking Agent's Terminal (A3564a). #3564's retirement inventory orders the removal; this file adds the acceptance that the removal is complete. The Contract recipe of `.agents/builder.md` applies: every caller changes in the same PR and the review run's approve covers the proof changes (V3).

**B3692a a question is never passed on.** Given an Agent `m1` with a parent Agent and a Door above it, when `c` sends `m1` a `question` and `m1` neither answers nor ends, then after 60 000 ms and after any number of idle edges and restarts the Daemon makes no second Message from that question, no Message to the user and no `held` Message; `m1`'s Message is `delivered` once as B50 says and stays so. Given `m1` ends or is dropped, the question stays `dropped` with its reason (B8, B9) and nothing replaces it. The RPC method `message.pass`, the MCP tool `message_pass`, the field `passedFrom` and the reason `escalated` are absent from `crates/contracts`, `contracts/generated/` and `rup mcp`'s tool list; a call to `message.pass` fails as an unknown method with zero effects. Tests to implement: `b3692a_an_unanswered_question_makes_no_second_message` in `crates/messages/src/tests/` (fake clock at 59 999, 60 000 and 600 000 ms, a Rail three deep and a second Workstream, asserting the Message count and statuses after each step), `b3692a_message_pass_is_not_offered_or_dispatched` in `crates/rup/tests/mcp/` (real MCP discovery and Daemon method lookup), and the existing `m1_offers_one_tool_per_method_and_ask_user_and_no_others` in `crates/rup/tests/mcp.rs` amended to the surviving methods.

**B3692b retired.** N5467a–d (`scenarios/local-data-retirement.md`, #5467) require refusal of obsolete local data, not conversion of stored hops or escalated questions. Current Message finality remains required.
