# Evidence outside git

Acceptance for #1603. This is a specification; the named tests below are implementation targets, not evidence that the migration has shipped.

**L112 captures and evidence leave the tree.** Supersedes L105's committed-capture, tracked-path ownership and historical merge-replay requirements (`scenarios/loop-rules.md:230`–`238`) only for evidence storage and publication. Capture selection, assertions with captures disabled, journey partitions and independent review remain required. Historical scenario paths under `artifacts/` describe artifact-relative paths after migration, never a requirement to commit the payload.

- Given a clean checkout, when `just capture <ids>` runs, then its PNGs and readings remain under the existing `artifacts/ux/<id>/` and journey partitions, git ignores every generated file there, no tracked file changes, and only the named ids receive output (`l112_capture_output_is_ignored_and_partitioned`). With `ROUNDUP_CAPTURES` unset, assertions still run and no capture is written (`l112_checks_without_captures_keep_assertions`). Tests live in `loop/captures.test.sh`, exercising the existing helper and recipe.
- Given required observer evidence, when a Builder publishes it, then the PR body links a downloadable GitHub Actions artifact or PR attachment for that PR head, naming scenario ids, revision, observer command, exit code and capture conditions; an Actions artifact has explicit 14-day retention. A committed UTF-8 Markdown summary of at most 16 KiB per observer, containing result rows rather than copied payloads or bulk logs, may retain those facts and measurements, but never replaces required captures before review (`l112_published_evidence_names_head_and_scenarios`). Policy: after expiry, the summary retains the result and the observer command can regenerate the payload; it must not claim the expired link remains downloadable. Upload/attachment failure is visible and leaves the PR draft, without treating missing evidence as a passing observer (`l112_failed_publication_leaves_draft`). The publication fixtures belong in `loop/captures.test.sh`; no PR can approve its own evidence or bypass independent required gates (policy).
- Given a PR whose required captures are pending, when a job that wrote no capture manifest ends, then a head already published changes nothing, a head without `Capture ready: <head>` stays draft with no comment and no failure, and only `Capture ready: <head>` without a manifest fails loudly; no publication comment follows a failed preparation (`l112_prepare_for_published_head_changes_nothing`, `l112_prepare_without_ready_line_keeps_draft_quietly`, `l112_prepare_ready_line_without_manifest_fails_loud`). While the PR is draft, `rules` passes a pending or older-head publication, so a draft spends no fix attempt on it; leaving draft reruns `rules`, which then requires the head's publication (`l112_draft_pending_publication_passes_rules`, `l112_draft_stale_publication_passes_rules`, `l112_ready_pr_without_publication_fails_rules`). A publication also covers a later head that only merged `main` into its revision, so a refresh or update-branch needs no recapture: the PR's own patch against `main` is the same at both. A head that changes that patch needs a new publication (`l112_merging_main_keeps_publication`, `l112_changing_the_pr_after_publication_fails`).
- Given the migration checkout, when inspecting `git ls-files`, then no tracked path remains under `artifacts/`, `crates/rpc/r16/` or `crates/rupd/evidence/` (`l112_evidence_directories_are_untracked`). Before deletion, classify every tracked file in those directories as generated evidence, executable observer or test input: move executable observers and required test inputs to their owning source/test directory or generate inputs in owned temporary directories; preserve their assertions (`l112_removed_files_have_no_test_readers`). Run the full `just check` on the removal checkout; no test reads a deleted file, including indirect shell/Python readers. Each surviving scenario citation of a removed committed file resolves to an artifact-relative path with its run link in the PR summary, or a small committed summary containing the result and regeneration command (`l112_scenario_evidence_references_resolve`). These checks belong in `loop/captures.test.sh`; the full-suite exit is also recorded (policy).
- Given fresh shallow clones of the same repository at the implementation PR's base and head, when measuring before installing dependencies or building, then record both full revisions, `du -sh .`, `du -sk .`, and `git ls-files | wc -l`; the head is smaller and the count drops by exactly the removed evidence-file count minus explicitly listed relocated observers/inputs and added source/summary files (`l112_shallow_clone_measurement`). Use separate `git clone --depth 1 --no-local --branch <ref>` clones while both refs exist, verify HEAD, and remove only the observer's own temporary clones. Record results in a small committed summary and link it from the PR. The expected drop is about 4,000 files, not an exact threshold independent of the base. Test/observer entry point: `loop/captures.test.sh`; each failing command is a separate summary row with its exit code.

Policy: removal from the tree proceeds without a history rewrite. Never run `git filter-repo`, force-push rewritten history or alter every clone in this implementation. Any proposed history rewrite is a separate Work Issue held by `flag:needs-user`, with the old/new clone measurements, affected refs and recovery plan for the user to approve. The removal PR leaves that choice open and does not wait for it.

Implementation boundary: #1603 owns the three evidence directories, `.gitignore`, the `capture` recipe in `justfile`, and `loop/captures*`. Necessary changes to capture callers, vocabulary, scenario references, publication workflows or L105's gate/instructions require separately scoped prerequisite Work Issues rather than silently expanding ownership. Do not edit Rust sources in `crates/rpc` or `crates/rupd` (owned by #1615 and #1620), or `qa.yml` and `loop/qa-sweep.sh` (owned by #1613). Coordinate with those owners when their readers/publication need migration. Publication/reference migration is #1650; scoped removal is #1651. Both remain blocked by this specification until it merges, and removal also waits for #1650.
