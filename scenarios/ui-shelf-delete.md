# UI: clear done and delete selected Shelf rows (U458 to U460)

Policy: U3787a (`scenarios/ui-mac-expectations.md`) replaces U459/U460’s confirmation step for reversible deletion with immediate delete and focused undo/redo without deletion success feedback; target freezing, scope, partial failures, readback, blockers and ownership remain. U3787c adds Home/End, typeahead and ⌘A to U458.

Module: `apps/desktop` (the webview). Acceptance for #1060. Extends U15, U31 and U150; narrows U370's Esc handling while rows are selected. U2744a decides which items belong in the Shelf, including done Todos; neither selection nor deletion widens that scope. U361's tick box, U155's reorder, U362's move, U373's tabs and single-item Drawer deletion remain available.

Policy: use existing `todo.delete` and `pad.delete`, with the user as Actor; no new RPC method, App seam command, Token or domain term. Implementation owns the Shelf's Todos and Pads components and their shared Shelf integration under `apps/desktop/src`, their tests and harness fixtures, and the captures below. Real-Daemon observations exercise existing T6 and P9, not a new contract.

**U458 rows can be selected by pointer and keyboard.** _Amended only as listed by U3789e (`ui-shelf.md`); U3789a–d govern those replacement clauses._ Given the Shelf's active Todos or Pads tab with at least five eligible rows in U2744a’s scope and displayed group order, then:

- **Pointer.** ⌘-click on a row button toggles only that item's selection and makes it the range anchor, including when toggled off. ⇧-click replaces the selection with the inclusive range from the anchor to that row; with no anchor it selects that row alone. The range follows rendered order, crosses Agent groups but skips group headings, and never includes folded done rows. ⌘⇧-click has the same range behavior. These gestures open no Drawer and call no mutation. Repeated copies of an item, if present, represent one identity and count once. Test: `u458_pointer_toggle_and_range_follow_visible_order`.
- **Keyboard.** Tab retains access to every existing control. On a row button, plain ↑/↓ moves focus to the previous/next rendered row without wrapping or changing selection; ⌘Enter toggles the focused item and sets the anchor; ⇧↑/⇧↓ moves focus one row and replaces the selection with the inclusive anchor range (with no anchor, the previously focused row becomes the anchor). At either end the range remains unchanged. Only these exact modifier sets are handled; a repeated ⌘Enter keydown never toggles again, and Caps Lock does not change the chord. Plain Enter and plain Space retain row activation and open the Drawer. No selection key handles an editor, tick box, blocker link, tab, fold, Terminal or control outside the row buttons; ⌥↑/⌥↓ retains U155. Tests: `u458_keyboard_toggle_range_and_bounds` and `u458_keys_leave_other_controls_and_reorder_unchanged`.
- **Single-item actions.** Plain click clears the selection and sets that row as anchor before opening its Drawer; modified clicks on the Todo tick box or blocker links retain their own actions and never select rows. Dragging still reorders or moves just the dragged Todo, never the selected set. Tests: `u458_plain_click_opens_the_drawer`, `u458_tick_blocker_and_drag_keep_their_actions`.
- **Selection lifetime.** Selected rows expose their state to assistive technology and use the existing selected wash with the U361 inset, distinct from focus. Refetch keeps surviving selections by Todo id or Pad name, not row index; rows no longer rendered lose selection and an absent anchor is cleared. Folding done clears selected done rows. Switching Shelf tab, scope, selected Rail row or Project, or closing the Shelf clears selection and anchor; reload restores none. Tests: `u458_selection_survives_refetch_by_identity`, `u458_hidden_rows_and_context_changes_clear_selection`.

**U459 clear done immediately deletes the scoped done Todos.** Given at least two done Todos in U2744a’s scope, an open Todo in the same scope and done Todos excluded by that scope, then:

- **Control.** Beside `✓ <n> done`, a separate `Clear done` button is available whether folded or unfolded; it neither toggles the fold nor opens a Drawer. Its count and targets include every eligible done Todo, even folded, and exclude open Todos and out-of-scope Todos. At zero, neither the fold nor the button is rendered. This is the sole folded-row exception to U458. Test: `u459_clear_done_targets_only_the_scoped_done_set`.
- **Immediate deletion and history.** Choosing Clear done freezes its scoped done identities and deletes immediately once without a question; success empties that done set, removes the fold at zero and keeps open Todos. The successful subset is one Shelf undo step: ⌘Z/Edit > Undo restores it and ⇧⌘Z/Edit > Redo deletes only that restored set again, without a success bar or hint; the Edit labels name Clear done. Tests: retain `u459_clear_done_success_removes_only_done_rows`; planned `u3787a_shelf_delete_undo_redo_without_feedback`, Clear done case. Policy: retire the confirmation/cancel-only proof `u459_clear_done_confirms_once_and_cancels_without_calls`.
- **Failure.** A partial failure uses U460's error handling: failed done Todos remain selected and the done fold opens so each failed row is visible; only successful deletions reduce the count. Test: `u459_failed_done_rows_are_visible_and_selected`.

**U460 delete selected rows immediately deletes one set and retains failures.** Given a nonempty selection in either Shelf tab, then:

- **Bar and cancel.** A bar beneath the list, outside its scroll area, reads `<n> selected`, `Delete <n>` and `Cancel`, counting unique selected items in the active tab. Cancel or plain Esc clears selection and the bar without a call and keeps focus on a surviving row. This Esc is consumed before U370 can close the Shelf. At zero the bar is absent and plain Backspace deletes nothing. Test: `u460_bar_counts_unique_items_and_cancel_clears_without_calls`.
- **Immediate execution.** Delete or plain Backspace from a selected row button or selection bar freezes the exact chosen identities and originating Project, then calls deletion immediately once under U3787a; no confirmation follows. Later arrivals never widen the set. While pending, repeated keys/clicks cannot start another delete and selection controls cannot change targets. Success removes rows through existing events/refetch and clears successful identities from selection. A Project switch cannot redirect calls or paint errors into another Project. Backspace in a Drawer, editor, naming field, tick box, Terminal or outside the selection bar/row buttons retains its meaning; modified Backspace and repeated keydown never start a bulk delete. Tests: adapt `u460_each_confirmed_target_is_called_once` to immediate execution; retain `u460_pending_delete_stays_with_its_project` and `u460_backspace_is_local_and_repeat_safe`; replace the confirmation-only proof with planned `u3787a_delete_has_no_question_and_freezes_targets`, selected-set cases. Policy: retire question cancellation and question-lifetime clauses; preserve captured target/scope lifetime during execution.
- **Undo and redo.** One acknowledged successful subset is one Shelf history step under U3787a. ⌘Z/Edit > Undo restores those identities; ⇧⌘Z/Edit > Redo deletes only the restored subset again, never newly selected/arriving rows. No deletion success bar, Undo/Dismiss button, toast or hint renders; the pre-delete selection controls and failed-row feedback remain. Planned `u3787a_shelf_delete_undo_redo_without_feedback` covers Todo and Pad sets, including the action-naming Edit menu.
- **Failures.** Attempt every captured target even if one fails. Display `✕ Could not delete` followed by each failed Todo's title and id, or Pad's name, and its returned error; names with the same title remain distinguishable. Successful targets are not selected again. Failed targets remain selected and visible with the bar's revised count, so retry immediately deletes only that remainder. For a lost response, refetch before offering retry: a missing row is no longer selected; a still-present row remains selected with the failure. Never claim a timeout proves deletion did not happen. `Refresh` shows only after a failed refetch: while deletes are pending and after a failure that needs no refetch, the bar holds no `Refresh` control. Tests: `u460_partial_failure_names_and_selects_only_failed_rows`, planned `u460_retry_deletes_only_the_remaining_set` (adapt the former confirmation-retry proof), `u460_lost_response_refetches_before_retry`, `u460_refresh_shows_only_after_a_failed_readback`.
- **Todo blockers.** Each deletion preserves T6, including a remaining Todo blocked by two selected Todos, one of which fails deletion: only the successful blocker is removed, and the remaining blocker still blocks it. Across Homes this cleanup still applies, even to Todos outside the Shelf; those Todos are never themselves deleted. Test/real-Daemon observation: `u460_bulk_todo_delete_preserves_t6_across_homes`.
- **Agent-owned Pads.** The user may select and delete any eligible Pad (P9), regardless of its owner's Kind. No Agent stop, ownership transfer or automatic Pad recreation occurs. An owner write committed before delete is deleted with the Pad; a write or append after delete returns NOT_FOUND and restores neither Pad nor file. A later explicit `pad.create` retains P1. An open Drawer retains U20's externally-deleted behavior. Tests: planned `u460_agent_owned_pads_delete_without_stopping_agents` (adapt the former warning proof), `u460_deleted_pad_updates_do_not_recreate_it`, `u460_open_pad_drawer_observes_bulk_delete`; the write/delete/write and append checks run on the real Daemon in both Pad storage modes.

Policy: visible control casing follows U416; the Issue's lowercase sketches describe placement, not an exception to D15. Selection adds no checkbox or selection mode; U361's completion tick box stays. Selection, deletion and history updates are instant; existing Shelf/Drawer motion is unchanged.
