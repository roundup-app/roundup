# UI: App Settings open as a center view

Acceptance for #3281, from the user's request: "we need to have settings view in the window mac menu for the whole app" and "the settings of the app also holds the mode -> dark | light | system". Module: `apps/desktop/src/` (`settings/`, `terminal/`, `keys/`, `app/`) and `crates/desktop/src/menu.rs`. Ids: U3799–U3806. Builds on #3280's shared shell (`settings/SettingsShell.tsx`, U3764), on B2706 (the user's own permission mode) and on U3737 (the capture chord). Chosen form: a center view, not a dialog or a separate window.

Contract (policy, by the Contract recipe of `.agents/builder.md`): one App seam event `open-app-settings` (App to webview, no payload) is added to `scenarios/app.md`'s seam table, `agent.spawn`, `rail.startDoor`, `agent.resume` and `workstream.clear` take an optional `permissionMode` (`default`, `acceptEdits`, `plan`, `auto`; absent means the user's own Claude Code mode, B2706), `agent.spawn` and `rail.startDoor` take an optional `engine`, and `models.list` also returns the `engines` the Daemon offers (`{id, label}`, like `models`). Every caller changes in the same PR and `App Settings` joins `GLOSSARY.md`'s _The App_. The Daemon stores nothing: App Settings are app-wide, so the webview keeps them in one `storedValue` record (`roundup:app-settings`, `state/storage.ts`), valid or defaulted field by field, and passes the chosen values on each call.

**U3799 `Settings…` in the app menu opens App Settings.** Given the App's macOS app menu, then it holds `Settings…` with `⌘,` under the app name's About item. Choosing it, or pressing `⌘,` in the webview, shows the App Settings view in the center in place of what it showed, with the Rail and Shelf still visible beside it and no dialog or window opened, whether or not a Project is open. It is the shared shell (U3764) with the heading **Settings** and the groups **Agents**, **Terminal**, **Shortcuts** and **Appearance** in that order; a second activation while it is open changes nothing. Tests: `s_u3799_the_app_menu_holds_settings_with_cmd_comma_and_emits_open_app_settings` (`crates/desktop/tests/`, Tauri mock runtime), `u3799_the_event_and_cmd_comma_open_app_settings_in_the_center_with_four_groups` (`apps/desktop/src/settings/`). Observer: the design critic on `just capture U3799` at 1512×950, dark, `tree-40`, with failure text visible on the densest seed (no test asserts geometry, rule 10).

**U3800 closing returns the center.** Given U3799's view, when the user activates the close control or presses Escape, then the center shows what it showed before and focus returns to the element that held it before the view opened; every value read after a reopen is the saved one. Tests: `u3800_close_returns_the_center_and_focus`.

**U3801 the permission mode new Agents start in.** Given the **Agents** group, then it holds a choice `Permission mode` with `Use my Claude Code default` first and selected on a fresh App, then `Default`, `Accept edits`, `Plan` and `Auto`. Given a mode chosen, when the user starts, resumes or clears an Agent normally, then the call carries that `permissionMode`; with `Use my Claude Code default` it carries none, so B2706 applies. A YOLO start is unchanged and ignores the choice. `agent.spawn` starts a new Agent, `rail.startDoor` starts or resumes a Door, `agent.resume` resumes an Agent, and `workstream.clear` carries the choice to its Door's next fresh launch after the Handoff; the old Door keeps its mode while writing that Handoff. An Agent already running keeps its mode (policy). Tests: `u3801_a_chosen_mode_rides_start_resume_and_clear`, `u3801_the_default_choice_sends_no_mode`, `u3801_yolo_ignores_the_choice`; in `crates/agents/tests/launch.rs`, `u3801_a_given_permission_mode_is_passed_to_claude_and_none_passes_nothing` (argv of start, resume and clear; YOLO argv unchanged).

**U3802 the default engine and model for a new Agent.** Given the **Agents** group, then it holds `Engine`, listing the `engines` of `models.list`, and `Model`, listing that engine's `models`, each with `Use the default` first and selected on a fresh App. Given an Engine and Model chosen, when the user starts a new Agent, then `agent.spawn` (or `rail.startDoor` for a Door) carries them; `Use the default` carries none, so the Project's Role models (A36) and the engine's own default apply. Changing the Engine resets Model to `Use the default` when the chosen model is not that engine's. A `models.list` that fails shows `✕ <message>` in the group and leaves the saved choice untouched. Today only Claude Code has an Adapter, so only it is listed; Codex appears with its Adapter (policy, no Codex Adapter exists on `main`, tracked on #3281). Tests: `u3802_engine_and_model_ride_a_new_agent`, `u3802_changing_the_engine_resets_a_foreign_model`, `u3802_a_failed_list_shows_the_message_and_keeps_the_choice`; `crates/rupd/tests/`: `u3802_models_list_returns_the_offered_engines`.

**U3803 Terminal font family and size.** Given the **Terminal** group, then it holds `Font family` (text, empty meaning the App's default stack) and `Font size` (a number from `--text-terminal-min` to `--text-terminal-max`, `fontSize.ts`). Given a committed change (Enter or blur with a changed value), then every open Terminal and every Terminal opened later renders with it at once, with no restart and without losing its scrollback; a size outside the range is refused in the field with `✕ <message>`, changing nothing. A Terminal's own zoom (`fontSizeStorage`, per path) keeps overriding the size for that Terminal until it is reset (policy). Tests: `u3803_a_commit_applies_to_open_and_new_terminals`, `u3803_a_bad_size_is_refused_and_changes_nothing`, `u3803_a_per_terminal_zoom_still_wins`.

**U3804 the Todo quick-add chord.** Given the **Shortcuts** group, then it holds `Quick add a Todo`, showing U3737's chord (`⇧⌘T`). Given the user activates it and presses a new chord (one non-modifier key with at least `⌘` or `⌃`), then the chord is saved and `CHORDS` (Help, the hint line, U3737's handler) uses it at once; Escape cancels and a `Reset` returns `⇧⌘T`. A chord that clashes with another `CHORDS` row, a leader key or a macOS-reserved chord (`⌘Q`, `⌘H`, `⌘Space`, `⌘Tab`) is refused with `✕ <the chord> is already <action>` naming what holds it, saved nowhere, and the old chord stays. Tests: `u3804_a_new_chord_opens_the_field_and_help_lists_it`, `u3804_a_clashing_chord_is_refused_naming_the_holder`, `u3804_reset_restores_the_default`.

**U3805 the App's mode.** Given the **Appearance** group, then it holds `Mode` with `Dark`, `Light` and `System`, and `System` selected on a fresh App. `Dark` and `Light` set the color scheme of the whole webview (`color-scheme` on the root, so `tokens.css`'s `prefers-color-scheme` rules and the Terminal theme, `terminal/theme.ts`, follow it) whatever macOS says; `System` follows macOS and changes when macOS does, with no restart. Open Terminals switch theme with it. Tests: `u3805_dark_and_light_override_the_system_scheme`, `u3805_system_follows_a_change_of_the_media_query`, `u3805_open_terminals_take_the_new_theme`. Observer: the design critic on `just capture U3805` in dark mode (U3725) reads D2, D5, D6 on the view and on `Light` once (no Check passing on `main` regresses).

**U3806 settings persist and apply at once.** Given any change in U3801–U3805, then it takes effect without restarting the App and survives one; a stored record that is unreadable or invalid in a field falls back to that field's default, the others kept. A change shows in every open Project tab. Tests: `u3806_a_change_survives_a_reload`, `u3806_an_invalid_field_falls_back_alone`, `u3806_every_open_tab_sees_a_change`.
