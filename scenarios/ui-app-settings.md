# UI: App Settings open as a center view

Acceptance for #3281, from the user's request: "we need to have settings view in the window mac menu for the whole app" and "the settings of the app also holds the mode -> dark | light | system". Module: `apps/desktop/src/` (`settings/`, `terminal/`, `keys/`, `app/`) and `crates/desktop/src/menu.rs`. Ids: U3799–U3806. Builds on #3280's shared shell (`settings/SettingsShell.tsx`, U3764), on B2706 (the user's own permission mode) and on U3737 (the capture chord). Chosen form: a center view, not a dialog or a separate window.

Contract (policy, by the Contract recipe of `.agents/builder.md`): one App seam event `open-app-settings` (App to webview, no payload) is added to `scenarios/app.md`'s seam table, `agent.spawn`, `rail.startDoor`, and `agent.resume` take an optional `permissionMode` (`default`, `acceptEdits`, `plan`, `auto`; absent means the user's own Claude Code mode, B2706), `agent.spawn` and `rail.startDoor` take an optional `engine`, and `models.list` also returns the `engines` the Daemon offers (`{id, label}`, like `models`). Every caller changes in the same PR and `App Settings` joins `GLOSSARY.md`'s _The App_. The Daemon stores nothing: App Settings are app-wide, so the webview keeps them in one `storedValue` record (`roundup:app-settings`, `state/storage.ts`), valid or defaulted field by field, and passes the chosen values on each call.

**U3799 `Settings…` in the app menu opens App Settings.** Given the App's macOS app menu, then it holds `Settings…` with `⌘,` under the app name's About item. Choosing it, or pressing `⌘,` in the webview, shows the App Settings view in the center in place of what it showed, with the Rail and Shelf still visible beside it and no dialog or window opened, whether or not a Project is open. It is the shared shell (U3764) with the heading **Settings** and the groups **Agents**, **Terminal**, **Shortcuts** and **Appearance** in that order; a second activation while it is open changes nothing. Tests: `s_u3799_the_app_menu_holds_settings_with_cmd_comma_and_emits_open_app_settings` (`crates/desktop/tests/`, Tauri mock runtime), `u3799_the_event_and_cmd_comma_open_app_settings_in_the_center_with_four_groups` (`apps/desktop/src/settings/`). Observer: the design critic on `just capture U3799` at 1512×950, dark, `tree-40`, with failure text visible on the densest seed (no test asserts geometry, rule 10).

T3779c observer disposition: `u3799_u3805_rendered_settings_checks` and `settings/u3799_browser.test.py` retain the dense-seed Settings/refusal captures and the System-dark/explicit-Light captures for the design critic. The duplicate first-run browser load is removed: `u3799_the_event_and_cmd_comma_open_app_settings_in_the_center_with_four_groups` and `u4277a_sections_work_by_pointer_and_keyboard_project_false` prove opening and section access without a Project. The duplicate browser reset from Light to System is removed: `u3805_dark_and_light_override_the_system_scheme` and `u3805_system_follows_a_change_of_the_media_query` prove scheme selection and host changes in jsdom. No product clause retires.

**U3800 closing returns the center.** Given U3799's view, when the user activates the close control or presses Escape, then the center shows what it showed before and focus returns to the element that held it before the view opened; every value read after a reopen is the saved one. Tests: `u3800_close_returns_the_center_and_focus`.

**U3801 the permission mode new Agents start in.** Narrows B2706 only for an explicit user-selected `permissionMode`: omission keeps its no-flag rule, and B50(b) notes name the mode actually launched in either case. Given the **Agents** group, then it holds a choice `Permission mode` with `Claude Code default` first and selected on a fresh App, then `Default`, `Accept edits`, `Plan` and `Auto`. Given a mode chosen, when the user starts or resumes an Agent normally, then the call carries that `permissionMode`; with `Claude Code default` it carries none, so B2706 applies. A YOLO start is unchanged and ignores the choice. `agent.spawn` starts a new Agent, `rail.startDoor` starts or resumes a Door, `agent.resume` resumes an Agent. An Agent already running keeps its mode (policy). An internal restart, including an Agent adding extras, retains an explicit user choice rather than reverting to a broader vendor default; `u3801_an_agent_restart_keeps_the_users_permission_choice` in `crates/rupd/tests/` asserts it. Tests: `u3801_a_chosen_mode_rides_start_resume_and_clear`, `u3801_the_default_choice_sends_no_mode`, `u3801_yolo_ignores_the_choice`; in `crates/agents/tests/launch.rs`, `u3801_a_given_permission_mode_is_passed_to_claude_and_none_passes_nothing` (argv of start and resume; YOLO argv unchanged).

**Permission mode** (`PermissionMode`, `permissionMode` on launch calls): The user's choice for one normal Attempt (`LaunchMode` retains it for internal restarts): `default`, `acceptEdits`, `plan` or `auto`. Omission passes no permission flag, preserving the vendor's own default. `agent.spawn`, `rail.startDoor` and `agent.resume` apply it to their launch. YOLO ignores it. An Agent cannot choose it, and it never changes an already running Attempt or stores an app-wide default in the Daemon.

**U3802 the default engine and model for a new Agent.** Given the **Agents** group, then it holds `Engine`, listing the `engines` of `models.list`, and `Model`, listing that engine's `models`, each with `Use the default` first and selected on a fresh App. Given an Engine and Model chosen, when the user starts a new Agent, then `agent.spawn` (or `rail.startDoor` for a Door) carries them; `Use the default` carries none, so the Project's Role models (A36) and the engine's own default apply. Changing the Engine resets Model to `Use the default` when the chosen model is not that engine's. A `models.list` that fails shows `✕ <message>` in the group and leaves the saved choice untouched. Today only Claude Code has an Adapter, so only it is listed; Codex appears with its Adapter (policy, no Codex Adapter exists on `main`, tracked on #3281). Tests: `u3802_engine_and_model_ride_a_new_agent`, `u3802_changing_the_engine_resets_a_foreign_model`, `u3802_a_failed_list_shows_the_message_and_keeps_the_choice`; `crates/rupd/tests/`: `u3802_models_list_returns_the_offered_engines`.

**Engine** (`engine`, `ModelList.engines`): The opaque identity of an implemented Adapter offered by `models.list`, with its display label. Today the Claude Code Adapter offers `claude-code` labelled `Claude Code`; no other engine is implemented. `agent.spawn` and `rail.startDoor` accept an offered id; omission selects the existing Adapter. Model and Effort ids remain opaque outside their Adapter.

**U3803 Terminal font family and size.** Given the **Terminal** group, then it holds `Font family` (a dropdown under U4687a, with the App's default stack as a choice) and `Font size` (a number from `--text-terminal-min` to `--text-terminal-max`, `fontSize.ts`). **U3804 the Todo quick-add chord.** Given the **Shortcuts** group, then it holds `Quick add Todo`, showing U3737's chord (`⇧⌘T`). Given default settings and no saved Mac-wide chord, then `⇧⌘T` in the webview opens quick add through `CHORDS`, `capture.configure` is called with no chord, and the native side registers no global shortcut, so in every other app `⇧⌘T` is that app's own. Policy (class): `capture.rs` is the only `global_shortcut` registration and no default setting registers one. Tests: `u5205_default_settings_call_configure_with_no_chord_and_cmd_shift_t_opens_quick_add`, `u5205_a_mac_wide_chord_calls_configure_and_reset_returns_none`, `u5205_no_default_setting_registers_a_global_shortcut` (a guard that fails when a default setting yields a `capture.configure` chord), and the capture-panel registration, refusal, replacement and release tests in `crates/desktop/tests/capture_panel/mod.rs` with an explicit chord.

**U3805 the App's mode.** Given the **Appearance** group, then it holds `Mode` with `Dark`, `Light` and `System`, and `System` selected on a fresh App. `Dark` and `Light` set the color scheme of the whole webview (`color-scheme` on the root, so `tokens.css`'s `prefers-color-scheme` rules and the Terminal theme, `terminal/theme.ts`, follow it) whatever macOS says; `System` follows macOS and changes when macOS does, with no restart. A change shows in every open Project tab. Tests: `u3806_a_change_survives_a_reload`, `u3806_an_invalid_field_falls_back_alone`, `u3806_every_open_tab_sees_a_change`.

## Native inset settings

Acceptance for #5242, from the Rex settings pattern (inset grouped rows, a muted description under each control, Back and Forward, live previews). Extends the existing App Settings view; no new RPC, App seam command, setting or domain term. Policy — taste: Settings is the one place a group of rows sits in a rounded inset box; this exception to "No outlines or boxes around controls or tabs" and "Radius only on floating panels" (`.agents/data/journey.md`) covers the group box only, and every other taste line holds, "No hover background boxes" included. Boxes, radius and spacing use existing Tokens only (rule 8); the pages' controls use `ui/` primitives (policy).

**U5242a settings rows form inset groups.** Given any App Settings page, when it shows, then its controls sit in rows, each row naming its setting and holding its control, and the rows of one group share one container that the page exposes as a labelled group (`role="group"` named by the group heading, or a `fieldset` and `legend`). Reading order and the accessible name of every control are unchanged from U4686d. Test: planned `u5242a_each_page_exposes_its_rows_as_labelled_groups` in `apps/desktop/src/settings/`, asserting roles, names and that every control sits in a group, not CSS. Observer: the design critic on `just capture U5242a` at 1512×950, dark, reads that each group is one rounded inset box with row dividers, no box around a single control, no hover background, D2, D5 and D6 holding on the densest seed (no test asserts geometry or radius, rule 10).

**U5242b a muted description sits under each control.** Given a row whose setting has a description (U4686d), when the page shows, then the description is the text directly after the row's label and control, associated to the control as its `aria-describedby`, and is not placed beside or above it. A row with no description renders no empty element. Test: planned `u5242b_each_control_is_described_by_the_text_under_it` in `apps/desktop/src/settings/`, extending U4686d's association proof rather than adding a second one. Observer: the design critic reads the muted tone and wrapping of a long description at the narrowest supported width (no test asserts colour or layout).

**U5242c Back and Forward move through the views.** Given Settings opened from a preceding center view (U4686b), then the header holds `Back` and `Forward`. `Back` closes Settings as U4686b specifies and `Forward` is disabled; once Back has closed it, a control `Forward` in the restored view's header (or `⌘]`) reopens Settings on the page last shown with its exact unfinished field text (U3806), until the user opens any other view, which clears it. Test: planned `u5242c_forward_reopens_settings_after_back_and_clears_on_other_navigation` in `apps/desktop/src/settings/`, plus the existing U3800 and U4686b Back proofs unchanged. Observer: the design critic reads the pair's placement and disabled look.

**U5242d a setting that changes looks previews live.** Given a setting whose value changes how something looks, then its row holds a preview of that value that updates on the current draft without a commit, a Daemon reply or a restart. Terminal font family, weight, size, line height and letter spacing keep U4687b's Terminal preview; Mode and interface scale (U4687a) preview in the same way inside their group, using the draft value and leaving the real App unchanged until it commits. A preview starts no program and sends no RPC. A setting that changes no look (Permission mode, Engine, Model, a chord) shows no preview. Test: planned `u5242d_mode_and_scale_previews_follow_the_draft_without_committing` in `apps/desktop/src/settings/`, asserting effective preview values and saved values; U4687b's tests stay its proof for the Terminal preview. Observer: the design critic compares the previews with the applied result.
