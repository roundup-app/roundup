# UI: primary navigation stays available

Acceptance for the implementation work order #4274. Journey stages: Enter, Understand and Intervene. Project tabs, the Rail and the Terminal bar are primary navigation. They remain mounted at rest; the calm-screen rule applies to secondary facts and inspection. This specification amends U2539b and restores U469's bar clauses. Shelf, Drawer, resource inspection, history and other secondary surfaces retain their on-demand behavior.

Policy: implement through the existing connected App and its current header, Rail, Bubble, menu and shortcut seams. Restore the Project strip's placement from `2efe45864`, retaining subsequent flat-tab styling, rename, overflow, attention, native title, window drag and zoom behavior. No new RPC method, App seam command, Token or glossary term is ordered. The test names below are required implementation observers, not claims that tests or behavior already exist. The specification PR leaves #4274 open.

**U4274a Project tabs share the native window bar.** Given an open Project, including an empty Project, with nothing selected and no requested surface, when the connected App settles, then its Project tablist is inside `WindowBar`, beside the traffic-light reservation, with no second Project-tab strip in the Rail or centre. Tabs require no menu request. Asserted by planned connected-App test `u4274a_project_tabs_mount_in_window_bar` in `apps/desktop/src/header/`, using App directly rather than the RequestedApp wrapper; assert DOM containment, roles and one tab per open Project, never pixel layout.

Given eight open Projects with distinct selections, when the user chooses another Project's window-bar tab, then that Project becomes active with its prior selection restored, and the window-bar tablist remains mounted. Asserted by planned connected-App test `u4274a_window_bar_tabs_switch_projects` in `apps/desktop/src/header/`. Retain existing rename, close, overflow, full accessible names, attention and native title observers (policy; checks 1 and 2).

**U4274b the open Project's Rail is always mounted.** Given an open Project with nothing selected, when the App settles, then the Rail and its direct Workstream/Agent navigation are mounted beside Ask and Needs you without a Workstreams view request. An empty Project retains the Rail and its existing create/start actions. Mounting starts no Agent, submits no Ask and opens no Terminal. Activating a Needs you entry still selects its requesting Agent's Terminal. Asserted by planned connected-App test `u4274b_landing_keeps_primary_navigation_and_attention` in `apps/desktop/src/rail/`, parameterized for empty/populated Projects; replace `u2539b_landing_mounts_only_ask_and_attention` and retain its no-start and attention-destination assertions in this replacement.

Given an open Project, when the user selects an Agent, returns to Ask, switches Projects or opens and closes a secondary surface, then the active Project's Rail remains mounted and available without another navigation request. Shelf, Drawer, history and resource inspection retain their existing open/close behavior. Asserted by planned connected-App test `u4274b_secondary_surfaces_keep_the_rail_available` in `apps/desktop/src/rail/`; retain U2539b's requested-secondary-surface and draft proofs (policy).

Given an open Project, when its Project menu is projected, then it contains no Workstreams or Terminal tabs visibility toggles; New Terminal remains an action. Asserted by planned connected-App test `u4274b_project_menu_omits_navigation_toggles` in `apps/desktop/src/keys/`, inspecting menu roles/dispatch identities rather than exact copy. Remove only the workstreams/terminal-tabs rows from `u2539b_landing_opens_requested_surfaces_and_returns`; this new test replaces their proof (policy).

**U4274c New Terminal opens a focused shell in one action.** Given an open Project with no requested surface and no Terminal, when the user presses ⌘T once, invokes New Terminal from the native menu once, or activates New Terminal on the Rail once, then the chosen action calls `terminal.open` exactly once, shows the returned Bubble and focuses its emulator. It requires no preliminary Terminal-tabs request and no intermediate “+ Terminal / Close” strip. Use U524's existing owner resolution: selected Workstream or selected Agent's Workstream; otherwise the first Workstream in Rail order; with none, `workstream: null` and a Project-owned Terminal, without creating a Workstream or starting a Door. Asserted by planned connected-App test `u4274c_new_terminal_opens_once_and_focuses` in `apps/desktop/src/bubbles/`, parameterized over keyboard/menu/Rail and selected Workstream/selected Agent/no selection/empty Project. Assert returned Terminal identity, call counts, resolved owner, shown Bubble and emulator focus, rather than only a view flag. The rendered observer judges the absence of an intermediate strip (policy).

Given an open Project with a Terminal, when a Terminal opens, minimises, exits, restores or closes, then the Terminal bar remains mounted while any Terminal exists in that Project, without a visibility request. Its tabs follow U469/U524 eligibility; minimising or exiting never hides an eligible tab or closes its Terminal. Selection changes expose the current selection's eligible tabs using existing ownership rules, without closing other Terminals. The bar remains available when the selection has no eligible tabs but the Project still has Terminals. The stable portal host survives even when the Project has no Terminals; New Terminal remains available through keyboard, menu and Rail. Asserted by planned connected-App test `u4274c_terminal_bar_follows_eligible_terminals` in `apps/desktop/src/bubbles/`, checking roles, identities and lifecycle calls. This replaces only the hidden/requested Terminal-tab assertions of `u2539b_strip_items_follow_actionable_facts`; retain that test's secondary-resource, portal/emulator-lifetime and zero-write proofs (policy).

Policy: retain U469's single-Bubble behavior, tab rename/close/cycle, keyboard access, duplicate-name identity and failure recovery, and U165/U524's in-flight, modal/editor ownership and Daemon-exit guards. Extend existing tests rather than duplicate proofs. No test in this specification PR is removed or claimed green for the new behavior. The implementation cuts contradictory U2539b assertions in the files it touches and names each replacement above; all unaffected clauses remain acceptance.

Policy — rendered observer: use the isolated headless U26 connected-App harness with a fresh profile, at 1512×950 in dark mode. Use `empty-project`, `tree-40`, `tabs-8` and `bubbles`; include long Project/Terminal names, an empty selection, minimised/exited Terminals, an open Shelf/Drawer and the densest seed with a complete rejected-open/rename failure visible. ## Agent view gives its space to the Terminal

Acceptance for #4453. Journey stages: Understand and Intervene. Owner direction, corrected 2026-10-28 in #4475: remove the Agent view's header bar, goal dialog, empty strip and undo controls; keep the bottom Terminal bar. The Agent's Terminal fills the height down to that bar. This amends U4315a/U4315b (the centre row), U4323a (hint-line placement), U4274c and the Todo quick-add and undo controls where they contradict the clauses below. Implementation is a dependent Issue; this specification PR leaves #4453 open until its observers exist. The test names below are planned observers, not claims of existing behavior.

Policy — scope: remove markup, copy keys, styles and tests together for the Agent view, and apply the same cut to every Door and Workstream view that mounts the same row, dialog or empty strip. U4453c preserves the bottom Terminal bar in every view, including Ask and requested screens; it overrides any bar-removal wording in #4453. The corrected specification closes #4475 only; implementation remains in its dependent Issue. Shelf, Drawer, Bubbles, requested screens and the Rail keep their own navigation. Mac-native ⌘Z and ⇧⌘Z (U3787a's scope rules) are unchanged. No new RPC method, App seam command, Token or glossary term is ordered.

**U4453a the Agent view renders the Rail and the Agent's Terminal only.** Given an open Project with an Agent selected, a Door selected and a Workstream selected, when the connected App settles, then the centre holds no navigation row (no name, state ring, Back to Ask button or goal line), no goal/Todo dialog, no empty strip between the Terminal and the bottom Terminal bar; the Agent's Terminal fills the centre above that bar. The bar stays (U4453c). Asserted by planned connected-App test `u4453a_agent_view_mounts_only_the_terminal` in `apps/desktop/src/terminal/`, parameterized over Agent, Door and Workstream, checking roles, region membership and absence of the removed controls, never geometry. It replaces the row assertions of `u4315a_navigation_survives_centre_switches` for those views; the Ask view and requested screens keep U4315's row (policy).

**U4453b navigation back needs no button.** Given an Agent, Door or Workstream selected, when the user presses the leader chord `⌘K` then `A`, or activates Ask in the Rail by pointer or keyboard, then the requested centre screen closes, the Rail selection clears and Ask becomes the centre view; the draft, pending-import guard (U4355) and call-count rules of `u4315b_back_to_ask_clears_centre_navigation` hold. Asserted by planned connected-App test `u4453b_back_to_ask_by_leader_and_rail` in `apps/desktop/src/keys/`, which replaces every test that clicked “Back to Ask” in the Agent, Door and Workstream views; U2239's table gains the `A` row and U2240 lists it (policy).

**U4453c no empty strip sits above the bottom Terminal bar; the bar stays.** Given an open Project in any view, including Agent, Door, Workstream, Ask and requested screens, when the connected App settles, then the bottom Terminal bar remains mounted with its New Terminal control (`.terminal-new`), eligible Terminal tabs (`.terminal-tab`) and their Close controls. With no eligible Terminals, New Terminal remains available. Asserted by planned connected-App test `u4453c_terminal_bar_stays_in_every_view` in `apps/desktop/src/bubbles/`, parameterized over those views and empty/populated Projects; assert controls, identities and dispatch, never geometry. Preserve `u4313a_empty_terminal_bar_keeps_new_terminal_available`, `u4313a_bar_plus_opens_once_and_focuses`, `u4313a_closing_the_last_terminal_returns_focus_to_plus` and `u524_a_failed_empty_project_open_can_be_retried` (check 3).

Given eligible minimised and exited Terminals and a saved Terminal rename draft, when the user restores a Terminal from its tab, closes another from its Close control, or opens Recover drafts (`.terminal-recover`), then the chosen Terminal alone restores or closes, and the unfinished-work dialog opens directly with the exact saved draft and original identity, without requiring a failure first. Asserted by planned connected-App test `u4453c_tabs_and_saved_drafts_stay_reachable` in `apps/desktop/src/bubbles/`; retain U469/U524 eligibility, unseen-output marks, rename, cycling, failure recovery and portal/emulator lifetime (policy; checks 3 and 6). No Rail row or leader entry replaces the tabs.

Given an open Project, when the user invokes New Terminal through the bar, ⌘T, the native menu or the command menu, then each invocation calls `terminal.open` once with U524's owner resolution and focuses the returned emulator. Asserted by planned connected-App test `u4453c_new_terminal_opens_once_and_focuses` in `apps/desktop/src/bubbles/`, parameterized over those four paths and selected Agent/Workstream/no selection/empty Project; extend the existing `u4313a_bar_plus_opens_once_and_focuses` proof without duplicating it (check 3). Modal/editor ownership and in-flight/Daemon-exit guards remain policy.

Given focus with shortcut hints, when the user opens the key chips or arms the ⌘K leader, then the applicable hints are reachable in the Terminal bar or key chips, including the armed leader's available actions; no separate hint line reserves height above the bar. When focus has no hints and the leader is idle, no empty hint row reserves height. Asserted by planned connected-App test `u4453c_hints_use_the_bar_or_key_chips` in `apps/desktop/src/keys/`, checking reachable hint/action identities and the absence of a separate hint region; sizing and placement belong to the rendered observer (policy; check 4). Preserve U2230a's context, modal and available-action filtering; command-menu New Terminal remains reachable through the preceding observer.

A current failure remains fully readable and actionable rather than hidden to meet the height requirement. Keep U4459's measured Bubble boundary above the bar, including after move, resize, fill, restore and bar/window-size changes; the bar's controls remain clickable (check 6).
