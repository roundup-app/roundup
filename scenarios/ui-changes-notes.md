# UI: a note starts from the line, shows its own state and sends from one bar (U7676a–U7676e)

Module: `apps/desktop/src/changes/`, the fake App and its fixtures. Ids: U7676a, U7676b, U7676c, U7676d, U7676e. Work order: [#7676](https://github.com/roundup-app/roundup/issues/7676), blocked by #7675. Owner, 2026-11-18: notes start from the line, not from an Add note button; "make it smooth and fully functional with clear convenient states that matches user expectations". No Daemon method, Message or contract change: the one Message per batch of U2540c stands, and #7677 (a designed note, sent notes that stay) and #7691 (a note on a whole file) build after this order. The implementation PR's `Reuse:` section names `@pierre/diffs` 1.6.1 (`enableGutterUtility` with `onGutterUtilityClick`, `enableLineSelection`) and `registerKeys`. Capability Pierre lacks, found in the prototype on 1.6.1: the + sits on the line number and takes its look only through `unsafeCSS` on `[data-utility-button]`; the PR uses that and says so. The same section names Undo history (`state/undo.ts`) and says it cannot hold a note: each of its entries is a Daemon-receipted deletion of Todos, Pads or Rail items (`Stacked`), and a note is neither, so a removed note's Undo lives in the notes store (U7676d). Size: about 650 changed lines. Observer: Vitest against the fake App for U7676a to U7676d; the isolated Chromium harness (U26) for U7676e. Never a native Mac capture.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

**Words.** The App writes "Unfinished work", the user label of Draft (`GLOSSARY.md`), never "Draft" (`AGENTS.md`: App copy uses user labels). Each state below shows the quoted words; a test asserts them through `copy.ts`, never layout or looks (rule 10). `<Agent>` is the Agent's name.

**U7676a a note starts from the line.** Given a loaded text diff (U7674) and the fake App, then:
- **Gutter +.** Activating the reader's gutter utility on a line opens the note field under that line, with Side and the 1-based Start line and End line set to it, and focus in the field. Hovering a line shows the + (U7676e judges how). Asserted in `u7676a_the_gutter_plus_opens_the_field_for_that_line`, which drives `onGutterUtilityClick` the way `u2540b_notes.test.tsx` drives `onLineNumberClick`.
- **Drag.** A drag over line numbers on one side opens the field under the last line for the range, start and end in line order whichever way the drag ran. Shift-click ranges stay (U2540b). Asserted in `u7676a_a_drag_over_line_numbers_opens_the_field_for_the_range`; kept: `u2540b_pointer_and_keyboard_select_lines`, edited to open the field from the selection.
- **What goes.** The Add note button and the "New line N" status are gone; the loading, binary, no-difference and fallback notices stay (U7675b), and a binary or image file offers no line note (U2540a). Asserted in `u7676a_add_note_and_new_line_are_gone_and_the_notices_stay`.

**U7676b the keys write and edit notes.** Given the diff holding focus (U7675e: no note field, text input or editor holds it), then:
- **N.** N opens the field with U2540b's labelled Side, Start line and End line, preset from the focused line (U7675d) or, when a range is Shift-selected, from that range. Asserted in `u7676b_n_opens_the_labelled_field_preset_from_the_line_or_range`.
- **⌘↵ and Esc.** ⌘↵ saves the typed note under its line, and focus returns to that line (U3474e). Esc in an empty field closes it; Esc in a field with text closes it, keeps the text as unfinished work and returns focus to its line, never discarding it (P11). Asserted in `u7676b_cmd_enter_saves_and_escape_keeps_text_as_unfinished_work`.
- **E and Delete.** On a line that holds a note, E opens that note for editing and Delete removes it (the Backspace key too, which is the Delete key of a Mac keyboard); with several notes on the line, the first saved. Remove asks nothing: the notes bar reads "Note removed · Undo" (U7676d). Asserted in `u7676b_e_edits_and_delete_removes_the_notes_line`.
- **Typing first.** None of N, E, Delete or Backspace fires while a note field, text input or the editor holds focus, so none takes a Terminal editing key (U6171c: these are plain keys scoped to the focused diff through `registerKeys`, no App chord). Asserted in `u7675e_keys_do_not_fire_while_typing_in_a_note_field`, edited to press N, E, Delete and Backspace (#7692 edits the same test for V; the build that comes second adds its keys).
- **? list.** The ? list gains N, E and Delete with their actions (U7675e: N, V and R are not listed until the Issues that build them do; this order builds N). Asserted in `u7676b_the_keys_list_gains_n_e_and_delete`.
- **No motion.** No key action animates (as U7675e). Policy; the design critic judges it (U7676e).

**U7676c each note shows its own state.** Given the fake App, then a note draws exactly one of these, in plain words:
- **Unfinished work. (retired)** Retired by #7978: no line or row says "Unfinished work" or carries a mark for it (U7978a); `u7676c_unfinished_work_survives_a_file_switch` is deleted. A field closed by Esc with text, or left by a file switch, still keeps its text, side and range exactly (U2773a), and N reopens it (U7978b).
- **Not sent.** A saved note says "Not sent" and offers Edit and Remove. Editing shows the field with the note's text; its saved text stays until Save replaces it, and Esc with changes keeps them as unfinished work. Asserted in `u7676c_a_saved_note_says_not_sent_and_editing_keeps_it_until_save`.
- **Sending.** While a send is pending each submitted note says "Sending", its Edit and Remove are hidden, its text is locked and a repeat send submits nothing (U2540c). Asserted in `u7676c_a_sending_note_is_locked`.
- **Couldn't send.** A note in a definitely rejected submission says "Couldn't send" and stays editable and removable. Asserted in `u7676c_a_rejected_note_says_couldnt_send_and_stays_editable`.
- **Send unknown.** A note in a submission whose acceptance is unknown says "Send unknown", stays locked, and offers no resend (U2540c, P11). Asserted in `u7676c_an_unknown_acceptance_locks_the_note_and_offers_no_resend`. The Issue's list leaves this state out; P11 requires it.
- **Kept from before the restart.** Notes restored when the App starts (U2773a) are counted on the notes bar as "N notes kept from before the restart", each says "Not sent", and the line goes when the user adds, edits, removes or sends a note or dismisses it. A submission restored as pending shows "Send unknown". Asserted in `u7676c_restored_notes_are_counted_on_the_bar`, extending `u2773a_changes_restores_exact_work`.
- **Lines the diff no longer shows.** A note whose comparison is older than the open one (U5646b) stays where it was made in the batch with "Original context"; its file shows these notes in one group after the file's last line, never moved onto another line (U2540b). Asserted in `u7676c_notes_for_lines_no_longer_shown_gather_after_the_last_line`, extending `u2540b_refresh_keeps_original_context`.

**U7676d the notes bar shows only what needs the user.** Given the fake App, then:
- **When.** The bar shows while the Agent's batch holds a saved note not yet sent, or a send is pending, accepted, rejected or unknown, and for 5 s after the last note is removed, to hold its Undo (Removed, below); at no other time, and unfinished work alone shows no bar. Asserted in `u7676d_the_bar_shows_only_for_unsent_notes_or_a_send`, replacing `u7674b_the_notes_bar_shows_only_while_the_batch_holds_a_note`.
- **The list.** The bar holds the notes' count as a button that opens the batch list of U2540b (file, side, range, text, Edit and Remove); Enter or Space on it opens it, Esc closes it before the view. Asserted in `u7676d_the_count_opens_the_batch_list_by_keyboard`. Edit and Remove there change only that note (kept: `u2540b_edit_remove_and_batch_across_files`). Open for the Issue, settled here: the prototype draws only the bar, so the list opens from the bar.
- **Send.** `Send notes: <Agent>` keeps U2540c's one Message per batch and its busy state. Kept: `u2540c_one_message_contains_all_original_context` and `u2540c_empty_batch_sends_nothing`.
- **Sent.** After an accepted send the bar reads "Sent N notes to <Agent>", the owner's words; N counts the notes just submitted. "Sent" claims only that the Daemon accepted the Message, never delivery (U2540c: acceptance alone claims none). The line stays until the user starts another note or dismisses it. Until #7677 builds, an accepted send clears the submitted notes (`u2540c_acceptance_clears_only_the_submitted_batch`, kept). Asserted in `u7676d_the_sent_line_names_the_count_and_the_agent`.
- **Couldn't send, Retry.** A definite rejection reads "Couldn't send N notes to <Agent>", the cause in full (U80), and Retry, which resubmits the retained notes as one Message. An unknown acceptance keeps U2540c's words and "Check Message history", and offers neither Retry nor Send. Asserted in `u7676d_retry_is_for_a_definite_rejection_only`; kept: `u2540c_rejection_and_unknown_acceptance_preserve_notes`.
- **Removed.** Remove, by key or button, shows "Note removed · Undo" for 5 s; Undo restores the note with its original context to its line. Each removed note stays restorable 5 s from its own removal, and Undo restores the latest still in its window; after 5 s a removed note is gone, as Remove is today. Asserted in `u7676d_remove_offers_undo_for_five_seconds`, with fake timers.

**U7676e the rendered notes at 1512 by 950.** Given the U26 harness, dark App, then these states draw, each capture named with the prefix `note-`: saved, editing, sending, send failed and restored. On the dense fixture (100 notes, a 10,000-line diff; `u2540.html?dense`) the view never scrolls sideways. D2, D5, D6 and every Check passing on `main` still pass.
