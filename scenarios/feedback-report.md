# One chord sends a Feedback report to the live feedback Issue (FB1 to FB6)

Module: `crates/desktop`, `crates/rupd`, `crates/contracts`, `apps/desktop/src` and `contracts/generated/`. Ids: FB1, FB2, FB3, FB4, FB5, FB6, U6381a. Acceptance for [#6164](https://github.com/roundup-app/roundup/issues/6164); implementation in #6165 (shot and App facts, FB2, FB3), #6166 (post or keep, FB3, FB4, FB5) and #6167 (chord, form and setting, FB1, FB2, FB4 to FB6). Decided by the owner (2026-11-04): from this day they use roundup all day; when something feels wrong they press one chord, type a line and send it, and the report lands as one comment on the feedback Issue #6163. Later they shape those comments into work Issues; this feature does none of the shaping.

A **Feedback report** (user label "Feedback") is the owner's line, the shot (FB2) and the debug facts (FB3), sent together. It is the owner's own action from the App: the Daemon posts it, and no Agent can.

Policy, Must not: the report posts nothing the owner has not seen in the form; no environment value, token or output of `gh auth` is read, stored or posted; no report is lost when posting fails.

**FB1 one chord opens the Feedback form.** Given the App in any state with a Project open, a focused Terminal included, when the owner presses `⌘⇧F` (physical `KeyF`, Shift and Command, Control and Option absent; unused on `main` on 2026-11-04), then the App takes the shot (FB2) first and the Feedback form opens after it, with focus in its text field. The chord is a registry action (`scenarios/ui-shortcuts.md`) so the Terminal does not receive it and Help lists it. Escape closes the form, discards the report and returns focus to where it was. A second press while the form is open does nothing. Tests: `fb1_the_chord_opens_the_form_with_focus_in_the_field`, `fb1_a_focused_terminal_does_not_receive_the_chord`, `fb1_escape_closes_and_restores_focus`, `fb1_the_shot_is_requested_before_the_form_mounts` in `apps/desktop/src/feedback/`.

**FB2 the shot is the window as it was.** Given the chord, then the App captures a PNG of the roundup window as it looked when the chord was pressed, without the form, Terminal text included (Terminals draw in a canvas). The capture sits behind a seam (a Tauri command in `crates/desktop` with a fake that returns a fixed PNG), so tests run with no display. The form shows the shot as a thumbnail and a control drops it; a dropped shot is not sent. A capture that fails or is refused by the operating system leaves the form open with no shot and a line that says why; Send still works. Tests: `fb2_the_capture_seam_returns_a_png_of_the_window` (`crates/desktop`, fake display), `fb2_a_failed_capture_opens_the_form_without_a_shot`, `fb2_the_form_previews_the_shot_and_drops_it`, `fb2_a_dropped_shot_is_not_sent` (`apps/desktop/src/feedback/`).

**FB3 the debug facts are shown and hold no secret.** Given the form, then it shows as text, before sending: App version and commit, macOS version, the Daemon up or down, the open Project, the selected Agent, Terminal or Workstream with its state and Kind, and the last 200 lines of the App log and of the Daemon log. The same text is what posts. It holds no environment value, token or Terminal scrollback: the shot is the only screen content. A log line that matches a token pattern (`gh[pousr]_…`, `github_pat_…`, `Bearer …`, a `KEY=value` of `GH_TOKEN` or `GITHUB_TOKEN`) is replaced by `[redacted]` before it is shown. Tests: `fb3_the_facts_name_version_os_daemon_and_selection` (`crates/desktop`), `fb3_the_logs_end_at_their_last_200_lines`, `fb3_a_token_in_a_log_is_redacted_before_it_is_shown`, `fb3_no_environment_value_or_scrollback_is_collected` (`crates/desktop`, a fake environment holding a marker value), `fb3_the_form_shows_the_text_that_posts` (`apps/desktop/src/feedback/`).

**FB4 Send posts one comment through the owner's `gh`.** Amends A5168d's "no comment" clause for this one method; the Contract recipe applies (`contracts/`, `GLOSSARY.md`, M5). New method `feedback.send {text, shot?, facts}` returns `{state: "posted", url}` or `{state: "kept", folder, cause}` (FB5). The Daemon runs the `gh` on its `PATH` with its own environment (A5168d) once: `gh issue comment <number> --body-file - --attach <shot>` for the Feedback Issue FB6 names, with the body (the line, then the facts) on stdin, so nothing reaches a shell; with no shot, no `--attach`. A5168c's error rule holds: a failure is one line naming `gh` and its first stderr line, at most 200 bytes, with no token, header or environment value. roundup stores, reads and passes no token. The form closes at Send, a Toast links the new comment, and the App stays usable while the call is pending. `feedback.send` is the owner's: M5 lists it under No tool with the reason that an Agent that posted could write to the owner's GitHub account unseen, and an Agent's call is `FORBIDDEN`. Tests (`fb4_`, a fake `gh` on `PATH` that records its argv, stdin and environment): `fb4_send_runs_one_comment_with_the_body_on_stdin_and_the_shot_attached`, `fb4_no_shot_runs_no_attach`, `fb4_a_failure_names_gh_with_its_first_stderr_line`, `fb4_no_token_variable_is_set_or_read`, `fb4_an_agent_is_forbidden` (`crates/rupd`), `fb4_send_closes_the_form_and_the_toast_links_the_comment`, `fb4_the_app_stays_usable_while_it_posts` (`apps/desktop/src/feedback/`), and `m5_every_app_action_has_a_tool_or_a_reason`.

**FB5 a report is never lost and never posts twice.** Given `gh` missing from `PATH`, logged out, offline or refusing, when Send runs, then the Daemon saves the report (line, facts, shot) to one folder per report under `<App data>/feedback/<id>/` before it returns `kept`, and the Toast names the cause (FB4's line) and the folder. The Toast's Retry runs `feedback.retry {id}`, which posts the saved report as FB4 does; on success the folder moves to `<App data>/feedback/posted/<id>/` and holds the comment URL. A report that posted is never posted again: a second `feedback.retry` for it, a retry racing the first, and a Send repeated by a double press each return the first result and run no `gh` (the report's id is the key). A report is saved before `gh` runs and removed from the unposted list only after `gh` exits 0, so a crash in between leaves it to retry. Tests (`fb5_`, fake `gh`): `fb5_a_missing_or_failing_gh_keeps_the_report_in_its_folder`, `fb5_the_kept_report_holds_the_line_the_facts_and_the_shot`, `fb5_retry_posts_once_and_moves_the_folder`, `fb5_a_second_or_racing_retry_runs_no_gh`, `fb5_a_double_send_posts_once`, `fb5_a_crash_after_posting_before_the_move_does_not_post_twice` (`crates/rupd`), `fb5_the_toast_names_the_cause_and_the_folder_and_retries` (`apps/desktop/src/feedback/`).

**FB6 the target is a setting.** Given App Settings, then a field holds the Feedback Issue's URL (`https://github.com/<owner>/<repo>/issues/<n>`) in the App's own settings; the owner sets it to `https://github.com/roundup-app/roundup/issues/6163`. The Daemon passes the URL to `gh issue comment` so `gh` resolves the repository (the Feedback Issue need not belong to the open Project). With the field empty or not an Issue URL, Send saves the report as FB5 does and the Toast says the setting is empty or invalid, never that `gh` failed; a later Retry after the owner sets it posts to the new target. Tests: `fb6_the_setting_holds_and_validates_the_issue_url` and `fb6_an_empty_setting_keeps_the_report_and_says_so` (`apps/desktop/src/feedback/`), `fb6_the_url_is_the_comment_target` and `fb6_an_empty_target_keeps_without_running_gh` (`crates/rupd`, fake `gh`).

**U6381a the Feedback Issue defaults to the live one.** Amends FB6's "the owner sets it" clause. Given an App with no saved Feedback Issue, then the field holds `https://github.com/roundup-app/roundup/issues/6163` and Send posts there. A saved value stays as U6276a says, a saved other URL included; a saved empty value keeps reports unsent as FB6 says. How a report is sent, kept or retried (FB4, FB5) does not change. Test: `u6381a_a_fresh_app_targets_the_live_feedback_issue_and_a_saved_value_stays` in `apps/desktop/src/settings/` (fresh settings give that URL and `feedback.send` carries it as its target; a saved other URL stays; a saved empty value stays empty).

**Observer.** One real send from the owner's Mac posts a comment with a shot to #6163. An agent on the Mac runs it and reports the comment URL on #6164; no `flag:needs-mac` holds any PR. Linux CI runs every test above with no display, a fake `gh` and the capture seam's fake.
