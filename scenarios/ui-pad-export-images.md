# UI: a Pad's diagrams and drawings export as images (U7415a to U7415c)

Module: `apps/desktop/src/pads/` (the webview) and `crates/pads/` (the Daemon's `pad.export`). Ids: U7415a–U7415c. Owner, 2026-11-17: "when the user exports a pad to md we add diagrams and drawings as photos". Narrows P6 and U21; follows #7414 (drawings render clean).

**U7415a an export links each diagram and drawing as an image.** Given a Pad holding, in order, a Mermaid block (U148), prose and a Drawing (U149), when the user exports it through U21's chooser to `/d/notes.md`, then:
- The webview renders each block to SVG with Mermaid's own `mermaid.render` (`strict` security level, as U148) and Excalidraw's own `exportToSvg` (never a hand-made renderer, rule 9), and the drawing's SVG shows no Excalidraw tool bars (#7414).
- `/d/notes.md` holds the Pad's text with each block replaced by `![Diagram 1](notes/diagram-1.svg)` and `![Drawing 1](notes/drawing-1.svg)`; the numbers count each kind from 1 in Pad order, and every other byte of the text is as stored.
- The folder `/d/notes/` holds `diagram-1.svg` and `drawing-1.svg`, each an SVG document. A block that fails to render (U148's invalid text) stays in the `.md` as its fenced source, takes no number, and writes no file; the export still succeeds.
- The stored Pad is unchanged by the export (P6, U148's byte-exact rule).
- Tests: `u7415a_export_links_each_block_and_writes_its_svg` (Vitest over the fake Daemon, one diagram and one drawing: the `pad.export` call's `text` holds both links and `images` names both files with SVG content), `u7415a_an_unrenderable_block_stays_fenced_and_is_not_numbered`, and the Rust case `u7415a_export_writes_the_text_and_the_images_folder` (`crates/pads/`, a temp directory: both files exist beside the `.md`).

**U7415b a Pad without blocks exports as before.** Given a Pad with no Mermaid block or Drawing, when it is exported, then `pad.export {name, path}` is called with no `text` and no `images`, one `.md` holding the stored text is written, and no folder is created; Mermaid and Excalidraw are not loaded for it (U148, rule 7). Test: `u7415b_a_pad_without_blocks_exports_its_text_alone` asserts the call's params and that neither module is requested. U21's other clauses (the chooser's suggested name, cancelling calls nothing, an error shows its toast) hold unchanged.

**U7415c `pad.export` writes the images folder.** Contract change (Contract recipe of `.agents/builder.md`; every caller changes in the same PR): `pad.export` gains optional `text: string` (written to `path` in place of the Pad's text) and optional `images: [{name, svg}]` (each written to the folder named by `path` without its `.md` suffix, beside `path`; the folder is created only when `images` is non-empty). An `images` name that is not a plain file name ending `.svg` (a separator, `..`, an absolute path) is `INVALID_PARAMS` and nothing is written. The relative-`path` and missing-directory errors of P6 hold and nothing is written then. `crates/contracts/` with `contracts/generated/`, `crates/pads/`, `crates/rupd/` where it dispatches, the App seam's `pad.export` caller and `GLOSSARY.md`'s Pad entry change with it; `pad.export` still leaves the Pad's text, Revision and Home unchanged and still touches it as a read (P15). It touches no Message law (M1 to M10). Tests: `u7415c_export_rejects_an_image_name_that_leaves_the_folder` and `u7415c_export_without_images_creates_no_folder` (Rust, `crates/pads/`).

Policy: amends P6's "one `.md` file" to "the `.md` file, and the images folder when `images` is given". Lost, by the owner's decision: embedding the images inside the one `.md`.
