# The import dialog and every modal sit in the middle

Module: `apps/desktop` (`ui/`, `importer/`, `shelf/`, `header/`, `todos/`, `bubbles/`). Ids: U3083a–U3083e. Acceptance for #3083 and #3180. Webview only: no App command, no Daemon method, nothing under `contracts/`. Narrows U2875d (`scenarios/import-work.md`): its period, selection, confirm, cancel, retry and restore clauses hold. These are acceptance specifications, not implementation evidence.

The journey stage is Enter (`.agents/data/journey.md`): the user brings earlier work in through a dialog that opens where they look and lists only what they can import. The taste rules #3021 adds (`scenarios/unfinished-input.md`, "Work at risk") apply to every string below.

**U3083a one positioner centres every modal.** Given any modal (the import dialog, bulk delete, the close dialog, the Todo drawer dialog, a Bubble dialog, the Project tab dialog), when it is open at 1512×950, then its content is rendered inside the one positioner `ui/Dialog.tsx` owns, and its centre is within 1 px of the window's centre on both axes. No other file styles a modal's positioner. A pointer press on the dialog never draws a focus ring round the dialog itself (D6); a control inside keeps its own. Assert in `u3083a_every_modal_renders_in_the_shared_positioner` (jsdom: each modal's content has the shared positioner as its ancestor and no modal file defines its own) and `u3083a_modal_centre_is_the_window_centre` (headless Chromium, real layout, centre measured on each modal on the densest seed). Policy: the taste list of `.agents/data/journey.md` holds "A modal's centre sits at the window's centre within 1 px on both axes; only `ui/Dialog.tsx` positions a modal."

**U3083b only importable conversations are listed.** Given discovery results with importable and not-importable conversations (already imported, ambiguous Project membership), when the import dialog opens, then it lists only the importable ones, each as one row, and no excluded conversation renders. When any are excluded, one quiet line below the list reads `<n> not importable` with a disclosure. Opening the disclosure lists each excluded conversation by its title, or its start time when it has none, with its reason in user words: `Already imported` or `Used more than one folder of this Project`. No session id renders anywhere in the dialog. Closing the disclosure removes the entries. With none excluded, the line does not render. Assert in `u3083b_excluded_rows_absent_until_the_disclosure_opens` and `u3083b_reasons_are_user_words_and_no_id_renders` at the App seam; U2875a's discovery and `u2875d_*` tests keep proving their clauses.

**U3083c one compact row.** Given an importable conversation, when listed, then its row has a tick box, its title, and a quieter second line with its folder and relative time; the tick box is a checkbox, not a radio-like circle. A failed import of that row shows its error on the same second line, naming its cause and what to do, never apart from the row. Assert the checkbox role, selection by pointer and keyboard, and the failure text in the row's second line in `u3083c_row_is_checkbox_title_and_second_line` and `u3083c_failed_import_error_names_cause_and_fix` at the App seam. Policy: the critic checks the row's structure, the second line's quieter tone and the error's place on the densest seed (long Unicode titles, ten results, an unavailable source, a partial failure); behaviour tests assert no layout or exact copy.

**U3083d a stale pick drops quietly.** Given a restored unsubmitted selection whose sources changed or are gone, when the dialog opens, then the stale picks are dropped, no `Changed or gone since you chose them` text renders and the remaining valid picks stay selected. The restored selection never submits itself. Assert in `u3083d_stale_picks_drop_without_a_notice`, extending the `u2875d` restore probes at the App seam.

**U3083e every modal's centre is measured.** Given each modal U3083a lists (the import dialog, bulk delete, the close dialog, the Todo drawer dialog, a Bubble dialog, the Project tab dialog), when it is open at 1512×950 in a mounted App, then its centre is within 1 px of the window's centre on both axes, and a modal whose own rule offsets it fails. Each modal is mounted through the action that opens it, never read from source text. Assert in `u3083e_every_modal_centre_is_the_window_centre` (headless Chromium, real layout, one measured case per modal, run by `just check` and not only under capture); it replaces the import-panel-only measurement in `u3083a_modal_centre_is_the_window_centre`, which keeps no clause of its own.

Checks it moves (rule 8): D2, D5 and D6 hold at 1512×950 on the densest seed, dark, using only Tokens, with no Check passing on `main` regressing; capture U3083a–c under `artifacts/ux/` through the existing harness (`.agents/data/harness.md`).
