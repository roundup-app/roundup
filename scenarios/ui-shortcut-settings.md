# UI: the Shortcuts page lists, records and exports every shortcut

Module: `apps/desktop` (`settings/ShortcutSetting.tsx`, `keys/chords.ts`, `keys/registry.ts`, `app/seam.ts`). Ids: U5239a–U5239e.

Specification for #5239. Builds on U3804 and U5205 (`scenarios/ui-app-settings.md`), U3806 (persistence), U2241 and U12 (Terminal key ownership), and the named action list of NA1–NA5 (`scenarios/named-actions.md`, #5236, an implementation prerequisite). A spec merge claims no behavioral pass; every test named here is planned.

Outside evidence (#5239): Rex, Superlogical's Mac terminal multiplexer, lists every shortcut, sets one in the app with Change Shortcut…, and resolves defaults, the config file and app-set shortcuts in that order (https://www.superlogical.com/rex/docs/llms-full.txt).

Observer for U5239a–e: Vitest in `apps/desktop/src/settings/` on the real `CHORDS` and `LEADER` tables, the registry and the mounted Settings view, as `u3804_*` does; the save dialog is the seam's `chooseSavePath` double. No browser, no Mac.

Policy: the action list of NA5 is the only source of rows (a second list is a defect); a row's label is the action's label and its keys are the keys Help shows now. An override is a saved press for one action `name` (NA1), stored with the other App settings (U3806). Resolution order, last wins: the default in `CHORDS`/`LEADER`, then the saved override. Recording reuses U3804's modal registry layer and its tinykeys press syntax; no new key library and no new App-scope chord (U2241's allowlist is unchanged; an override replaces a chord, never adds one). Pre-release data is disposable: no migration.

**U5239a every action is listed by name.** Given the **Shortcuts** group, then it holds one row per action of NA5 in Help's order, each showing the action's label and its keys now (`None` for an action without a key), and the two quick-add rows of U3804 and U5205 are among them with their behaviour unchanged. An action added to `CHORDS` or `LEADER` appears with no change here. Tests: `u5239a_one_row_per_named_action_with_its_label_and_keys` (rows equal the NA5 list, quick-add rows included), `u5239a_a_new_table_entry_gets_a_row`.

**U5239b record a new key for any action.** Given a row, when the user activates its key and presses a chord, then it is saved as that action's override and Help, the hint line, the menu and the key handler use it at once and after a reload (U3806); Escape cancels; the row's `Reset` returns the default and shows only while overridden. A chord that another action holds, a leader key or a macOS-reserved chord (`⌘Q`, `⌘H`, `⌘Space`, `⌘Tab`) is refused with `✕ <the chord> is already <action>` naming the holder, as U3804 does, saved nowhere. Given a chord that needs a modifier rule, then the U3804 acceptance (one non-modifier key with at least `⌘` or `⌃`) holds for every row. Tests: `u5239b_a_recorded_key_runs_the_action_at_once_and_after_reload`, `u5239b_a_clash_or_reserved_chord_is_refused_naming_the_holder`, `u5239b_escape_cancels_and_reset_restores_the_default`.

**U5239c press a key to see its owner.** Given the **Shortcuts** group, when the user activates `Find a key` and presses a chord, then the page shows `<chord> is <action label>` for the action that owns it (default or override), or `<chord> is free`, and runs nothing and saves nothing; Escape leaves the mode. Tests: `u5239c_a_pressed_key_names_its_action_or_says_free`, `u5239c_the_lookup_runs_nothing_and_saves_nothing`.

**U5239d a focused Terminal keeps its keys.** Given a recorded chord that a focused Terminal needs (U2241's rule: any `⌃` or `⌥` combination, or a `⌘` combination other than those the allowlist names, and `⌘C`, `⌘V`), then it is refused with `✕ <the chord> belongs to the Terminal`, saved nowhere. Given the allowlisted chords that already reach App scope (`⌘N`, `⇧⌘N`, `⌘T`, `⌘K`, `⌘/`, `⌘,`, `⌃⌘J`, the quick-add chord, scoped `⌘B`), the user may swap them between actions. Given any saved override, then U2241's modifier sweep at a focused Terminal still sees no other chord handled. Tests: `u5239d_a_chord_a_terminal_needs_is_refused`, `u5239d_the_terminal_sweep_holds_with_overrides` (the sweep of `u2241_no_other_chord_is_taken_at_app_scope` run with overrides saved).

**U5239e export the overrides.** Given at least one override, when the user chooses `Save to file…`, then the seam's save dialog (the installed dialog plugin, `chooseSavePath`) opens with the suggested name `shortcuts.json`, and on a chosen path the file holds exactly the overrides as `{ "<action name>": "<press>" }`, nothing for an unchanged action; a cancelled dialog writes nothing and shows no failure; a failed write shows `✕ <message>` in the group. With no override the control is disabled. Writing the file goes through the Daemon like `pad.export`; a new RPC method follows the Contract recipe of `.agents/builder.md` in the implementing PR. Tests: `u5239e_the_file_holds_exactly_the_overrides`, `u5239e_cancel_writes_nothing_and_no_override_disables_the_control`, `u5239e_a_failed_write_shows_its_cause`.

Regression observers, unchanged and passing: `u3804_a_new_chord_opens_the_field_and_help_lists_it`, `u3804_a_clashing_chord_is_refused_naming_the_holder`, `u3804_reset_restores_the_default`, the `u5205_` tests, `u3806_` tests and `u2241_no_other_chord_is_taken_at_app_scope`.

Moves: D2, D5, D6 (`docs/design-system.md`, heading `The checks`). Policy: the view uses `ui/` primitives wrapping Ark UI and Tokens only; the Reuse section of the implementing PR names the libraries considered (rule 9) and the installed tinykeys registry and dialog plugin first. Blocked by the named action list (#5236) and #5205 (closed); implementation is one Issue, #5239.
