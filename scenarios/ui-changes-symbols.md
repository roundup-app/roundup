**U7695a an item of Logic lists its changed functions and types.** Given the fixture and the fake App, then:
- **List.** The item's pane holds a closed disclosure "Functions and types". Open, it lists one entry for each changed symbol of a finished trace whose `path` is a file of the item: its name, its kind in words (`function`, `type`; a camel-case kind reads as words) and, for a status of added or removed, that word. Order is the item's file order, then the symbol's first line (new span, else old). Asserted in `u7695a_a_logic_item_lists_its_changed_functions_and_types_with_their_kind`.
- **Name.** An entry's name is the symbol's containers and name joined by dots, read from its `key` (`path#containers#name#kind`), without a segment the server leaves anonymous (`<function>`, `<class>` or one ending " callback"); a symbol of kind `topLevel` has no entry; two symbols of one name in one file, whatever their kind, are one entry (the first one's kind, the spans joined), so two changed callbacks in one function list once under that function's name. Decided here, as the Issue's reading that the list shows the server's names: the server names the innermost symbol around a hunk (CP2), so a hunk in a callback or a local names that one, and the enclosing function reads in the dotted containers. Rolling it up to the enclosing function is the Daemon's CP2, which this order does not change. Asserted in `u7695a_a_name_drops_anonymous_segments_and_a_top_level_hunk_has_no_entry`.
- **Only Logic.** Modules, Tests and Flows show no list, and the switch keeps its four lenses (U7679a): the list is no lens. Asserted in `u7695a_a_logic_item_lists_its_changed_functions_and_types_with_their_kind`.
- **No request.** The list reads the traces the view already asked for and makes no `agent.callPaths` request: opening it, and choosing a name, add none. Asserted in `u7695c_choosing_a_name_focuses_its_first_changed_line_and_asks_for_no_trace`.
