# UI: the Changes list is a lens (Modules, Logic or Tests) with the Overview first, and a file is found by typing (U7679a–U7679f)

Module: `apps/desktop/src/changes/` (`ChangedTree.tsx`, `ChangesView.tsx` and the file that holds #7678's rules), the lens and its places beside the Compare choice in `apps/desktop/src/state/changeTargets.ts` and `changePlaces.ts` (one session memory, as U7672d keeps it), the fake App and its fixtures. Ids: U7679a, U7679b, U7679c, U7679d, U7679e, U7679f. Work order: [#7679](https://github.com/roundup-app/roundup/issues/7679), blocked by #7678. Owner, 2026-11-18: "module by module or tests or logic, also I don't care about file by file I care about flows/paths/modules and mental models", "the logic's essence first". After #7678 the list groups by module and nothing else; this order makes the list a lens, adds the Overview row and finds a file by typing. No Daemon method, Message or contract change: the lenses read `ChangedFile.path` through #7678's rules, and U2540c's one Message per batch stands. "Lens" and the Changes view's Overview are not rows of `GLOSSARY.md` yet; the implementation PR adds both in the same PR (`AGENTS.md`), the Overview not as `ConversationOverview` (the Rail's conversation overview) and the find not as `search.find` (text matches). #7683 puts Flows first in the switch; a fourth lens joins the switch's order and U7679a's key, U7679c's memory and U7679d's find take it with no change. Reuse (rule 9): #7852 replaced `@pierre/trees` with the list `ui/TreeView.tsx` builds over `@ui-sdk/solid/tree`, so the find narrows that list: `narrow` in `lens.ts` keeps the files whose path holds the letters in one run, whatever their case (a folder's name matches its files), and the list draws what is left; with no match no row shows and the view says so (U7679d). The library has no search option to leave off and no shadow root: the field is an App field over `ui/Field.tsx`, and `typing` in `ChangesView.tsx` reads its `event.target`. The scroll and the rules are #7678's, and the switch is `ui/SegmentGroup.tsx`, as the Compare-to switch in `ChangesView.tsx` uses it. The PR's `Reuse:` section names `@ui-sdk/solid` (its tree, segmented control and field) as selected, `fuse.js` and the `command` primitive of `@ui-sdk/solid` as the candidates it considered, with each one's evidence, and says no new machinery was added. Size: about 720 changed lines (classification 100, switch 100, Overview 120, find 120, tests 280). Observer: Vitest against the fake App for U7679a to U7679e; the isolated Chromium harness (U26) for U7679f. Never a native Mac capture.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

**Words.** The quoted words below are asserted through `copy.ts`, never layout or looks (rule 10). The App writes "Unfinished work", the user label of Draft (`GLOSSARY.md`). A row is a line of the list. An item is what a row opens and holds hunks: a module or a noise file. The Overview is a row and no item; what is open is an item or the Overview.

**Fixture.** The lens fixture changes seven files, each with its own `counts` (U7610a): `crates/a/src/x.rs`, `crates/a/tests/x.rs`, `crates/b/src/y.rs`, `crates/c/tests/z.rs`, `README.md`, `pnpm-lock.yaml` and `crates/a/generated/g.rs`. By U7678b the modules are `crates/a` (logic `x.rs`, test `x.rs`), `crates/b` (logic), `crates/c` (test) and Top level (logic `README.md`); the noise rows are "Generated · 1 file" and "Lockfiles · 1 file".

**U7679a the list is a lens, switched at its top.** Given the open view, the lens fixture and the fake App, then:
- **Switch.** The list is headed by the lens switch, a `SegmentGroup` of "Modules", "Logic" and "Tests" in that order with one selected, below U7674a's group switcher when one shows; the header (U7674b) gains nothing. It shows whenever the list does. Choosing a lens replaces the list's rows with that lens's. Asserted in `u7679a_the_switch_names_the_three_lenses_in_order_and_choosing_one_changes_the_list`, which asserts that choosing Logic drops the `crates/c` row; U7679b holds each lens's contents.
- **Keeps.** Switching lens keeps what is open when the new lens lists it: the same module, the same noise file, or the Overview, which every lens lists. A module the new lens lacks opens the new lens's Overview row (U7679c). A module's scroll in another lens is a scroll of its own, so its reveals fold again (U7692a); a noise file is the same diff in every lens, so a switch leaves its scroll, place and reveals as they are. Decided here, as the Issue's reading with the first row, the Overview, as the lens's first item. Asserted in `u7679a_switching_keeps_the_open_item_when_the_lens_lists_it_else_opens_the_overview`.
- **Places.** A place is a scroll offset and a focused line, and it belongs to a lens and a module (a noise file's belongs to the file alone, the same in every lens): `crates/a` holds one place in Modules, one in Logic and one in Tests, none moves to another, a lens never opened for a module starts that module at its top, and the memory lasts the connection's session as U7675d and U7675f's does. Asserted in `u7679a_each_lens_keeps_its_own_place_in_a_module`.
- **Keyboard.** L opens the next lens and Shift-L the previous, in the switch's order, wrapping at its ends, from the list or the diff alike; both are the switch's own act, and never fire while a note field, text input or the editor holds focus. L is free: J, K, ] and [ (U7675e), N and E (U7676b), G (U7690c), V and R (#7680, #7688), Tab, Enter, Esc, ? and Delete are taken, and `/` is U7679d's. A click on a segment does the same. Decided here, as the Issue's reading that the switch is reachable by keyboard; a digit key was left out because #7683 puts Flows first and would renumber it. Asserted in `u7679a_l_and_shift_l_step_the_lenses_in_switch_order`.

**U7679b a lens holds the hunks of its files, grouped by module.** Given the lens fixture and the fake App's `agent.compareFile`, then:
- **Rows.** Modules lists `crates/a` (2 files), `crates/b`, `crates/c` and Top level; Logic lists `crates/a` (1 file, `src/x.rs`), `crates/b` and Top level; Tests lists `crates/a` (1 file, `tests/x.rs`) and `crates/c`. Each module row shows the file count and `+added -removed` of its files in that lens only, by U7678a's rules for a `null` count, and a file shows only inside its module, folded at first. A module with no file in the lens has no row. The noise rows (U7678b) end every lens, the same in each, since a noise file belongs to no module and so to no lens's item; a noise file that sits under `tests/` is noise, not a test. Asserted in `u7679b_each_lens_lists_its_modules_with_its_own_files_and_counts`.
- **Logic and Tests.** A hunk is a test hunk when its file is a test and a logic hunk when its file is logic, both by the one function U7678b holds, which the lenses read and never copy; so a test inside a logic file, such as a Rust `#[cfg(test)]` block, is logic. Logic holds no test hunk and no noise hunk; Tests holds test hunks only, under the module they test (U7678b's module for a test file). A file with no hunk to show (binary, an image, mode only) belongs to the lens its path says and draws its notice in the scroll (U7678c). Decided here, as the Issue's reading that the test rule is #7678's. Asserted in `u7679b_logic_holds_no_test_or_noise_hunk_and_tests_holds_test_hunks_only`.
- **Scrolls.** Choosing a module in Logic opens one scroll of its logic files' hunks in path order, in Tests one of its test files' hunks in path order, and in Modules logic then tests (U7678c); each file's hunks sit under its file's header and each hunk carries its function (U7678c). The Modules scroll of a module is its Logic scroll followed by its Tests scroll. Reads, file states, reveals and the editor are U7678c's in each. Asserted in `u7679b_a_module_opens_its_logic_in_logic_its_tests_in_tests_and_both_in_modules`.
- **Marks.** A file's unfinished note (U7676c) marks the row of the item whose scroll holds that file, in each lens: a note on `crates/a/tests/x.rs` marks `crates/a` in Modules and Tests and no row in Logic, and a note on a noise file marks that noise row in all three. The notes bar (U7676d) still counts every unsent note. Asserted in `u7679b_unfinished_work_marks_the_row_that_lists_the_file_in_each_lens`.
- **Notes.** A note made in a Logic or Tests scroll keeps its file, side and line, and the Message names that file (U2540b, U2540c). Asserted in `u7679b_a_note_made_in_logic_keeps_its_file_side_and_line`.
- **Jumps.** A jump to a note's file and line (the list of U7690c's G, the batch list of U2540b) opens the file as "A file row" does (U7678c) in the open lens when the lens lists it, and else switches to Modules, which lists every file that is not noise, and opens it there; a noise file opens alone in every lens. Switching this way is choosing the lens, so the Agent's lens last used follows. Decided here, as P11: a note stays reachable from every lens. Asserted in `u7679b_a_jump_to_a_note_the_open_lens_does_not_list_switches_to_modules`.

**U7679c the Overview is the first row of every lens, and the view opens on it.** Given the lens fixture and the fake App, then:
- **Row.** Every lens's list holds the Overview row first, then the module rows, then the noise rows. The Overview is a row and not an item: no hunk, note, mark or place of its own belongs to it; it starts at its top whenever it opens. Up and Down onto it, a click and Enter open its pane, as a module row does (U7678a). Asserted in `u7679c_the_overview_row_is_first_in_every_lens_and_never_takes_a_mark_or_a_place`. #7680's Viewed and #7691's whole-item note read an item as what holds hunks and never take it (policy).
- **Pane.** Before a readback (#7688) the Overview opens a pane that lists the lens's modules in list order, each with its name, its file count and `+added -removed`, the same numbers as its row, read from the listing's `counts` alone. A lens that lists no module says "No changes in <lens>" (Tests of a change with no test, Modules of a change of lockfiles only). #7688 adds its readback above this list and keeps the list. Decided here, as the Issue's reading that the Overview lists the modules: the lens's own, so each entry opens in that lens. Asserted in `u7679c_the_overview_lists_the_lenses_modules_with_counts_and_a_lens_with_none_says_so`.
- **Choosing.** Choosing a module in the pane (a click, or Enter on it) opens that module in this lens as choosing its row does (U7678a), and focus lands on that module's row in the list. Asserted in `u7679c_choosing_a_module_in_the_overview_opens_it`.
- **Lens last used.** One lens is remembered for each Agent for the connection's session, "Modules" for an Agent never chosen for; choosing one by the switch or by L and Shift-L sets it for the open Agent only, as U7672d's choice and U7675f's places are kept. Nothing is stored, so a new session opens on "Modules" and nothing is migrated. Decided here: the Issue says "the lens last used" with no scope; per Agent follows U7672d, and one Agent's reading of its change never steers another's. Asserted in `u7679c_each_agent_keeps_its_lens_and_a_new_session_opens_on_modules`.
- **Landing.** A view that opens for an Agent with no remembered place, and a view whose Compare value or group changes (U7674e), opens the Overview row of the lens last used with focus in the list, and no `agent.compareFile` call is made. This replaces #7674's first-file landing and #7678's first-module landing. Asserted in `u7679c_the_view_opens_on_the_overview_of_the_lens_last_used`, replacing `u7678d_the_view_opens_on_the_first_module_at_its_top`.
- **Reopening.** Closing the view and reopening it for the same Agent opens the lens last used with the item that Agent's view last had open when the lens lists it, at that lens's place for it, and else that lens's Overview row; switching Agents or Projects restores that Agent's own place, never another's (U2540a). Decided here: the landing is first-time only, so the place U7675f restores is not given up. Asserted in `u7679c_reopening_restores_the_open_item_in_the_lens_last_used`, which edits `u7675f_reopening_restores_the_open_file_its_scroll_and_line` as U7678d does.
- **A module leaves.** When the open module's last file leaves the lens's list, the pane says "<module> no longer differs from <From>" and focus moves to its neighbour module, the next, else the previous, else the lens's Overview row; with no file left in the listing at all, the view's empty state (U7675a) shows and the switch with it goes. Asserted in `u7679c_when_the_open_module_leaves_focus_moves_to_its_neighbour_else_the_overview`, replacing `u7678a_when_the_open_module_leaves_focus_moves_to_its_neighbour`.

**U7679d typing narrows the list to the files that match.** Given the lens fixture, the fake App and the open view, then:
- **Way in.** `/`, with no modifier, from the list or the diff alike and never while a note field, text input or the editor holds focus, opens a find field at the top of the list under the lens switch and puts focus in it. A letter or digit pressed in the list opens nothing: the keys of U7679a and U7675e still fire. Decided here: `/` is free (`⌘/` is `ask.open` and no plain chord uses it), and the Issue's example is taken. Asserted in `u7679d_slash_opens_the_find_and_a_letter_pressed_in_the_list_opens_nothing`.
- **Narrowing.** While the field holds letters the list shows only the files whose `path` holds them, whatever their case, in one run, never a row's label ("Top level" and "Lockfiles" match nothing), a case apart and in one run, each inside its module row unfolded and showing only its matching files; the Overview row and every module without a match leave, and the noise rows show only when one of their files matches, unfolded. A file is searched in the open lens only. On the fixture "tests" shows `crates/a/tests/x.rs` and `crates/c/tests/z.rs` in Modules and Tests; "LOCK" shows `pnpm-lock.yaml` under "Lockfiles"; "crates/b" shows `y.rs`. A module row's counts do not change with the letters. Decided here: the find narrows files inside their items, the Issue's open reading of the library. Asserted in `u7679d_typed_letters_narrow_the_list_to_the_files_that_match`.
- **No match.** Letters that match no file in the lens show the line "No file matches <letters> in <lens>" and no row, never the whole list. Asserted in `u7679d_letters_that_match_nothing_say_so_and_show_no_row`.
- **Into the list.** Down moves focus from the field to the first row shown, as Down does in the list (U7678a), and Enter opens the first matching file as choosing a file row does (U7678c), with focus on that row; the letters stay. Asserted in `u7679d_enter_opens_the_first_match_and_down_moves_into_the_list`.
- **Esc.** Esc clears the letters, closes the field and returns the list as it was, folds and scroll included, with focus on the row that held it before `/` (else the open item's row); it never closes the view. A press after that closes it as before. With focus in the diff, Esc clears the find first too. Esc closes the ? list first, then the find, then the view (U7675e). Asserted in `u7679d_escape_clears_the_find_before_it_closes_the_view`, which edits `u7675e_escape_closes_the_keys_list_before_the_view`.
- **Typing.** With focus in the field, no key of the ? list fires, the letters J, K, V, R, G, N and L and `/` among them: they enter the field, the open item and its focused line stay and no note field or list opens. Asserted in `u7679d_typed_letters_fire_no_key`, which types into the field's own element.
- **No reads.** Narrowing reads no file and moves, closes and scrolls neither the open scroll nor the lens; the pane stays. The field and its letters belong to the open view: switching lens keeps them and narrows the new lens's list, and closing the view clears them. Asserted in `u7679d_finding_reads_no_file_and_leaves_the_open_scroll_alone` and `u7679d_the_find_follows_a_lens_switch_and_a_closed_view_forgets_it`.

**U7679e the keys reach the Overview, the lens and the find.** Given the open view with no note field, text input or editor holding focus, then:
- **J and K.** J and K step the rows that open something, in list order: the Overview, then each module, never a noise row. K on the Overview and J on the last module do nothing; with a noise file open, J does nothing and K opens the last module, else the Overview. While a find holds letters they step the module rows shown, and with the open item not among them J opens the first and K the last. Asserted in `u7679e_j_and_k_step_the_overview_and_the_modules_and_skip_noise_rows`, replacing `u7678d_j_and_k_step_modules_and_skip_noise_rows`.
- **Overview.** ] and [ do nothing in the Overview and Enter on its row opens no editor. The pane's entries are in list order after the list in the tab order: Tab from the list goes to the first, Tab again to the next, and Shift-Tab goes back and, from the first, to the Overview row; Enter or Space chooses one (U7679c); with no module the pane holds no entry and Tab does nothing. Asserted in `u7679e_in_the_overview_brackets_do_nothing_and_tab_walks_its_modules`.
- **The ? list.** The list gains L with "next lens" and `/` with "find a file", and its J and K line names the Overview. Asserted in `u7679e_the_keys_list_names_the_lens_and_find_keys`, extending `u7675e_question_mark_lists_the_keys`.
- **Typing in a note field.** Typing L or `/` in a note field fires nothing (`u7675e_keys_do_not_fire_while_typing_in_a_note_field`, edited to press both). No key action animates: a lens switch, a find and a scroll or focus change are instant. Policy; the design critic judges it (U7679f).
