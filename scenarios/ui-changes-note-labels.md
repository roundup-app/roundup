# UI: a note carries a label and replacement text, and one key jumps between notes (U7690a–U7690d)

Module: `apps/desktop/src/changes/` (`NoteForm.tsx`, `NoteBatch.tsx`, `notes.ts`), the fake App and its fixtures. Ids: U7690a, U7690b, U7690c, U7690d. Work order: [#7690](https://github.com/roundup-app/roundup/issues/7690), blocked by #7677. Owner, 2026-11-18, from the Plannotator audit: "Labels on notes", "Suggested code" and "Jump between notes". No Daemon method or contract change: U2540c's one Message per batch stands, and its body gains two keys, written only when set. The implementation PR's `Reuse:` section names `registerKeys` for the key (as `registerChangesKeys` in `ChangesView.tsx` uses it) and weighs, for the list, `@ui-sdk/solid` (installed; `apps/desktop/src/ui/` wraps its `command` and `popover` primitives), `@ark-ui/solid` (named by #7690, but commit 51fbc57d8b replaced it with ui-sdk, and neither `apps/desktop/package.json` nor `pnpm-lock.yaml` lists it on main, so using it would add a dependency back), `@pierre/trees` (installed) and the rows of `NoteBatch.tsx` (one list of notes, not two). Size: about 470 changed lines. Observer: Vitest against the fake App for U7690a to U7690c; the isolated Chromium harness (U26) for U7690d. Never a native Mac capture.

**Precedence.** A design check (the critic, a D-check) that reads a decision here as a defect changes how it is drawn, never the decision. When both cannot hold, `ask` (`flag:needs-user`).

**Words.** The quoted words below are asserted through `copy.ts`, never layout or looks (rule 10). The App writes "Unfinished work", the user label of Draft (`GLOSSARY.md`). A label's data value is its word in lower case: `question`, `nit`, `issue`.

**U7690a a note can carry one label.** Given the composer (U7677d) and the fake App, then:
- **Choose.** After the note's text the composer offers a group named Label of three toggle buttons, "Question", "Nit" and "Issue", reachable by Tab; none is pressed at first. Pressing one presses it and releases any other, and pressing the pressed one clears it. The set is these three; the user cannot edit it. Edit opens the composer with the note's label pressed. Asserted in `u7690a_the_composer_sets_and_clears_one_label`.
- **Meta.** A labelled saved note reads "Lines 51-53 · Question · Not sent", the label between the range and the state, also as "Lines 51-53 · Nit · Sent 14:02"; an unlabelled note reads as U7677b says. No header label (U7677). Asserted in `u7690a_the_meta_line_names_the_label`.
- **Message.** A labelled note's entry in the Message body holds `"Label:"` with `question`, `nit` or `issue` beside `"User comment:"`; an unlabelled note's entry holds no `"Label:"` key. The label is data, never a command (U2540c), and it changes nothing else: a labelled note sends, retries and counts in the batch as an unlabelled one does. Asserted in `u7690a_a_labelled_note_sends_its_label_and_an_unlabelled_one_none`.

**U7690b a note can carry replacement text.** Given a saved range and the fake App, then:
- **Fill.** A "Suggest a change" button in the composer opens a second field under the note's text, filled with the selected source text (the note's retained `source`, all its lines for a range, as a line does); the user edits it, and the button again drops the field. Asserted in `u7690b_the_field_opens_filled_with_the_selected_source`.
- **Old side.** A note on the old side offers no replacement, since those lines no longer exist in the file. Asserted in `u7690b_the_old_side_offers_no_replacement`.
- **Message.** The note's entry holds `"Replacement:"` with the field's exact text, beside `"Lines:"` naming the lines it replaces, written only when set. A fill left unchanged is no suggestion and writes no `"Replacement:"`; a field emptied suggests deleting those lines and writes `"Replacement:": ""`. The text is plain text, never a patch or a command (U2540c). Asserted in `u7690b_a_replacement_reaches_the_message_and_an_unchanged_fill_sends_none`.
- **Saved.** A saved note shows its replacement under its text as preformatted text, folding with the note (U7677b); Edit opens the composer with the replacement field open and holding it. Asserted in `u7690b_a_saved_note_shows_its_replacement_and_edit_reopens_it`.
- **Stored.** The label and the replacement are optional fields of a stored note and of an unfinished note: notes saved before they existed restore unchanged, and a note, saved or closed by Esc with text, restores with its label and replacement after a restart, never losing them (P11, U2773a). Asserted in `u7690b_labels_and_replacements_survive_a_restart_and_older_notes_still_load`, extending `u2773a_changes_restores_exact_work`.

**U7690c one key and a list reach every note.** Given the open view and the fake App holding notes on several files, then:
- **The key.** `G` opens the list of the open Agent's notes, from the list or the diff alike (as J and K, U7675e), and never while a note field, text input or the editor holds focus. N, ] and [ are taken (U7676b, U7675e), as are J, K, E, V, R, Tab, Enter, Esc, ? and Delete; `G` is free among them. The ? list gains G with its action. Asserted in `u7690c_the_keys_list_gains_g` and, for the typing guard, `u7675e_keys_do_not_fire_while_typing_in_a_note_field`, edited to press G.
- **The list.** It holds every note of the Agent, unsent, Sent and Outdated alike, in file order: the files in path order, then line, the old side before the new on one line. A row shows its file, its lines, its state in its own words (U7676c, U7677e), its label when it has one and the first line of its text. Asserted in `u7690c_the_list_holds_every_note_in_file_order_whatever_its_state`.
- **Stepping.** The list opens on the first note after the focused line in that order, else the first note; Up and Down move its row and stop at its ends; Enter closes it and focuses that note's line in its file, opening what the list opens for that file, and scrolls the line into view. So G then Enter visits each note in turn across files and, from the last note, wraps to the first. Asserted in `u7690c_g_then_enter_steps_from_note_to_note_across_files_and_wraps`.
- **Click and Esc.** A click on a row chooses it as Enter does. Esc closes the list and moves nothing, returning focus to where it was; it closes before the view and after the ? list, as U7676d's batch list does. Asserted in `u7690c_a_click_chooses_and_escape_closes_without_moving`.
- **No notes.** With no note the key does nothing: no list opens and focus stays. The list opens from the key alone, since the notes bar shows only while the batch holds an unsent note (U7676d). Asserted in `u7690c_with_no_notes_g_does_nothing`.
- **A file that left.** A note whose file the change no longer holds stays in the list with its state and the words "No longer changed" and cannot be chosen; Enter on it does nothing. Asserted in `u7690c_a_note_whose_file_left_the_change_is_listed_and_cannot_be_chosen`.

**U7690d the rendered notes and list at 1512 by 950.** Given the U26 harness, dark App, then these draw, each capture prefixed `note-`: a note of each label, a note with a replacement saved and in the composer, the list holding unsent, Sent and Outdated notes across files, and a worst case, a list of 100 notes. From a still capture a reader can name each note's label and state. D2, D5, D6 and every Check passing on `main` still pass. **Amended.** U2540b ("`Add note` opens a labelled field", "Notes retain file paths"): the field gains the label and the replacement, and a note retains both. U2540c ("`User comment:` with the exact note text"): the body gains `Label:` and `Replacement:` when set. U7675e ("The ? list"): G is listed, as N is from U7676b. U7677b ("Meta"): the meta line gains the label; U7677's "a saved note carries no label, only the meta line" now reads: a saved note may carry one of three labels, in its meta line only, and never a header label. Kept: one Message per batch (U2540c), a Sent note never sent twice (U7677e), #7676's N, ⌘↵, E, Delete and the notes bar, and no gate on Landing, Send or a Message (U2540d).

Not wanted: a label that blocks or gates Landing, Send or a Message (U2540d), a label set the user edits, an editor in the diff, a new Daemon method, Plannotator (plannotator.ai) as the review surface, rejected by the owner, 2026-11-18. No test of layout or looks.
