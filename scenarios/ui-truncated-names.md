# Truncated names can be read in full

Acceptance for #2228, found by break-ui on `tree-40` with a Workstream named `payments workstream` plus a very long tail. Webview only: no App command, no Daemon method, nothing under `contracts/` and no Token changes. Owns `apps/desktop/src/rail/` (the row's name), `apps/desktop/src/header/` (the window bar's title), and for U3296a/b (#3296) `apps/desktop/src/pads/` and `apps/desktop/src/changes/`, and for U3296c `apps/desktop/src/todos/`. Narrows U65 (`scenarios/ui-rail.md`) and U449's overflow clause (`scenarios/ui-window-bar.md`); U29's ellipsis, U46's unmoved rows and U450's title text hold.

The journey stage is Understand (`.agents/data/journey.md`): the user can tell which Workstream a row or the window names, whatever its length.

**U2228a a truncated Rail name is readable in full.** Given `tree-40` with a Workstream whose name is 80 characters, at a Rail width of 252 px, when its row is hovered or keyboard-focused, then the row carries the native `title` holding the full unchanged name and nothing else (no status, no count), for a Workstream row as for a Door, Agent or Project row. The row's accessible name holds the full name, its status and its counts, not the cut text. A name that fits has no `title`, so hovering, clicking, focusing or selecting its row shows nothing extra; the `title` follows the row's current layout, so widening the Rail until the name fits removes it and narrowing it restores it. The row opens no custom Tooltip (U2228c); the Add Agent button keeps its own tooltip, and a hover on it shows that one only. The rename field still holds the full name (U61). Asserted in `u2228a_a_truncated_workstream_name_has_its_full_text` (the `title` is the full name and the accessible name holds name, status and counts), `u2228a_a_name_that_fits_has_no_tooltip` (no `title`) and `u2228a_the_add_agent_tooltip_stays` (jsdom: attribute and accessible name), and `u2228a_title_follows_the_layout` (headless Chromium, the real width).

**U2228c a Rail row has no custom Tooltip.** Given a Rail row of any kind, when it is hovered, clicked, focused or selected, then no `role="tooltip"` element opens for it, whatever its status or counts (`u2228c_a_row_opens_no_tooltip`, jsdom). Supersedes the Tooltip clauses of U521 (`scenarios/ui-rail-lane.md`) and U2749b's Rail row anchor (`scenarios/ui-tooltip-anchor.md`), whose `u2749b_explicit_row_anchor_keeps_full_text` and `u521_full_text_is_in_a_tooltip` are retired with this scenario, and amends the "`title` is left" ban of U521 for the row's cut-name `title` only (policy). The implementing PR removes the row's Tooltip, its status and count text and, if no caller remains, the named row anchor option of `ui/Tooltip`.

**U2228b the window title keeps the name's start and end.** Given the window bar's title (U449, U450) for `<Project> — <Workstream>` too long for its box, then the visible text is cut in the middle with a single `…`: it begins with the start of the Project name and ends with the last characters of the Workstream's name, never ending in `…`. A title that fits is shown whole with no `…`. The visible text fits on one line in the box, whose midpoint stays at half the window width (U449), at 1280×800 and 1600×800 with a 300-character Workstream name and with a long Project name. The accessible name and `title` stay the full, untruncated text, and so does the native window title (U450). Widening or narrowing the window re-cuts the text without a reload, and a rename updates the cut after the successful response (U450). Asserted in `u2228b_a_long_title_keeps_start_and_end` (the visible text starts with the Project's first characters and ends with the Workstream's last ones, contains one `…`), `u2228b_a_short_title_is_whole`, `u2228b_the_full_title_stays_in_name_and_window` and `u2228b_resize_recuts_the_title` (headless Chromium, the box measured with the real font, not jsdom). Replaces only U449's "stays on one line with ellipsis" wording for the title; its centring, overlap and accessible-name clauses hold.

**U3296a no Tooltip repeats what its trigger shows.** Given the Pad name on a Shelf row (`pads/Pads.tsx`) and in the Pad drawer's head (`pads/PadDrawer.tsx`), the path on a Note line of a Note batch (`changes/NoteBatch.tsx`), and the branch and base values of the worktree panel (`changes/WorktreeControl.tsx`), when any is hovered or keyboard-focused, then no `role="tooltip"` element opens for it, whether its text is cut or not (`u3296a_repeating_text_opens_no_tooltip`, jsdom, one case per site). Icon-only buttons keep their label tooltip, and the worktree button keeps its accessible name (policy).

**U3296b a cut name carries the native `title`, only while cut.** Given the four sites of U3296a, when the text is cut by its box, then its element carries the native `title` holding the full unchanged text and nothing else; when it fits, there is no `title`; the `title` follows the current layout as in U2228a, so widening removes it and narrowing restores it. The sites share the cut-name `title` mechanism U2228a introduced instead of a second one, and the "no JSX `title`" ban of U2749c yields to it for cut names only (policy). Asserted in `u3296b_a_cut_name_has_its_full_text_as_title` (jsdom, a forced cut: the `title` equals the full text, one case per site), `u3296b_a_name_that_fits_has_no_title` (jsdom) and `u3296b_title_follows_the_layout` (headless Chromium, the real width, one site).

**U3296c selecting a row opens no text Tooltip.** Given a Todo row (`todos/RowButton.tsx`, whose Tooltip today holds the Todo's title), the owner and Home lines of Quick-add (`todos/Capture.tsx`) and a Todo's Pad link (`todos/TodoRefs.tsx`), when the row is clicked, selected, or reached by arrow keys or Tab, then no `role="tooltip"` element opens; a cut Todo title gets U3296b's native `title`, only while cut. Only an icon-only button's label Tooltip opens on keyboard focus (policy). Asserted in `u3296c_selecting_a_todo_opens_no_tooltip` (jsdom: click, ArrowDown and Tab on a Todo row, no tooltip element). From the owner's report: "why sleecting a todo shows it's fucking tooltip - it shouldn't this is too annoying".

Reuse (rule 9, policy): the implementing PR researches existing middle-truncation helpers and the shared `ui/Tooltip` before adding code, and carries the `Reuse:` section with at least two maintained candidates and the evidence for the choice.
