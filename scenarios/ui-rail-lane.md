# Rail uses the shared tree and sortable

Specification for #1607. Implementation owns `apps/desktop/src/rail/`, deletes `apps/desktop/src/keys/railStep.ts`, edits only the `.rail*` rules in `apps/desktop/src/styles.css`, and edits only the `copy.ts` entries the Rail uses. It does not edit `ui/`, other `keys/` files, other lanes, `tokens.css`, manifests or lockfiles (policy). A capability `ui/` lacks becomes a native prerequisite Issue against the UI epic, never a local copy (policy).

Direction: #1629, #1627, #1630 and #1869 (the registry #1608 specified) are implemented; #1984 delivered the shared TreeView and Sortable (U483 to U485 in `scenarios/ui-buttons.md`), which this lane consumes. The owner's closing comment on #1852 cancels semantic Tokens as a prerequisite: keep the current Token names and add no raw visual values (policy). The `u52x_` observers below are the implementation's acceptance, not tests this specification PR claims to hold.

**U520 The Rail is a tree.** Given a three-level Rail (Project → Workstream → Agent, with a sibling after the first Workstream), when Tab enters it, then focus is the first row, and Down, Up, Right, Left, Home, End and typed letters behave as U483's three-level walk does: Right expands a collapsed branch, then moves to its first child; Left collapses an expanded branch, then moves to its parent; Home and End reach the first and last visible row; typing jumps to a row by its name (`u520_three_level_keyboard_walk`, planned in `apps/desktop/src/rail/`, real Ark TreeView in headless Chromium). Selecting a row by keyboard shows its Terminal as a click does and calls no method of its own (U41, `scenarios/ui.md`). A leaf Agent with Pads expands them on Right and folds them on Left (U41, U58). Rows folded into U5483a's idle branch are not rows until the branch is opened, so Right never lands on a hidden child (`u520_done_line_is_not_a_row`, retargeted to U5483a).

Given the open Rail, when its accessibility tree is read, then there is one `tree` with an accessible name, each row is a `treeitem` at its level with `aria-expanded` matching its fold, leaves carry none, and every button in a row has an accessible name that is not a native `title` (`u520_tree_semantics_and_names`). An axe check of the Rail reports no violation (`u520_axe_clean`).

Implementation composes `ui/TreeView` for navigation and ARIA and keeps `RailRow` as the caller-rendered row; it deletes `keys/railStep.ts` and the Rail's own arrow, Home, End and typeahead handling, adds no parallel interaction state machine, and keeps U31's guards (a key in the rename field never moves the row; Enter on the fold button does not select the row), now proven by `u31_arrow_down_in_the_rename_field_does_not_cancel_the_rename` and `u31_enter_on_the_collapse_button_does_not_select_the_row` in `apps/desktop/src/rail/u31_rail_keyboard.test.tsx` (policy, diff inspection). `U41`'s F2, `⌘1`, `⌘2` and `⌘J` stay on the registry (`apps/desktop/src/keys/u41_rail_keys.test.tsx`).

**U521 Rail controls use shared accessible behaviour.** Given the Rail with every row kind, when each icon-only button is hovered and keyboard-focused independently, then it has a nonempty accessible name and a linked visible shared Tooltip showing that name (`u521_icon_controls_show_their_names`). Every icon-only button is `ui/IconButton`, every tooltip `ui/Tooltip`, every menu `ui/Menu` and every confirmation `ui/Dialog` or `ui/AlertDialog` (policy, inspect source and rendered controls). A Rail row carries no shared Tooltip: a truncated name, a status, the need-you count, the folded-agents count and a Pad name are not tooltip content (U2228c).

Given focus in the Rail or an owned layer (the jump list, attention key, add-Agent picker), when an existing Rail shortcut is pressed, then the registry selects only that scope's action, an open Help suppresses the underlying actions, and disposal leaves no stale callback (`u521_shortcuts_follow_focus`, real registry). The Rail's own `keydown` listeners in `Rail.tsx`, `Jump.tsx` and `AttentionKey.tsx` move onto the registry; keys inside Ark components (menu arrows, dialog Escape, tree navigation) come from Ark (policy). Every App-authored string and accessible name in `rail/` comes from `copy.ts`, as user labels (`u521_copy_preserves_content`; names and returned errors stay verbatim).

**U522 Rail reordering uses the shared Sortable.** Given the Rail and a row dragged by pointer, when the drop commits, then `rail.move {id, parent, index}` is called once with the parent and index of U22, with U22's CONFLICT, outside-the-Rail cancel, Escape cancel, edge scroll, daemon-gone and no-drag-on-a-button behaviour kept (`u522_pointer_move_calls_rail_move`, `u522_cancel_calls_nothing`, `u522_conflict_restores_the_row`, `u522_edge_scroll_reaches_an_offscreen_row`). Given the keyboard lift of a row, when it is moved and dropped, then the same single call is made and focus stays on the row (`u522_keyboard_move`). Given a real file dragged over a row, then the U348 drop targets and U420 landing still work and no reorder session starts (`u3800a_one_drag_fixture` in `apps/desktop/src/ui/u484_browser.test.ts`, the file-drop proofs of `apps/desktop/src/app/u348_file_drop.test.tsx`).

U22's drop line's depth (a sideways move changes the parent) needs reparenting that U484's flat order does not state. If Sortable cannot carry the depth, implementation files a native prerequisite against the UI epic and keeps `drag.ts` for that part only until it lands; it never grows a second engine (policy). `rail/drag.ts` and `THRESHOLD_PX` are deleted when the prerequisite holds; U22's consumer-owned 4 px threshold is superseded by the Sortable's activation (policy).

Delete `rail/styles.css` and `.rail*` rules in `styles.css` that only patched hand-written focus, open-state, press or drag behaviour (the `:has()` press and selection rules), keep document layout and focus visibility, and move the remaining `.rail*` rules into `rail/styles.css` (policy, `wc -l` before and after in the PR). Delete tests that pin one computed style or exercise deleted behaviour, and for each name the test that still proves its then-clause or the retired clause (rule 10). Tests are named after their scenario.

## Idle children in a Workstream

Specification for #5483; first-journey stage: Understand. U5483a–c supersede U8's automatic Agent folding, including the root-Agent fold, the ten-minute done delay and the disappearing one-way disclosure. Workstream disclosure and membership otherwise retain U8. These are implementation acceptance, not runtime evidence from this specification PR. The earlier #1607 scope and validation describe that implementation only; this slice uses the scope and validation below (policy).

**U5483a done and long-idle children share one fold.** Given an expanded Workstream with children in Rail order, when a child becomes `done`, or remains `idle` continuously for 300,000 ms, then, unless U5483c protects it, it belongs to one initially closed idle branch after that Workstream's other children. Done has no delay. Idle at 299,999 ms remains outside; at 300,000 ms it belongs inside. Any intervening non-idle Kind resets the idle interval; duplicate idle observations and label-only changes do not reset it. Use the existing injected clock and status-transition identity, not wall-clock sleeps or the time the component mounted. Tests: `u5483a_working_idle_five_minutes_then_working_returns` and `u5483a_idle_must_be_continuous` in `apps/desktop/src/rail/u5483_folding.test.tsx` (planned), using `railFixture` and production Rail rendering. The first drives working → idle, advances the fake clock to each boundary, finds the child absent from the visible tree while the branch is closed, then drives working and finds it back in its original sibling position.

Given a mixture of eligible idle and done children, when the branch is closed or open, then its count includes both exactly once and it follows all other children; opening lists its members in their existing Rail order. Test: `u5483a_done_and_idle_share_one_branch` in the same file. Policy, design critic: its count uses the existing `idle` user label (for example `8 idle`), including done members; it is a disclosure label, not a change to any child's Kind. Preserve individual KindGlyphs when open. No second done line appears. Exact copy, placement and contrast are rendered observations, not UI-test assertions.

Given a working, blocked, needs-you or error child, a Workstream's own row (including its Door), a Terminal, or any root Agent even if long-idle or done, when the clock advances, then that row never enters an automatic fold. Test: table-driven `u5483a_only_idle_or_done_workstream_children_fold` in the same file. Each Workstream has its own branch; no branch is rendered for zero eligible children, and collapsing the Workstream hides the branch with its other children. Test: `u5483a_workstreams_keep_separate_folds`. Policy: folding is presentation only; it changes no Home, parent, sibling order, process, Message, selection or Terminal attachment and calls no RPC. Extend the first observer to assert unchanged selected identity and zero mutation calls across folding and return. Replace U8's root/ten-minute/unfold-once tests with these scenarios; retain its Workstream and Door regressions (check 1).

**U5483b the folded row stays open until the user closes it.** Given eligible children behind a closed branch, when the user clicks its disclosure, then it opens; clicking again closes it. Its disclosure remains present when open. Test: `u5483b_click_opens_and_closes_the_branch` in `apps/desktop/src/rail/u5483_folding.test.tsx`. Given keyboard focus on the branch, Right opens it, a further Right visits its first child, Left on that child returns to the branch, and Left there closes it; hidden children are absent from the tree walk. The branch is an Ark TreeView branch with an accessible count/name and matching `aria-expanded`; opening it selects no Agent and opens no Terminal. Test: `u5483b_keyboard_walk_enters_only_open_children`, extending the real headless Chromium fixture in `apps/desktop/src/rail/u520_tree_walk.test.ts`; retain check 2's axe observer. Use the shared tree's ordinary navigation, without a second keyboard engine (policy).

Given the user opened one Workstream's branch, when time, membership or Kind changes or the enclosing Workstream is closed and reopened, then that branch stays open until the user closes it. Changes in another Workstream do not change it. If its count becomes zero it disappears, but another eligible child in that same mounted Project restores the user's open choice; a newly mounted Project starts with closed idle branches. Test: `u5483b_open_choice_survives_membership_changes` in the same folding file. No new persisted setting is required (policy).

Given a child in either an open or closed idle branch, when it becomes working, needs-you or error, then it leaves that branch and returns to its ordinary sibling position on the next rendered status update, without waiting for the five-minute clock. Blocked also leaves because it is ineligible. Test: table-driven `u5483b_attention_and_work_return_immediately` in the same file (working return is already proved by U5483a; do not duplicate it). The count updates and the zero-count branch disappears in that render. Policy: retain the selected Agent and its pane; if tree focus would become hidden by folding, move tree focus to the branch without selecting another Agent. On return, focus follows a focused child; removing an empty focused branch returns tree focus to its Workstream. Test: `u5483b_focus_survives_folding_and_return` using the same headless tree fixture. No geometry assertions in these tests.

**U5483c a stopped plain-text question stays reachable.** Given a Workstream child with an unanswered outgoing `question` Message or a Clarification order, when it is idle for five minutes or becomes done, then it stays outside the fold. A reply alone does not prove the child has continued: keep protection until the child resumes working and its clarification is settled. Tests: `u5483c_unanswered_question_never_folds` and `u5483c_clarification_never_folds` in `apps/desktop/src/rail/u5483_folding.test.tsx`, with messages/order supplied through the existing connected-Project fixture. Native needs-you already stays out by U5483a; do not invent another native question record (policy).

Given a child ends its turn with final assistant text but no explicit question Message, when the Adapter reports that completed turn, then it is protected before any fold can hide it. This includes `Should I publish three pages or five` without a question mark and a multiline question beyond any displayed excerpt. The Rail does not guess from punctuation, a Status label, an excerpt or Terminal pixels. Conservative policy: all such unclassified final assistant text stays visible, including an ordinary final statement, until that child resumes working; a clock tick, Message delivery/receipt, unrelated note, user selection, done transition or opened/closed branch cannot clear protection. This exception deliberately favors keeping a possible question visible over folding every idle reply. A known empty final reply with no explicit question or Clarification order remains eligible. Missing final-text evidence is unknown, not proof of an empty reply, and keeps the child visible. A new working turn clears the previous turn's text protection; the next idle interval starts anew. Tests: `u5483c_final_text_without_a_question_mark_stays_visible`, `u5483c_unknown_final_text_stays_visible` and `u5483c_resuming_clears_only_the_previous_turn` in the same file; table-drive empty, ordinary, multiline and unavailable text cases without asserting literal UI copy.

The source is the Adapter's completed-turn observation, scoped to Agent and Attempt/turn identity, never a vendor parser in the App or a read of Terminal output. Preserve protection over a Project reconnect/reopen until authoritative evidence or resumed work replaces it; an old Attempt's delayed observation cannot protect or unprotect the new turn. Test: `u5483c_final_text_protection_follows_attempt_identity` in the existing `crates/agents` observation fixtures (planned). Policy: use the existing Agent/Rail state and serialization, not a new question service or Message status. If Rail metadata is needed, the Contract recipe changes its declarations, generated output and every caller together; it conveys protection/identity rather than a transcript. No contract name is introduced by this specification.

Pairing with #5482 is about delivery, not fold eligibility: the lead receives and interprets final text through that Issue's existing Message/Digest path, and its reply can cause the child to resume. This slice sends no automatic question, answers no native prompt, starts no Agent and adds no answer form (policy). It does not require #5482's unmerged scenarios or its implementation to protect the row; do not block this Issue on cancelled or speculative work. Observer: `u5483c_adapter_question_stays_visible_until_work_resumes` extends the existing real-Daemon/fake-vendor harness used by check 4: stop a child turn with the unpunctuated question, observe the production Rail protection data, advance an injected clock five minutes and assert no fold, then resume working and assert the next known-empty idle turn can fold. Count zero roundup-authored Terminal answer bytes and zero automatic native questions; the process is required to prove Adapter → Daemon → Rail wiring rather than only a hand-built web fixture. No live-model interpretation is claimed.
