# UI: an Attachment reaches the Door (U419)

Module: `apps/desktop` (the webview), with one Daemon method in `crates/rup`. Ids: U419.

**U419 an Attachment is sent to the Door as a file path in the Message.** Found by the user's report #790 ("paste images to the door input the same way I can do in all agents"): U109 shows an image as an Attachment and U199 adds the ways to attach one, but `message.send` carries only text, so the Door never sees it. Narrows U109, whose spike this settles; follows U175, where a dropped image reaches an Agent's terminal as its quoted path and Claude Code reads the file. It adds one Daemon method, `attachment.save`, so it follows the Contract recipe of `.agents/builder.md` (rule 4): `crates/contracts` gains `attachment_SaveParams {name: string, data: string}` (`data` is the image's bytes in base64) and `attachment_Saved {path: string}`, `contracts/generated/` is regenerated, every caller changes in the same PR, and `GLOSSARY.md` gains **Attachment file** (the copy of a pasted image the Daemon keeps so a path can name it) and its _Avoid_ words; no App seam command, no Token and no change to `message.send`'s shape. The route is one: the Message's `body` names each image by absolute path, as a Terminal does, and the Door's Agent reads the file. Given a selected Workstream (U145) with one or more Attachments in the composer, then:

- **Save.** `attachment.save` writes `data` decoded to a new file under the Daemon's data directory, `attachments/<n>-<name>`, where `<n>` is a counter that makes the path unique and `<name>` is `name` with every `/`, `\` and control character replaced by `_`; it returns the file's absolute path. A `data` that is not base64, or whose bytes are over 20 MB, fails with a message and writes no file. The file is not deleted by a send; the Daemon removes the files older than 7 days when it starts. Tests (`u419_`, in `crates/rup/tests/`): `u419_save_returns_a_path_holding_the_bytes`, `u419_a_name_with_slashes_stays_inside_the_folder`, `u419_two_saves_of_one_name_make_two_files`, `u419_bad_base64_and_over_20_mb_write_nothing`, `u419_start_removes_files_older_than_7_days`.
- **Send.** On `⏎` or `send` (U145), each Attachment of this send (not a kept one, U189) is resolved to a path: a native-dropped Attachment (U199) uses the dropped path as is; a pasted or DOM-dropped one calls `attachment.save` with its bytes, in order, before the Message leaves. The one `message.send` then has `body` equal to the typed text (placeholders expanded, U199), and after it, one line per Attachment in order, each the path single-quoted for a POSIX shell as U162 quotes it; between the text and the lines there is one `\n`, and with no text there is no leading newline. With no Attachment the body is exactly what U199 says. Asserted in `u419_the_body_ends_with_one_quoted_path_per_attachment`, `u419_a_pasted_attachment_is_saved_then_sent`, `u419_a_native_drop_sends_its_own_path` and `u419_an_attachment_alone_can_be_sent` (U145's empty rule counts an Attachment, as it does now).
- **Failure.** A failed `attachment.save` shows its message on U80's one line, sends nothing, and keeps the text, the Quotes and every Attachment, as a failed `message.send` does (U193); a second press saves again. Asserted in `u419_a_failed_save_sends_nothing_and_keeps_the_composer`.
- **Feed.** The Thread's feed shows the sent Attachment chip (U189) as it does now, and the body's path lines are not shown twice: the feed hides the lines it can match to the sent chips' paths and shows any other line as text. Asserted in `u419_the_feed_shows_the_chip_not_its_path_line`.
- **Kept.** U109's chip, hover preview and removal, U199's three routes and U193's multi-line value hold; a removed Attachment is not saved or sent. Asserted by the `u109_`, `u193_` and `u199_` tests passing unchanged, and `u419_a_removed_attachment_is_not_saved`.
- **Policy: Claude Code.** That the Door's Claude Code attaches the image from a path in a Message is the behaviour U175 compares; the user reports on the Mac what a real Door does with a pasted screenshot, and a Door that ignores the path files its own Issue.

Observer: `u419_` Vitest cases in `apps/desktop/src/thread/` against the fake App seam, which records `attachment.save` and `message.send` calls, and the Rust cases above against a real `rupd`. No browser capture, since no layout changes; no native Mac capture.
