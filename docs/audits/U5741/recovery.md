The risk metadata lets the user decide whether to inspect the destination before resending, resume the editor, copy work elsewhere or discard that selected revision. A retry retries storage, never delivery. A current availability check is not an invitation to substitute a newer object. Source-only states remain identified rather than claimed as rendered.

## Public, persisted and conditional boundaries

There is no recovery-specific RPC, `rup` command, MCP tool, named action or global shortcut. `recover` is a local menu id. Local Tab/Shift+Tab, Enter/Space and details disclosure behavior belong to the existing controls; context-menu keys are scoped to the Overview row. `todo.update` and `pad.rename` occur only on a later rename commit; opening recovery is not an alternate delivery endpoint. The historical actual public census remains pinned in public-seams.json; fresh both-role runtime offers and whole-App current-revision reconciliation remain required.

`state/storage.ts::draftStorage` holds per-Project revision/destination/value/selection/status/policy records. The browser fixture uses `roundup:drafts:<Project path>` with `{version:1,drafts:[...]}`. Production native storage wraps records separately through the official store adapter; the fixture does not prove native disk durability. Pending restores become unknown, credential drafts are excluded from persisted ordinary records, and vendor Terminal buffers never enter this holder. `connectedProject::createProjectDrafts` shares one holder across consumers. No reader, storage shape, refusal protection or migration changes here. A selected future retirement must first inventory all affected older data and name store-open plus real in-process Daemon reopen tests; refusal/reset is insufficient.

Unfinished work eligibility excludes active editors, empty/choice-only records, unknown original availability as sole risk and Rail-owned problems. Failed, unknown, unsaved retention, abandoned and gone-original revisions qualify through source branches. The replay covers failed Todo creation, removed order/selection, Rail original-name conflict, Rail removed target and invalid restore. It does not cover each editable owner, credential exposure, all retention failures, concurrent newer drafts, cross-Project behavior, browser restart durability, accepted real delivery, exact clipboard contents or native presentation. Malformed fixture retry stays failed rather than resetting data.
