## Criteria and observer

Q1 asks whether Claude Code, Codex, macOS or `gh` supplies the same action/result, including scope and authority. Q2 asks whether none of the five required journey results needs this independent feature. Q3 asks whether information has no action on or because of it. Every row records all three; unverified is not no. A yes is only a candidate reason for the eventual complete request.

Journey references below mean `.agents/data/journey.md`, **What must work**: Intervene requires answering in the requesting Agent's own Terminal; Review requires reading outcomes and inspecting resulting work, then reopening retained work. No stage requires a separate user shell, rearranging it, renaming it or selecting command spans. Those optional paths remain required by their own scenarios until an explicit owner answer and atomic amendment.

Inspected production paths: `terminal/Pane::Pane` and `createScreens` in `terminal/screens.ts`; `emulator::createXtermEmulators`, `attachLinkGestures`, `createLinkProvider`, `attachTurns`; `bubbles/Bubbles::Bubbles`, `Bubble`, `Tab`, `createTerminalClose`, `placesStorage`; shared clipboard, link and keyboard owners. Paths are relative to `apps/desktop/src/`. Source-only controls are explicitly identified below. Terminal typography/settings decisions already live in settings.md and settings-evidence.md; the per-Project zoom below is a separate control.

Primary comparison evidence read 2026-11-03: [Apple Terminal shortcuts](https://support.apple.com/en-kw/guide/terminal/trmlshtcts), [marks and bookmarks](https://support.apple.com/en-ae/guide/terminal/trml135fbc26/mac), [profile text settings](https://support.apple.com/en-mt/guide/terminal/trmltxt/mac). These establish Find, selection/copy/paste and marked-command selection in Apple's own sessions, not access to roundup's PTY, identity or authority. Profile typography is not proof of identical per-Project reset semantics. No future Adapter is treated as a replacement.

## Offers, direction and boundaries

Exact recorded public mappings remain in endpoints.md/public-seams.json: `terminal.open` → `rup terminal open` / Agent-only `terminal_open`; `terminal.spawn` → `rup terminal spawn` / Agent-only `terminal_spawn`; `terminal.close`, `terminal.write`, `terminal.resize`, `terminal.kill` → corresponding `rup terminal <verb>` and both roles' `terminal_<verb>`; `terminal.show` → `rup terminal show` / Door-only `terminal_show`; `agent.run` → `rup agent run` / Agent-only `agent_run`. `terminal.read`/streaming and adjacent lower-level public operations still need independent endpoint decision rows. These historical runtime offers are not relabelled as newly rebuilt on this pin. Current declarations were inspected; the final all-feature revision must rebuild both roles. App user-shell authority and Agent tool access remain distinct: a tool offer does not authorize opening a Project-owned shell or closing an ownerless Agent Terminal.

Rename, zoom, Find, geometry and minimisation are App operations, not separate RPC methods. Links use App `openTarget`/`openInEditor`, clipboard uses App capabilities, native file drop uses App `onFileDrop`; image saving is user-only `save_pasted_image`, never an Agent tool. Shell custom names/places live in local `placesStorage`; live Terminals end with Daemon lifetime. No storage or refusal rule changes here.
