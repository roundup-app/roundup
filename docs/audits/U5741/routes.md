## Actual public observer and authority

The isolated real Daemon creates an unstarted Workstream solely to supply a canonical receiver and real Door role lookup. CLI first lists zero Routes. User RPC sets Drop then Auto for each of `ext:audit`, `rupd` and `you`, then lists the three stored Auto pairs as a synthetic non-Door caller and the actual unstarted Door id. A Door attempt to change the user-origin pair is refused; a following list is unchanged. Exact replies, help, return codes and schemas are retained. No vendor process starts; no owner Project or credentials are read or changed. These are actual CLI calls and actual MCP `tools/list`, not successful MCP `tools/call` or real Message delivery observations.

Selector resolution in `crates/rupd/src/selectors.rs::Daemon::resolve_agent_inputs` preserves reserved `ext:*` and `rupd` senders and resolves Agent receiver references. Agent Route writes must have both endpoints equal to the caller or within its Reach, may not target the caller, and may not replace a user-set Route; Extensions cannot set Routes. `to:"you"` and equal endpoints are invalid. The setter records ownership internally, emits `route.changed`, and records an Agent write Touch; the list returns all stored pairs without a per-caller Reach filter. Availability in a tool list is not authority to bypass these checks.

`set_route` upserts one pair, retaining no old configuration revision. `send` reads its current value only for a later send; it does not rewrite an existing pending Message. A missing Route means default Auto. The existing named Route tests and real in-process Daemon authority tests supply behavior evidence beyond the live offer probes; [validation-routes.md](validation-routes.md) records their results. No test is added merely to reread this report.
