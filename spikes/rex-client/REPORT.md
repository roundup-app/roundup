# Spike: rupd drives Rex

Ran 2026-10-31 on the user's Mac: Rex server 0.0.1793377904-ge6592f, API revision 8; Rex Beta.app 0.1.0 (1696). The client is Rust (`tokio-tungstenite` over a `UnixStream`): `src/lib.rs` speaks the control and data WebSockets. `src/bin/spike/` runs one proof per question. Raw output of each run is in `raw/`. No real `claude` ran: `fake-agent` echoes keys and runs `flood`, `tick`, `status`, `title`, `size`, `env` and `exit`. Only Unix sockets were used; no TCP listener was opened. The driver played rupd with `CLAUDECODE=1` and `RUPD_SOCKET` in its environment.

Every question except Q1 ran against a Rex server the driver started and stopped itself. Q1 also made one session on the user's server and destroyed it. Each run destroyed every session it made. `rex ls --json` on the user's server was identical before and after (`raw/rex-ls-before.json`, `raw/rex-ls-after.json`): only `icy-canyon`.

```
cargo build --release --bins          # in spikes/rex-client
env -u ROUNDUP_AGENT -u ROUNDUP_AGENT_ID CLAUDECODE=1 RUPD_SOCKET=/tmp/fake-rupd.sock \
  target/release/spike q1|q2|q3|q4|q5|q6|q7|q7-restart|q8|q9|q10|exitcodes
```

| Q | Answer | Proof (`raw/`) |
|---|---|---|
| Q1 Server | **Both work.** rupd can own a server: `rex server run --listen unix:///…/rex.sock --state-dir … --restore=false --config <empty>`. It gets its own `host_id` and opens no TCP port. `--listen unix:/path`, without `//`, is read as TCP and refused unless you pass `--allow-anonymous`. **The Rex app sees nothing on rupd's own server.** The app connects only to the user's socket. It adds other servers from its own UI ("Type the address or socket path of a Rex host") and keeps them in its preferences (`com.superlogical.rex` `RexSync.servers`, empty here). Rex's docs say the server API's `hosts.put` refuses Unix sockets. `rex hosts add` writes to the server's host list; I did not verify whether the app reads that list. Adding roundup's server to the app is therefore a UI step; see "Size with the Rex app" below. **On the user's server, the app attached to roundup's new session within 3 s but did not take its block.** roundup kept 100×30. | `q1.txt`: own `clients attached = [roundup-spike]`, `app clients = []`. User: `clients attached = [roundup-spike, Rex Beta pid 19065]`, `after take+resize and 3 s: 100x30 owner is me=true` |
| Q2 Spawn | **Rex takes no `env`** (flavor options: shell, command, args, login, cwd, path_prepend, size, theme, initial_input, exit). **A bad `cwd` silently falls back to `$HOME`.** With launch.rs's argv passed as-is, the agent got the *server's* environment: `CLAUDECODE=1` and `CLAUDE_CODE_SESSION_ID` leaked in, `ROUNDUP_AGENT` was missing, and `PATH[0]` was Rex's bin directory. **Fix: carry env and cwd in the argv**, as `env -i -C <cwd> K=V… TERM=xterm-256color <argv>`. That gave the exact env (`ROUNDUP_AGENT=7`, no markers, `PATH[0]`=rup's directory). A bad cwd then fails with exit 125 and the block stays open. **Side finding: `shell:"none"` reports `exit_code: 0` for every exit.** `shell:"/bin/sh", login:false` reports the real code. | `q2.txt` naive: `cwd=/Users/saad.shahd`, `CLAUDECODE=Some("1")`. Wrapped: `ROUNDUP_AGENT=Some("7")`, `CLAUDECODE=None`. `wrapped-bad-cwd: child_exited exit_code 125`. `exitcodes.txt`: `sh exit 125` → `{"exit_code":0}` under `shell:none` |
| Q3 Stream | **Yes, byte for byte, with roundup's unchanged `terminal` crate.** `rex-tap` runs as the Terminal's program on a raw PTY and plays the Rex stream's program bytes. `Terminals` logs and parses them, so `read`, `search`, `screen` and `catchUp` are the real code. A 5000-line flood (379,804 B, many 64 KiB frames, UTF-8 split across them) read back in 27 `read` calls by offset: 5000 lines, all unique, in order, 0 split. `search` gives an offset, and `read(after=offset)` starts on that line. `screen` matches Rex's own `format`. Offsets equal Rex program bytes since the join, and a gate (below) makes that byte 0. | `q3.txt`: `lines seen=5000 unique=5000 … split=0 out_of_order=0`. `Terminals log bytes == Rex stream program bytes: true (379804 B)`. `exit 3` → `exit_code=Some(3)` |
| Q4 Late join | **Neither catch-up route is byte-aligned today, so I picked: never late-join.** The snapshot is `GHOSTSNP` v1 binary, and no Rust decoder exists. libghostty-vt's C API has `ghostty_snapshot_*` import, but its format may change until Ghostty's first tagged release ([discussion #11998](https://github.com/ghostty-org/ghostty/discussions/11998)). [libghostty-rs](https://github.com/uzaaft/libghostty-rs) does not wrap snapshots and needs Zig 0.17, which is not installed here. [go-libghostty](https://pkg.go.dev/github.com/mitchellh/go-libghostty) has no snapshot API either. **`format vt` plus the live stream overlaps:** 1 tick at 0 ms, 2 at 5 ms and 21 at 50 ms between the stream's WELCOME and the `format` call. **What does work, and is proven:** (1) join at creation behind a one-byte gate, so the snapshot is an empty screen; (2) **RESUME** with the token and an exact byte count, which continued with no gap or repeat. After more than 60 s away, repaint from `format vt` behind an explicit Gap (`CatchUp::Gap` exists). | `q4.txt`, `q4-overlap.txt`: `format vt ticks 2..17; live 17..100; overlap=1`, `…50 ms… overlap=21`. `live + resumed program bytes … gaps or repeats=0` |
| Q5 Size | **The last client to call `own_block` with `take` sets the size.** A non-owner's `resize` returns `{}` and only records a request. `own_block` with `request` does not take a block from its owner. The program sees the owner's size (`stty` → `20 60`). **roundup keeps authority only by taking the block again,** for example on `block_owner_changed`, which fights a user who resizes in the app. The real app attached to roundup's session but did not take the block while it did not show it (Q1). **Not observed: what the app does once the user opens the block.** That needs a UI action. | `q5.txt`: `second client resize 60x20 without owning: 100x30`, `own_block request: 100x30`, `own_block take: 60x20`, `roundup takes back: 100x30` |
| Q6 Input | **`write` returns `{"bytes_written":N}` once Rex has queued the text.** That is neither the physical PTY write nor the program reading it. `block.event` returns `{}` once the block has the event. Neither is roundup's `write_completed`. Per Rex's docs, a lost response means the outcome is unknown. **Order:** `write` calls run concurrently on the server. A paste and a separate `\r` sent without waiting came out intact in only 74 of 100 pairs; waiting for the paste's response first gave 100 of 100. `block.event` paste plus `key enter` sent without waiting gave 100 of 100, because Rex runs those methods in order. Rex also adds the bracketed-paste markers when the program has enabled them. | `q6.txt`: `write-pipelined … intact=74`, `write-awaited … intact=100`, `event-pipelined … intact=100` |
| Q7 Exit, reattach | **The exit code arrives three ways:** the `child_exited` event `{exit_code:7,error}`, the stream message `{"type":"child_exited","exit_code":7}`, and `process.last_exit` when the block stays open. **Reattach works.** Process 1 created, owned and streamed a block, then died without close frames. Process 2 sent the saved reconnect token and got `resumed=true` with the same client id, still owning the block, with the same child pid. Its RESUME continued the ticks with no gap or repeat. A forged token got `REJECT 0x01`. **A block id alone is weaker than owner.rs's incarnation check.** After a Rex restart with `--restore`, the same block id returned with a **new** child pid, an empty screen and a new `instance_id`. A sufficient check is `instance_id` + `block_id` + child pid and name + `last_exit:null`, plus the secret reconnect token while it lasts (60 s). **Run with `--restore=false`:** restore starts the program again, which for an agent would be a second `claude --resume`. | `q7.txt`, `q7-restart.txt`: `resumed=true same client id=true`, `child pid 14545 == saved 14545`, `ticks 2..40, gaps or repeats=0`, `instance_id before … after …`, `same block id process child 14677` |
| Q8 Status | **The stream carries OSC 7501 exactly as the program printed it** (`ESC]7501;state=working:msg=cmVhZGluZyBmaWxlcw==ESC\`), so roundup's parser sees it, as Q3 proved byte for byte. `program_status_changed` carries the parsed record: `state`, base64-decoded `msg`, foreground `owner` pid and name, and `reason:"report"`. Both arrived within 0.5 ms of the write. `program_status` returns the latest record, and `title_changed` carries the title and the process that set it. | `q8.txt` |
| Q9 Delay | **Rex adds about 0.1 ms; the budget is 16 ms.** Over 200 tries each, from key to echoed byte, on a release build with load average about 9: direct PTY (`Terminals`) p50 0.011 ms, p95 0.013 ms. Rex `write` to stream: p50 0.122 ms, p95 0.157 ms. Rex `block.event` key: p50 0.072 ms, p95 0.095 ms. None of these include webview rendering. | `q9.txt` |
| Q10 Memory | **Within budget.** Today, ten fake agents in `Terminals` grew rupd by 5.0 MB. With Rex, the server grew 9.0 MB (38.0 → 47.0 MB) and the client holding ten streams and vt100 mirrors grew 1.6 MB. **An own server also adds its 38 MB base, for about 49 MB in all, under rule 7's 150 MB.** Sharing the user's server adds about 10.6 MB. | `q10.txt` |

## Size with the Rex app showing the block: blocked

The user approved listing roundup's server in the Rex app. `spike q5-app` held rupd's own server for 100 s with a fake agent at 100×30 owned by roundup (`raw/q5-app.txt`); no other client attached, because the host could not be added:

- computer use was held by another Claude session;
- `osascript` has Accessibility and `screencapture` has Screen Recording, but the app's host controls carry no accessibility labels, so the app must be driven by sight, in front of the user's roundup window;
- Claude Code's auto-mode classifier refused an `osascript` click into Rex Beta.

Afterwards the user's host list, the app's server list and `rex ls --json` matched their earlier copies (`raw/hosts-before.json`, `raw/app-servers-before.txt`, `raw/rex-ls-before-app.json`). Still open: who owns the size while the app shows the block, and after the app window is resized.

## Smallest rupd change that lets Rex hold the terminals

`rex-tap` proved the seam with no rupd change: `Terminals` already accepts any byte source behind one program. The production change sits inside the crates and skips the extra PTY:

| Module | Change |
|---|---|
| `crates/terminal/src/rex.rs` (new, beside `remote.rs`) | A Terminal whose bytes come from a Rex data stream (`Splitter`: drop the snapshot, separate out Rex messages) instead of `pty.rs`'s reader. It feeds the same `Chunk` broadcast and `ScreenState`, so `read`, `search`, `screen`, `catchUp`, output subscribers and title detection do not change. Input: one awaited `write` (or `block.event`) at a time. Resize: `own_block` with `take`, then `resize`. Exit: the stream's `child_exited` message calls `finish(code)`. |
| `crates/terminal/src/lib.rs` `start` | Build the block command: `/bin/sh` non-login, `env -i -C <cwd> <env minus clean_env> TERM=xterm-256color`, the one-byte gate, then argv. Refuse a bad cwd before starting, as today. |
| `crates/terminal/src/owner.rs` → Rex record | Persist `{instance_id, session, block, child pid and name, control reconnect token, data token, bytes received}` at mode 0600, in place of the incarnation socket. |
| `crates/agents/src/owners.rs` | The reattach check compares that record (Q7) and resumes the stream. Past 60 s, or after a new `instance_id`, the Agent is `done`, as `open.rs` does today. |
| `crates/rupd/src/open.rs` | Start and own a Rex server (`--listen unix://<data>/rex.sock --state-dir <data>/rex --restore=false --config <empty>`), hold one control connection, and stop wiring `RUPD_TERMINAL_OWNER`. Find `rex` under `…/RexServer/Versions/Current`. |
| `crates/perf` | `rss_extra_mb` counts the Rex server. The keystroke observer includes the Rex hop. |

Unchanged: `launch.rs` argv and env building, hooks as the Status source (OSC 7501 and `title_changed` are extra inputs), the idle gate and paste-then-`\r` in `steer.rs`, the 8-Terminal cap and `guard_reach`.

## Still unsolved

- **Late join past 60 s, byte-aligned:** it needs a GHOSTSNP decoder (libghostty-vt through FFI and Zig; format v1 is unstable). Until then, it is a Gap plus a `format vt` repaint.
- **Size when the user opens the block in the Rex app:** not observed. Either the app claims with `request`, or roundup gives way while the user views.
- **Write completion:** Rex confirms "queued", which is weaker than `write_completed`'s physical write. A lost response is unknown, and roundup must not retry it.
- **Env in argv:** visible to same-user `ps` (Rex's `process` hides args). A small exec helper that reads a 0600 env file would hide it.
- **`shell:"none"` reports exit 0:** a Rex bug to report. Avoid it until fixed.
- **Anyone with the socket can type into an Agent:** the same uid, or the app over a host link, bypasses `guard_reach`, Routes and the idle gate.
- **Own servers write outside `--state-dir`:** each `rex server run` left an empty `start.lock` folder under `~/Library/Application Support/rex/servers/<hash>`, keyed by its socket. I removed the 40 this spike left; rupd must clean them up or reuse one socket path.
- **Young surface:** API revision 8 on a 0.0.x build, and the binary path changes with each version.
- **Not tested:** remote use over `ssh -L` or the tailnet listener, and Rex's `bell` and `desktop_notification` events.

## Decision for the user

To finish the size test, one of: free computer use for this spike, allow `osascript` to drive Rex Beta, or add the host in the Rex app by hand while the spike holds its server.
